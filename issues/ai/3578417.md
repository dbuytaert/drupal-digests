## Summary

Uninstalling AI Automators now removes the `ai_automator_status` field it creates on entity bundles such as `media:image`. Previously the field storage, the field instance and its entries in the form and view displays stayed behind and still showed up under Manage fields. The uninstall confirmation page now lists these configs as going away. Existing sites get the fix by running database updates, because the post-update hooks tag already-created status fields so they are cleaned up on a later uninstall.

## Impact

Affects site owners.

- **Database update:** Two new post-update hooks, `ai_automators_post_update_13001` and `ai_automators_post_update_13002`, add an enforced `ai_automators` module dependency to existing `ai_automator_status` field storage and field config entities.

## Technical details

The status field config entities are now created with `dependencies.enforced.module: [ai_automators]`, via a new `AiAutomatorStatusField::MODULE_DEPENDENCY` constant. When the storage already exists, a new `ensureModuleDependency()` method adds the dependency and saves it. Because Drupal's config dependency handling acts on these, uninstall shows the affected config on the confirmation page and deletes dependent display component references. The `field_config` default value is also now stored in the proper `['value' => ...]` structure.

A contributor found that enforced dependencies delete `field_storage_config` entities but not `field_config` entities on uninstall. So `hook_uninstall()` in `ai_automators.install` stays and now only handles `field_config`. The old loop queried by `label` equal to the field name, which was wrong. It now queries `field_name`.

The backfill is a pair of post-update hooks, `ai_automators_post_update_13001` for storage and `ai_automators_post_update_13002` for field config, using `ConfigEntityUpdater`. They were chosen over regular update hooks so entity operations run in a reliable system state. A new kernel test, `AiAutomatorsUninstallCleanupTest`, creates the status field and form/view displays through the entity API so display config dependencies are recorded properly. It uninstalls the module and asserts the field and display components are gone.

## Upgrade

Run database updates (`drush updb`). The two post-update hooks add the enforced `ai_automators` dependency to existing `ai_automator_status` field storage and field config entities. Status fields left behind by an earlier uninstall are not removed automatically.
