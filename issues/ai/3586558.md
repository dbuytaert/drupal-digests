# #3586558: Preserve HTML in streamed output (1.3.x)

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586558](https://git.drupalcode.org/project/ai/-/work_items/3586558) · 1 contributor · 33 comments

## Summary

Streamed AI responses that contain HTML no longer get stray closing tags injected mid-sentence. The reported case was AI Translate in the GUI, where text such as `<strong>…</strong>` in a page body came back split into extra `<p>` paragraphs and sentences were broken apart. Streamed output now keeps the HTML the model produced.

## Impact

No upgrade or configuration changes required.

## Technical details

`StreamedChatMessageIterator` buffers streamed chunks and flushes them through `HostnameFilter::filterText()`. In HTML mode the filter parses the text as a fragment and re-serializes it. When a flush landed mid-element, for example after an opening `<strong>` but before its closing tag had streamed, the HTML5 parser auto-closed the open tags and dropped the orphaned closing tags. That corrupted the markup.

`shouldFlush()` now returns FALSE while a new private helper, `bufferHasUnclosedHtml()`, reports that the buffer is unbalanced. The helper returns TRUE when the buffer ends inside an unfinished `<…` tag, or when a stack-based scan of the tags finds non-void, non-self-closed elements still open. Whatever remains is flushed at end of stream, where the full message is balanced. Two guards limit the hold. A new constant `MAX_HTML_BUFFER_SIZE` (102400 bytes) forces a flush if a tag never closes, so malformed output cannot grow the buffer without bound. The hold is also skipped while a streaming guardrail is registered (`$streamingGuardrailStates` non-empty), because guardrails do their own start/stop buffering and holding the buffer across their markers would change what they evaluate. The commit adds a unit test, `StreamedHtmlIntegrityTest`, that re-chunks HTML at several sizes and checks that it round-trips unchanged.
