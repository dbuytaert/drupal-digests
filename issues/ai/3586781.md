## Summary

The Extractive Question Answering Explorer in AI API Explorer has been rebuilt on the shared explorer layout. The answer is now highlighted inside the passage instead of being shown as a table of start and end offsets. When the model returns several candidate answers, you can click one to see where it sits in the passage. The explorer's route is now `/admin/config/ai/explorers/extractive_question_answering_generator`. Each run is stored through the run history, and its code example is generated per run with escaped values.

## Technical details

`ExtractiveQuestionAnsweringGenerator` now builds the form with `buildLayout()` and `providerElement('extractive_question_answering', ...)`. Submission goes through `executeRun()`, which stores `question`, `context` and `provider` as run input and the sorted answers (`answer`, `score`, `start`, `end`) as run output. `getResponse()` returns `resultsResponse()`, and `buildRunOutput()` renders the stored run. Answers are sorted by score, best first, and answers without a score go last. Blank answers are dropped.

`locateAnswer()` decides where an answer sits in the passage. It trusts the offsets as character offsets when the text at that position matches the answer. Otherwise it tries them as byte offsets, then searches for the answer text, and finally falls back to offsets that fit within the passage. Providers that return no offsets still get a highlight when the answer text is found. CRLF line breaks are normalised for display, so the `data-start` and `data-end` values on each candidate button match what the browser shows.

The new `js/explorers/extractive_question_answering.js` behavior moves the `<mark>` when a candidate button is clicked. It splits the passage by code point so the offsets stay consistent with PHP's `mb_*` functions. The buttons use `aria-pressed`, and the range text sits in an `aria-live` region. Styles are in `css/explorers/extractive_question_answering.css` and are attached through the new `explorer.extractive_question_answering` library.

The code example is built with the shared `CodeExample` builder, replacing the hand-built HTML string that pasted the question and passage in unescaped. The passage and answers are escaped with `Html::escape()`. The diff also adds a `ai_api_explorer_test` provider plugin (`TestExtractiveQaProvider`), a functional test and a docs URL update.
