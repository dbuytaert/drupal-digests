## Summary

The Moderation Explorer (part of the AI API Explorer module) has a new layout shared with the other redesigned explorers. Each check now shows a clear Flagged or Not flagged verdict with the highest-scoring category, and every category score as a bar, highest first, with flagged categories in red. The field is labelled "Text to check" and the button reads "Check text" instead of "Ask The AI". Each check is stored as a run, so results can be kept across reloads when run history is enabled. The generated code example is now correct: it previously used an undefined `$input` variable.

## Technical details

`ModerationGenerator` now builds on the shared shell from `AiApiExplorerPluginBase` (`buildLayout()`, `runButton()`, `executeRun()`, `buildRunResults()`), replacing the old `getFormTemplate()` and `AiProviderFormHelper::generateAiProvidersForm()` flow with the `ai_provider_configuration` element via `providerElement('moderation', ...)`. Submission creates a `ModerationInput`, calls `moderation()`, and stores flagged state, scores, flags, the provider message and token usage on the run. Results are rendered from stored runs (`buildRunCard()`, `buildRunOutput()`), and the code example is generated per run with the shared `CodeExample` builder in `buildRunCode()`.

Providers return scores in different shapes, so `findScores()` handles both a flat category to score map (OpenAI style, with per-category flags read from the raw response's `results[0].categories`) and a nested `categories` array with `probability` or `score` and its own `flagged`. Only values between 0 and 1 count as scores. When no scores can be found, the raw information is shown as key/value details instead. Category names are made readable (for example `harassment/threatening` becomes "Harassment, threatening") and scores under 0.001 show as `<0.001`.

Styles live in a new `css/explorers/moderation.css`, registered as the `explorer.moderation` library in `ai_api_explorer.libraries.yml`. A new `ModerationExplorerTest` functional test uses the `ai_test` mock provider to cover the flagged and not-flagged cases, nested categories, and the code example. The docs page for the moderation operation now points to the correct explorer path `/admin/config/ai/explorers/moderation_generator`.
