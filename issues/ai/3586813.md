## Summary

The Decision operation can now ask a fourth kind of question, a box question, which asks where one described target is in an image. The answer is a box of four edges (top, bottom, left, right) given as fractions of the image size, plus a confidence. Providers opt in by declaring a new `DecisionBox` capability, which requires image file support. The Decision Explorer shows box answers, including the box in pixels for each uploaded image. This supports the TypeSafe Jev 1.14 box feature described in the issue.

## Impact

Affects module maintainers.

- **API change:** `QuestionFactory` and `AnswerFactory` now accept `box`. `DecisionRequestValidator` rejects box questions without an image file with `AiBadRequestException`. Models without `DecisionBox` now fail box questions with `AiMissingFeatureException` instead of an unknown-type error. The shared contract suite image fixtures changed from 1×1 PNG/GIF to 300×300 PNG/JPEG.
- **New API:** New `BoxQuestion`, `BoxAnswer`, `QuestionInterface::TYPE_BOX`, `DecisionResponse::getBox()` and `AiModelCapability::DecisionBox` (`decision_box`) for Decision calls.

## Technical details

Box is added to the closed set of question types. `QuestionInterface::TYPE_BOX` and a final `BoxQuestion` (instructions only, `getCriteria()` returns NULL) are added. `QuestionFactory::fromArray()` builds it and throws on any criteria. `BoxAnswer` validates that every edge and the confidence are finite and in 0 to 1, and that `left <= right` and `top <= bottom`. Equal edges are allowed, since transport rounding can collapse a thin box. `getBox()` returns the edges keyed `top`, `bottom`, `left`, `right`. `toPixels($width, $height)` rounds outward (left and top down, right and bottom up), so right and bottom are exclusive as in a crop rectangle. `AnswerFactory` dispatches `box`, and `DecisionResponse::getBox()` behaves like `getScore()`: it throws `AiDecisionRefusedException` for a refusal and `\UnexpectedValueException` for another type.

`DecisionRequestValidator` maps box questions to `AiModelCapability::DecisionBox`. A new final check throws `AiBadRequestException` for a box question when the request has no image files. A model without `DecisionBox` still gets `AiMissingFeatureException` first. In `DecisionCapabilities`, `DecisionBox` requires `DecisionImageFiles` and does not count as one of the noul, choice or score types a profile must declare.

In the explorer (`DecisionGenerator`), box rows show the edges, the confidence and a pixel box per uploaded image, because the explorer cannot tell which image the instructions named. The generated code example uses `getBox()`. The capability summary substitutes a placeholder image when box questions are present, to avoid a false "needs an image" error. Guardrails are unchanged. Moderation is text-only and stops requests with files, so it stops every box request. The docs (`call_decision.md`, `decision_provider_contract.md`, explorer index) are updated. The provider contract suite gets a `box` request case, malformed-box cases and a box-without-image check. The commit also changes the shared fixture images to a 300×300 PNG and a 300×300 JPEG, because the issue says TypeSafe rejects GIF and images under 256 px per side. The commit also changes a `DeepChatLazyLoadTest` test to dispatch `focusin` instead of calling `focus()`, which is unrelated to the feature.

## Upgrade

Provider authors whose model can locate targets in images can declare it, together with image support:

```php
new DecisionCapabilities([
  Capability::DecisionNoul,
  Capability::DecisionImageFiles,
  Capability::DecisionBox,
]);
```

Return box answers in the normalized shape `['type' => 'box', 'box' => ['top' => 0.25, 'bottom' => 0.82, 'left' => 0.44, 'right' => 0.84], 'confidence' => 0.92]`. Adapters that declare `DecisionImageFiles` now run against 300×300 PNG and JPEG fixtures in the shared contract suite, which replace the 1×1 PNG and GIF. Callers read results with `$response->getBox('id')`.
