## Summary

In the Chat Explorer, if Structured output is turned on but the JSON schema is empty, not valid JSON, or lacks a `schema` or `properties` key, the request is sent without a schema. The assistant's answer now shows a "Sent without a schema" notice, and the chat list only labels the chat "JSON schema" when a schema was really sent.

## Impact

No upgrade or configuration changes required.

## Technical details

`ChatGenerator::schema()` returns NULL for unusable schemas. It now also rejects a full schema (with `name`/`strict` keys) whose inner `schema` is empty or not an array, instead of falling back to the wrapper as the schema. A new `checkSchema()` method replaces the duplicated validation in the non-streamed and streamed paths: with `structured` on and no schema it sets `schema_missing` on the answer message; otherwise it stores `schema_errors` from `validateJsonSchema()` as before. The streamed answer keeps the flag when the browser posts it back, via the answer-parsing code that copies `schema_errors`.

The message render adds a `Sent without a schema` notice when `schema_missing` is set. The chat list label now checks whether any message's `meta.request.structured_output` is set, instead of the `structured` input flag. `ChatExplorerTest::testStructuredOutputWithoutSchema()` covers empty, broken, keyless and empty inner schemas, plus the streamed path.
