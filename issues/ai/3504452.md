## Summary

In the AI Automators advanced settings, the Joiner select kept showing "-- Don't join --" after you saved a different value. It now shows the saved value. The "Other Joiner" text field, which had no default at all, now also shows its saved value.

## Impact

Affects module maintainers.

- **API change:** `GeneralHelper::addJoinerConfigurationFormField()` now requires an `array $defaultValues` argument, inserted before the optional `$extraJoiners` and `$defaultJoiner`.

## Technical details

The Joiner default was read only from the field config's third party setting `ai_automator` (`{$id}_joiner`). Automator settings are stored on the `ai_automator` config entity, so that lookup came back empty. `GeneralHelper::addJoinerConfigurationFormField()` now takes the `$defaultValues` array that `extraAdvancedFormFields()` already receives. `#default_value` on `{$id}_joiner` uses the third party setting when it is non-empty. Otherwise it falls back to `$defaultValues["{$id}_joiner"]`, then to an empty string. `{$id}_joiner_other` gets `#default_value` from `$defaultValues["{$id}_joiner_other"]`. The diff also loads `ai_automator` entities by `entity_type` and `bundle` into a `$fields` variable that is never used afterward. `ComplexTextChat::extraAdvancedFormFields()` is updated to pass `$defaultValues`. It is the only caller in the module.

## Upgrade

Custom code calling the helper must pass the new argument. A call that passes `$extraJoiners` or `$defaultJoiner` must also insert `$defaultValues` before them.

```php
$this->getGeneralHelper()->addJoinerConfigurationFormField('automator', $form, $entity, $fieldDefinition, $defaultValues);
```
