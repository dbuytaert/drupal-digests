## Summary

AI chatbot blocks (`ai_chatbot_block` and `ai_deepchat_block`) could fail to render with a PHP "typed property must not be accessed before initialization" error when the assistant's history setting didn't store the session (for example `session_one_thread`, per a tester in the thread). The runner now returns an empty message history when no user message has been set yet, so the blocks render on first page load.

## Impact

No upgrade or configuration changes required.

## Technical details

In `AiAssistantApiRunner::getMessageHistory()`, the fallback path for when the session isn't stored read `$this->userMessage->getMessage()` unconditionally. `$userMessage` is a typed property with no default, so on initial block render, before `setUserMessage()` has been called, it threw an `Error`. The fix guards that branch with `isset($this->userMessage) && $this->userMessage instanceof UserMessage` and returns `[]` otherwise. Behavior is unchanged once a user message exists. The commit landed on `1.x` and was also committed to the 1.1.x, 1.2.x, 1.3.x, 1.4.x, 2.0.x and 2.x branches.
