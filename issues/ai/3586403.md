## Summary

The Chat Explorer has been redesigned on the shared explorer layout. It now supports a full message history instead of a single message, with system, user, assistant and tool roles. Several chats can be kept and reopened when run history is on. Tool calls and their results are shown in the thread, and the model can be set to only show a call, run it, or run it and continue for up to 5 rounds. Request settings (model, tools, output, code) sit in tabs, chats can be imported and exported as JSON, and structured output answers are checked against the schema. Provider and model selection now use the `ai_provider_configuration` element. The generated code example no longer contains the broken calls and unescaped values it had before.

## Impact

Affects module maintainers, front-end developers and site owners.

- **Security:** `AiValidator` no longer fetches external documents referenced by `$ref` in a user-supplied JSON schema; it returns a validation error instead.
- **Theme change:** Chat Explorer renders through the new `ai-api-explorer-chat.html.twig` template; the `ai_api_explorer/stream` and `ai_api_explorer/multiselect` libraries are removed.
- **New API:** `ExplorerRunManager::getRuns()` takes a new `$sort` argument (`created` or `changed`); new `ai_api_explorer_chat` theme hook and `explorer.chat` library.

## Technical details

`ChatGenerator` was rewritten around a stored chat (an `ExplorerRunInterface` run) holding messages and settings (`provider`, `tools`, `tool_mode`, `stream`, `structured`, `schema`, `guardrail_set`). It is saved after every turn through `ExplorerRunManager`; with history off the chat lives in form state and the chats column only lists the open chat. Layout comes from a new `ai_api_explorer_chat` theme hook (`template_preprocess_ai_api_explorer_chat()` splits the form into `chats`, `thread`, `settings` and `import`), the `explorer.chat` library (`css/explorers/chat.css`, `js/explorers/chat.js`), and `MAX_ROUNDS = 5` caps automatic tool rounds. Streaming is done in the new chat script, so the old `stream.js`, `stream.css`, `multiselect.js` and the `multiple-select` assets and their libraries are deleted.

`ExplorerRunManager::getRuns()` gains a `$sort` parameter (`created` default, or `changed`), and the purge of runs past the count limit now orders by `changed`, so a chat that is still used is kept over a newer but idle one.

The code example is built with `\Drupal::service(...)`, passes the normalized tool definitions to `new ToolsInput($functions)`, and escapes message text and schema values. Outside the explorer, `AiValidator::validateSchema()` now uses a `UriRetriever` backed by an empty `PredefinedArray`, so schema references inside the document resolve but a `$ref` to a URL or file is never fetched; it returns "The schema references an external document, which is not supported." The mdxeditor build also gets `safeHtmlNodes` so HTML in the markdown shows without scripts or event handlers (requires rebuilding the editor assets).
