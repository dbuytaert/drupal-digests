## Summary

The Search API index status page for indexes using the AI Search backend now has an "Indexing options configured" row. If no indexing options have been set in the Fields tab, it shows a yellow warning saying they must be configured first. Previously, an index created with "Save" (not "Save and add fields") reported "Successfully indexed X items" while nothing reached the vector database, and a PHP warning about an undefined `indexing_options` key appeared in the logs.

## Impact

No upgrade or configuration changes required.

## Technical details

The reporter's problem was a configuration omission, not a code bug: `EmbeddingBase::buildBaseMetadata()` reads `indexing_options` from the `ai_search.index.<id>` config, which is empty until the Fields tab is saved. Rather than changing indexing behavior, the fix extends `ai_search_preprocess_search_api_index()` in `ai_search.module`. For the `search_api_ai_search` backend it loads the raw `ai_search.index.<id>` config and appends a table row. If `indexing_options` is empty the row gets `warning` and `color-warning` classes plus an explanatory message. Otherwise it says "Indexing options have been configured." `AiSearchSetupMySqlTest` now asserts that success text after the fields are saved.
