## Summary

Right-to-left text (Arabic, Hebrew, Farsi, Urdu) in AI API Explorer results, such as run titles, quotes, outputs, chat bubbles and transcripts, was laid out left to right, so it started at the left edge and its punctuation landed next to the first word. These blocks now take their direction from the text, so right-to-left text is right-aligned with punctuation at its end. English and other left-to-right text looks as before.

## Impact

Affects module maintainers.

- **New API:** `ExplorerUi::isolate()` and `ExplorerUi::languageDirection()` added for explorer plugins that show free text or mixed labels.

## Technical details

`css/explorer-ui.css` gets one rule with `unicode-bidi: plaintext` and `text-align: start` for the shared classes (`.aie-run__title`, `.aie-quote`, `.aie-output`) and for the explorer-specific blocks that hold free text (chat, extractive QA, rerank, speech to text, speech to speech, moderation, tools, object detection labels and others). `plaintext` takes each paragraph's direction from its first strong character. A second rule, `.aie [dir] { unicode-bidi: isolate; }`, keeps an explicit `dir` working, because `plaintext` would ignore it.

Two helpers are added to `ExplorerUi`. `languageDirection(string $code)` returns `rtl` or `ltr` from `LanguageManager::getStandardLanguageList()`, or `NULL` for an unknown code. `isolate(string $text)` wraps text in U+2068 and U+2069, which works like `<bdi>` but is also usable in attributes and `<option>` labels. The Translate explorer uses `languageDirection()` to set `dir` on the output from the target language and on the quote when the source language was picked, not detected, which fixes an Arabic translation that starts with a Latin word. Speech to Speech sets `dir` and `lang` on its texts. Embeddings labels ("T2 · text") use `isolate()`. The Speech to Speech and Text Classification run titles wrap file names and labels in `<bdi>`, and `ObjectDetectionGenerator` gives the label cell the `aie-object-detection__label` class. The module README gains a "Showing text in any language" section, and new Functional and FunctionalJavascript tests cover the behavior.

## Upgrade

For custom explorer plugins that show user or model text: put the text in a block with `aie-run__title`, `aie-quote` or `aie-output`, or add your own class to the rule in `css/explorer-ui.css`. Where the language is known, set `dir` from `ExplorerUi::languageDirection()`. For a label that puts a prefix before a text, use `<bdi>` or `ExplorerUi::isolate()`:

```php
'label' => $label . ' · ' . ExplorerUi::isolate($names[$j]),
```
