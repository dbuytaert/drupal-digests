## Summary

Closing the AI assistant dialog in CKEditor 5 could throw a JavaScript `TypeError` ("has is not a function"). The AI CKEditor integration replaced a core CKEditor 5 lookup object with a bare function. The proposed fix registers the callback in that object instead of replacing it. The maintainer who tried to reproduce it (abhisekmazumdar) could not, so the exact conditions that trigger it are unconfirmed in the thread. The merge request is the only fix shown and no commit had landed when this was written.

## Impact

No upgrade or configuration changes required.

## Technical details

The AI CKEditor dialog code ended with `Drupal.ckeditor5.saveCallback = saveCallback;`. That replaced the core `Drupal.ckeditor5.saveCallback` Map with a function, so any later `.has()` call on it failed. The merge request (!848) changes this to `Drupal.ckeditor5.saveCallback.set(dialogSettings.selector || '#drupal-modal', saveCallback);`. The callback is keyed by the dialog selector and falls back to `#drupal-modal`. The Map-keyed-by-selector behavior is taken from the issue text and the diff, not checked against core.

The merge request diff also bumps the `ckeditor5` dev dependency in a `package-lock.json` from `~34.1.0` to `~41.3.1`. This is build tooling and does not change the one-line behavior fix.

In the current `ai` repository checkout, the JavaScript containing `saveCallback` no longer exists. The latest commit there, "Issue [#3586836](https://www.drupal.org/node/3586836): Remove ai_ckeditor submodule and require standalone version instead", removed the `ai_ckeditor` submodule. The fix therefore applies to the code that moved out of this repository.
