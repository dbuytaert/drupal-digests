## Summary

The AI module's hostname filter no longer turns `&` into `&amp;` and `>` into `&gt;` in text that has no HTML. Chat answers written in Markdown (quote blocks, code spans, tables) now come through unchanged. Plain-text mode no longer breaks Markdown links. A disallowed link is reduced to its text, and an allowed link keeps its closing parenthesis. Text that really does contain HTML tags is still filtered as before. An opt-in Markdown mode is available for consumers that render Markdown and want HTML examples inside code spans and blocks preserved.

## Impact

Affects module maintainers.

- **New API:** New `markdownMode` property on `HostnameFilterDto` and new `HostnameFilter::setMarkdownMode()` method; `snapshotSettings()`/`restoreSettings()` now include `markdownMode`.

## Technical details

The encoding came from `HostnameFilter::filterText()` always round-tripping text through the HTML5 parser, which encodes text nodes. After the Markdown link pass, it now returns early when the new `containsHtmlMarkup()` check finds no HTML. That check looks for `<` followed by a letter, `/`, `!` or `?`. It also treats invalid UTF-8 as HTML, because the HTML parser drops invalid bytes before tokenizing and so could hide a tag with an invalid byte after the `<` from the check. By default any `<tag` counts as markup, including inside backticks or indented code, since an HTML consumer would still act on it.

When `markdownMode` is TRUE, `containsHtmlMarkup()` parses the text with a League CommonMark parser, without rendering it. It reports HTML only if it finds an `HtmlBlock`, an `HtmlInline`, or a `Text` node containing a tag-like sequence. Autolinks, reference destinations and code therefore skip the HTML round trip. Plain-text mode takes precedence over Markdown mode. Mixed Markdown and HTML can still be HTML-encoded.

In plain-text mode, `filterMarkdownLinks()` now runs before the bare-URL pass, with `$allow_rewrite = FALSE` so a disallowed link is always reduced to its text and never rewritten. It also takes `$preserve_mailto = TRUE`, which keeps `mailto:` links, autolinks and reference definitions as plain-text mode already did for bare URLs. The bare-URL replacement now keeps trailing punctuation when it removes a URL. `markdownMode` is also handled by `applySettings()`, `snapshotSettings()` and `restoreSettings()`. The README gains a "Markdown consumers" section.

## Upgrade

Only enable this if your consumer renders the output as Markdown:

```php
use Drupal\ai\Dto\HostnameFilterDto;

$chatInput->setHostnameFilter(new HostnameFilterDto(markdownMode: TRUE));
```

For direct service calls, use `$hostnameFilter->setMarkdownMode(TRUE)`. The service is shared, so restore the previous settings afterwards with `snapshotSettings()` and `restoreSettings()`.
