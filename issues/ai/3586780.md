## Summary

The Text Classification Explorer in AI API Explorer has been rebuilt on the shared explorer layout. Labels are entered as removable chips with one click presets (Sentiment, Support topic, Spam check), and results show as score bars ranked best label first. The long usage paragraph above the text field is gone in favour of a plain "Text" label. The generated PHP example now escapes the text and labels, so quotes and backslashes no longer break the snippet. Runs are stored and listed through the explorer run history when it is enabled.

## Technical details

`TextClassificationGenerator` now builds on `buildLayout()` and replaces `AiProviderFormHelper::generateAiProvidersForm()` with `providerElement('text_classification', ...)`, the `ai_provider_configuration` element. Submission goes through `executeRun()`: it calls `textClassification()` and stores label/score items, sorted by score with unscored labels last. A response with no items is treated as a failed run ("The provider returned no labels."). Run cards are rendered from the stored run via `runTitle()`, `runBadge()`, `buildRunOutput()` (using `ExplorerUi::bars()`) and `buildRunCode()`. The submitted text is passed through `Html::escape()` before display.

Labels use `ExplorerUi::labelChips()`, which falls back to a plain one per line textarea without JavaScript. `parseLabels()` trims lines and drops blanks and case-insensitive duplicates. The new `explorer.text_classification` library adds `js/explorers/text_classification.js` (presets, `aria-pressed` state, run button label showing the label count) and `css/explorers/text_classification.css`. The code example is built with the shared `CodeExample` builder, which fixes the unescaped text and labels. The commit also adds a test-only `TestTextClassificationProvider` in `ai_api_explorer_test` and a functional `TextClassificationExplorerTest`. The docs now give the explorer path as `/admin/config/ai/explorers/text_classification_generator`.
