## Summary

Editing an existing Search API server that uses the Milvus (or Zilliz) vector database provider no longer fails validation with a bogus error. Previously the form treated any response code other than 200 as a failure, even though Milvus returns 0 on success, so the update was blocked with an error showing code 0 and no message.

## Impact

No upgrade or configuration changes required.

## Technical details

In the `MilvusProvider` backend config validation, the check on the `describe` response compared `$described['code']` to `200`. Per the Milvus docs the success code is `0`, so the condition was always true on success. It now casts the code with `(int)` and compares against `0`, and requires a non-empty message with `!empty($described['message'])` instead of `isset()`. The error is still only set when the server entity is not new (`!$entity->isNew()`).
