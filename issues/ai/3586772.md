## Summary

The AI API Explorer can now keep a per-user history of runs (prompt, settings, output, errors, files) instead of forgetting everything on page reload. It is off by default, for new installs and for existing sites after the update, so nothing is stored until a site turns it on at `/admin/config/ai/explorers/settings`. With history on, a user sees only their own runs, and old runs are removed on cron by count and age limits. Anonymous visitors never get a stored history, even with it enabled. Administrators with the new permission can delete everyone's runs but cannot read or download them.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_api_explorer_update_16001()` installs the `ai_api_explorer_run` entity type and default settings with history left off.
- **Config change:** New `ai_api_explorer.settings` config with `history.enabled` (default off), `history.max_runs` (50) and `history.max_age` (30 days).
- **Permission change:** New restricted `administer ai api explorer` permission: change history settings and delete other users' runs (not read them).
- **New API:** New `ai_api_explorer_run` content entity type and `ai_api_explorer.run_manager` service (`ExplorerRunManager`) for storing, listing, purging and clearing explorer runs.

## Technical details

Runs are stored in a new content entity `ai_api_explorer_run` (`src/Entity/ExplorerRun.php`, status enum `ExplorerRunStatus`). `ExplorerRunAccessControlHandler` allows view and update only to the authenticated owner who also has `access ai prompt`. `administer ai api explorer` adds delete on any run. Create access also requires an authenticated user, because every anonymous visitor is user 0.

`ExplorerRunManager` (`ai_api_explorer.run_manager`) is the entry point: `create()`, `record()`, `getRuns()`, `getRecentFiles()`, `loadOwnRun()`, `clear()`, `saveFile()`, `purge()`, `enforceLimit()`, `deleteForUser()`, `deleteAll()`. `isEnabled()` is true only for an authenticated user with `history.enabled` on. When it is false, `record()` keeps the run only in form state for that visit, and `clear()` leaves stored runs alone. `purge()` counts age from the `changed` timestamp, not `created`, so a run re-saved later, for example when one of its files is removed, is not purged early. Files are saved as managed files, in `private://` when a private path is configured and otherwise in `public://` (the settings form warns about this). `hook_file_download()` serves a run file only to its owner. Administrators are denied, including when history is off and no run references the file.

Output from explorers not yet moved to run history goes through `ExplorerOutputFiles`, which keeps unguessable file names. These files go to `private://ai-explorers/` when a private path exists, otherwise to `temporary://ai-explorers/`. The settings form is `ExplorerSettingsForm`, with a confirmed "delete all runs" form (`ExplorerRunsDeleteAllForm`) and a local task on the explorers hub. Kernel tests cover limits, purge, anonymous users, Clear without history, file download access and the update hook.

## Upgrade

Run database updates: `ai_api_explorer_update_16001()` installs the entity type and creates `ai_api_explorer.settings` with history off. To use the history, enable it at `/admin/config/ai/explorers/settings` and adjust the limits. To let other roles manage it, grant `administer ai api explorer`.
