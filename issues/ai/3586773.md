## Summary

The AI API Explorer's "Code Example" output is now generated by a shared builder that exports user input as safe PHP literals. This replaces per-plugin HTML string concatenation, where quotes, `$`, backslashes or HTML in the input could produce broken or wrong PHP. The commit that shipped under this issue hardens the builder's edge cases: very large or small integers, floats, negative numbers after a minus sign, and user text inside comments. Copied examples therefore stay valid and reproduce the run.

## Impact

Affects module maintainers.

- **New API:** `Drupal\ai_api_explorer\CodeExample\CodeExample` and `PhpExporter` build explorer code examples as plain PHP text, escaping every exported value.

## Technical details

The shipped commit hardens the builder in `modules/ai_api_explorer/src/CodeExample/`. The builder itself was already in the repo, and I did not review the earlier commits that added it. `CodeExample::line()` takes a template where `@0`, `@1` and so on are replaced by `PhpExporter::export()` output, so values are never pasted into quotes by hand. `CodeExample::comment()` turns line breaks into spaces and rewrites `?>` as `? >`, so run text cannot close the PHP tag and turn the rest of the example into HTML.

`PhpExporter` now prints `PHP_INT_MIN` as the constant, because its digits read back as a float. Floats are exported with `serialize_precision` temporarily set to `-1` and then restored, so `0.1 + 0.2` keeps its exact value even on sites configured with precision 14. In `line()`, a negative exported value that directly follows a `-` is wrapped in parentheses (`1-(-1)`), which avoids producing the `--` decrement operator.

The unit tests in `CodeExampleTest` cover these cases and check that output parses with `CodeExample::parseError()`. `CodeExampleAssertionsTrait::codeFromElement()` now fails when no `pre` code panel is found, instead of passing as an empty example.
