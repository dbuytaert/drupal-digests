## Summary

The AI API explorer and other provider dropdowns now list both the new Symfony AI Platform based providers (configured as `ai_platform` entities) and the older legacy provider plugins, so both can be tested manually. Legacy providers are labelled `Legacy: ...` in these lists. The Configuration menu gets an `AI Platforms` entry, and the old providers entry is renamed `AI Legacy Providers`.

## Impact

Affects module maintainers and site owners.

- **Config change:** Admin menu: new `AI Platforms` link to `entity.ai_platform.collection`; `AI Platform Providers` link renamed `AI Legacy Providers`.
- **API change:** `AiProviderPluginManager::getProvidersForOperationType()` returns legacy `AiProvider` plugins (bare plugin id keys, labels prefixed `Legacy: `) as well as `ai_platform:<entity_id>` entries.

## Technical details

`AiProviderPluginManager::getProvidersForOperationType()` had been returning only `AiPlatform`-backed definitions. It now first iterates the discovered legacy `AiProvider` plugins, skipping those that fail to instantiate, don't support the operation type, or (when `$setup` is TRUE) aren't usable. It prefixes their label with `Legacy: `. It then adds one entry per `ai_platform` entity via `createPlatformProxy()`, keyed `ai_platform:<id>`. Legacy entries keep the bare plugin id as key, and the docblock says `::createInstance()` accepts both forms.

`AiProviderFormHelper::getAiProvidersOptions()` now delegates to `getProvidersForOperationType($operation_type, TRUE)` instead of building options from `getDefinitions()` itself, so form selects get the merged list. Test support changed too: the `echo` test platform label became `EchoAI` and its output string became `Hello world from the echo platform. Input: %s.`. A functional JS test, `testCreateChatMessageAndResponseViaAiPlatform`, was added to `ChatExplorerTest`. Other edits are docblock and description text fixes.
