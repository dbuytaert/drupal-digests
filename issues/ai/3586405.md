## Summary

The Translate Text Explorer in the AI API Explorer module has been rebuilt on the shared explorer layout. Source and target languages are now selects showing language names (the source defaults to "Detect automatically"), a swap button exchanges them, and the provider and model are chosen through the `ai_provider_configuration` element. Each run appears under Results with the source text, the translation, the detected language, a copy button and a generated PHP code example. Previously there was no code example, and provider metadata could print as "Array" with a PHP warning; an empty translation now shows as an error on the run.

## Impact

No upgrade or configuration changes required.

## Technical details

`TranslationGenerator` now builds its form with `buildLayout()` and `providerElement('translate_text', ...)` instead of `AiProviderFormHelper::generateAiProvidersForm()`. Submission goes through `executeRun()`, which stores each run (when run history is enabled) and renders Results from stored runs via `buildRunResults()`, `buildRunOutput()`, `runBadge()` and `buildRunCode()`. If history is off the explorer still works. The target is a single language per run. When the source is empty, `NULL` is passed to `TranslateTextInput` so the provider detects it.

The detected language is read from the output metadata key `detected_source_language` by the new static `detectedLanguage()`, which accepts a plain code, a list of codes, or an array with `language` or `code`. This replaces the old string cast of metadata. An empty translation throws a `RuntimeException` with a translated message, shown as an error run. Language names come from `LanguageManager::getStandardLanguageList()`. Code examples are built with `CodeExample`.

A new library `explorer.translate` (`css/explorers/translate.css`, `js/explorers/translate.js`) is attached explicitly, because the layout's automatic library name would be `explorer.translation`. The `aieTranslateSwap` behavior enables the swap button only when a source language is selected. The tests add a `TestTranslateProvider` (`ai_api_explorer_test_translate`) in `ai_api_explorer_test`, plus functional, JavaScript and unit tests, and the old `TranslationGeneratorTest` unit test is removed. The docs page now gives the path `/admin/config/ai/explorers/translation_generator`.
