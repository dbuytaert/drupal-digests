# #3586670: DeepChat block loads the whole jQuery UI dialog stack on every page

- **Project:** Drupal AI
- **Type:** Minor bug report
- **Status:** Fixed
- **Discussion:** [#3586670](https://git.drupalcode.org/project/ai/-/work_items/3586670) · 1 contributor · 46 comments

## Summary

Pages that show the DeepChat chatbot block no longer load Drupal's dialog JavaScript (including jQuery UI dialog) by default. The dialog is only needed for the structured results modal, so it is now loaded only when a chatbot block has `show_structured_results` enabled.

## Impact

Affects front-end developers.

- **Theme change:** The `ai_chatbot/deepchat` library no longer depends on `core/drupal.dialog.ajax`; custom code relying on it being loaded alongside the chatbot must attach its own dialog library.

## Technical details

The `core/drupal.dialog.ajax` dependency is removed from the `deepchat` library in `ai_chatbot.libraries.yml`. `DeepChatFormBlock::build()` now attaches `core/drupal.dialog` only when the chat processor plugin configuration has `show_structured_results` set. The lighter `core/drupal.dialog` is enough because `deepchat-init.js` opens the modal with `Drupal.dialog().showModal()` and never issues an Ajax dialog command, so `core/drupal.ajax` is no longer pulled in either.

In `deepchat-init.js` the dialog instance is now kept in a `dialog` variable and the close button calls `dialog.close()` instead of `Drupal.dialog.close()`. The `plugin_configuration` passed to `createInstance()` now falls back to `[]` when it is unset. The diff also adds a functional test and a functional JavaScript test for the on-demand attachment and modal, plus fixture changes in the `ai_chatbot_test` module.

## Upgrade

Custom code or themes that relied on the chatbot loading `core/drupal.dialog.ajax` should attach it themselves, for example `$build['#attached']['library'][] = 'core/drupal.dialog.ajax';`.
