## Summary

Enabling "Enable AI Automator" on a field without choosing an "AI Automator Type" no longer saves a broken setup. The Type select is now marked required when the checkbox is ticked, and the form shows "If you enable AI Automator, you have to choose an AI Automator Type." Before, the save went through and the "AI Automator Run Order" tab then failed with a `PluginNotFoundException` for the empty plugin ID.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `AiAutomatorFieldConfig`. The `automator_rule` element gets a `#states` `required` condition tied to `automator_enabled` being checked. `validateConfigValues()` is now attached to the form unconditionally, where before it was only added inside the branch that had a rule. Previously, with no rule selected, validation never ran. It now returns early with an error on `automator_rule` when the value is empty, before calling `findRule()`. The old loop over all `automator_*` form keys is gone. It ran the same checks once per matching key. The prompt, base field and rule-specific validation now run once.
