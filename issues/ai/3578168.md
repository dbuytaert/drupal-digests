## Summary

AI assistants backed by an AI agent now honor streaming output. Before, calling `streamedOutput(TRUE)` on an agent-backed assistant had no effect, and the whole response came back as one complete message. Now the response comes back as a streamed iterator, as it does for assistants without an agent.

## Impact

Affects module maintainers.

- **New API:** `AgentRunner::runAsAgent()` gains an optional trailing `bool $streaming = FALSE` parameter.

## Technical details

`AiAssistantApiRunner::process()` now passes `$this->streaming` as a new last argument to `AgentRunner::runAsAgent()`. When it is set, `runAsAgent()` calls `setStreamedOutput(TRUE)` on the `ChatInput` it gives the agent. If `solve()` returns a `StreamedChatMessageIteratorInterface`, the runner wraps it in a `ChatOutput` and returns it right away. Its normalized value is the iterator itself.

Persisting the agent thread state in the `ai_assistant_threads` temp store used to happen before `solve()`. It moved into a private `storeAgentState()` method. For streamed responses it runs from a callback registered with `$response->addCallback()`, so state is saved or deleted only once the stream completes. Non-streaming runs call it right after `solve()`. If the agent is not finished, the state is saved. Otherwise it is deleted.

The commit adds unit tests: `AgentRunnerStreamingTest` and `AiAssistantApiRunnerAgentStreamingTest`. The issue's remaining-tasks list also names a check of agents that need several LLM or tool-call loops before the final streamed answer. The diff has no test for that.

## Upgrade

Existing callers of `runAsAgent()` need no change, because the new parameter defaults to `FALSE`. To stream from code that calls it directly:

```php
$output = $agent_runner->runAsAgent($assistant_id, $chat_history, $defaults, $job_id, FALSE, [], TRUE);
```
