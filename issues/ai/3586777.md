## Summary

The `ai_json_schema` form element can now show a "Create with AI" button. The user describes the answer they want, an LLM (the site's default chat model) writes a JSON schema, and the user reviews it as a field list or as JSON before clicking "Use this schema" to fill the element. The schema is adjusted to OpenAI-style strict mode rules, and the dialog lists what was changed. The button is opt-in per element, so existing uses are unchanged. Using it requires the new `use ai json schema generator` permission. The shipped commit also hardens the generator: values in the review dialog are escaped once, empty objects are no longer written as `[]`, more schema constructs are handled, and model errors are logged.

## Impact

Affects module maintainers and site owners.

- **Permission change:** New `use ai json schema generator` permission gates the Create with AI dialog.
- **API change:** `JsonSchemaGeneratorInterface` gains `encode()`; messages and type labels from `normalize()`, `validate()` and `describeFields()` are now safe HTML.
- **New API:** `#ai_generate` and `#ai_generate_answer` on the `ai_json_schema` element; `JsonSchemaGeneratorInterface::encode()`.

## Technical details

The feature is split across the `ai` module's `AiJsonSchema` element (`#ai_generate`, `#ai_generate_answer`), the `ai.json_schema_generate` route (`/admin/config/ai/json-schema/generate`, `AiJsonSchemaGenerateForm`) and the `ai.json_schema_generator` service. The shipped commit (532289d5) is the hardening pass on those pieces. The base feature came in with the earlier commit 00a5a57ec, which also built the AI API Explorers layout.

In `JsonSchemaGenerator`, `normalize()` now also covers these cases:
- It applies strict rules inside `anyOf`, `oneOf`, `$defs` and `definitions`.
- It turns `const` into a one-item `enum`.
- It infers a missing `type` from `properties` or `items`.
- It gives an object with no fields an empty `properties` map and `additionalProperties: false`.
- It rewrites `oneOf` as `anyOf` only when the alternatives' types cannot overlap (`cannotOverlap()`). Otherwise `validate()` reports `oneOf` as unsupported.

`nullable()` adds `null` to every keyword that restricts values (`type`, `enum`, `anyOf`/`oneOf`) instead of always inventing a `type`. A `$ref` is wrapped as `anyOf: [$ref, {type: null}]`. `describeFields()` uses `acceptsNull()` to decide Required versus Can be empty. `validate()` also reports required names that don't exist in `properties`.

`JsonSchemaGeneratorInterface` gains `encode(array $schema): string`. It casts `properties`, `$defs` and `definitions` to objects so an empty map or one with numeric names is not written as a JSON list, which strict structured output rejects. The form's JSON view and `useCallback()` now use it. Messages from `normalize()`, `validate()` and the `type` label in `describeFields()` are now documented as safe HTML (values escaped once), and the form renders them as `#markup`. The form's error path also calls `Error::logException()` on the `ai` logger channel.

## Upgrade

To opt an element in:

```php
'#type' => 'ai_json_schema',
'#ai_generate' => TRUE,
'#ai_generate_answer' => $last_answer,
```

Grant `use ai json schema generator` to roles that should see the button. Custom classes implementing `JsonSchemaGeneratorInterface` must add `encode(array $schema): string`. Code that consumes the `normalize()` and `validate()` messages, or the `describeFields()` `type` labels, should render them as markup, not as plain text.
