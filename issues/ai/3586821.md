## Summary

Installing a module that alters Vector DB provider definitions now takes effect immediately. Before, the cached VDB provider plugin definitions were not cleared on module install, so the alter was missing until a manual cache rebuild. Config installed by that module could therefore run against the unaltered plugin class.

## Impact

No upgrade or configuration changes required.

## Technical details

The `ai.vdb_provider` plugin manager is not named `plugin.manager.*`, so core's `PluginManagerPass` never tagged it `plugin_manager_cache_clear`. `ai_modules_installed()` clears `ai_provider_plugins` but not `ai_vdb_provider_info_plugins`. The commit adds `tags: [{ name: plugin_manager_cache_clear }]` to `ai.vdb_provider` in `ai.services.yml`. This clears the definitions cache before config install, which a `hook_modules_installed()` implementation cannot do. The issue also notes that a 1.x backport of [#3535939](https://www.drupal.org/node/3535939) would help, but that is not part of this commit.

## Upgrade

No action needed. Rebuild caches once after updating so the container picks up the new service tag.
