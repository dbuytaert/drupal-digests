# #3586784: Let Decision models declare a minimum number of choice options

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3586784](https://git.drupalcode.org/project/ai/-/work_items/3586784) · 1 contributor · 18 comments

## Summary

Decision providers can now declare a minimum number of options for choice questions. Some backends need at least two options and previously could only fail after a round trip to the server, because the shared contract suite assumed a single option was valid. With a declared minimum, a choice question with too few options is rejected with `AiBadRequestException` before anything is sent. The provider's capability details now show the minimum next to the maximum. Existing declarations keep working unchanged.

## Impact

Affects module maintainers.

- **New API:** `DecisionCapabilities` gains a trailing nullable constructor argument and public property `minChoiceOptions` (NULL means unknown, a single option is accepted).

## Technical details

`DecisionCapabilities` takes `?int $minChoiceOptions = NULL` as the last constructor argument. The constructor throws `\InvalidArgumentException` if a minimum is set without `DecisionChoice` support, is below 1, or exceeds `maxChoiceOptions`. `DecisionRequestValidator::validate()` calls a new private `checkMinimum()` for choice questions, throwing `AiBadRequestException` ("supplied N choice options; the minimum is M") before the existing maximum check. An unknown (NULL) minimum is left to the provider.

`DecisionCapabilityDetails::limits()` now prints "Choice options: minimum X, maximum Y" (or "maximum Y", or "not supported" when choice is not declared). It also reports "not supported" for score levels when score is not declared. The markup string changed from "Maximum choice options: ..." to "Choice options: ...".

On the test side, `DecisionContractCases` builds choice questions with `max(1, minChoiceOptions)` options. `boundaries()` adds an accepted `choices/<min>` case and a rejected `choices/<min - 1>` case when the minimum is above 1. `DecisionProviderContractTestBase::testDecisionDeclarationsAndDiscovery()` now compares `minChoiceOptions` too. `docs/developers/decision_provider_contract.md` and `call_decision.md` document the limit.

## Upgrade

Providers whose models need more than one choice option can declare it in their capabilities, for example:

```php
new DecisionCapabilities([Capability::DecisionChoice], maxChoiceOptions: 26, minChoiceOptions: 2)
```

Providers that currently map a server 4xx for too few options can drop that workaround.
