## Summary

The Image-To-Image Explorer is redesigned on the shared explorer layout. You pick a source image (recent results, media library or upload), then a task: edit with a prompt, remove background, fill an area, or upscale. Only the settings relevant to the task and to the selected model are shown. For "Fill an area" you can paint the mask in a full-screen editor (brush, eraser, size, undo, invert, clear) instead of uploading a mask file. Results are stored as runs with before/after comparison, and failed runs keep an error with Retry. Provider and model selection now use the `ai_provider_configuration` element. A new "Flatten transparency onto white" option (on by default) addresses transparent PNG sources producing mostly empty edits.

## Technical details

`ImageToImageGenerator` was rewritten around `buildLayout()` and `executeRun()`, replacing `AiProviderFormHelper::generateAiProvidersForm()` with `providerElement('image_to_image', ...)`, with `modelDetails()` as the capability details callback. The source uses the `ai_api_explorer_file` element. `validateRun()` runs only for the `aie_run` trigger and checks the per-task prompt, rejects JPEG with a transparent background, and validates the painted mask: it must be a PNG data URL up to 20 MB and match the source image dimensions, so a provider does not reject it after a paid upload. Provider creation now goes through `createProviderFromValue()` inside the run callback, so failures are recorded on the run instead of thrown. Task settings are mapped to the model's `getAvailableConfiguration()` through `resolveSettings()`; settings the model does not list are reported as skipped. Result files are saved through `runManager()->saveFile()` with the MIME type taken from the image data, falling back to a known image type, so returned SVG or HTML is not served as claimed. The code example per run comes from the shared `CodeExample` builder.

The client side is in `js/explorers/image_to_image.js` and `css/explorers/image_to_image.css`, attached through the new `explorer.image_to_image` library. The mask editor is a `<dialog>` with a canvas. It keeps strokes as a list of steps so undo replays them. It exports an opaque black PNG with the painted areas transparent into the hidden `mask_data` field, and clears the mask if the source image changes. Retry presses the run button of the picked task. Tests add a `TestImageToImageProvider` (models `greyscale`, `inpainter`, `upscaler`) plus kernel and FunctionalJavascript tests.
