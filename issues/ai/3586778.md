## Summary

The AI API Explorer module gets a shared input picker for explorers that take an image or audio file. The user can choose a recent result from their own explorer runs, pick an item from the media library, or upload a file. A preview shows the chosen file with its type, size, and dimensions or length. Without run history the recent results are not shown. If Media or Media Library is off, the media option is replaced by a note giving the reason, or by a plain media autocomplete when only Media Library is missing. The commit shows the element working in a test explorer. The diff I could read does not show the existing file-input explorers being switched to it.

## Impact

Affects module maintainers.

- **New API:** New `ai_api_explorer_file` form element (`Drupal\ai_api_explorer\Element\ExplorerFile`) with `ExplorerFile::toOperationFile()`, plus a `media_library.opener` service and an `ai_api_explorer.file_forget` route.

## Technical details

The picker is a new form element, `ExplorerFile` (`#type` `ai_api_explorer_file`), in `modules/ai_api_explorer/src/Element/ExplorerFile.php`. Its value is `['fid' => ..., 'source' => 'recent'|'media'|'upload']`. Properties are `#media_type` (image, audio or video), `#operation_type`, `#extensions`, `#recent` and `#media`. Accepted extensions come from `#extensions`, else from the `OPERATION_EXTENSIONS` map for the operation type (for example `speech_to_text` audio: mp3 m4a mp4 wav webm ogg flac), else from per-media-type defaults. Every source goes through `ExplorerFile::accepts()`, which checks extension and MIME type. A recent result or media item therefore cannot bring in a format that an upload would be refused for. MP4 and WebM files that Drupal detects as video are allowed as audio.

On validation, a recent or uploaded file must belong to the current user and the user needs `access ai prompt`. Uploads must also be files stored by the explorers (`isRunFile()`). Media items must pass `access('view')` and belong to a media type whose source is the right kind. `ExplorerFile::toOperationFile()` turns the file entity into an `ImageFile`, `AudioFile`, `VideoFile` or `GenericFile` carrying the file's real MIME type.

When Media Library is enabled, a new `AiApiExplorerServiceProvider` registers `ExplorerFileOpener` as a `media_library.opener`. It returns the picked item to the picker by AJAX and refuses files the picker does not accept. A required picker with no default value takes the `?file=` query parameter, which is how "Use as source" links can preselect a file. This only works for the user's own files stored by the explorers. A new `ai_api_explorer.file_forget` POST route and a hover button on the thumbnails let users remove a file from recent files. A `file` library (`explorer-file.js` and `explorer-file.css`) drives the preview and the clear and remove buttons. The commit also adds a `PickerTestExplorer` in `ai_api_explorer_test`, which calls `useAsSourceLink()` from the plugin base class. Kernel and functional tests were added but were not in the diff I could read.

## Upgrade

Explorer plugin authors can replace a custom upload field with the element:

```php
$form['setup']['image'] = [
  '#type' => 'ai_api_explorer_file',
  '#title' => $this->t('Source image'),
  '#media_type' => 'image',
  '#extensions' => 'png jpg jpeg',
  '#required' => TRUE,
];
```

Then on submit, turn the picked file into an operation input:

```php
$value = $form_state->getValue('image');
$operation_file = ExplorerFile::toOperationFile(File::load($value['fid']));
```
