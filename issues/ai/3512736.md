## Summary

The AI Chatbot block no longer crashes with a `TypeError` when it has no valid AI Assistant, for example when no provider is configured or the assistant can't be loaded. Instead it renders a short message saying the assistant is missing or couldn't be loaded. The assistant field in the block configuration form is now required, so new blocks can't be saved without one.

## Impact

No upgrade or configuration changes required.

## Technical details

In `ChatFormBlock::build()` the configured `ai_assistant` value was loaded straight from entity storage and passed to `AiAssistantApiRunner::setAssistant()`, which is typed to `AiAssistant`, so a null load result caused a fatal error. `build()` now returns a `#markup` message if the configured ID is not a non-empty string. It returns a different `#markup` message if the loaded entity is not an `AiAssistant` instance. Only after both checks does it call `setAssistant()`. In `blockForm()` the `ai_assistant` select element gets `#required => TRUE`. The required flag overlaps with [#3520273](https://www.drupal.org/node/3520273), which was already RTBC at the time and which a commenter pointed to for that part.

## Upgrade

Existing placed chatbot blocks with no assistant selected will now show the message text instead of erroring. Re-save them with an assistant selected.
