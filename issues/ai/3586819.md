## Summary

An AI Chatbot block with no AI Assistant selected no longer triggers an `array_flip()` PHP warning in the log. This showed up on sites where a page builder or similar tool creates every block plugin with default configuration and checks access on each one. The unconfigured block is now simply treated as not accessible.

## Impact

No upgrade or configuration changes required.

## Technical details

`ChatFormBlock::blockAccess()` passed `$this->configuration['ai_assistant']` straight to the `ai_assistant` entity storage `load()`. With default configuration that value is empty, so `EntityStorageBase::loadMultiple()` received `[NULL]` and logged the warning. `blockAccess()` now reads the ID first and returns `AccessResult::forbidden('No AI Assistant configured.')` when it is not a non-empty string. Otherwise it loads the entity and runs the existing exists and enabled checks. This matches the guard already in `ChatFormBlock::build()` and the unconfigured handling in `DeepChatFormBlock::blockAccess()` ([#3577813](https://www.drupal.org/node/3577813)).
