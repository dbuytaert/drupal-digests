## Summary

The AI module's hostname filter treated JSON responses as HTML, so the result often no longer decoded. This hit structured output and any JSON built from HTML-containing strings, and some sites turned on full trust mode to get around it. Now JSON objects or arrays are detected and filtered one string at a time, so they stay valid JSON. A clean payload comes back unchanged, and only the strings that had a disallowed URL or unsafe markup are rewritten. Chat requests that set a structured output schema, streamed ones included, are filtered this way automatically. Callers can opt out with `jsonMode: FALSE`.

## Impact

Affects module maintainers and site owners.

- **Config change:** No stored configuration changed. `jsonMode` is a per-request option on `HostnameFilterDto`.
- **New API:** New `jsonMode` option on `HostnameFilterDto`, and `HostnameFilter::setJsonMode()`; structured output responses enable it automatically.

## Technical details

`HostnameFilter::filterText()` now calls `filterJsonText()` before the Markdown and HTML5 round trip. It recognises text that is wholly a JSON object or array, or a single fenced block (` ``` ` or `~~~`, `json*` tag, closing fence optional). Every string, keys included, is filtered through the new `filterScalarString()` and rewritten only if it changed. Numbers and whitespace stay as they were. Strings that are themselves JSON documents are handled recursively, up to depth 8. If the filtered raw text still reads as unsafe, for example when an escape such as `\u0027` hides an attribute, the payload is re-encoded with `<`, `>`, `&` and quotes as `\u` escapes. If that still fails, the regular pipeline takes over.

`filterHtmlLinks()` now returns a bool saying whether it modified the tree. The HTML5 serializer output is used only when it did, so strings with a stray `<` or `&` are not entity-encoded. The unused `processElements()` helper was removed.

The new `HostnameFilter::setJsonMode()`, `HostnameFilterDto::$jsonMode` and the `jsonMode` key in `snapshotSettings()` and `restoreSettings()` cover text that does not decode, such as malformed or truncated JSON or a partial stream chunk. With `jsonMode` on, that text gets plain-text URL removal plus the DOM walk, and is rewritten only when something unsafe is found. `ProviderProxy` and `StreamedChatMessageIterator` turn it on for the duration of a call when `ChatInput::getChatStructuredJsonSchema()` is non-empty and the caller's DTO leaves `jsonMode` as NULL. They restore the singleton filter's settings afterwards. A streamed chunk is not decodable on its own, so a chunk that loses unsafe markup may no longer be valid JSON.

Related change: when a disallowed URL is removed in plain text, a trailing backslash is kept. That keeps the closing `\"` of a JSON string intact.

## Upgrade

To opt out of the automatic JSON mode for a structured output request:

```php
$input->setHostnameFilter(new HostnameFilterDto(jsonMode: FALSE));
```

Sites that enabled full trust mode only to keep JSON decodable can try removing it.
