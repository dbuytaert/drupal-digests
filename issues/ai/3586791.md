# #3586791: Add Refusal Answer type to support OpenAI Decision API

- **Project:** Drupal AI
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3586791](https://git.drupalcode.org/project/ai/-/work_items/3586791) · 1 contributor · 6 comments

## Summary

The AI module's Decision operation can now represent a model declining to answer an individual question. Previously a refusal, which OpenAI's Decision API can return, was treated as broken output and failed the whole response. Models that declare the new `decision_refusals` capability may now refuse single questions while the other answers stay usable. Refusals from models that don't declare it still count as broken output.

## Impact

Affects module maintainers.

- **API change:** `AnswerValidation::forQuestion()` gains an optional third parameter `$allow_refusal` (default `FALSE`); `AnswerFactory::fromArray()` accepts a `refusal` type.
- **New API:** New `RefusalAnswer` value, `AiModelCapability::DecisionRefusals`, `AiDecisionRefusedException`, and `DecisionResponse::isRefused()` / `getRefusals()`.

## Technical details

A new `final` class `Drupal\ai\OperationType\Decision\Value\RefusalAnswer` implements `AnswerInterface`. Its type is `'refusal'` (`RefusalAnswer::TYPE`), `getRaw()` keeps the provider's wire data, and `toArray()` returns only `['type' => 'refusal']`. `AnswerFactory::fromArray()` gains a `refusal` case.

`AnswerValidation::forQuestion()` takes a third parameter `bool $allow_refusal = FALSE`. A `RefusalAnswer` is accepted for any question type when it is TRUE, and otherwise throws `\InvalidArgumentException`. `DecisionValidationEventSubscriber::postGenerate()` only resolves the model's capabilities when the answer is a refusal. It checks the provider's `getDecisionCapabilities()` for `AiModelCapability::DecisionRefusals`. If the provider or model can't be resolved, it counts as not declared, and the `InvalidArgumentException` becomes `AiBrokenOutputException`.

On `DecisionResponse`, `isRefused($id)` and `getRefusals()` (question ids) were added. `getNoul()`, `getChoice()` and `getScore()` now throw the new `AiDecisionRefusedException` (an `\UnexpectedValueException` implementing `AiExceptionInterface`) when the question was refused, instead of the type-mismatch error. The capability's enum value is `decision_refusals`, in the `decision` operation type group.

## Upgrade

Provider authors whose Decision API can decline a question should declare the capability and return a refusal answer:

```php
AiModelCapability::DecisionRefusals
// wire answer: ['type' => 'refusal', ...]; AnswerFactory::fromArray() turns it into RefusalAnswer
```

Callers of `DecisionResponse` should check `isRefused($id)` or `getRefusals()` before calling `getNoul()`, `getChoice()` or `getScore()`, or catch `AiDecisionRefusedException`.
