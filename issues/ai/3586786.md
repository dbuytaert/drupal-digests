## Summary

Duplicating AI config entities (assistants, guardrails, guardrail sets, prompts, prompt types, automators, automator tools and automator chain types) with the entity API's `createDuplicate()` no longer crashes with a `TypeError`. Code that clones these entities, including contrib modules such as Entity Clone, now gets an unsaved copy with no ID and a new UUID.

## Impact

No upgrade or configuration changes required.

## Technical details

`EntityBase::createDuplicate()` sets the ID key of the clone to `NULL`. The eight entity classes declared `protected string $id;`, so that assignment failed. Each now declares `protected ?string $id = NULL;`, matching core config entities. The affected classes are `AiGuardrail`, `AiGuardrailSet`, `AiPrompt`, `AiPromptType`, `AiAssistant`, `AiAutomator`, `AutomatorsTool` and `AutomatorChainType`. `id()` already returns `string|int|null`, so the public API does not change. The commit adds three kernel tests (`ConfigEntityDuplicateTest`, `AiAssistantDuplicateTest`, `AutomatorEntityDuplicateTest`). They call `createDuplicate()` on each entity type and assert that the ID is null, the UUID differs and the original keeps its ID. I did not check whether other code reads `$this->id` directly and assumes a string. The issue lists that as a remaining task, and the diff does not touch such code.
