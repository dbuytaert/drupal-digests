## Summary

When the AI ECA submodule was replaced by the standalone `ai_integration_eca` module, any ECA model using an AI action (for example the Chat action) was deleted during the database update, without a warning. The update now rewrites those ECA models so they depend on the new module and use the new plugin IDs, and the models survive the upgrade.

## Impact

Affects site owners.

- **Database update:** `ai_eca_update_11001()` now rewrites existing `eca.eca.*` config: module dependencies and `ai_eca_*` action plugin IDs are migrated to `ai_integration_eca` equivalents before the old submodule is uninstalled.

## Technical details

ECA models that use AI plugins list `ai_eca` under `dependencies.module`. Uninstalling that module in `ai_eca_update_11001()` caused Drupal to delete the dependent config entities. The update hook now runs the migration first. It loops over all `eca` entities but loads each one with `\Drupal::configFactory()->getEditable('eca.eca.' . $eca->id())` instead of saving the entity. Saving the entity through `ECA::load()` re-adds the old dependency on pre-save, while editable config avoids that.

For each model, `ai_eca` is replaced by `ai_integration_eca` and `ai_eca_agents` by `ai_integration_eca_agents`, at the same array key so the list is not reindexed. When a migration applied, each action whose `plugin` starts with `ai_eca_` is rewritten to `ai_integration_eca_*`. The action's machine name (the config key) is left unchanged. If the target plugin is not defined in `plugin.manager.eca.action`, a warning is logged on the `ai_eca` channel and that action is removed from the model. The `eca_ai_trigger_agent` plugin ID in the agents submodule does not start with `ai_eca_`, so it is not touched. The existing logic that installs `ai_integration_eca` and uninstalls `ai_eca` is unchanged, apart from the `$installer` service now being fetched once at the top of the function.

## Upgrade

Sites that already ran the update without this fix and lost models need to restore the ECA config from CMI or a backup. Before importing, replace `ai_eca` with `ai_integration_eca` in the module dependencies and rename the plugin IDs from `ai_eca_*` to `ai_integration_eca_*`, as jurgenhaas described in the thread.
