## Summary

The AI DeepChat Chatbot block has a new Loading strategy option under its advanced settings. Previously the Deep Chat JavaScript bundle (about 98 KB gzipped) loaded on every page where the block was placed, even though most visitors never open the chat. You can now choose to load it on page load (the old behavior and the default), when the browser is idle, or only on first interaction. With the interaction option the bundle is not downloaded until the visitor hovers over or focuses the chat launcher, and it is only run once the chat is opened. Existing blocks keep the old behavior until you change the setting.

## Impact

Affects module maintainers, front-end developers and site owners.

- **Config change:** New `load_strategy` setting (`eager`, `idle`, `interaction`) on the `ai_deepchat_block` block, default `eager`; no update hook needed since missing values fall back to `eager`.
- **Theme change:** With `idle` or `interaction`, no `<script>` tag for `deepchat.bundle.js` is output; it is imported by `deepchat-init.js` at runtime.
- **New API:** New library `ai_chatbot/deepchat.bundle` holding only `deepchat/deepchat.bundle.js`; `Drupal.aiDeepchat.load()` and `Drupal.aiDeepchat.whenNeeded()` JS helpers.

## Technical details

The bundle was split out of the `ai_chatbot/deepchat` library into a new `ai_chatbot/deepchat.bundle` library. `ai_chatbot/deepchat` now holds only `js/deepchat-init.js` and its dependencies. It also dropped `core/jquery` and `core/drupal.ajax` and gained `core/once`. `DeepChatFormBlock::build()` attaches `ai_chatbot/deepchat.bundle` only for `eager`. For `idle` and `interaction` it passes `load_strategy` and a cache-busted `bundle_url` (from the new `getBundleUrl()`, using `library.discovery` and `asset.query_string`) in `drupalSettings.ai_deepchat`. The strategy is resolved in the browser rather than on the server because the "remember" toggle state lives in `localStorage`, and deciding server side would need a per-user cache context and make the block uncacheable.

`deepchat-init.js` now defines `Drupal.aiDeepchat.load()`, which does a single dynamic `import(url)` and then waits on `customElements.whenDefined('deep-chat')`. `Drupal.aiDeepchat.whenNeeded()` wraps the existing `deepChatToggle` behavior setup so the `<deep-chat>` element is configured only after the bundle has loaded. For `idle` it uses `requestIdleCallback`, falling back to a 1s `setTimeout`. For `interaction` it watches for the open state with a `MutationObserver`: the `ai-chatbot-opened` class on `<body>` for the toolbar placement, or `chat-open` on `.chat-container` for the other placements. Hover or focus on the launcher adds a `<link rel="modulepreload">` so the fetch is usually done by the click. If `bundle_url` is empty, a console error is logged and the chat is not initialised. The config schema adds `load_strategy` with a `Choice` constraint. Tests added: a functional test for which strategies attach the bundle, and a FunctionalJavascript test `DeepChatLazyLoadTest` using resource timings.

## Upgrade

Custom code or themes that attach `ai_chatbot/deepchat` and expect `deepchat.bundle.js` to come with it must now also attach the new library:

```php
$build['#attached']['library'][] = 'ai_chatbot/deepchat.bundle';
```

Code that relied on `ai_chatbot/deepchat` pulling in `core/jquery` or `core/drupal.ajax` should declare those dependencies itself.
