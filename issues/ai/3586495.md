## Summary

Embeddings now work with the new symfony/ai platform layer. A platform plugin whose model catalog has an embeddings-capable model reports `embeddings` as a supported operation type. It is returned by `getProvidersForOperationType('embeddings')`. Existing code that calls `$provider->embeddings()` keeps working against these platforms, as does batch embedding. The AI settings form now also lists platform-based providers as default-provider choices.

## Impact

Affects module maintainers.

- **API change:** `AiPlatformPluginBase` now takes a `LoggerInterface $logger` constructor argument and has a `create()` factory; `getSupportedOperationTypes()` is derived from the model catalog instead of always returning `chat`.
- **New API:** `PlatformProxy` implements `EmbeddingsInterface` and `EmbeddingsCollectionInterface`; new `AiProviderPluginManager::getAllProviders()`; `InputOutputConverter::toEmbeddingsOutput()` and `toEmbeddingsCollectionOutput()`.

## Technical details

`PlatformProxy` now implements `EmbeddingsInterface` and `EmbeddingsCollectionInterface` and uses `EmbeddingsTrait`. `embeddings()` sends the prompt string through `invoke()`, and `InputOutputConverter::toEmbeddingsOutput()` takes the first vector from `DeferredResult::asVectors()`. `embeddingsCollection()` sends all prompts as one batch, and `toEmbeddingsCollectionOutput()` keeps every vector in order. If the platform returns a different number of vectors than prompts, it throws `AiResponseErrorException`, so consumers that map vectors positionally can fall back to single-input calls. An empty prompt list returns an empty output. `getPlugin()` returns the proxy itself so legacy `getPlugin() instanceof EmbeddingsCollectionInterface` checks work. `isUsable($operation_type)` now checks the operation type against `getSupportedOperationTypes()`.

`AiPlatformPluginBase::getSupportedOperationTypes()` now scans the model catalog. `Capability::INPUT_MESSAGES` gives `chat` and `Capability::EMBEDDINGS` gives `embeddings`. A catalog exception is logged as a warning and no operations are reported. The base class now has a constructor with a `$logger` (the `ai` channel) and a `create()` factory. `AiManagedPlatform`, `AiProviderPlatform` and `PlatformWithModelRouting` were changed from `new self(...)` to `parent::create(...)`.

`AiProviderPluginManager::getAllProviders()` merges legacy providers and non-backend-only platform proxies (keys prefixed `ai_platform:`), with no operation type or usability filter. `AiSettingsForm` uses it and keys the options by that array key. The `ai_test` `EchoProvider` and a new `EchoAiPlatform` gained an `echo-embedding` model for tests.

## Upgrade

Custom `AiPlatformPluginBase` subclasses that instantiate themselves in `create()` must go through the parent factory so the logger is injected:

```php
// Before
$instance = new self($configuration, $plugin_id, $plugin_definition);
// After
$instance = parent::create($container, $configuration, $plugin_id, $plugin_definition);
```

Subclasses that override the constructor need to accept the added `LoggerInterface $logger` argument. Platforms that relied on the default `['chat']` operation list now get it from their model catalog capabilities, so check that the catalog declares the right `Capability` values.
