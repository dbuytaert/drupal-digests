## Summary

The AI API Explorers that handle images, audio or video can now export a run as a `.tar.gz` archive and import it again. Each run card gets an Export button, and the explorer's Import button opens an archive upload dialog instead of the JSON one. The archive holds the run's input, settings and its input and output files, so a run can be moved to another site with its files. Explorers that only handle text keep the JSON export.

## Impact

Affects module maintainers.

- **New API:** `AiApiExplorerPluginBase` gains `supportsArchiveExport()`, `archiveFileKeys()` and `importArchiveInput()` hooks, plus the new `ExplorerRunArchive` class.

## Technical details

The base class `AiApiExplorerPluginBase` gets an opt-in `supportsArchiveExport()` (default `FALSE`), and `supportsImportExport()` now covers either JSON or archive support. An explorer that opts in lists where file IDs sit in its input via `archiveFileKeys()` (dot-separated keys mapped to image, audio or video). On export, `buildArchive()` replaces each file ID in the input with `path`, `filename` and `mime_type`, puts input files under `files/input/` and every other file of the run under `files/output/`, and wraps the result in the same envelope as the JSON export (`exportEnvelope()`). Export is a per-run submit button, because without run history the run only exists in form state. It answers with a `BinaryFileResponse` that is deleted after sending. The form cache is disabled for that response so the page keeps working.

The new `ExplorerRunArchive` class reads and writes archives with core's `ArchiveTar`. It never extracts to disk: entries are listed, checked and read into strings. Limits in the code: 32 MiB archive (`MAX_BYTES`), 128 MiB unpacked (`MAX_TOTAL_BYTES`), 1 MiB `run.json` (`MAX_RUN_BYTES`), 64 entries (`MAX_ENTRIES`). A response too large for `run.json` is written to `files/output/response.json`, which import ignores. On import, `importArchiveFile()` checks each file's extension against the list the explorer's file picker offers (`archiveExtensions()`), checks that images decode with `getimagesizefromstring()`, rejects empty files, and saves it with `runManager()->saveFile()`. Import is all or nothing: if one file fails, the files already saved are deleted. Import also now clears every field of the form from user input so the imported run replaces what was shown. `importPlainValues()` keeps only scalars and lists of scalars from the imported input.
