## Summary

The Decision Explorer, the admin page in `ai_api_explorer` for trying decision calls, is rebuilt on the shared explorer layout. The state can be entered as named fields or JSON. Questions appear as cards instead of a JSON text box. The page lists what the questions need from the model. Answers show as charts, and a box answer is drawn on each uploaded image. Export JSON saves the form, and Import JSON loads a saved form or run back in. A run can be edited and run again.

## Technical details

The change is mostly in `DecisionGenerator.php`, with new `js/explorers/decision.js` and `css/explorers/decision.css` files. A new `explorer.decision` library is declared in the module's libraries file, depending on `ai_api_explorer/explorer_ui` and `ai_api_explorer/media`. Per the existing comment in that file, `AiApiExplorerPluginBase::buildLayout()` attaches only this explorer's own assets. The explorer keeps the `ai_provider_configuration` element, so only models declaring the features the parsed request needs are listed, and the selected model's features and limits are shown. Incompatible selections and entered criteria are kept for correction.

A refused question is labelled "Refused" and shows no distribution. A box question needs an image. The box is drawn over each image with its edges in pixels.

The export format builds on `DecisionInput::toArray()`. It has `format` set to `ai_api_explorer_decision`, `version`, `title`, `input` (`state`, `questions`, `files`), and optional `settings` and `response`. Import also accepts any JSON with `state` and `questions`. Exported runs list images by name only, and the form export leaves images out. An image can be included by adding `base64`, plain or as a data URL. Imported images must be PNG, JPEG, GIF or WebP and at most 10 MB. `settings` is applied only if "Also use the model saved in the file" is checked, and `response` is ignored.
