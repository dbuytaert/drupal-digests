## Summary

The Fields tab of an AI Search index no longer throws "Undefined array key bundles" and "Trying to access array offset on null" warnings when the indexed entity type has no bundles, such as a custom single-type content entity. The "Preview content to be vectorized" item checker, which did not work for these entities, now appears and works. The fix is in the 1.2.x and 1.1.x branches.

## Impact

No upgrade or configuration changes required.

## Technical details

In `AiSearchIndexFieldsForm::buildForm()` the datasource configuration was read as `$configuration['bundles']['default']`, which fails when no `bundles` key exists. It is now guarded with `!empty(...)`. The checker's `entity_autocomplete` element was previously only built when `$current_type && $current_bundles`. It is now built whenever `$current_type` is set, and `#selection_settings` only carries `target_bundles` when `$current_bundles` is non-empty. The same diff was committed to 1.2.x (`1d684457`) and to 1.1.x (`bed5b32d`). The 1.1.x backport landed later, after it was noticed to be missing.
