## Summary

The Tools explorer in `ai_api_explorer` is rebuilt on the shared explorer layout. It lists tools in collapsible groups with a search field. A card shows the picked tool's function name, plugin ID, group and whether it likely only reads or may change the site. Arguments are typed and marked as required, and limits and **Run as** sit in the same form. Results show structured output as a table, with the raw output one click away. Each run also gets a PHP code example. Tools that may change the site ask for confirmation before they run. The explorer no longer needs a chat provider to open, since tools use no model. Several bugs are fixed: **Run as** was ignored, tool output was not escaped, and an empty limit value triggered PHP warnings.

## Impact

No upgrade or configuration changes required.

## Technical details

`ToolsExplorer::isActive()` now returns `TRUE`, so the explorer no longer depends on the `chat` operation type. The hub card shows the tool count via `getHubSummary()`. The form is built from the shared shell and components, with explorer-specific files attached through a new `explorer.tools` library in `ai_api_explorer.libraries.yml` (`css/explorers/tools.css`, `js/explorers/tools.js`). The JS handles tool search, "Show more" for long groups, and "Show all N rows" for long output tables. The table/raw switch is the shared `ExplorerUi::viewSwitch()`.

Runs go through `executeRun()`, so they are stored with the run history when it is enabled and the explorer still works with it off. Each run records the function name, group and who it ran as. **Run as** is now applied: `runAsAccount()` switches with the injected `AccountSwitcherInterface` and switches back in a `finally` block. Role options in `runAsOptions()` are limited to the current user's own roles plus anonymous and authenticated, and only roles whose permissions are a subset of the user's. Users with `administer permissions` may pick any such role. The switched session keeps the current user ID via `runAsUid()` (user 1 uses 0), so "edit own" permissions do not match content owned by anonymous. Access-denied results are detected from exception messages and from `status: access_denied` in action tool output, and are shown as access errors.

Argument and limit validation failures are stored as failed runs with a Retry action, not form errors. `limitConstraints()` rejects a limit with no values with a message instead of calling `explode()` on `NULL`. Output goes through `Html::escape()` in the table cells and raw `<pre>` view. Read versus write is a guess from the tool's group: `READ_GROUPS` (`information_tools`, `context_tools`) run immediately, and `WRITE_GROUPS` need a confirm checkbox. A test tool plugin `ai_api_explorer_test:list_colors` and Functional and FunctionalJavascript tests were added. `SetupNeededTest` now expects no setup screen for this explorer.
