## Summary

On 1.6.x the Tools Explorer showed no argument fields for tools provided by Tool API, such as Tool Belt's "Log message", so those tools could not be run with input. The explorer now shows and submits arguments for Tool API tools again, as it did on 1.5.x.

## Impact

No upgrade or configuration changes required.

## Technical details

`ToolsExplorer::argumentElements()` skipped every definition that was not a core `ContextDefinitionInterface`, and Tool API tools describe input with `Drupal\tool\TypedData\InputDefinition`, so all arguments were dropped. A new `ToolsExplorer::arguments()` method now instantiates the tool through `functionCallPluginManager->createInstance()` and, if it is a `ContextAwarePluginInterface`, uses `getContextDefinitions()`, which gives the context definitions the tool adapts its own input definitions to. If the tool cannot be created (any `\Throwable`), it falls back to the `context_definitions` in the plugin definition. The result is filtered to `ContextDefinitionInterface` instances and cached per tool ID in a private `$arguments` property. `argumentElements()`, `callValues()` and the run submit handler now use this method instead of reading `context_definitions` from the plugin definition.

A hidden test module `ai_api_explorer_tool_test` provides an `ai_api_explorer_echo_text` Tool API tool, and `ToolsExplorerTest::testToolApiArguments()` covers it. The test is skipped when Tool API is missing or incompatible, including on Drupal 12.
