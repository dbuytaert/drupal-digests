## Summary

The AI module 2.x now works with Symfony AI Platform 0.14.1 instead of being pinned to 0.12. It also fixes streamed chat, which crashed with "Object of class ... could not be converted to string" whenever the model sent reasoning or tool call chunks. Models that reason before answering, such as NVIDIA ones, failed on every streamed chat. Streamed tool calls are now passed through to Drupal.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `symfony/ai-platform` now requires `^0.14.1`, `symfony/ai-generic-platform` `^0.14`, and dev `symfony/ai-gemini-platform` `^0.14` (previously `^0.12`).
- **New API:** New `Drupal\ai\Exception\AiStreamException` (implements `AiExceptionInterface`); `InputOutputConverter` constructor takes an optional logger.

## Technical details

`InputOutputConverter::toStreamedChatOutput()` used to cast every stream delta to string, which only works for `TextDelta`. The anonymous `StreamedChatMessageIterator::doIterate()` now maps deltas by type. `TextDelta` becomes a text chunk. `ToolCallComplete` becomes a chunk of OpenAI-shaped `CreateStreamedResponseToolCall` objects, one whole call each, which is the format the Drupal iterator reassembles tool calls from. Calls with an empty id (Gemini before 3.0) get a `call_<index>` id, and empty arguments are encoded as an empty JSON object. `ToolCallStart`, `ToolInputDelta`, the `Thinking*` deltas and `MetadataDelta` are skipped. Any other delta is skipped with a warning on the new `logger.channel.ai` channel, which is injected into `ai.symfony.input_output_converter`. A `ChoiceDelta` (multi-candidate stream) throws the new `AiStreamException`.

Tool schema building in the same class changed to match the 0.14 expectations. Each property now always carries a `description` and has its `name` key removed. The parameters array always includes `required` (possibly empty) and `additionalProperties => FALSE`. The Generic bridge now completes tool calls on any finish reason, which is why the stream fix matters more on 0.14. The issue lists follow-ups not covered here: no finish reason or token usage in streamed output, empty non-streamed token usage, Gemini text plus tool call losing the tool call, and the platform route ignoring `ai.settings:request_timeout`.

## Upgrade

Update the Composer constraints. The requirements now resolve to:

```json
"symfony/ai-platform": "^0.14.1",
"symfony/ai-generic-platform": "^0.14"
```

Run `composer update drupal/ai --with-all-dependencies`. Custom code that constructs `InputOutputConverter` directly can still do so, since the logger argument is optional.
