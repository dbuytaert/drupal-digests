## Technical details

The plugin `AudioToAudioGenerator` drops `AiProviderFormHelper::generateAiProvidersForm()` and uses the `ai_provider_configuration` element through `providerElement('audio_to_audio', ...)`. File input is the shared `ai_api_explorer_file` element. Each run goes through `executeRun()`, so it is stored as an explorer run and results are rendered from stored runs by `buildRunOutput()`, with a per run code example from `buildRunCode()` using the shared `CodeExample` builder. New assets `explorer.audio_to_audio` (`css/explorers/audio_to_audio.css`, `js/explorers/audio_to_audio.js`) are registered in `ai_api_explorer.libraries.yml`; the JS only switches the run button label and hint per task.

The old failure came from passing the `AudioFile[]` returned by `getNormalized()` straight to `saveData()`. The new code treats every normalized item as its own file and saves each with `runManager()->saveFile()`, so a model that splits audio can return two files. The result file's extension and MIME type follow the audio the provider returns, with a notice when it differs from the requested format.

The audio to audio operation takes only the audio, so the task options (strength, keep room sound, sample rate, which part to keep, output format) are sent through the provider configuration. `mapOptions()` matches each option to a model configuration key from `OPTION_KEYS` (for example `strength`, `noise_reduction`, `denoise_strength`) only when that field can take the value (`fieldTakes()`). Matched fields are hidden from the model's own settings; options the model has no usable setting for are listed in a notice on the run, and the model uses its own value.

The docs page for the explorer is updated: the example uses `audio/mpeg` instead of `audio/mp3` and reads `getNormalized()[0]`, and the explorer path and name are corrected.
