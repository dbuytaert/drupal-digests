## Summary

The Text to Image explorer in AI API Explorer has been rebuilt on the shared explorer layout. The prompt and settings sit on the left and results on the right. Size is picked from shape tiles, and the number of images is a stepper. Quality and format are segmented controls. Each run is kept with its prompt and settings when run history is on, and shows progress while generating. Images open in a preview with download, use as source in Image to image, and save to media library. On phones the settings open in a bottom sheet. Generated files now get the extension that matches the real image format (PNG, JPEG or WebP) instead of always `.png`, and the code example no longer calls a nonexistent method.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** `ai-api-explorer-image.html.twig` renders a `.aie-lightbox__head` wrapper with an optional `title_label` and `title_actions` around the title.
- **New API:** `ExplorerUi::image()` and the image viewer template accept `title_label` and `title_actions` options.

## Technical details

`TextToImageGenerator` now builds its form on the shared layout and replaces `AiProviderFormHelper::generateAiProvidersForm()` with the `ai_provider_configuration` element via `providerElement()`. The size, quality, format and count fields are filled in by `processImageSettings()` from the selected model's definition and replaced when the model changes. Every size the provider lists for the model is offered. The code does not disable sizes the model cannot make, and says so in a comment: a size the model refuses shows as an error on the run, and a size the model adjusts shows as the size that came back. The OpenAI `1792x1024` and `1024x1792` listing and the missing `auto` size are not fixed here, as the issue says this needs a follow-up in the provider.

The file extension and MIME type are detected from the image data first, then from the provider's file name (`imageType()`), and are used for the saved run file, the download and the media entity. The code example is generated per run in `buildRunCode()`. It uses `getRawOutput()` and the real extension. Save to media uses a hidden submit button filled in by `text_to_image.js`, it only works for the current user's runs, it is disabled with a reason when media cannot be created, and saving an image twice does not create a second media item.

The shared image viewer gets `title_label` and `title_actions` options (`ExplorerUi::image()`, the default in `AiApiExplorer`, and `ai-api-explorer-image.html.twig`). A new `explorer.text_to_image` library holds the CSS and JS. The `ai_api_explorer_test` module gains a test text to image provider, and a functional test covers generation, formats and media saving. The docs now give the new explorer path `/admin/config/ai/explorers/text_to_image_generator`. `AiApiExplorerInterface::getAjaxResponseId()` documentation now allows a static method.
