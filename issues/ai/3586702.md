# #3586702: Emit automator config ID tag and entity_context on chat requests

- **Project:** Drupal AI
- **Type:** Normal task
- **Status:** Fixed
- **Discussion:** [#3586702](https://git.drupalcode.org/project/ai/-/work_items/3586702) · 1 contributor · 23 comments

## Summary

Chat requests sent by AI Automators now identify which automator config entity produced them. Previously, several automators on the same field (for example Default, Short summary and Bullet outline on one body field) sent identical tags, so event subscribers could not tell them apart. Requests now also carry structured entity information, including for unsaved entities where the entity ID is not yet known.

## Impact

Affects module maintainers.

- **New API:** New `ai_automator:id:{automator config ID}` tag and `entity_context` request metadata (`entity_type`, `entity_id`, `uuid`, `bundle`, `field_name`, `automator_id`) on automator chat requests; new protected `RuleBase::buildEntityContext()` and `attachEntityContext()`.

## Technical details

`AiAutomatorEntityModifier::entityHasConfig()` and `RunAutomatorAction` now set `$automatorConfig['id']` to the automator config entity ID. In `entityHasConfig()` this is set after the plugin config loop so a stray `automator_id` setting cannot override it. `RuleBase::getTags()` emits `ai_automator:id:{id}` when `id` is a non-empty string, alongside the existing `ai_automator`, `type`, `entity_type`, `entity`, `bundle` and `field_name` tags.

New protected methods `RuleBase::buildEntityContext()` and `attachEntityContext()` set an `entity_context` request metadata value on the `ChatInput` via `setRequestMetadataValue()`. The array holds `entity_type`, `entity_id` (NULL when `isNew()`), `uuid`, `bundle`, `field_name` and `automator_id`; nothing is attached when there is no entity. It is attached in `runRawChatMessage()` after `applyGuardrailsToInput()`, since that may return a clone of the input, and also in the vision call in `RichTextImageDescriptionTrait`. Kernel and unit tests were added, and `docs/modules/ai_automators/index.md` documents the tags.

## Upgrade

Subscribers that need to target one automator can match on the tag, e.g. `ai_automator:id:node.blog.field_content.bullet_outline`, or read `entity_context` from the request metadata. Custom code that builds its own `$automatorConfig` array and calls `getTags()` should set `$automatorConfig['id']` to get the tag.
