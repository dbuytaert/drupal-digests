## Summary

The Object Detection Explorer in the AI API Explorer module has been rebuilt on the shared explorer layout. Previously it showed detected objects only as numbers in a table and never displayed the image. Now the uploaded image is shown with a box for each detected object, labelled with its name and score, and there is a Boxes/Table switch. A minimum confidence slider sets which boxes start visible (lower-scoring ones stay in the response), and results are stored as runs with a code example generated per run.

## Impact

No upgrade or configuration changes required.

## Technical details

`ObjectDetectionGenerator` drops its custom constructor and `AiProviderFormHelper::generateAiProvidersForm()` in favour of the base-class `providerElement('object_detection', ...)` (the `ai_provider_configuration` element), `buildLayout()`, and the `ai_api_explorer_file` element for the image. Submission goes through `executeRun()`, so output is saved on the run entity as `width`, `height` and `objects`; results render from stored runs via `buildRunResults()`/`buildRunOutput()`, and the code example is built with the shared `CodeExample` builder in `buildRunCode()`.

Providers return boxes in different shapes, so `pixelBox()` accepts corner keys (`xmin`/`ymin`/`xmax`/`ymax` and variants), x/y/width/height keys, and plain four-value lists. Values that are all at most 1 are treated as fractions of the image, and results are clamped to the image. Boxes in an unknown format are not drawn but stay in the table, which shows named box keys as columns when all boxes share them. The image size is read with `getimagesizefromstring()` at run time to place the overlay.

A new `explorer.object_detection` library adds `object_detection.css` and `object_detection.js` (live value for the confidence range). The commit also adds an `ai_api_explorer_test` provider (`TestObjectDetectionProvider`) whose behaviour is driven by the file name, and a functional test `ObjectDetectionExplorerTest` using it.
