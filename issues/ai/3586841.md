## Summary

This forward-ports features that had landed in `1.x` to `2.x`. The main addition is a Decision operation type: calling code asks true/false (`noul`), choice, score and box questions about shared text or structured state, optionally with images, and gets back probabilities and confidence it can threshold on. A default Decision provider can be chosen in AI settings, and an installed provider has to implement it. Guardrails (RegEx, Input Length Limit, Moderation) can run on Decision requests, the API Explorer gains a Decision Explorer, and AI Automators gain boolean, list and numeric field rules backed by Decision. Provider selection forms can now filter models by required capabilities and show what the selected model supports.

The commit also contains documentation and tooling updates. Only 21 of the 336 changed files were visible in the diff I was given, so this summary covers what those files and their docs describe.

## Impact

Affects module maintainers and site owners.

- **Config change:** `ai.settings` default operation providers schema gains a `decision` entry ('Default decision provider').
- **New API:** New `decision` operation type (`DecisionInterface`, `DecisionInput`, `DecisionResponse`, `Drupal\ai\OperationType\Decision\Value` question/answer classes), `DecisionGuardrailInterface`, and optional `validate{OperationName}Input()` provider hooks.

## Technical details

Decision calls go through `decision(DecisionInput $input, $model_id, $tags)` on a provider and return a normalized `DecisionResponse` with typed getters (`getNoul()`, `getChoice()`, `getScore()`, `getBox()`). Helpers are `isLikely()` for noul and `isConfident()` for choice, score and box. Question state must be plain arrays, JSON scalars and `NULL`; objects, resources, non-finite numbers and invalid UTF-8 are rejected. Invalid or incomplete provider answers raise `AiBrokenOutputException`. Choice and score answers are validated for probability totals, winner and weighted score, with an optional `AnswerPrecision` for providers that round values for transport. Without it the documented tolerance is `0.02`. Box answers expose `toPixels()`, which rounds outward.

Guardrails: `services.yml` registers `GuardrailExecutionContext`, `OperationGuardrailHandlerRegistry` (a `service_collector` for the `ai.guardrail_operation_handler` tag), `ChatGuardrailHandler`, `DecisionGuardrailRunner` and `DecisionValidationEventSubscriber`. Only plugins implementing `DecisionGuardrailInterface` and declaring `supportsOperation('decision', $phase)` run on Decision requests, returning `PassResult` or `StopResult`. Reaching a set's threshold throws `AiDecisionBlockedException`, which extends `AiUnsafePromptException`. Per the docs, global sets attach at priority 100, validation runs at 20 and the guardrail handler at 10. Token-based length limits and similar unsupported checks in a caller-attached set raise `AiSetupFailureException`; in global sets they are skipped with a warning.

Operation types gain an optional input validator: `ProviderProxy` calls `validate{OperationName}Input(Input $input, string $model_id): void` on the configured provider before `PreGenerateResponseEvent`, so guardrails never see rejected input. The scaffolding skill docs and check script were updated to enforce the exact name and signature. `ai_modules_installed()` and a new `ai_modules_uninstalled()` now clear the `ai_operation_types` discovery cache.

The `ai_provider_configuration` element gets `#capabilities`, `#show_capabilities` and `#capability_details_callback`, and returns a `use_default` key. It lists only models declaring every required capability. A current selection that no longer qualifies stays visible, marked incompatible or unavailable. The selection is validated on submit. `AiProviderPluginManager::getModelsWithCapabilities()` applies the same rule outside forms.

## Upgrade

Providers that want to reject bad input early can add a validator named exactly after the operation type, for example:

```php
public function validateChatInput(ChatInput $input, string $model_id): void {
  // Throw AiBadRequestException when the input cannot be handled.
}
```

Code using `ai_provider_configuration` should read the new `use_default` key and resolve the site default when it is `TRUE`, for example with `getDefaultProviderForOperationType()`.
