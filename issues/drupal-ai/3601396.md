# #3601396: Handoff prompt: Enter should open the shell immediately, Esc to skip; --yolo skips the handoff entirely

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3601396](https://git.drupalcode.org/project/one_line_installer/-/work_items/3601396) · 1 contributor · 3 comments

## Summary

The one_line_installer's final step, which offers to drop you into a shell inside your freshly installed project, had its confirmation key backwards: pressing Enter used to skip the handoff, while doing nothing for 30 seconds opened the shell. This is now fixed so Enter immediately opens the shell (matching normal “Enter confirms” expectations), Esc explicitly skips it, and letting the 30 second timer run out still opens the shell. Additionally, running the installer with `--yolo` no longer bypasses this prompt entirely: as long as a real terminal is available, a `--yolo` run gets the same prompt and lands you in the project directory, since that's what a human running it interactively almost always wants. The only remaining case where the handoff is skipped automatically is when `/dev/tty` can't be opened at all, such as in CI or when an agent runs the installer without a pty.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix is in `step_agent_handoff()` in `src/lib/steps/agent_handoff.sh`. Previously it did a single `IFS= read -r -t 30 </dev/tty` line-read: any Enter press (success exit status) meant "skip," and only a timeout (non-zero exit) fell through to `exec "${SHELL:-bash}"`. That logic is replaced by a new helper, `_agent_handoff_read_choice()`, which loops on `read -rsn1 -t "$remaining"` to read single keypresses against a shrinking time budget (tracked via `$SECONDS` so the 30s window, configurable through `AGENT_HANDOFF_TIMEOUT`, covers the whole wait rather than resetting per keystroke). Enter (`''`, `$'\n'`, or `$'\r'`), a read timeout, or a read error all resolve to `"open"`. A bare `Esc` (`$'\e'`) resolves to `"skip"`, but the function first drains up to two more bytes to distinguish a real Esc from the start of an arrow/function-key escape sequence, treating a full sequence as "any other key" that just keeps the window running. Any other key is likewise ignored and the loop continues.

The early `if [[ $YOLO -eq 1 ]] || ! { : </dev/tty; } 2>/dev/null; then` guard was narrowed to just the `/dev/tty` check, so `--yolo` no longer bypasses the handoff when a terminal is actually available; the timeout path already served as the unattended/`--yolo` fallback. The duplicated "your project is ready in ..." messaging used on both the no-tty and Esc-skip paths was factored into a new `_agent_handoff_skipped()` helper. Test coverage in `tests/bats/lib/steps/agent_handoff.bats` was substantially expanded to exercise Enter, Esc, timeout, arrow-key sequences, and the `--yolo`-with-tty case.
