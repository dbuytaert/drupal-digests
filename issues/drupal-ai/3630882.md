## Summary

OAuth2 tokens now record the client identifier (the same value the server uses in requests and in the access token `aud` claim) in a new `client_id` field. Before, a token only pointed to a saved consumer entity. This is groundwork for allowing clients that are not saved consumer entities ([#3630879](https://www.drupal.org/node/3630879)). Existing tokens are filled in by a database update, so run updates after deploying. The old `client` reference is kept.

## Impact

Affects module maintainers and site owners.

- **Database update:** `simple_oauth_update_8609()` installs a new indexed `client_id` string field on `oauth2_token` and backfills it from each token's referenced consumer.
- **New API:** New `client_id` base field on the `oauth2_token` entity type, holding the OAuth2 client identifier the token was issued to.

## Technical details

`Oauth2Token::baseFieldDefinitions()` adds a non-translatable `client_id` string field (max length 255) and lists it in `field_indexes`. `TokenEntityNormalizer` sets it from `$client->getIdentifier()`. `RefreshTokenEntityNormalizer` sets it from `$token_entity->getAccessToken()->getClient()->getIdentifier()`. The `client` entity reference is still written by `TokenEntityNormalizer`.

`simple_oauth_update_8609()` installs the field storage definition. It then copies `client_id` from `consumer_field_data` (default language rows only) into `oauth2_token`, matching on the token's `client` column. Tokens with no consumer reference stay `NULL`.

`ExpiredCollector::collectForClient()` now matches on an OR group of `client` (consumer entity ID) and `client_id` (`$client->getClientId()`). This differs from the issue's proposal to query by `client_id` alone. The code comment says matching the reference as well finds tokens issued before a consumer's client ID changed. Kernel tests cover token creation across the authorization code flow and the update path. The unit test for the collector was adjusted for the OR group.

## Upgrade

Run database updates (`drush updb`) to apply `simple_oauth_update_8609()`, which adds the `client_id` field to `oauth2_token` and backfills existing tokens from their consumers.
