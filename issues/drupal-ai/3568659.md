## Summary

The OpenAI provider now supports batched embeddings: instead of issuing one API call per text to embed, sites indexing content into a vector database (VDB) can send a batch of prompts in a single request, reducing the number of OpenAI API calls needed. Moderation, the safety check that runs before embeddings are generated, is also batch aware: a whole batch is checked in one moderation request rather than one request per item, and every result in the response is checked so a flagged item anywhere in the batch is caught. This depends on companion batching support landed in the base `ai` module (issue [#3568648](https://www.drupal.org/node/3568648)) and, for vector storage, in `ai_vdb_provider_milvus` ([#3568651](https://www.drupal.org/node/3568651)).

## Impact

Affects module maintainers.

- **API change:** `OpenAiProvider::moderationEndpoints()` now accepts `string|array $prompt` (widened from `string`) and validates every entry in `$response['results']`, not just the first.

## Technical details

The base batching mechanics (`EmbeddingsCollectionInput`, `embeddingsCollection()`, chunking) live in `OpenAiBasedProviderClientBase` in the `ai` core module, added by a companion MR there. This MR only adds the OpenAI-specific pieces: a new `moderateEmbeddingsCollectionInput()` override that forwards the entire batch of prompts to `moderationEndpoints()` in one call instead of moderating per chunk, and a widened `moderationEndpoints(string|array $prompt, array $tags = [])` that now loops over every entry in `$response['results']` and throws `AiUnsafePromptException` if any is flagged, rather than checking only `$response['results'][0]`. A defensive check was also added to the single-item `embeddings()` path that throws `\RuntimeException` if the API response is missing `data[0]['embedding']`.

A new `OpenAiProviderTest` unit test suite exercises this against a mocked Guzzle handler wired into a real OpenAI SDK client, covering: embeddings returned out of index order get re-sorted, a count mismatch between requested and returned embeddings throws, a flagged batch item throws `AiUnsafePromptException`, all moderation results (not just the first) are checked, and the `skip_moderation` tag bypasses moderation entirely.

A hardcoded `omni-moderation-latest` model name in the moderation payload was flagged during review (comment from nikro) as a concern for future multi-model moderation support, and was split off into follow-up issue [#3607418](https://www.drupal.org/node/3607418) rather than addressed here.</technical>
