## Summary

Using OpenAI models like GPT-5.6-Luna (or the `o4` family) together with function tools (e.g. in AI Agents) triggered an API error: "Function tools with reasoning_effort are not supported for gpt-5.6-luna in /v1/chat/completions." This happened because the provider defaulted the `reasoning_effort` setting to `medium`, which OpenAI's Chat Completions endpoint rejects for these models when tools are in use. The `ai_provider_openai` module now automatically defaults `reasoning_effort` to `none` for these models, so tool calling works out of the box without manual configuration. The module also adds `none` and `xhigh` as selectable `reasoning_effort` values, matching OpenAI's current API.

## Impact

Affects site owners.

- **Config change:** The `reasoning_effort` setting for OpenAI models now offers `none` and `xhigh` as options (matching OpenAI's current API), and defaults to `none` instead of `medium` for `gpt-5.6*` and `o4*` models.

## Technical details

In `OpenAiProvider`'s configurable-fields logic, the `reasoning_effort` constraint's `options` list gained `none` and `xhigh` (previously only `minimal`, `low`, `medium`, `high`) and the field was marked `required`. A new check, `str_starts_with($model_id, 'gpt-5.6') || str_starts_with($model_id, 'o4')`, overrides the field's `default` to `none` for those model families, since OpenAI's `/v1/chat/completions` endpoint (still used on the `1.2.x` branch) rejects a non-`none` reasoning effort when function tools are attached. The issue notes that on `1.3.x`, which switches to `/v1/responses`, this restriction doesn't apply, so this fix is scoped to `1.2.x`. Separately, `OpenAiConfigForm`'s constructor-promoted properties (`$aiProviderManager`, `$keyRepository`, `$openAiHelper`) were changed from `private readonly` to `protected`, allowing subclasses to access them.
