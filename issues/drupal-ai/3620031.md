## Summary

The image safety recipe now has three tiers instead of a binary block. Safe images save silently. Moderate images (partial nudity, suggestive content, mild violence) are accepted, and the uploader sees a warning. Restricted images (full nudity, explicit sexual content, gore, graphic violence, graphic medical imagery) are still blocked with a validation error. An image the model cannot classify is treated as Restricted. Sites that already applied the recipe do not pick this up automatically.

## Impact

Affects site owners.

- **Requirements:** `drupal/ai_validations` constraint raised from `^1.3` to `^1.4`, which provides the opt-in XSAFE/XWARN/XBLOCK warning tier (#3606131).
- **Config change:** Shipped `field_validation.rule_set.media_image` rule: new title, XSAFE/XWARN/XBLOCK prompt, reworded `message`, new `warningMessage` key in the rule `data`.

## Technical details

The rule's prompt in `config/field_validation.rule_set.media_image.yml` now returns `XSAFE`, `XWARN` or `XBLOCK` in place of `XTRUE`/`XFALSE`. The rule title becomes "Block restricted imagery, warn on moderate". The `message` text now covers only Restricted content, and the new `warningMessage` key in the rule's `data` holds the Moderate text. The rule's `provider` is unchanged, an empty string meaning the site default. `recipe.yml` and the `composer.json` description are reworded, and `composer.json` requires `drupal/ai_validations` `^1.4`.

The warning tier is opt-in in AI Validations and is active only while the warning message is non-empty. The README says that emptying it returns validation to `XTRUE`/`XFALSE`, and that the prompt must then be rewritten to match. If only one of the two is changed, uploads are blocked (empty message with the three-token prompt) or no warning is ever shown (message set with the two-token prompt). The README also documents "Adjusting the tiers", for example mapping Moderate to `XBLOCK` or `XSAFE`. It states that an `XWARN` verdict also writes to the `ai_validations` logger channel, so headless flows such as JSON:API keep an audit trail and are never blocked by a warning.

## Upgrade

The recipe creates the rule set with `createIfNotExists`, so re-applying the new version on a site that already has the `media_image` rule set changes nothing. Either delete the rule set at Structure → Field Validation and re-apply the recipe, or edit the existing rule by hand:

```
=== DECISION ===
- If the image is SAFE, respond with: XSAFE
- If the image is MODERATE, respond with: XWARN
- If the image is RESTRICTED, respond with: XBLOCK

=== OUTPUT FORMAT ===
Respond with exactly one token — XSAFE, XWARN, or XBLOCK — and nothing else.
```

Then fill in the rule's **Warning message** field. Update `drupal/ai_validations` to 1.4 or newer.
