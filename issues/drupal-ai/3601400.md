# #3601400: Management mode hangs for ~60s with no output: `ddev exec true` starts the project instead of probing it

- **Project:** Drupal AI

- **Status:** Fixed

## Summary

Running the installer's management mode (`drupalaibp` inside an existing DDEV project) against a project that was configured but stopped used to appear to hang for about a minute with no output. The cause was the check used to decide whether DDEV needed starting: it ran `ddev exec true` and threw away its output, but on a stopped project `ddev exec` itself silently starts the project before running the command, taking roughly 60 seconds with nothing printed to explain the wait. The fix replaces that check with a read-only probe of DDEV's actual state, so a stopped project prints "Checking DDEV..." then "Starting DDEV..." with DDEV's own progress output, and a running project is confirmed in a fraction of a second without being touched.

## Impact

No upgrade or configuration changes required.

## Technical details

The probe in `manage_existing()` (`src/lib/shared/manage/manage_existing.sh`) now runs `ddev describe -j 2>/dev/null | grep -q '"status":"running"'` instead of `ddev exec true >/dev/null 2>&1`. `ddev describe -j` only reads project state and returns in well under a second, whereas `ddev exec` on a stopped project starts it as a side effect of trying to execute the command, which is what produced the ~60s of silence. The grep match deliberately keeps the leading quote (`"status":"running"`) so it can't be tripped by sibling JSON keys like `router_status` or `status_desc`. A `step "Checking DDEV..."` message was also added before the probe so the previously dead `step "Starting DDEV..."` branch (which could never run when the probe itself started the project) now actually fires and is visible on screen.
