# #3588977: Behavioral eval runner: the default (claude) provider runs the agent inside the repo checkout with write access

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3588977](https://git.drupalcode.org/project/ai_best_practices/-/work_items/3588977) · 1 contributor · 2 comments

## Summary

The behavioral eval harness in this project runs AI agent CLIs (claude, codex, gemini) with real write permissions to test how they respond to prompts. Previously, the default provider (claude) was exempted from sandboxing and ran directly inside the project's repository checkout, so an agent could write files into the actual working tree, as happened when a test case caused the agent to create a stray `README.md` in the repo root. Since this project accepts outside contributions and evaluates skill content as prompt input, a `--behavioral` eval run over a contributed skill could execute third-party content with write access to the operator's checkout. Every eval provider now starts in a fresh, disposable temporary directory by default, closing that gap and making eval runs reproducible regardless of the operator's working tree state.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix moves isolation down into `providers.py` instead of handling it ad hoc in each caller. A new `_isolated_cwd(provider, cwd)` helper returns the caller-supplied `cwd` when given, otherwise calls `tempfile.mkdtemp(prefix=f"eval-{provider}-")` to create a throwaway directory. All three CLI runners, `run_claude()`, `run_codex()`, and `run_gemini()`, now call this helper instead of falling back to `REPO_ROOT` (which is removed along with its `Path` import).

This removes the previous claude-specific exemption in `run-evals.py`, which used to special-case `provider != "claude"` to assign a tempdir; that logic is deleted since every provider now gets the same treatment for free from `providers.py`. `compare.py` is updated only to fix its status output (`CWD: fresh tempdir per call (provider default)`) since it already delegated to the same runners and had no explicit cwd handling of its own. Callers that need a specific working directory still pass `cwd` explicitly and bypass the tempdir default. The related design discussion about grading observed site state and defined starting targets is tracked separately and does not block this isolation fix.</technical>
