## Summary

When a node indexed with the Postgres pgvector Search API backend was edited and re-saved, the old vector chunks for that item were never actually removed before the new ones were inserted. Each re-save doubled the stored rows for that content, and searches could keep returning stale, outdated chunks alongside the current ones. The fix ensures the old chunks for an item are correctly deleted before the new chunks are written, so re-saving content keeps the row count stable and removes outdated text from search results. Sites that indexed and re-saved content on an affected version should re-index to clear out any duplicate or stale rows that already accumulated in their Postgres vector tables.

## Impact

No upgrade or configuration changes required.

## Technical details

The bug was in `PostgresProvider::deleteItems()`. It first called `getVdbIds()` to look up the numeric primary key `id` values matching the given Search API item IDs (queried via `drupal_entity_id`), then passed those primary keys into `deleteFromCollection()`, whose underlying `PostgresPgvectorClient::deleteFromCollection()` query deletes `WHERE drupal_entity_id IN (...)`. Because the ids passed in were numeric primary keys rather than `drupal_entity_id` strings, the `WHERE` clause never matched, so nothing was actually deleted and old chunks piled up on every re-save.

The committed fix removes the primary-key lookup entirely: `deleteItems()` now passes the Search API item IDs (e.g. `entity:node/1174:en`) directly to `deleteFromCollection()`, matching the column it actually filters on. This also sidesteps a fixed row-limit on the old lookup query that could have silently truncated which chunks got deleted for large items.

A second change in the same commit fixes `indexItems()` for progressive/batched indexing: it now excludes IDs listed in `skipDeleteItemIds` (from AI core) from the delete pass via `array_diff()`, so chunks written by earlier passes of the same indexing operation are not deleted again on later passes, only stale chunks from a previous, completed indexing run are removed.
