## Summary

The AI validations recipe no longer assumes a Basic page content type with a `field_content` or `body` field. When you apply it, you choose the content type and the text field to validate. The defaults are `page` and `field_content`, so Drupal CMS needs no extra input. On a Standard-profile site you pass `--input=ai_recipe_validations.field_name=body`. If the chosen field doesn't exist on the content type, the apply now fails. Before, it succeeded and left a rule set with an empty field dropdown.

## Impact

Affects site owners.

- **Requirements:** The target field must already exist on the chosen content type, or the apply aborts.
- **Config change:** The recipe has two new inputs, `bundle` (default `page`) and `field_name` (default `field_content`). It creates one `node_${bundle}` rule set with one text rule, instead of a hardcoded `node_page` set with two rules.

## Technical details

In `recipe.yml`, two inputs are added: `bundle` (constraint `EntityBundleExists: node`) and `field_name` (`ConfigExists` on the `field.storage.node.` prefix, a max length of 32 and a machine-name regex). Each has a prompt, a default value and an installer form element. `node` is added to `install`.

The rule set action key becomes `field_validation.rule_set.node_${bundle}`. Its label is now `AI validations`, `bundle: ${bundle}`, and a single `ai_text_prompt_constraint_rule` uses `field_name: ${field_name}`. This replaces the two hardcoded rules, one on `field_content` and one on `body`.

Input constraints can only check that the field storage exists, not that the field is on that bundle. So a preflight action on `field.field.node.${bundle}.${field_name}` runs `setSettings: validated_with_ai: true`. It fails the apply if the field is missing. Per the reviewer, `FieldConfig::preSave()` discards the unknown setting, so nothing is stored. The action runs before `createIfNotExists`, so a failed apply leaves no rule set behind.

The test helpers are also updated for AI Validations 1.4.0. The prompt is read from `ChatInput::getSystemPrompt()`, and the content assertion uses `assertStringStartsWith` because the validator appends a reply-format reminder. The README gains a "Recipe inputs" section and a Standard-profile `--input` example.

## Upgrade

On a Standard-profile site, pass the field explicitly. Drupal CMS uses the default.

```bash
php core/scripts/drupal recipe ../recipes/ai_recipe_validations \
  --input=ai_recipe_validations.field_name=body
```

To target another content type, add `--input=ai_recipe_validations.bundle=article`.
