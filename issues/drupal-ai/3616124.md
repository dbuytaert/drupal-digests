## Summary

Saving the anonymous user (uid 0) no longer deletes OAuth tokens belonging to real users on consumers that have no default user. Saving a user who is a consumer's default user also no longer revokes other users' access tokens on that consumer. Tokens that actually authenticate as the saved user are still revoked, and refresh tokens are still kept. If you have custom code that relied on the old behavior of sweeping a default user's consumer tokens, use `collectForClient()` instead.

## Impact

Affects module maintainers.

- **API change:** `ExpiredCollector::collectForAccount()` now returns only non-refresh tokens that authenticate as the account (explicit subject, or no/deleted subject on a Consumer defaulting to it) and returns `[]` for the anonymous account. `TokenExpiryTriggerHandler::handleUserUpdate()` ignores the anonymous account.

## Technical details

`simple_oauth_user_update()` fires on every user save, including uid 0, and called `ExpiredCollector::collectForAccount()`. That method collected tokens by `auth_user_id` and then every token of any Consumer whose default `user_id` matched the account. The fix leaves the hook unchanged. `TokenExpiryTriggerHandler::handleUserUpdate()` now returns early for anonymous users, and `collectForAccount()` returns `[]` for them.

`collectForAccount()` now runs two queries. The first selects non-refresh tokens whose `auth_user_id` is the account. The second selects non-refresh tokens of Consumers defaulting to the account that have no existing user, using `notExists('auth_user_id.entity.uid')`. That covers tokens with no subject or a deleted subject, which fall back to the Consumer's default user. Tokens whose explicit subject is another existing user are skipped. The `QueryException` case when loading consumers by `user_id` now falls back to the first query's results only.

The collector queries in `collect()`, `collectForAccount()` and `collectForClient()` now use `accessCheck(FALSE)`, since they are internal and not run on behalf of a user. The issue notes this means cron deletes expired tokens owned by any account. A reviewer found no query access handler on `oauth2_token`, so this was not filtering anything before. The anonymous skip lives in the default handler, which is a replaceable service from [#2946882](https://www.drupal.org/node/2946882); a custom handler must add its own check. Refresh tokens are not revoked on user or consumer saves, consistent with [#3436728](https://www.drupal.org/node/3436728), which rejects refresh grants for unpublished consumers.

## Upgrade

If custom code called `ExpiredCollector::collectForAccount()` expecting every access token of a Consumer whose default user is the account, call `collectForClient()` for those consumers instead:

```php
$tokens = $collector->collectForClient($consumer);
```

If you replaced the `TokenExpiryTriggerHandlerInterface` service, add your own `$user->isAnonymous()` check in `handleUserUpdate()`.

### Collaboration

Scott Falconer pointed out early that a uid 0 guard alone missed the root cause: `collectForAccount()` could revoke other users' tokens for any Consumer default user, and he extended the MR to cover that. Pfrilling then drove the review, reworking the design. A credential-change gate in the handler was tried and later dropped so the default handler only skips the anonymous account, and the refresh token purge update hook was removed. Alex UA's runtime retest with real authorization_code tokens exposed that refresh-token revocation on the consumer side could not reach real refresh tokens, which fed into that rework.
