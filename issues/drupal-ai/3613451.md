# #3613451: Make it possible to select agent supplied/default model

## Summary

The AI Agents Debugger's "Run Agent" form used to force you to pick a concrete provider and model on every run, which meant you could never see the model an agent is actually configured to use, since the debugger always overrode it. The Model dropdown now has an "Agent Supplied/Default" option, selected by default, so a debug run uses whichever provider/model the agent itself is configured with, falling back to the site's default chat provider only if the agent doesn't specify one. Explicitly picking a provider/model in the dropdown still works exactly as before and overrides the agent's own configuration.

## Impact

No upgrade or configuration changes required.

## Technical details

In `AIAgentsDebuggerForm`, the model `#options` array now gets an empty `''` entry labeled "Agent Supplied/Default" prepended to `getSimpleProviderModelOptions()`, the field is no longer `#required`, and `#default_value` is set to `''` instead of being computed from `getDefaultProviderForOperationType('chat_with_tools')`.

`AIAgentsDebuggerController::runAgent()` no longer treats an empty `provider_name` as an error. When it's empty, the controller skips `$agent->setAiProvider()`/`setModelName()` entirely, so a `ConfigAiAgentInterface` agent resolves its own `provider_config` (falling back to the site default on its own). Agent plugins that don't implement `ConfigAiAgentInterface` can't self-resolve, so for those the controller explicitly loads `getDefaultProviderForOperationType('chat_with_tools')` and calls `setAiProvider()`/`setModelName()` with that default. `askAi()` follows the same pattern for the "Ask AI" side panel, falling back to `getDefaultProviderForOperationType('chat')` instead of returning a "Missing model" error when no model was selected. Client-side, `debugger-init.js` and `AskAiChat.tsx` drop their "please select a model" validation since an empty model value is now a valid, meaningful choice.
