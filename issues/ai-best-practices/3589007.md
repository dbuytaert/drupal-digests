# #3589007: composer reinstall and composer install --no-dev delete ai_best_practices.yaml and block the plugin

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3589007](https://git.drupalcode.org/project/ai_best_practices/-/work_items/3589007) · 1 contributor · 6 comments

## Summary

Running `composer reinstall drupal/ai_best_practices` or `composer install --no-dev` (when the package is a dev requirement) no longer wipes the project's `ai_best_practices.yaml` or the plugin's entries in `composer.json`. Before the fix, those commands removed the package's `allow-plugins` entry, so the next `composer install` failed with a "plugin blocked by your allow-plugins config" error, and any customizations in `ai_best_practices.yaml` were lost. Cleanup still runs on a real `composer remove`.

## Impact

No upgrade or configuration changes required.

## Technical details

Composer calls `PluginInterface::uninstall()` for the first half of a reinstall and for dev packages dropped by `--no-dev`, not only when the package is removed. `AiBestPracticesPlugin::uninstall()` now calls a new private `packageStaysInstalled()` and returns early, with a verbose-only message, if it reports true. The check relies on Composer writing the lock (or holding it in memory with `lock: false`) before running package operations, so the lock reflects the post-command project. It looks for the package name in the lock's `packages` and `packages-dev` sections. If there is no usable lock, or reading it throws, it falls back to the root package's `require` and `require-dev`. Transitive installs are covered because the lock lists them too. A new `AiBestPracticesPluginUninstallTest` covers the behavior.

## Upgrade

If a project already hit this and the `allow-plugins` entry was removed, restore it with `composer config allow-plugins.drupal/ai_best_practices true` (the entry the issue says gets removed), or follow the workaround in [#3588983](https://www.drupal.org/node/3588983) of deleting `vendor/drupal/ai_best_practices` and running `composer install`.
