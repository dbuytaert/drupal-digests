# #3589000: drupal-a11y-dynamic recommends FocusCommand, which does not exist in core (use FocusFirstCommand)

- **Project:** Drupal AI

- **Version:** 1.0.x-dev
- **Status:** Fixed
- **Discussion:** [#3589000](https://git.drupalcode.org/project/ai_best_practices/-/work_items/3589000) · 1 contributor · 7 comments

## Summary

The `drupal-a11y-dynamic` skill in AI Best Practices told agents to return focus after AJAX responses with `\Drupal\Core\Ajax\FocusCommand`, a class core does not have. Code generated from it would fail when the AJAX response was built. The skill and its evals now point to core's `FocusFirstCommand`, and the skill notes that a heading or landmark used as a focus target needs `tabindex="-1"`.

## Impact

No upgrade or configuration changes required.

## Technical details

The skill's `SKILL.md` now uses `FocusFirstCommand` in its frontmatter description, the AJAX focus section and its code example, the inline-error example and the "What not to do" section. It describes the command as taking a container selector. Focus moves to the first tabbable element inside the container, or to the container itself if that is focusable. Otherwise focus stays on the triggering element, which is why heading or landmark targets need `tabindex="-1"`.

The evals had locked in the wrong class. In the rubric for case B02, `FocusFirstCommand` moves into `must_contain_any`, and `new FocusCommand(` and `Ajax\FocusCommand` are listed under `must_not_contain`, so an answer using the nonexistent class now fails. The dataset criteria, the `README.md` and the static check (S06) text are updated to match.
