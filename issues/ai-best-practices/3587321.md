## Summary

This is a proposal (MR !22), not yet merged. If it lands, installing or updating `drupal/ai_best_practices` will write a small `docs/ai/PROJECT.md` into the project. The file lists the Drupal version, PHP version, local environment (DDEV or Lando), the DDEV URL, and a count of custom-module directories. The plugin also adds a `# This project` section to `AGENTS.md`. That section only says when an agent should load `PROJECT.md`, so the file is read on demand and not at session start. Removing the package deletes the generated files and the injected block. The issue started as a much larger harvest of services, hooks and entity bundles. After review that part was dropped from this MR.

## Technical details

The MR adds `src/Harvester/ContextHarvester.php`. `AiBestPracticesPlugin` calls `run()` after `ComposerProjectSynchronizer::runDeferredSyncIfPending()` and calls `cleanup()` from `uninstall()`. Both calls are wrapped in `catch (\Throwable)` and only emit a `<warning>`, so a failure never makes Composer exit non-zero.

`run()` first checks that `composer.json` requires a `drupal/core*` package. It then reads `composer.json` (package name, `drupal/core` or `drupal/core-recommended` constraint, PHP constraint) and the filesystem. A `.ddev/` directory gives a `<name>.ddev.site` URL, taken from `.ddev/config.yaml` or the directory name. A `.lando.yml` file is detected as Lando with no URL. Custom modules are counted as the directories under `<web-root>/modules/custom`. The web root comes from `extra.drupal-scaffold.locations.web-root`, with fallbacks `web`, `docroot`, `public_html` and `htdocs`.

The `AGENTS.md` block sits between the HTML comment markers `MARKER` and `MARKER_END`. A rerun replaces the existing block in place. If the end marker is missing, everything from the start marker to the end of the file is stripped and a fresh block is appended. `cleanup()` removes the block and also deletes the legacy `PROJECT_MODULES.md`, `PROJECT_SERVICES.md`, `PROJECT_HOOKS.md` and `PROJECT_ENTITIES.md` names, which earlier iterations of the branch produced.

The diff also adds PSR-4 entries for `Harvester` and `Composer`, and `extra.drupal-scaffold.file-mapping` entries for `AGENTS.md`, `CLAUDE.md` and `GEMINI.md`. It adds a README section and eval fixtures under `evals/`. The `drupal-project-context` eval fixture and its `SKILL.md` still contain the full services, hooks and entities content that this MR no longer generates. The eval runner gains a `file_contains` check and a `php_lint_wrapper` option.

The original proposal harvested services, hooks and entity bundles by scanning files. mxr576 argued that file scanning gives false confidence and that stale data is worse than none.
