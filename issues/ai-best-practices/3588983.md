## Summary

The `drupal/ai_best_practices` Composer plugin now adds `/ai_best_practices.yaml` to the project's `.gitignore` when it first creates that file. The file holds per-developer settings, such as the skills output directory and excluded skills. The issue reporter had committed it and got deployment errors on Pantheon. The README now has a "What to commit" section. It says to ignore `ai_best_practices.yaml` and to commit `AGENTS.md` and `.agents/skills/`. It also lists optional ignore rules for teams that want agent context to stay local.

## Impact

Affects site owners.

- **Config change:** `ai_best_practices.yaml` is now treated as per-developer and git-ignored via `/ai_best_practices.yaml` in `.gitignore` when the plugin first creates it.

## Technical details

`ComposerProjectSynchronizer::ensureDefaultConfig()` now calls a new private `ensureConfigGitIgnored()` after it copies `ai_best_practices.yaml.dist` into the project root. If creating the file fails, it returns early and does not touch `.gitignore`. The new public constant `CONFIG_GITIGNORE_ENTRY` is `/ai_best_practices.yaml`.

The `.gitignore` handling is conservative. If any existing non-comment line matches `ai_best_practices.yaml`, the plugin leaves it alone. This check ignores a leading `!` or `/`, so a `!` negation counts as the project's choice. A `.gitignore` that is a symlink or not a regular file is never written to. If it can't be read or written, the plugin warns and tells the user to add the entry manually. Otherwise it appends a comment line and the entry, adding a newline first when the file doesn't end with one.

Because the entry is only added when the plugin creates the file, a project that already tracks it must run `git rm --cached ai_best_practices.yaml` once. On `composer remove`, the config file is still deleted, but the `.gitignore` line is left in place. The `.dist` file header and `.agents/SETUP.md` now point to the new guidance.

## Upgrade

If `ai_best_practices.yaml` is already committed, untrack it once:

```
git rm --cached ai_best_practices.yaml
```

If the file already exists, the plugin won't add the ignore rule, so add `/ai_best_practices.yaml` to `.gitignore` yourself. For local-only agent context, the README suggests also ignoring:

```gitignore
/AGENTS.md
/CLAUDE.md
/GEMINI.md
/.agents/
```
