## Summary

`composer drupal-ai skills-list` no longer crashes with a `TypeError` on skills whose `description` is a multi-line YAML value, and `skills-sync` no longer rejects them. This affected 13 of the 14 drupal-canvas skills. SKILL.md frontmatter that is not valid YAML now shows up as a validation error for that skill instead of a fatal.

## Impact

No upgrade or configuration changes required.

## Technical details

`SkillValidator::parseFrontmatter()` used a hand-rolled line parser that turned plain multi-line, folded (`>-`) and literal (`|`) scalars into an empty array. It now passes the frontmatter block to `Symfony\Component\Yaml\Yaml::parse()`, which is already a dependency used by `AiBestPracticesConfigLoader`. The old `normalizeValue()` helper is removed. An empty block returns `[]`, so the required-field checks report each missing field. Valid YAML that is not a mapping, such as a list, throws a `ParseException` ("Frontmatter must be a mapping..."). `validateSkill()` catches `ParseException` and returns `valid => false` with an error of the form `Invalid YAML frontmatter in SKILL.md: <message>`. A file with no `---` block gets a separate message. An unquoted colon, as in `description: Use when: something`, is now reported as invalid YAML.

`SkillsListCommand` is also hardened. A non-string or blank description is shown as `(no description)`. Whitespace is collapsed so each skill stays on one table row, and truncation uses `mb_substr()`. The XML output coerces a non-string description to an empty string. Tests were added for the validator and for `SkillsListCommand`. The commit also changes `AiBestPracticesPluginUninstallTest` to write its fixtures with `file_put_contents()` instead of Composer's `JsonFile::write()`, to avoid PHPUnit warnings.
