# #3589006: Default skills output_directory to .claude/skills when Claude Code is detected

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3589006](https://git.drupalcode.org/project/ai_best_practices/-/work_items/3589006) · 1 contributor · 4 comments

## Summary

Claude Code only loads project skills from `.claude/skills/`, but ai_best_practices synced skills into `.agents/skills/` by default, so Claude Code users got no skills unless they changed the setting by hand. Now, when `ai_best_practices.yaml` is first created, the plugin picks `.claude/skills` if it detects Claude Code. Otherwise it keeps `.agents/skills`. Existing projects keep whatever their yaml already says. Agents that read only `.agents/skills` will not see the skills in a project that picked `.claude/skills`.

## Impact

Affects site owners.

- **Config change:** New `ai_best_practices.yaml` files get `skills.output_directory: .claude/skills` when Claude Code is detected (`CLAUDECODE` or `CLAUDE_CODE` env var, or a `.claude/` directory), otherwise `.agents/skills`.

## Technical details

The issue proposed detecting Claude Code at sync time, whenever `skills.output_directory` is unset. That could never fire, because `ai_best_practices.yaml.dist` hardcodes `output_directory: .agents/skills` and gets copied into every project. The commit instead runs detection once, at file creation. `ComposerProjectSynchronizer` now reads the `.dist` template, calls the new `SkillsConfig::detectDefaultOutputDirectory($projectRoot)`, and rewrites the first `output_directory:` line through a regex in `withOutputDirectory()`. The Composer message then reports the chosen value, for example "skills output: .claude/skills". The commit message does not give a reason for this change. The `SkillsConfig` docblock says it keeps the directory from changing depending on who runs Composer later.

Detection is in `SkillsConfig::isClaudeCodeProject()`. It returns true if the `CLAUDECODE` or `CLAUDE_CODE` environment variable is set, or if `$projectRoot/.claude` is a directory. The directory check covers container wrappers that don't forward the variable (older DDEV, Lando, `docker compose exec`).

The `skills-sync` command description and help text and the script usage output no longer hardcode `OUTPUT_SKILLS_DIR`. They now say `skills.output_directory`. The `.dist` comment, the README files and the agent setup docs are updated to match. `ComposerProjectSynchronizerTest` gains cases for each env var, a `.claude/` directory, neither, and an existing config. I did not check the open items in the issue body about `SkillsScanner::scanAllSkills()` and hand-written skills already in `.claude/skills/`. The diff does not touch the scanner.

## Upgrade

Existing projects are not changed. To get the new behavior, set the value in `ai_best_practices.yaml` yourself, or delete the file so it is regenerated on the next Composer install or update:

```yaml
skills:
  output_directory: .claude/skills
```
