## Summary

The AI Best Practices project gains a canvas-migration eval instrument for grading whether an AI agent really rebuilt a website homepage as Drupal Canvas components and pages. It checks the served page, screenshots and measured geometry, not the agent's own report. A run produces two separate results: a quality score and a set of validity gates. A failed gate invalidates the run but does not lower the score. Cases blocked by a broken tool are marked unmeasured and left out of the score. Some checks are calibrated to one specific source page (pixel widths, section order, image and SEO fields). Against other sites they will report calibration mismatches, not real migration defects.

## Technical details

This is based on the issue description only. No diff or comments were available, and the default branch I cloned does not yet contain `evals/canvas-migration/`, so I could not check the code.

According to the description, the instrument reuses the repo's existing scoring core. It adds about 24 check probes covering layout, link integrity, images, SEO, geometry, secrets and served-page checks. It also adds a rubric catalogue and a 2-case sample dataset, and consumers bring their own eval set. Grading runs in a docker "referee" sidecar (Python, Node, Chromium, geometry measurer) that talks to the test bed's containers without being given the docker socket, so the system under test cannot tamper with it. The referee ships build-from-source only. A native Inspect AI runner covers the same cases and exports results in Every Eval Ever 0.2.2 format. A vendored GPL-2.0-or-later `geom-probe` measurer is isolated in its own commit for licence auditability.

The rubrics validate against the vendored Eval Commons Layer 1 schema and use only the canonical check kinds (command / target_match / score_delta). Per the description, the `evals/<skill-name>/` layout convention gains one documented exception, an eval set not tied to a single skill, noted in `AGENTS.md`.
