## Summary

Installing this module into a Drupal 12 site previously failed outright: Composer could not resolve dependencies because the module's `composer.json` pinned Symfony Console/Filesystem/Yaml to versions 6 or 7, while Drupal 12 requires Symfony 8. This is now fixed, the module installs cleanly on Drupal 12.

## Impact

Affects site owners.

- **Requirements:** `composer.json` now allows `symfony/console`, `symfony/filesystem`, and `symfony/yaml` `^8.0` in addition to `^6.0`/`^7.0`, so the package installs alongside Drupal 12's Symfony 8 dependency.

## Technical details

The fix widens the version constraints for `symfony/console`, `symfony/filesystem`, and `symfony/yaml` in `composer.json` to also accept `^8.0`. That alone wasn't sufficient because Symfony Console 8 removed `Application::add()` in favor of `addCommand()` (introduced in 7.4), while the Console phar bundled inside Composer itself is still 5.4 and only has `add()`. `AiBestPracticesApplication`'s constructor now checks `method_exists($this, 'addCommand')` and calls whichever method is available, so the same code works whether the runtime Console is old or new. Two command classes' `configure()` methods also picked up a `: void` return type for consistency with the base `Command` class signature in newer Symfony versions.
