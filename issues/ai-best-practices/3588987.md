The `drupal-configuration` skill in AI Best Practices now covers Config Split, which it previously never mentioned. Its decision table gains a row for config or modules that should vary by environment, and a new reference explains how to choose between complete and partial splits, when to use a split instead of a settings.php override, and how to set one up. ## Technical details

`skills/drupal-configuration/SKILL.md` adds a "Config Split" row to the decision table, a paragraph telling the agent to read `references/config-split.md` first, and a See also link. The new reference file explains:

- **Complete vs. partial splits.** Complete splits remove the listed config or module from `config/sync/`. Partial splits keep it there and store only a `config_split.patch.<config name>.yml` diff.
- **Split vs. override.** A `$config` override in settings.php suits a single value or a secret, since it is never exported. A partial split suits structural or multi-key differences that should be shared with the team.
- **Setup.** The split folder goes outside the sync directory. The split is saved with status off, then enabled per environment with `$config['config_split.config_split.dev']['status'] = TRUE;` in settings.php.
- **Export trap.** If a partial-split item is not already in `config/sync/`, `drush cex` moves it entirely into the split. Other environments then lose it on import. The fix is to export once with the split off first.

The commit also adds static checks in `evals/drupal-configuration/static-checks.json` and updates the eval README for this content. The reference states it matches Config Split 2.x.
