# #3589003: Eval runner: let run-evals.py evaluate another repository's skills (--root)

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed

## Summary

The eval runner can now grade another repository's skills. A package that ships its own skills through the Composer sync, such as an organisation's layer on top of the AI best practices package, can run the runner from `vendor/drupal/ai_best_practices/evals/` against its own `skills/` and `evals/` directories instead of copying the runner. Without the new option, behaviour is unchanged.

## Impact

Affects module maintainers.

- **New API:** New `--root <dir>` option on `evals/run-evals.py` and new `scoring.set_repo_root()` in `evals/scoring.py`.

## Technical details

Before this change, `run-evals.py` and `scoring.py` computed `REPO_ROOT` from their own file location, so they only ever saw the package's own `skills/` and `evals/`. `run-evals.py` now takes `--root`. When it is given, the script resolves the path, overrides its module-level `REPO_ROOT`, and calls the new `scoring.set_repo_root()`. That function reassigns `scoring.REPO_ROOT` and `EVALS_DIR`, so case loading follows the same root.

The runner also fails earlier on bad input. It calls `parser.error()` if `<root>/evals` does not exist, and again if no eval suites (`static-checks.json` directories) are found under it. `test_scoring.py` builds a temporary repository with one skill. It checks exit codes for a passing and a failing suite, that only that repository's suites run, and that `set_repo_root()` follows and restores. `CONTRIBUTING.md` documents the option.

## Upgrade

Run the vendored runner against your own package's skills:

```bash
python3 vendor/drupal/ai_best_practices/evals/run-evals.py --static --root .
```
