## Summary

The accessibility skills in AI Best Practices contained three claims that don't match Drupal core, and they are now corrected. `#states` is client-side only, which is the real reason to use `#access` for permission-based hiding. `#type => 'table'` does not add `scope` attributes by itself. `item_list` is a theme hook, so lists need `#theme => 'item_list'`, because `#type => 'item_list'` renders nothing. The recommended practices stay the same. Only the stated reasons and the example code changed.

## Impact

No upgrade or configuration changes required.

## Technical details

The edits are in the `drupal-accessibility` dispatcher `SKILL.md`, `drupal-a11y-fapi` (including its `SYNC.md`), `drupal-a11y-dom`, and the fapi evals.

`#states`: the old text said it leaves hidden fields in the accessibility tree. The issue points out that the `state:visible` handler in `core/misc/states.js` toggles the field's wrapper with jQuery, which sets `display: none`, so the element does leave the accessibility tree. The text now says `#states` acts only in the browser. The element is still in the HTML and its value is still submitted and processed. `#access => FALSE` keeps it out of the output, and `FormBuilder::handleInputElement()` ignores input for it. The text also says CSS that hides only visually, such as `.visually-hidden`, leaves the element exposed to assistive technology.

Tables: the text no longer claims core generates `<th scope="col">` or `<th scope="row">`. The issue reports that the `table.html.twig` templates and `ThemePreprocess::preprocessTable()` add no `scope`. The skills now show setting it per cell, for example `['data' => $label, 'header' => TRUE, 'scope' => 'row']`, since extra cell keys become attributes.

Lists: the skill now says to use `#theme => 'item_list'` with `#items`, and notes that `#type => 'item_list'` renders nothing. The canonical-source notes in the front matter are updated to match.

Evals: the fapi evals keep their checks. Only the S11 description and one B06 expectation changed, replacing the accessibility-tree wording with "server-side" and "not rendered and its input is ignored".
