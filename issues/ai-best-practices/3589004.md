# #3589004: Eval runner: add a Kiro CLI provider

## Summary

Behavioral evals can now run against Kiro CLI as well as `claude`, `codex`, `gemini` and `mistral`. Run `python3 evals/run-evals.py --behavioral --skill <skill> --provider kiro` to see whether a skill changes Kiro's answers. Kiro runs answer-only with no tools trusted. It needs `kiro-cli` 2.31 or later, and you log in with `kiro-cli login` or set `KIRO_API_KEY`. Kiro reports credits rather than tokens, so runs show no token or cost figures.

## Impact

Affects module maintainers.

- **New API:** New `kiro` provider for the behavioral eval runner (`--provider kiro`, Inspect model string `abp_cli/kiro`), default model `claude-sonnet-5`.

## Technical details

The provider is `run_kiro()` in `evals/providers.py`, registered in `PROVIDERS`, `PROVIDER_DEFAULTS` and `ISOLATION_MODES`. It calls `kiro-cli chat --agent-engine v3 --no-interactive --trust-tools= --output-format stream-json --model <model>` from a fresh temporary directory. The merged code differs from the issue text: the prompt goes on stdin rather than after `--`, which also avoids Kiro parsing the skill's `---` frontmatter as an option. The output is `stream-json`, not plain text. The default model is `claude-sonnet-5`, not `auto`, because `auto` picks a model per task and runs would not compare.

Older `kiro-cli` releases leave their agent server running with the inherited stdout, so stdout and stderr go to temp files, the process is started in its own session, and the whole process group is killed after `wait()`. The answer comes from the `runFinished` event's `finalText`. If that is truncated or missing, the `agent_message_chunk` updates are joined instead.

Each call gets a throwaway `KIRO_HOME`, so the operator's `~/.kiro` steering, skills and agents do not load. `_kiro_context()` reads the steering from the session log under `KIRO_HOME` and the skills and agents from the stream's command list. It raises `ContextLeakError` for anything that is not bundled with Kiro, or when no session log exists. Per the docs, `kiro-cli` 2.16 still read `~/.kiro` with `KIRO_HOME` set, so it is unsupported. `test_scoring.py` tests this against a fake `kiro-cli`. `CONTRIBUTING.md`, `evals/inspect/README.md` and `evals/inspect/to_eee.py` were updated for the new provider.

## Upgrade

Install `kiro-cli` 2.31 or later, then run:

```bash
python3 evals/run-evals.py --behavioral --skill drupal-automated-testing --provider kiro
```
