## Summary

AI Agents 1.4.x and its submodules now declare compatibility with Drupal 12 while still supporting Drupal 10.3 and 11. The change came from an automated Project Update Bot issue. It also fixes how constraints are passed to tool parameters so they keep working on Drupal 12.

## Impact

Affects site owners.

- **Requirements:** All AI Agents submodules now allow `^12` in `core_version_requirement`, and `composer.json` allows `drupal/core: ^10.2 || ^11 || ^12`.

## Technical details

Drupal 12 expects Symfony validator constraint options as a named array. The commit changes the `Choice`, `AllowedValues` and `ComplexToolItems` constraints on `ContextDefinition` attributes in the tool plugins to the named form, for example `'Choice' => ['choices' => [...]]`, `'AllowedValues' => ['choices' => [...]]` and `'ComplexToolItems' => ['value' => ...::class]`. `AiAgentEntityWrapper` does the same for constraints it adds at runtime: `FixedValue` now gets `['value' => $context_value]` and `Choice` gets `['choices' => $values]` for the `force_value` and `only_allow` tool limits.

The `ai_agents_explorer` library also gains an explicit `core/drupalSettings` dependency. The rest of the diff is test-only: `#[Group('ai_agents')]` attributes, and `AiAgentOverrideKernelTest` now sets `configSchemaCheckerExclusions` in `setUp()` because Drupal 12 types that parent property. A few assertions were loosened for output differences, such as the empty `{ }` YAML formatting.

## Upgrade

Custom tool plugins that pass constraint options as a bare list should use named options. This is the pattern the commit applies:

```php
constraints: [
  'Choice' => ['choices' => [DRUPAL_REQUIRED, DRUPAL_OPTIONAL, DRUPAL_DISABLED]],
],
```
