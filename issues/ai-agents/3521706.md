## Summary

The 'Create with AI' button on the Manage Fields page (from the `ai_agents_form_integration` submodule) now works when you submit only a prompt. Previously, submitting without uploading a document crashed with a "Cannot load the file entity with NULL ID" error, and the document upload widget itself failed because it used a validator that no longer exists. After generation, you now get a success message and are redirected back to the Manage Fields page. The document field now accepts only `csv` files.

## Impact

No upgrade or configuration changes required.

## Technical details

In `FieldTypeCreation::submitForm()`, the code assumed `$form_state->getValue('document')[0]` always existed and loaded it as a file entity. It now adds the prompt to the batch `$data` and only loads the file when the `document` value is non-empty. When a CSV is uploaded, `$data` is set from `getBatchDataForCsv()`, which replaces the prompt entry added just before it.

The `file_validate_extensions` upload validator (a `PluginNotFoundException` on current core) is replaced with `'FileExtension' => ['extensions' => 'csv']`, and the `managed_file` element gets `'#required' => FALSE`. The code that built the allowed-extension list from the Chat with Image Vision provider and the `unstructured` module, along with its warning message, was removed. The description text now lists only `csv`, so image and Unstructured-based document types are no longer offered on this form.

In `FieldTypeGeneration`, the batch `finished()` callback passed an already resolved `Route` object to `Url::fromRoute()`, which expects a route name. It now keeps the name in `$route_name` and passes that. The batch operation also adds a "Fields has been created successfully." message after `$agent->solve()`.
