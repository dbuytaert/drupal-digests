## Summary

The Content Type agent could white-screen when the LLM answered with something other than JSON, for example in response to an incomplete prompt in the agent explorer. The agent now validates the response and asks the LLM to retry with valid JSON. If it still can't understand the request, it throws a clearer message: "The content type agent can not understand your request."

## Impact

Affects module maintainers.

- **New API:** Two new `AiAgentValidation` plugins: `json_exists_validation` and `determine_node_type_task_validation`.

## Technical details

The Content Type agent's YAML config gains a `validation` block that runs `json_exists_validation` and `determine_node_type_task_validation` through their `defaultValidation` method. Both are new `AiAgentValidation` plugins under `Drupal\ai_agents\Plugin\AiAgentValidation`. Each decodes the response with `ai.prompt_json_decode` when it is a `ChatMessage` or `StreamedChatMessageIteratorInterface`. On failure each throws `AgentRetryableValidationException` with a hint telling the LLM to return RFC8259 compliant JSON.

`JsonExistsValidation` only checks that the decoded result is an array. `DetermineNodeTypeTaskValidation` also requires `[0]['action']` to be one of `create`, `edit`, `delete`, `information` or `fail`.

Smaller changes: the exception message in `ContentType::determineTypeOfTask()` was reworded. The prompt now says that when only a human readable name or only a data name is given, the other can be inferred. The example `fail` message was changed to "The node type you want to create already exists."
