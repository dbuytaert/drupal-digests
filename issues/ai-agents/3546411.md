## Summary

AI agents can now use a short term memory plugin from the AI module. A new "Short term memory" section on the agent edit form lets you pick a plugin (default is none) and configure it. The plugin decides what part of the conversation is actually sent to the LLM on each request, for example by truncating or summarizing the history, so long running agents don't run out of context. With no plugin selected, behavior is unchanged and the whole conversation is sent.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_agents_post_update_10003()` sets empty defaults for the two new properties on existing agents.
- **Config change:** New `short_term_memory_plugin` (string, default empty) and `short_term_memory_config` (plugin settings) properties on `ai_agents.ai_agent.*` config entities; the agent now depends on the module providing the selected plugin.
- **New API:** `AiAgentEntityWrapper` and `AiAgentManager` take the `plugin.manager.ai.short_term_memory` service as a new constructor argument; `AiAgentForm` gets a matching one.

## Technical details

Two new config properties, `short_term_memory_plugin` and `short_term_memory_config`, are added to the `AiAgent` entity and to the `ai_agents.ai_agent.*` schema. The config schema uses `type: ignore` for the plugin settings, with a `@todo` to use `ai.short_term_memory.settings.[%parent.short_term_memory_plugin]` in 2.0. `AiAgent::calculateDependencies()` adds the plugin's providing module as a dependency, and `onDependencyRemoval()` resets the plugin and config to empty instead of deleting the agent when that module is removed. `AiAgentForm::buildShortTermMemoryForm()` renders a plugin select with an AJAX-loaded subform from the plugin's `buildConfigurationForm()`. Validation and submit are delegated to the plugin through `SubformState`, and the saved config is `getConfiguration() + defaultConfiguration()`.

In `AiAgentEntityWrapper`, the new `applyShortTermMemory()` runs just before the `ChatInput` is built. It calls the plugin's `process()` with the current values and the untouched originals. The agent's own `$chatHistory` is never modified, because it is needed for tool call bookkeeping. Only the request's chat history, system prompt and tools, and the `AgentRequestEvent` payload, use the plugin's output. Between loops the wrapper keeps `memoryChatHistory`, `memoryChatHistoryOffset`, `memorySystemPrompt` and `memoryToolNames`. Messages the agent appended since the last call are added to the plugin's previous history. The system prompt and tools carry over only if the plugin actually changed them, because the agent rebuilds them each loop. The thread id passed is `threadId`, falling back to the runner id, and `request_id` is `runnerId:looped`. Any `\Throwable` from the plugin is logged and the full conversation is sent instead.

## Upgrade

Code that instantiates `AiAgentEntityWrapper`, `AiAgentManager` or `AiAgentForm` directly must pass the extra `plugin.manager.ai.short_term_memory` service (`AiShortTermMemoryPluginManager`) as the last constructor argument. Run `drush updb` so `ai_agents_post_update_10003()` sets the new properties on existing agents.
