## Summary

AI agents that call tools with a parameter explicitly set to `0` now pass that value to the tool. Before, `0` was dropped, so the tool's default took over. In the reported case, asking the Drupal CMS Assistant chatbot how many taxonomy vocabularies exist returned only 10 and reported a count of 10, even when more existed. The issue is closed as fixed, but the merge request had not been committed when this was written.

## Impact

No upgrade or configuration changes required.

## Technical details

In `AiAgentEntityWrapper`, where tool parameters from the agent's configured tools are applied to the tool plugin, the guard `if ($parameter_value)` treated `0` as empty and skipped `setContextValue()`. The `amount` context then fell back to its field-definition default of 10, which capped config entity listings. The proposed change in MR !168 is `if (!empty($parameter_value) || $parameter_value === 0)`. The strict comparison only matches integer `0`. Other falsy values, including the string `"0"`, still behave as before. Reading this as "0 means no limit" is the issue author's framing, and I did not verify it in the tool code.
