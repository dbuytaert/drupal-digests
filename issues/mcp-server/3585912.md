# #3585912: STDIO tool calls execute without an authenticated user, so permission-gated tools fail

## Summary

Previously, `drush mcp:server` (the STDIO transport used by AI clients like Claude Desktop) ran every tool call as the anonymous user, so any permission-gated tool (most entity or configuration reads/writes) silently failed access checks. The command now requires a Drupal account argument, a user name or numeric ID, and runs the whole session as that account, so permission checks evaluate correctly. Passing `0` still allows an explicit anonymous session. Existing MCP client configurations and manual invocations that call `mcp:server` with no argument will now fail with an error rather than silently running as anonymous, so they need to be updated to pass an account. Running the command from an interactive terminal without an argument now opens a user picker instead of failing.

## Impact

Affects module maintainers and site owners.

- **Requirements:** Minimum Drush version for the STDIO transport raised from 12.x to 13.
- **API change:** `drush mcp:server` now takes a required `account` argument (user name or numeric ID, or `0` for anonymous); invocations that omit it now error instead of running as anonymous.

## Technical details

The fix is in `McpServerCommands::server()`, which gained a required `account` positional argument. `loadAccount()` resolves it: `'0'` becomes an `AnonymousUserSession`, an all-digit value loads the user by ID, anything else is looked up by user name via `entity_type.manager`'s `user` storage; blocked or unresolvable accounts throw before the transport is created. The resolved account is applied with the `account_switcher` service (`AccountSwitcherInterface::switchTo()`), and `switchBack()` runs in a `finally` block so the process-global account is always restored.

A Drush `#[CLI\Hook(type: HookManager::INTERACT, ...)]` hook, `interactAccount()`, handles the case where the argument is omitted: if STDIN is a TTY (a real terminal, not an MCP client's pipes), it prompts with `$this->io()->search()` against `matchUsers()` (a fuzzy, access-check-free lookup over active user names); otherwise Symfony's normal missing-argument error is reported on STDERR before the server is built, so nothing corrupts the STDIO transport. The `README.md` and the `mcp_server_test` module's new `test_current_user` tool (which reports the acting `uid`, name, and a permission check) were added to support this. The change also bumps the documented minimum Drush version for STDIO to 13.</technical>
<parameter name="upgrade">Update any MCP client configuration or manual invocation of the STDIO transport to pass an account:

```json
{
  "mcpServers": {
    "drupal": {
      "command": "vendor/bin/drush",
      "args": ["mcp:server", "admin"]
    }
  }
}
```

or from the shell:

```bash
drush mcp:server admin
```

Use `drush mcp:server 0` to keep running as anonymous. Also confirm the site runs Drush 13 or higher for the STDIO transport.
