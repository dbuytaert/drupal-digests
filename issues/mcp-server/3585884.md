# #3585884: Version requirements in submodule .info files causes issues

- **Project:** Drupal AI
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3585884](https://git.drupalcode.org/project/mcp_server/-/work_items/3585884) · 1 contributor · 4 comments

## Summary

Installing MCP Server from an unreleased dev snapshot via Composer left the main `mcp_server.info.yml` without version metadata (Drupal only stamps a module's version when drupal.org tags a release). A prior change had added a `mcp_server:mcp_server (>=2.0)` version constraint to the submodules' dependency declarations, so Drupal could not resolve that constraint against the versionless parent module. This blocked enabling the submodules (UI, OAuth, tool bridge, examples) from the admin interface and made `drush core:requirements` report unresolved dependency errors, breaking CI/CD pipelines that check requirements. The fix removes the problem at its root: the affected submodules are no longer shipped inside the `mcp_server` project at all. They have been split out into separate companion projects with their own Composer-managed versioning, so the in-tree version constraint that caused the failure no longer exists.

## Impact

No upgrade or configuration changes required.

## Technical details

The constraint was introduced in commit `a82ea733` (issue [#3585873](https://www.drupal.org/node/3585873)), which added `mcp_server:mcp_server (>=2.0)` to the `dependencies` key of `mcp_server_ui.info.yml`, `mcp_server_oauth.info.yml`, `mcp_server_tool_bridge.info.yml`, and `mcp_server_examples.info.yml`. Since dev installs of `mcp_server` carry no version string, Drupal's dependency resolver treats `>=2.0` as unsatisfiable and refuses to enable the dependents, both in the admin UI and via `drush core:requirements`.

The actual fix landed in [#3585898](https://www.drupal.org/node/3585898) ("Extract in-tree submodules into separate companion projects"), which deletes `modules/mcp_server_ui`, `modules/mcp_server_oauth`, `modules/mcp_server_tool_bridge`, and `modules/mcp_server_examples` from this repository along with their `require-dev` entries (`drupal/simple_oauth`, `e0ipso/simple_oauth_21`) in `composer.json`. Core `mcp_server` is now a standalone module with no Drupal module dependencies, requiring only `php` and `mcp/sdk` at the Composer level, which removes the problematic info.yml version constraint entirely rather than trying to work around it.
