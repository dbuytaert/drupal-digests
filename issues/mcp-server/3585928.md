# #3585928: Session lock delays elicitation and sampling replies until the lease expires

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Version:** 2.x-dev
- **Status:** Fixed
- **Discussion:** [#3585928](https://git.drupalcode.org/project/mcp_server/-/work_items/3585928) · 1 contributor · 7 comments

## Summary

Tools that ask the client for something mid-call, through `ClientGateway::elicit()`, `sample()` or `listRoots()`, no longer stall for about 30 seconds per round trip. The session lock added in [#3585923](https://www.drupal.org/node/3585923) had been holding off the client's reply until the lock lease expired. The reply is now accepted while the streamed response is waiting.

## Impact

No upgrade or configuration changes required.

## Technical details

The module now uses an `@internal` subclass, `SessionLockingStreamableHttpTransport`, in place of the SDK's `StreamableHttpTransport`. The issue picked the "release the lock while waiting" option. Letting reply-only POSTs skip the lock was rejected because the SDK saves the session as one blob, so an unlocked write could clobber the stream's `_mcp.outgoing_queue` (upstream php-sdk#275).

In `McpServerController::handle()`, the streaming callback now calls `lockSessionPerWrite()` on the transport and then releases the request-wide session lock. From then on the transport takes the lock only around the session read-modify-writes in the SDK's streaming loop, by overriding `getOutgoingMessages()`, `checkForResponse()` and `handleFiberYield()`. The client's reply POST can therefore get in between polls. If the lock cannot be acquired after one `wait()`, it throws `LockAcquiringException`.

If a database transaction is open (`Connection::inTransaction()`) when the stream starts, the controller keeps holding the lock for the whole stream. A rollback would undo the release. The subclass overrides protected SDK hooks, which the class docblock says can change in any mcp/sdk minor release. The controller now also takes the `database` service. The commit adds an `ElicitingTool` test plugin and extends `McpServerFunctionalTest` to cover an elicitation round trip.
