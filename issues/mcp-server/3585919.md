# #3585919: Nested empty object schemas still serialize as [] because normalizeObjectSchema() only normalizes the top level

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Version:** 2.x-dev
- **Status:** Fixed
- **Discussion:** [#3585919](https://git.drupalcode.org/project/mcp_server/-/work_items/3585919) · 1 contributor · 10 comments

## Summary

The MCP Server module builds JSON Schema definitions for each registered tool and sends them to connecting MCP clients. An empty `properties` map is indistinguishable from an empty array in PHP, and a prior fix ([#3585899](https://www.drupal.org/node/3585899)) made sure the top-level `properties` of a tool's input schema always serializes as a JSON object (`{}`) rather than an array (`[]`). This issue found that the fix only checked the top level: a nested empty object, for example a free-form `opts` parameter, still serialized as `[]` several levels down. Strict MCP clients reject schemas with an array where an object is required, so a tool declaring such a nested parameter could fail to register with those clients. The fix makes the normalization recursive so every nested schema position, not just the top level, is corrected.

## Impact

No upgrade or configuration changes required.

## Technical details

`McpServerFactory::normalizeObjectSchema()` previously converted only the schema's top-level `properties` value. It now delegates to a new `normalizeSchema()` helper that walks every JSON Schema keyword that can hold a sub-schema: single sub-schema keywords (`additionalProperties`, `contains`, `if`/`then`/`else`, `not`, `propertyNames`, `contentSchema`, etc.), map keywords (`properties`, `$defs`, `definitions`, `patternProperties`, `dependentSchemas`), and list keywords (`allOf`, `anyOf`, `oneOf`, `prefixItems`), recursing into each. `items` and draft-07 `dependencies` get special-cased handling since each can hold either a single sub-schema or a list, and an empty array means something different in each case (`items: []` is the empty schema, `allOf: []` is a valid empty list). Any sub-schema that is an empty PHP array is replaced with `\stdClass` so it serializes as `{}`.

The module's `tests/modules/mcp_server_test` gained a `NestedSchemaTool` fixture that declares empty object schemas in every nested position (`items`, `additionalProperties`, `anyOf`, `$ref` targets in `$defs`, `contentSchema`, `dependencies`), and `ToolSchemaNormalizationTest` asserts each one decodes back as `\stdClass` rather than an empty list.

Two things called out in the issue were left out of scope deliberately: `registerTools()` still passes a tool's `outputSchema` through without normalization, so a top-level empty `outputSchema.properties` still serializes as `[]` (tracked separately per the issue); and `normalizeObjectSchema()` still unconditionally overwrites `$schema['type']` to `'object'`, silently masking a tool that declared a different type instead of surfacing the SDK's `InvalidArgumentException`.
