# #3585939: mcp/sdk 0.8 logs an empty middleware list warning on every HTTP request

## Summary

With mcp/sdk 0.8, every MCP HTTP request wrote a warning to the site log saying the Streamable HTTP transport started with an empty middleware list. The warning is gone. CORS handling stays with Drupal's `cors.config`, and Host validation stays with `trusted_host_patterns`. The SDK's own CORS and DNS-rebinding middleware remain off, so there are still no duplicate CORS headers and no 403 for non-localhost hosts.

## Impact

No upgrade or configuration changes required.

## Technical details

The SDK warns only when the middleware list is exactly `[]`. It installs its default CORS and DNS-rebinding middleware only when it gets `null`. `McpServerController::handle()` now uses `$this->middlewareCollector->getMiddleware() ?: [new PassThroughMiddleware()]`. When no module tags a `mcp_server.transport_middleware` service, the transport gets a one-entry list holding a no-op middleware. If any middleware is tagged, the controller passes that stack unchanged. The issue text proposed tagging the pass-through as a service. The merged diff instead instantiates it in the controller, so there is no new service definition.

`Drupal\mcp_server\Transport\PassThroughMiddleware` is a `final`, `@internal` PSR-15 middleware that calls `$handler->handle($request)`. Its docblock says mcp/sdk 0.9 ships its own `PassthroughMiddleware`, which can replace it once 0.9 is the minimum. The SDK maintainers suggested this opt-out in php-sdk#523, instead of a constructor flag. A logger wrapper that matched on the SDK's message text was dropped, because that text can change in any SDK minor. A kernel test in `McpServerControllerTest` asserts that an `initialize` request returns 200 and logs no record containing "empty middleware list". The diff also updates the project's internal knowledge-base docs. Those docs say `ProtocolVersionMiddleware` only applies on mcp/sdk 0.7 and that `McpServerServiceProvider::alter()` removes it on 0.8. That change is not part of this MR's code diff.
