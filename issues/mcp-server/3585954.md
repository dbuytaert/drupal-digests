## Summary

mcp_server 2.x now requires mcp/sdk 0.9 or later, and drops support for 0.7 and 0.8. Per-session request serialization is no longer done by module code in the HTTP controller and a custom transport. The SDK's own session lock now does it, backed by Drupal's lock service. The change also fixes tool input schemas that Tool API writes with an empty `properties` map (an `\ArrayObject`), which the SDK's `Tool` class would not accept.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `mcp/sdk` constraint changed from `^0.7.1 || ^0.8` to `^0.9`; 0.7 and 0.8 are no longer supported.
- **API change:** The `mcp_server.middleware.protocol_version` service (tagged `mcp_server.transport_middleware`) is removed. `McpServerController` no longer takes the lock or database services.
- **New API:** New `mcp_server.session_lock` service, `Drupal\mcp_server\Session\LockBackendSessionLock`, implementing the SDK's `SessionLockInterface`.

## Technical details

`McpServerFactory` takes a new `SessionLockInterface` argument and passes it to `Builder::setSessionLock()`. The implementation is `LockBackendSessionLock`, registered as `mcp_server.session_lock` with the `lock` and `database` services. It keeps the lock name `mcp_session:<sha256 of session id>`. `acquire()` waits once and then throws the SDK's `SessionLockTimeoutException`. `tryAcquire()` is for the SDK's SSE polls. `release()` is deferred while `Connection::inTransaction()` is true, because a rollback would restore the deleted semaphore row. This keeps the old behavior for a tool that suspends inside a transaction.

`SessionLockingStreamableHttpTransport`, which overrode protected SDK hooks, is deleted. So are its lock handling in `McpServerController::handle()` and the `PassThroughMiddleware` class. The controller now builds the SDK's `StreamableHttpTransport` and passes the SDK's `PassthroughMiddleware` when no middleware is tagged. SSE responses are still converted to streamed Symfony responses. A lock timeout is now answered by the SDK (503 with a JSON-RPC error), not by `ServiceUnavailableHttpException`.

The 0.7/0.8 compatibility code is also removed. That covers the `method_exists()` guards around `setRequestState()`, `McpServerServiceProvider::alter()`, and the `mcp_server.middleware.protocol_version` service. `FiberShield` now recognizes the SDK's `RequestSuspension` and `NotificationSuspension` objects, where it used to look for an array with a `type` key. `McpServerFactory` converts an `\ArrayObject` schema map to an array. A `test_array_object_input` tool was added to `mcp_server_test` to cover that. The CI lowest-SDK job and the contributor docs now pin `^0.9`.

## Upgrade

Update the constraint in `composer.json`:

```json
"mcp/sdk": "^0.9"
```

Code that tags or references `mcp_server.middleware.protocol_version`, or constructs `McpServerController` directly with the lock and database arguments, needs updating. The SDK's transport already applies `ProtocolVersionMiddleware` to handshake-era requests.
