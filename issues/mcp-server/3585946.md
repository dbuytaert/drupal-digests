## Summary

The issue reported that two tool calls eliciting on the same MCP session could receive each other's answers. The proposed fix was to wait for an upstream fix in the PHP SDK (php-sdk#544) and then add a test. The shipped commit raises the SDK requirement to `mcp/sdk` ^0.9 only. The SDK now owns the per-session locking that this module used to do itself. Sites need an SDK 0.9 install, and 0.7 and 0.8 are no longer supported. The commit does not include the end to end test with two eliciting tool calls that the issue proposed.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `mcp/sdk` constraint changes from `^0.7.1 || ^0.8` to `^0.9`; 0.7 and 0.8 are no longer supported.
- **API change:** The `mcp_server.middleware.protocol_version` service is removed, and the `mcp_server.session_lock` service is added. Calling code that referenced `mcp_server.middleware.protocol_version` must stop doing so.

## Technical details

The module's own locking is replaced by SDK hooks. `McpServerController` no longer takes a Drupal lock around the whole run, and it no longer wraps the SSE stream callback to release the lock. It builds the SDK's own `StreamableHttpTransport`. The custom `SessionLockingStreamableHttpTransport`, which overrode `getOutgoingMessages()`, `checkForResponse()` and `handleFiberYield()`, is deleted. So is the `PassThroughMiddleware` class, replaced by the SDK's `PassthroughMiddleware`.

The new `Drupal\mcp_server\Session\LockBackendSessionLock` implements the SDK's `SessionLockInterface` (`acquire()`, `tryAcquire()`, `release()`) on Drupal's `lock` service. It uses the lock name `mcp_session:<sha256 of session id>`, as before. `acquire()` waits once and retries, then throws the SDK's `SessionLockTimeoutException`. If a tool suspends inside a database transaction, `release()` is deferred until the transaction ends, because a release inside it would be invisible to other requests and a rollback would restore the semaphore row. The service is `mcp_server.session_lock`, passed to `McpServerFactory`, which calls `Builder::setSessionLock()`.

Other changes: `FiberShield` now recognises the SDK's `RequestSuspension` and `NotificationSuspension` objects instead of arrays with a `type` key. `McpServerFactory` calls `setRequestState()` unconditionally. It also converts an empty `ArrayObject` schema map (as Tool API writes it) to an array before building the SDK `Tool`. The `mcp_server.middleware.protocol_version` service and `McpServerServiceProvider::alter()` are removed, because the 0.9 transport applies that middleware itself. CI's lowest-SDK job now pins `^0.9`. Tests that hit `StdioTransport` now use `tmpfile()` for stdin, since the transport's `stream_select()` rejects `php://memory`.

## Upgrade

Update the SDK constraint in `composer.json`:

```json
"mcp/sdk": "^0.9"
```

Custom code that referenced the `mcp_server.middleware.protocol_version` service, `Drupal\mcp_server\Transport\PassThroughMiddleware` or `SessionLockingStreamableHttpTransport` must stop using them. Use `Mcp\Server\Transport\Http\Middleware\PassthroughMiddleware` and the SDK's `StreamableHttpTransport` instead.
