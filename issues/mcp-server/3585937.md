# #3585937: Tool call arguments and results end up in the Drupal log

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Version:** 2.x-dev
- **Status:** Fixed
- **Discussion:** [#3585937](https://git.drupalcode.org/project/mcp_server/-/work_items/3585937) · 1 contributor · 13 comments

## Summary

MCP Server no longer writes tool call arguments and results to the Drupal log by default. Before, one `tools/call` could leave the full request and the tool result in Database Logging, readable by anyone with `access site reports`. The log now shows the JSON-RPC method and the outcome. Sites that want full payloads while debugging can turn them back on with a container parameter.

## Impact

Affects site owners.

- **Security:** Tool arguments, results and request payloads no longer land in dblog or other log backends by default, where anyone with `access site reports` could read them.
- **Config change:** New `mcp_server.log_payloads` container parameter, `false` by default, set in `services.yml` rather than config.

## Technical details

The fix is in `McpContextLogger`, the PSR-3 decorator that appends `@mcp_*` placeholders so context values survive into dblog. It now takes a second constructor argument, `bool $logPayloads` (default `FALSE`), wired in `mcp_server.services.yml` from the new `mcp_server.log_payloads` parameter (default `false`).

When payloads are off, a private `withoutPayload()` filters each context value. An object implementing `HasMethodInterface` is reduced to its method. A `Response` or JSON-RPC `Error` is reduced to its ID. The SDK's raw input under the `message` key is dropped, and so is any array or non-stringable object. Dropping is by type and not by a list of key names, so a payload logged under a new SDK key stays out too. `Throwable`, `Stringable` and `UnitEnum` values and scalars are kept, and the existing `exception` handling is unchanged. Dropped keys are also removed from the context passed to the inner logger, because backends such as Monolog can store the whole context and not just the placeholders in the message.

The switch is a container parameter and not config, so it is set in `development.services.yml` and cannot reach production through config sync. The README documents it.

## Upgrade

To log tool arguments and results in full while debugging, set the parameter in a services file such as `development.services.yml`:

```yaml
parameters:
  mcp_server.log_payloads: true
```
