## Summary

When the MCP server runs over STDIO (`drush mcp:server`), content edits made by an AI client were stamped with the time the client connected, not the time of the edit. This affected entity changed times, revision creation times and comment created times. Each STDIO message now gets the current time as its request time, so timestamps are correct for the whole session. HTTP transport was never affected.

## Impact

No upgrade or configuration changes required.

## Technical details

`drush mcp:server` is one long-lived PHP process, so Drupal's request time, read from the initial request's `REQUEST_TIME`, never advanced. The fix adds `Drupal\mcp_server\EventSubscriber\StdioRequestTimeSubscriber`, registered as `mcp_server.stdio_request_time_subscriber` with `@request_stack`. It subscribes to the MCP SDK's `Mcp\Event\RequestEvent` at priority 1000, so other listeners already see the new time.

When `PHP_SAPI === 'cli'`, it sets `REQUEST_TIME` and `REQUEST_TIME_FLOAT` on the current request's `server` bag. It also sets them in `$_SERVER`, because core's time service falls back to `$_SERVER` when there is no request. Under any other SAPI it does nothing, since each HTTP message is already its own request. A kernel test, `StdioRequestTimeTest`, backdates the request time and checks that both `initialize` and `ping` messages move it forward.
