## Summary

MCP resource content cached for one user could be returned to other users. A resource that varied by a cache context such as `user` kept serving the first caller's content to everyone with view access until the entry expired. Access checks still ran on every call, so the leak only affected users who were allowed to read the resource. Each caller now gets the cached variation for their own context values.

## Impact

Affects site owners.

- **Security:** Cached MCP resource content could be served to a different user than the one it was generated for, when the content varied by cache context (e.g. `user`) and both users had view access.

## Technical details

The old `ResourceContentCache::generate()` stored the first caller's resolved context keys (for example `[user]=10`) in a pointer entry at `mcp_resource:{uri}`. It reused that suffix for every later lookup. Render caching avoids this by storing context tokens and resolving them again on each request.

The class now delegates storage to core's `VariationCacheInterface`, the store `RenderCache` uses. It is wired as a new service, `mcp_server.variation_cache.resource`, created from `variation_cache_factory` over the `default` bin. The `mcp_server.resource_content_cache` service takes only that service as its argument, so the constructor no longer takes `cache.default` and `cache_contexts_manager`. Cache keys are `['mcp_resource', hash('sha256', $expandedUri)]`. The URI is hashed because it is client-controlled and the variation cache joins keys and context keys with `:`, so a raw URI could spell another caller's cache ID. The access result's cacheability is passed as the initial cacheability to both `get()` and `set()`, and it is merged into the DTO metadata.

Behavior that stays the same: the access callback runs on every call and is never cached, and a `NULL` from the content callback raises `ResourceNotFoundException`. Content with max-age 0 is not stored. A new kernel test, `ResourceContentCacheTest`, covers two users reading one resource, the URI-spoofing case, and max-age 0.

## Upgrade

Previously cached resource content sits under the old `mcp_resource:{uri}` pointer keys, which the new code does not read, so it is simply ignored. Clear caches if you want those stale entries removed. Code that constructs `ResourceContentCache` directly must pass a `VariationCacheInterface` instead of the cache backend and contexts manager. The class is `final` and used through the `mcp_server.resource_content_cache` service.
