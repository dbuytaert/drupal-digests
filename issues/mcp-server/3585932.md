# #3585932: "mcp_prompt_config" entity type does not exist on Drupal 10 and 11.0

- **Project:** Drupal AI
- **Type:** Major bug report
- **Version:** 2.x-dev
- **Status:** Fixed
- **Discussion:** [#3585932](https://git.drupalcode.org/project/mcp_server/-/work_items/3585932) · 1 contributor · 9 comments

## Summary

Sites running the MCP Server module on Drupal 10.x or 11.0 had the "MCP Prompts" feature completely broken: the module's logs filled with "Failed to load prompt configs" errors and the Prompts admin tab crashed with a `PluginNotFoundException`. This is now fixed, so prompts load and the Prompts tab works again on Drupal 10 and 11.0, not just 11.1 and later.

## Impact

No upgrade or configuration changes required.

## Technical details

The `mcp_prompt_config` config entity was declared only via the PHP `#[ConfigEntityType]` attribute. Drupal core only reads entity type attributes starting in 11.1; on 10.x and 11.0 the entity type manager relies on annotation-only discovery, so the entity type never registered and both `McpServerFactory::loadEnabledPromptConfigs()` and the `mcp_server_ui` Prompts listing route (which uses `_entity_list: mcp_prompt_config`) failed.

The fix adds a `@ConfigEntityType` docblock annotation to `Drupal\mcp_server\Entity\McpPromptConfig` that mirrors the existing attribute (same `id`, `config_prefix`, `entity_keys`, `handlers`, and `config_export`), so 10.x and 11.0 discover the entity via the annotation while 11.1+ continues to use the attribute. This is the same approach already applied in the `mcp_server_tool_bridge` module.

To actually catch this class of regression, `.gitlab-ci.yml` now opts into running the previous core major on every pipeline (`OPT_IN_TEST_PREVIOUS_MAJOR`, `_AUTORUN_PREVIOUS_MAJOR: all`, `CORE_PREVIOUS_PHP_MIN: 8.3`) and `composer.json` widens the `phpstan`/`mglaman/phpstan-drupal` constraints so those tools install under Drupal 10's PHP baseline. Running against Drupal 10 also exposed that its bundled PHPUnit 9.6 ignores the `#[Group]`, `#[CoversClass]`, and `#[DataProvider]` PHP attributes several tests rely on, so those tests gained matching docblock tags (`@group`, `@coversDefaultClass`, `@dataProvider`) alongside the attributes.</technical>
