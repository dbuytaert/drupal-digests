## Summary

When an MCP client sent several requests at once on the same session (for example `resources/read`, `resources/list` and `tools/list`), some of them could fail immediately with a 503 "MCP session lock timeout" even though no real timeout had happened. Requests that lose the race for the session lock now keep waiting, up to 30 seconds in total, and only get a 503 if the lock really stays busy that long. The reporter's test went from 2 failures in 90 requests to 270 of 270 passing.

## Impact

Affects module maintainers.

- **API change:** `LockBackendSessionLock` takes the `datetime.time` service as a new third constructor argument.

## Technical details

`LockBackendInterface::wait()` returns as soon as the lock looks free. With three or more concurrent requests, two waiters can see it free, one takes it, and the other's single follow-up `acquire()` fails at once. `LockBackendSessionLock::acquire()` now loops on `acquire()` against one deadline of `WAIT_SECONDS` (30), computed from `TimeInterface::getCurrentMicroTime()`. Each `wait()` gets only the remaining time, rounded up to whole seconds. A `TRUE` return from `wait()` means the lock stayed held for the whole delay, so it throws `SessionLockTimeoutException`, which the SDK answers with a 503. A `FALSE` return means the lock looked free, so the loop retries `acquire()`. Retrying `acquire()` once more was rejected because it only moves the race. Restarting a full 30 s `wait()` each time was rejected because it could hold a worker without limit.

The loop lives in `LockBackendSessionLock`, the `SessionLockInterface` adapter the SDK calls for every locked request. The issue says an earlier patch with a separate `SessionLock` class was dropped in favor of this. The service definition gains `@datetime.time` as a third argument. The commit adds unit tests (`LockBackendSessionLockRaceTest`, with `FakeClock` and `ContendedLockBackend` helpers) covering a free lock, lost races, a shared budget and a long hold. The kernel test constructors were updated for the new argument.

## Upgrade

Rebuild caches after updating, because the `mcp_server.session_lock` service definition gained an argument. Code that constructs `LockBackendSessionLock` directly must pass the time service as the third argument:

```php
new LockBackendSessionLock($lock, $database, $this->container->get('datetime.time'))
```
