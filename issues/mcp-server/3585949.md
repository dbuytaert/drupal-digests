## Summary

mcp_server 2.x now requires mcp/sdk 0.9 and no longer installs with 0.7 or 0.8. Update with `composer update mcp/sdk --with-all-dependencies` when you update the module. The issue's release notes say 0.9 rejects tool results that don't match a tool's `outputSchema`, so custom tools with a mismatched schema will start returning errors. The issue says 0.9 also fixes concurrent SSE streams of one session taking each other's client responses, and stateless SSE output buffering that kept Claude Code from connecting.

## Impact

No upgrade or configuration changes required.

## Technical details

The commit raises the floor in `composer.json` and pins the `composer (lowest SDK)` CI job to `^0.9`. It also removes the code that handled 0.7 and 0.8: the `method_exists()` guards, the `mcp_server.middleware.protocol_version` service, and `McpServerServiceProvider::alter()`. The controller now passes the SDK's own `PassthroughMiddleware` when no middleware is tagged, replacing the deleted `Transport\PassThroughMiddleware`.

Session locking moved from the controller into the SDK. `McpServerController` no longer takes a lock, and `SessionLockingStreamableHttpTransport` is deleted. `McpServerFactory` passes the new `LockBackendSessionLock` to `Builder::setSessionLock()`. It uses the same lock name as before, `mcp_session:` plus the sha256 of the session id. It throws `SessionLockTimeoutException` when the lock can't be acquired. The SDK holds the lock around session reads and saves, and releases it while a tool waits on the client. If a tool suspends inside a database transaction, the release is deferred until the transaction ends, because a rollback would restore the semaphore row. The issue says 0.9 saves a resumed tool's session inside the fiber resume, which only the SDK's lock covers.

Other adaptations to 0.9: `FiberShield` now re-yields `RequestSuspension` and `NotificationSuspension` objects instead of arrays with a `type` key. `McpServerFactory` converts an `ArrayObject` schema map, such as the empty `properties` map Tool API writes, to an array so the SDK's `Tool` accepts it. A new test tool, `test_array_object_input`, covers that case. Tests that fed `StdioTransport` from `php://memory` now use `tmpfile()`, since the transport calls `stream_select()` on stdin.

## Upgrade

Update the SDK together with the module:

```
composer update mcp/sdk --with-all-dependencies
```

Custom tools that declare an `outputSchema` must return results that match it, or 0.9 will return errors. Code that referenced `Drupal\mcp_server\Transport\PassThroughMiddleware` should use `Mcp\Server\Transport\Http\Middleware\PassthroughMiddleware` instead.
