# #3585930: Default settings omit langcode required for translatable server_instructions

- **Project:** Drupal AI
- **Type:** Normal unknown (0)
- **Status:** Fixed

## Summary

Installing the mcp_server module on a site that enables strict configuration constraint validation, such as via recipes, `ConfigSchemaChecker` with constraints enabled, or Drupal's test-site installer, previously failed with a schema error because the shipped default configuration for `mcp_server.settings` did not declare a language code even though it contains a translatable value (`server_instructions`). The default configuration now ships with `langcode: en`, so installation succeeds. Existing installed sites are unaffected since this only changes the shipped install default, not active configuration, and no update hook was added.

## Impact

Affects site owners.

- **Config change:** Shipped default configuration `config/install/mcp_server.settings.yml` now includes `langcode: en`, since the schema for `mcp_server.settings` marks `server_instructions` as translatable and Drupal 10.3+ requires a langcode on any simple config object with translatable values.

## Technical details

The `server_instructions` key in `mcp_server.settings` config schema is typed as `text`, which is translatable, and Drupal 10.3+'s `LangcodeRequiredIfTranslatableValues` constraint requires any simple config object containing translatable values to declare a `langcode`. The shipped `config/install/mcp_server.settings.yml` omitted it, so `ConfigSchemaChecker` raised "The mcp_server.settings config object must specify a language code, because it contains translatable values" whenever constraint validation ran during install.

The fix adds a single `langcode: en` line to the top of `config/install/mcp_server.settings.yml`. A new kernel test, `McpDefaultSettingsSchemaTest`, installs the module's config and runs the same `ConfigSchemaChecker` (instantiated with constraints enabled, mirroring the test-site installer path) against it, then asserts the `langcode` is `en` and that `server_instructions` is still marked translatable in the typed config schema, guarding against regressions on either front.
