## Summary

This one commit on `1.1.x` covers [#3594862](https://www.drupal.org/node/3594862) and seven related fixes ([#3594855](https://www.drupal.org/node/3594855) to [#3594861](https://www.drupal.org/node/3594861)). The compare page now lists differences with plain names such as "Dataset content" or "Judge model". Dataset and rubric hashes show as "changed" or "same", and the raw keys and values sit in a closed "Technical details" section. Grader ids become grader labels, and the heading reads "1 difference" in the singular. Result screens show the gate a run recorded, or "Gate not recorded", rather than a made-up 4.0 threshold, and they show test labels with the id as a tooltip. Hard and soft gate wording now says the type only changes the exit code of `drush ai-eval:run`. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred", still adding up to 100%. Annotate progress counts labeled answers against the latest run. Calibration screens now warn when a saved fit will not apply because the rubric wording changed, and they say when a save replaced an earlier inactive fit.

## Impact

Affects module maintainers.

- **API change:** `ResultsCompareController::__construct()` gains an optional trailing `?PluginManagerInterface $graderManager` argument (wired to `ai_eval.grader_manager`). `FailureRateService` rows gain a `verdict` key.
- **New API:** `GateTypeWording` helper class in `Drupal\ai_eval\Form` supplies gate type labels and descriptions shared by the target and guided forms.

## Technical details

Compare page: `ResultsCompareController` gets `differenceLabel()` (a `match` from snapshot key to translatable label, unknown keys keep the raw key) and `readableValue()`. `readableValue()` collapses `dataset_sha256` and `rubric_sha256` to changed, same, recorded or not recorded, with per-rubric-reference states. It maps `metric` through `GateMetric::label()`, `gate` to Hard or Soft, and grader ids in `grader_ids`, `must_pass`, `judge_prompt_versions` and `judge_models` to plugin labels from the injected grader manager. Raw values are rendered in a `details` element (`#open` FALSE) titled "Technical details". `RunComparability` is unchanged. The heading uses `formatPlural()`. When the two runs belong to different tests, the warning uses test labels with the id in a `title` attribute and adds cache tags.

Gate display: `EvalResultsController::recordedGate()` builds the `GateThreshold` from the run's validated snapshot (`metric` and `threshold`), then falls back to the live test, then returns NULL. A NULL gate drops the threshold and the gate comparison from the aria label, and the detail page shows "Gate not recorded". Metric names show as labels instead of ids. The overview also loads targets once up front, so tables and the pending-optimization list can show target labels with cache tags. A new `GateTypeWording` class feeds the options and description in `EvalTargetForm` and `GuidedTestForm`.

Annotation and calibration: `FailureRateService::decorate()` merges tagged rows by failure mode and splits rows with no failure mode by `verdict` (`pass`, `fail`, `defer`). Rows now carry a `verdict` key, and the old "(untagged)" label is gone. `WorkflowStateService` drops the fixed suggested target of 100. Step 2 progress is canonical annotations on the latest result over its `question_count`, and the ribbon label is plural-aware ("N of M answers labeled"). `CalibrationSaveTrait::saveAndReport()` counts inactive earlier curves for the same provider, model and fingerprint before saving, and reports the replacement afterwards. `CalibrationFromReviewsForm` compares the group fingerprint to `currentFingerprint()` to warn, and to qualify the readiness text, when the judge no longer asks that question.

## Upgrade

If you construct `ResultsCompareController` directly or subclass it, the new last constructor argument is optional (`?PluginManagerInterface $graderManager = NULL`). Without it, grader ids are shown as they are. Code or tests that match the old "(untagged)" failure-rate label must now expect "Passed", "Failed, no failure mode" or "Deferred".
