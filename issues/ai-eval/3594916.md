## Summary

The judge validation, compare, prompt and run pages no longer open for grader ids that do not exist. Previously a URL like `/judges/definitely_not_a_grader` returned 200 with a Launch button, and saving the prompt form created a judge config for the made-up id. Now those pages return 404. Saved validation history stays readable (validation and compare pages) after a grader module is removed.

## Impact

Affects module maintainers.

- **API change:** `JudgeConfigStore::__construct()` now requires `$configFactory` and a new `GraderPluginManager $graderManager`; its write methods throw for unknown grader ids.

## Technical details

`JudgeValidateController` gets a private `requireGrader(string $graderId, bool $allowHistory = FALSE)` that checks `graderManager->hasDefinition()` (the plugin definition only, no grader is instantiated) and throws `NotFoundHttpException` otherwise. `prompt()` and `run()` require the plugin. `workflow()` and `compare()` pass `$allowHistory = TRUE`, so they 404 only when the plugin is missing and `validationStore->history($graderId, 1)` is empty. For a removed grader with history, `workflow()` shows 'This grader plugin is no longer available.' as the unavailable reason.

The write side is guarded too: `JudgeConfigStore::saveJudgeModelOverride()`, `saveOverride()` and `saveDomainTags()` call `graderManager->getDefinition($graderId)` first, which throws for an unknown id, so no `EvalJudgeConfig` is created for it. `JudgeConfigStore` now takes `GraderPluginManager` as a fourth constructor argument (`@ai_eval.grader_manager` in `ai_eval.services.yml`), and `$configFactory` is no longer nullable, which removes the fallback branch in `effectiveJudgeModel()`. Gold labeling routes already refused unknown ids and are unchanged. `JudgeValidateWorkflowTest` adds `testUnknownGraderRoutes()` and `testRemovedGraderHistory()`.

The same commit bundles fixes for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926); this entry covers only the judge page change. In the same controller it also catches concurrent start and finalize conflicts (`StartInProgressException`, `ActiveValidationException`, `JobBusyException`) and shows a retry message.

## Upgrade

Code that constructs `JudgeConfigStore` directly must now pass a config factory and the grader manager:

```php
new JudgeConfigStore($entityTypeManager, $time, $configFactory, $graderManager);
```

Calling the `JudgeConfigStore` save methods with an id that is not a grader plugin now throws a plugin exception instead of creating a config entity.
