## Summary

A judge validation run no longer gets lost when you leave its page. Coming back to the judge page shows the newest unfinished run with its scored count, resumes polling, and hides the launch form until the run finishes or you press Cancel. The run uses the labels saved when it started, even if you have since changed them. The same commit changes gold labeling. Only final answers (non-empty reply, no tool calls) are used for labeling, coverage, agreement and validation. Labels already stored on tool-call steps are kept but not used, and the judge page reports how many were left out. Gold navigation is now stable: saving a verdict, including Defer, moves to the next unlabeled answer. There is a **Next unlabeled** button and a **Deferred: N** count. When everything is labeled or deferred, the page shows a completion message with a **Review deferred answers** link.

## Impact

Affects module maintainers.

- **API change:** Classes implementing `JudgeValidationRunnerInterface` or `HumanLabelSourceInterface` must add the new methods.
- **New API:** `JudgeValidationRunnerInterface::activeRunFor()` and `cancelValidation()`, and `HumanLabelSourceInterface::nonFinalLabelCount()`, plus `TraceBrowser::finalAnswerIds()` and `TraceBrowser::isFinalAnswer()`.

## Technical details

Validation resume: `JudgeValidationRunner::activeRunFor()` returns the newest `pending` or `running` row for the grader with `total > 0`. `JudgeValidateController::workflow()` renders `ValidationFragment::progress()` for it instead of the launch form. The progress fragment now includes a Cancel button that posts `action=cancel` to the existing CSRF-protected POST progress route, and the route stays POST only. `cancelValidation()` takes the step lock and only cancels when `completed < total`. Once the last score is stored it refuses, and the controller shows a notice that the report appears on the next poll. A canceled run responds with `HX-Refresh` so the page restores the launch form. `stepValidation()` re-reads the run after acquiring the lock so it never scores from stale or canceled state. A stale launch POST to `run()` rejoins the active run instead of starting a second one.

Final-answer filtering: `TraceBrowser::isFinalAnswer()` requires non-empty `response_text` and empty `response_tools`, regardless of the provider finish reason. `TraceBrowser::finalAnswerIds()` pages the source in 200-span chunks and filters before applying the window, so tool steps do not use up the 200-answer limit. `GoldLabelController`, `GoldSetAgreement::domainScope()` and `HumanLabelSource` use it. `HumanLabelSource::nonFinalLabelCount()` feeds the "labels on tool-call steps were not used" line on the judge page. When a domain has only tool steps or empty replies, the gold screen says so.

Gold navigation: the label POST in `ReviewController` accepts an optional local `next` path. It rejects non-strings, paths not starting with `/`, `//` prefixes, and paths with backslashes or whitespace. A posted verdict returns `HX-Location` to `next`, or an `ai-eval-gold-saved` trigger when `next` is empty. A note-only save stays put. `GoldLabelController::passNavigation()` builds Next unlabeled, the deferred count and the completion state. The blind re-label pass keeps first-pass label-id order instead of moving unlabeled items first. The client script skips its own auto-click on gold forms to avoid skipping an answer.
