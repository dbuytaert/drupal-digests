# #3594795: Judge content review criteria without saving a node

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594795](https://git.drupalcode.org/project/ai_eval/-/work_items/3594795) · 1 contributor · 2 comments

## Summary

The AI Eval content review judge no longer saves and deletes a temporary unpublished node for every judged answer. The page is built in memory and reviewed without being saved, so automators, search indexing and other save hooks stop running per answer. That removes the extra LLM call per judged answer and the search index warning for the deleted node. Records made by the judge are visible only to users with "configure reviews" and are hidden from the AI Content Review review queue. A criterion that needs a saved entity cannot be judged this way.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `ai_eval_content_review` now depends on the `entity` module.
- **Database update:** `ai_eval_content_review_update_10001()` installs the `ai_eval_page` review record bundle with an `eval_key` field.
- **Permission change:** Records of type `ai_eval_page` and their suggestions require "configure reviews" to view, and are hidden from the AI Content Review review queue.
- **API change:** `CriterionRunner` constructor takes a new fourth argument, the `ai_eval_content_review.eval_pages` service (`EvalPageRegistry`).

## Technical details

AI Content Review's internal record type reloads the reviewed entity by id, so it cannot review an unsaved one. The submodule now ships its own `review_record` bundle plugin, `ai_eval_page`, with an `eval_key` bundle field. `CriterionRunner::review()` builds the node with `create()` and does not save it. It wraps the node and a random key in a new `EvalPage` value object, which is deliberately not an entity because the internal record type claims every entity. The `EvalPage` is registered in a request-scoped `EvalPageRegistry` (service `ai_eval_content_review.eval_pages`) and passed to the real `ReviewOrchestrator::runCriterion()`. The record type looks the page up by key. It gives the criterion the same review context lines as for a saved node, with the node as its `node` token context, and it applies no rules and refuses suggestions. In a `finally` block, `deleteReviews()` removes the records and their suggestions by `eval_key`, and the page is removed from the registry.

Access: AI Content Review alpha3 checks the reviewed subject only for records about a Drupal entity, so `ai_eval_page` records and their suggestions would be viewable with "view review records". `EvalPageAccess` forbids view, update and delete of them, and of their suggestions, without "configure reviews". Two pages in AI Content Review do not check entity access. A route subscriber adds `JudgedPageRecordAccessCheck` to the record detail route (`/ai-content-review/record/{record_id}/detail`), and a form alter on the review queue removes `ai_eval_page` rows for everyone and leaves them out of the waiting count.

Limit: the criterion gets an entity with no id. Tools that reload the node by id (for example `GetCurrentContentEntityValues`) and resumed runs cannot see it. The `extra_fields` setting still fills extra values on the unsaved node, but automators no longer fill them.

## Upgrade

Run database updates. `ai_eval_content_review_update_10001()` installs the `ai_eval_page` review record bundle on existing sites. The submodule now also depends on the `entity` module, which AI Content Review already requires. Code that constructs `CriterionRunner` directly must pass the new fourth argument, the `ai_eval_content_review.eval_pages` service:

```yaml
ai_eval_content_review.eval_pages:
  class: Drupal\ai_eval_content_review\EvalPageRegistry
```
