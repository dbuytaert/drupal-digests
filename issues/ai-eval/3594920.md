## Summary

LLM judge grading is more tolerant of real model output. Replies that mention a brace in prose before or after the JSON verdict now parse into a score instead of becoming a "could not parse judge response as JSON" error. Models that reject sending `temperature` and `top_p` together are retried with `temperature` only, instead of failing the question with a judge error. Unicode spaces and zero-width characters can no longer hide a closing prompt tag in an answer.

## Impact

No upgrade or configuration changes required.

## Technical details

In `LlmJudgeBase::parseJudgeResponse()`, the first-`{`-to-last-`}` slice is replaced by a single pass that pairs braces while skipping braces inside JSON strings and after escapes. Each paired span is run through `json_decode()`, and the last decoded object that has `score` wins. A fallback retries opening braces after an unmatched quote in prose, under a shared scan budget. The existing score and scale checks are unchanged. An array `reason` now becomes an empty string instead of "Array" with a warning.

`escapePromptValue()` now uses the `/u` flag with `[\s\p{Z}\p{Cf}]` in place of the `\xC2\xA0` byte alternative, so U+2000 style spaces and U+200B or U+FEFF no longer defeat the closing-tag escape. If `preg_replace()` returns NULL (invalid UTF-8), every `<` is escaped rather than returning the raw value.

For decoding pins, `refusesPinnedKnob()` now also accepts a message such as "temperature and top_p cannot both be specified" (new `refusesCombinedPins()`). The retry then sets `temperature` to 0, drops `top_p`, and records `['temperature']` as the pinned setting. The static `$pinRefused` map changed from a boolean per provider and model to a list of allowed knobs, so later grader instances in the same process pin `temperature` only. An empty list keeps the old no-pin behaviour, which is used when `temperature` itself is refused or the temperature-only retry is also refused. The same commit also changes `LlmJudgeBase` to implement `ValidationSettingsReportingInterface` through `validationSettingsFingerprint()`, which belongs to [#3594919](https://www.drupal.org/node/3594919) rather than this fix.
