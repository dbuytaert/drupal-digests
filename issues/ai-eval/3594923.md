## Summary

The AI Eval admin forms that offer a model picker (settings, test add and edit, guided test, judge prompt, calibration fit) now cache the provider model list for 10 minutes. Before, one slow or failing provider, such as one that retries after a 401, added 6 to 10 seconds to every load of each of these forms. The results page also stops loading the large per-question score data for up to 1,000 older results it only needed a few summary columns from, so it should stay fast as runs accumulate.

## Impact

Affects module maintainers.

- **New API:** New `ai_eval.provider_model_options` service (`Drupal\ai_eval\Service\ProviderModelOptions`) caching raw model lists per operation type.

## Technical details

The new `ProviderModelOptions::getOptions($operationType)` service wraps `AiProviderPluginManager::getSimpleProviderModelOptions()` and stores the raw result in `cache.default` under `ai_eval:provider_model_options:{operation}:{langcode}`, expiring after 600 seconds. Cache tags are `config:ai.settings`, `config:core.extension` and the config cache tags of every provider definition, so saving AI settings or provider config clears it. Partial lists from drupal/ai are cached as returned. A list containing only the empty `''` ("- None -") entry is not cached. The service is injected into `EvalSettingsForm`, `GuidedTestForm`, `EvalTargetForm`, `JudgePromptEditForm` and `CalibrationFitForm`; the per-form `(saved)` option and warnings are still built per form.

In `EvalResultsController`, the 1,000-row history query now selects only `target_id`, `timestamp`, `avg_score`, `passed_gate`, `question_count`, `error_count`, `scored_count` and `import_key` instead of `fields('r')`. The separate 200-row query was removed, and the newest timestamp is taken from the already loaded latest results (`$latestResults[0]`). The latest result per test and the pager rows still load every column.
