# #3594776: Annotate is shown to users who cannot annotate

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594776](https://git.drupalcode.org/project/ai_eval/-/work_items/3594776) · 1 contributor · 2 comments

## Summary

A user who could operate AI Eval but not annotate results used to see an Annotate button on every result row, and clicking it did nothing. The result page now leaves out the Annotation column for such users. The workflow's Annotate step now says it requires the Annotate AI Eval results permission, as the Validate judges step already did. Roles that should review traces need that permission granted.

## Impact

Affects site owners.

- **Permission change:** Seeing the Annotation column on a result now requires `annotate ai eval results` or `administer ai eval`; `operate ai eval` alone no longer shows it.

## Technical details

In `EvalResultsController::buildQuestionsTable()`, a `$canAnnotate` flag is computed by checking access on the `ai_eval.results.annotation_open` route with a placeholder question id. When it is false, the Annotation header and the per-row annotation cell are not added, and the column count is derived from the header. The column also hides annotation verdicts, because annotations are visible only to users who may annotate (`AnnotationAccessControlHandler`). The permission note for the workflow Annotate step is added in the workflow rendering code (`PermissionRequirement`). The fix landed in commit dcbcdf0, a combined "Sprint 7" commit that also carries other changes (for example [#3594775](https://www.drupal.org/node/3594775)), and it adds a functional test in `AnnotationUiTest`. The docs now state that annotating and seeing annotations require `annotate ai eval results` or `administer ai eval`. Before, they said annotating needed both `annotate ai eval results` and `administer ai eval`.
