## Summary

On the guided test form, the Examples step used to turn into a long stack of full editors as soon as someone added, updated or removed one example. Saved examples now show as one-line collapsed rows (id, the start of the input, and the expectation count) that open on click. A reload and an htmx update look the same, and an example with a validation error opens by itself. When editing an existing test with an entity dataset, its questions appear as compact read-only rows rather than disabled copies of the editor. Counts now read "1 expectation" or "N expectations".

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** Existing guided examples render as `details.ai-eval-guided-example` with a `summary` line, and edit-flow questions render as `#ai-eval-guided-existing-questions` rows instead of disabled fieldsets.
- **API change:** `GuidedExampleList::build()` loses its `$editExisting` parameter, and `GuidedExampleList::summary()` is now public static with the signature `summary(array $question)`, returning the compact text only.

## Technical details

`GuidedExampleList::build()` had two code paths. The page load rendered summaries and the htmx fragment rendered full editors. The `$editExisting` flag is removed, so both callers use one path. Each existing example is a `<details class="ai-eval-guided-example" data-guided-index="N">` holding the old editor, so `hx-include="closest .ai-eval-guided-example"` on the update and remove buttons still works. `open` is set when `$errors[$index]` is non-empty.

`summary()` is now a public static helper that returns the shared compact text. It uses `mb_strlen`/`mb_substr` for the 80 character cut and `PluralTranslatableMarkup` for the count. `GuidedTestForm` reuses it for the read-only existing-question rows inside a new `#ai-eval-guided-existing-questions` container. The disabled fieldset copies of the editor are gone.

A closed `details` still posts its inputs, so existing editors could leak their expectations into the no-JavaScript "Add example" submit. To prevent that, the editor sits in a `fieldset` that is rendered `disabled` and `hidden`. `scopeFields()` rewrites `name` and `hx-params` attributes to `examples[INDEX][field]`. The guided-test behavior in the JS file enables the fieldset only when `window.htmx` exists and the row is open. On `htmx:configRequest` and when building the request from the block, it strips the `examples[N]` prefix again via `canonicalName()`, so the shared endpoint receives the original field names. Fields in rows added by htmx are re-scoped on `htmx:afterSwap`. CSS for the rows is added to `css/admin.css`.

The same commit also ships [#3594928](https://www.drupal.org/node/3594928) (Cancel during a running step) and [#3594927](https://www.drupal.org/node/3594927) (imported results scaled to their maximum score), which are separate from this issue.

## Upgrade

If you call the list builder yourself, remove the fifth argument. The compact page-load rendering is now the default:

```php
// Before
GuidedExampleList::build($draftKey, $draft['examples'] ?? [], [], NULL, FALSE);
// After
GuidedExampleList::build($draftKey, $draft['examples'] ?? []);
```

Code that used the old private `summary($question, $draftKey, $index)` must use the new public `GuidedExampleList::summary($question)`, which returns only the compact text and no remove button.
