## Summary

Decision answers recorded while a new entity is being saved (for example by a Direct field automator running during presave) used to be stored with no entity link and no kept text, and were never deleted with the entity. They counted toward the caller's "Stop after" limit but could not be reviewed properly. They are now linked to the entity, with the kept text, once the entity is saved, and are deleted with it. Linking needs an AI version that reports the entity UUID. Without it, behavior is as before. Rows already recorded before this release stay unlinked. The same commit changes some wording and rubric forms. When the stored count is above the limit, Record decisions and Review decisions say "Recording stopped: 42 recorded, limit 3." instead of "42 of 3 recorded." A new rubric opens with **all_pass** selected in **Scoring: combine**. Saving a rubric without a combine rule says "Choose how the checks combine (Scoring: combine)." Rubric and failure taxonomy schema errors now show the field path instead of a raw `{properties}` placeholder ([#3594833](https://www.drupal.org/node/3594833)).

## Impact

Affects site owners.

- **Config change:** No config schema change. Rubrics now require a combine rule on save, and new rubrics default to `all_pass`.

## Technical details

The recorder (`DecisionRecorder`) reads the optional `entity_context` request metadata through `pendingUuid()`. It uses `method_exists()` on `getRequestMetadataValue`, so older AI releases keep recording as before. It accepts the context only when the entity type matches the request tags and the UUID is valid. For a pending entity it inserts the row without text and remembers the row ID, entity type, UUID and the text it would have kept in an in-request `$linkable` map. The map holds at most `LINKABLE_MAX_ROWS` (200) rows and drops the oldest. A new `Hook\RecordedEntityLink` implements `hook_entity_insert()` and calls `DecisionRecorder::linkInserted()`. That method matches content entities by type and UUID, then updates `entity_id` and the text columns where `entity_id` is still NULL. The update runs inside the entity's save transaction, so a rollback removes the row too. A failed link logs a warning and does not break the save. Rows with no entity tags are not tracked.

The "Stop after" wording is a branch on `$recorded > $limit` in `RecordSettingsForm` and `DecisionReviewForm`. On Record decisions the separate "Recording stopped." marker now shows only when the count equals the limit.

On the rubric side, `RubricEditor::fields()` takes a new `$isNew` argument. For a new rubric it defaults `combine` to `all_pass` and drops the "(none)" option. Existing rubrics with no combine rule still show "(none)". The rubric form checks `combine` against `RubricEditor::COMBINE` before schema validation. `RubricEditor::assemble()` now emits an empty `scoring` as a `stdClass`, so it encodes as `{}` and not `[]`. A new `SchemaErrorFormatter` is shared by `DatasetValidator`, `RubricValidator` and `FailureTaxonomyValidator`. It returns path-prefixed messages with resolved arguments.

## Upgrade

Existing answers recorded on new content before this release keep no entity link and are left unchanged. The CHANGELOG says to find them on Review decisions by the message "The [entity type] was not saved yet when the answer was recorded." No update hook is added.
