## Summary

Imported embeddings calls used to show "Output type ... EmbeddingsOutput not supported for string conversion." as if it were the model's answer. That text is written by the AI module's `ai_observability` submodule, not by ai_eval. Trace review now shows "Embeddings: no text output" on these cards, without the "streamed response not captured" warning. Promoting such a trace gives an empty AI response, so the diagnostic text stays out of datasets. The check runs when a trace is read, so older imports are fixed too and the stored `output` is unchanged. The same commit also shipped related trace review and promotion changes tracked in other issues ([#3594838](https://www.drupal.org/node/3594838), [#3594839](https://www.drupal.org/node/3594839), [#3594841](https://www.drupal.org/node/3594841), [#3594850](https://www.drupal.org/node/3594850)). These include promoting an agent run from its final answer, showing the first question on group cards, and replacing the promote controls with a confirmation after a successful promotion.

## Impact

Affects module maintainers.

- **New API:** Normalized trace arrays gain an optional `response_kind` key (documented in `TraceSourceInterface`), plus an optional `row_id` insertion id.

## Technical details

In `OtelTraceSource`, the span normalizer sets `response_text` to an empty string and sets `response_kind` to the operation type when `operation_type` is `embeddings`. It does the same for `text_to_image`, `text_to_speech`, `speech_to_text` and `speech_to_speech` spans, but only when the whole `output` matches the exact "Output type <class> not supported for string conversion." sentence (anchored regex). `chat` spans are never touched, so a chat reply that equals or quotes the sentence is kept. The raw output column is not rewritten.

`TraceReviewFragment` renders the card body as "Embeddings: no text output" for `response_kind` `embeddings`, or "No text output" for other kinds. It also skips the `streamed_uncaptured` notice when `response_kind` is set. `PromotionService::promotionIntegrityFlag()` (now `public static`) likewise skips the `streamed_uncaptured` refusal when `response_kind` is set. A non-chat call with output tokens and no text can therefore still be promoted by hand, with an empty `metadata.ai_response`. `docs/user/usage/traces.md` names the upstream cause.

The bundled changes in the same commit add a `@lock` service argument to `PromotionService`, so any code that constructs it directly must now pass a lock backend. Promotions are serialized per destination with it. The commit also adds an optional `question` key to group summaries from `OtelTraceSource::groups()`. Agent run promotion now uses the final answer, with the visitor's first user message as input.

## Upgrade

If you construct `PromotionService` yourself, for example in a test, pass the lock backend after the input normalizer:
