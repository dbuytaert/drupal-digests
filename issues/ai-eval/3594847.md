## Summary

In the AI Eval rubric editor, pressing Enter in a phrase field used to save the whole rubric. The save overwrote the rubric in place, because the version is a typed field and a save does not create a new one. Enter in a phrase field now adds a new phrase input below and moves focus to it, and Enter in other text inputs of the editor does nothing. Saving only happens from the Save button. Each check also has an "Add phrase" button, so a user can add several phrases in one editing session instead of one per save. Empty phrase inputs are ignored on save. The same commit also bundles other 1.1.x polish: accessible names on dataset question row buttons, gate threshold defaults that follow the selected metric, singular and plural wording, a no-chat-models notice, and entity labels in admin text.

## Technical details

The check row template in `RubricEditor.php` no longer renders the always-present trailing empty input. It renders an `.ai-eval-phrase-add` button instead, which does an `hx-get` to the new `ai_eval.rubric.phrase_row` route (`/admin/config/ai/ai-eval/rubrics/phrase-row/{index}`, GET, `administer ai eval`, `index` must be digits). The route's `RubricController::phraseRow()` returns a single `<input type="text" name="check_values[index][]">`. htmx appends it to the check's `.ai-eval-check-row__values`.

`js/repeater.js` adds a capture-phase `keydown` listener on `document.body`. It matches `.ai-eval-rubric-editor input[type="text"]` and calls `preventDefault()` on Enter, skipping IME composition. Capture phase is used so that key events which do not bubble, as some assistive and test tools send, are handled too. If the input is a phrase field and not blank, the handler clicks the check's Add phrase button. It focuses the new input after `htmx:afterSettle`, so htmx's own focus handling can't move focus back. A blank phrase does not add another blank one. The data model and schema are unchanged. The user docs describe the new behavior.
