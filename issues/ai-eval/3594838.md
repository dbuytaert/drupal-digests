## Summary

When a reviewer labels a whole agent run `fail` or `defer` and uses "Promote all", the dataset question now comes from the run's final answer. Before, it came from the run's first call, which was often an embeddings call for a search query, so the stored response was meaningless. The question's input is now the visitor's first message, not the whole agent history. The reviewer's group failure mode is also saved with the question. Questions promoted earlier are not changed. Along the way, trace review group cards show the visitor's first question. After a successful single-answer promotion, the form shows a confirmation with a link to the question. Promotions to the same dataset are now serialized, so concurrent promotions no longer race.

## Impact

Affects module maintainers and site owners.

- **Config change:** New optional `metadata.group_failure_mode` and `metadata.raw_input` keys in promoted question data. No schema or update hook.
- **API change:** The `PromotionService` constructor takes a new `LockBackendInterface $lock` argument, placed before `$resultEnvelope`. The `ai_eval.promotion` service definition passes `@lock`.
- **New API:** `PromotionService::promotionIntegrityFlag()` is now public static. `LabelStore::groupLabelsWithVerdicts()` returns a new `failure_mode` key per group, and `GroupedTraceSourceInterface::groups()` may return an optional `question` key.

## Technical details

`PromotionService::representativeTrace()` now treats an `agent_run` group differently from a conversation. It orders the run's calls by `created`, then by the new `row_id` (the stored insertion id that `OtelTraceSource` now exposes), and keeps tree order for sources without row ids. It picks the last `chat` call with non-empty `response_text` and empty `response_tools`. If none qualifies it takes the last chat call, then `$members[0]`. In `promoteTraceInto()`, an agent-run group replaces the picked call's `messages` with only the run's first user message (new `agentQuestion()`). It also stores that call's raw input as `metadata.raw_input`. This avoids the multi-turn tool history described in the issue's step 4. A cut or flagged first input marks the trace `truncated` and is refused, even if the final answer is intact. A run with no user message is counted as missing.

`LabelStore::groupLabelsWithVerdicts()` now returns `failure_mode`, and `mapTrace()` writes it as `metadata.group_failure_mode` only when non-empty. The call's own `verdict` and `note` are deliberately left as they were, so the reviewer's run label lives in `group_*`. This follows the issue's recommendation not to fall back to the group's values.

The commit also bundles work from sibling issues. The trace source marks embeddings and unstringifiable non-chat output with `response_kind` and stores empty text for them, so they are no longer treated as uncaptured streams ([#3594840](https://www.drupal.org/node/3594840)). Trace cards warn about tool turns ([#3594850](https://www.drupal.org/node/3594850)). Group cards show a 120-character `question` ([#3594839](https://www.drupal.org/node/3594839)). Each promotion check and insert now runs under a per-destination `lock`. A busy destination counts as `refused` in the bulk report. Duplicate outcomes now carry the existing `qid` and `question_entity_id`. The promote form is replaced by an "Added to [dataset]" state with an "Edit this question" link and an "Add to another dataset" reopen link ([#3594841](https://www.drupal.org/node/3594841)).

## Upgrade

Code that constructs `PromotionService` directly must pass the lock service before the optional envelope argument, as the updated kernel test does:

```php
$this->container->get('ai_eval.input_normalizer'),
$this->container->get('lock'),
```

Questions already promoted from agent run labels keep the old call. To get the final answer, delete them and promote again.
