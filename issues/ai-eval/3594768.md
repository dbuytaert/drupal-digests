# #3594768: Result page: each annotation action nests the question table one card deeper with Gin

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594768](https://git.drupalcode.org/project/ai_eval/-/work_items/3594768) · 1 contributor · 2 comments

## Summary

With Gin as the admin theme, each Annotate, Save annotation, Add to dataset or Reset action on an AI Eval result page used to wrap the question table in another card. After a few actions the table was several borders deep, the Input column wrapped one word per line and the annotation panel was cut off. The result page now swaps a container owned by the module, so the table stays at the same depth. Claro was not affected.

## Impact

No upgrade or configuration changes required.

## Technical details

The htmx target `#ai-eval-question-results` (`AnnotationFragment::REGION_ID`, swapped with `outerHTML`) was on the table itself. Gin's table template adds `gin-layer-wrapper` and `gin-table-scroll-wrapper` around every table, so each response left the old wrappers in place and put the newly themed table, with fresh wrappers, inside them. The id now sits on a module-owned container around the table, and every open, close, save, reset and promote action swaps the whole container. The server still renders zero or one open annotation row, as before. I read this from the issue body and the `REGION_ID` docblock in `src/Render/AnnotationFragment.php`. I could not see the fixing commit diff (none was linked, and the issue was migrated to GitLab work items), so it is probably in commit 8c8f8cd, "Sprint 7 data integrity: Gin table nesting, ...".
