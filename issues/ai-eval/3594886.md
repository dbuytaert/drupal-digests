## Summary

With "Do not count a pass that rests on a judge that is not trusted" turned on, a passing run used to be recorded as failed whenever any grader was an untrusted LLM judge, even if the other graders (for example rubric checks) passed the gate on their own. Now the gate is recalculated without the untrusted judges' scores. The pass stands if the recalculated gate still passes and at least half of the original questions remain measured. Otherwise it is refused as before. The result names the untrusted judges either way.

## Impact

Affects site owners.

- **Config change:** Behavior of the `refuse_unvalidated_judges` setting changed: a passing gate is recalculated without untrusted judges' scores instead of being refused outright. Setting label and key are unchanged.

## Technical details

`EvalRunner::applyJudgeTrustPolicy()` now takes the per-question scores, the question pass threshold, the gate metric and the must-pass grader IDs. For each question it rebuilds `GradeResult` objects, drops the scores of untrusted judges, and calls `Scorer::scoreQuestion()` again, then `Scorer::scoreTarget()` for the target. Original skipped questions and invocation errors are carried over unchanged. Grader errors from untrusted judges are kept, because the scorer treats any grader error as an unmeasured question. A question left with no remaining score stays in the coverage denominator, so skipped, errored and now-unscored questions all count against the half-measured requirement.

If the recalculated gate fails, behavior is as before: `passed_gate` is set to FALSE and `trust_refused` records the judges. If it passes, the original score is kept and the judges are recorded under a new `trust_note` key. Both keys are copied into `config_snapshot` through `array_intersect_key()` in the run, regrade and finalize paths, and the `EvalRunnerInterface` return shape documents `trust_note`. Stored scores are not altered; the recalculation only decides the verdict. The settings form description and docs (settings, running, judges pages) were updated to describe this.

The same commit also ships two unrelated fixes: file and config dataset questions with a `caller_uid` now error unless the run starter has `run ai eval as another user` ([#3594929](https://www.drupal.org/node/3594929)), and dimension judge validation in `HumanLabelSource` uses whole-answer annotations only when that judge alone attempted the answer, with matching trace reviews taking precedence ([#3594931](https://www.drupal.org/node/3594931)).
