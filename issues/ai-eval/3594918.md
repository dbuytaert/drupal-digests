## Summary

A rubric check set that missed its own threshold used to give the grader a passing score. For example, `weighted_avg` with threshold 0.9 and a score of 0.80 gave 4.0 out of 5, which passed the default question threshold of 3.5 and also passed a must-pass `rubric_checks` gate. Now a failed rubric scores 0, so the question fails and must-pass gates fail. Regex errors now report the real PCRE message. Empty phrases and patterns fail their check instead of silently matching. A negative weight fails a `weighted_avg` rubric. The grader reason now includes each failed check's message, not only its id. Results of existing runs can change on re-grade for rubrics that sat below their threshold.

## Impact

Affects site owners.

- **Config change:** Stored rubrics with empty phrases/patterns, or negative `scoring.weights` under `weighted_avg`, now fail at run time even though the schema allows them.

## Technical details

`RubricChecksGrader::grade()` now returns `0.0` when `$verdict['pass']` is false, instead of `score * 5.0`. Option (a) from the issue was chosen because the grader does not know the question threshold. A rubric threshold of 0 still passes everything. `RubricCheckEvaluator` compares `$score >= $threshold - TOLERANCE` (1e-9, matching `GateMetric`) so floating-point rounding does not fail a rubric that is exactly on its threshold. For `weighted_avg`, any negative weight in `scoring.weights` sets the score to 0, forces `pass` to false and adds `negative weight for check <id>` to the reason. The other combine modes ignore weights. A weight of 0 still turns a check off. The failed-check part of the reason is now `<id or kind>: <check reason>`.

`StringCheckExecutor::execute()` first rejects any empty entry in `values` (or `patterns` for `regex`) with `Empty phrase in check <id>`. When the check has no id it uses the position, which `RubricCheckEvaluator` passes through as `check_position` in the context. For `regex`, every pattern is now compiled and run before the any/all short-circuit rules apply, so a later bad pattern can no longer be hidden by an earlier match. Compile failures report `invalid regex pattern: <pattern> (<PCRE warning>)`, caught with a temporary error handler. Run-time failures report `regex runtime error: <pattern> (<preg_last_error_msg()>)`, for example backtrack limit or malformed UTF-8.
