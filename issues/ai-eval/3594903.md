## Summary

Importing an EEE envelope that has no pass-rate metric no longer writes the quality score's confidence interval into the pass-rate interval columns. For example, a quality score of 4 with an interval of 3.8 to 4.2 used to be stored as `pass_rate_ci_low = 3.8` and `pass_rate_ci_high = 4.2`. Now those columns stay empty unless the envelope reports a pass rate. Rows imported before the fix are not corrected by this change.

## Impact

No upgrade or configuration changes required.

## Technical details

In `EnvelopeImporter::mapRow()`, the interval's `score_details` used to come from `$passRateItem ?? $primary`. It now comes only from `$passRateItem['score_details'] ?? []`. With no pass-rate result item there is no `uncertainty` data, so the CI low and high values stay null. The existing `pass_rate_source` provenance marker still separates "not reported" from a measured zero. No `schema/*.schema.json` change. A new kernel test in `EnvelopeImporterTest` imports a 0 to 5 quality metric with an interval of 3.8 to 4.2 and asserts `pass_rate` is 0.0 and both CI columns are null.
