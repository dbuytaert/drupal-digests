## Summary

Trace review and promotion in ai_eval 1.1.x now read traces more faithfully. Text before the first role line is kept as a user message instead of being lost, Windows line endings and `developer` messages work, and a role word inside a list no longer produces empty messages. Promoted questions keep the raw input text in their metadata. The structured JSON that ai_observability writes by default is now read as messages, tool calls and reply text. Spans that ai_observability cut or summarized are marked and cannot be promoted. Traces with tool calls in their input also cannot be promoted yet, because replay cannot send those turns. Trace import no longer drops every document after a stray closing brace. The import page and `drush ai-eval:import-traces` now report how many parts were skipped and when the rest of a file was not read. The commit bundles the fixes for [#3594820](https://www.drupal.org/node/3594820), [#3594819](https://www.drupal.org/node/3594819) and [#3594834](https://www.drupal.org/node/3594834).

## Impact

Affects module maintainers and site owners.

- **Config change:** Promoted questions gain `metadata.raw_input` and, for tool-only replies, `metadata.ai_response_tools`.
- **New API:** New `Drupal\ai_eval\Service\TracePayloadParser` with `parsePlain()`, `parseInput()`, `parseOutput()` and `hasCutSignature()`; new `TraceImporter::splitDocumentsWithReport()`.

## Technical details

The old `OtelTraceSource::parseMessages()` is replaced by `TracePayloadParser`, which has no container dependency. `parsePlain()` normalizes line endings and maps `developer` to `system`. It treats a role line directly after another role marker as content, because the producer writes an empty turn as a blank line. Leading text becomes a user message. The format has no escaping, so a bare `user` or `tool` line after a text line can still split a message. This is documented, and the raw input is stored to compensate. `parseInput()` and `parseOutput()` detect structured payloads (`{"messages":[` and `{"normalized":{"role":`). They recover only complete leading messages from a capped payload and never fabricate missing text. They report flags (`input_cap`, `output_cap`, `omitted`, `shortened`), including the ai_observability middle `[...]` marker at any length limit of at least 32 characters. Non-chat output is passed through unchanged.

`OtlpSpanMapper` now sets `truncated` for any of these signals. `PromotionService` gains `STATUS_TOOL_TURNS`. It refuses structured input with `tool` roles, tool calls or call ids, and no longer calls a tool-only reply `streamed_uncaptured`. `promotionIntegrityFlag()` is unchanged for plain input. The question metadata gets `raw_input` (capped at 8000 characters) and, for tool-only replies, `ai_response_tools` as a JSON string. `TraceReviewFragment` renders tool calls, results matched to call names, and warning notices.

On the import side, `TraceImporter::splitDocumentsWithReport()` replaces the brace-depth scanner. It skips stray text, stray closing braces and closed non-documents, and counts each one. It never restarts inside a candidate, so nested payload objects are not imported as documents. An unclosed object or an unterminated string (a raw line break ends a string) stops the read and sets an unread-tail count. `ImportResult` carries `skippedDocuments` and `unreadTails`. `TraceImportBatch` and `EvalImportTracesCommand` show them as warnings. Drush still exits 0 when at least one document was read.

## Upgrade

Traces imported before this change keep their stored `truncated` value. The new payload flags are also computed when a trace is read, so older rows with cut or summarized structured payloads are now shown with notices and refused for promotion. Re-import is only needed for traces whose files had damaged parts that were previously dropped.
