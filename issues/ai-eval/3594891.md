## Summary

Decision calibrations are now tied to the model version the provider reports with each answer (for TypeSafe, `jev-1.14.0`), not the alias that was requested (`jev-latest`). Before, the judge and the field automator callers disagreed about what the model was, so a curve fitted on the Answer file tab with `jev-latest` never applied to automators. Now, when a provider moves an alias to a new version, the newest active curve for the same judge or automator and question keeps applying and is shown as carried over, until an active fit on the new version replaces it. Curves fitted for an alias before this release stop applying to the judge and need a new fit; automator curves fitted before this release are not carried over either.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_eval_decision_calibration_update_10002()` adds a `requested_model` column to `ai_eval_decision_record`.
- **Config change:** `ai_eval.calibration.*` gains a `requested_model` string key.
- **New API:** `CalibrationApplierInterface::applyForAlias()`, `CalibrationStoreInterface::carried()`, `EvalCalibration::getRequestedModel()`, and an optional `$requestedModel` argument on `CalibrationStoreInterface::save()`.

## Technical details

`EvalCalibration` gets a `requested_model` property (also in the `ai_eval.calibration.*` schema) holding the model id the caller asked for. `ai_eval_decision_record` gets a matching column, filled by `DecisionRecorder` from the event's model id, and `RecordedDecisionSource::groups()` passes the latest recorded value to `RecordedFitForm`, which stores it on the new fit. Update `ai_eval_decision_calibration_update_10002()` adds the column with an empty default, so rows recorded earlier have no requested model and their curves cannot carry over.

Lookup is now exact match first (`CalibrationStore::fresh()` on provider, reported model and fingerprint), then a new `carried()` method that returns the newest active curve for another model, filtered by a caller-supplied predicate. For automators, `CalibrationSubscriber` requires the curve's `requested_model` to be non-empty and equal to the event's model id, and the curve's `scope` to share a tag with the request, so switching the automator to another model stops the correction. A carried correction is marked with `carried_from` in the `ai_eval_calibration` metadata of the answer. For the judge, the new `CalibrationApplier::applyForAlias()` does the same with a predicate on the curve's `requested_model` or `model_id` equal to the judge's configured model.

The judge's served model is read from State (`DecisionRubricGrader::SERVED_MODEL_STATE`, a provider/requested/served mapping) via `CalibrationJudgeUse::servedModel()`, falling back to the configured model before the first grade. `CalibrationJudgeUse::of()` gains a `CARRIED` result and optional `$state` and `$store` arguments. The calibrations list, the calibration page and the Answer file and review fit forms use it for messages and for the default model, and add `DecisionRubricGrader::SERVED_MODEL_CACHE_TAG` to the cache metadata. `RecordedDecisionSource::check()` counts answers from another version when `calibration_id` is the curve, and the Callers tab reports how many. The shown diff does not include the `DecisionRubricGrader` changes themselves.

## Upgrade

Run database updates so `ai_eval_decision_calibration_update_10002()` adds `requested_model` to `ai_eval_decision_record`. Then refit curves that were fitted for an alias such as `jev-latest` (they no longer apply to the judge), and refit automator curves fitted before this release, since they have no recorded requested model and are not carried over. On the Answer file tab, enter the model as the provider reports it, for example `typesafeai__jev-1.14.0`.

Code that implements `CalibrationApplierInterface` or `CalibrationStoreInterface` must add `applyForAlias()` and `carried()` respectively; `CalibrationApplier` now takes `@ai_eval.decision_calibrator` as a second constructor argument.
