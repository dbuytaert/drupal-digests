## Summary

The AI Eval results screens now show names instead of machine ids. The overview (Recent Runs, Target Health, pending optimizations), the result detail Run Summary and the compare warning show the test label, with the id in a `title` tooltip. The Judge trust badges show short judge names such as "Accuracy". The detail Gate cell shows "Pass rate" or "Average score" instead of `pass_rate`. The same 1.1.x commit also shipped several related results and calibration changes. The detail page and overview show the gate the run actually recorded, or "Gate not recorded" instead of an invented 4.0. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred". Annotate progress counts against the latest run's answers. Gate type wording now says that hard and soft only change the exit code of `drush ai-eval:run`. Calibration screens warn when saving replaced an inactive fit, or when the judge no longer asks the question a fit was made on. The compare page uses plain labels for differences and moves raw values into a closed "Technical details" section.

## Impact

Affects front-end developers.

- **Theme change:** Results pages now render target names in a `span` or link with a `title` attribute holding the id, and the compare page has a new `.ai-eval-readable-differences` list plus a closed Technical details section.

## Technical details

On the overview, `EvalResultsController` now loads the page's pending, latest and paged results first, then calls `loadMultiple()` once on `ai_eval_target` for all target ids. It uses those entities for the labels and adds `ai_eval_target_list` plus each target's cache tags to `#cache`. The detail page adds the same tags next to its existing `max-age` 0. When a target has been deleted, the id is shown as the text with no `title`. Judge badges pass `graderShortLabel($id)` as the text while the validation link keeps the real id. The compare page's different-test warning loads both targets and builds `<span title="id">label</span>` markup. `ResultsCompareController` gets an optional `$graderManager` constructor argument (`ai_eval.grader_manager`). It uses that argument to turn grader ids into plugin labels, and a `differenceLabel()` map to give difference keys plain names. Hashes show as "same", "changed" or "recorded", and raw values stay in the closed details element.

The new private `recordedGate()` resolves the gate from the result's validated `config_json` snapshot (`metric` and `threshold`). If the snapshot has no usable gate, it falls back to the live target's threshold. If neither exists it returns NULL, which gives "Gate not recorded" and drops the threshold from the Target Health score cell. The detail Gate cell prints `GateMetric::label()`. `FailureRateService` now groups by `verdict` as well as `failure_mode`. `decorate()` merges tagged verdicts back into one row per mode and splits only the rows without a mode by verdict, so the shares still sum to 100%. `WorkflowStateService` now reads `question_count` from the latest result and counts canonical annotations on it for Annotate progress. The suggested total of 100 is removed. A new `GateTypeWording` class supplies the gate type options and description for `EvalTargetForm` and `GuidedTestForm`. `CalibrationSaveTrait` counts inactive curves for the same provider, model and fingerprint before saving and reports when one was replaced. `CalibrationFromReviewsForm` compares the group fingerprint with `currentFingerprint()` to warn about stale rubric wording. Docs and `CHANGELOG` are updated. The issue text proposes an `EntityLabels::target()` helper. The portion of the diff I could read does not add one, and the controllers call `$target->label()` directly.
