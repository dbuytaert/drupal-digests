## Summary

On a result page, after a reviewer presses "Add to dataset" the promote controls are replaced by "Added to [dataset name]", with an "Edit this question" link when the user may edit questions. An "Add to another dataset" link brings the form back. Errors and refusals leave the form active so the reviewer can fix the input and retry. A repeat promotion of the same answer points to the existing question and does not save edits typed into the old form. The same commit also changes trace review. Agent runs are now promoted from their final answer, with the visitor's first message as the input. Trace group cards show the visitor's first question. Imported embeddings show "Embeddings: no text output". Tool-turn and truncated traces get a "cannot be promoted" warning. Promotions into the same destination are now serialized, which prevents duplicates when two requests arrive together.

## Impact

Affects module maintainers.

- **API change:** `PromotionService` constructor takes a new `LockBackendInterface $lock` argument (after `InputNormalizer`, before `ResultEnvelopeBuilderInterface`); `PromotionService::promotionIntegrityFlag()` is now `public static`; `AnnotationFragment::form()` gains an optional `$promoteDone` argument.
- **New API:** Optional `row_id` and `response_kind` keys on normalized trace arrays; optional `question` key on group summaries from `GroupedTraceSourceInterface::groups()`.

## Technical details

The done state is rendered on the server. `EvalResultsController::promoteAnnotation()` builds a `$done` array (dataset label, edit URL, reopen URL) for `STATUS_PROMOTED`, `STATUS_DUPLICATE` and `STATUS_SOURCE_PRESENT`. It passes the array through `questionsTableFragment()`, `buildQuestionsTable()` and `annotationFormBuild()` to `AnnotationFragment::form()`. The promote `<form>` also gets `hx-disabled-elt="find button[type='submit']"` as a double-click guard. "Add to another dataset" is an `hx-get` to the `ai_eval.results.annotation_open` route.

`existingProvenance()` now also returns each question's `qid` and `question_entity_id`, so a `STATUS_DUPLICATE` outcome carries them and the done state can link to the question. `promoteAnnotationOutcome()` and `promoteTraceInto()` run the duplicate check, id allocation and write under a `lock` service lock. The lock name is derived from the destination (`acquirePromotionLock()`), and a new dataset is re-resolved by label after waiting (`resolveLockedTarget()`). If the lock cannot be acquired within the wait, an `InvalidArgumentException` is thrown. Bulk "Promote all" catches it and counts the trace as refused. Annotation promotion sets `another_result` when the same question was promoted from a different result, and `PromoteFragment::outcome()` adds a hint that this result has its own copy. A copy previously promoted from an annotation is no longer treated as the source question when deciding `STATUS_SOURCE_PRESENT`.

Agent-run promotion changed in the same commit. The representative trace is now the last chat call by `created`, then `row_id`, that has non-empty text and no response tool calls. It falls back to the last chat call, then the first member. `agentQuestion()` replaces the input with the run's first user message and keeps that call's `raw_input`. A run with no user message gives `STATUS_MISSING`, and a cut first input is refused. The group label's failure mode is saved as `group_failure_mode` in metadata. `OtelTraceSource` adds `response_kind` (embeddings, or a recognized non-chat "not supported for string conversion" diagnostic) and `row_id`. Its `groups()` adds a `question`, the first user message truncated to 120 characters.
