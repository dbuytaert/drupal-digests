# #3594808: Let a test mark a grader as must pass, so its failure fails the question

- **Project:** Drupal AI
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3594808](https://git.drupalcode.org/project/ai_eval/-/work_items/3594808) · 1 contributor · 3 comments

## Summary

A test in AI Eval can now mark individual graders as must pass. If a must-pass grader scores a question below the question pass threshold, that question fails, however well the other graders scored. Previously a failing safety check could be outweighed in the average (scores of 5, 5, 5 and 0 average 3.75 and pass). A must-pass failure also fails the whole quality gate, whether the gate metric is average score or pass rate. A must-pass grader that does not apply to a question (no score) does not fail it. The option is a "Must pass" checkbox per selected grader on the test edit form and in the guided test. The results page, the review step and the Drush run output name the must-pass grader that failed each question. Runs with different must-pass lists are not treated as directly comparable.

## Impact

Affects module maintainers and site owners.

- **Config change:** New `must_pass` sequence of grader plugin IDs on the `ai_eval.target.*` config entity (added to the schema and to `EvalTarget` `config_export`), empty by default.
- **API change:** `ScorerInterface::scoreQuestion()` gains a fifth optional parameter `array $mustPass = []`; custom implementations of the interface must add it.
- **New API:** New `Scorer::mustPassFailures()` static helper, `EvalTarget::getMustPass()`, and a `must_pass_failures` key in `scoreTarget()` and runner results.

## Technical details

`Scorer::scoreQuestion()` converts each grader score to the 0 to 5 composite scale as before. A must-pass grader whose composite score (rounded to two decimals) is below the question pass threshold is added to a `must_pass_failed` list on the question score, and `passed` becomes false. A null score adds no failure. A grader error still marks the question errored and takes it out of the gate. `Scorer::scoreTarget()` calls the new static `Scorer::mustPassFailures()`, which skips unscored questions but keeps measured failures on questions that errored for another grader. Any such failure forces `passed_gate` to false for both `avg_score` and `pass_rate` metrics. This settles the open question in the issue about the run gate. The threshold used is the shared question pass threshold. The issue's alternative of a separate threshold per grader was not implemented.

`must_pass` is stored on the `EvalTarget` entity. `getMustPass()` returns only ids that are also in `graders`. It is written to the run snapshot as `must_pass` in `EvalRunner`. When a run is resumed or replayed, `applySnapshotToConfig()` uses the snapshot value. A snapshot without the key, or a resumed run without a snapshot, is treated as an empty list, so older runs score as before. `RunComparability` compares the sorted lists, and a difference is reported under `must_pass`. `ResultEnvelopeBuilder` adds `must_pass` as a comma-separated string in `metric_config.additional_details`, next to `graders`. The form element is built by the new `MustPassChoice` class, shared by `EvalTargetForm` and `GuidedTestForm`. Its checkboxes only show for selected graders, and submitted values for unselected graders are dropped.

## Upgrade

Code that implements `ScorerInterface` must accept the new optional parameter:

```php
public function scoreQuestion(string $questionId, string $input, array $gradeResults, float $questionPassThreshold = 3.5, array $mustPass = []): array;
```

Existing tests need no config change. `must_pass` defaults to an empty list, so scoring is unchanged until a grader is marked.
