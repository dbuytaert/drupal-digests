# #3594782: --as-user and caller_uid do not switch the Drupal account

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594782](https://git.drupalcode.org/project/ai_eval/-/work_items/3594782) · 1 contributor · 2 comments

## Summary

`drush ai-eval:run --as-user=<uid>` and a question's `caller_uid` now really run the agent or chat call as that Drupal user. Before, the uid only went to an optional `ai_eval.caller_context` service that AI Eval does not ship, so on most sites the agent ran as the current account, which is anonymous under drush. With AI Metering that meant eval runs spent the anonymous visitors' shared monthly token budget, and could exhaust it. `0` means anonymous on purpose, and a uid with no account fails that question with "caller uid N has no account" instead of silently running as someone else. Judges and graders are not switched.

## Impact

No upgrade or configuration changes required.

## Technical details

In `EvalRunner::runQuestion()` the caller uid (`caller_uid`, or the run's `--as-user` default) is turned into an account by a new private `callerAccount()`: uid `0` gives `AnonymousUserSession`, otherwise the user entity is loaded via `entity_type.manager`. If none loads, the question returns a failed result with `error` set to `caller uid %d has no account` without invoking anything. Otherwise `account_switcher->switchTo()` is called just before the chat or agent invocation, and `switchBack()` runs in a nested `finally`, after `callerContext?->clear()`, so the original account is restored even if the caller context throws. The caller context service is still told the uid as before. `EvalRunner` gets two new optional trailing constructor arguments, `?AccountSwitcherInterface` and `?EntityTypeManagerInterface`, wired in `ai_eval.services.yml` as `@account_switcher` and `@entity_type.manager`. When no switcher is injected, no switching happens. The `--as-user` option help and the `running.md` warning were rewritten, and a kernel test `CallerAccountSwitchTest` was added.

## Upgrade

Agent tests run from drush without `--as-user` or `caller_uid` still run as anonymous. The updated docs recommend running them as a dedicated eval user, for example `drush ai-eval:run --target=<agent test> --as-user=<uid>`. Check that any existing `caller_uid` values point to real users, since a missing account now fails the question. Subclasses or custom service definitions that construct `EvalRunner` directly need no change, as the new constructor arguments are optional.
