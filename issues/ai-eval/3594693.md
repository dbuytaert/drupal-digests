# #3594693: Surface model and token telemetry on eval result detail

## Summary

The AI Eval result detail page now shows which models produced a run and how many tokens it used. The run summary has new rows for Target Model, Judge Models, Tokens and Shortened for Judges. Shortened for Judges counts responses cut before the judges read them. Each expanded question lists its model, its tokens, and a note when its response was shortened for the judges. A count the run did not record reads "Not recorded", never 0. Older results without this data, and imported results ("Not reported (imported)"), still display normally. Agent targets and AI Answers targets now record the model calls and tokens behind each answer, including answers that failed. The issue also asked for retry and rate-limit counts and an export link. I found no display for either in the commit.

## Impact

Affects module maintainers.

- **New API:** New `ModelCallRecorder` event subscriber and `TelemetryText` render helper; both are new classes with no documented extension point.

## Technical details

The Target Model, Judge Models, Tokens and Shortened for Judges cells are built in `EvalResultsController` from the stored run snapshot and the stored question rows. They never read the graders installed now. Judge Models reads the snapshot's `judge_models`. It falls back to the older single `judge_model` and `judge_provider` keys, shows "No LLM judge" when the list is empty, and shows "Not recorded" otherwise. Shortened for Judges reads `truncated_question_count`, `question_count` and `judge_response_char_limit`. Each question's "Model and tokens" section comes from `questionTelemetry()`, which uses `model_id`, `model_id_resolved`, `token_usage` and `identity.judge_truncated`.

`TelemetryText` keeps an unknown count apart from zero. A stored count is a whole number of at least 0, otherwise NULL, and the run total is not summed when counts are missing.

A new `ModelCallRecorder` event subscriber captures chat provider calls during one agent answer. It listens to `PreGenerateResponseEvent`, `PostGenerateResponseEvent` and `AiExceptionEvent`. `EvalRunner` arms it before the agent runs and disarms it before grading, so judge calls are not counted. A nested question pauses the outer recording with `suspend()` and `resume()`. Agent rows then get `token_usage`, `model_id` and `model_id_resolved` through `applyAgentTelemetry()`. `token_usage` appears only when every call reports usage. The model ids appear only when every call agrees. `token_usage` also gains an optional `cached` count, which AI Answers workflow rows get too. `WorkflowPanel` no longer shows a missing token count as 0.
