# #3594766: Promote all creates a dataset when nothing qualifies, ignores conversation labels, allows duplicate names

- **Project:** Drupal AI
- **Type:** Major bug report
- **Status:** Fixed
- **Discussion:** [#3594766](https://git.drupalcode.org/project/ai_eval/-/work_items/3594766) · 1 contributor · 2 comments

## Summary

In the AI Eval module's Trace review, "Promote all" into a new dataset now behaves sensibly. It no longer leaves an empty dataset behind when nothing qualifies, and the message says so instead of reporting "Promoted 0 traces". A conversation or agent run labeled Fail or Defer now counts, and the report splits trace labels from conversation or run labels. A new dataset name that another dataset already uses is refused, on Promote all, on a trace card and on a result annotation. The refusal comes with a refreshed dataset list and an emptied name field, so you can pick the existing dataset.

## Impact

Affects module maintainers.

- **API change:** `PromotionService` promote methods accept a dataset ref or a `PromotionTarget` and their outcome adds `dataset_ref`; `PromoteFragment::bulkConfirmation()` replaced by `bulkReport()`; `bulkControl()` takes an optional message.
- **New API:** `PromotionService::promoteByVerdictReport()`, `PromotionService::datasetWithLabel()`, `PromotionTarget`, `LabelStore::groupLabelsWithVerdicts()`, `AnnotationFragment::datasetSelect()` and `::newDatasetInput()` added.

## Technical details

The fix landed in the AI Eval commit "Sprint 7 data integrity" (8c8f8cd) as part of a larger change. I read the CHANGELOG and docs for it, not the full code diff. `PromotionService` promote methods now take a dataset ref string or a `PromotionTarget`. For a new dataset, `append()` creates the dataset and its first question in one database transaction, so selection happens first and no empty dataset is written on the SQL entity storage. `promoteByVerdictReport()` returns `{qualifying, created, from_traces, from_groups, duplicate, refused, missing, unresolved, dataset_ref}`. `promoteByVerdict()` stays as a qid-only wrapper around it.

Conversation and agent run labels are read through the new `LabelStore::groupLabelsWithVerdicts()`. It loads all `scope = 'group'` rows and keeps the earliest row per group key. Each qualifying group is represented by one trace: the last turn of a conversation, or the root of an agent run. Group labels whose group has no trace left are counted as `unresolved`. `PromoteFragment::bulkReport()` renders the outcome as sentences, replacing `bulkConfirmation()`.

Duplicate names are checked by `PromotionService::datasetWithLabel()`, which compares trimmed, lowercased labels. `PromoteController::promote()`, `PromoteController::bulk()` and `EvalResultsController::promoteAnnotation()` call it only for a new dataset target and return a visible refusal without writing. The annotation path also swaps a fresh dataset select and an empty name input out of band, using `AnnotationFragment::datasetSelect()` and `::newDatasetInput()`.

## Upgrade

Code calling `PromoteFragment::bulkConfirmation()` must switch to `PromoteFragment::bulkReport(array $report, string $datasetLabel, bool $newDataset)`. Callers of the `PromotionService` promote methods can now pass a `PromotionTarget` as well as a dataset ref. The outcome array now includes `dataset_ref`.
