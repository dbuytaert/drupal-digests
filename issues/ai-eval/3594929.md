## Summary

The restricted permission `run ai eval as another user` is now also enforced for questions that come from YAML file datasets, not just stored question entities. If the account that started a run lacks the permission, a file-dataset question that sets `caller_uid` records an error instead of switching accounts. Drush runs and older runs with no recorded starter keep working as before. The same commit also changes how `refuse_unvalidated_judges` works: a passing gate is now recalculated without the untrusted judges' scores, and judge validation for dimension judges uses whole-answer annotations only when that judge alone graded the answer ([#3594886](https://www.drupal.org/node/3594886), [#3594931](https://www.drupal.org/node/3594931)).

## Impact

Affects site owners.

- **Security:** Closes a gap where a YAML dataset could run a question as another account, such as user 1, without the new permission. Needs server file write access, so low severity.
- **Permission change:** Runs from non-entity (file or config) datasets that set `caller_uid` now require the run starter to have `run ai eval as another user`; otherwise that question records an error.

## Technical details

The check lives in `EvalRunner::runQuestionBody()`, just before the switch to the caller account, because `EvalQuestion::preSave()` only covers entity questions and the runner reloads the dataset at every step, so a file can change mid-run. `runQuestion()` and `runQuestionBody()` take a new `?int $startedBy`, passed from `ai_eval_run.started_by`. When it is non-NULL, the question's `dataset_source` is not `entity`, and the starter lacks `run ai eval as another user`, the runner returns `questionError()` with an explanatory message. A NULL starter (Drush, legacy rows) skips the check, matching the [#3594906](https://www.drupal.org/node/3594906) policy. A missing dataset source defaults to `file`, so it is checked.

The same commit bundles two other fixes. For [#3594886](https://www.drupal.org/node/3594886), `applyJudgeTrustPolicy()` now rescored the target without untrusted judges' scores using `Scorer::scoreQuestion()` and `scoreTarget()`. Skipped and errored questions stay in the coverage denominator. The pass stands only if the recalculated gate passes and at least half of the original questions remain measured. A dependent pass is recorded as `trust_refused`. An independent pass keeps the judges in a new `trust_note` in the config snapshot. For [#3594931](https://www.drupal.org/node/3594931), `HumanLabelSource` uses whole-answer annotations for a dimension judge only when it was the sole attempted grader (`attempted_graders`), and matching trace reviews take precedence. `JudgeValidateController` follows suit. Docs and the settings form description were updated.

## Upgrade

If you rely on YAML datasets (from `dataset_path` or module `datasets/` folders) that set `caller_uid`, grant `run ai eval as another user` to the roles that start those runs, or remove `caller_uid` from the dataset.
