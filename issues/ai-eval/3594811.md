# #3594811: Record the model calls and tokens behind each agent-mode answer

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3594811](https://git.drupalcode.org/project/ai_eval/-/work_items/3594811) · 1 contributor · 3 comments

## Summary

AI Eval results for agent-mode tests now record which model answered and how many tokens it used, as chat-mode tests already did. Before this, an agent row showed "not recorded", so its cost could not be compared with a chat or workflow test on the same questions. Judge calls are not counted, and a failed answer still gets the figures.

## Impact

Affects module maintainers.

- **New API:** `EvalRunner` takes an optional `ModelCallRecorder` in its constructor; agent-mode result rows now carry `token_usage`, `model_id` and `model_id_resolved`.

## Technical details

While an agent answers one question, a new shared `ModelCallRecorder` event subscriber (service `ai_eval.model_call_recorder`) is armed in `EvalRunner::runQuestionBody()` and records each chat provider call as a `ModelCall`. It is armed only for `mode === 'agent'`. It is disarmed in the `finally` block before the graders run, so judge calls never count. The recorder is shared with the AI Answers recording from [#3594802](https://www.drupal.org/node/3594802).

A nested run, meaning an eval question that runs inside another agent's answer, does not record. `runQuestion()` now wraps `runQuestionBody()` and calls `suspend()` and `resume()` on the recorder around the whole question, grading included. `arm()` throws a `LogicException` when already armed, and the runner catches it.

The new `applyAgentTelemetry()` follows the chat-mode meaning of the keys. `token_usage` (input, output, and optional `cached`) is written only when the totals are known. `ModelCallRecorder::total()` returns nothing when any call reports no usage. `model_id` and `model_id_resolved` are written only when every call agrees (`ModelCallRecorder::shared()`). It is applied on both the success path and the failed-answer path. Retries made by the rate limit handler are included in the recorded calls. `cached_tokens` was also added to `lastGeneration`, so chat and workflow rows now carry an optional `token_usage.cached`. `docs/user/usage/scoring.md` and `CHANGELOG.md` are updated.

The `EvalRunner` constructor gets an optional trailing `?ModelCallRecorder $modelCallRecorder` argument, wired in `ai_eval.services.yml`. The result row keys are the existing chat-mode keys, so there is no schema change.
