## Summary

Decision calibration no longer skips recording an answer just because a short state value (such as `no`, `1` or `a`) appears inside a longer word of the question, for example `no` inside "notice". Previously the answer was dropped and the log claimed the wording contained state text, which left calibration with fewer answers than expected. Short values are now matched only as whole words, while values of four or more characters are still matched anywhere in the text, so the protection against storing state values is not weakened.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `DecisionRecorder::containsAny()` in `ai_eval_decision_calibration`, which is now `public static` (it was `private static`) so it can be unit tested. For each state value it builds a `preg_quote()` pattern and runs it case-insensitively (`/iu`). Values shorter than 4 characters get a `(?<![\p{L}\p{N}_])` lookbehind and a `(?![\p{L}\p{N}_])` lookahead, each added only when the value's first or last character is a letter, digit or `_`. So `$5` still matches in "costs $5 today" but not in "costs $50", and `C#` still matches in "C#support".

Scripts without word separators keep substring matching: a short value containing Han, Hiragana, Katakana, Thai, Lao, Khmer, Myanmar or Tibetan characters is never wrapped in boundaries, and a text that contains any of those characters is checked with `mb_stripos()` instead of the regex. Values that are not valid UTF-8 fall back to plain `str_contains()` on bytes, as does a text where `preg_match()` returns `FALSE`. Long values are now compared case-insensitively too, which they were not before. Tests added: `RecordedDecisionTest::testStateValueBoundaries()` (kernel), `DecisionRecorderStateValueTest` and `DecisionRecorderStateTextTest::testInvalidUtf8StateValue()` (unit).

The commit also bundles fixes for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926), which are covered separately.
