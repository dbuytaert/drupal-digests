## Summary

Trace review cards now warn up front when a trace has tool calls in its input and cannot be promoted, so reviewers no longer find out only after opening the promote form. The commit also bundles several related trace review and promotion changes. Group cards show the visitor's first question. Promoting a labeled agent run now uses the run's final answer, paired with the visitor's first user message. After a successful promotion the promote controls are replaced by an "Added to [dataset]" confirmation. Embedding outputs show "Embeddings: no text output".

## Impact

Affects module maintainers.

- **API change:** `PromotionService::promotionIntegrityFlag()` is now `public static`. The `PromotionService` constructor takes a new `LockBackendInterface $lock` argument.
- **New API:** `PromoteFragment::toolTurnsNotice()`. Optional trace keys `response_kind` and `row_id`, and an optional `question` key in group summaries.

## Technical details

The card and the promote form share one rule. `PromotionService::promotionIntegrityFlag()` is now `public static`, and `TraceReviewFragment` calls it and shows the notice when it returns `STATUS_TOOL_TURNS`. A cut trace returns the cut flag first, so only the cut notice appears. The sentence itself comes from the new `PromoteFragment::toolTurnsNotice()`, which the "Not promoted: ..." outcome message also uses. The notice is followed by "This trace cannot be promoted." The truncated-trace card line now ends with that sentence too.

Agent run promotion changes. The representative trace is the last chat call ordered by `created`, then the new `row_id` (the stored insertion id, added to the trace array by `OtelTraceSource`), with non-empty text and no response tool calls. Failing that, it falls back to the last chat call, then the first member. The promoted input is only the first user message (`agentQuestion()`). `metadata.raw_input` keeps the raw input of the call that supplied that message. A run with no user message counts as missing. A cut first input is refused even if the final answer is intact. `LabelStore::groupLabelsWithVerdicts()` now also returns `failure_mode`, which is stored as `group_failure_mode` in the question metadata.

Promotions are serialized per destination with the `lock` service (`acquirePromotionLock()`), which covers the duplicate check, id allocation and write. In a bulk run a busy destination counts as refused and the run continues. Duplicate outcomes now carry `qid` and `question_entity_id`. `PromoteFragment::form()` takes a `$promoteDone` array and renders the confirmation, an edit link and "Add to another dataset" in place of the form, and the submit button is disabled while the request is in flight. Annotation promotion no longer treats an earlier promoted copy as the source question, and adds a hint when the same question was promoted from another result.

On the import side, `OtelTraceSource` sets `response_kind` for `embeddings`. For text_to_image, text_to_speech, speech_to_text and speech_to_speech it sets it only when the output is exactly ai_observability's "Output type ... not supported for string conversion." diagnostic. Those traces get empty text, are not flagged `streamed_uncaptured`, and the card shows "No text output". `groups()` adds an optional `question`, the first user message of the earliest chat call, truncated to 120 characters. The docs and `CHANGELOG.md` were updated to match.
