# #3594765: Envelope import does not recognize a result that was first run on this site

- **Project:** Drupal AI
- **Type:** Major bug report
- **Status:** Fixed
- **Discussion:** [#3594765](https://git.drupalcode.org/project/ai_eval/-/work_items/3594765) · 1 contributor · 2 comments

## Summary

Importing an envelope that this site exported from one of its own runs no longer stores the run a second time. Previously, exporting a local run with `drush ai-eval:export-envelope` and importing the file again created a duplicate result under a new `ai_eval/<dataset>` target with status Imported, and the results list counted the run twice. Now the import reports "already on this site (run #N)" when the measurement is unchanged. If the same run carries a different measurement, it is reported as a conflict and nothing is written. The original run is not modified.

## Impact

Affects module maintainers.

- **API change:** `EnvelopeImporter::__construct()` takes an optional fifth argument, `?ResultEnvelopeBuilderInterface $resultEnvelope` (default NULL). Without it, a site's own exports import as new rows as before.

## Technical details

The old duplicate check looked up existing rows by `import_key`. Rows from local runs have a NULL `import_key`, so they never matched. The fix does not set `import_key` on native rows, because a non-NULL value marks a row as imported with no gate applied, and the duplicate path also compares a fingerprint.

`EnvelopeImporter` gets a private `nativeRun()` step that applies only to envelopes whose `source_metadata.source_name` is `ai_eval`. It parses the `evaluation_id` (target, model, timestamp, row id) and loads the `ai_eval_result` row with that id, target and timestamp and a NULL `import_key`. It then rebuilds that row's envelope through `ResultEnvelopeBuilderInterface::buildFromResultRow()` and requires the rebuilt `evaluation_id` to match. The `measurement()` and `sameMeasurement()` helpers compare the `avg_score` and `pass_rate` items: scale, sample size, score, confidence interval bounds and `passed_gate`. Numbers are compared within 1e-6. `corrected_pass_rate` is deliberately excluded, since its presence and value depend on judge validation at export time. A metric that appears more than once makes the measurement ambiguous, which never counts as equal.

Limits noted in the code and changelog: the `evaluation_id` names no site, so a run from another site with the same test id, start second and row id would read as local. A run without a run snapshot rebuilds its identity from the test's current configuration. If that test was later deleted or its model changed, the export no longer matches and imports as a new result, as before. No update hook is needed because matching uses the computed identity.

## Upgrade

Only relevant if you instantiate `EnvelopeImporter` yourself. Pass the result envelope builder as the optional fifth constructor argument to get round-trip detection. The core service definition in `ai_eval.services.yml` was updated in the same commit.
