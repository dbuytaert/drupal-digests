## Summary

The bootstrap range for the corrected pass rate no longer collapses to a single value when every answer passes or every answer fails. A run of 5 of 5 passes now shows a real range instead of 100% to 100%, so a small run is no longer presented as certain. Separately, a run in which no question received a score (no errors, but no grader gave a score) no longer counts as gate evidence on the target dashboard, the workflow page or the run history. The run history shows "Not scored" for such a run instead of "Errored". Run database updates after upgrading.

## Impact

Affects site owners.

- **Database update:** Update 10053 adds a nullable `scored_count` column to `ai_eval_result` and backfills it from `scores_json`; imported or unreadable rows stay NULL.
- **Config change:** `CorrectedPassRateInterface::BOOTSTRAP_METHOD` is now `parametric_beta_posterior`, so the method name in exported envelopes changes; `schema/*.schema.json` is unchanged.

## Technical details

In `CorrectedPassRate::runBootstrap()` the observed rate was drawn as a binomial around `passed / total`, which is degenerate at 0 and 1. It is now drawn with `BetaBinomialSampler::beta($passed + 1.0, $total - $passed + 1.0)`, the same way the TPR and TNR draws are made. This changes the method for every rate, so `CorrectedPassRateInterface::BOOTSTRAP_METHOD` is now `parametric_beta_posterior` and its docblock describes the new draw. `ResultEnvelopeBuilder` emits that name. The interval can still be absent under the existing degenerate-draw policy.

Gate evidence uses a new nullable `ai_eval_result.scored_count`, written from `Scorer::targetMetrics($questionScores)['valid_count']` (no error, not unscored) in `EvalRunner`, `EvalRunCommand` and `ResultRegrader`. `EnvelopeImporter` writes NULL, since imported envelopes have no per-question scores. `GateEvidence::measured()` returns `scored_count > 0` when the column is set and falls back to `question_count - error_count > 0` when it is NULL. The same rule is applied in SQL in `TargetDashboardController` and `WorkflowStateService` (`r.scored_count > 0 OR (r.scored_count IS NULL AND r.question_count > r.error_count)`). `scored_count` is added to the fields selected for the run history, and `RunHistory` shows "Not scored" for a not-measured run with no errors. `ai_eval_update_10053()` is a batched update that adds the column and backfills it from `scores_json`, skipping imported rows and rows whose JSON is unreadable or whose count does not match `question_count`. The commit also carries fixes for other issues in the [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926) range, which are not covered here.

## Upgrade
