## Summary

A "%" in a judge's prompt template (for example "score 100% of the facts") no longer stops the whole run. The Edit prompt tab now refuses a template that does not have exactly four `%s` placeholders, and tells you to write `%%` for a literal percent sign. A template saved earlier that no longer fits now makes each answer it scores an error with a clear reason, not a failed run. A template that leaves out the answer placeholder also scores nothing and reports an error, where before the judge was asked without the answer. The same commit also bundles several related judge trust changes ([#3594812](https://www.drupal.org/node/3594812), [#3594813](https://www.drupal.org/node/3594813), [#3594814](https://www.drupal.org/node/3594814), [#3594816](https://www.drupal.org/node/3594816), [#3594817](https://www.drupal.org/node/3594817)), which are listed in the changelog.

## Technical details

`LlmJudgeBase::grade()` used to call `sprintf($template, ...)` outside its `try`, so an `ArgumentCountError` from a stray `%` escaped and ended the browser or Drush run. The call now sits inside the `try`, preceded by a new public static `LlmJudgeBase::templateCheck()`. It formats the template with four marker strings and returns `throws` (formatting failed) and `missing` (slot numbers whose marker is absent from the output). If it throws, or slot 4 (the answer) is missing, `grade()` returns an errored result with a `judge error:` message and does not call the model. Missing slots 1 to 3 are not blocked at run time.

`JudgePromptEditForm::validateForm()` uses the same `templateCheck()`. It rejects a template that throws, and one that leaves out any of the four placeholders, naming the omitted slots. The field description now mentions `%%`, and the save message tells the user to validate the judge again. `LlmJudgeBase` also gains `hasResolvedPrompt()`, which reports whether the latest attempt resolved a prompt and version, including errored attempts. `escapePromptValue()` became public static and now escapes closing `question`, `criteria` and `agent_response` fence tags in any letter case, with spaces or attributes.

The commit is large (85 files) and bundles other work. The partial diff I could read shows judge trust gating: a minimum of 10 distinct pass and 10 fail labels, a new `not_enough_labels` state, not-scored answers blocking trust, and a threshold-matched corrected pass rate. The prompt-version staleness behaviour, `ScoreScale::passes()` rounding and the two-decimal threshold validation in the settings, target and guided-test forms also appear in the diff. I did not read the omitted files, including `JudgeTrustReason`, `ValidationCompare` and the store implementation.

## Upgrade

Review any saved judge prompt overrides. A literal percent sign must be written as `%%`, and the template needs exactly four `%s` placeholders (dimension, question, expectations, answer). Re-saving an override on the judge's Edit prompt tab runs the new check. Also run `drush updatedb`, because the commit adds `ai_eval_update_10050`.
