## Summary

A judge is now Trusted only if it was scored on at least 10 distinct pass labels and 10 distinct fail labels, in addition to TPR and TNR of at least 0.90. Before, one pass and one fail label could both agree and earn the Trusted badge. A validation below the floor now shows a new **Not enough labels** state (with the counts) on the Judges page, the target list, result pages and in Drush. A repeated score of the same answer counts once. Existing validations below the floor read Not enough labels after the update. The `drush ai-eval:validate-judge` command exits with code 3 when the fixture is under the floor, so a CI gate built on it can start failing until you add labels. The floor is fixed at 10 per class. The `gold_target_n` setting is documented as a labeling target, not the minimum. Docs note that a 70/30 split of a small set rarely reaches the minimum.

## Impact

Affects module maintainers and site owners.

## Technical details

The rule lives in `JudgeValidationReport::trustBlocker()`, which returns the first blocker in precedence order: not-scored answers, fewer than `MIN_LABELS_PER_CLASS` labels in either class, then the existing rate check against `TRUST_THRESHOLD`. `isTrusted()` is now `trustBlocker() === NULL`, and the new `trustState()` maps a few-labels blocker to `not_enough_labels`. The chosen rule is a fixed floor of 10 per class, not the `gold_target_n` floor or the bootstrap confidence interval option the issue proposed.

Label counts come from new `pass_items` and `fail_items` columns (distinct scored items, so repeats count once). Older rows have NULL there, and `passLabels()` and `failLabels()` fall back to `tp + fn` and `fp + tn`, which include repeats. The update hook adds the columns as nullable and does not recompute. The new state is wired through `JudgeTrustBadge`, `JudgeTrustMark`, `EvalTargetListBuilder` (counted among the not-trusted states and ranked in `TRUST_SEVERITY`), the Judges table legend and CSS class `ai-eval-trust--not_enough_labels`. The Drush command prints a specific warning with the pass and fail counts.

The same commit also ships sibling changes from the issues listed in the CHANGELOG: not-scored answers blocking trust ([#3594816](https://www.drupal.org/node/3594816)), a corrected pass rate that requires validation at the run's threshold ([#3594814](https://www.drupal.org/node/3594814)), stale trust after a prompt edit ([#3594812](https://www.drupal.org/node/3594812)), fence-tag escaping ([#3594817](https://www.drupal.org/node/3594817)) and prompt template `%` handling ([#3594815](https://www.drupal.org/node/3594815)). Pass thresholds now accept at most two decimals. The diff was partly truncated, so those parts are described from the CHANGELOG and the visible hunks.
