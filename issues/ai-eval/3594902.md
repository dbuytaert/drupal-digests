## Summary

The AI Eval optimizer no longer ignores questions that failed with a measured score of 0.0. Before, a run where every failure scored 0.0 ended with "No failures to optimize". Failures are now selected the same way everywhere: the question did not pass, has no `error`, and is not `unscored`. Questions that errored or could not be scored are excluded.

## Impact

No upgrade or configuration changes required.

## Technical details

`EvalOptimizeCommand::formatFailures()` skipped questions with `avg_score === 0.0`, meant to drop errored questions. It now skips a question only if it passed, has an `error`, or is flagged `unscored`. The stored failure details no longer filter on `avg_score > 0` and use the same rule. The `--dry-run` failure count previously counted every non-passed question, errored ones included. It now uses the same rule.

The same commit also carries fixes for [#3594903](https://www.drupal.org/node/3594903), [#3594904](https://www.drupal.org/node/3594904) and [#3594905](https://www.drupal.org/node/3594905): the run snapshot records `default_caller_uid` (from `--as-user`), and `RunComparability` treats a difference as side by side only (a missing value reads as no default caller). `ResultRegrader` carries `default_caller_uid` over to a re-grade. `EnvelopeImporter` now reports a conflict when the same `evaluation_id` arrives with a different target, and no longer reads the pass rate interval from a non pass rate item. Docs and tests were updated.
