## Summary

The Import traces page no longer offers the server path option to users who only have **Operate AI Eval**. Previously those users could type any server path. They could learn which paths exist and import JSON from any readable directory. Now only users with **Administer AI Eval** see that option. Operators can still upload a file. The same change narrows module uninstall. It now deletes only the result and envelope files AI Eval wrote, not every `.json` file under the configured results path (tracked as [#3594827](https://www.drupal.org/node/3594827)). The Drush import command is unchanged and has no permission check.

## Impact

Affects site owners.

- **Security:** Users with only `operate ai eval` could probe server paths and import JSON from any readable directory through the trace import form. The server path option now requires `administer ai eval`, enforced in form build and validation.
- **Permission change:** Importing from a server path on the Import traces page now requires `administer ai eval`. File upload still accepts `operate ai eval` or `administer ai eval`.

## Technical details

`TraceImportForm` gets a `canUseServerPath()` check on `administer ai eval`. Without it, the `source` radios and `server_path` field are not built. `source` becomes a `value` element fixed to `upload`, and the upload field's `#states` visibility dependency is dropped so the field is always visible. `validateForm()` also rejects a forged post. If the user lacks the permission and either the form value or the raw user input has `source` set to `path`, it sets the same fixed error on `source`, "You do not have permission to import from a server path. Upload a file instead." This runs before any path is checked, so existing, missing and unreadable paths all get the same message and nothing leaks.

`ai_eval_uninstall()` in `ai_eval.install` now scans non-recursively. At the top level of `results_path` it matches `/^results-\d{8}-\d{6}\.json$/`. In `results_path/envelopes` it matches `/\.eee\.json$/`. It skips non-files and catches `FileException` per file, so one failed delete does not block uninstall. It then tries `rmdir()` on the `envelopes` folder, which succeeds only if the folder is empty. The results path, other files, subfolders, the default temp folder and `--output-dir` exports are left alone. New tests cover the operator-only form, a forged POST, the validation guard and the uninstall patterns. The docs (`traces.md` and the uninstall notes), the CHANGELOG and the `results_path` field description are updated. The docs also note that Drush reads any path the shell user can read.

## Upgrade

Nothing to run. Operators who relied on the server path option need an administrator to run the import, or they can use `drush ai-eval:import-traces`. If you want old results files removed on uninstall that don't match `results-YYYYMMDD-HHMMSS.json` or `envelopes/*.eee.json`, delete them manually.
