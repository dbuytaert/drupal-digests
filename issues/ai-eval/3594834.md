## Summary

Trace import in ai_eval now handles the structured JSON that ai_observability writes by default. Before, a structured span showed up in trace review as one user message full of raw JSON, and tool calls were lost. Messages now appear as separate messages, tool calls show on the review card, and the reply is the reply text. Spans that ai_observability cut or summarized are flagged and cannot be promoted, and neither can traces with tool calls or tool results in their input, because replay cannot send those yet. The importer also no longer drops every document after a stray closing brace in a trace file. It reports how many parts were skipped, and warns when the rest of a file was not read because of an unclosed brace. The warnings appear on the import page and in `drush ai-eval:import-traces`. Plain role-line input is read more reliably too: text before the first role line is kept, Windows line endings work, and `developer` is shown as `system`.

## Impact

Affects module maintainers.

- **New API:** New `Drupal\ai_eval\Service\TracePayloadParser` with `parseInput()`, `parseOutput()`, `parsePlain()` and `hasCutSignature()`, and `TraceImporter::splitDocumentsWithReport()`.

## Technical details

The new `TracePayloadParser` replaces `OtelTraceSource::parseMessages()`. `parseInput()` treats input starting with `{"messages":[` as structured. It keeps each message's role and text, each assistant message's tool calls (id, name, arguments as a string) and each tool message's `tool_id`. Anything else goes through `parsePlain()`. `parseOutput()` uses `normalized.text` and `normalized.tools` when the output is a chat `normalized` object. Other outputs, such as embeddings, are returned unchanged.

Cut detection does not depend on the 1024 default. `hasCutSignature()` looks for the `[...]` marker at the midpoint position where ai_observability's truncation puts it, for strings of at least 32 characters. When a payload is cut, only complete leading message objects from the retained head are recovered. Flags (`input_cap`, `output_cap`, `omitted`, `shortened`) land in `payload_flags` on the normalized trace, set `truncated`, and drive the review card notices. `OtlpSpanMapper` also uses these checks when setting the stored `truncated` column. Normalized traces gain `raw_input`, `input_format`, `response_tools`, `response_incomplete` and `payload_flags`.

`PromotionService` has a new `STATUS_TOOL_TURNS` (`tool_turns`) refusal. It applies to structured input containing tool role messages, tool calls or call ids. Promoted questions now store `metadata.raw_input` (up to 8000 characters) and, for tool-only replies, `metadata.ai_response_tools` as a JSON string. Both are strings so questions stay editable. The `streamed_uncaptured` check no longer fires when the reply has tool calls or was cut.

On the document side, `TraceImporter::splitDocumentsWithReport()` scans depth-zero objects with a string-aware matcher. Stray text, stray `}` and closed non-OTLP objects are skipped and logged with a byte offset. An unclosed object or string stops the read, since later objects could be nested payload data. `ImportResult` gains `skippedDocuments` and `unreadTails`. `splitDocuments()` still exists and delegates to the new method.

## Upgrade

Spans already imported keep their stored `truncated` value, so re-import them to get the new cut and summarized flags. Parsing of messages and replies happens when a trace is read. Observed tool calls do not fill **Expected tools** during promotion.
