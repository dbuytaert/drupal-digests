## Summary

A judge validated on one prompt used to keep showing Trusted after you edited its template or guidance, and a gate with `refuse_unvalidated_judges` still accepted it. Now the judge shows Validation out of date, with a reason naming the validated and current prompt versions. This applies on the Judges page, result pages and the test list. A judge validated on the default prompt also goes out of date once any override is saved. Judges validated from a CLI fixture measure no prompt, so they go out of date as soon as the judge has an override. Validate again in the browser to clear it. The same release commit also adds other judge-trust rules (minimum labels, unscored answers, threshold matching for the corrected pass rate).

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_eval_update_10050` adds nullable `not_scored`, `pass_items`, `fail_items` and `endpoint_only` columns to `ai_eval_judge_validation`. The commit bundles several related judge-trust changes.
- **Config change:** Pass thresholds in the settings, target and guided test forms now accept at most two decimals (step 0.01).
- **New API:** `JudgeValidationStoreInterface` gains `validatedVersionMatches()` and `activePromptVersion()` (plus other methods from the same commit); custom implementations and mocks must add them.

## Technical details

`JudgeValidationStore::trustStateForRow()` now returns `STATE_STALE` for an otherwise trusted row when `validatedVersionMatches()` is FALSE, in the same place as the existing model-mismatch check. `validatedVersionMatches()` compares the row's `config_version` (NULL means the default template) with `activePromptVersion()`, which reads `JudgeConfigStore::activeOverride()`. The store service now receives `@ai_eval.judge_config_store`. If no config store is injected, the match is unknown (NULL) and the state is unchanged. Saving only the model or domain tags does not bump the prompt version, so only the existing model rule applies there.

The reason text comes from the new `JudgeTrustReason::forRow()`. The Judges page shows the version column as `v1 (now v2)`. `drush ai-eval:validate-judge` prints a note when the judge has an override, because a fixture validation records no `config_version`. Trust is evaluated when a page opens, so results stored earlier also lose their Trusted mark and corrected rate after a prompt edit. The docs (`judges.md`) and CHANGELOG were updated.

The commit is a combined release commit: it also introduces the `not_enough_labels` state (fewer than 10 distinct pass or fail labels), `not_scored` handling, threshold-matched corrected pass rates, and fence-tag and `%` template fixes, tracked in separate issues ([#3594813](https://www.drupal.org/node/3594813), [#3594814](https://www.drupal.org/node/3594814), [#3594815](https://www.drupal.org/node/3594815), [#3594816](https://www.drupal.org/node/3594816), [#3594817](https://www.drupal.org/node/3594817)).

## Upgrade

Run database updates (`ai_eval_update_10050`). After editing a judge's template or guidance, validate the judge again in the browser. CLI fixture validations record no prompt version, so they also read Validation out of date once an override exists. Custom implementations or mocks of `JudgeValidationStoreInterface` must add `validatedVersionMatches(object $row): ?bool` and `activePromptVersion(string $graderId): ?int`.
