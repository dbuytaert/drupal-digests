## Summary

A question can attach an image by `private://` URI. Before this fix, AI Eval would read any private image file on the site, including files kept there by other modules. It showed the file on the result detail page and sent it to the AI provider. Errors also differed for "unreadable", "too large" and "not an image", which let an admin discover which private files exist. Saving a question could also take over another module's managed file and make it permanent. Now private images are only accepted from `private://ai_eval/question-files`, where the question editor stores uploads. All refusals give one error message. A run whose questions point to a private file outside that folder stops at start with an error naming the question id. `public://` handling is unchanged. This fix shipped in one commit together with fixes for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926).

## Impact

Affects site owners.

- **Security:** Question images could read any `private://` file that passed as an image (up to 5 MB) and could make other modules' files permanent. Reads and ownership are now limited to `private://ai_eval/question-files` and `public://ai_eval/question-files`.

## Technical details

`QuestionImageResolver` gets a public `isQuestionFile()`. It requires the URI to start with `<scheme>://ai_eval/question-files/`, then resolves both the file and the directory through the stream wrapper and `realpath()`. The resolved file must sit under the resolved directory. This catches `..` traversal and symlinks, and a path that does not resolve (`realpath()` returns `FALSE`) is refused. In `resolve()`, a `private://` URI that fails the check throws, and the `InvalidArgumentException` handler replaces any message for a `private://` URI with the single `QuestionImageResolver::PRIVATE_ERROR`. The 5-image limit now returns a `skip_reason` instead of throwing.

`EvalRunner::validatePrivateImages()` runs in both the run-start path (`doStartRun`) and the earlier question-loading path. It resolves every `private://` entry in each question's `files` and throws `RunDatasetException` with `Question <id>: <PRIVATE_ERROR>` before any run rows are created or AI calls are made. A deleted image inside the upload folder also stops the run, so the message does not reveal whether a file exists.

`QuestionImageUpload::updateUsage()` now adds `ai_eval` file usage and sets the file permanent only when `isQuestionFile()` passes for the managed file's URI. Removing ai_eval's own usage still works for any file.

## Upgrade

Questions that reference a `private://` file outside `private://ai_eval/question-files` (for example `private://pixel.png`) now fail at run start. Move the image into the question editor's upload folder, or re-upload it through the editor:

```
private://ai_eval/question-files/pixel.png
```
