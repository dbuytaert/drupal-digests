## Summary

In ai_eval 1.1.x, traces imported from AI Observability in the legacy text format could show an agent's tool step as a reply of just "assistant:". These steps were wrongly treated as final answers. They appeared on the gold labeling screen and counted toward coverage, agreement and judge validation. They are now excluded. Promoting such a step is refused, and so is promoting an embeddings call, which has no text answer to test. The trace card explains why. "Promote all" now picks the real final answer of an agent run. On the compare page, a difference that reads the same on both sides, such as a changed dataset hash, now shows once ("Dataset content: changed") instead of "A: changed; B: changed". Labels already saved on tool steps stay but are no longer counted.

## Impact

Affects module maintainers.

- **New API:** `TraceBrowser::isRoleLabelOnly()`, `PromotionService::STATUS_TOOL_STEP` and `PromotionService::STATUS_NO_ANSWER` outcome statuses.

## Technical details

`TraceBrowser::isFinalAnswer()` now also requires that the reply is not role-label-only. The new `TraceBrowser::isRoleLabelOnly()` trims `response_text` and strips a leading `assistant:` (case-insensitive). If nothing is left, the reply is a tool step. `GoldSetAgreement` and `HumanLabelSource` inherit the fix through `isFinalAnswer()`.

`PromotionService::promotionIntegrityFlag()` returns two new flags. `no_answer` (`STATUS_NO_ANSWER`) applies when `response_kind` is set, as for embeddings. `tool_step` (`STATUS_TOOL_STEP`) applies when the reply is role-label-only and there are no `response_tools`. Both count as refused in the promotion report. For agent runs, the "Promote all" selection of the last chat now calls `TraceBrowser::isFinalAnswer()` instead of its own text and tools check. As a result, a trailing "assistant:" step is skipped and an earlier real answer is chosen.

`PromoteFragment` gains `toolStepNotice()` and `noAnswerNotice()`. `TraceReviewFragment` renders them as a `refusal_notice` warning with "This trace cannot be promoted." In `ResultsCompareController`, the two readable values are compared as strings. When they match, a single value is shown, otherwise the "A: @a; B: @b" form is kept. The user guide and changelog are updated. Existing tests that expected embeddings to promote with an empty answer now expect a refusal.

## Upgrade

No update steps are needed. Embeddings calls can no longer be promoted, so any workflow that relied on promoting them with an empty AI response will now see them refused.
