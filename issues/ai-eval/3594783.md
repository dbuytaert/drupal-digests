# #3594783: The run drops the agent's own error when it does not answer

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594783](https://git.drupalcode.org/project/ai_eval/-/work_items/3594783) · 1 contributor · 2 comments

## Summary

When an agent gives no answer during an AI Eval run, the run now keeps the reason. Previously each question showed only "invocation failed" and the log said "returned solvability 0". Now the agent's own error, such as an AI Metering "Monthly AI token quota exceeded" message, is included in the warning log and stored with the question result. The results detail page shows it under an "Error:" section.

## Impact

No upgrade or configuration changes required.

## Technical details

In `EvalRunner`, a new per-question property `lastInvocationError` is reset at the start of each question. When `invokeAgent()` gets no answer, it reads `getLastError()` from the agent wrapper if the method is callable (it can be empty) and appends it to the "not solvable" and "solved but returned empty" warnings. The same property is also filled from the catch blocks in `invokeAgent()` and the chat invocation, and for the missing-agent-id and agent-not-found cases. Text goes through the new `capErrorDetail()`, which collapses whitespace and cuts to 300 characters, because provider errors can echo parts of the request.

For a failed question, the result row gets an `error_detail` key next to `error`. `error` keeps its fixed value, so existing readers are unaffected, and `error_detail` is only present when something supplied a reason. `EvalResultsController` renders an "Error:" section in the question details, with `error_detail` appended after a colon. Tests in `ToolCallCaptureTest` cover both an agent-reported error and a thrown exception reaching the row, and `ResultsDetailReadabilityTest` covers the display.
