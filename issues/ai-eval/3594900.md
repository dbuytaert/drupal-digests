## Summary

The AI Eval quality gate now compares the unrounded pass rate or average score with the threshold. Before, values were rounded to two decimals first, so 199 of 200 questions passing counted as 1.00 and cleared a 100% gate, and 159 of 200 (79.5%) cleared an 80% gate. Such runs now fail. The stored and displayed figures are still rounded to two decimals. Earlier runs that passed only because of rounding may have been marked as passing wrongly.

## Impact

No upgrade or configuration changes required.

## Technical details

`Scorer::scoreTarget()` now gets its figures from a new public static `Scorer::targetMetrics()`. It returns `valid_count`, `passed_count`, `avg_score` and `pass_rate`, all unrounded, and skips errored and unscored questions as before. The gate goes through `GateMetric::passesGate()` with those values, and `round(..., 2)` is applied only to the returned `avg_score` and `pass_rate`.

Unrounded averages bring float error, so `GateMetric::passesGate()` now compares with a `TOLERANCE` of `1e-9`. The code comment gives the example that three scores of 3.8 average to 3.7999999999999998 and must still meet a 3.8 gate. A new test covers this: 200 questions scoring 3.8 pass a 3.8 gate.

The repeated-run path in `EvalOptimizeCommand::runRepeatedEval()` had the same problem, because it averaged the already-rounded per-run `pass_rate`. It now calls `Scorer::targetMetrics()` on each result's `question_scores`, averages the unrounded values, and calls `GateMetric::passesGate()`. The private `passesAggregatedGate()` is removed. The docs were updated to describe the new behavior.
