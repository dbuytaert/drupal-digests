## Summary

A browser run whose dataset loses questions mid-run now stops with an error such as "The dataset changed during the run. Questions at the start: 10. Questions now: 8." It no longer polls at the same progress until someone presses Cancel. This commit also ships three related fixes. A run no longer starts on a dataset with no runnable questions: the Run button and `drush ai-eval:run` say why, store no result, and the command exits with 1. Deleting a dataset now deletes its questions, and the confirmation page lists the questions and the tests that use it. `drush ai-eval:optimize` compares a candidate with the baseline only on questions both were scored on, and skips runs scored on fewer than half their questions. `drush ai-eval:export-envelope` skips imported results and reports how many.

## Impact

Affects module maintainers and site owners.

- **Config change:** Dataset delete form replaced by `EvalDatasetDeleteForm`; deleting a dataset now deletes its questions.
- **New API:** New `Drupal\ai_eval\Service\RunDatasetException`, thrown by `EvalRunner::runTarget()` and `startRun()` when the dataset has no runnable questions.

## Technical details

A new `RunDatasetException` (in `src/Service/`) carries messages written for the user, with factories `empty()`, `emptySplit()`, `questionNotFound()` and `changed()`. In `EvalRunner`, the step method now throws `changed($total, count($questions))` when the reloaded dataset has fewer questions than the stored `total`, replacing the old "dataset shrank" early return. Growth and reordering still only record `identity_drift`. `markRunError()` stores the exception's own message without the class prefix for this exception type. `runTarget()` and `doStartRun()` throw instead of returning an empty scored result. `RunController` catches the exception and renders the new `RunFragment::notStarted()` with a Retry button. `EvalRunCommand` catches it per target, prints the reason, continues with the other targets, and returns failure at the end if any target did not run. With `--question`, a missing ID or an empty split now counts as such an error.

Dataset deletion: `EvalDataset::postDelete()` deletes the questions in chunks of 50, and the explicit question cleanup in `DatasetCloner` and `GuidedTestFinalizer` was removed. `EvalDatasetDeleteForm` replaces `ContentEntityDeleteForm`, showing the question count and the tests from `ai_eval.dataset_usage` (`targetsUsing('entity', $id)`). Stored results, runs, annotations and labels are kept. Questions orphaned by earlier deletions stay in the database, and `ReferenceOptions::bundles()` and the test case count ignore them.

Optimizer: the new `RunCoverage` helper computes the question IDs scored in every repeat and compares baseline and candidate means over the shared IDs only. It uses `Scorer::isCoverageInsufficient()` as the "fewer than half" policy. An insufficient baseline skips the target, and an insufficient or non-overlapping candidate is not stored. `runRepeatedEval()` fails the aggregate gate when coverage is insufficient. Dataset failures during baseline or candidate runs skip the target. The export command adds `isNull('r.import_key')` to its query and counts the skipped imported rows with the same `--target` and `--since` filters. It exits 0 when every result found was imported.

## Upgrade

No update is needed. Questions left behind by a dataset deleted in an earlier version stay in the database. Dropdown suggestions and test counts ignore them. Scripts that call `drush ai-eval:run` on a target with an empty dataset, or with `--question` or `--split` values that match nothing, will now get exit code 1 and no stored result.
