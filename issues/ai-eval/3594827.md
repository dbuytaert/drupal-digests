## Summary

Two fixes in AI Eval 1.1.x. First, uninstalling the module used to delete every `.json` file under the configured results path, including files it never wrote when the path pointed at a shared folder. It now removes only its own result files and envelope exports. Second, the Import traces page used to offer a server path option to anyone with `operate ai eval`. That option now appears only for users with `administer ai eval`. Operators can still upload a file. The Drush import command is unchanged and has no permission check, so the docs now say to restrict shell access.

## Impact

Affects site owners.

- **Security:** Users with only `operate ai eval` can no longer import traces from a server path. Only `administer ai eval` can. Forged form posts are rejected.
- **Permission change:** The server path source on the Import traces page now requires `administer ai eval`. Uploads still work with `operate ai eval`.

## Technical details

`ai_eval_uninstall()` now scans non-recursively. In the results path it matches only `/^results-\d{8}-\d{6}\.json$/`. In the `envelopes/` subfolder it matches only `/\.eee\.json$/`. It skips anything that is not a regular file, such as a directory with a matching name. A `FileException` on one delete is caught, so one failure cannot block uninstall. It then tries `rmdir()` on the `envelopes` folder, which succeeds only if the folder is empty. The results path itself stays. The default temp folder, used when `results_path` is empty, is not cleaned, and neither are files written by `ai-eval:export-envelope --output-dir`.

In `TraceImportForm`, a new `canUseServerPath()` checks `administer ai eval`. Without it, the `source` radios and `server_path` field are not built. `source` becomes a `value` element fixed to `upload`, and the upload field's `#states` visibility is dropped so it always shows. `validateForm()` also rejects `source=path` coming from either the form values or the raw user input. This covers forged posts, because the value element would otherwise hide them. It returns one fixed error on `source`, "You do not have permission to import from a server path. Upload a file instead.", so operators learn nothing about whether a path exists.

The commit also adds kernel tests for uninstall and form validation, a functional test for the operator view and a forged post, and changelog and docs updates. The changelog credits [#3594827](https://www.drupal.org/node/3594827) for uninstall and [#3594821](https://www.drupal.org/node/3594821) for the import restriction.

## Upgrade

No update steps are needed. If operators who hold only `operate ai eval` import from server paths, grant them `administer ai eval`, have an administrator do the import, or use `drush ai-eval:import-traces`. Uninstall no longer removes `.json` files in the results path that do not match `results-YYYYMMDD-HHMMSS.json` or `envelopes/*.eee.json`. Remove any other leftover files by hand.
