## Summary

On the judge gold labeling screen, Defer now moves to the next answer, as Pass and Fail do. Before, all three verdicts left the same answer on screen. Deferred answers keep their place in the list. They are skipped when advancing, and a "Deferred: N" count is shown. When every answer is labeled or deferred, the screen says "All answers are labeled or deferred. N deferred." and offers "Review deferred answers", which opens the first deferred one. Defer still does not count toward gold coverage. The same commit also ships three related changes. Saving a verdict now advances by one stable position, and a "Next unlabeled" link is added ([#3594843](https://www.drupal.org/node/3594843)). Only final answers, meaning non-empty replies with no tool calls, are used for gold labeling, coverage, agreement and validation ([#3594842](https://www.drupal.org/node/3594842)). The judge page resumes an unfinished validation run and offers Cancel ([#3594845](https://www.drupal.org/node/3594845)).

## Impact

Affects module maintainers.

- **New API:** `TraceBrowser::finalAnswerIds()` and `TraceBrowser::isFinalAnswer()`, `HumanLabelSourceInterface::nonFinalLabelCount()`, `JudgeValidationRunnerInterface::activeRunFor()` and `cancelValidation()`.

## Technical details

The gold screen no longer calls `TraceBrowser::orderedIds()` with unlabeled-first partitioning. It uses the new `TraceBrowser::finalAnswerIds()`, which pages the source 200 at a time and keeps only traces where `isFinalAnswer()` is true, so tool steps cannot use up the 200-answer window. The provider finish reason is not consulted. `GoldSetAgreement::domainScope()` and the coverage domain use the same filter. The blind re-label pass now keeps the round-1 label-id order and no longer puts pending items first.

`GoldLabelController::passNavigation()` computes the next index and renders the "Next unlabeled" link, the Deferred count and the completion message. On the gold route, the next target is the first item ahead of the current one with no label, wrapping to the first unlabeled item. A deferred item counts as labeled for this step. The label form posts a hidden `next` field. `ReviewController::saveLabel()` accepts only a local path starting with `/`, rejecting `//`, backslashes and whitespace or control characters with a 400. After a verdict it replies with an `HX-Location` header for that path, or with `HX-Trigger: ai-eval-gold-saved` and `HX-Reswap: none` when `next` is empty. The frame listens for that trigger and reloads itself. A note-only save, with no verdict, stays on the item. In the front-end JS, the old delayed Next click is skipped for forms that carry `next`, so it cannot race the server advance.

On the validation side, `HumanLabelSource` gains `nonFinalLabelCount()`. Labels on non-final spans stay stored but are excluded from validation, and the judge page reports how many were not used. `JudgeValidationRunner::activeRunFor()` returns the newest pending or running run with a non-zero total. The judge page shows its progress instead of the launch form, and a stale launch POST to `run()` rejoins that run. `cancelValidation()` takes the per-run step lock and refuses once `completed >= total`, so the next poll finalizes the report. `stepValidation()` now re-reads the run after taking the lock, so it cannot score a run canceled in the meantime. The progress POST handles `action=cancel`. A canceled run answers with `HX-Refresh` to restore the launch form.
