## Summary

A calibration fitted from an answer file without a name is now saved under the question it calibrates, so two calibrations for the same model no longer look identical in the Calibrations list. Decision recording also now matches a short state value such as "no" as a whole word in questions that mix in Chinese, Japanese or Thai text, instead of falling back to loose substring matching there. Existing calibrations keep their stored name.

## Impact

No upgrade or configuration changes required.

## Technical details

In `CalibrationFitForm::validateForm()` the Answer file tab now stores the question as a temporary value: the decision rubric's `question` when a rubric is selected, or the typed `instructions` when "Other wording" is chosen. On submit, an empty or whitespace-only name is replaced by that question, trimmed and cut to 200 characters with `Unicode::truncate(..., 200, TRUE, TRUE)` (word boundary plus ellipsis), matching the other tabs. A typed name still wins, trimmed. `docs` text and the CHANGELOG now say unnamed calibrations show their question on all three tabs, while older ones saved with an empty name still show the model id.

In `DecisionRecorder`, the separate branch that treated any text containing Han, Hiragana, Katakana, Thai, Lao, Khmer, Myanmar or Tibetan characters as substring-only was removed (follow-up [#3594930](https://www.drupal.org/node/3594930) to [#3594922](https://www.drupal.org/node/3594922)). Short needles (under 4 characters, not themselves in those scripts) now use the whole-word regex, with the boundary lookarounds extended to also accept an adjacent character from those unseparated scripts. So `no` matches in `東京no` and `noภาษาไทย` but not in `Does this notice apply to 東京?` or `東京_no`.
