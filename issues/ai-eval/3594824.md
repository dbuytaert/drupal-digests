## Summary

A run no longer starts on a dataset with no questions to run (missing, invalid, or every question turned off). The Run button shows the reason with a Retry button, no result is stored, and `drush ai-eval:run` prints the reason, runs the remaining targets, and exits with 1. The same applies when `--question` names an ID a target lacks or `--split` names an empty split. The commit also bundles related fixes. Deleting a dataset now deletes its questions, and the confirmation page lists the questions and the tests that use it. A browser run whose dataset loses questions mid-run stops with an error naming the question counts. `drush ai-eval:optimize` compares a candidate with the baseline only on questions both were scored on, and skips a baseline or candidate scored on fewer than half its questions. `drush ai-eval:export-envelope` skips imported results and reports how many.

## Impact

Affects module maintainers and site owners.

- **Database update:** No update. Questions orphaned by datasets deleted in earlier versions stay in the database; dropdown suggestions and test counts ignore them.
- **New API:** New `RunDatasetException` thrown by `EvalRunner::runTarget()` and `startRun()` when a dataset has no runnable questions; new `EvalDatasetDeleteForm`, `RunCoverage` helper and `RunFragment::notStarted()`.

## Technical details

`EvalRunner::runTarget()` and `doStartRun()` throw the new `RunDatasetException` (named constructors `empty()`, `emptySplit()`, `questionNotFound()`, `changed()`) instead of returning a failed empty result. Its message is written for users and shown as is. `RunController` catches it and renders `RunFragment::notStarted()`. `EvalRunCommand` catches it per target, collects the target in `$notRun`, still prints the gate summary of the others, and returns `EXIT_FAILURE`. `markRunError()` stores the message without the exception class for this exception type. In the step loop, a dataset with fewer questions than the stored run total now throws `changed()`, where it used to return quietly and poll forever. Growth or reordering only records drift.

Dataset deletion moved into `EvalDataset::postDelete()`, which deletes questions in chunks of 50. The duplicate cleanup in `DatasetCloner` and `GuidedTestFinalizer` was removed. `EvalDatasetDeleteForm` replaces `ContentEntityDeleteForm`, using `ai_eval.dataset_usage` to list affected tests. Using tests do not block deletion. Stored results, runs, annotations and review labels are kept. `ReferenceOptions::bundles()` and `WorkflowStateService::caseCount()` ignore questions whose dataset no longer exists.

The new `RunCoverage` helper (in the `ai_eval` namespace) takes the question IDs scored in every repeat on both sides of an optimizer comparison and averages over those. It reuses `Scorer::isCoverageInsufficient()` for the half-coverage rule. An insufficient baseline fails the aggregate gate and the target is skipped. An insufficient candidate, or one with too little overlap, is not stored. The applied baseline keeps the candidate's own mean, not the shared-question mean. `RunDatasetException` during optimizer runs skips that target.

Envelope export adds `isNull('r.import_key')` to the export query. A matching count query for imported rows, built with the shared `applyFilters()`, feeds the skipped message. The command exits 0 when every result found was imported.

## Upgrade

Scripts that relied on `drush ai-eval:run` storing a failed empty result for an empty dataset, an unknown `--question` ID or an empty `--split` now get an error and exit code 1 for that target. Questions left by a dataset deleted in an earlier version stay in the database. No update is needed.
