## Summary

In the AI Eval dataset question editor, the "Caller user ID" text box is now a "Caller account" field that suggests user accounts as you type, with "Anonymous (0)" always offered. Typing a numeric user ID still works. A stored ID with no matching account shows as "User 42 (no account on this site)" and is kept on save. The "Caller name" field is now "Name in the prompt". Its help text says it adds `[Caller: name]` before the question and changes only the text the model sees, not the account the question runs as.

## Impact

Affects module maintainers.

- **New API:** New route `ai_eval.dataset.caller_accounts` (`/admin/config/ai/ai-eval/caller-accounts`, `administer ai eval`) returning `<option>` suggestions for the caller field.

## Technical details

The stored value is still the integer `caller_uid`, and `user_name` keeps its key, so the dataset schema is unchanged. The editor input is a plain text field with a `<datalist>`. It uses htmx attributes (`hx-get`, `hx-trigger="input changed delay:300ms"`, `hx-target`) to fetch options from the new `DatasetQuestionController::callerAccounts()` route.

That endpoint always lists "Anonymous (0)" first. It then adds active accounts whose name contains the search term, taken from `q` or `caller_uid`. It returns at most 20 options in total, escapes the names, and exposes no email addresses. The query uses `accessCheck(TRUE)`, and the route requires `administer ai eval`.

On load, `DatasetQuestionController::callerDisplay()` turns the stored uid into display text, passed to `DatasetQuestionEditor::valuesFromStored()` through a new optional `$callerDisplay` argument. On save, `DatasetQuestionEditor::normalize()` takes the number from a trailing `(N)` or from the "User N (no account on this site)" form. Plain digits are also accepted, and leading zeroes are normalized. Anything else, including negatives, fractions and overflow, stays as text so the existing schema check rejects it. `docs/user/usage/datasets.md` and the changelog are updated. Tests: a new functional test `DatasetQuestionCallerAccountTest` and unit cases for the parsing.
