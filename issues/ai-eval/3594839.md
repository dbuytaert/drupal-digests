## Summary

In the trace review list, each conversation or agent run card now shows the visitor's first question, shortened to 120 characters. Reviewers no longer have to open every card to tell them apart. The same commit changes promotion to a dataset. Promoting a labeled agent run now takes the run's final answer as the AI response and the visitor's first user message as the input, instead of the root call. The group's failure mode is kept. Runs with a missing or cut first question are refused. Promotions to the same destination are serialized, so a busy destination counts as refused in **Promote all** and the run continues. After a successful promotion, the promote form is replaced by an **Added to [dataset]** confirmation with an **Edit this question** link and an **Add to another dataset** link. Trace cards also warn when tool turns in the input prevent promotion, and embeddings show "Embeddings: no text output".

## Impact

Affects module maintainers.

- **API change:** `PromotionService` constructor gains a `LockBackendInterface $lock` argument before the optional result envelope; `promotionIntegrityFlag()` is now public static.
- **New API:** `GroupedTraceSourceInterface::groups()` rows may carry an optional `question` string; trace arrays gain optional `response_kind` and `row_id` keys.

## Technical details

`OtelTraceSource::groups()` now also selects `created` and `operation_type` for the page's member rows. It picks the earliest `chat` call per group, breaking ties by `span_id`. It then reads `input` for those spans only, in one query. The text is parsed with `TracePayloadParser::parseInput()`, and the first `user` message is cut with `Unicode::truncate(..., 120, TRUE, TRUE)`. The result goes into the group row as `question`, is passed through `TraceReviewFragment::groupList()`, and is printed in the card Twig with normal escaping. `GroupedTraceSourceInterface::groups()` documents `question` as optional.

For agent runs, `PromotionService::representativeTrace()` now chooses the last chat call, ordered by `created` and then the new `row_id` key, with non-empty text and no response tools. Fallbacks are the last chat call, then the first member. `agentQuestion()` replaces the trace's messages with the first user message. It keeps that call's `raw_input` as `metadata.raw_input`, and a cut or flagged input marks the trace truncated and refused. `LabelStore::groupLabelsWithVerdicts()` now returns `failure_mode`, stored as `group_failure_mode`.

`PromotionService` gets a `LockBackendInterface` (`@lock` in `ai_eval.services.yml`). `acquirePromotionLock()` serializes the duplicate check, id allocation and write per destination, and `resolveLockedTarget()` reuses a dataset a competing request just created. If a lock cannot be acquired, `promoteByVerdictReport()` catches the `InvalidArgumentException` and counts the trace as refused. Duplicate outcomes now carry the existing `qid` and `question_entity_id`. Annotation promotions flag `another_result` when the same question was already promoted from a different result, and the outcome then adds a hint that this result has its own copy. `EvalResultsController` passes a `promoteDone` array to `PromoteFragment`/`AnnotationFragment` so the form is replaced by the confirmation. `OtelTraceSource` also sets `response_kind` for embeddings, and for non-chat outputs that exactly match the string-conversion diagnostic, so they are not treated as uncaptured streams. `PromotionService::promotionIntegrityFlag()` is now public static so the trace card can show the tool-turn notice.
