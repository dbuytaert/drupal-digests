## Summary

On the Decision Calibration review page, a caller with more stored answers than its limit (for example 5 recorded, limit 3) showed "Recording stopped: 5 recorded, limit 3" and also "Recording for this caller stopped at 3 answers." The second line is now shown only when the recorded count equals the limit. The "Record 50 more" button and the admin notice stay when the count is above the limit. The commit that shipped this fix also bundles other form and wording fixes: Enter no longer saves a rubric, the gate threshold follows the selected metric, question row buttons have accessible names, entity types and bundles show their labels, and singular and plural counts are corrected in many messages.

## Impact

Affects module maintainers.

- **New API:** New route `ai_eval.rubric.phrase_row`, `EntityLabels` helper, and `GateMetric::browserSettings()` in ai_eval.

## Technical details

The cause was that `DecisionReviewForm` showed the "stopped at" paragraph whenever `RecordedCallers::stopped()` was true, and that is `$recorded >= $limit`. The paragraph is now wrapped in `$recorded === $limit` and uses `formatPlural()`. The rest of the `stopped` block is unchanged. `DecisionReviewFormTest::testLimitBelowCount` now asserts that "stopped at" is absent when 4 are recorded against a limit of 2, and that an admin still sees the "Record 50 more" button. New `testStoppedNoticePlural` covers limits of 1 and 2.

The same commit (1.1.x, listed in the changelog as [#3594846](https://www.drupal.org/node/3594846) to [#3594852](https://www.drupal.org/node/3594852)) also changes the following:
- **Rubric editor:** Rubric phrases are added one at a time through a new `ai_eval.rubric.phrase_row` route (`RubricController::phraseRow()`) and an "Add phrase" button. A keydown handler in the rubric editor JS blocks Enter from submitting in text inputs and moves focus to a new phrase input. Only **Save** submits.
- **Gate threshold:** New `js/gate-threshold.js` and `GateMetric::browserSettings()` reset the threshold when the metric changes, if it is empty, equal to the previous metric's default, or above the new scale's max. A custom value that fits the new scale stays.
- **Question rows:** Row buttons in `DatasetQuestionList` get `aria-label` and `title` text that include the question id.
- **Manual model entry:** `ProviderModelOptionsTrait` gains a notice and a hint for the case where no chat models are listed.
- **Entity labels:** New `EntityLabels` helper shows entity type and bundle labels instead of machine names in the automator option lists and recorded answers.
- **Plurals:** Many messages use `formatPlural()` or `PluralTranslatableMarkup`.
- **Wording:** AI Observability length-limit wording now says "unless the site changed it".
