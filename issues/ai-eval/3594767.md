# #3594767: Promoting an annotated answer drops the question's criteria and can duplicate it

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594767](https://git.drupalcode.org/project/ai_eval/-/work_items/3594767) · 1 contributor · 2 comments

## Summary

Annotate > Add to dataset on a result page now builds the new question from the question the answer was given for, not from the input alone. The "What makes an answer good" field is prefilled with the source question's criteria and one expected fact. The new question keeps the source id (for example `sunday_visit`) instead of `annotation-<id>`. Adding an answer to a dataset that already holds the source question no longer creates a silent copy. It adds nothing and links to the existing question. The status message now shows in the form next to the button.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix landed in the Sprint 7 commit 8c8f8cd, which fixed several promotion problems at once. `PromotionService::promoteAnnotationOutcome()` now calls `sourceQuestion()` and `sourceDataset()` to find the dataset question behind a result. It prefers the dataset recorded in the run's snapshot over the test's current dataset. It also reports a certainty (`exact` when the dataset still hashes to the recorded `dataset_sha256`, `current` when it changed or only the current dataset is known, `none` when no question matched). The new question copies the source's `CARRIED_FIELDS` (criteria, expected, expected_facts, expected_tools, rubric_ref, choices, files, bundle, tags, caller_uid, user_name). The source's `trace_key` is dropped so the trace is not treated as already promoted. Provenance goes in metadata along with `source_question_id` and `source_certainty`.

The id is the source id. If a different question in the target already has it, `-2`, `-3` and so on are appended. When the target already holds the source id with the same recorded transcript, the new status `PromotionService::STATUS_SOURCE_PRESENT` is returned with the existing question's `qid` and `question_entity_id`. `PromoteFragment` renders that status. The old `annotation-<id>` id remains only as the fallback when no source question can be found.

`sourcePrefill()` supplies the form's criteria and one fact. It picks the first scalar fact that is not `must_not_contain` and can be stored back unchanged. The new optional `$formFact` argument of `promoteAnnotationOutcome()` tells the service which fact the form showed. This way, clearing a field drops only that criteria or fact, and the source's other facts stay.
