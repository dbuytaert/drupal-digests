## Summary

One commit bundles five fixes in the AI Eval module. (1) `drush ai-eval:export-envelope` no longer writes results imported from another EEE file. They used to come out labelled first party with a failed gate that was never applied here. The command now skips them and says how many it skipped ([#3594826](https://www.drupal.org/node/3594826)). (2) A run no longer starts on a dataset with no runnable questions. The Run button and `drush ai-eval:run` give the reason and store no result, and the command exits with 1. A `--question` ID a target lacks, or an empty `--split`, is now reported as an error per target and exits with 1, where it used to store a failed empty result ([#3594824](https://www.drupal.org/node/3594824)). (3) A browser run whose dataset loses questions stops with an error naming the question counts, instead of polling forever ([#3594823](https://www.drupal.org/node/3594823)). (4) Deleting a dataset now deletes its questions, and the confirmation page lists the tests that use it ([#3594825](https://www.drupal.org/node/3594825)). (5) `drush ai-eval:optimize` compares a candidate with the baseline only on the questions both were scored on. It skips a baseline or candidate scored on fewer than half its questions, so questions lost to errors can no longer raise the score ([#3594818](https://www.drupal.org/node/3594818)).

## Impact

Affects module maintainers.

- **API change:** `EvalRunnerInterface::runTarget()` and `startRun()` now throw the new `RunDatasetException` when the dataset has no runnable questions, instead of returning an empty scored result.
- **New API:** New `Drupal\ai_eval\Service\RunDatasetException` and `Drupal\ai_eval\RunCoverage` helper.

## Technical details

Export: `EvalExportEnvelopeCommand` builds the export query with `isNull('r.import_key')` and runs a second count query for imported rows. Both use a shared `applyFilters()` for `--target` and `--since`. If every row found was imported, the command exits 0.

Empty datasets: a new `RunDatasetException` has readable messages (`empty()`, `emptySplit()`, `questionNotFound()`, `changed()`). `EvalRunner::runTarget()` and `startRun()` throw it instead of returning an empty scored result. `RunController` renders it through `RunFragment::notStarted()`. `EvalRunCommand` catches it per target, continues with the other targets, and returns failure at the end. In the step loop, a dataset that shrank below the run's stored total now throws `changed()`. `markRunError()` stores that message without the exception class prefix.

Dataset deletion: `EvalDataset::postDelete()` deletes the questions in chunks of 50. This replaces the manual question deletion in `DatasetCloner` and `GuidedTestFinalizer`. `EvalDatasetDeleteForm` shows the question count and the tests from `ai_eval.dataset_usage`. Tests using the dataset do not block deletion. Results, runs, annotations and review labels are kept. Questions orphaned by earlier deletions stay in the database. `ReferenceOptions::bundles()` and `WorkflowStateService::caseCount()` now ignore them.

Optimizer: the new `RunCoverage` helper uses `Scorer::isCoverageInsufficient()`. It computes the question IDs scored in every repeat on both sides and the mean over those IDs. A target is skipped when its baseline coverage is insufficient. An attempt with insufficient coverage is skipped and not stored. `runRepeatedEval()` now fails the aggregate gate on insufficient coverage. When the compared set is narrower than the full set, the applied candidate's own mean stays as the running baseline (`$candidateOwnScore`), and the shared means are used only for that comparison. A `RunDatasetException` during optimizer runs skips that target.

## Upgrade

Questions left behind by a dataset deleted in an earlier version stay in the database. Dropdown suggestions and test counts ignore them. No update is needed.

Scripts that call `drush ai-eval:run` should expect exit code 1 when a target's dataset has no runnable questions, when `--question` names an ID a target lacks, or when `--split` is empty. Custom callers of `EvalRunnerInterface::runTarget()` or `startRun()` should catch `Drupal\ai_eval\Service\RunDatasetException`.
