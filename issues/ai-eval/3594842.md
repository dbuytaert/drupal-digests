## Summary

The gold labeling screen for LLM judges now serves only final answers: replies with text and no tool calls. Tool-call steps no longer appear on the screen, in the "Trace N of M" counter, in coverage, or in agreement numbers. Labels already stored on those steps are kept but left out of judge validation. The judge page says how many were not used. The screen now keeps one stable order. Saving a verdict, Defer included, moves on to the next unlabeled answer, and a "Next unlabeled" button and a deferred count are shown. When every answer is labeled or deferred, the page says so and links to the deferred ones. A domain that has only tool steps shows a new empty-state message. Separately, returning to a judge page now resumes its newest unfinished validation run with the labels saved when it started. The launch form stays hidden while a run is open, and a Cancel button stops it.

## Impact

Affects module maintainers.

- **API change:** `HumanLabelSourceInterface` and `JudgeValidationRunnerInterface` gained methods, so custom implementations must add them. The label POST endpoint accepts an optional local `next` path.
- **New API:** `TraceBrowser::isFinalAnswer()` and `TraceBrowser::finalAnswerIds()`; `HumanLabelSourceInterface::nonFinalLabelCount()`; `JudgeValidationRunnerInterface::activeRunFor()` and `cancelValidation()`.

## Technical details

The final-answer rule is `TraceBrowser::isFinalAnswer()`. It is true when the normalized `response_text` is non-empty after trim and `response_tools` is empty, and it does not look at `finish_reason`. `TraceBrowser::finalAnswerIds()` pages the trace source in blocks of 200 and filters normalized traces in PHP. The 200-answer window is therefore filled with answers rather than tool steps. `GoldLabelController::build()` and `GoldSetAgreement::domainScope()` both use it, so the screen, the coverage count and the relabel scope agree. Per the commit, `HumanLabelSource` now hydrates round-1 labels through a shared generator. `forGrader()` skips non-final traces, and the new `nonFinalLabelCount()` feeds the note on `JudgeValidateController`. The count is skipped if building the judge throws a `PluginException`.

Navigation moved into `GoldLabelController::passNavigation()`. The blind relabel pass keeps round-1 label-id order and no longer moves answered items to the end. The gold card form now posts a hidden `next` URL. `ReviewController` accepts it only if it is a local path (no `//`, backslash or whitespace, else 400). After a saved verdict it replies with an `HX-Location` header, or with `HX-Trigger: ai-eval-gold-saved` at the end of the pass. A note-only save stays put. The client-side script no longer clicks Next after a gold submit, which would race the server redirect and skip an answer.

For validation, `JudgeValidationRunner::activeRunFor()` returns the newest pending or running run with `total > 0`. `JudgeValidateController` renders its progress fragment in place of the launch form. A stale `run()` POST rejoins that run instead of creating a new one. `cancelValidation()` takes the step lock and refuses once `completed >= total`, so the next poll finalizes the report. The progress POST accepts `action=cancel` and answers with `HX-Refresh` on cancel. `stepValidation()` now re-reads the run after taking the lock, so a canceled or finished run is never scored from stale state.

## Upgrade

Custom implementations of `HumanLabelSourceInterface` must add `nonFinalLabelCount(?array $domainTags = NULL, ?string $dimension = NULL): int`. Custom implementations of `JudgeValidationRunnerInterface` must add `activeRunFor(string $graderId): ?array` and `cancelValidation(int $runId): bool`.
