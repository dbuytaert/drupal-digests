## Summary

AI Eval no longer lets automatic result export write into a publicly served folder. The settings form refuses a `results_path` inside the web root or the public files folder, and the export checks the path again before it writes. If your saved `results_path` is unsafe, you must change it before the settings form will save again. Importing traces from a server directory is also bounded: at most 100 JSON files and 64 MB in total (still 8 MB per file), and the import form tells admins to use `drush ai-eval:import-traces` for anything larger. Large directory imports no longer hold every span in the batch table.

## Impact

Affects module maintainers and site owners.

- **Security:** Exported `.eee.json` result files (questions and answers) could be written to a publicly downloadable folder; `results_path` is now validated.
- **Config change:** `results_path` inside the web root or public files folder, or using a stream wrapper other than `private://` or `temporary://`, is rejected on save and at export time.
- **New API:** New `ResultsPathGuard` service class with static `localPath()` and `isSafe()`; `TraceImportForm::MAX_BYTES`, `MAX_FILES` and `MAX_TOTAL_BYTES` are now public constants.

## Technical details

`ResultsPathGuard` (new, `src/Service/ResultsPathGuard.php`) has two static methods. `localPath()` passes plain paths through, maps `private://` and `temporary://` to their local base directories (rejecting `..` segments), and returns NULL for any other scheme, so `public://` and `php://` are refused. `isSafe()` resolves symlinks in the nearest existing ancestors and compares the result with both the web root and the public files directory, both lexically and after resolution, so a folder that does not exist yet is checked through its parent. `EvalSettingsForm` validates `results_path` with it, and `EnvelopeExportSubscriber` (which now takes `%app.root%` as a constructor argument in `ai_eval.services.yml`) throws a `RuntimeException` before `prepareDirectory()` if either the results path or the `/envelopes` output directory is unsafe. `drush ai-eval:export-envelope --output-dir` is not changed.

`TraceImportForm` makes `MAX_BYTES` public and adds `MAX_FILES` (100) and `MAX_TOTAL_BYTES` (64 MB). It checks them in validation, and `TraceImportBatch::process()` checks them again on the first step, then re-checks each file's size just before reading it, since files can change between form validation and the batch. The sandbox now holds only `files`, `offset` and `span_offset`. Each step reads one file through `readSpans()`, which reads at most `MAX_BYTES + 1` bytes, and imports up to 100 spans from it. Parse counts (`skipped_documents`, `unread_tails`) are added once per file. Import counts and undo work as before. No change to `schema/*.schema.json`.

The same commit bundles fixes for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926); this entry covers only the [#3594908](https://www.drupal.org/node/3594908) parts.

## Upgrade

If your saved `results_path` is inside the web root or the public files folder, change it to a local directory outside both, or to a `private://` or `temporary://` URI, before saving the AI Eval settings form. Leaving it unsafe makes automatic export fail with `Automatic export requires a local directory outside the web root and public files directory.` For trace directories above 100 files or 64 MB in total, use `drush ai-eval:import-traces`.
