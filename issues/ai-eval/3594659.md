## Summary

AI Eval dataset questions can now include images (png, jpeg, webp, gif). Chat targets, config agent targets and AI Prompt workflow targets send the images to the model. LLM judges receive the same images when grading. You add images with a new **Upload images** field in the question editor, or by listing filename and image reference pairs under **Files**. A model or judge that cannot read images does not get a zero: the question is skipped, or the judge returns no score, and the reason is shown. Other workflow runners and code-defined agents skip image questions. The results page shows thumbnails of a question's images and any skip reason. Limits are 5 MB per image and 5 images per question.

## Impact

Affects module maintainers and site owners.

- **Config change:** Uploaded question images become managed files under `private://ai_eval/question-files/` (or `public://` when private storage is not configured).
- **New API:** New services `ai_eval.question_image_resolver` (`QuestionImageResolver`) and `ai_eval.question_image_upload` (`QuestionImageUpload`); `WorkflowRunOptions` carries an `images` list to workflow runners.

## Technical details

The per-question `files` key already existed in the dataset schema but the runner ignored it. A new `QuestionImageResolver` service turns `files` entries into images and attaches them to the last user `ChatMessage`. It accepts `public://` and `private://` URIs and `data:image/...;base64,` URLs with a matching MIME type. For FileSource YAML datasets, `FileSource` also rewrites paths relative to the YAML file, and the resolved path, symlinks included, must stay inside that folder. Remote URLs are refused. Non-image string values are carried but never sent.

`EvalRunner` resolves images before invoking the target. It skips the row (unscored, with `skip_reason`) when the model cannot read images, when the workflow runner is not `ai_prompt`, or when a code-defined agent is used. For config agents (`AiAgentEntityWrapper`) it checks the agent's provider and model, falling back to the `chat_with_tools` default. If the model cannot be resolved, it sends the images anyway and records an `image_warning`. `AiPromptWorkflowRunner` attaches `$options->images` to the rendered prompt. The `LlmJudge` base class receives the same resolved bytes through a `_question_images` entry in the grader context, so judges see what the target saw. A judge without vision support returns a null score with an explanation.

Uploads go through `QuestionImageUpload`, which stores managed files and tracks usage. The question editor saves inside a database transaction and deletes the new files on failure. A new `QuestionFileUsageHooks` releases file usage when a question is deleted. Run identity records each image's name, SHA-256, MIME type and byte count in a `files` entry, not the contents. Results pages limit inline previews to 256 KB each and 2 MB per page, and show the name and size when a preview is too large. `LabeledExample` gained a `files` map. `HumanLabelSource` reloads a question's files from the source dataset only when `PromotionService::sourceDataset()` reports an exact match with the run. Otherwise that review is left out of judge validation, and `inexactAnnotationCount()` feeds a message on the validation page. Text-only reviews stay usable after the dataset changes or is deleted.

## Upgrade

Custom classes that construct `AiPromptWorkflowRunner` need the extra constructor argument, which is optional on the class:

```yaml
arguments: ['@entity_type.manager', '@?ai.provider', '@ai_eval.chat_invoker', '@ai_eval.rate_limit_handler', '@datetime.time', '@ai_eval.question_image_resolver']
```

`EvalRunner`, `EvalResultsController`, `FileSource`, `HumanLabelSource` and `LlmJudge` also take the new service or `@ai_eval.promotion_service`. Constructor changes only matter if you subclass or re-register them.
