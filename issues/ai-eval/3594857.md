## Summary

The Annotate step (step 2 of the error-analysis workflow) used to show progress against a fixed target of 100, so a test with 8 answers read "0 of 100 suggested" even after every answer was labeled. It now counts labeled answers on the latest run and reads, for example, "12 of 20 answers labeled". Step 2 is Done only when the latest run is fully labeled, so running the test again takes it back to "Start here". Deferred answers count as labeled. The same commit also changes several related screens in `ai_eval` (1.1.x). Results screens show the gate a run actually used, or "Gate not recorded", instead of an invented 4.0 threshold, and they show test names instead of ids. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred". The compare page uses plain labels. Gate type wording now says it only changes the exit code of `drush ai-eval:run`. Calibration screens warn when a fit will not apply because the rubric wording changed, and when a saved fit replaced an inactive one.

## Impact

Affects module maintainers.

- **API change:** The annotate step's `progress` array from `WorkflowStateService` no longer has a `suggested` key, and `progress` is NULL when the latest result has no questions. `FailureRateService` rows gain a `verdict` key and the `(untagged)` label is replaced.

## Technical details

Annotate progress: `WorkflowStateService` drops `ANNOTATION_TARGET` and the `suggested` flag. `latestResult()` now also selects `question_count`. `done` is the number of canonical annotations (via `AnnotationStore::joinCanonical()`) on the latest result's `result_id`, and `total` is its `question_count`. The target-wide `$labeled` count is kept for the grouping floor, rates and promote steps. `WorkflowRibbon` builds the label with `PluralTranslatableMarkup` ("@done of 1 answer labeled" / "@done of @total answers labeled").

Gate display: `EvalResultsController::recordedGate()` resolves the gate from the run's validated config snapshot (`decodeValidatedSnapshot()`) when it has a known metric and a numeric threshold. Otherwise it falls back to the live target's threshold, and returns NULL if neither exists. The detail page then prints "Gate not recorded", and the dashboard drops the "/ threshold" text and the gate wording from the score aria label. The results pages also load target entities once, show `label()` with the id as a `title` attribute, and add target cache tags.

Failure rates: `FailureRateService` now selects and groups by `verdict`. In `decorate()`, rows with a failure mode are merged per mode, and rows without one are bucketed by verdict ("Passed", "Deferred", "Failed, no failure mode"), so the shares still sum to 100%. `ratesForReviewedTraces()` follows the same rule.

Compare page: `ResultsCompareController` gains an optional `graderManager` constructor argument (`ai_eval.grader_manager`). It maps snapshot keys to labels, hides hash values (shown as "same" or "changed"), and moves raw values into a closed "Technical details" element. Gate wording is centralised in the new `GateTypeWording` class, used by `EvalTargetForm` and `GuidedTestForm`.

Calibration: `CalibrationFromReviewsForm` warns when the group's rubric fingerprint differs from `currentFingerprint()`. `CalibrationSaveTrait::saveAndReport()` counts inactive curves for the same provider, model and fingerprint before saving, and reports when a save replaced them.

## Upgrade

Code that reads the annotate step from `WorkflowStateService::stepsForTarget()` should stop reading `progress['suggested']`. It should also handle `progress` being NULL when the latest result has no questions. `done` and `total` keep their keys, but `total` is now the latest result's `question_count` instead of 100.
