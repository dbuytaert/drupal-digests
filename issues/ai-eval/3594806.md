## Summary

AI Eval's Review decisions screen can now show the reviewer the text the model judged, not just a link to the entity. This is opt-in per caller on Record decisions and is off by default, because the text can contain personal data. When enabled, the text appears in a collapsed section on each row and is removed after the answer is reviewed or when its entity is deleted. The model's probability stays hidden while an answer waits for review, so it does not bias the label. A separate view of reviewed answers shows the saved label next to the raw probability and, if a calibration was applied, the calibrated one. This summary is based on the issue text only. The fix's code was not available to check, so the shipped behavior may differ in detail.

## Impact

Affects site owners.

- **Database update:** Nullable text column for the stored state on `ai_eval_decision_record`, with an update hook (as described in the issue).
- **Config change:** Record decisions gets a per-caller opt-in, "Keep the text sent to the model, for review", off by default (as described in the issue).
- **Permission change:** Stored text is shown only to users with the existing review permission.

## Technical details

The issue explains why the text is stored instead of rebuilt from the entity reference. A token-mode automator sends a rendered token prompt. A multi-value base field sends one request per value, and the record does not keep which value. A caller that is not a field automator has no entity field. The entity can also change after the answer. The plan is to store the sent text in a nullable column on `ai_eval_decision_record`, added by an update hook. The existing entity-deletion cleanup hook would delete it, as would the review step. The issue lists the retention rule as unconfirmed: delete after review, or keep until a calibration is fitted from the answer. It also lists tests for storage, deletion and access, and an update to the privacy text on Record decisions. The reviewed-answers view is meant to let each answer type render its own output: true/false now, choice and score later. I could not find the implementing commit in the cloned repository, so these details come from the issue body, not from a diff.

## Upgrade

Run database updates after upgrading to add the nullable column on `ai_eval_decision_record`. Then decide per caller on Record decisions whether to turn on "Keep the text sent to the model, for review". It is off by default. Update your privacy notice if you enable it.
