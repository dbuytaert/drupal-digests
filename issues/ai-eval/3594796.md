# #3594796: Add a settings form and a requirements check for the content review judge

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594796](https://git.drupalcode.org/project/ai_eval/-/work_items/3594796) · 1 contributor · 2 comments

## Summary

The content review judge in `ai_eval_content_review` now has a settings form at `/admin/config/ai/ai-eval/content-review` for the review rule, criterion, content type, body field and text format. It offers only choices that exist on the site. Previously these could only be changed with `drush cset` or config import, and a content type without the expected `body` field (as on a Drupal CMS `page`) made the criterion see only the title and score the answer 0 with no warning. Now a judge with settings that do not fit the site reports the answer as not measured, and the status report says what is wrong. New installs leave the content type, body field and text format unset, so a site owner must choose them before the judge can run. Existing sites keep their current values.

## Impact

Affects module maintainers and site owners.

- **Config change:** New installs ship `ai_eval_content_review.settings` with `bundle`, `body_field` and `body_format` empty (previously `page`, `body`, `basic_html`); existing sites keep their values.
- **Permission change:** New route `/admin/config/ai/ai-eval/content-review` is gated by the existing `administer ai eval` permission.
- **New API:** New `JudgeSettingsChecker` service (`ai_eval_content_review.settings_checker`) with `problems()` and `errors()`; `CriterionRunner` takes it as a fifth constructor argument.

## Technical details

A single `JudgeSettingsChecker` is shared by the form, the status report and the judge. `problems()` returns errors and warnings keyed by setting. Errors cover a missing rule, a missing criterion index, a missing or nonexistent content type, a body field that is unset, absent or not of type `text`, `text_long` or `text_with_summary`, an unset, nonexistent or disabled text format, a format the field's `allowed_formats` excludes, and `extra_fields` the type lacks. A warning is raised for a disabled rule, or for a rule that does not apply to the configured bundle. `errors()` returns only the blocking messages.

`CriterionRunner::review()` calls `errors()` before building the unsaved node. If any are returned it throws a `RuntimeException` ("The content review judge settings do not fit this site: ..."), so the judge records no measurement instead of reviewing a page without the answer. `JudgeSettingsRequirements` (`hook_runtime_requirements`) adds a status report row: "Not set up" (warning) when no rule is set, "Settings fit this site" (OK), "Check the settings" (warning) or "Cannot review" (error). `JudgeSettingsForm` is a `ConfigFormBase` that filters the criterion, body field and format selects by the chosen rule, content type and field, and redraws them with htmx. It warns when the criterion changes, since existing judges then check another criterion and need validating again. Earlier validations are not marked stale. The default `config/install` values for `bundle`, `body_field` and `body_format` are now empty strings.

## Upgrade

Custom code that constructs `CriterionRunner` directly must pass the new `ai_eval_content_review.settings_checker` service (`JudgeSettingsChecker`) as the fifth argument. On new installs, open `/admin/config/ai/ai-eval/content-review` and choose the content type, body field and text format before running the judge.
