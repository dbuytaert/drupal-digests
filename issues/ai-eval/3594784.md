# #3594784: Let the decision rubric judge see the question as well as the answer

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3594784](https://git.drupalcode.org/project/ai_eval/-/work_items/3594784) · 1 contributor · 2 comments

## Summary

The decision rubric judge can now see the test question as well as the answer. Previously it only received the answer, so rules such as \"do not add facts that answer a different question\" or \"reply in the visitor's language\" could not be judged. Set the new optional `input_key` in `ai_eval.decision_rubric` and every rule is asked with the question under that name. Left empty, nothing changes and stored calibrations keep applying. Once it is set, any calibration fitted on the answer alone stops applying and you need to fit a new one. The issue's demo-site validation (72 labeled answers) showed mixed results: fewer missed padding errors, but lower overall true positive rate. The author says the rule wording is probably the next thing to tune.

## Impact

Affects site owners.

- **Config change:** New optional `input_key` in `ai_eval.decision_rubric`; empty (default) keeps current behavior and stored calibrations.

## Technical details

`DecisionRubric` gains a readonly `inputKey` property, read from config `input_key` and trimmed, defaulting to an empty string. In `DecisionRubricGrader::grade()`, when `inputKey` is non-empty the Decision state becomes `[$rubric->inputKey => $input, $rubric->stateKey => $response]`. Otherwise it stays `[$rubric->stateKey => $response]`. `DecisionRubric::fingerprint()` adds `input_key` to the fingerprint settings only when it is set, so a rubric without it keeps its old fingerprint and its stored calibrations stay valid. A rubric with it gets a new fingerprint, since a curve fitted on the answer alone says nothing about judging with the question. `problem()` now refuses an `input_key` equal to `state_key`, because the answer would overwrite the input in the state array. The config schema `ai_eval.decision_rubric` has the new `input_key` string. `docs/user/usage/calibration.md` gains a paragraph that suggests wording the rubric's question to mention the visitor's question and the assistant's reply.

## Upgrade

Optional. To let the judge see the question, set `input_key` in `ai_eval.decision_rubric` (the docs use `question` as an example) and reword the rubric question to say it is given a question and a reply. Then refit the calibration, because the fingerprint changes. Existing configs without `input_key` need no action.
