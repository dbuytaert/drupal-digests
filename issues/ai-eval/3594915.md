## Summary

`drush ai-eval:optimize` and `drush ai-eval:distill` now exit with a non-zero status when something goes wrong, so CI no longer treats a failed run as a success. `optimize` also saves an accepted prompt through the agent entity instead of raw config, so entity hooks and cache invalidation run, and it stops with an error if the agent was deleted during the run. `distill` now reports write failures and includes questions that scored exactly 0.0 in `intel_failure_patterns.md`.

## Impact

No upgrade or configuration changes required.

## Technical details

Both command methods change their return type from `void` to `int` and return `self::EXIT_FAILURE` or `self::EXIT_SUCCESS`. In `EvalOptimizeCommand::optimize()` a `$hadError` flag is set on every per-target error path (same-family proposer refusal, invalid split declaration, `RunDatasetException`, too-few-measured baseline or candidate, no shared scored questions, short metaprompt result, JSON encode failure, failed or missing agent save). The flag persists across targets, so a later successful target does not mask an earlier error. No targets configured and an invalid `--split` return failure immediately.

The accepted-prompt path previously did `configFactory->getEditable("ai_agents.ai_agent.{id}")->save()`, which skips the config entity save, its hooks and the entity list cache tag, and could recreate a deleted agent's config. The prompt is still read through `configFactory->get()`, but the write now reloads the agent with `getStorage('ai_agent')->loadUnchanged($agentId)` just before saving, errors out if it is `NULL`, and calls `set('system_prompt', ...)->save()` on the entity, with a caught exception also counting as an error.

In `EvalDistillCommand::distill()`, the `prepareDirectory()` result and the `file_put_contents()` byte count for `intel_quality_baseline.md` and `intel_failure_patterns.md` are checked. The failure filter changed from `avg_score > 0` to rows that have `avg_score` set, no `error` and no `unscored` flag, and `passed` false, so judged 0.0 failures are kept (the same fix [#3594902](https://www.drupal.org/node/3594902) made in the optimizer). The same commit also covers many other review findings under [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926); this entry covers only the Drush command changes.

## Upgrade

If a CI job or script runs these commands, expect non-zero exit codes on any target error, an empty result set, an invalid `--split`, or an unwritable output directory. Check that pipelines handle this, for example:

```
drush ai-eval:optimize --target=my_agent || echo "optimize reported errors"
drush ai-eval:distill --output-dir=/path/to/intel
```
