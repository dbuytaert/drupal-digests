# #3594774: Buttons and workflow steps that promise what they do not do

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594774](https://git.drupalcode.org/project/ai_eval/-/work_items/3594774) · 1 contributor · 2 comments

## Summary

The AI Eval guided test and workflow page no longer promise things they did not do. "Save and run" on the Review step now saves the test and starts a run, then opens the workflow page, which shows the run's progress. Chat tests no longer offer the prompt optimizer, which only works on agent tests; the step now says so. The steps in tabs A and B open this test's own dataset, rubrics and judges (a dropbutton when there are several) instead of the site-wide lists. Step A1 no longer promises generated cases. Because "Save and run" now starts a run, it can incur provider charges, and the form says so.

## Impact

Affects module maintainers.

- **API change:** `WorkflowStateService` takes the dataset loader and rubric loader as optional fifth and sixth constructor arguments, `GuidedTestForm` takes the eval runner, and workflow step descriptors may carry `action_links` and `requires_permissions`.
- **New API:** `RubricLoader::loadEntity()` is new, and step descriptors accept `action_links` (list of `{label, route, params}`) rendered as a dropbutton.

## Technical details

`GuidedTestForm::saveAndRun()` now calls `EvalRunnerInterface::startRun($target, 'ui')` after the finalizer saves the draft. If the start throws, the save stands. When `activeRunForTarget()` returns a run, the form shows "A run is already in progress." as a warning. Any other failure is shown as "The run could not start: @reason". The button and a cost note are rendered only when `$unresolved === []`, so a selected judge with no model hides the run.

`WorkflowStateService` gets the dataset loader and rubric loader as optional constructor arguments. It uses them to build step descriptors with `action_links` (rubrics the test's questions name, LLM judges the test uses, the test's dataset). `WorkflowRibbon::accessibleLinks()` filters those by access. With more than one link it renders a `dropbutton` whose first item keeps the step's label. With exactly one accessible link, that link replaces the collection route. The test's own route is used only when no specific link is known, so the collection link remains the fallback. `TargetDashboardController` attaches `core/drupal.dropbutton`, since tab switches swap in fragments that carry no libraries. For chat-mode targets (`mode === 'chat'`) the optimize step becomes not-started with the badge "Agent tests only" and no action. The re-run step text changes, and a leftover pending candidate no longer blocks it.

The same commit also added a `requires_permissions` descriptor key, used to note the Annotate permission next to the Annotate step's link (tracked in [#3594776](https://www.drupal.org/node/3594776)). It also scoped the error-analysis counts to the current test ([#3594775](https://www.drupal.org/node/3594775)).

## Upgrade

Code that constructs these classes directly needs the new arguments. `GuidedTestForm` now requires `ai_eval.eval_runner` (and `ai_eval.reference_options`, from [#3594777](https://www.drupal.org/node/3594777)). `WorkflowStateService` accepts the dataset loader and rubric loader as optional fifth and sixth arguments, so existing constructions still work but the rubric step then links to the rubric list.
