# #3594809: ai-eval:optimize spends a baseline on tests it cannot optimize

## Summary

`drush ai-eval:optimize` now skips tests it cannot optimize before running any baseline. Previously a workflow test, or an agent test whose agent has no system prompt, ran the full baseline (3 runs by default, 6 with a dataset split) and only then failed with "No system_prompt found in agent config". That wasted model and judge calls, and `--dry-run` spent the same baseline. The command now prints a message naming the test and the reason. On the test workflow page, chat and workflow tests show "Agent tests only" in place of the Optimize link.

## Impact

No upgrade or configuration changes required.

## Technical details

The issue body says the command already skipped chat tests before running anything (`EvalOptimizeCommand.php`). The change extends that early check, run before any model call, to two more cases. One is any test not in agent mode. The other is an agent test whose agent config has no system prompt. The workflow page gate now covers chat and workflow tests, not chat only. The page change is in the Optimize step logic, where the "Agent tests only" badge text lives (`WorkflowStateService.php`).
