## Summary

Judge validation used to count a labeled answer the judge never scored (a provider error, a rate limit, or a judge with no model) as a judge fail. That inflated the true negative rate on fail-labeled rows and added false negatives on pass-labeled rows. Such answers are now left out of the confusion matrix and the rates, and shown as **Not scored** on the validation report, history, Judges page and `drush ai-eval:judges`. Any not-scored labeled answer blocks the Trusted state. Run database updates and validate again any judge that had provider errors, because earlier stored counts cannot be repaired. The same commit also ships related trust changes: a minimum of 10 distinct pass and 10 distinct fail labels (new **Not enough labels** state), and stricter threshold handling.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_eval_update_10050` adds nullable `not_scored`, `endpoint_only`, `pass_items` and `fail_items` columns to `ai_eval_judge_validation`.
- **Config change:** Pass thresholds now accept at most two decimals (form step changed from 0.1 to 0.01).
- **API change:** `JudgeValidationReport` gains optional trailing `$notScored`, `$passItems`, `$failItems`, `$endpointOnly` constructor arguments; `JudgeValidationStoreInterface`, `JudgeGateTrustInterface` and `CorrectedPassRateInterface` gain methods that custom implementations must add.
- **New API:** `JudgeValidationReport::trustBlocker()`, `passLabels()`, `failLabels()`, `trustState()` and a new `not_enough_labels` trust state.

## Technical details

In `JudgeValidator::validate()`, a labeled row with a NULL `graderScore` now increments `$notScored` and is skipped before TP/FP/FN/TN. The correlation and calibration arrays already skipped NULL scores. `RepeatedVerdicts::group()` now records verdicts only for scored repeats, so an item with no scored repeat has an empty verdict list. The error profile, stability and judge comparison skip those items, and the comparison reports them as not scored (`notScoredA`/`notScoredB` on `JudgeComparisonResult`).

`JudgeValidationReport::trustBlocker()` returns the first blocker in order: `BLOCKER_NOT_SCORED` (any `notScored > 0`), `BLOCKER_FEW_LABELS` (fewer than `MIN_LABELS_PER_CLASS` = 10 distinct scored pass or fail items), then `BLOCKER_RATES` (TPR or TNR under 0.90). `isTrusted()` is now true only when there is no blocker. The `not_scored`, `pass_items`, `fail_items` and `endpoint_only` values are stored on `ai_eval_judge_validation`, NULL meaning not recorded for older rows. `drush ai-eval:validate-judge` prints a specific warning for each blocker and exits 3 when the fixture has too few labels.

The commit also bundles other changes tracked in separate issues, listed in the CHANGELOG: the corrected pass rate requires validation at the run's threshold ([#3594814](https://www.drupal.org/node/3594814)), the label minimum ([#3594813](https://www.drupal.org/node/3594813)), stale trust after a prompt edit ([#3594812](https://www.drupal.org/node/3594812)), fence-tag escaping ([#3594817](https://www.drupal.org/node/3594817)) and `%` handling in prompt templates ([#3594815](https://www.drupal.org/node/3594815)). Scores are now compared with `ScoreScale::passes()` so validation and run scoring use the same two-decimal rounding.

## Upgrade

Run database updates (`ai_eval_update_10050`). Existing validation rows get NULL for the new columns. Validate again any judge that had provider errors.

Custom code that constructs `JudgeValidationReport` can pass the new optional trailing arguments `$notScored`, `$passItems`, `$failItems` and `$endpointOnly`. Custom implementations or mocks of `JudgeValidationStoreInterface` (four new methods), `JudgeGateTrustInterface` and `CorrectedPassRateInterface` (new `thresholdMismatch()`) must add them. A CI gate on the exit code of `drush ai-eval:validate-judge` can start failing with code 3 if the fixture has fewer than 10 distinct scored pass or fail items.
