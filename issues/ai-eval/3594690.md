# #3594690: Artifact source plugins expose capabilities for read/write/promote/versioning

- **Project:** Drupal AI

## Summary

AI Eval dataset sources (file, config, entity) now say what they can do. File and config sources are read-only. The entity source can also be written to and can take promoted traces and annotations. Writing and promotion go only to sources that support them, and existing file-based datasets keep working as before. The issue's wider capability list (`listable`, `versioned`, `remote`, `validates_schema`) is not in the code I read. Neither is a capability-driven source picker.

## Impact

Affects module maintainers.

- **API change:** Custom dataset source plugins must provide `capabilities()`. Extending `DatasetSourceBase` gives them `['read']` by default.
- **New API:** `DatasetSourceInterface::capabilities()` returns capability tokens (`read`, `write`, `promote`), and a new `WritableDatasetSourceInterface` adds `appendQuestions()` and `createDataset()`.

## Technical details

The change was found by reading the current `ai_eval` main branch, not a fix diff, because the issue had no linked diff and no comments. The code comments reference [#3586840](https://www.drupal.org/node/3586840) and [#3594690](https://www.drupal.org/node/3594690).

`DatasetSourceInterface` declares `capabilities(): array`, which always contains `read`. `DatasetSourceBase` implements it as `['read']`, so `FileSource` and `ConfigSource` inherit read-only. `EntitySource` returns `['read', 'write', 'promote']`.

Write support is a separate `WritableDatasetSourceInterface`, which extends `DatasetSourceInterface`. It adds `appendQuestions(string $ref, array $questions)` and `createDataset(string $label, string $origin = 'manual')`. `appendQuestions()` validates every question against the dataset JSON Schema before persisting anything, and it persists none if any question fails. The interface docs say to use `instanceof WritableDatasetSourceInterface` for type safety and `capabilities()` for UI introspection.

In the code I read, the enforcement paths `PromotionService::writableSource()`, `GenerationRunner` and `GenerationController::isWritableDataset()` check `instanceof WritableDatasetSourceInterface`, not `capabilities()`. `WritableSeamTest::testWriteCapabilityMatrix` checks that only `entity` advertises `write` and that `write` implies the interface. I did not verify that any UI code calls `capabilities()`.

## Upgrade

A custom dataset source that extends `DatasetSourceBase` needs no change and reports `['read']`. A source that should accept writes must implement `WritableDatasetSourceInterface` and override `capabilities()`, as `EntitySource` does:

```php
public function capabilities(): array {
  return ['read', 'write', 'promote'];
}
```
