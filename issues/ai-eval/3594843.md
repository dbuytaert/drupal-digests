## Summary

On the judge gold labeling screen and the blind re-label screen, saving a verdict used to leave the card in place. The list order then shifted, so Next skipped one answer and a reviewer missed every second item. Both screens now keep one stable order, and saving a verdict moves on to the next item. A **Next unlabeled** button takes a returning reviewer to the first item they have not labeled. At the end of the pass the screen shows **Pass complete**. The re-label screen keeps the order of the first-pass label ids and still hides earlier verdicts. The gold screen no longer lists unlabeled answers first. The commit that fixed this also shipped three neighboring changes ([#3594842](https://www.drupal.org/node/3594842), [#3594844](https://www.drupal.org/node/3594844), [#3594845](https://www.drupal.org/node/3594845)). They are summarized below.

## Impact

Affects module maintainers.

- **New API:** `ReviewController::saveLabel()` accepts a local `next` path and answers with `HX-Location` (or `HX-Trigger: ai-eval-gold-saved` at the last item). `TraceBrowser::finalAnswerIds()`, `TraceBrowser::isFinalAnswer()`, `HumanLabelSourceInterface::nonFinalLabelCount()`, `JudgeValidationRunnerInterface::activeRunFor()` and `cancelValidation()` were added.

## Technical details

The old index-based URL pointed into a list that changed on save. `GoldLabelController::build()` used `orderedIds(..., unlabeledFirst: TRUE)`. `relabel()` joined pending items ahead of done ones. Now `build()` uses the new `TraceBrowser::finalAnswerIds()` in source order, and `relabel()` uses the pool as stored (round-1 label id order). Pending and done are only used for progress and for finding the next item. The new private `passNavigation()` builds the `nav`, the **Next unlabeled** link (htmx `hx-get` into `#ai-eval-gold-frame`), and the completion message. It also puts a hidden `next` input on the verdict form through the `advance_after_save` and `next_url` card context.

`ReviewController::saveLabel()` validates `next` as a string and a local path. It returns 400 for values starting with `//`, containing a backslash or control and space characters, or not starting with `/`. When a verdict is posted with `next`, it replies with an empty 200 and an `HX-Location` JSON header targeting `#ai-eval-gold-frame`. An empty `next` (the last item) replies with `HX-Trigger: ai-eval-gold-saved` and `HX-Reswap: none`, and the frame refreshes itself. A note-only save without a verdict does not advance. `js/review-keys.js` no longer clicks Next after a keyboard save when the form has a `next` input, since that would race the server redirect. The gold nav links also gain `data-review-nav` attributes.

On the gold screen, every verdict including Defer advances to the next item that has no label, wrapping around. It skips the current item and deferred items. The screen adds a **Deferred: N** count, a completion message and a **Review deferred answers** link ([#3594844](https://www.drupal.org/node/3594844)).

The same commit changes what counts as gold data ([#3594842](https://www.drupal.org/node/3594842)). Only traces with non-empty reply text and no response tool calls are used. `finalAnswerIds()` filters before filling the 200-answer window. `GoldSetAgreement::domainScope()` and coverage use the same rule. `HumanLabelSource` skips non-final labels in validation, keeps them in storage, and reports the count through `nonFinalLabelCount()` on the judge page.

It also lets the judge page resume validation ([#3594845](https://www.drupal.org/node/3594845)). `JudgeValidationRunner::activeRunFor()` finds the newest open non-empty run, and the page shows its progress instead of the launch form. A stale launch POST rejoins that run. `cancelValidation()` is exposed as `action=cancel` on the progress POST, which sends `HX-Refresh` when the run is canceled. It refuses if a step lock is held or the last score is already stored. `stepValidation()` now re-reads the run after taking the lock.
