## Summary

An AI Answers test can now ask a real follow-up question. Before, every question started a new AI Answers conversation, so a follow-up such as "Which courses does it include?" reached AI Answers without the earlier answer to refer to. A question can now set `metadata.follow_up_of` to the id of an earlier question. It is asked as the next turn of that question's conversation and graded as its own result. The result records `follow_up_of` and the `turn` number, and judges see the earlier questions and answers. A follow-up is skipped, with the reason on its result, when the question it follows is not in the run (for example with `--question` or `--split`), comes later in the dataset, failed, was skipped, or ran as another user. It is also skipped on engines that cannot continue a conversation, and on chat and agent targets. If you split a dataset with a hash rule, give every question in a chain the same `split` label, or the follow-up may be skipped.

## Impact

Affects module maintainers and site owners.

- **Config change:** Datasets accept a new optional `metadata.follow_up_of` string, added to `schema/dataset.schema.json`.
- **New API:** New `WorkflowFollowUpInterface::releaseRun()` for workflow runners that can continue a conversation, plus `continueRunId` and `keepOpen` on `WorkflowRunOptions`.

## Technical details

`AnswerClientInterface::answer()` takes a new optional `$conversationId` and passes it to AI Answers' `AnswerService`. `AnswerResult` gains a `turn` property. In `AiAnswersWorkflowRunner`, `WorkflowRunOptions::$continueRunId` selects the conversation to continue. `WorkflowRunOptions::$keepOpen` is TRUE while a later question of the run follows this one, and it stops the runner deleting the conversation after the answer. A failed follow-up keeps the conversation id as its run id.

On a follow-up, the `retrieve` step is recorded as `skipped` ("follow-up: AI Answers does not search before the agent"), and the `generate` step is labeled `Answer, turn N` for turns after the first. The new `WorkflowFollowUpInterface` has one method, `releaseRun()`. The eval runner calls it after the last question of a chain, whether that question answered, failed or was skipped, so a conversation kept open for a follow-up that never ran is not left behind. It honors `keep_conversation`. Only runners that implement the interface receive follow-ups. The `src/Service/EvalRunner.php` changes that do the ordering and skip checks were not in the diff I could read, so the details of how the runner builds the judge transcript are not covered here.

The docs and tests describe these rules: a chain is linear, so two questions cannot follow the same question. The follow-up's `input` must be a string, not a message list. The question cannot follow itself. A run that is cancelled between two questions of a chain leaves the conversation stored until AI Answers' `conversation_ttl` expires it. The dataset schema adds `metadata.follow_up_of` as a non-empty string.

## Upgrade

To ask a follow-up, name the earlier question in `metadata.follow_up_of` (from the docs):

```yaml
questions:
  - id: q_entry
    input: "What are the entry requirements for the Marine Resource Management program?"
  - id: q_courses
    input: "Which courses does it include?"
    metadata:
      follow_up_of: q_entry
```

Custom workflow runners can implement `Drupal\ai_eval\Workflow\WorkflowFollowUpInterface` to receive follow-ups. Other runners skip them.
