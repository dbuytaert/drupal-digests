## Summary

Decision recording no longer skips questions that mix Latin or digit text with Chinese, Japanese or Thai wording just because a short state value such as `no` or `1` appears inside a longer word like `notice` or `12`. Sites with mixed-language questions now record more decisions for calibration. The same commit also fixes [#3594830](https://www.drupal.org/node/3594830): a calibration fitted on the Answer file tab without a name is now named after the selected rubric question or the typed question wording, shortened as on the other tabs.

## Impact

No upgrade or configuration changes required.

## Technical details

In `DecisionRecorder::containsAny()` the old code switched the whole text to plain substring matching (`mb_stripos`) as soon as it contained any character from the scripts written without spaces. That branch is removed. Matching is now decided per needle: a short (fewer than 4 characters) Latin or digit value still gets word boundary lookarounds, but each lookaround is widened to also accept a neighbouring character from `\p{Han}\p{Hiragana}\p{Katakana}\p{Thai}\p{Lao}\p{Khmer}\p{Myanmar}\p{Tibetan}`. So `no` matches in `東京no` and `no東京`, but not in `notice` or `東京_no`. Values written in those scripts keep substring matching. The script list is now a shared `$unseparatedScripts` string. Cases were added to `DecisionRecorderStateValueTest`.

In `CalibrationFitForm`, validation now stores the rubric question (or typed `instructions`) as a temporary value `question`. On submit, an empty or whitespace only `label` is replaced with that question, trimmed and cut with `Unicode::truncate(..., 200, TRUE, TRUE)`. An explicitly typed name still wins. Existing calibration names are unchanged, and older unnamed Answer file calibrations still show the model id. `CalibrationFitFormSubmitTest::testAnswerImportName` covers both question sources. The changelog and docs are updated.
