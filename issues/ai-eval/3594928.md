## Summary

Cancel on the run box, the question generation box and the judge validation box now takes effect while a step is in progress. Before, a click during an open progress request was silently dropped and the run continued to the end. A finished run now reports its counts, for example "Run complete. 28 questions, 28 errors", instead of a fixed "Run complete · 100%". If every question failed it says "All 28 questions failed" and shows the most common error. The same commit also makes imported results use their own maximum score as the scale on the results list and trend bars, shows the imported model and a read-only table of result items, and collapses saved guided test examples into short summaries ([#3594927](https://www.drupal.org/node/3594927), [#3594863](https://www.drupal.org/node/3594863)).

## Impact

No upgrade or configuration changes required.

## Technical details

The progress box polls with `hx-sync="this:drop"`, and the Cancel button inherited it, so htmx dropped the click while a progress request was open. The Cancel button in `RunFragment::active()`, `GenerationFragment` and the `ValidationFragment` form now has its own `hx-sync="closest .ai-eval-run:replace"` (or `.ai-eval-gen`, `.ai-eval-validate`), which aborts the open progress request. The issue proposed `queue all`, but the shipped markup uses `:replace`. To make aborting safe, `GenerationRunner::cancelGeneration()` and `JudgeValidationRunner::cancelValidation()` no longer take the step lock. They rely on step writes requiring an active status, so a late reply cannot advance a cancelled job. The "step is still finishing, try Cancel again" notices are removed. `GenerationController` now returns `GenerationFragment::cancelled()` if a cancel landed during its step. Validation still refuses to cancel once `completed >= total` and lets the next poll finalize the report.

`RunFragment::complete()` builds its label from `total` and `error_count`. `EvalRunner::runState()` adds a `common_error` key for complete runs where `error_count === total`. It takes the most frequent `error_detail` (falling back to `error`) from the run's `scores_json`. On the target workflow hub, `RunController::completeResponse()` puts the same summary in the status message shown after the redirect.

For imports, `EvalResultsController::ceilingForRow()` reads `config_json['import']['score_max']` and falls back to the recorded native ceiling. It replaces the hardcoded `/ 5` in the trend bars, and `noLlmJudgeScored()` now treats imports as having no native judge. Imported detail pages render `importedResultsTable()` from `envelope['evaluation_results']` instead of the annotation questions table. Guided examples render as `<details class="ai-eval-guided-example">` rows, with scoped `examples[N][...]` field names normalized back in the JS `htmx:configRequest` handler.
