# #3594778: Dataset Save drops an open question editor without a warning

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594778](https://git.drupalcode.org/project/ai_eval/-/work_items/3594778) · 1 contributor · 2 comments

## Summary

On a dataset's edit page, pressing the dataset's Save while a question editor was open and unsaved used to discard the question with no warning. Now the dataset's Save is stopped and the editor shows "Save or cancel this question first. The dataset's Save does not save it." Closing or leaving the page with unsaved question edits also asks for confirmation. The question's own Save is still what stores the question.

## Impact

No upgrade or configuration changes required.

## Technical details

The question editor is its own htmx form inside the dataset form, so the dataset form's Save never submitted it. The fix is client-side, in `js/dataset-csrf.js`. Any `input` event inside `form.ai-eval-q-editor` sets a `data-ai-eval-unsaved` attribute on the editor. A capture-phase click handler sets it too when a repeater row is added or removed (`.ai-eval-rep-add`, `.ai-eval-rep-remove`), because those fire no input event. An editor the server returns with `.ai-eval-q-errors` is also marked unsaved. The editor's own Save or Cancel swaps or removes it, which clears the mark.

While an editor is marked, a capture-phase `submit` listener cancels submission of any other form (the dataset Save) and shows a `messages--warning` block in the editor. An `htmx:confirm` and `htmx:beforeRequest` guard does the same for requests whose target contains the editor but which come from outside it: Add question and the move and delete buttons on other questions, which redraw the whole list. A `beforeunload` handler asks before leaving the page. The issue offered two options, saving open editors with the dataset or warning. The landed change takes the warning route. It landed in a larger Sprint 7 commit (8c8f8cd), documented in `CHANGELOG.md` and `docs/user/usage/datasets.md`.
