## Summary

Saving some sample-size settings (confidence of 0 or 1, margin of error of 0) could cause 500 errors on the result detail page, the test dashboard and `drush ai-eval:run`. The settings form now offers only 90%, 95% and 99% confidence, and requires a margin of error above 0 and at most 0.5. A database update repairs bad saved values. The site judge model is no longer required, so sites that use only deterministic checks, or a model on each judge, can save settings without choosing one. The status report now warns, rather than errors, and only when a test uses an LLM judge that has no model of its own and no site judge to fall back to.

## Impact

Affects site owners.

- **Database update:** `ai_eval_update_10057()` repairs invalid `cochran_confidence` and `cochran_margin_of_error` values in `ai_eval.settings` and reports what it changed.
- **Config change:** `cochran_confidence` is now limited to 0.90, 0.95 or 0.99 and `cochran_margin_of_error` to above 0 and at most 0.5; update 10057 rewrites invalid saved values to 0.95 and 0.05.

## Technical details

`SampleSize::normalizeTarget()` is a new static method that maps an unsupported confidence to 0.95 and a margin outside (0, 0.5] (or non-finite) to 0.05. It is used by `EvalSettingsForm`, `PowerAdvisory` and `EvalRunCommand`, so values that bypass the form (`drush cset`, config import) no longer reach `assertValidTarget()` and throw. Previously `zScoreFor()` silently used 0.95 for unknown confidence while drush printed the saved value; normalizing up front removes that mismatch.

In `EvalSettingsForm`, `cochran_confidence` is a select with options `0.9`, `0.95`, `0.99`; `cochran_margin_of_error` has `#min` 0.01 plus a `validateForm()` check. `judge_provider_model` is no longer `#required`. The textfield validation now splits on `__` and rejects an empty provider or model part, like the proposer field. Saved models that the provider no longer lists are kept selectable in the select.

`AiEvalRequirements` now loops over `ai_eval_target` entities and their LLM graders, and resolves each effective model with `JudgeConfigStore::resolveEffectiveJudgeModel()`. It returns a warning listing judges without a model, or "Not needed" when none are missing. `decision_rubric` never uses the site judge, so its message points to the judge's Edit prompt tab. `ai_eval_update_10057()` applies `normalizeTarget()` to saved config.

The commit also bundles fixes for sibling issues [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926) (new permission, results path guard, `scored_count` column and others); those are separate and not covered here.

## Upgrade

Run database updates. `ai_eval_update_10057()` changes saved `cochran_confidence` to 0.95 if it is not 0.90, 0.95 or 0.99, and `cochran_margin_of_error` to 0.05 if it is not above 0 and at most 0.5. It prints the settings it changed. Config set by `drush cset` or import is also handled at runtime by `SampleSize::normalizeTarget()`.
