## Summary

Re-grading a results file that has no settings snapshot no longer causes the new result to lose its recorded settings. The answer settings (mode, provider, model, agent and similar) are now stored as unknown instead of being removed or replaced by the site's current settings. Result export and the Compare page no longer treat them as if they matched the live configuration. Existing re-grade rows made from such files, and re-grades of those, are repaired by a database update, so run updates after upgrading.

## Impact

Affects site owners.

- **Database update:** `ai_eval_update_10055()` sets the answer keys to NULL and `regrade.answers_unrecorded` to TRUE on stored re-grade rows whose answer settings were never recorded, including re-grades of such rows.

## Technical details

`ResultRegrader::regrade()` used to `unset()` answer keys the earlier run did not have. `ResultEnvelopeBuilder::decodeValidatedSnapshot()` requires those keys (`SNAPSHOT_REQUIRED_KEYS`) and returned NULL, so all of the snapshot was ignored. Now `ANSWER_KEYS` (made `public const`) are always written, with NULL when the earlier snapshot lacks them, and `regrade.answers_unrecorded` is set to TRUE when the earlier snapshot is empty, already carries `answers_unrecorded`, or has no `mode`. That flag therefore carries forward through a re-grade of a re-grade. The re-grade row also now stores `scored_count`.

Readers were changed to treat NULL as unknown rather than falling back to live values. `ResultEnvelopeBuilder` reads `mode`, `provider_id`, `model_id` and `agent_id` from the snapshot when one decoded, or from the live config only when there is no snapshot, and no longer uses `??` chains across both. `RunComparability::compare()` returns `inspection_only` when either side has `answers_unrecorded` or lacks `mode`, so two unknown values are never equal. `EvalResultsController::targetModelCell()` shows "Not recorded" in the same cases.

`ai_eval_update_10055()` is a batched update. It first walks all rows with `source = regrade`, follows `regrade.from.result_id` to a fixed point so descendants of flagged rows are flagged too (including children with lower ids), then rewrites `config_json` for the flagged rows. It adds the missing answer keys as NULL, using a frozen key list, and sets `answers_unrecorded`. The commit also bundles many unrelated review fixes ([#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926)); only the re-grade part is described here.

## Upgrade

Run database updates (`drush updatedb`). `ai_eval_update_10055()` repairs stored re-grade rows. Code that reads a result snapshot should treat a NULL answer setting, or `regrade.answers_unrecorded`, as unknown and not fall back to the live value with `??`.
