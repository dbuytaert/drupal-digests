# #3594805: Eval Commons schemas are out of date with the 1.1.x targets

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594805](https://git.drupalcode.org/project/ai_eval/-/work_items/3594805) · 1 contributor · 4 comments

## Summary

The ai_eval portable schemas (Eval Commons) now match what the 1.1.x targets actually do. Exported workflow runs get a real identity instead of `unknown`, and the schema URLs no longer point at a non-existent 1.0.x branch. A new decision rubric schema is added, and the schema README and examples are brought up to date. The five Northmoor sample datasets already validated and still do. The old schemas and 404 URLs stay on `main` until 1.1.x merges back.

## Impact

Affects module maintainers.

- **API change:** Exported workflow runs are now identified as `drupal-workflow/<engine>/<workflow_id>` in `model_info` and `evaluation_id`; schema `$id` URLs moved from `raw/1.0.x/` to `raw/1.1.0-alpha1/`.
- **New API:** New `schema/decision_rubric.schema.json` for the portable decision rubric; a rubric judge declaration may omit `model_id` to use the site judge model.

## Technical details

In `ResultEnvelopeBuilder`, a workflow-mode run now reads `workflow_engine`, `workflow_id`, `workflow_snapshot` and `workflow_output_path` from the run snapshot, falling back to the run config. When engine and id are set, `model_info` is `drupal-workflow/<engine>/<workflow_id>` and `evaluation_id` is built from it. Rows recorded before this change have no workflow keys, so they fall through to the previous agent-id branch and keep their original `evaluation_id`. The issue also says the recorded workflow now runs on every step of a stepped run. I did not verify that part in the diff.

Schema changes: `dataset.schema.json` descriptions are corrected for multi-turn, `caller_uid` (also the account a workflow runs as), `user_name` and inputs. Expected outputs for automator and taxonomy targets are documented as `expected.<name>`, checked with `target_match`. Per the issue, `expected.items` ids must name a datasource, so bare ids like `108` are rejected (new invalid example `dataset-retrieval-items-bare-id.yaml`). `decision_rubric.schema.json` is new: it requires `question` and `rules`, and describes the grader as scoring 0 to 100, counting at most two errors per rule.

`$id` values now name the release that ships the file (`raw/1.1.0-alpha1/`), and editor headers name the branch (`raw/1.1.x/`). The issue says a test keeps `$id` off branch names. `schema/README.md` and the docs are rewritten to list all four schemas plus the new one, which check kinds have executors, the runtime validation, and the targets with the fields they read. New valid and invalid examples cover automator fields, taxonomy labels, the decision rubric, and failure taxonomy modes.

## Upgrade

If you copy the schemas or use editor headers in your own dataset or rubric YAML files, point them at the new URLs (`raw/1.1.x/schema/...` for editor headers). Any bare retrieval ids in `expected.items` need to be changed to ids that name a datasource. Consumers that match on exported workflow `model_info` or `evaluation_id` will see `drupal-workflow/<engine>/<workflow_id>` for new runs instead of `unknown`.
