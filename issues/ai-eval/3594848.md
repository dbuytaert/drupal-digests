## Summary

On the guided test form and the classic target form, changing the Gate metric now updates the Gate threshold in the browser. Switching from Average score to Pass rate turns the default 4.0 into 0.8, so saving no longer fails with the "cannot exceed 100%" error. A custom value that fits the new scale is kept. The same commit also makes other wording and form fixes. The rubric editor gets an Add phrase button, and pressing Enter in a rubric text input no longer saves the rubric. Dataset question row buttons get accessible names that include the question id. Counts in many admin, report and Drush messages now use singular forms ("1 answer", "1 test"). Entity types and bundles in automator options and recorded answers show human labels. When no chat models are listed, the model field now has an explanation and a link to the AI provider settings. The trace-limit wording now says the 1024 character default can be changed by the site.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** The rubric check row now has an `Add phrase` button in place of the always-present blank phrase input. The dataset question row buttons gain `aria-label` and `title` text that includes the question id.
- **New API:** `GateMetric::browserSettings()` returns each metric's default threshold and maximum, and is passed to the browser as `drupalSettings.aiEval.gateMetrics`. A new route `ai_eval.rubric.phrase_row` returns one blank phrase input.

## Technical details

The threshold fix is a new `js/gate-threshold.js`, attached through the `admin` library with `core/drupal`, `core/drupalSettings` and `core/once` as dependencies. It adds `Drupal.behaviors.aiEvalGateThreshold` on `select[name="metric"]`. On change it sets the new metric's default when the threshold is empty, equals the previous metric's default, or is above the new metric's max. Otherwise it keeps the value. The numbers come from the new `GateMetric::browserSettings()`, so `GateMetric` stays the single source of truth. Both `GuidedTestForm` and `EvalTargetForm` attach it as `drupalSettings.aiEval.gateMetrics`. Server-side validation on save is unchanged and still guards the no-JavaScript case. The stale "no live metric switch" comment in `EvalTargetForm` was trimmed.

Rubric editor: a capture-phase `keydown` handler in the rubric editor script handles Enter in `.ai-eval-rubric-editor input[type="text"]`. It calls `preventDefault()`. In a phrase field with text it clicks the `.ai-eval-phrase-add` button and moves focus to the new input after `htmx:afterSettle`. The phrase button does an htmx GET to the new `RubricController::phraseRow()` (route `ai_eval.rubric.phrase_row`, `/admin/config/ai/ai-eval/rubrics/phrase-row/{index}`, requires `administer ai eval`). It appends an input named `check_values[index][]`.

Other changes: `ProviderModelOptionsTrait` gains `noChatModelsNotice()` and `manualModelDescription()`, and `EvalTargetForm` and `GuidedTestForm` now use the trait. A new `EntityLabels` helper resolves entity type and bundle labels, falling back to the stored id if the definition is gone. In `DecisionReviewForm`, the "stopped at N answers" notice is shown only when the recorded count equals the limit. Plurals use `formatPlural()`, `PluralTranslatableMarkup`, or a count conditional in Drush and report text. The diff was returned only in part (43 of 58 files), so some test files were not reviewed.
