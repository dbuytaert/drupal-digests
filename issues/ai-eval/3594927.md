## Summary

Imported evaluation results now display correctly on the results pages. The results list and the trend bars use the imported file's own maximum score, so a 1.0 out of 1.0 import shows a full bar instead of a short red one. The detail page shows the model named in the imported file, lists the file's result items in a read-only table, and no longer warns about a judge that did not take part in the run.

## Impact

No upgrade or configuration changes required.

## Technical details

A new private helper `EvalResultsController::ceilingForRow()` returns `config_json.import.score_max` when it is numeric and above 0, otherwise falls back to `ceilingForScoresJson()`. `list()` and `detail()` both use it, replacing the inline `$importCeiling` logic in `detail()`. Trend bars previously used a hard-coded `/ 5`; they now load `config_json` and `scores_json` for only the five visible history rows per test, in one query keyed by `id`, and scale by the row's ceiling.

On `detail()`, the "Model under test" cell shows `model_info.id` or else `model_info.name` from `config_json.envelope`, with "(from the imported file)". It keeps "Not reported (imported)" when neither is present. For imports, the questions table is replaced by `importedResultsTable()`, which lists each `evaluation_results` item: `evaluation_name`, a metric name (from `metric_name`, `metric_id` or `evaluation_description`), the score with its `min_score` to `max_score` scale, and `score_details.details` as pretty-printed JSON. File content is output through `#plain_text` or an `inline_template` context, so it is escaped. An empty envelope shows "The imported file has no result items."

`noLlmJudgeScored()` now returns TRUE for a row with no snapshot when `config_json.import` is present, so `judgeTargetFamilyAdvisoryForRow()` returns early and the site judge is never used as a stand-in for an imported run.
