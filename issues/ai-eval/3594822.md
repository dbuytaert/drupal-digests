# #3594822: Failure mode rates count each reviewer's annotation of the same question

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594822](https://git.drupalcode.org/project/ai_eval/-/work_items/3594822) · 1 contributor · 3 comments

## Summary

Failure mode counts and rates for a result or test now count each reviewed question once. Before, if two reviewers annotated the same question, its failure mode was counted twice and the total grew by two. Now only the earliest annotation for each question counts. On sites with more than one reviewer per question, counts and percentages in the failure modes table will change. The user docs now define Count as questions whose counted annotation carries that mode.

## Impact

Affects module maintainers.

- **New API:** New public static `AnnotationStore::joinCanonical()` limits an annotation query to the earliest row per (result_id, question_id).

## Technical details

`FailureRateService::aggregate()` ran `COUNT(*)` over every annotation row in scope, which `ratesForResult()` and `ratesForTarget()` both use. It now calls a new static helper, `AnnotationStore::joinCanonical()`, before the `GROUP BY failure_mode`. The helper is the SQL form of `AnnotationStore::canonical()`. It joins a subquery that takes `MIN(id)` per (`result_id`, `question_id`) over the whole annotation table. The service filters on that join, so the earliest annotation per question is the one counted.

The earliest row is chosen across the whole table, not only the filtered rows. A condition added by the caller, such as the `ratesForTarget()` time window (`$sinceTimestamp`), therefore filters out the counted row. It does not promote a later reviewer's row. The total used for rates is now the number of annotated questions in the scope. This matches the rule judge validation and calibration already use, and the reviewed-traces rates, which already kept one earliest label per conversation.
