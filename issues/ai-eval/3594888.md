## Summary

The trace review filter in AI Eval now groups tags by the part before the first colon (for example `feedback:negative` goes under "feedback"; tags without a colon go under "Other"). Ticks inside a group are OR, and different groups are AND, so you can ask for "thumbs down AND not yet labeled" or "this agent AND no answer". Three non-tag filters were added: Source (AI Answers or Imported), Visitor "not rated" (no `feedback:` tag), and Verdict (unlabeled, pass, fail, deferred). The whole filter now travels in the URL through the list, pager, group links, previous/next and saving a verdict, so a filtered queue can be bookmarked or shared. The failure rates on the review page use the same filter. Group cards and trace cards also show thumbs up/down badges for visitor feedback.

## Impact

Affects module maintainers and site owners.

- **Config change:** New query parameters on the trace review pages: `source[]`, `verdict[]`, `not_rated`, alongside `from`, `to` and `tags[]`.
- **New API:** `GroupedTraceSourceInterface` gains `availableTagGroups()` and `hasFeedbackTags()`; new `TraceFilter` service class with `groupTags()` and `apply()`; `TraceSourceInterface` filters accept `source`, `not_rated` and `verdict`.

## Technical details

The filter logic is centralized in a new `Drupal\ai_eval\Service\TraceFilter`. `groupTags()` splits on the first colon (unprefixed goes to `other`). `apply()` adds `from`/`to` bounds, a `source` condition on `t.span_id LIKE 'ai_answers:%'` (selecting both sources adds no constraint), one correlated `EXISTS` on `ai_eval_trace_tag` per tag group (OR inside via `IN`, AND between groups), and a `verdict` condition. `not_rated` is OR-ed with any selected `feedback:*` tags instead of being AND-ed, since it could never match them otherwise. The verdict filter matches the group verdict shown on the card: the earliest group-scope row in `ai_eval_review_label` (`MIN(id)`) keyed by `TraceFilter::GROUP_KEY_EXPRESSION`; `unlabeled` means no group-scope label exists.

`TraceSourceInterface` documents the new `source`, `not_rated` and `verdict` keys. `GroupedTraceSourceInterface` adds `availableTagGroups()` and `hasFeedbackTags()`. The DB trace source's `groupKeysWithTags()` became `groupKeysWithFilters()`, which uses `TraceFilter`. `TraceReviewController::filtersFromRequest()` validates `source`, `verdict` (including `defer`) and `not_rated` against allow lists. A new `filterQuery()` serializes the full state into the list, pager, `groupUrl()`, back link and the verdict save URL. `groupNeighbors()` is computed before saving a verdict so prev/next stays based on the pre-save filtered set. `ratesForReviewedTraces()` is now called with the full `$filters` array instead of just the tags.

The landing route now returns only the `#ai-eval-review-landing` container as an htmx fragment (`HX-Request: true`), so filter bar, group list and rates swap together. The filter bar and pager target this container. The filter bar is rebuilt as grouped fieldsets with friendly tag labels, and a collapsible "Other tags" section when it has more than 8 tags. CSS and a spelling dictionary were updated.

## Upgrade

Custom implementations of `GroupedTraceSourceInterface` need the two new methods:

```php
public function availableTagGroups(): array;
public function hasFeedbackTags(): bool;
```

Code calling `ratesForReviewedTraces()` with a tag list should pass a filters array instead, e.g. `['tags' => $tags]`, as `TraceReviewController::landing()` now passes `$filters`.
