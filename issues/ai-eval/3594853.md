## Summary

Three small gaps in AI Eval are closed. Uninstalling the module no longer follows a symlinked `envelopes` folder and so cannot delete export files from some other directory. Files whose names end in a newline are no longer mistaken for the module's own result and envelope exports and deleted. The escaping of closing prompt tags (`</question>`, `</criteria>`, `</agent_response>`) now also catches forms with whitespace or a non-breaking space around the slash, and no longer rewrites unrelated tags such as `</question-name>`.

## Impact

Affects site owners.

- **Security:** Low-priority hardening: uninstall could delete `.eee.json` files in a folder reached via a symlinked `envelopes` directory; closing prompt fences written with whitespace could escape the `escapePromptValue()` filter.

## Technical details

In `ai_eval_uninstall()` (`ai_eval.install`) the envelopes folder is only scanned when `is_dir()` is true and `is_link()` is false. A symlinked `results_path` itself is still allowed, and a new kernel test covers that. Both cleanup masks now end in `\z` instead of `$`, because PCRE's `$` also matches before a final `\n`.

`LlmJudgeBase::escapePromptValue()` keeps its signature. Its regex now allows whitespace or a UTF-8 NBSP (`\xC2\xA0`) before and after the `/`, and replaces `\b` with `(?![\w:.-])` after the tag name. That means `</question-name>`, `</question:part>` and `</question.x>` stay unchanged, while `< /question>`, `</question/>` and NBSP variants are escaped. The `u` flag is deliberately not used: with invalid UTF-8 `preg_replace()` would return NULL and the `?? $value` fallback would return the text unescaped. A unit test covers an invalid UTF-8 input that still gets escaped. The `CHANGELOG` gets an Unreleased entry. The issue states the same changes are to be backported to 1.0.x, but this commit is on 1.1.x only.
