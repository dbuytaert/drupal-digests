# #3594686: Failure-mode taxonomy artifact for error analysis

## Summary

The AI Eval module now has failure modes: named categories such as "hallucinated_fact" that reviewers use to group the problems they find in open-coding notes. Failure modes are managed under Failure Modes in the AI Eval admin area and can be exported and imported as a shareable, versioned taxonomy. Reviewers can tag an annotation with a failure mode. The UI can then report how often each mode occurs, including an untagged bucket, so the dominant failure modes are visible.

## Impact

Affects module maintainers and site owners.

- **Config change:** New `ai_eval.failure_mode.*` config entities with keys `id`, `label`, `description`, `taxonomy_id`, `weight`, `status`.
- **New API:** New `ai_eval_failure_mode` config entity, `FailureModeTaxonomySerializer` and `FailureTaxonomyValidator` services, `FailureRateService`, and `schema/failure_taxonomy.schema.json`.

## Technical details

`FailureMode` is a config entity (`ai_eval_failure_mode`, config prefix `failure_mode`). It is managed at `/admin/config/ai/ai-eval/failure-modes` and exports `id`, `label`, `description`, `taxonomy_id`, `weight` and `status`. Modes sharing a `taxonomy_id` (default `default`) form one taxonomy. The issue proposed a suggested check or judge prompt seed field, but the entity as it stands has no such field.

`schema/failure_taxonomy.schema.json` is a peer to the dataset schema. It requires `id`, `version` (semver) and `modes`. Each mode needs `id`, `label` and `description`, with an optional integer `weight`, and unknown mode properties are rejected. `FailureModeTaxonomySerializer::export()` produces that shape. Its import upserts modes and never deletes modes missing from the payload. `FailureTaxonomyValidator` checks a serialized taxonomy against the schema using opis `CompliantValidator`, in the same way as `DatasetValidator`.

The `ai_eval_annotation` entity gets a `failure_mode` entity reference field. `FailureRateService` groups annotation rows with a single `GROUP BY` on the base table. It provides rates per eval result (`ratesForResult()`) and per target with an optional time window (`ratesForTarget()`), and a variant over reviewed conversations. Rate is the per-mode count divided by all annotations in scope, and untagged annotations are always included so rates sum to 1.0. This work was merged across several commits, and the trace review linkage landed under [#3594752](https://www.drupal.org/node/3594752). The repository history has no single commit for this issue, so this summary is based on the final code.
