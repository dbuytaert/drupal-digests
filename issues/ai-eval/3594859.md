## Summary

One commit in `ai_eval` 1.1.x fixes eight small UI problems found in a user-guide walkthrough, including [#3594859](https://www.drupal.org/node/3594859). Saving a calibration now says when it replaced an earlier fit that was not active, because that fit is deleted. Results screens show the gate a run actually used, taken from the run's recorded settings. Runs with no recorded gate show "Gate not recorded" in place of an invented 4.0 threshold. Test names appear as labels instead of ids. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred". Annotate progress counts the answers of the latest run. The compare page uses plain labels for differences. The hard and soft gate options now say that the type only changes the exit code of `drush ai-eval:run`. A calibration whose question the decision rubric judge no longer asks now gets a warning that the judge will not apply it.

## Impact

Affects front-end developers and site owners.

- **Config change:** The gate type option labels in the target and guided test forms now describe the `drush ai-eval:run` exit code. The stored values `hard` and `soft` are unchanged.
- **Theme change:** Failure-rate rows are labeled "Passed", "Failed, no failure mode" or "Deferred" instead of "(untagged)". The results, compare and gate-type screens show different text and markup.

## Technical details

The issue's fix is in `CalibrationSaveTrait::saveAndReport()`. It counts the pair's inactive curves via `$this->store->curvesFor()` before saving. After a successful save it adds a separate `formatPlural()` message ("It replaced the earlier fit that was not active." / "It replaced @count earlier fits that were not active."). The message is a warning when the new fit is inactive and a status message otherwise. `CalibrationStore::replace()` and the interface are unchanged. The count is read outside the store's lock, as the issue acknowledges.

The same commit covers the other items:
- `EvalResultsController::recordedGate()` resolves the gate from the run's validated config snapshot (`decodeValidatedSnapshot()`), then falls back to the live target's threshold. If neither exists it returns NULL. The overview and detail pages then drop the threshold and verdict comparison, and the detail page shows "Gate not recorded". The metric is shown through `GateMetric::label()`.
- The results controller now loads the target entities once and adds their cache tags plus `ai_eval_target_list`. Target labels replace ids, with the id kept as a `title` attribute. Judge trust badges use `graderShortLabel()`.
- `ResultsCompareController` gets an optional `graderManager` constructor argument (`ai_eval.grader_manager`). It adds `differenceLabel()` and `readableValue()`, so hashes show as "same", "changed" or "recorded" and grader ids show as labels. Raw values move into a closed "Technical details" `details` element.
- `FailureRateService` now also groups by `verdict`. Rows with no failure mode are labeled by verdict, tagged verdicts are merged back into their mode, and the rates still sum to 1. Each row gains a `verdict` key.
- `WorkflowStateService` computes Annotate progress as canonical annotations on the latest result against its `question_count`. The fixed suggested total of 100 is removed.
- `GateTypeWording` is a new helper shared by `EvalTargetForm` and `GuidedTestForm`. It supplies the gate option labels, a description and the review text.
- `CalibrationFromReviewsForm` compares the group's fingerprint with `currentFingerprint()` to show the warning and a "Yes, but the judge does not ask this question now..." readiness text.
- The docs and CHANGELOG are updated to match.
