## Summary

Agent tests in ai_eval now give config agents the question as separate chat messages with their roles, as the AI Assistant does on the site. Before, the question was flattened into one text and wrapped as a task ("Task Title… Task Description…"), and HTML in it was stripped. Scores for agent tests can change, including for single-turn questions, so thresholds and baselines may need re-checking. Code-defined agents that read only the Task still get the flattened transcript.

## Impact

No upgrade or configuration changes required.

## Technical details

`EvalRunner::invokeAgent()` now takes the normalized `ChatMessage[]` that `runQuestionBody()` already builds, in addition to the flattened transcript. It keeps `setTask(new Task($message))`, because code-defined agents read only the Task, and also calls `setChatInput(new ChatInput($conversationTail))`. Config agents build their history from the chat input, so they get the original turns with roles. The agent's own system prompt, or an optimizer's `agent_prompt_override` candidate, stays in force.

Dataset `system` entries are dropped. The filter was extracted from the chat path into a private `withoutQuestionSystemMessages()` and is shared by chat and agent modes. It logs the drop once, outside the rate-limit retry closure.

A new kernel test, `EvalRunnerAgentChatInputTest`, uses a real config agent with a scripted provider. It covers three-turn roles with the caller prefix, single-turn HTML without a Task wrapper, system-entry removal with the override prompt, and a tool loop that keeps the original turns once. The CHANGELOG gets an "Unreleased / Fixed" entry. `docs/user/usage/datasets.md` and `schema/README.md` no longer say agent mode flattens.

## Upgrade

No code changes are needed. Re-run agent tests and re-baseline scores and thresholds, since input to config agents differs from earlier versions.
