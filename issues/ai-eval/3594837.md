## Summary

When ai_observability stores a chat reply as plain text, the stored string begins with the role label `assistant: `. ai_eval now hides that label when it reads such a reply. The trace review card, the `ai_response` saved on a promoted question, and the examples used for judge validation show `Cold and windy.` instead of `assistant: Cold and windy.`. Stored trace rows are not changed, so old traces read cleanly without an update.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `TracePayloadParser::parseOutput()`, in the branch for output that is not structured chat. If the output starts with exactly `assistant: ` (lowercase, no leading space), one copy of that prefix is removed and the rest is returned as `text`. The `format` is still `plain`. `OtelTraceSource::normalize()` parses the stored `output` on every read, so the clean text reaches `response_text`, the review card, promotion and `HumanLabelSource` without a data migration.

The prefix is kept in some cases. If what follows it would itself count as a bare role label, such as `assistant: ` alone or `assistant: assistant:`, the output is left byte for byte. This means `TraceBrowser::isRoleLabelOnly()` classifies every output as before. A tool-only turn that was stored as `assistant: ` therefore keeps its label and is still refused for promotion, as before. The issue proposed stripping it and relaxing the streamed-uncaptured check, but that check is not in the diff. Other plain text is untouched: other roles, `Assistant:` with a capital, `assistant:` with no space, and embedding output. A trailing `[Files: ...]` suffix is kept. Already promoted questions keep the prefix in their `metadata.ai_response`.

Tests added: unit cases for `parseOutput()`, a kernel test in `PromoteGroupLabelTest` that checks the stored `output` column still holds the prefix, and a calibration test in `HumanLabelSourceTest`. The `CHANGELOG` and the traces user docs are also updated.
