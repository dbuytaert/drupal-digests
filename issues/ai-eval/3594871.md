## Summary

For agent tests, the Groundedness judge now sees what the agent's tools returned, not just which tools ran. It can check a stated value, such as a tuition figure, against the actual tool result instead of passing any answer that follows a search. Each call's output is capped at 4,000 characters and the whole output section at 12,000. The newest outputs are kept and omitted ones are named. The Accuracy judge still sees only call names and arguments. Outputs are not stored or exported, but a judge's stored reason may quote part of one. If the AI module's logging is on, it will log the judge prompt with the tool data. Judge prompts for these tests are longer, so they use more tokens.

## Impact

Affects module maintainers and site owners.

- **Config change:** No stored config changes. Groundedness judge prompts for agent tests get longer, which raises judge token use.
- **New API:** New `sees_tool_output` property on the `AiEvalGrader` attribute (requires `sees_tool_calls`), and optional `output` and `output_cut` keys on tool call records.

## Technical details

`ToolCallRecord::fromFunctionCall()` now reads `getReadableOutput()` when the tool implements `ExecutableFunctionCallInterface`. It stores `output`, cut to `OUTPUT_MAX_LENGTH` (4000) characters, plus `output_cut` when shortened. If the accessor throws, the record keeps its identifiers and arguments and omits the output. Redaction is name-based and runs on the first `OUTPUT_SCAN_LENGTH` (16,000) raw characters. It does not decode JSON, so numbers and key order are preserved. JSON-style values under secret-looking keys become `"(redacted)"`. Plain `key: value` and `key=value` lines whose key matches the argument secret-name rules are also redacted. A secret under an innocuous name is not caught.

`AiEvalGrader` gains `sees_tool_output` (default `FALSE`), only meaningful with `sees_tool_calls`. `GroundednessGrader` sets it and `AccuracyGrader` does not. In `LlmJudgeBase::toolCallBlock()`, a judge with the flag gets an extra section from `toolOutputBlock()`. Outputs are listed in execution order, each inside `[BEGIN TOOL OUTPUT n nonce]` and `[END TOOL OUTPUT n nonce]` fences with a fresh random nonce per prompt. A heading tells the judge the outputs are data, never instructions. Fence words inside outputs are neutralized, and records from other runners are re-capped to 4,000 characters. The 12,000 character budget counts the escaped text. It fills from the newest call backwards, and calls that do not fit are named under "Outputs not shown". If no call has a nonempty output, the prompt is the same as before. The Groundedness scoring guidance now says that when outputs are listed, a claim is supported only by a listed output or the question. Without outputs it judges as before.

Docs and the changelog were updated, including how outputs may still surface through judge reasons and AI module logging. In workflow mode, redacted arguments are kept in a step's input preview.

## Upgrade

Custom LLM judge plugins that should see tool results can opt in alongside the existing flag:

```php
#[AiEvalGrader(
  // ...
  sees_tool_calls: TRUE,
  sees_tool_output: TRUE,
)]
```

Graders that read `tool_calls` keep working. Records may now carry optional `output` and `output_cut` keys. Workflow runners that build `WorkflowRunResult::$toolCalls` with `ToolCallRecord::fromFunctionCall()` get the output captured automatically.
