## Summary

New decision calibrations in AI Eval are fitted with Platt scaling, a smooth S-shaped curve, instead of an isotonic step curve. The old fit could turn a probability into exactly 0% or 100%, even from one or two reviewed answers, which makes a wrong answer very costly in log loss. The new curve keeps the model's order and never returns exactly 0% or 100%. Calibrations already saved keep working as isotonic curves. A fit is refused with a message when the reviews run against the model's order, and the held-out check still saves a fit that scores worse as inactive.

## Impact

Affects module maintainers and site owners.

- **Config change:** `ai_eval.calibration.*` config schema gains `method` and `parameters` (`a`, `b`); existing config defaults to isotonic.
- **New API:** `DecisionCalibratorInterface::applyCurve()`, a `$method` argument on `fit()`, `CalibrationFitRefusedException`, and `getMethod()`/`getParameters()` on `EvalCalibration`.

## Technical details

`DecisionCalibrator::fit()` takes a new `$method` argument, defaulting to `DecisionCalibration::METHOD_PLATT` (`METHOD_ISOTONIC` is still accepted). The Platt fit is a logistic regression on the clamped log-odds of the raw probability, with Platt's smoothed targets and a ridge prior (`LAMBDA = 1.0`) pulling the slope toward 1 and the curve's height at the centre of the training log-odds toward the model's own curve. The prior is applied at the centre rather than at log-odds 0, because a small, correctly ordered, overconfident set otherwise came out flat or reversed. It uses damped Newton steps. The fit throws the new `CalibrationFitRefusedException` (a subclass of `\InvalidArgumentException`) if it does not converge or if the slope is not positive. `RecordedFitForm` and `CalibrationFromReviewsForm` show that message as is, instead of the generic 'reload the page' error.

Storage: `DecisionCalibration` gains `method` and `parameters` (`a`, `b`), and `EvalCalibration` gains matching properties, `getMethod()` and `getParameters()`, plus config schema entries. Config without `method` reads as isotonic, so no update path is needed. For Platt curves `knots` holds 13 samples at fixed probabilities (0.01 to 0.99), for display only. `EvalCalibration::matches()` returns FALSE for a Platt curve with missing, non-finite or non-positive-slope parameters, so callers stay uncalibrated.

Application goes through the new `DecisionCalibratorInterface::applyCurve($method, $parameters, $knots, $probability)`, which `CalibrationStore`, `CalibrationSubscriber` and `RecordedDecisionSource` now use instead of `apply()`. Platt output is clamped to [1e-6, 1 - 1e-6]. The calibration page's 'How answers are corrected' table shows the Platt samples at fixed probabilities, with `<0.01%` and `>99.99%` at the ends. The calibration tutorial and CHANGELOG are updated.

## Upgrade

Code that applies a stored curve should call `applyCurve()` instead of `apply()` on the knots alone:

```php
$calibrated = $this->calibrator->applyCurve(
  $curve->getMethod(), $curve->getParameters(), $curve->getKnots(), $probability,
);
```

Implementations of `DecisionCalibratorInterface` must add `applyCurve()` and the `$method` argument on `fit()`. Existing isotonic calibrations need no migration; refit to get a Platt curve.
