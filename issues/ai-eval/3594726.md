# #3594726: TraceStore::clearBatch() is unreachable, so a trace import cannot be undone

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594726](https://git.drupalcode.org/project/ai_eval/-/work_items/3594726) · 1 contributor · 3 comments

## Summary

A trace import can now be undone. `drush ai-eval:clear-traces <batch>` deletes the traces of one import batch after a confirmation prompt. The Import traces page lists earlier imports, and users with `administer ai eval` get an "Undo this import" link to a confirmation page for each one. Both the Drush import command and the UI import now report the batch id and how to undo it. Each UI import also gets its own batch id, so undoing one import no longer removes other UI imports.

## Impact

Affects module maintainers and site owners.

- **Permission change:** The undo page and the batch list on the import page require `administer ai eval`.
- **New API:** New Drush command `ai-eval:clear-traces <batch>` (alias `aect`), new `TraceStore::batches()`, and new route `ai_eval.trace_import_undo`.

## Technical details

`TraceStore::clearBatch()` already existed but nothing called it. It now runs its two deletes (tags, then traces) in one transaction and rolls back on failure. A new `TraceStore::batches()` returns trace count and latest import time per batch id, newest first. The Drush command (`EvalClearTracesCommand`, alias `aect`, registered in `drush.services.yml`) rejects an unknown batch id and lists the known batches. The confirm form `TraceImportUndoForm` lives at route `ai_eval.trace_import_undo` (`/admin/config/ai/ai-eval/trace-review/import/undo?batch=...`) and requires `administer ai eval`. `TraceImportForm` shows the "Earlier imports" table only to users with that permission.

The UI batch id changed from the fixed `ui-import-upload` or `ui-import-path` to `ui-<source>-<Ymd-His>-<random hex>`, so same-second imports differ. Older fixed ids are still labelled by source in the table. `ai-eval:import-traces` and the batch finish callback print the batch id and the undo command. Users without `administer ai eval` get only the Drush command in the message.

If a span fails part-way, rows written before the failure stay. `TraceImporter::importSpans()` now throws a new `ImportFailedException` carrying the span and imported counts. The Drush and UI paths use it to still name the batch to undo. Undo deletes only traces and tags. Review labels and annotations are kept. Per the docblock, a trace re-imported while the delete runs is a known limit, since no lock is taken. The traces docs page and `CHANGELOG.md` were also updated. I read the change in the squashed commit on the `1.1.x` line, because the issue thread has no comments or linked diff.
