# #3594802: AI Answers runner: record the model calls behind each answer

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3594802](https://git.drupalcode.org/project/ai_eval/-/work_items/3594802) · 1 contributor · 3 comments

## Summary

Results from AI Answers targets in AI Eval now show which provider and model wrote each answer and how many tokens it used. Before this, those results had no model calls, so cost could not be compared with agent or prompt targets on the same questions. The "answered by" check, which flags a provider serving a different model than requested, also never ran for them. Calls are recorded when an answer fails too. Token counts the provider did not report are left unknown.

## Impact

Affects module maintainers.

- **API change:** `AiAnswersWorkflowRunner` has a new third constructor argument, `ModelCallRecorder $modelCalls`, so code that builds it by hand must pass it.
- **New API:** New `ai_eval.model_call_recorder` service (`Drupal\ai_eval\EventSubscriber\ModelCallRecorder`) that collects chat provider calls as `ModelCall` objects between `arm()` and `disarm()`.

## Technical details

The new `ModelCallRecorder` event subscriber is registered as `ai_eval.model_call_recorder`. It listens to the AI module's `PreGenerateResponseEvent`, `PostGenerateResponseEvent` and `AiExceptionEvent`. It tracks attempts by provider request thread id. `disarm()` returns only `chat` operations that reached a provider, as `ModelCall` objects with provider, requested model, resolved model and input, output and cached tokens. `ModelCallRecorder::total()` sums the token counts.

`AiAnswersWorkflowRunner` calls `arm('ai_answers:' . $workflowId)` just before the answer starts and `disarm('generate')` right after it, before anything else can throw. That keeps later judge calls out of the answer's record. If the recorder is already armed, the runner disarms its tool-call recorder and throws `WorkflowLaunchRefusedException`. The recorder also has `suspend()` and `resume()`, which pause recording while a nested question runs. `WorkflowRunResult` now gets `calls`, `inputTokens` and `outputTokens` on success. On a failed run the calls are passed too, with their step execution id cleared to `NULL`.

The same commit (adc7e6c) also covers [#3594693](https://www.drupal.org/node/3594693) and [#3594811](https://www.drupal.org/node/3594811). It adds result-page display of target and judge models and tokens, plus `EvalRunner` and `WorkflowPanel` changes. The issue's own test is `AiAnswersWorkflowRunnerTest`, which runs a fake answer through two model requests.

## Upgrade

Anything that constructs `AiAnswersWorkflowRunner` directly must pass the recorder as a third argument. In `ai_eval_ai_answers.services.yml` the new argument is added to the service definition; custom code needs the equivalent, taking the recorder from the `ai_eval.model_call_recorder` service.
