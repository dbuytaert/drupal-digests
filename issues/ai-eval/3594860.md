## Summary

This commit is a bundle of AI Eval 1.1.x UI fixes. The headline issue, [#3594860](https://www.drupal.org/node/3594860), is the calibration "Fit from reviews" form. A reviewed group fitted on earlier rubric wording used to read a plain "Can fit: Yes", even though the judge would not apply that fit. The cell now says the judge does not ask this question now, and saving such a group shows a warning. The group stays selectable. The same commit also shows the gate a run actually used, or "Gate not recorded", instead of an invented 4.0. It shows test and grader names instead of ids on the results screens. The compare page uses plain-language differences. Failure-rate rows without a failure mode are split into Passed, Failed with no failure mode, and Deferred. The Annotate progress bar counts the answers of the latest run. The hard and soft gate wording now says it only changes the exit code of `drush ai-eval:run`.

## Impact

No upgrade or configuration changes required.

## Technical details

Calibration form: `CalibrationFromReviewsForm::readinessText()` compares the group's fingerprint with `currentFingerprint()` and, for a ready group that differs, returns "Yes, but the judge does not ask this question now, so it will not apply this fit". `submitForm()` adds a warning after a save when the fingerprint differs. The shared `saveAndReport()` is not changed for this. The warning text says the fit can apply again only if the rubric is restored, the fit is active, and it uses the judge's provider and model.

Gate shown for a run: `EvalResultsController::recordedGate()` reads the run's validated config snapshot (metric and threshold) first. It falls back to the live test's threshold, then to NULL. The results list and detail pages no longer default to 4.0. They show "Gate not recorded" on the detail page and omit the threshold comparison in the list. The metric is shown by label, for example "Pass rate", not `pass_rate`. The controller now loads the target entities once, shows the test label with the id as a `title` attribute, adds cache tags, and uses `graderShortLabel()` for judge trust badges. `ResultsCompareController` gets an optional `ai_eval.grader_manager` constructor argument. It maps snapshot keys to labels (`differenceLabel()`), shows hashes only as "same", "changed" or "recorded" (`readableValue()`), and moves raw key and value pairs into a closed "Technical details" element.

Failure rates and Annotate progress: `FailureRateService` now selects `verdict` as well. Rows with a failure mode merge back into one bucket per mode. Rows without a mode are split into "Passed", "Failed, no failure mode", "Deferred" or "No verdict" (replacing `(untagged)`), so the shares still sum to 100%. Each row gains a `verdict` key. `WorkflowStateService` drops the fixed suggested total of 100 annotations. Progress is now the canonical annotation count on the latest result against that result's `question_count`, and the label is "N of M answers labeled". Gate wording is centralized in the new `Drupal\ai_eval\Form\GateTypeWording`, used by `EvalTargetForm` and `GuidedTestForm`. A new message after saving a calibration says when it replaced earlier fits that were not active ([#3594859](https://www.drupal.org/node/3594859)). The commit also updates `CHANGELOG.md` and the user guides.
