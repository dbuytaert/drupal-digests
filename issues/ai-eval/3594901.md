## Summary

Before, if a grader could not be loaded (for example its module was uninstalled, or its plugin threw in its constructor), it was silently left out of scoring. Questions and gates could then pass without that grader's check, even if it was a must-pass grader. Now a run does not start when a grader cannot be loaded, and the error names the grader and the reason. A grader that is not installed gives `Could not load grader "id": it is not installed.` Re-grades (the admin UI and `drush ai-eval:regrade`) stop with the same message.

## Impact

No upgrade or configuration changes required.

## Technical details

`EvalRunner::createGraders()` used to catch `\Throwable`, log it and drop the grader. It now still logs, then throws `RunDatasetException::graderUnavailable()`, a new factory on `RunDatasetException` (the class docblock is widened from dataset-only). That factory gives a short message for `PluginNotFoundException` and otherwise includes the plugin's own exception message.

For browser runs, `doStartRun()` checks `graderManager->hasDefinition()` for each configured grader before the run is created, so a missing grader means no run row and no active run. It checks only that the plugin exists, because graders are instantiated per step as the account that started the run. `stepRun()` now passes `NULL` graders to `runQuestion()`/`runQuestionBody()` (parameter type is now `?array`), which load them lazily. If loading fails there, for example after the grader was removed mid-run, the question gets an error row with `grader_scores` empty, `avg_score` 0.0 and `passed` FALSE, and it counts toward the run's `error_count`. The repeated error-row arrays were extracted into `questionError()`.

`runTarget()`, `startRun()` and `regradeTarget()` (via `EvalRunnerInterface` docblocks) can now throw `RunDatasetException` for this case. `EvalRegradeCommand` and `RegradeForm` catch it next to `\InvalidArgumentException` and show the message. No schema changes. The module docs were updated.

## Upgrade

Code that calls `EvalRunnerInterface::runTarget()`, `startRun()` or `regradeTarget()` should also handle `Drupal\ai_eval\Service\RunDatasetException`, which it now throws when a grader cannot load:

```php
catch (\InvalidArgumentException | RunDatasetException $e) {
  // Show $e->getMessage() as is.
}
```
