## Summary

In the AI Eval dataset question list, the move, edit and delete buttons showed only a glyph. Screen readers could not tell them apart or say which question they acted on. Each button now has a name that includes the question id, such as "Edit question nursing-degree" or "Delete question nursing-degree". Edit and delete also get a tooltip. Nothing changes visually. The same commit ships several related fixes. Pressing Enter in a rubric text field no longer saves the rubric, and check phrases are added with an "Add phrase" button. The gate threshold follows the selected metric. A "No chat models are available" notice now explains the manual `provider__model` entry. Singular and plural wording is corrected in many messages, and admin text shows entity and bundle labels instead of machine names.

## Impact

Affects module maintainers.

- **New API:** New route `ai_eval.rubric.phrase_row` and `GateMetric::browserSettings()` for the new add-phrase row and gate threshold behavior, plus an `EntityLabels` render helper.

## Technical details

The row template in `DatasetQuestionList.php` now gives every button an `aria-label` built with `|t` and `{{ qid }}`. It uses the question's own id, not its row position, so labels stay correct after a move. The glyphs are wrapped in `<span aria-hidden="true">`. The disabled edit button keeps its explanatory `title` and gets the label "Edit question @qid (not available)". The Enable and Disable text and the delete confirm text are now translatable too.

The same commit also covers sibling issues listed in the changelog ([#3594847](https://www.drupal.org/node/3594847) to [#3594852](https://www.drupal.org/node/3594852)):

- **Rubric phrases:** the rubric editor JS intercepts Enter in text inputs inside `.ai-eval-rubric-editor`. In a phrase input, Enter adds another phrase via the new `ai_eval.rubric.phrase_row` route (`RubricController::phraseRow()`) and focuses it. Elsewhere Enter does nothing. Only Save submits.
- **Gate threshold:** new `js/gate-threshold.js` in the `admin` library, fed by `GateMetric::browserSettings()` through `drupalSettings.aiEval.gateMetrics`. When the metric changes, it replaces the threshold if it is empty, equals the previous metric's default, or exceeds the new scale's max.
- **Model fallback notice:** `ProviderModelOptionsTrait` gained `noChatModelsNotice()` and `manualModelDescription()`. They are used by `EvalTargetForm` and `GuidedTestForm`, and the notice is hidden when the model list failed to load and that error was already shown.
- **Plurals and labels:** many strings moved to `formatPlural()` or `PluralTranslatableMarkup`. The new `Drupal\ai_eval\Render\EntityLabels` helper resolves entity type and bundle labels and falls back to the stored id if the definition is gone. The decision review form no longer prints a "stopped at" line when the recorded count exceeds the limit.
