## Summary

Clicking Apply on a pending prompt candidate on the AI Eval Optimize page used to always fail with an error, leaving the candidate pending and the agent prompt unchanged. Apply now saves the candidate prompt on the agent. If the agent has been deleted, Apply returns a "not found" response and the candidate stays pending.

## Impact

No upgrade or configuration changes required.

## Technical details

`OptimizationController::apply()` called `$this->configFactory()`, which `ControllerBase` does not provide, so the call threw and the transaction rolled back. The fix loads the `ai_agent` entity through `entityTypeManager()` and calls `set('system_prompt', ...)->save()` on it. Loading the entity rather than editing config directly means a deleted agent is not recreated as a config record holding only a prompt. If the `ai_agents` module is not installed, or the agent does not load, `apply()` throws `NotFoundHttpException`. The existing `catch` then rolls back the transaction, so the row stays `pending`. A new kernel test, `OptimizationApplyTest`, covers both the success path (row marked `applied`) and the deleted-agent path.
