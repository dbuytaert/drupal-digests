## Summary

In AI Eval's two test forms (the guided form and the classic target form), the "Gate type" options used to say a hard gate "fails the run" and a soft gate is "warning only". No screen treats them differently. The only effect is the exit code of `drush ai-eval:run`: a hard miss exits with 1, and a soft miss is named in the output without changing the exit code. Both forms and the guided Review line now say this, and the user docs match. The same commit also ships several related fixes to the results and calibration screens ([#3594855](https://www.drupal.org/node/3594855), [#3594857](https://www.drupal.org/node/3594857) to [#3594862](https://www.drupal.org/node/3594862)). Results now show the gate a run actually recorded, or "Gate not recorded", instead of an invented 4.0 threshold. Test and judge names are shown as labels instead of ids. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred". Annotate progress counts the answers of the latest run. The compare page uses plain labels for differences. Calibration screens warn when a saved fit will not apply because the rubric wording changed, and when a save replaced an earlier inactive fit.

## Technical details

The gate wording lives in one new class, `Drupal\ai_eval\Form\GateTypeWording`. Its `options()`, `description()` and `review()` methods are called by `EvalTargetForm`, `GuidedTestForm` and the guided Review line (`gateSummary()`), so the strings cannot drift between forms. The stored values stay `hard` and `soft`.

In the bundled changes, `EvalResultsController::recordedGate()` reads the gate metric and threshold from the run's validated config snapshot first. It falls back to the live target's `threshold` and `metric` only when the snapshot has none. If neither exists, the detail page shows "Gate not recorded" and the dashboard drops the "/ threshold" text and the gate wording in the score aria label. The results dashboard and detail pages load targets in one `loadMultiple()` call and show `label()` with the id as a `title` attribute. They also add target cache tags.

`FailureRateService` now selects `verdict` as well. It merges rows that have a failure mode back into one bucket per mode and splits only rows with no mode by verdict. Each row carries a new `verdict` key, and the `(untagged)` label is gone. `WorkflowStateService` counts Annotate progress as canonical annotations on the latest result against its `question_count`, which replaces the fixed suggested total of 100. `ResultsCompareController` takes a new optional `graderManager` constructor argument and maps snapshot keys to readable labels. Hashes show as same or changed, and raw values go into a closed "Technical details" details element. `CalibrationSaveTrait::saveAndReport()` and `CalibrationFromReviewsForm` add the messages for a replaced inactive fit and for a fit that does not match the current rubric fingerprint.
