# #3594791: Let each question pass its own inputs to a workflow target

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3594791](https://git.drupalcode.org/project/ai_eval/-/work_items/3594791) · 1 contributor · 3 comments

## Summary

In AI Eval, a question in a dataset can now set its own inputs for a workflow target. Put a map of port name to value under the question's `metadata.inputs`. It overrides the target's fixed inputs for the same ports. One target can then cover questions that need different values, such as a language or a length limit, so you no longer need a target for each combination. Bad input is refused before the workflow starts. The question editor keeps these inputs as a typed map when you save.

## Impact

Affects module maintainers.

- **New API:** Question `metadata.inputs` (map of workflow port to value) is read by workflow targets and described in `schema/dataset.schema.json`.

## Technical details

`EvalRunner::invokeWorkflow()` now builds the workflow inputs in three layers. First come the target's fixed `workflow_inputs`. The question's `metadata.inputs` goes over them with `array_replace()`, so the question wins on the same key and values keep their types. The question port is set last, so nothing else can override it. The workflow arm of the question dispatch passes `$question['metadata']['inputs']`. Chat and agent modes ignore it.

Validation happens before launch, and failures are recorded as `refused`. A new `questionInputs()` helper accepts NULL, a string-keyed map, or a JSON object string. It rejects lists and empty or non-string keys. A `metadata.inputs` key that matches the question port is refused. The runner's `inputPorts()` is called, and an exception from it is also a refusal. When the workflow declares ports, the question port and every fixed or per-question input must be one of them. The refusal message lists the declared ports. A workflow that declares no ports takes any names as given.

For the editor, `DatasetQuestionEditor::assemble()` decodes the JSON text in `metadata.inputs` and stores it as a map. An empty `{}` or `[]` is dropped. Nested empty objects are refused, because dataset storage cannot tell `{}` from `[]` once decoded. `DatasetQuestionEditor::inputsError()` gives a readable message for this, and `DatasetQuestionController` and `GuidedTestController` call it. A question with `metadata.inputs` stays editable instead of read-only. `schema/dataset.schema.json` declares `metadata.inputs` as an object. The same commit also adds the `ai_eval_ai_answers` submodule and moves tool-call recording into `Workflow\ToolCallRecord`. Those are not part of this issue.

## Upgrade

Per-question inputs are set in the dataset. For example, `schema/examples/valid/dataset-workflow-inputs.yaml` is a working example. A question carries `metadata.inputs` such as `{"language": "el"}`, keyed by the workflow's input port names.
