## Summary

The judge prompt in AI Eval wraps the question, criteria and the evaluated answer in XML-style tags. Before this fix, only the exact lower-case closing tags were neutralised. An answer containing `</AGENT_RESPONSE>` or a closing tag with extra spaces could close the answer section early, so any text after it might read to the judge as instructions. Closing fence tags are now escaped in any letter case and with spacing or attributes. The reporter did not test whether a judge model actually follows such text, so this is a hardening measure. Updating is enough; the 1.1.x changelog and judge documentation were updated to describe it.

## Impact

Affects site owners.

- **Security:** Low-priority prompt-injection hardening: an answer could close the judge prompt's `<agent_response>`, `<question>` or `<criteria>` fence with `</AGENT_RESPONSE>` or `</agent_response >`. Those variants are now escaped.

## Technical details

`LlmJudgeBase::escapePromptValue()` replaced its three-pair `str_replace()` with a case-insensitive `preg_replace()`. It matches `<` followed by `/`, optional whitespace, then `question`, `criteria` or `agent_response`, and anything up to the closing `>`. It prefixes a backslash after the `<`, so `</AGENT_RESPONSE>` becomes `<\/AGENT_RESPONSE>`. The inner text is otherwise untouched, so the judge still sees the original content. The method also changed from `private` to `public static`. The issue proposed a pattern allowing only whitespace inside the tag, and the merged pattern also covers attributes. The commit also contains the other 1.1.x judge-trust changes ([#3594812](https://www.drupal.org/node/3594812), [#3594813](https://www.drupal.org/node/3594813), [#3594814](https://www.drupal.org/node/3594814), [#3594815](https://www.drupal.org/node/3594815), [#3594816](https://www.drupal.org/node/3594816)). They are not part of this fix, and I did not read the `LlmJudgeBase.php` hunks for them beyond the escape function.
