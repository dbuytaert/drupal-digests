# #3594781: Judges fail on models that refuse temperature; make the pin optional

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3594781](https://git.drupalcode.org/project/ai_eval/-/work_items/3594781) · 1 contributor · 2 comments

## Summary

LLM judges are pinned to temperature 0 and top_p 1 where the provider offers them. Some models, such as Claude Haiku 5.5, reject `temperature`, and every judged question then failed and the run measured nothing. Now, if a model refuses a pinned setting, the judge asks again without the pin and the run records the judge as not pinned. A new settings checkbox, "Pin judges to temperature 0" (on by default), lets a site turn pinning off entirely and use the provider defaults.

## Impact

Affects site owners.

- **Database update:** `ai_eval_update_10048()` sets `pin_judge_decoding` to TRUE on existing sites.
- **Config change:** New `pin_judge_decoding` boolean in `ai_eval.settings` (default TRUE), with schema and a checkbox on the settings form.

## Technical details

The setting is stored as `pin_judge_decoding` and read in `LlmJudgeBase::create()`. A public `setPinDecoding()` setter exists for tests. `pinDeterministicDecoding()` returns early when pinning is off or the model has already refused. It also keeps the provider configuration without the pinned knobs in `unpinnedConfiguration`.

The chat call moved into a new private `askJudge()`, used both directly and inside the rate-limit handler callback. On an exception, `refusesPinnedKnob()` checks whether the message names a knob that was actually pinned (`temperature` or `top_p`, with spellings such as `top-p` and `topP`) within a few words of a refusal term (deprecated, unsupported, not supported, invalid, and similar). A message that only echoes the request, such as an invalid API key with `temperature=0` in it, does not match. On a match, the provider is reset to the unpinned configuration, `lastPinnedDecoding` is set to `[]` so the run identity records no pin, and the call is retried once. Any other error is rethrown as before, so a broken provider does not cost two calls per question. A retry that hits a rate limit goes through the existing rate-limit handler.

The refusal is remembered in a static `$pinRefused` array keyed by provider and model. It is static because stepped runs create a new judge per question. So the extra call happens once per process and model, not once per question.

## Upgrade

Run `drush updatedb` to apply `ai_eval_update_10048()`, which sets `pin_judge_decoding: true` and keeps the existing behavior. To use provider defaults, uncheck "Pin judges to temperature 0" on the settings form, or set `pin_judge_decoding: false` in `ai_eval.settings`.
