## Summary

The run snapshot now records the default caller set with `drush ai-eval:run --as-user`, and Compare runs shows it as "Default caller". Previously a run as an anonymous visitor and a run as an administrator looked like they had identical settings. Runs recorded before this change count as having no default caller, so upgrading does not change comparisons with older runs. A re-grade keeps the caller of the run it re-grades.

## Impact

No upgrade or configuration changes required.

## Technical details

`EvalRunner` adds `default_caller_uid` to the snapshot, cast to int when `$targetConfig['default_caller_uid']` is set and `NULL` otherwise. `RunComparability::compare()` treats a missing key as `NULL` and, when the two values differ, adds a `default_caller_uid` entry to `differences` with `a` and `b` values. Per the added unit tests, differing callers produce a `side_by_side` result, and a legacy snapshot without the key compares as `direct` against one with `NULL`. `ResultRegrader` adds `default_caller_uid` to the list of snapshot keys carried over from the earlier run, and `ResultsCompareController` adds the "Default caller" label. No schema change.

The same commit also bundles fixes for [#3594902](https://www.drupal.org/node/3594902), [#3594903](https://www.drupal.org/node/3594903) and [#3594904](https://www.drupal.org/node/3594904). In `EvalOptimizeCommand`, the failure filters (proposer prompt via `formatFailures()`, stored failure details, dry-run failure count) now include measured failures with a score of 0.0 and exclude questions with an `error` or `unscored` flag. In `EnvelopeImporter`, re-importing an envelope with the same `evaluation_id` now also compares `target_id` (source name plus dataset name) and reports a conflict if it differs, and the interval is read only from the pass rate item's `score_details`, so a quality score interval is no longer stored as a pass rate interval. Docs were updated accordingly.
