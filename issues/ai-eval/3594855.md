## Summary

The AI Eval results overview and result detail page now show the gate a run actually used. Before, they read the gate from the live test. A deleted test or a changed gate produced a threshold the run never had, often "4.0" with `avg_score`. The gate now comes from the settings recorded with the run. If the run has no usable record, the page uses the live test. If neither exists, the detail page says "Gate not recorded" and the overview shows the score with no "/ threshold". The same commit makes several related screen and wording fixes. The results screens show test names instead of ids (the id is kept as a hover title). The compare page uses plain labels for differences, with raw values in a closed "Technical details" section. Failure-rate rows without a failure mode are split into "Passed", "Failed, no failure mode" and "Deferred", and the shares still add up to 100%. Annotate progress counts the answers of the latest run. Calibration shows a message when a save replaced an earlier inactive fit. It also warns when the judge's rubric wording has changed, so the judge will not apply that fit. The hard and soft gate wording now says it only changes the exit code of `drush ai-eval:run`.

## Impact

Affects front-end developers.

- **Theme change:** Results overview, detail and compare screens render different text: test labels with ids as hover titles, "Gate not recorded", and a closed "Technical details" section on the compare page. Any custom theme or test that matches the old strings, such as "(untagged)" or "@done of @total suggested", needs updating.

## Technical details

`EvalResultsController` gets a private `recordedGate()` helper, used by both the overview Target Health loop and `detail()`. It calls `ResultEnvelopeBuilder::decodeValidatedSnapshot()` on `config_json`. It accepts the snapshot's `metric` and `threshold` only when the metric parses with `GateMetric::tryFrom()` and the threshold is numeric. Otherwise it falls back to the live target's `threshold` and `metric`, and returns NULL if neither is available. With a NULL gate, the score cell template drops the "/ threshold" part and the aria label drops the gate comparison. The detail Gate cell prints "Gate not recorded". The detail page also prints the metric's label (for example "Pass rate") instead of the raw `pass_rate`. The overview now runs its pending-optimization and paged-results queries earlier and calls `loadMultiple()` once, so all three sections can show target labels. Cache tags for the loaded targets and `ai_eval_target_list` were added to the results, annotate and compare pages.

`ResultsCompareController` gets an optional `ai_eval.grader_manager` constructor argument. It adds `differenceLabel()` and `readableValue()`: hashes show as "same", "changed" or "recorded", grader ids show as grader labels, and gate metric and type are readable. The raw key and value pairs go into a closed `details` element titled "Technical details". `FailureRateService` now also groups by `verdict`. `decorate()` merges tagged verdicts back into their mode and splits only the rows with no failure mode by verdict, with labels "Passed", "Failed, no failure mode", "Deferred" or "No verdict". Result rows carry a new `verdict` key.

`WorkflowStateService` drops the fixed suggested total of 100 for the Annotate step. Progress is now the canonical annotations on the latest result over that result's `question_count`, and is NULL when there is no result. A new `Drupal\ai_eval\Form\GateTypeWording` class holds the shared gate-type labels and description for `EvalTargetForm` and `GuidedTestForm`. `CalibrationSaveTrait::saveAndReport()` counts inactive curves for the same provider, model and fingerprint before saving, and reports how many were replaced. `CalibrationFromReviewsForm` compares the group's fingerprint with `currentFingerprint()`. When they differ, it warns on save and changes the readiness text.
