## Summary

Edit links for rubrics and dataset questions used to open a bare fragment with no page, CSS or htmx, where Save sent a GET and silently lost the changes. They now open the full rubrics page or dataset page with the editor open, and a direct non-htmx visit to the old fragment URLs redirects there. In trace review, Ctrl+Enter (Cmd+Enter on macOS) no longer saves Pass when no verdict is active. It shows "Choose a verdict first" instead, and it moves to the next item only after the save response arrives.

## Impact

No upgrade or configuration changes required.

## Technical details

`RubricController::edit()` and `DatasetQuestionController::edit()` now redirect a GET without `HX-Request: true` to a full page. Rubrics go to `ai_eval.rubric.collection` with `?edit=ID`. Questions go to `EvalQuestion::datasetEditUrl()`, which is `entity.ai_eval_dataset.edit_form` with `?edit=ID`. `WorkflowStateService::rubricLinks()` now emits that rubric URL, passed through a new `action_options` key next to `action_route` and `action_params`. `PromoteController` uses `datasetEditUrl()` for the "Edit this question" link.

`EvalDatasetForm` reads the `edit` query argument. It renders the question editor only if the question belongs to that dataset and `DatasetQuestionEditor::isEditable()` accepts it, so types the editor cannot round-trip are still refused. The editor render array comes from the new public `DatasetQuestionController::buildInlineQuestion()`. `DatasetQuestionList::renderOutsideForm()` is a `#pre_render` callback that moves the question region after the dataset form's wrapper, so the question forms are not nested inside the dataset `<form>`. The dataset form now varies its cache on `url.query_args:edit`.

In `js/review-keys.js`, Ctrl+Enter without an `.ai-eval-verdict-btn--active` button writes a `.ai-eval-review-verdict-required` alert and returns. With an active verdict it clicks that button and advances via the `[data-review-nav="next"]` link from an `htmx:afterRequest` listener, replacing the fixed 150 ms `setTimeout`. It does not advance if the response contains error markup. It also guards against double submits with a per-form `WeakSet` and releases on htmx cancel events or a two minute fallback timer. Gold forms with `input[name="next"]` still advance through the server response.

The commit is a combined fix for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926). These changes are only the [#3594914](https://www.drupal.org/node/3594914) part.
