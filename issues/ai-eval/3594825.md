## Summary

One commit on 1.1.x covers several run and data fixes. Deleting a dataset now deletes its questions, and the confirmation page says how many questions go with it and which tests use it. Those tests cannot run until you pick another dataset. Stored results, runs, annotations and review labels are kept. A run no longer starts on a dataset with no questions to run: the Run button and `drush ai-eval:run` say why and store no result, and the command exits with 1. A browser run whose dataset loses questions now stops with an error naming the question counts instead of polling forever. `drush ai-eval:optimize` compares a candidate and the baseline only on questions both were scored on. It skips a baseline or candidate scored on fewer than half its questions. `drush ai-eval:export-envelope` skips imported results and reports how many it skipped.

## Impact

Affects module maintainers.

- **New API:** New `RunDatasetException` thrown by `EvalRunnerInterface::runTarget()` and `startRun()` when the dataset has no runnable questions; new `RunCoverage` helper and `EvalDatasetDeleteForm`.

## Technical details

Dataset delete: `EvalDataset::postDelete()` now deletes the dataset's `ai_eval_question` entities in chunks of 50. The delete form is a new `EvalDatasetDeleteForm` (extends `ContentEntityDeleteForm`) that uses the `ai_eval.dataset_usage` service to list tests via `targetsUsing('entity', $id)`. The manual question cleanup in `DatasetCloner` and `GuidedTestFinalizer` was removed because the entity hook now does it. Questions orphaned by earlier deletes stay in the database. `ReferenceOptions::bundles()` and `WorkflowStateService::caseCount()` now ignore them.

Empty datasets: `EvalRunner::runTarget()` and `doStartRun()` throw the new `RunDatasetException` (factories `empty()`, `emptySplit()`, `questionNotFound()`, `changed()`). Before, `runTarget()` stored a failed empty result. `RunController` catches it and renders `RunFragment::notStarted()` with a Retry button. `EvalRunCommand` reports the error per target, continues with the other targets, and returns `EXIT_FAILURE` at the end if any target did not run. This covers `--question` with an unknown ID and `--split` with an empty split. In the stepwise run, if the dataset has fewer questions than the stored total, the step throws `changed()`. `markRunError()` stores that message without the exception class prefix. Growth or reordering still only records drift.

Optimizer: the new `Drupal\ai_eval\RunCoverage` helper finds, for each side, the question IDs scored in every repeat, using `Scorer::isCoverageInsufficient()` as the policy. `EvalOptimizeCommand` skips a target whose baseline has insufficient coverage and does not store a candidate with insufficient coverage. It compares the candidate and baseline means on the shared IDs, and skips the attempt when fewer than half the questions overlap. `runRepeatedEval()` fails the aggregate gate on insufficient coverage. A `RunDatasetException` from the baseline or candidate runs skips the target. The Optimizations page gets an explanatory paragraph. Export: `EvalExportEnvelopeCommand` excludes rows with a non-null `import_key` and counts them with the same target and since filters. It exits 0 when every result found was imported.

## Upgrade

Questions left behind by a dataset deleted in an earlier version stay in the database. Dropdown suggestions and test counts ignore them. No update is needed (stated in the CHANGELOG).
