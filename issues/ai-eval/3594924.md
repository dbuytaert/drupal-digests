## Summary

A decision calibration fit is now activated automatically only if it was checked on at least 10 held-out answers. Before, a fit checked on only 1 or 2 held-out rows could go live, because a comparison on so few rows means little. Once active, it changed every answer of that model and question. Such a fit is now saved inactive and the calibration page says "too few held-out rows (N of 10)". An admin can still activate it by hand, and the confirmation form warns that the result is uncertain.

## Impact

Affects module maintainers.

- **New API:** New constant `CalibrationStoreInterface::MIN_HELD_OUT_ROWS` (10), the minimum held-out rows for automatic activation.

## Technical details

`CalibrationStore::save()` now sets `$active` only when `heldOutCount >= CalibrationStoreInterface::MIN_HELD_OUT_ROWS` (10) and `CalibrationVerdict::of()` is not `Worse`. A fit that fails either test is saved inactive, so any active curve keeps applying.

The reason is not stored, so the config schema is unchanged. It is derived from `held_out_count` at display time. `CalibrationController` uses a `match` that checks the minimum first, then the `Worse` verdict, then a generic message. `CalibrationSaveTrait` shows a matching warning after saving, and `CalibrationActivateForm` adds a note about the small sample to its confirmation text. The commit also touches many unrelated areas, covered by other issues in the range [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926).
