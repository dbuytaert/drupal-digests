# #3594780: Apply decision calibrations to the callers a site selects

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3594780](https://git.drupalcode.org/project/ai_eval/-/work_items/3594780) · 1 contributor · 3 comments

## Summary

AI Eval gets an optional submodule, AI Eval Decision Calibration. Until now only the decision rubric judge used a calibration, and other callers such as the "Decision: Boolean" automator got the raw probability. With the submodule, a site picks which callers use an active calibration, and only those callers get the corrected probability. The issue's own test numbers show why this is scoped: a curve fitted on another model's answers made calibration error worse. A site can also record a sample of a caller's true/false answers, have people review them, and fit a curve from those reviews. The Callers tab then warns if the curve does worse than the raw probability on answers recorded after the fit.

## Impact

Affects module maintainers and site owners.

- **Config change:** New `ai_eval_decision_calibration` module with a `scope` third-party setting on calibrations and record settings (callers and sample rate).
- **Permission change:** No new permissions. The Record decisions page needs `administer ai eval`, and the Callers, Review and Fit pages need `validate ai eval judges`.
- **New API:** New `CalibrationFingerprint::fromDecision()`, `hook_ai_eval_calibration_view_alter()`, and an optional `$thirdPartySettings` argument on `CalibrationStoreInterface::save()`.

## Technical details

The new `ai_eval_decision_calibration` module requires `ai_eval` and `ai`, and Drupal ^11.3. Its `CalibrationSubscriber` listens to `PostGenerateResponseEvent` at priority 10, so the AI module's validation subscriber (priority 20) runs first. For the `decision` operation it handles each `NoulAnswer`. It computes the fingerprint with the new `CalibrationFingerprint::fromDecision()`, which also accepts array instructions and NULL criteria. It looks up the active curve through `CalibrationStore::fresh()` using the provider, the model that answered (`DecisionResponse::getModel()`) and that fingerprint. The curve applies only if its `scope` third-party setting (request tags such as `ai_automator:id:<id>`) intersects the event tags. An empty model ID or an empty scope means no correction. Score and choice answers are untouched. A matching answer is rebuilt with the calibrated probability, and its raw data gets an `ai_eval_calibration` entry with `raw_probability`, `calibration` and `tag`. If anything fails, the output stays unchanged and a warning is logged.

Calibration scope is stored as a third-party setting on `EvalCalibration`. `CalibrationStoreInterface::save()` gets an optional `$thirdPartySettings` argument. When a new active curve replaces an active one, it inherits the old curve's third-party settings unless it sets its own. A new `hook_ai_eval_calibration_view_alter()` lets modules change the calibration detail page. The submodule uses it to replace the judge-use text for scoped calibrations.

`DecisionRecorder` stores sampled true/false answers. A row holds the entity reference, field name, question wording, provider, answering model, raw probability and any applied calibration. It does not store the state sent to the model. Answers are skipped when the response reports no model, or when the question wording contains text from the state. Recorded answers are deleted when their entity is deleted. New admin forms cover choosing callers, record settings, blind review and fitting from recorded decisions (`RecordedFitForm`). Fitting needs at least 30 reviewed answers, both classes on the fitted side, and held-out answers, with answers about one entity kept on the same side of the split. A fit that worsens the held-out Brier score is saved inactive. The calibration is not deactivated automatically when it later does worse. The Callers tab shows a warning.

## Upgrade

Enable the module, open a calibration from Manage > Calibrations, then its Callers tab. Select the automators that should use it. To build a curve from a caller's own answers, use Record decisions, Review decisions, then Fit a calibration > From recorded decisions. Modules that call `CalibrationStoreInterface::save()` need no change, because the new `$thirdPartySettings` argument is optional.
