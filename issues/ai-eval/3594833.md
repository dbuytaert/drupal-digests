## Summary

Saving a new rubric without a "Scoring: combine" rule used to fail with the unhelpful "The properties must match schema: {properties}". A new rubric now opens with `all_pass` selected and no "(none)" option. If the value is still missing on save, the editor shows "Choose how the checks combine (Scoring: combine)." and saves nothing. Rubric and failure taxonomy schema errors now show the field path and filled-in details instead of a placeholder. Older rubrics with no combine rule still show "(none)" until someone picks a value. The same commit also ships the [#3594832](https://www.drupal.org/node/3594832) decision-recording changes: answers recorded while a new entity is saved are linked to it once it exists, and a lowered limit shows "Recording stopped: 42 recorded, limit 3."

Affects module maintainers.

## Technical details

The editor's empty `scoring` array was encoded as a JSON list, so validation reported a type error instead of a missing `combine`. `RubricEditor::assemble()` now returns an empty `\stdClass` for empty scoring, so the schema reports the missing property. `RubricEditor::fields()` takes a new `$isNew` argument. The `combine` select defaults to `all_pass` for new rubrics, and a new `allowNone` parameter on the private `select()` hides the "(none)" option. `RubricController` checks the submitted `combine` against `RubricEditor::COMBINE` before schema validation. The select is an inline template, so the server has to check the value itself.

A new `Drupal\ai_eval\Service\SchemaErrorFormatter::format()` wraps opis `ErrorFormatter::formatKeyed()` and prefixes each message with its path. `DatasetValidator`, `RubricValidator` and `FailureTaxonomyValidator` all use it.

The decision-recording changes in the same commit work as follows. `DecisionRecorder` reads the optional `entity_context` request metadata, if the installed AI version provides it, to get the UUID of an entity being created. It keeps up to `LINKABLE_MAX_ROWS` (200) pending rows in memory per request, dropping the oldest beyond that. A new `RecordedEntityLink` `entity_insert` hook calls `linkInserted()`. That sets `entity_id` and the kept text on matching rows inside the save transaction, so a rollback removes them too. `RecordSettingsForm` and `DecisionReviewForm` show "Recording stopped: N recorded, limit L." when the count exceeds the limit.
