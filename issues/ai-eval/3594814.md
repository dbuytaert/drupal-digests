## Summary

The corrected pass rate on a result page now appears only when the judge was validated at the same question pass threshold the run used. Before, a judge validated at 3.0 could correct a run scored at 3.5 with no warning, which gave a number nobody had measured. When the thresholds differ, or the result did not record its threshold, the Corrected Pass Rate row reads "Not available" with both thresholds, and the EEE export leaves the corrected value out. The fix is to validate the judge again at the threshold the run used. Existing results can change to Not available after the update. A validation where the judge only ever scored 0 or 5 is exempt, since every threshold in between gives the same verdict. Older validations need a rerun to record that evidence. The same commit also ships several related judge-trust fixes ([#3594812](https://www.drupal.org/node/3594812), [#3594813](https://www.drupal.org/node/3594813), [#3594815](https://www.drupal.org/node/3594815), [#3594816](https://www.drupal.org/node/3594816), [#3594817](https://www.drupal.org/node/3594817)).

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_eval_update_10050` adds nullable `endpoint_only`, `not_scored`, `pass_items` and `fail_items` columns to `ai_eval_judge_validation`.
- **Config change:** Question pass thresholds (site settings, target form, guided test form) now accept at most two decimals; the number step changed from 0.1 to 0.01.
- **API change:** `CorrectedPassRateInterface::forResult()` and `bootstrapForResult()` take an optional `$runThreshold`; omitting it returns NULL (no correction). New `thresholdMismatch()` method on `CorrectedPassRateInterface` and `JudgeGateTrustInterface`, so custom implementations and mocks must add it.
- **New API:** `ScoreScale::passes()`, `ScoreScale::sameThreshold()` and `ScoreScale::thresholdMismatch()` give one shared pass decision and threshold comparison.

## Technical details

`CorrectedPassRate::forResult()` and `bootstrapForResult()` now require a recorded `$runThreshold` and a compatible validation threshold. The compatibility check is `ScoreScale::thresholdMismatch()`. Thresholds match when they agree at two decimals, and a positive threshold that rounds to zero never matches zero. Otherwise, a validation flagged `endpoint_only` fits any run threshold above 0 and up to 5. The evidence is measured from the scores (new `endpoint_only` column), not inferred from a judge's name or declared range. Legacy rows have NULL there, so they get no exemption.

A new `thresholdMismatch()` method on `CorrectedPassRate` returns the two thresholds for an otherwise eligible judge. `EvalResultsController` reads the run threshold from `question_pass_threshold` in the dataset snapshot. When no correction is produced, it renders the "Not available" message, with a separate wording when the run recorded no threshold.

To make "same threshold" mean the same thing in both places, validation and run scoring now share `ScoreScale::passes()`, which compares the score rounded to two decimals. `LabeledExample::graderPassesAt()` and the result page's low-score check both use it. Before, a score of 3.496 at threshold 3.5 failed validation but passed a run. The threshold inputs on the settings, target and guided test forms now use step 0.01 and reject more than two decimals. The validation controller applies the same rule. Docs in `scoring.md`, `judges.md` and the EEE export docs, plus the CHANGELOG, were updated.

## Upgrade

Run database updates: `ai_eval_update_10050` adds the nullable `endpoint_only` column (and the other new validation columns). Existing validation rows keep NULL there, so they get no endpoint-only exemption. Validate such judges again at the threshold your tests use to get a corrected pass rate.

Custom code that implements or mocks `CorrectedPassRateInterface` or `JudgeGateTrustInterface` must add `thresholdMismatch()`. Callers must pass the run's threshold, or no correction is returned:

```php
$corrected = $correctedPassRate->forResult($graderIds, $p, $ciLow, $ciHigh, $runThreshold);
$bootstrap = $correctedPassRate->bootstrapForResult($graderIds, $scoresJson, $seed, $runThreshold);
```
