# #3594777: Fields that name another thing are typed by hand

## Summary

In AI Eval's admin forms, several fields that name something the site already knows no longer have to be typed from memory. A question's "Rubric reference" is a select of the site's enabled rubric versions. "Expected tools" suggest the AI module's function names and plugin ids. A question's domain bundle, its tags, a rubric's applicable bundles and a failure mode's taxonomy suggest values already in use on the site. New values can still be typed for the grouping fields, and for tool names not in the list. The issue's other examples (test form "Proving-ground fixtures", calibration "Model") are not covered by the changes I found.

## Impact

Affects module maintainers.

- **New API:** New `ai_eval.reference_options` service (`ReferenceOptions`) supplying rubric versions, tool names, bundles, dataset tags and failure mode taxonomies for form fields.

## Technical details

The work lives in a new `ReferenceOptions` service (`ai_eval.reference_options`). `forQuestionEditor()` returns `rubrics`, `tools`, `bundles` and `tags`. `bundles()` combines the `domain_bundle` values of questions with the `applicable_bundles` in rubric data. `datasetTags()` reads tags from the questions of the current dataset. `taxonomies()` returns the taxonomy ids of existing failure modes plus `default`.

`DatasetQuestionEditor::fields()` takes an `$options` array. When `rubrics` is supplied, `rubric_ref` renders as a select with a `(none)` option. A stored ref the site does not have stays selected and is labelled "(not on this site)", so saving never silently drops it. Without options the old free-text fields remain. Suggestions for tools, bundles, tags and taxonomies are HTML `<datalist>` elements, so free text is still accepted. Each editor gets its own datalist id for its tool rows (`TOOL_LIST_PREFIX`), and the "+ Add" request carries it as a `list` query parameter so added rows use the same suggestions. `FailureModeForm` now injects `ReferenceOptions` and attaches a taxonomy datalist to its `taxonomy_id` field.

The changes landed in two untagged commits (`dcbcdf0`, `a19a68e`), described in the CHANGELOG under [#3594777](https://www.drupal.org/node/3594777). The issue has no comments. The test form fixtures and the calibration model fields named in the issue body were not changed in those commits.
