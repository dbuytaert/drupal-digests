## Summary

A grader that throws an exception while grading no longer stops the whole evaluation run. The failure is recorded as a grader error for that question, logged, and counted like other grader errors in scoring, so coverage and the gate stay correct. The other graders and questions keep going, and results from earlier questions are saved. When a question aborts with an exception before its last follow-up, the open workflow conversation is now released instead of staying open.

## Impact

No upgrade or configuration changes required.

## Technical details

`EvalRunner::gradeResponse()` now loops over the graders and wraps each `grade()` call in `try`/`catch (\Throwable)`. On failure it logs the exception through the module logger and substitutes a `GradeResult` with a NULL score, the exception message shortened by `capErrorDetail()`, the grader plugin id, and the grader's `min_score`/`max_score` from its plugin definition. The scorer then treats it as any other grader error. Re-grade goes through the same method.

For chains, `runQuestion()` now passes a `WorkflowExecution` by reference into `runQuestionBody()` and catches `\Throwable` around it. It resolves the run id from that invocation's record, or from `chainRunId()` for earlier rows in the chain, calls `releaseChain()`, and rethrows. Coverage is in the new `EvalRunnerGraderFailureTest` Kernel test, with a `ThrowingGrader` test plugin, for a run, a stepped run, a re-grade and chain release.

The commit also bundles many unrelated fixes ([#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926)); they are not covered here. The change touches `gradeResponse()`, which also now stores `criteria` and `expected_facts` on each question row (part of [#3594919](https://www.drupal.org/node/3594919)).
