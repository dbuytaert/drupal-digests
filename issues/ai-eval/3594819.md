## Summary

Importing OTLP trace files in ai_eval 1.1.x no longer silently loses documents. Before, one stray `}` or one unclosed `{` made the importer drop every later document in the file, with no warning. Now a stray closing brace, stray text or a closed object that is not a trace document is skipped and counted, and later documents are still imported. An unclosed brace or unterminated string stops the read for that file. The import page and `drush ai-eval:import-traces` warn about both cases. The same commit also changed trace review: it reads the structured JSON that ai_observability writes by default, shows tool calls, and marks cut spans as not promotable. It also fixes role-line parsing ([#3594834](https://www.drupal.org/node/3594834), [#3594820](https://www.drupal.org/node/3594820)). If you imported trace files before, re-import any that had damaged parts.

## Impact

Affects module maintainers.

- **New API:** New public static `TraceImporter::splitDocumentsWithReport()` returning docs, skipped and unread counts; `ImportResult` gains `skippedDocuments` and `unreadTails`; new `PromotionService::STATUS_TOOL_TURNS`.

## Technical details

`TraceImporter::splitDocuments()` now delegates to the new `splitDocumentsWithReport()`. It scans for depth-zero objects with a string-aware `objectEnd()` and never restarts a scan inside a candidate. That keeps nested payload objects from being imported as documents. Strings that contain a raw line break count as unterminated. Skipped parts are logged to the `ai_eval` channel with a byte offset and a reason. The scan stops only on an unclosed object or string, and that sets `unread` to 1. `importString()` merges the counts into `ImportResult`, which gained `skippedDocuments` and `unreadTails`. `TraceImportBatch` and `EvalImportTracesCommand` turn those counts into warnings. Drush exits 0 with warnings if at least one document was read, and 1 if none was.

The commit also bundles two related issues. For [#3594834](https://www.drupal.org/node/3594834), the new `TracePayloadParser` (`parseInput()`, `parseOutput()`) reads either plain role-line input or ai_observability's structured `{"messages":[...]}` input. It extracts tool calls and tool results, and detects payloads cut at ai_observability's length limit, omitted items and shortened strings. `OtlpSpanMapper` and `OtelTraceSource` use it to set the `truncated` flag. `TraceReviewFragment` shows tool calls and specific notices. `PromotionService` refuses cut traces and traces with tool turns in structured input (new status `tool_turns`). Calls and call ids count in either format. A tool-only reply is no longer called `streamed_uncaptured`. Promoted questions keep `metadata.raw_input` (up to 8000 characters) and `metadata.ai_response_tools`.

For [#3594820](https://www.drupal.org/node/3594820), plain role-line parsing moved into `TracePayloadParser::parsePlain()`. It keeps text before the first role line as a user message, handles Windows line endings, and maps `developer` to `system`. A role word directly after a role line is kept as content. A role word after content still starts a new message, because the plain format has no escaping.
