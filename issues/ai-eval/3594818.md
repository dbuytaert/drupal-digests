## Summary

This commit bundles several fixes. The headline one is for `drush ai-eval:optimize`. It used to average only the questions that got scored. A candidate prompt could therefore look better because the judge errored on its hard questions, and a baseline that lost questions to provider errors could look good enough to be skipped. Now the optimizer compares a candidate with the baseline only on the questions both were scored on. If fewer than half of a run's questions were scored, it skips that test (for a baseline) or that attempt (for a candidate) and stores nothing for it.

The same commit changes four other behaviors:
- A run no longer starts on a dataset with no questions. The Run button and `drush ai-eval:run` say why, store no result, and the command exits with 1. This also applies to `--question` and `--split` selections that match nothing.
- A browser run whose dataset loses questions stops with an error that names the counts, instead of polling forever.
- Deleting a dataset now deletes its questions, and the confirmation page lists the tests that use it.
- `drush ai-eval:export-envelope` skips imported results and reports how many it skipped.

## Technical details

Optimizer: a new `Drupal\ai_eval\RunCoverage` helper reuses `Scorer::isCoverageInsufficient()` as the "fewer than half" policy. `runRepeatedEval()` now returns a failed aggregate gate when any run has insufficient coverage. `EvalOptimizeCommand` skips a target whose baseline (in either split when dual-phase) is under-covered. For candidates, `RunCoverage::shared()` takes the question IDs scored in every repeat on both sides, and the comparison uses the means over those IDs. `resolveCandidateStatus()` and the margin check use those shared means. The live prompt's own mean (`$currentScore`) is kept separately so that later attempts are not skewed. Under-covered candidates, or candidates with too little overlap, are not stored, and a warning goes to the output and the channel logger.

Runs: `EvalRunner::runTarget()` and `startRun()` throw the new `Drupal\ai_eval\Service\RunDatasetException` for an empty dataset, an unknown or disabled `--question` ID, or an empty split. `runTarget()` used to return a failed empty result for these cases. `runStep()` throws it when the dataset has fewer questions than the stored total. Growth and reordering still only record drift. `markRunError()` stores the exception's message without the class name for this exception. `RunController` renders `RunFragment::notStarted()`. `EvalRunCommand` reports each failing target, runs the rest, and returns exit 1. The optimizer skips such targets.

Data: the delete form is now `EvalDatasetDeleteForm`. `EvalDataset::postDelete()` deletes the questions in chunks, so `DatasetCloner` and `GuidedTestFinalizer` dropped their own question cleanup. Existing orphan questions stay in the database. `ReferenceOptions::bundles()` and the guided-flow case count ignore them. Export: `EvalExportEnvelopeCommand` filters on `import_key IS NULL` and counts the rest as skipped. It exits 0 when everything found was imported.</technical>
<parameter name="upgrade">Callers of `EvalRunnerInterface::runTarget()` or `startRun()` should catch the new exception instead of expecting a failed empty result. This is the pattern used in `EvalRunCommand`:

Questions left behind by datasets deleted in earlier versions stay in the database. Dropdown suggestions and test counts ignore them, and no update is needed. CI that runs `drush ai-eval:run` will now see exit 1 for a target with an empty dataset or a `--question` ID that does not exist.
