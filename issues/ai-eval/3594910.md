## Summary

Questions added to a dataset from AI Answers traces have ids like `trace-ai_answers:abc123`. Opening the result detail page for a result containing such a question returned a 500 error for users who can annotate results. The page now opens, and annotating, resetting and promoting work for those ids. If some other question id still cannot be used in an annotation link, that row is shown without annotation controls and a warning is logged, instead of breaking the page.

## Impact

No upgrade or configuration changes required.

## Technical details

The four annotation routes `ai_eval.results.annotate`, `ai_eval.results.promote_annotation`, `ai_eval.results.reset_annotation` and `ai_eval.results.annotation_open` in `ai_eval.routing.yml` restricted `{question_id}` to `[A-Za-z0-9_.-]+`, so URL generation threw `InvalidParameterException` for ids containing `:`. The requirement is now `[A-Za-z0-9_.:-]+`. The dataset schema allows any string as a question id, so other characters can still fail. In `EvalResultsController`, the per-row annotation cell build (`annotationFormBuild()` or `annotationCompactBuild()`) is now wrapped in a `try/catch` for `InvalidParameterException`. On failure the cell is left empty and a warning is logged to the `ai_eval` channel. Full support for arbitrary ids was left as a follow-up. The issue also proposed a Functional test, but the portion of the commit diff I could read did not include one. The commit is a combined fix for [#3594906](https://www.drupal.org/node/3594906) to [#3594926](https://www.drupal.org/node/3594926), and the diff I could read was partial, so the controller change was checked in the cloned repo rather than the diff.
