## Summary

AI Eval's admin pages now explain their own jargon. Terms such as Overall error, Average gap, TPR, TNR, n, Split, Config version, Gate, Unscored, Corrected pass rate, Trend, Taxonomy, EEE and OTLP get a small "?" button. Clicking, tapping or pressing Enter on it opens a short definition with a "Learn more" link to the matching glossary entry on the docs site. Escape or a second click closes it. The calibration, judges, results, compare, traces, failure mode and import pages also get a short help text with a link to the relevant user guide. The glossary gained entries for the terms that had none.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** Labels and headers on AI Eval admin pages now include a `.ai-eval-toggletip` button and popover bubble, which can change exact-text selectors.
- **New API:** New `ai_eval_toggletip` render element with `Toggletip::term()` and `Toggletip::cell()` helpers, the `ai_eval/toggletip` library and generated `GlossaryTerms::all()` definitions.

## Technical details

The definitions come from one source, `docs/user/glossary.md`. `scripts/glossary-to-php.php` parses the first paragraph of each entry with `GlossaryMarkdown::parse()` and writes `src/Help/GlossaryTerms.php`, a generated class of `TranslatableMarkup` strings keyed by glossary anchor, so the definitions can be extracted for translation. After editing a first paragraph you must rerun the script. A unit test (`GlossaryTermsTest`) compares the generated class with the glossary. The README documents the workflow.

The UI is a new render element, `#type => 'ai_eval_toggletip'` (`Drupal\ai_eval\Element\Toggletip`), with `#term` (the glossary anchor) and `#label`. Two static helpers wrap it: `Toggletip::term($term, $label)` for any render array, and `Toggletip::cell($term, $label)` for a table header or body cell. It renders the label, a `<button popovertarget>` and a `<span popover>` bubble using the native popover attribute, with no Ajax. The new `ai_eval/toggletip` library (`css/toggletip.css`, `js/toggletip.js`, depending on `core/drupal` and `core/once`) is attached only when a known term renders. The JS only positions the bubble near its button on `toggle`. An unknown anchor logs a warning once and falls back to the plain escaped label.

Placements cover the calibration list and detail pages, the judges table and validation history/compare, results list, detail and compare, failure rate table, failure mode list, trace review verdict filter and the two import forms. Some explanatory prose on those pages was removed in favor of the popovers, for example the TPR/TNR hover `title` text and the overall-error sentence on the callers form. Because a label cell now also contains the button and the definition text, existing tests that matched exact cell text were changed to `starts-with(...)` XPaths or strip the toggletip nodes. A new `HelpHooks` class implements `hook_help` for these routes and links to the guide pages. The glossary and the failure rate and average score definitions were also reworded. `GraderPluginManager` now names the deprecated annotation class as a string, and a phpstan baseline entry for it was removed.

## Upgrade

Only relevant if you render your own admin tables or tests against AI Eval pages. To add a definition to a label, use the glossary anchor:

```php
use Drupal\ai_eval\Element\Toggletip;

$header[] = Toggletip::cell('overall-error', $this->t('Overall error'));
```

Tests that match the exact text of an AI Eval label or header may need `starts-with(normalize-space(.), "...")`, since the cell now also contains the "?" button and its definition.
