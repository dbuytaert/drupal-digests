## Summary

The failure-rates table in AI Eval used one "(untagged)" row for every answer with no failure mode. That row included passed answers, so "(untagged) 60%" looked like 60% of answers had failed in an unnamed way. That row is now split by verdict into "Passed", "Failed, no failure mode" and "Deferred". The labels are translatable, rows with a zero count are hidden, and the rows still add up to 100%. Rows for named failure modes are unchanged. The same commit also ships several other 1.1.x results and calibration changes, listed in the changelog, such as the recorded gate on results screens, plain compare-page labels and Annotate progress counted against the latest run.

## Impact

Affects module maintainers.

- **API change:** `FailureRateService` rate rows gain a `verdict` key. Rows with no failure mode are now split into three rows, so code that keys rows by `failure_mode` alone must account for it. Their `label` changes from `(untagged)` to "Passed", "Failed, no failure mode" or "Deferred".

## Technical details

`FailureRateService::aggregate()` now selects and groups by `verdict` as well as `failure_mode`. `decorate()` then folds tagged rows back into one bucket per mode, so mode rows keep their old counts. Rows with no mode are bucketed per verdict. The denominator is unchanged, which keeps the sum at 100%. `ratesForReviewedTraces()` also selects `verdict` from `ai_eval_review_label` and keeps it beside the mode for the earliest label per `trace_key`. Both paths go through `decorate()`.

Each rate row gains a `verdict` key. It is NULL for rows that carry a mode and one of `pass`, `fail` or `defer` for the no-mode rows. For those rows `failure_mode` stays NULL and `label` comes from `TranslatableMarkup`: "Passed", "Failed, no failure mode" or "Deferred". A fallback "No verdict" label covers any other value. Callers that index rows by `failure_mode` alone can no longer tell the three no-mode rows apart and need to check `verdict`. The `FailureRateTable` docblock was updated, and the render code needed no change. `docs/user/usage/failure-modes.md` and the changelog describe the new rows.

## Upgrade

Code that reads `FailureRateService` rows and looks for the `(untagged)` label, or indexes rows by `failure_mode` alone, should use the new `verdict` key to tell the three no-mode rows apart. Rows with a mode have `verdict` set to NULL.
