## Summary

On the `1.x-workspaces` branch, saving a Canvas config entity (content template, pattern, code component, and so on) in Live now updates or discards that entity's draft in whichever workspace holds it. Before, only the active (staging) workspace's draft was reconciled. A template renamed or changed in Live could keep a stale draft in a named workspace, and publishing that workspace would revert the Live change.

## Impact

No upgrade or configuration changes required.

## Technical details

`AutoSaveManager::onCanvasConfigEntitySave()` used `getAutoSaveEntity()`, `delete()` and `saveEntity()`, which all resolve against the staging workspace. Config has no workspace-aware storage, so a Live save never reached drafts held as fallback rows in other workspaces. It now calls the new `WorkspaceAutoSave::findFallbackDraftOfEntity()`, which scans `AutoSaveFallbackStore::workspaceIds()` and returns the workspace ID and draft of the one workspace holding a fallback row for the entity. A cross-workspace lock keeps a config draft to a single workspace. The per-draft rule is unchanged: a change to `label`, `status`, `dependencies` or a content template's `page_variant` is copied into the draft. A change to any other exported property discards it.

Discarding calls `BrandKit::clearAutoSaveFileUsage()`, `deleteFallbackDraft()` and `deleteDraftBookkeeping()` with the owning workspace ID. Updating re-persists the draft inside `executeInWorkspaceUnchecked($workspace_id, ...)`, so `advanceStoredBaseHash()` and `saveEntity()` act on the owning workspace. The `isPublishTimeStaging()` latch is kept, so saves made during a workspace publish are not reconciled. A test shows a Live delete of a used code component discards the draft of its `Component`, because the `Component` is saved with the fallback version.

`AutoSaveFallbackStore` takes a new `EntityLastInstalledSchemaRepositoryInterface` dependency. `workspaceIds()` now returns `[]` when the `workspace` entity type is defined but its schema is not yet installed, since module installation can trigger Canvas config saves before the tables exist. ADR 0022 and the `delete()` docblock document the rule.
