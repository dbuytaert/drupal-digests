## Summary

Content templates can now have exposed slots: a site builder marks slots in a template as editable per entity, and content creators fill them with their own components on each node, while the rest of the template stays locked. Each exposed slot is backed by its own Canvas (`component_tree`) field on the content type. A template can expose several slots, and content already placed in a slot acts as the default until an entity overrides it. An override can also be deliberately empty. Removing a slot from the template only detaches it, so entity content is kept and returns if the slot is exposed again. Deleting the field itself happens in Field UI. This last commit adds an "Edit in Canvas" tab on templated nodes and a Content panel in the editor. The panel lists templated entities grouped by content type and is searchable. It also adds end-to-end tests.

## Impact

Affects module maintainers and site owners.

- **Database update:** New post-update `canvas_post_update_0032_install_empty_slot_marker()` installs the `marker.empty_slot` component on existing sites. Sites using config sync must export config after running it.
- **Config change:** `ContentTemplate::exposed_slots` is now keyed by the machine name of a `component_tree` field on the template's bundle; the template gains config dependencies on those field configs. New `canvas.component.marker.empty_slot` config ships (disabled).
- **Permission change:** `administer content templates` is now marked `restrict access: true` because exposing a slot can create a `canvas_slot_*` field storage.
- **New API:** New routes `canvas.api.content_template.slot_field.create|list|usage` under `/canvas/api/v0/config/content_template/{content_template}/slot-fields`, the `canvas.content.layout` local task, `ContentTemplate::getMergedComponentTree()`, and `exposed_slots` in the content template client payload, CLI types and schema.

## Technical details

Storage: `exposed_slots` keys are now machine names of `component_tree` fields on the template's bundle (validated by `ValidExposedSlotConstraintValidator`, key pattern now lowercase letters, digits and underscores). Each entry keeps `component_uuid`, `slot_name` and `label`. `ContentTemplate::calculateDependencies()` adds the field configs as dependencies, and `onDependencyRemoval()` drops the matching slot when a field is deleted, so a template is not cascade-deleted. `preSave()` prunes slots whose target component no longer exists. The old `assert(count === 1)` in `ContentTemplate::build()` is gone. `build()` now uses the new `getMergedComponentTree()`, which calls `ComponentTreeItemList::injectSlotContent()` (replacing `injectSubTreeItemList()`) for each slot field. A slot field the user cannot view renders the template default, and a `SubtreeInjectionException` (for example a UUID collision) is logged and falls back to the default. `ExposedSlotContentIsMergeableConstraint` validates this on entity save.

Empty overrides: an empty field means "inherit the default". An override that renders nothing is stored as a single `marker.empty_slot` component instance (new `Marker::EMPTY_SLOT_LOCAL_ID`, a disabled `Component` config shipped in `config/install`), which `Component::preSave()` keeps disabled.

HTTP/UI: `ApiContentTemplateSlotFieldController` creates `canvas_slot_`-prefixed `component_tree` fields (with symmetric translation sync when `content_translation` is installed, 409 if the bundle already has the field), lists reusable candidate fields, and reports per-slot override counts. `ApiLayoutController` serves per-slot editable nodes for templated entities and accepts per-slot subtree writes, and the rest of the template is read-only. `ApiContentControllers::list()` now also lists entities of bundles with exposed slots (via `ComponentTreeLoader::getBundlesWithExposedSlots()`). It is gated by `_canvas_ui_access` plus entity access, and canvas pages still require `edit canvas_page`. Templated entities only get an edit operation link. The React UI adds `Content.tsx`/`TemplatedContentGroups.tsx`, the expose, detach and delete-protection dialogs, slot overlays, and a "Content" contextual-panel tab. The decision is recorded in ADR 0022 (`docs/adr/0022-...`) and a user guide `guides/exposed-slots.mdx`. The CLI (`packages/cli`) pushes `exposed_slots` and calls `createSlotField()` before pushing a template.

## Upgrade

Existing sites should run database updates so `canvas_post_update_0032_install_empty_slot_marker()` installs the `marker.empty_slot` component. If you deploy with config sync, export config afterwards, or the next import removes the marker. The issue states no update hook migrates old data: the earlier test-only storage shape (`parent_uuid` pointing at a template-internal component UUID) is abandoned, and nothing released stored it. Templates that define `exposed_slots` by hand must key them by an existing `component_tree` field on the bundle:

```yaml
exposed_slots:
  canvas_slot_main:
    label: 'Main'
    component_uuid: <uuid of the component in the template>
    slot_name: <slot name>
```
