## Summary

Unpublished changes in Canvas (page edits, homepage changes, and other auto-saved entities) used to be dropped after 30 days without an update. They now stay until they are published or discarded. Existing unpublished changes are carried over by a post-update, so run database updates when upgrading.

## Impact

Affects site owners.

- **Database update:** `canvas_post_update_0010_migrate_auto_save()` copies auto-save data and form violations from shared tempstore to the key-value store.

## Technical details

The cause was that `AutoSaveManager` stored auto-saves in a shared tempstore created with a 30 day expiry. It now uses the plain `keyvalue` service, with three collections defined as constants: `AutoSaveManager::AUTO_SAVE_STORE` (`canvas.auto_save`), `FORM_VIOLATIONS_STORE` (`canvas.form_violations`) and `COMPONENT_INSTANCE_FORM_VIOLATIONS_STORE` (`canvas.component_instance_form_violations`). The constructor changed: the tempstore factory argument is gone, and `keyvalue`, the current user and `TimeInterface` were added.

The shared tempstore used to record the owner and last-updated time. Each auto-save entry now carries `owner` and `updated` itself, set in `saveEntity()` from the current user and request time. `getAllAutoSaveList()` reads from `getAll()` and sorts entries by key. The tempstore lock semantics are gone. The issue thread raised the open question of side effects from losing that lock behavior. `AutoSaveTempStore` and `AutoSaveTempStoreFactory`, along with the factory's service definition, were removed.

Because entries now live in the key-value store indefinitely, they are cleaned up only when an entity's auto-save is published or the entity is deleted (see `ApiAutoSaveController::post()` and `AutoSaveHooks::entityDelete()`). `deleteAll()` now also clears the component instance violations collection. `canvas_post_update_0010_migrate_auto_save()` reads each old tempstore collection and writes its values to the key-value store. It reaches the protected `storage` property of `SharedTempStore` by reflection, because `getAll()` is not public. For the auto-save collection it copies the old `owner` and `updated` values into the entry data. Tests added: `AutoSaveTempstoreToKeyValueUpdateTest` for the migration and `AutoSaveManagerTest::testAutoSaveDoesNotExpire()`, which advances the time past `tempstore.expire`.

## Upgrade

Run database updates (`drush updb`) after updating so `canvas_post_update_0010_migrate_auto_save()` moves existing auto-save data from the shared tempstore to the key-value store. Code that constructed `AutoSaveManager` by hand or used `Drupal\canvas\AutoSave\AutoSaveTempStoreFactory` or `AutoSaveTempStore` must be updated. Both classes are removed.
