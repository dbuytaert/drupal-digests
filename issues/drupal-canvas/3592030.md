# #3592030: Canvas AI: Remove obsolete region-based AI instructions and the unused page variant descriptions form

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592030](https://git.drupalcode.org/project/canvas/-/work_items/3592030) · 1 contributor · 56 comments

## Summary

Canvas moved from theme-global regions (header, footer, sidebar, etc.) to page variants, where everything besides a page's main content is built as its own component tree in the Canvas editor. The Canvas AI module still had leftover instructions and an admin settings page from the old multi-region model, describing a capability that no longer exists. This change removes them: the AI page builder and template builder agents no longer reference regions other than `content`, and the "Page Variant Descriptions" admin settings page (where an admin could describe how AI should treat each page variant) is deleted since nothing read those descriptions anymore. Site owners who had configured page variant descriptions for AI will find that settings page and its data gone; AI-generated pages and templates will only ever place components in the content region, with header, navigation, footer or sidebar sections generated inside that same region only when explicitly requested in the prompt.

## Impact

Affects site owners.

- **Config change:** The `canvas_ai.page_variant.settings` config object and its admin form at `/admin/config/ai/canvas-ai-page-variant-settings` ("Page Variant Descriptions") are removed; update hooks delete any existing config and rebuild routes.

## Technical details

The `[canvas_ai:available_regions]` token is deleted from `CanvasAiHooks::canvas_ai_token_info()`/`canvas_ai_tokens()`, along with `CanvasAiPageBuilderHelper::getAvailableRegions()` and its helpers `resolveVariantForContext()`/`getVariantDescription()`, which used to resolve a page variant via `PageVariantResolver` and pull a per-variant AI description out of `canvas_ai.page_variant.settings`. Both `CanvasBuilder` and `CanvasDevAiBuilder` controllers drop the `available_regions` token context accordingly.

The `canvas_page_builder_agent` and `canvas_template_builder_agent` system prompts (`ai_agents.ai_agent.*.yml`) are rewritten to state that `content` is the only region components can be placed in; `canvas_template_builder_agent`'s description and prompt no longer mention adapting to theme-specific region names, and its YAML output format uses a fixed `content` key instead of `region_name`. `CanvasAiPageVariantSettingsForm`, its route `canvas_ai.page_variant_settings`, its local task, and the `canvas_ai.page_variant.settings` config schema are deleted outright.

Three new update functions land in `canvas_ai.post_update.php`: `canvas_ai_post_update_0012_reimport_region_free_builder_agents()` re-imports just the `system_prompt` (and, for the template builder, `description`) keys of both agents from `config/install` without disturbing other per-site config, and `canvas_ai_post_update_0013_delete_page_variant_settings()` deletes `canvas_ai.page_variant.settings` from every config collection and rebuilds routes. Per the issue's stated scope, the region parameter accepted by the placement tools (`PlaceComponents`, `PlacementOperation`, etc.) and validated via `CanvasAiPageBuilderHelper::getRegionIndex()`/`validateRegionExists()` is left untouched, deferred to a follow-up issue.

## Upgrade

Sites that had customized the `canvas_page_builder_agent` or `canvas_template_builder_agent` system prompts directly will have those customizations overwritten by the update hooks; use the Context Control Center or custom event subscribers to alter agent behavior instead. Any values previously entered in the "Page Variant Descriptions" admin form (`canvas_ai.page_variant.settings`) are deleted and cannot be recovered after update.
