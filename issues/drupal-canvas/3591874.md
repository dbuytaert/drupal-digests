# #3591874: Upgrade the Canvas UI to React Router 7

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)

## Summary

The Canvas module's front-end admin application (the page-building UI) has upgraded its routing library, React Router, from version 6 to version 7. The previous version had known security advisories, so this removes that exposure for sites running Canvas. As part of the upgrade, a bug in the page preview panel was also fixed: in some navigation sequences, a canceled preview page could still be shown if it reported "ready" after the editor had already navigated away and back to it; the preview now correctly waits for the current page's iframe before swapping it in.

## Impact

Affects site owners.

- **Security:** Canvas UI's `react-router`/`react-router-dom` dependency (used by the experimental Canvas/Experience Builder module's admin app) is upgraded from v6, which had known security advisories, to v7.

## Technical details

React Router 7 merges `react-router-dom` into the single `react-router` package, so every import across the Canvas UI (`App.tsx`, `AppRoutes.tsx`, `CodeEditorRouteGuard.tsx`, `ErrorBoundary.tsx`, `ConflictResolutionPage.tsx`, `ReviewChangesPage.tsx`, `useEditorNavigation.ts`, and the related test files) was changed from `react-router-dom` to `react-router`, and `RouterProvider` is now imported from `react-router/dom` in `AppRoutes.tsx`. The five v6 opt-in compatibility flags (`v7_fetcherPersist`, `v7_normalizeFormMethod`, `v7_partialHydration`, `v7_relativeSplatPath`, `v7_skipActionErrorRevalidation`) are removed from `createBrowserRouter`'s `future` option and from `MemoryRouter` usages in tests, since that behavior is now the v7 default.

In `HeadlessPreview.tsx`, the double-buffered preview frame logic was reworked: `activateFrame`'s ref-based check (`currentFrameKeyRef`) against a "newer navigation" was replaced with a `pendingReady` flag on `PreviewFrameState`, set via a new `markFrameReady` callback wrapped in `startTransition`. The promotion from `pending` to `active` now happens inside the existing route-sync `useEffect` (which now also depends on `frames.pendingReady`), so a pending iframe is only promoted if it still matches the currently committed route, preventing a canceled page from being shown if it reports readiness late. The Playwright `CanvasNavigation` helper's preview-wait logic was also updated to wait for visible preview content instead of a full document load, since SPA navigation no longer triggers one.

## Upgrade

Developers extending or patching the Canvas UI's TypeScript/React code should update their own imports:

```ts
// before
import { useNavigate, Outlet } from 'react-router-dom';

// after
import { useNavigate, Outlet } from 'react-router';
```

and, for `RouterProvider` specifically:

```ts
import { RouterProvider } from 'react-router/dom';
```

`react-router-dom` is no longer a dependency; only `react-router` (`^7.18.4`) is required.
