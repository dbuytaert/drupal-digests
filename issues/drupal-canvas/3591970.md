# #3591970: Components library UI is broken if a single component preview rendering fails: treat them as "errored" instead so they cannot be placed but the listing is still functional

- **Project:** Drupal Canvas
- **Type:** Major bug report
- **Version:** 1.x-dev
- **Status:** Fixed
- **Discussion:** [#3591970](https://git.drupalcode.org/project/canvas/-/work_items/3591970) · 1 contributor · 5 comments

## Summary

In Canvas, if a single component's preview render failed (for example, a Views block whose display requires URL arguments that Canvas cannot supply), the entire Components library UI broke and became unusable, blocking editors from placing any component at all. Now such a component is simply marked as "broken" and excluded from placement, while every other component in the library keeps working normally.

## Impact

No upgrade or configuration changes required.

## Technical details

The crash happened in `Component::normalizeForClientSide()`. Previously, only components already known to be broken via `ComponentSourceInterface::isBroken()` were wrapped in a try/catch; components that passed that check but then threw during `getClientSideInfo()` or during `RendererInterface::renderInIsolation()` were not caught, so an uncaught `\Throwable` bubbled up and turned the whole `ApiConfigControllers::list()` response into a 500, taking down the entire library listing.

The fix unifies both code paths (the "known broken" branch and the "renders preview" branch) under a single `try`/`catch (\Throwable $e)` block, so any crash during preview building or rendering is now caught and converted into a per-component "broken" state via `RenderSafeComponentContainer::handleComponentException()`, rather than propagating. `EnforcedResponseException` and `FormAjaxException` are explicitly re-thrown rather than swallowed, since those are Drupal Form API flow-control exceptions that must keep bubbling (noted as a workaround pending [#2367555](https://www.drupal.org/node/2367555)). A related `@todo` references [#3521041](https://www.drupal.org/node/3521041) for eventually simplifying the `RenderSafeComponentContainer` wrapping logic itself.

Test coverage was added: `CanvasTestBlockInputValidatableCrash` gained a static `$forceCrash` flag so a block can be made to crash unconditionally (mirroring a Views-backed block crashing while building its preview), and `BlockComponentTest::testCrashingPreviewDoesNotBreakComponentList()` asserts that the crashing component is reported with `broken => TRUE` and a "Component failed to render" message, while unrelated components in the same listing remain present and `broken => FALSE`.</technical>
