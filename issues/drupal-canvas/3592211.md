# #3592211: Workspaces PR 1: retire the 1.x external-edit conflict detection

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592211](https://git.drupalcode.org/project/canvas/-/work_items/3592211) · 1 contributor · 3 comments

## Summary

Canvas removes the experimental 1.x conflict detection that was enabled by the `canvas_dev_cd` module. That flow detected when an entity was saved outside Canvas after an auto-save, then blocked publishing and offered a `/conflict` resolution page. It is replaced by core's Workspaces `EntityWorkspaceConflict` lock, planned in a later step of the Workspaces work. This step targets the `1.x-workspaces` branch. Sites that never installed `canvas_dev_cd` should see no change. The pending-changes endpoint now always returns 200 for conflict purposes, and validation errors are always 422.

## Impact

Affects module maintainers.

- **API change:** Removed `AutoSaveManager` conflict methods and the `with_conflicts` argument of `getAllAutoSaveList()`, removed `ErrorCodesEnum` codes 4, 5 and 6, dropped `resolved_conflict_id` from the auto-save PATCH, and API errors are always 422, never 409.
- **Deprecation:** The `canvas_dev_cd` module is marked hidden and obsolete, and its conflict detection and resolution flow is removed.

## Technical details

This is the first step of the Workspaces plan (work item 3592187). It removes the hash-based flow, where an auto-save stored `original_hash` and a mismatch triggered a conflict. The issue body, not a verified diff, is the source for the details below.

Back end: the `canvas_dev_cd` module is hidden and marked obsolete. `ConflictResolutionOutcomeEnum` and `AutoSaveEntityConflictConstraint` are deleted. Codes 4, 5 and 6 are removed from `ErrorCodesEnum`. `ApiControllerBase` always returns 422 and never 409. The auto-save PATCH controller drops `resolved_conflict_id` and takes `status` only. `ApiExceptionSubscriber` loses its conflict-constraint branch. `AutoSaveManager` loses `AUTO_SAVE_CONFLICT_KEY`, `AUTO_SAVE_STORED_ENTITY_HASH_KEY`, `getUnresolvedConflict()`, `getConflictId()`, `getUnresolvedConflictForEntity()`, `resolveConflict()`, `setStoredEntityHash()` and the `with_conflicts` argument of `getAllAutoSaveList()`. The callers in `ConfigAuditBase`, `Inventory` and `PageVariant` are updated. `ApiAutoSaveController` drops `autoSaveListHasConflicts()`, the 409 branch of `get()` and `getConflictAwareContentEntityViolations()`. `canvas_post_update_0026` now writes the literal `'original_hash'` key because the constant is gone. The `devConflictDetectionMode` setting is dropped from `DrupalSettings.ts` and `CanvasController`.

UI: the `ui/src/features/conflict/*` code, conflict notifications, `ConflictBanner`, the `/conflict` route and conflict state in the change list components are removed. `isReviewUxEnabled()` in `ui/src/features/review/reviewChanges.ts` is now gated on `devMode` instead of `canvas_dev_cd`, so the side-by-side review page still works for developers. The related tests are removed, including `testPatchConflictResolution` and the Playwright `conflictResolution.spec.ts`. The issue gives the size as about 30 lines added and 3,900 removed.

## Upgrade

Code that used `canvas_dev_cd`, a 409 response from GET `/auto-saves/pending`, error codes 4, 5 or 6, or `resolved_conflict_id` in the auto-save PATCH must stop depending on them. Code calling `AutoSaveManager::getAllAutoSaveList()` should drop the `with_conflicts` argument.
