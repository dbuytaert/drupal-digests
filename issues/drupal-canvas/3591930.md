# #3591930: Apply brand kit colour changes optimistically

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591930](https://git.drupalcode.org/project/canvas/-/work_items/3591930) · 1 contributor · 6 comments

## Summary

Editing or adding a brand kit colour in the Canvas editor now updates the swatch right away instead of waiting for the server. The form closes on save, and the editor reverts the change if the server rejects it. The colour change also reaches the page preview while the editor stays open, which didn't happen before. This also fixes colour edits not showing when a brand kit auto-save draft existed, for example after a font edit.

## Impact

No upgrade or configuration changes required.

## Technical details

The changes are all in the `ui/` React app. In `ui/src/services/brandKit.ts`, `updateColor` and `createColor` now patch the `getBrandKit` cache entry in `onQueryStarted` through a `patchColors()` helper, and call `patchResult.undo()` if the request fails. Each patch mutates a single colour in place, so undoing it cannot revert an edit to a different colour. `updateColor` also records a `Symbol` token per colour id in `latestColorWrites`. It rolls back only if its token is still the newest for that id, so a slow failing request cannot overwrite a later edit. `createColor` inserts a temporary row with a `pending-<uuid>` id and swaps in the server's row when the response arrives. It does not mint the final UUID on the client, which the issue body proposed. The invalidated tag changed from the literal `'global'` to `BRAND_KIT_ID`.

`useBrandKitColors` now reads colours only from the canonical `getBrandKit` entry and no longer prefers the auto-save draft. The hook uses `data` instead of `currentData`, so optimistic patches stay visible during the refetch triggered by invalidation. The local `colors` state and `setColors` are removed. `BrandKit.colors` becomes optional in the type.

`ColorFormPopover` dispatches the mutation, then closes the popover. On failure it reopens through `reopenOnFailure()`, keeping the entered values and the error. For the preview, `Viewport` builds CSS custom properties from the live brand kit with `buildColorStyles`. It passes them to `IframeSwapper` as a new required `headStyles` prop. `IframeSwapper` injects them as a `<style id="canvas-preview-head-styles">` block at the end of `<head>`. It updates already-loaded iframes in place and re-applies the block when a new preview iframe finishes loading.
