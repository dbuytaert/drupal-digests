# #3592085: Canvas AI: Let the user stop a running chat turn

## Summary

In the Canvas AI dev chat (`AiWizardDev`), the user can now stop the agent while it is working. A stop button shows only during a running turn. Pressing it drops the in-flight request, stops applying further placements or edits, clears the loader, and unlocks the input and Tools selector. The chat adds the assistant message "You interrupted the agent. What would you like to change?" and the progress row shows a neutral stopped icon, not the completed check. Work already applied to the page stays, and the user can undo it from the editor. The next message starts a fresh turn and does not resume the stopped one. The server is not interrupted: PHP already running finishes its current step. The original non-dev `AiWizard.tsx` is untouched.

## Impact

Affects module maintainers.

- **API change:** `CanvasAiTempStore::getStoredConversationState()` now requires a `$request_id` argument. `setStoredConversationState()` now takes `$request_id` as its second argument and an optional `$resumed_request_id` as its last. The dev AI endpoint reads a new `last_successful_request_id` prompt key.
- **New API:** New `last_successful_request_id` field in the dev AI request payload, naming the checkpoint the next turn resumes.

## Technical details

The fix is in `AiWizardDev.tsx` and `CanvasDevAiBuilder`, in `canvas_dev_ai`. The client keeps a per-turn `stopped` flag that the hop loop and the placement and edit batches check (`isStopped()`), and it aborts the fetch. This is needed because aborting alone only rejects the current request.

A stopped turn can still finish on the server and write its agent state. If the next turn resumed that state, it could send an unrun tool call back to the model. To prevent this, the client now sends `last_successful_request_id` with every hop. This is the last turn that was fully applied and not stopped. `CanvasDevAiBuilder::prepareAgent()` resumes only the checkpoint stored under that request ID, and otherwise seeds the agent from the client transcript. A stopped turn is never named, so it is never resumed.

`CanvasAiTempStore` conversation state is now a map keyed by request ID. It holds at most two entries: the checkpoint the current turn resumed from, and the one it wrote. Older entries, including those from stopped turns, are dropped on the next write. When `keep_tool_calls_in_history` is off, or the turn fails or is not solvable, all checkpoints are deleted. `placementUtils.ts` was also changed so placements can be cut short when a stop lands.

## Upgrade

Callers of the `CanvasAiTempStore` conversation methods must now pass request IDs:

```php
$store->getStoredConversationState($conversation_id, $request_id);
$store->setStoredConversationState($conversation_id, $request_id, $agent_id, $state, $resumed_request_id);
```

Clients of the dev AI endpoint should send `last_successful_request_id` in the prompt payload. Without it the turn is seeded from the transcript.
