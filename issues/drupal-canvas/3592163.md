## Summary

Canvas AI now ships the new client-side orchestrated chat and is no longer hidden, so it can be enabled normally. New sites get the new chat when they install Canvas AI. Existing sites that already have Canvas AI get a new deprecated module, `canvas_ai_legacy`, installed by the update. It holds the old orchestrator agents and tools, so the existing chat keeps working with any customizations kept. While it is installed, the chat shows a legacy warning that links to the change record ([#3628747](https://www.drupal.org/node/3628747)), and the deprecated agents' edit forms show a deprecation warning. To switch to the new chat, uninstall `canvas_ai_legacy`. This deletes the five legacy agents, including any changes made to them. On sites that deploy configuration, export after the updates and again after uninstalling.

## Impact

Affects module maintainers and site owners.

- **Database update:** `canvas_ai_update_11200()` installs `canvas_ai_legacy`; post-updates `0015` and `0016` set legacy agent dependencies and install the new agents and settings.
- **Config change:** `main_agent`, `tools` and `keep_tool_calls_in_history` move from `canvas_dev_ai.settings` to `canvas_ai.settings`; `canvas_agent` and `drupal_canvas_page_agent` now ship in `canvas_ai/config/install`; the five legacy agents are now enforced on `canvas_ai_legacy`.
- **API change:** Route `canvas_ai.canvas_builder` renamed to `canvas_ai.builder`; route `canvas_ai.get_progress` removed from `canvas_ai` (now `canvas_ai_legacy.get_progress` at `/admin/api/canvas/ai-progress-legacy`); token `[canvas_dev_ai:available_tools]` is now `[canvas_ai:available_tools]`.
- **Deprecation:** The orchestrator-based Canvas AI agents (`canvas_ai_orchestrator`, `canvas_page_builder_agent`, `canvas_template_builder_agent`, `canvas_title_generation_agent`, `canvas_metadata_generation_agent`) are deprecated and moved to `canvas_ai_legacy`.
- **New API:** New deprecated module `canvas_ai_legacy` with route `/admin/api/canvas/ai-legacy`; new Agents & Tools form at `/admin/config/ai/canvas-ai-agent-selection` in Canvas AI.

## Technical details

The code that was in the hidden `canvas_dev_ai` module moved into `canvas_ai`: the `canvas_agent` and `drupal_canvas_page_agent` agents (in `config/install`, enforced on `canvas_ai`), the `main_agent`, `tools` and `keep_tool_calls_in_history` settings (now in `canvas_ai.settings` with schema), the `CanvasAiAgentSelectionForm` as an "Agents & Tools" tab, and the chat controller, which is merged into `CanvasBuilder` at `/admin/api/canvas/ai`. `canvas_ai_install()` sets `main_agent` and `tools` in code rather than in `config/install`, because simple config is saved before the module's config entities exist and the `ConfigExists` constraints would fail (see core [#3425992](https://www.drupal.org/node/3425992)). `canvas_dev_ai` is left only to set the `aiDevMode` flag.

The legacy chat controller is now `CanvasAiLegacyBuilder` in `canvas_ai_legacy`, serving `/admin/api/canvas/ai-legacy` and `/admin/api/canvas/ai-progress-legacy`. The legacy agents are in that module's `config/optional`, with their enforced module dependency changed from `canvas_ai` to `canvas_ai_legacy`, so uninstalling the module removes them. Existing `canvas_ai` post-updates that reimport agent config now read from `canvas_ai_legacy/config/optional`. `canvas_component_agent` stays in Canvas AI because the new chat uses it too. The legacy UI code (`AiWizard.tsx`) stays in the Canvas UI package. While `canvas_ai_legacy` is installed, the new agents installed by post-update `0016` have no effect.

## Upgrade

Existing sites run the updates; no manual step is needed to keep the legacy chat:

```
drush updb
```

This runs `canvas_ai_update_11200()`, which installs `canvas_ai_legacy`, then post-updates `canvas_ai_post_update_0015_enforce_legacy_agent_dependency()` and `canvas_ai_post_update_0016_install_chat_agents()`.

To switch to the new chat (this deletes the five legacy agents):

```
drush pm:uninstall canvas_ai_legacy
```

Custom code or config that references `canvas_dev_ai.settings`, the `[canvas_dev_ai:available_tools]` token, or the route `canvas_ai.canvas_builder` or `canvas_ai.get_progress` must be updated to `canvas_ai.settings`, `[canvas_ai:available_tools]`, `canvas_ai.builder`, or `canvas_ai_legacy.get_progress`.
