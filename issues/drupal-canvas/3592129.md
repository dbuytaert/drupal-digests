# #3592129: CanvasOauthAuthenticationProvider does not allow OAuth authentication on the folder config entity external API route

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592129](https://git.drupalcode.org/project/canvas/-/work_items/3592129) · 1 contributor · 5 comments

## Summary

Sites using the `canvas_oauth` module together with the Canvas CLI (`@drupal-canvas/cli`) could not sync folders or page templates via `npx canvas pull` when using OAuth2 client-credentials authentication. The request to fetch folder configuration was rejected with "The used authentication method is not allowed on this route," even though the OAuth client had the correct permissions. This is now fixed: OAuth2 bearer-token authentication is accepted on the folder config entity API route, matching how it already worked for components, JavaScript components, asset libraries, brand kits, content templates, and page variants.

## Impact

No upgrade or configuration changes required.

## Technical details

`CanvasOauthAuthenticationProvider::applies()` gates OAuth2 authentication on Canvas's external config entity API routes using an explicit `$protected_config_entity_types` allowlist. `Folder::ENTITY_TYPE_ID` had been omitted from that list, so for requests to `/canvas/api/v0/config/folder` the provider's `applies()` returned `FALSE`, the `simple_oauth` delegation never ran, and Drupal core's `AuthenticationSubscriber` rejected the bearer token as not allowed on that route, even though `folder` is a valid HTTP-API-eligible config entity type per the `canvas_config_entity_type_id` route requirement.

The fix simply adds `Folder::ENTITY_TYPE_ID` to the allowlist alongside the existing entries. The corresponding kernel test case in `CanvasOauthAuthenticationProviderTest` was updated from expecting `FALSE` to `TRUE` for the folder entity type to cover this route.</technical>
