# #3591885: Add `document` object $ref for linking locally hosted documents

- **Project:** Drupal Canvas
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3591885](https://git.drupalcode.org/project/canvas/-/work_items/3591885) · 1 contributor · 6 comments

## Summary

Drupal Canvas code components and Single Directory Components (SDCs) can now declare a "document" prop, the same way they already can for image and video. A component that accepts a `document` (or an array of them) gets a file upload widget for content authors, or the Media Library picker when Media Library is enabled and a compatible media type exists, and receives the document's URL, title, filename, size, and MIME type. This was split off from the broader video/embed proposal in [#3524130](https://www.drupal.org/node/3524130) because linking a local document has no dependency on the postponed core oEmbed work, unlike remote video.

## Impact

Affects module maintainers.

- **New API:** New `document` object shape (`json-schema-definitions://canvas.module/document`) that code components and SDCs can `$ref` to declare a document/file-download prop with `src`, `title`, `description`, `filename`, `filesize`, and `mimetype`.

## Technical details

The new shape is defined in `schema.json` as `document`, requiring only `src` (a `uri-reference` restricted to `http`/`https` via `x-allowed-schemes`) and adding an `x-allowed-file-extensions` annotation listing common office and document formats. It is registered as `JsonSchemaObjectRef::Document` and added to the `Choice` constraint in `config/schema/canvas.json_schema.yml` alongside `image` and `video`.

Storage matching is handled in `JsonSchemaType::computeStorablePropShape()`, which maps `Document` to a `file` field (`fieldWidget: file_generic`) with `src`, `filename`, `filesize`, and `mimetype` resolved from the referenced File entity's `uri`, `filename`, `filesize`, and `filemime`; the field's `file_extensions` instance setting is derived from the shape's `x-allowed-file-extensions` list via the new `JsonSchemaObjectRef::allowedFileExtensions()`. `title` and `description` are left unmapped because a plain file field exposes neither.

To support Media Library, the media-source-to-schema mapping (previously a private array and method inside `ShapeMatchingHooks`) was extracted into a new internal `MediaSourceObjectShapes` class shared by both the media library integration and `EntityFieldPropSourceMatcher`. It maps `Document` to `\Drupal\media\Plugin\media\Source\File`, matching any media type whose source is `File` (but not a more specific subclass like `VideoFile`) and whose source field's allowed extensions intersect the shape's list; this intersection logic is carried by a new no-op `UriTargetFileExtensionsConstraint`/validator pair, mirroring how `UriTargetMediaTypeConstraint` narrows matches by MIME type. `EntityFieldPropSourceMatcher` gained `matchDocumentShapeToMediaTypes()` to also suggest existing single-value media reference fields pointing at compatible media types, one reference level deep. Embedding or previewing the document, and remote-video support, remain out of scope, per the split from [#3524130](https://www.drupal.org/node/3524130) and the still-postponed [#3567249](https://www.drupal.org/node/3567249).
