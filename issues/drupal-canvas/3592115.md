## Summary

Drupal Canvas's headless frontend tooling now supports Angular. A new `@drupal-canvas/headless-angular` adapter package and an experimental Angular starter template join the existing Next.js, Astro, Nuxt and TanStack Start integrations offered through Canvas Create. Developers can now build headless Angular 21 or 22 apps that render Canvas's component trees with server-side rendering and hydration, named slots, component discovery, and full support for Canvas's draft preview and publishing workflow. The starter defaults to Angular 22 and documents Angular 21 setup; Angular Workbench integration is explicitly out of scope for now.

## Impact

Affects module maintainers.

- **New API:** New `@drupal-canvas/headless-angular` package providing Angular 21/22 bindings (component-tree rendering, SSR/hydration, draft-preview server endpoints, and a `canvas-angular` codegen tool) for building headless Canvas frontends, plus a new experimental `angular` starter template in Canvas Create.

## Technical details

The new `@drupal-canvas/headless-angular` package mirrors the structure of the other framework adapters and builds on the shared, framework-agnostic `@drupal-canvas/headless` core (its `client`, `server`, `components-endpoint`, and `component-registry` submodules). It exposes:

- Rendering primitives (`CanvasComponentTree`, `CanvasElement`, `CanvasSlot`, `CanvasChildren`, `CanvasMarkerDirective`, `CanvasMarkup`) built on Angular signals and `NgComponentOutlet`, which walk the component tree, resolve named slots against a `CanvasComponentRegistry`, and emit the `data-canvas-*` marker templates used by the visual editor.
- An application layer (`CanvasPageStore`, `canvasPageResolver`, `CanvasDraftSession`, `CanvasDocumentHead`, `provideCanvas()`) that wires page data into Angular's router (via a resolver and `TransferState` for hydration), manages the draft-session/renewal state machine, and syncs `<head>` metadata.
- A server layer (`createCanvasHandler`, `createCanvasRequest` in `@drupal-canvas/headless-angular/server`) implementing the same REST-style endpoints as the other adapters (`/api/draft`, `/api/draft/renew`, `/api/disable-draft`, `/api/canvas/components`, `/api/canvas/page`, `/api/canvas/entity`), enforcing private/no-store caching, CSP `frame-ancestors` merging for embedded previews, and an explicit allowlist (`CanvasSession`) so tokens and PKCE verifiers never cross into the browser-visible `TransferState`.
- A `canvas-angular` CLI/tooling script that generates a browser-safe component registry module and a server-only metadata manifest module, meant to run before `ng serve`/`ng build`, analogous to the codegen used by the other adapters.

The package targets Angular's partial compilation output (verified by a build test asserting `ɵɵngDeclareComponent` rather than `ɵɵdefineComponent` in the built bundle) so it can be consumed by both Angular 21 (TypeScript 5.9) and Angular 22 (TypeScript 6) host apps via matching peer dependency ranges.

On the tooling side, `templates.json` in `canvas-headless-templates` gains an `angular` entry (marked `experimental`, sourced from a separate `drupal-canvas/headless-templates` GitHub repo), and Canvas Create's `SetupSection` framework picker now lists Angular alongside the four existing frameworks.</technical>
