## Summary

Headless SDK clients now work on Drupal sites that serve JSON:API from a prefix other than `/jsonapi` (for example `/api`), without extra configuration. The SDK asks the site for its prefix automatically. To support this, the Canvas `site-data` endpoint is now readable by anonymous users, and `getPublicClient()` and `getDraftClient()` became async.

## Impact

Affects module maintainers and site owners.

- **Config change:** New optional `CANVAS_JSONAPI_PREFIX` environment variable (or `apiPrefix` config override) used as fallback JSON:API prefix.
- **Permission change:** Route `canvas.api.site_data` (`/canvas/api/v0/site-data`) is now public (`_access: 'TRUE'`) instead of requiring Canvas UI access and authentication.
- **API change:** `getPublicClient()` and `getDraftClient()` on the draft server now return `Promise<JsonApiClient>` and must be awaited.
- **New API:** `createApiPrefixResolver()` exported from the headless draft server package; `DraftConfig` gains optional `apiPrefix`.

## Technical details

A new `createApiPrefixResolver()` in `site-data.ts` fetches `/canvas/api/v0/site-data` once per draft server instance and reads `jsonapiSettings.apiPrefix`. The in-flight promise is cached, so concurrent callers share a single fetch. If the response is not OK or the fetch throws, it logs a warning and returns the configured fallback prefix. If `jsonapiSettings` is null (JSON:API not installed), it returns `undefined` and the client keeps its `/jsonapi` default.

`resolveDraftConfig()` now accepts an `apiPrefix` override or reads `CANVAS_JSONAPI_PREFIX`, trimming leading and trailing slashes. `createDraftServer()` resolves the prefix inside `getPublicClient()`, `getDraftClient()` and `getClient()`, which is why the first two now return promises. The prefix is passed to `JsonApiClient` as `apiPrefix`. Configuration is read lazily at client access, not at server creation.

On the Drupal side, the `canvas.api.site_data` route in `canvas.routing.yml` moves from `_canvas_authentication_required` and `_canvas_ui_access` to `_access: 'TRUE'`. The route is also removed from the named routes in `CanvasOauthAuthenticationProvider`. A docblock on `SiteDataController` warns not to add data that is not already exposed via `drupalSettings` on public pages. `DxRouteConsistencyTest` now whitelists this route as intentionally public. Changesets mark `@drupal-canvas/headless` and the `headless-next` and `headless-tanstack-start` packages as minor bumps, and the framework READMEs document the behavior.

## Upgrade

Await the client getters:
```ts
const client = await server.getPublicClient();
const draftClient = await server.getDraftClient(draftData);
```
To set the fallback prefix for when the site-data endpoint is unreachable, set `CANVAS_JSONAPI_PREFIX=api` or pass `apiPrefix: 'api'` in the config override.
