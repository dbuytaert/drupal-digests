## Summary

When Canvas AI's page builder agent places a Block component (for example the Site Branding block), it can now see and set that block's actual configuration options instead of just its id and label. Previously the agent only received a block's id, name, and description, so it either produced validation errors when trying to place blocks with required settings, or the values it tried to set (like `use_site_logo` or `use_site_name`) were silently dropped and the block was always placed with its default configuration. Now the "Get component context" tool includes each block's available properties (name, description, type, default value, required flag, and allowed choices where applicable), so the agent can configure blocks correctly. Internal-only settings that have no effect on the rendered block (`id`, `provider`, `admin_label`, `context_mapping`) are still left out.

## Impact

Affects module maintainers and site owners.

- **Config change:** Sites with previously saved block descriptions in `canvas_ai.component_description.settings` have that config automatically rebuilt by `canvas_ai_post_update_0007_add_block_props_to_component_description_settings()` to include the newly exposed props, while any custom-edited descriptions are preserved.
- **New API:** New public `CanvasAiPageBuilderHelper::getEnabledBlockComponentsFromStorage()` returns enabled block components with prop metadata, loaded directly from storage independent of the current user's access, for use by update hooks and other server-side code.

## Technical details

`CanvasAiPageBuilderHelper::getAllComponentsKeyedBySource()` previously only branched into rich prop extraction for SDC and JS component sources (`processSdc()`, `processCodeComponents()`); everything else, including Block components, fell into a generic branch that emitted only `id`/`name`/`description`. A new `processBlock()` method now builds prop metadata for blocks by reading the block's config schema definition (`block.settings.<plugin_id>`) via the newly injected `TypedConfigManagerInterface`, mapping each schema key to a prop with `name`/`description` (from the schema label), `type`, `default` (preferring the component's saved `default_settings` over the schema default), a `required` flag (true unless the schema marks `requiredKey === FALSE`), and `enum` values pulled from any `Choice` constraint. Keys that Canvas can't act on (`id`, `provider`, `admin_label`, `context_mapping`, the latter because Canvas doesn't apply context mappings at render time) are filtered out via `isBlockPropExcluded()`.

Because the AI update path (`drush updb`) runs as the anonymous user, and the access-checked component listing returns nothing in that context, a new public `getEnabledBlockComponentsFromStorage()` method loads enabled block components directly from the `Component` storage instead. It backs a new `canvas_ai_post_update_0007_add_block_props_to_component_description_settings()` hook that rebuilds any previously saved `canvas_ai.component_description.settings` block data with the new prop structure, re-layering each block's previously customized `description` text on top of the rebuilt data.

Two related bugs surfaced by the missing propSources on blocks were also fixed: `AiResponseValidator::validateComponentStructure()` dereferenced `$clientNormalized['propSources']` unconditionally, which is unset for blocks, now guarded with `?? []`; and the UI's `removeMediaFields()` (used by `AiWizard.tsx` when placing AI-suggested components) now short-circuits with `isPropSourceComponent()` since block component definitions have no `propSources` to filter.

## Upgrade

Code integrating with Canvas AI's page builder helper can now fetch block component prop data directly from storage, independent of the current user's permissions:

```php
$blocks = \Drupal::service('canvas_ai.page_builder_helper')
  ->getEnabledBlockComponentsFromStorage();
```

Sites that previously saved custom block descriptions via the component description settings form will have that config automatically migrated by the `canvas_ai_post_update_0007_add_block_props_to_component_description_settings()` update hook; no manual action is required.
