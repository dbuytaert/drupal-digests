# #3592096: Headless preview of homepage drafts can serve stale published content from cache

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)

## Summary

When previewing a homepage draft (or other auto-saved changes) on a site configured for headless delivery through Canvas, the preview could show stale, already-published content instead of the draft. This happened when a shared cache or CDN sat in front of the site's content API: it didn't distinguish between an anonymous published request and an authenticated preview request carrying a draft token, so it could serve the cached published response to the editor's preview. Canvas's content API responses now vary caching by the request's authorization credentials, so shared caches treat preview requests separately from published ones and editors reliably see their draft content.

## Impact

No upgrade or configuration changes required.

## Technical details

In `CanvasContentResponseSubscriber` (`modules/canvas_headless/src/EventSubscriber/CanvasContentResponseSubscriber.php`), a new `addAuthorizationVary()` listener is registered on `kernel.response` at priority `-12`, running after core's `FinishResponseSubscriber` (which sets the default `Cookie` vary context) and after Canvas's own `convertRedirect` (`-11`). For any main-request response matching `isContentApiRequest()`, it calls `$response->setVary('Authorization', replace: FALSE)`, appending `Authorization` to whatever `Vary` header is already present rather than overwriting it.

Since preview/auto-save requests present the draft token as a bearer credential in the `Authorization` header, this makes shared caches (CDNs, reverse proxies) key their cached copies per `Authorization` value, so they no longer serve an anonymous published response to a token-carrying preview request. The accompanying test additions in `CanvasContentResponseSubscriberTest` exercise this against a real dispatcher wired with core's `FinishResponseSubscriber`, covering combinations of `omit_vary_cookie`, pre-existing custom `Vary` values, subrequest-to-main-request response reuse, private (non-cacheable) responses, and converted redirect responses, confirming `Authorization` is always appended without dropping other Vary values.
