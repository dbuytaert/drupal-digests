## Summary

In Canvas 1.x, asking Canvas AI to create a code component from `/canvas` failed with "Unable to read the page layout. Please reload the page and try again." because the AI request was rejected whenever the editor sent no page layout regions. That blanket check is removed, so code component requests now go through. Agents that really need page regions now report a missing layout themselves.

## Impact

No upgrade or configuration changes required.

## Technical details

In `CanvasAiLegacyBuilder`, the early return for an empty `current_layout.regions` is removed. The layout is now written to `CanvasAiTempStore` under `CURRENT_LAYOUT_KEY` only when regions exist. Otherwise the key is deleted with `deleteData()`, so a layout left from an earlier request can't leak into a request without one.

The region check moved to where regions are actually needed: `CanvasAiPageBuilderHelper::validateRegionExists()` returns a message when the layout has no regions at all ("Unable to read the page layout: no regions were sent. Do not retry; tell the user to reload the page and try again."). Previously that case produced the misleading "Region ... does not exist" text. Kernel tests in `CanvasAiBuilderControllerTest` now assert the controller doesn't refuse such requests and that only a layout with regions is stored, and a new `testValidateRegionExists` covers the helper.
