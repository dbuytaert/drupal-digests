# #3592001: Apply page variant translation overrides to previews

- **Project:** Drupal Canvas
- **Type:** Critical feature request
- **Status:** Fixed
- **Discussion:** [#3592001](https://git.drupalcode.org/project/canvas/-/work_items/3592001) · 1 contributor · 7 comments

## Summary

In Drupal Canvas, when a `PageVariant` (or a page region) has a config translation, the translated text never showed up in the editor's own preview of that variant, and it also failed to show up in the page chrome wrapped around content previews whenever the page variant had an unsaved auto-save draft. Switching the language dropdown in the editor, or opening a preview URL with a language parameter, kept showing the original base-language text even though the live front end correctly rendered the translation. This made the editor's language switcher effectively non-functional on those two preview surfaces. The fix makes both preview paths apply the language's translation override before rendering, so what editors see in preview now matches what visitors actually see on the live site.

## Impact

No upgrade or configuration changes required.

## Technical details

Canvas intentionally keeps its client model and PATCH operations on untranslated base config; translation is meant to surface only at preview/render time, driven by the requested preview language. Two rendering paths were missing that step. `ApiLayoutController::buildPreviewRenderable()` built the preview straight from the upcast base entity's component tree via `componentTreeLoader`, never consulting any `LanguageConfigOverride`. `CanvasPageVariant::buildPageVariant()`, when a valid auto-save draft exists, renders that draft's tree, but drafts live in key/value storage outside the config system, so a `LanguageConfigOverride` structurally cannot apply to them, leaving the chrome permanently base-language whenever a draft was present.

Both fixes reuse the existing `ComponentTreeConfigEntityBase::getTranslatedComponentTree()`, which merges the base tree (including a draft's tree) with a language's override. In `ApiLayoutController`, the current interface language (from the newly injected `LanguageManagerInterface`) is checked against `$entity->getTranslationLanguages(include_default: FALSE)`; if it has a stored override, the merged tree is used instead of the raw one, and the render array gets a `languages:interface` cache context added (no separate cache tag is needed since the override shares the base config's cache tag). `CanvasPageVariant` gets a new private `getPreviewComponentTree()` helper that does the same check and is used by both `buildPageVariant()` and the legacy-regions rendering path, but only when `$is_preview` is true; live (non-preview) rendering is untouched. `LanguageManagerInterface` was added to the plugin's constructor via `create()`.</technical>
