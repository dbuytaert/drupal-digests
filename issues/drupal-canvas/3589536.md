## Summary

Code components in Canvas can now declare a prop that holds a list of referenced entities, not just a single one. Previously a multi-value entity reference field could not be used for a `content-entity-reference` prop, and referenced entities past the first would be dropped. A site builder can now pick a multi-value reference field (for example "related news items") and the component receives all the referenced entities in order.

## Impact

Affects module maintainers and site owners.

- **Config change:** `canvas.js_component.*` schema now accepts an array-of-references form for props; the `MultiValuedFieldNotSupported` constraint was removed.
- **New API:** Code component props may be `type: array` with `items` set to the `content-entity-reference` shape (optional `maxItems`), resolving to an ordered array of entity payload objects.

## Technical details

A list prop is declared as `type: array` with `items` being the `content-entity-reference` object shape, plus `x-allowed-entity-type-id` / `x-allowed-bundle` on `items` and an optional `maxItems`. `JsonSchemaObjectRef` gained `isContentEntityReferenceObject()` and `isContentEntityReferenceObjectList()`; `isContentEntityReference()` now matches both. `JavaScriptComponent::toSdcDefinition()` puts the `x-allowed-*` keys on `items` for lists, and `isContentEntityReferenceObjectListProp()` was added. `ComponentMetadataRequirementsChecker` applies the existing rules to both forms, so these props must still be optional and `minItems` is never allowed.

`EntityFieldPropSourceMatcher::matchContentEntityReferenceShape()` now takes the prop cardinality (1, or `maxItems`, or unlimited) and applies the same rule as scalar props, extracted to `fieldCardinalityMatchesJsonSchemaCardinality()`: a single reference matches only single-value fields; a list matches multi-value fields whose cardinality is at most `maxItems`, and an unlimited list accepts only an unlimited field. So a list is never truncated at render time. `JsComponent::getExplicitInput()` builds a list payload via `buildReferenceListPayload()` for list props and `buildReferencePayload()` for single ones; leaves on multi-valued fields with no delta yield arrays of values. `HostEntityPropSource` is never suggested for lists.

The `MultiValuedFieldNotSupported` constraint and validator were removed from the `canvas.js_component.*` config schema, and `ApiUiContentEntityReferenceControllers` no longer hides multi-valued fields from the picker. Docs (`docs/shape-matching.md`) describe the payload shapes and list three open todos ([#3592326](https://www.drupal.org/node/3592326), [#3592322](https://www.drupal.org/node/3592322), [#3592323](https://www.drupal.org/node/3592323)) around inaccessible or deleted referenced entities and empty-array output. The JS preview now omits a single reference prop from preview props when it has no value.

## Upgrade

To use the new form in a code component:
```yaml
featured_articles:
  type: array
  maxItems: 3
  items:
    type: object
    $ref: json-schema-definitions://canvas.module/content-entity-reference
    x-allowed-entity-type-id: node
    x-allowed-bundle: article
```
Existing single-reference props are unchanged.
