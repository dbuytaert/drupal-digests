# #3592090: Support multilingual previews in Canvas Headless

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592090](https://git.drupalcode.org/project/canvas/-/work_items/3592090) · 1 contributor · 4 comments

## Summary

Canvas Headless read-only previews (for pages, content templates, and page templates) now show the translation selected in Canvas's language switcher instead of always rendering the default language. Previously, a headless frontend's read-only preview ignored the language picked in Canvas and always showed one language's content. The editable editor iframe is unaffected: this only changes the separate, read-only preview shown alongside it.

## Impact

Affects module maintainers.

- **API change:** Canvas Headless content API gains an optional `language` query parameter (preview-scoped only) and may respond with a same-origin, non-cacheable HTTP 302 transport redirect during language negotiation; a new `PreviewLanguageSubscriber` service and `PreviewLanguageRedirectResponse` class were added to `canvas_headless`.

## Technical details

The Canvas content API (`/canvas/content-api`) gained a `language` query parameter, honored only for preview-scoped tokens. `CanvasContentEntityRenderer` now accepts a `preview_language` argument and, via the new private `previewComponentTree()` helper, swaps in `getTranslatedComponentTree()` when the requested language has a translation, falling back to `getComponentTree()` otherwise (mirroring how the coupled/embedded preview already merges page variant translation overrides and, for content templates, an auto-saved draft tree cloned and re-populated with the translated tree before rendering).

Since Drupal's language negotiation (prefixes, sessions, domains) normally happens during routing rather than being settable per-request, a new `PreviewLanguageSubscriber` runs early (priority 250, after auth/language init, before routing) and, when the negotiated content language doesn't match the requested preview language, issues a single same-origin, non-cacheable HTTP 302 (`PreviewLanguageRedirectResponse`) back to the content endpoint with a language-specific `requestUri`, computed via `Url::fromUri()` and `LanguageManagerInterface::getLanguageSwitchLinks()`. Only one redirect hop is allowed (tracked via the `_canvas_headless_language_redirect` internal query flag); if negotiation still doesn't match after that hop, or cross-domain negotiation would be required, the endpoint returns 404 rather than looping or silently rendering the wrong language. An unknown language passed when minting the signed preview assertion (in `AssertionController::previewContext()`) returns 400.

On the frontend, `@drupal-canvas/headless`'s `fetchPage()` forwards the selected `language` from `previewContext` only while the draft session is live, and follows the transport redirect using the same bearer credential, but only when it stays same-origin (never forwarding the token cross-domain). `@drupal-canvas/headless-host` retains the preview language across draft session renewal and recovery. In the Canvas UI, `Topbar.tsx` and `PagePreview.tsx` were simplified to route translated content-template previews through the headless renderer unconditionally, removing the previous workaround that fell back to the legacy snapshot renderer for translated template previews.
