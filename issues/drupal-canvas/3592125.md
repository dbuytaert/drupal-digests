# #3592125: Preserve local package.json when pulling code components

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)

## Summary

The Canvas CLI's `canvas pull` command used to overwrite a project's local `package.json` entirely with the version stored in Drupal, discarding any custom scripts, dependencies, or metadata the developer had added locally. Now, when a local `package.json` already exists, `pull` preserves it and only adds dependencies from the pulled manifest that are missing locally, leaving existing versions, scripts, and other fields untouched. If no local file exists, the pulled manifest is still written as before, and `--skip-overwrite` continues to leave an existing file alone entirely.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix replaces the previous overwrite-or-skip logic in `createAssetsPullTask` (`packages/cli/src/commands/pull.ts`) with a merge step implemented in the new `mergePackageJsonDependencies` utility (`packages/cli/src/utils/merge-package-json.ts`). It compares the pulled `dependencies` against the local file's `dependencies`, `devDependencies`, and `peerDependencies`: any pulled dependency whose name already appears in any of those three sections is left alone (add-only, no version bumps), and anything missing is inserted into local `dependencies` using the pulled version spec. All other local fields (name, version, scripts, custom sections like `overrides`) are copied through unchanged, and the file is rewritten with 2-space indentation only when at least one dependency was actually added; otherwise the on-disk file is left byte-identical.

Each added dependency is now reported as its own `Dependency` result item (`itemType: 'Dependency'`, detail `'Added'`), and the "run npm install" reminder note only fires when something changed, either a fresh file write or an added dependency. If the local `package.json` is invalid JSON, the merge throws and the command reports `Could not merge dependencies: ...` for that item while leaving the local file untouched and letting the rest of the pull continue.</technical>
