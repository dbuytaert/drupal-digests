## Summary

On the `1.x-workspaces` branch, Canvas now generates Component config entities outside the active workspace. Component config generated from code, such as block components, is written to Live. It no longer piles up as pending changes in each workspace. Switching workspaces also no longer triggers a cascade of component regeneration inside the workspace. Code components are the exception. They are config entities edited in Canvas, so their generated Component follows them into the active workspace. Publishing a workspace draft of a code component's Component now requires update access to the code component, meaning the `administer code components` permission.

## Impact

Affects module maintainers.

- **API change:** `ComponentSourceManager` takes a new optional `$workspaceManager` constructor argument (`@?workspaces.manager`), and generated Components now save to Live unless their source sets `discoveryReadsStagedConfig`.
- **New API:** New `discoveryReadsStagedConfig` property (default FALSE) on the `ComponentSource` plugin attribute, set TRUE on `JsComponent`.

## Technical details

`ComponentSourceManager::generateComponents()` has a private `$generating` flag, set in a `try`/`finally` block. Saving Component config switches workspace context. That clears entity field definitions, which makes Layout Builder clear block plugin definitions. `BlockManagerDecorator` then calls back into generation, so nested calls return early. The `finally` block resets the flag after a failed pass.

The manager splits the source definitions in two. Sources whose definition has `discoveryReadsStagedConfig` TRUE are generated in the current workspace. All other sources are generated together in a single `executeOutsideWorkspace()` call, from the new `OptionalWorkspaceManagerTrait`. `ComponentSourceManager` gets an optional `$workspaceManager` constructor argument, wired as `@?workspaces.manager` in `canvas.services.yml`. The comment in the diff says it is NULL until a 1.x site has run `canvas_update_11201()`.

The `ComponentSource` attribute gains a `bool $discoveryReadsStagedConfig = FALSE` property. `JsComponent` sets it to TRUE.

`AutoSaveWorkspacePublishSubscriber` no longer skips the access check for generated Components. The skip was previously inert and carried a `@todo Workspaces MR 4`. A new `accessSubject()` checks update access on the source `JavaScriptComponent` for `JsComponent`-sourced Components. It falls back to the Component itself if the code component is gone (`ComponentNotFoundException`).

The `BlockComponent` block settings subform class now also implements core's `WorkspaceSafeFormInterface`. Without it, core refuses to submit the form inside a workspace, so `blockSubmit()` was skipped. A kernel test showed this left `multiplier` at 0.

New and extended tests are `ComponentSourceManagerWorkspaceTest`, `BlockComponentTest` and `WorkspaceAutoSaveStagingTest`. The ADR text drops the sentence saying the block manager decorator regenerates only when the plugin ID set changed.

## Upgrade

Custom `ComponentSource` plugins whose discovery reads workspace-staged config entities should opt in:

```php
#[ComponentSource(
  // ...
  discoveryReadsStagedConfig: TRUE,
)]
```

Leaving the default (FALSE) generates the plugin's Component config against Live.
