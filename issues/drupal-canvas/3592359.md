## Summary

Canvas now ships an optional `canvas_ssr` submodule that renders Code Components (JavaScript) on the server, so their HTML is in the first paint. Until now only SDCs and Block components rendered server-side. This matters to sites that need SSR before adopting Code Components. If SSR can't render an island, for example because no runner is available, Canvas falls back to its usual client-side rendering. The JavaScript execution is delegated to a pluggable "runner". The included runner uses Deno, which you install yourself.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `canvas_ssr` requires Drupal 11.4 or later, and a Deno binary at `vendor/bin/deno` for the included runner.
- **Config change:** New optional container parameters `canvas_ssr.timeouts` and `canvas_ssr.additional_tamed_properties`, set in `services.yml`.
- **New API:** New `canvas_ssr` submodule with a `canvas_ssr.runner` service tag (and other `canvas_ssr.*` tags) for contrib runner modules and providers.

## Technical details

`canvas_ssr` requires Drupal ^11.4 and depends on `canvas:canvas`. It implements `hook_element_info_alter()` to replace the `#pre_render` of the `astro_island` element with `AstroIslandSsr::preRenderIsland()`. That method renders the slots to HTML once, then `Renderer::render()` runs the component's main module on a runner. Any failure falls back to client-side rendering (`client="only"`). The `docs/ARCHITECTURE.md` added in the commit describes the flow. A successful island is static if nothing in its component graph needs the browser. Otherwise it becomes `<canvas-island client="load">` and hydrates. A component that needs state, effects or event handlers must start with `'use client';` to mark a client boundary.

Runners are services tagged `canvas_ssr.runner` with a priority. `RunnerSelector` picks the highest-priority available one and uses `UnavailableRunner` when none is. The built-in `DenoRunner` has priority 0 and looks for the binary at `vendor/bin/deno`, so a runner module can outrank it with a positive priority. Other tagged extension points are `canvas_ssr.js_module_provider`, `canvas_ssr.site_data_provider`, `canvas_ssr.page_data_provider`, `canvas_ssr.boundary_checker` and `canvas_ssr.path_policy`. Components get a same-site `fetch()` through `SameSiteFetch`, which runs allowlisted GET and HEAD requests as subrequests.

There is no config form. Tuning is through container parameters in `services.yml`. `canvas_ssr.timeouts` has `short: 100`, `medium: 2000` and `long: 10000` (ms), and each must be at least twice the previous one. `canvas_ssr.additional_tamed_properties` is merged into the built-in `canvas_ssr.tamed_properties` list, which the realm setup module freezes. The commit also adds an ADR on import map entries for Canvas's own use, a Deno install step (`.deno`, v2.9.8) in `.gitlab-ci.yml`, and the module's tests.

## Upgrade

To use it: enable `canvas_ssr`, install Deno (or a symlink to it) at `vendor/bin/deno`, then run `drush cr`.
