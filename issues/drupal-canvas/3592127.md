# #3592127: Checkbox shows stale content after publishing the page

- **Project:** Drupal Canvas

## Summary

Plain Form API checkboxes rendered in the Canvas page data form by custom field widgets, such as the "Provide a menu link" checkbox from Canvas Page Menu, no longer show a stale value after the page is published. Before the fix, the checkbox kept its pre-publish state and the next click could toggle to the wrong value. Boolean component props are unaffected, since they render as toggle switches.

## Impact

No upgrade or configuration changes required.

## Technical details

The problem was in `ui/src/components/form/components/Checkbox.tsx`. It seeded `checked` from `attributes.checked` only once in the `useState` initializer, and the `<input>` was uncontrolled (`defaultChecked`), so the DOM `checked` property was set only at mount. The issue describes the resolution as mirroring the earlier `DrupalRadioGroup` fix from MR !1612. The component tracks the last-rendered `attributes.checked` and resyncs local state when a new render carries a different value, without overriding an in-progress user toggle the server hasn't echoed yet. A `useEffect` with a ref then pushes the resynced value onto the DOM node. This is based on the issue description only. No fix diff was available, and the cloned default branch did not yet contain the change.
