## Summary

In Canvas Brand Kit, choosing "Add color" from a color folder's menu could let the closing menu return focus to its trigger after the color popover had opened. If you typed into a field such as Alpha quickly, that late focus change blurred the field and could reset an invalid value, which re-enabled the Add button. The folder menu no longer takes focus back when it hands focus to the popover. Pressing Escape still returns focus to the menu trigger.

## Impact

No upgrade or configuration changes required.

## Technical details

The Brand Kit colors section already used a `suppressAutoFocusRef` flag to stop the top-level dropdown's `onCloseAutoFocus` from restoring focus. The per-folder menus did not use it. The check is now a shared `handleMenuCloseAutoFocus` handler in `BrandKitColorsSection`. It calls `preventDefault()` when the flag is set, then resets the flag. The folder "Add color" menu item now sets `suppressAutoFocusRef.current = true` before opening the popover.

The handler is passed to the folder menus as a new optional `onMenuCloseAutoFocus` prop on `FolderList`. `FolderList` forwards it to `SidebarFolder`, which wires it to `onCloseAutoFocus` on both the dropdown and the context-menu `UnifiedMenu.Content`. Without the flag set, normal menu dismissal behaves as before.

A new Vitest spec for `BrandKitColorsSection` adds two tests. The first uses fake timers to enter an invalid Alpha (`-0.5`) before the menu's delayed focus return. It then asserts that the field keeps focus, the value stays, and the save button is disabled. The second asserts that Escape still returns focus to the menu trigger. The issue says this fixes the identified focus-related failure in `brandKitColors.spec.ts`, not every possible source of flakiness.
