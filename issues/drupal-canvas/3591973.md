## Summary

The Canvas CLI can now reconcile external documents, not just images. When a page spec, content template or page template has a document prop pointing to an external URL such as a PDF, `canvas reconcile-media` downloads the file and uploads it to Drupal as a `document` media entity. It writes the resolved media data and provenance back into the local spec. The back end upload API accepts file based media types to support this, and the CLI's default OAuth scopes now include document media creation. After updating, run database updates so the matching OAuth scopes exist, and re-authorize CLI clients that use explicit scopes. Video props are not handled by this change.

## Impact

Affects module maintainers and site owners.

- **Database update:** `canvas_oauth_post_update_0008_media_document_scopes` creates create scopes for media types with the `file` source plugin.
- **Config change:** New `canvas:media:document:create` OAuth scope in the CLI default scopes, and `canvas_oauth` creates scopes for media types with the `file` source.
- **API change:** `MediaScopesHelper::ensureMediaImageScopes()` renamed to `ensureMediaScopes()`.
- **New API:** `POST /canvas/api/v0/media/{mediaType}/upload` now accepts media types using the `file` source plugin (document shape), with an optional `description` field and a document-shaped `inputs_resolved`.

## Technical details

`ApiMediaControllers::upload()` previously rejected anything but the `image` source plugin. It now allows the plugin IDs in the new `ApiMediaControllers::SUPPORTED_SOURCE_PLUGIN_IDS` (`image` and `file`). The comparison is strict, so `audio_file` and `video_file` media types stay excluded. For `file` sources the `FileIsImage` validator is dropped, because the source field only checks allowed extensions. When the field's `file_extensions` setting is blank, the default now comes from `FieldTypePluginManagerInterface::getDefaultFieldSettings()` for the field type instead of a hardcoded image list. The source field item is built per field type: image fields get `title` and `alt`, file fields get `description`. The response's `inputs_resolved` is `{src, filename, filesize, mimetype}` for documents, matching the `document` object shape, and the OpenAPI spec describes both shapes with `oneOf`.

On the CLI side, `prop-transforms.ts` registers a `documentDescriptor` in `mediaDescriptors`, matching the `json-schema-definitions://canvas.module/document` `$ref` and reading `value.src`. In `reconcile-media.ts`, `SUPPORTED_IMAGE_TYPES` is replaced by an exported `SUPPORTED_MEDIA_MIME_TYPES` map keyed by media type. The document map lists the MIME types for each extension in `x-allowed-file-extensions` on `schema.json` `$defs.document.properties.src`, and a test checks the two stay in sync. `txt` is deliberately excluded. The descriptor's `mediaType` is passed to the upload call, and the MIME check reports `Unsupported document type ...`. For documents the form fields are `title` (falling back to the filename) and `description`, taken from the prop value. For images they remain `title` (the filename) and `alt`.

On the OAuth side, `MediaScopesHelper::ensureMediaImageScopes()` is renamed `ensureMediaScopes()` and creates scopes for every media type whose source is in `SUPPORTED_SOURCE_PLUGIN_IDS`. It is called from `canvas_oauth_install()` and from the new `canvas_oauth_post_update_0008_media_document_scopes()`. `DEFAULT_SCOPES` in the CLI's `config.ts` gains `canvas:media:document:create`. A changeset adds a minor bump for `@drupal-canvas/cli`.

## Upgrade

Run database updates so `canvas_oauth_post_update_0008_media_document_scopes` creates the document create scopes. CLI clients that set `CANVAS_SCOPE` explicitly need to add `canvas:media:document:create` to upload documents.

Code calling the renamed helper must change:
```php
\Drupal::classResolver(MediaScopesHelper::class)->ensureMediaScopes();
```
