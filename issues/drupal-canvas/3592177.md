## Summary

The Canvas JavaScript packages now build with Vite 8. The Vite plugin (`@drupal-canvas/vite-plugin`) declares support for Vite 8 alongside Vite 6 and 7, while the CLI and workbench upgrade to Vite 8 themselves. The workbench also moves to Tailwind CSS 4.3.3, and the headless host gets a fix for a preview iframe that could stay stuck at its temporary probe height.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `@drupal-canvas/vite-plugin` peer dependency widened from `^6 || ^7` to `^6 || ^7 || ^8`; the CLI and workbench now depend on `vite` `^8.3.3`.
- **API change:** `createCanvasViteBuildConfig()` now returns `oxc: { jsx: { runtime: 'automatic' } }` instead of `esbuild: { jsx: 'automatic' }`.

## Technical details

Vite 8 replaces Rollup and esbuild with Rolldown and Oxc, so the build configs were renamed throughout the CLI, workbench and Vite plugin: `build.rollupOptions` became `build.rolldownOptions`, `output.inlineDynamicImports: true` became `output.codeSplitting: false`, and `esbuild: { jsx: 'automatic' }` became `oxc: { jsx: { runtime: 'automatic' } }` in `createCanvasViteBuildConfig()`. The `tsdown` config for one package switched `external` to `deps.neverBundle`. The workbench dropped its `rollup` type imports and now derives output types from `Awaited<ReturnType<typeof viteBuild>>`.

In `buildCanvasComponentEntry()`, Oxc lowers syntax such as object spread for the es2015 component target by importing `@oxc-project/runtime/helpers/*`. A new `isOxcRuntimeHelperImport()` check keeps those imports from being externalized and vendored as third-party packages, so the helpers are bundled into the component. The code comment notes Rolldown only consults the `external` option for these injected imports, not plugin `resolveId` hooks. The bundled source harvest plugin now skips modules with `info.code === null` instead of checking `info.isExternal`.

Separately, `createHeadlessPreviewHost` now cancels the pending probe animation frame and calls `restoreProbeHeight()` when the iframe loads a new document. Before, a reload during a height probe left the iframe at the probe height and later height reports were ignored. A test covers this case.

## Upgrade

Projects using `@drupal-canvas/vite-plugin` with Vite 8 should check their own config for the renamed options:

```ts
// Before
build: { rollupOptions: { output: { inlineDynamicImports: true } } },
esbuild: { jsx: 'automatic' },

// After
build: { rolldownOptions: { output: { codeSplitting: false } } },
oxc: { jsx: { runtime: 'automatic' } },
```
