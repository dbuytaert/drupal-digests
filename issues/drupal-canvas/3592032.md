# #3592032: Canvas AI: Proper chat history management in the backend

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592032](https://git.drupalcode.org/project/canvas/-/work_items/3592032) · 1 contributor · 50 comments

## Summary

The Canvas dev AI chat (an experimental page-builder assistant, part of the `canvas_dev_ai` module) used to forget everything it had done as soon as a chat turn finished. Each new message started the agent from scratch, so it would re-read component schemas and redo lookups it had already performed earlier in the same conversation, wasting extra round trips. This change lets the backend keep the agent's own history, including its tool calls and their results, across turns within the same chat session, so follow-up requests can skip work already done. Because keeping this history costs more tokens per request, it is off by default and must be turned on explicitly via a new checkbox on the Agents & Tools configuration form.

## Impact

Affects site owners.

- **Config change:** New `keep_tool_calls_in_history` boolean added to `canvas_dev_ai.settings` (default `FALSE`), togglable on the Canvas AI Agents & Tools form at `/admin/config/ai/canvas-ai-agent-selection`.

## Technical details

The frontend (`AiWizardDev.tsx`) now generates one `conversation_id` per mount of the chat panel (the chat is cleared on mount) and sends it with every turn, alongside the existing per-turn `request_id`. On the backend, `CanvasDevAiBuilder` no longer unconditionally deletes the stored agent state when a turn finishes: if `keep_tool_calls_in_history` is enabled, it calls the new `CanvasAiTempStore::setStoredConversationState()` to persist the finished agent's serialized state (via `::toArray()`) keyed by `conversation_id` and tagged with the `agent_id` that produced it. On the next turn, `prepareAgent()` looks up that stored conversation state and, if it exists and belongs to the same agent, resumes it with `$agent->fromArray()` instead of rebuilding history from the client transcript via `CanvasAiChatHelper::getFilteredChatHistory()`. The resumed state's `looped` counter is reset to `0` so the new user message is appended and the per-turn loop ceiling still applies. If a turn ends unsolvable (the agent gave up or errored), `forgetTurn()` deletes both the per-turn agent state and the conversation state, so the following turn falls back to seeding from the transcript rather than resuming a broken history. Switching to a different agent between turns, or turning the setting off, also causes the transcript-based path to be used, and turning the setting off actively deletes any previously kept conversation state.

The setting is exposed as `keep_tool_calls_in_history` in `canvas_dev_ai.settings` (schema and `.install` default added), with a checkbox on `CanvasDevAiAgentSelectionForm`, and its description notes that enabling it makes the existing "Maximum chat history messages" setting a no-op.
