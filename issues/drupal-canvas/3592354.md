## Summary

The Canvas AI page agent (`drupal_canvas_page_agent`) no longer sends the "This is the Nth time that this agent has been run" sentence that `ai_agents` adds to every system prompt. That sentence changes on each agent loop, which stopped AI providers from reusing their prompt cache past that point. With it removed, the component catalog and chat history that follow can be cached, which should lower token costs and latency for page agent runs.

## Impact

No upgrade or configuration changes required.

## Technical details

A new `Drupal\canvas_ai\EventSubscriber\PageAgentRunCounterSubscriber`, registered in the `canvas_ai` services file, subscribes to `BuildSystemPromptEvent::EVENT_NAME`. For agent ID `drupal_canvas_page_agent` only, it strips the sentence with a `preg_replace()` matching `first|second|third|Nth` followed by "time that this agent has been run." and a newline. Other agents keep the sentence. The class is marked `@internal`, and the issue text mentions `canvas_dev_ai` while the commit places it in `canvas_ai`.

This is a stopgap for an upstream `ai_agents` fix (https://git.drupalcode.org/project/ai_agents/-/work_items/3586083). The `@todo` says to remove the subscriber once a required `drupal/ai_agents` release includes that fix. A unit test covers the first, second, third and 12th ordinals, and checks that another agent is left unchanged.
