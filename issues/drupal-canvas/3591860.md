# #3591860: Add a button to close the right tray

## Summary

The Canvas Editor's right-hand contextual panel (used for component settings, crop controls, and prop editing) previously stayed open once populated, taking up screen space even when its content wasn't needed. This adds a close ("X") icon to the panel so editors can manually hide it and get more room for the canvas. When the user then selects a component, a crop/image area, or another editable element, the panel automatically reopens. A small hamburger-style button appears in its place while closed, letting the user reopen it manually as well. The panel still opens automatically on page load as before.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is confined to the Canvas Editor's React UI. `uiSlice.ts` gains a `rightPanelOpen` boolean (defaulting to `true`) with a `setRightPanelOpen` reducer and `selectRightPanelOpen` selector. The selection reducer now sets `rightPanelOpen` back to `true` whenever `action.payload.items.length > 0`, which runs on every selection dispatch, so re-clicking an already-selected component also reopens the panel, something a `useEffect` keyed on the selection value wouldn't catch.

`ContextualPanel.tsx` adds a `Cross1Icon` `IconButton` (`data-testid="canvas-contextual-panel--close-icon"`) that dispatches `setRightPanelOpen(false)`. `EditorLayout.tsx` toggles the visibility of the right column (`rightColumnRef`) versus a small reopen button (`rightColumnMenuRef`, `data-testid="canvas-right-panel-menu-button"`, using `HamburgerMenuIcon`) based on `isRightPanelOpen`, via direct `style.display` manipulation in a `useEffect`. Cypress coverage in `contextual-panel.cy.js` verifies the close/reopen interaction, including the re-selection edge case described above.
