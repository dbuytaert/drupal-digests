# #3591957: Improve the Brand Kit fonts UI

## Summary

Canvas's Brand Kit fonts panel has been redesigned to match new UI designs and gains functionality that was previously missing: each font family row now shows its file formats and whether it is static or variable, families can be searched, and a whole family (all its variant files) can now be deleted in one action, something the old UI didn't offer at all. The font detail view moved from a centered modal into the flyout that clicking a family already opens, splitting the crowded single column into a settings side and a code-examples side. Separately, and affecting every site using Brand Kit fonts, the generated `@font-face` CSS (both the JavaScript preview and the PHP-rendered library CSS) now includes `font-display: swap`, so visitors see a fallback font immediately instead of invisible text while a custom web font downloads.

## Impact

No upgrade or configuration changes required.

## Technical details

The family list in `FontFamiliesList.tsx` replaces the old single-button row with a `familyRowWrapper` containing the details trigger plus a separate overflow-menu button (nesting a menu button inside the row's own button wasn't possible), exposing "Add variant" (hidden for variable families, which ship every weight in one file) and "Delete font", the latter wired to a new `onRemoveFamily` handler in `BrandKitFontsSection.tsx` that filters out every font whose `normalizeFontFamilyName` matches the family, added in `fontCss.ts` to keep grouping and deletion logic from drifting apart.

`FontFamilyFlyout.tsx` was restructured from a single scrolling column into `centerConsole` (family name, variant list or preview, and the weight/style or variable-axis editor) and `rightConsole` (the copyable `@font-face` and Tailwind snippets via `FontSnippetsCard`), stacking vertically under 820px. `fontCss.ts`'s `getFontFaceStyleDeclaration` (renamed from `getStyleDeclaration`) no longer emits the combined `normal italic` value for variable fonts whose `ital` axis spans both: it always declares a single style matching the axis default, and the alternate slant is reached through `font-variation-settings` in the preview instead, avoiding a synthetic browser slant on top of the axis. The Tailwind snippet builder (`buildUsageUtilities`) was rewritten to only emit utilities for axis values that differ from their default, so the example code no longer spells out weight-400/upright/at-default-axis utilities that do nothing.

`font-display: swap` was added to the `@font-face` output in both `fontCss.ts` (`buildFontFaceSnippet`, used for the live preview) and the PHP-side `BrandKit::getCss()` in `src/Entity/BrandKit.php`, which generates the CSS actually served to visitors.</technical>
