## Summary

When the Canvas AI option "Keep tool calls and results in the chat history" is on, a turn the user stopped no longer disappears from the agent's context. Before, typing "Continue" after pressing stop gave the agent only the earlier finished turn and "Continue", so it didn't know what to continue. Now the agent also receives the stopped turn's user message and the "You interrupted the agent. What would you like to change?" notice, as it already did with the option off.

## Impact

No upgrade or configuration changes required.

## Technical details

Each stored conversation checkpoint now records a `message_count`: the number of client transcript messages its turn was sent with, including its own user message. `CanvasDevAiBuilder::storeConversationState()` passes `\count($prompt['messages'])` to `CanvasAiTempStore::setStoredConversationState()`, which gained a required `int $message_count` parameter before `$resumed_request_id`. `getStoredConversationState()` now also returns `message_count`.

When a later turn resumes a checkpoint in `prepareAgent()`, the new private helper `getMessagesAfterTurn()` drops the first `message_count` transcript messages. It then skips the resumed turn's own narration and answer, which the checkpoint already holds, by starting at the first remaining `user` message. If no user message is left, nothing is appended. The remaining messages are appended to the restored history through `setChatHistory()`.

The conversion was extracted from `CanvasAiChatHelper::getFilteredChatHistory()` into a new public `CanvasAiChatHelper::toChatMessages()`. It converts every message it is given and does not apply the maximum chat history messages limit. `CanvasDevAiBuilder` is marked `@internal`.

## Upgrade

Checkpoints already in the tempstore have no `message_count`. `getStoredConversationState()` reads `$record['message_count']` without a default, so a checkpoint written before this change may trigger an undefined array key warning when resumed. I did not verify how that case behaves.
