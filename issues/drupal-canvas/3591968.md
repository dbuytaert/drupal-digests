# #3591968: Forbid the reserved component tree root UUID as a component instance `uuid`/`parent_uuid`

- **Project:** Drupal Canvas
- **Type:** Critical unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591968](https://git.drupalcode.org/project/canvas/-/work_items/3591968) · 1 contributor · 3 comments

## Summary

Every Canvas component tree has a synthetic root, identified internally by a fixed, reserved UUID. Because that UUID happens to be a syntactically valid v4 UUID, nothing previously stopped a component instance from using it as its own `uuid`, or from pointing to it as its `parent_uuid`. Canvas itself never generates such data, but a hand-edited exported page, or content produced by an AI integration like `canvas_ai`, could contain it. When it did, the component's children were silently reparented to the top level of the tree during hydration, with no error raised to flag the corrupted structure. This fix makes the reserved UUID explicitly forbidden in both positions, so such content is now caught by validation instead of silently misbehaving.

## Impact

Affects site owners.

- **Security:** The `Uuid` constraint alone let a component instance use the reserved component tree root UUID (`a548b48d-58a8-4077-aa04-da9405a6f418`) for its `uuid` or `parent_uuid`, silently reparenting its children to the top level during hydration with no validation error; `ComponentTreeStructureConstraintValidator` now rejects it.

## Technical details

The fix lives in `ComponentTreeStructureConstraintValidator`, which validates component tree items for both content entity and config entity component trees. It now checks each item's `uuid` and `parent_uuid` against `ComponentTreeItemList::ROOT_UUID`, using `strcasecmp()` because the underlying database columns are case-insensitive even though the constraint previously compared case-sensitively. A `uuid` matching the reserved value raises a violation at the `uuid` path; a `parent_uuid` matching it raises a violation at `parent_uuid`, since placement at the root is expressed by omitting `parent_uuid` and `slot` entirely, not by pointing at the root UUID explicitly.

There is no update path: existing data with this violation is not migrated. `drush canvas:doctor` re-runs these constraints as part of its data health checks, so any pre-existing offending component trees will now surface there. The issue also lists several related gaps left as follow-ups: parent cycles of length two or more still pass validation, duplicate-UUID violations don't name the offending UUID or delta, and config sequence keys aren't bound to each item's `uuid`.

## Upgrade

No code changes are required for callers. Sites with existing component trees should run `drush canvas:doctor` after upgrading to detect any component instance that illegally used the reserved root UUID (`a548b48d-58a8-4077-aa04-da9405a6f418`, compared case-insensitively) as its `uuid` or `parent_uuid`; such trees will now fail validation and need to be corrected manually since there is no automatic update path.
