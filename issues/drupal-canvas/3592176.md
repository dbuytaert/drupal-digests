# #3592176: Duplicating a page template silently does nothing: the GET representation is no longer a valid POST body

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592176](https://git.drupalcode.org/project/canvas/-/work_items/3592176) · 1 contributor · 3 comments

## Summary

The "Duplicate" action in the Templates panel (Page templates) now works. In Canvas 1.12.0 it appeared to do nothing, because the server rejected the request with a 422 and the UI hid the error. A copy of a disabled template now stays disabled, and any failure to duplicate is shown as an error card in the panel with a Dismiss button.

## Impact

No upgrade or configuration changes required.

## Technical details

The GET representation of a page variant, since [#3592106](https://www.drupal.org/node/3592106), includes the computed `inputs_resolved` and explicit `null` values for optional keys. `buildDuplicateVariantPayload()` in `ui/src/services/pageVariants.ts` spread each response item into the POST body, so `POST /canvas/api/v0/config/page_variant` failed validation. The fix is client-side only (the issue's Option A), so the server and the CLI, which reads `inputs_resolved`, are untouched. Each tree item is now rebuilt from storable keys: `uuid`, `component_id`, `component_version`, `inputs`, and `parent_uuid`, `slot` and `label` only when non-null. The `status` of the source is also carried over.

In `ui/src/types/PageVariant.ts`, a new `PageVariantComponentTreeItemResponse` type (nullable optional keys plus `inputs_resolved`) is used for `PageVariant.component_tree`. This way TypeScript rejects passing a read item where the write type `PageVariantComponentTreeItem` is expected. `CreatePageVariantPayload` gains an optional `status`. In `PageVariants.tsx`, `handleDuplicate()` now stores the rejection in `duplicateError` and renders an `ErrorCard`. The commit also adds a unit test and a Playwright test in `pageVariants.spec.ts`.
