## Summary

Content creators who can use the Canvas editor but lack `administer folders` now see component folders (Library categories) in the component picker. Before, components showed up ungrouped and no folders were listed. Rename, update and delete still need `administer folders`. Sites that granted `administer folders` only so editors could browse folders can remove that grant.

## Impact

Affects site owners.

- **Permission change:** Users with Canvas UI access can now view folders without `administer folders`; create, update and delete still require `administer folders`.

## Technical details

The `Folder` config entity used core's default `EntityAccessControlHandler`, so only users with `administer folders` passed `view` access. The picker's list endpoint filters out entities the user can't view, which dropped every folder for other editors. The `access` handler on `Folder` is now `ContentCreatorVisibleCanvasConfigEntityAccessControlHandler`, the same handler Component, Pattern and Color use. This is "Option B" from the issue. The proposed new `view folders` permission (Option A) was not added.

A new kernel test, `FolderTest::testViewAccess()`, covers this. A user with `ContentTemplate::ADMIN_PERMISSION` (a permission that grants Canvas UI access) can `view` and `view label` a folder, but not `update` or `delete` it. A user with no permissions cannot `view` it.
