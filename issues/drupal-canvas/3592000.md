# #3592000: Translating a component tree config entity (such as PageVariant) that has an auto-save draft breaks Canvas layout validation

- **Project:** Drupal Canvas
- **Type:** Critical unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592000](https://git.drupalcode.org/project/canvas/-/work_items/3592000) · 1 contributor · 5 comments

## Summary

If a `PageVariant` or `ContentTemplate` had unpublished changes sitting in Canvas's auto-save draft when it was translated via config translation, the next time anyone opened the Canvas editor it would crash with a 500 error on every layout request, and stay crashed since the error masked the whole screen (there was no way to publish or discard the draft to recover). This affected plain, single-language-default sites, not just multilingual ones with langcode drift. The fix stops this crash: translating an entity that has a pending auto-save draft no longer breaks the editor.

## Impact

No upgrade or configuration changes required.

## Technical details

The crash came from `CanvasConfigEntityTranslationsAreValidConstraintValidator::validate()`, which simulates `Config::setOverriddenData()` by running `NestedArray::mergeDeepArray()` on the entity's base `component_tree` and the `LanguageConfigOverride`'s translated data, then validates the merged array against config schema. A saved `component_tree` is re-keyed by instance UUID in `ComponentTreeConfigEntityBase::preSave()`, but an auto-save draft never runs `preSave()`, so a draft created before the translation existed keeps the client's delta keys (`0, 1, 2, …`). A `LanguageConfigOverride`, however, always targets instances by UUID. Merging a delta-keyed base with a UUID-keyed override made the merge treat them as disjoint sets, appending the override's sparse translated inputs as a phantom component instance with no `component_id`, `component_version`, or `uuid`. Validating that merged data tripped the `assert(\array_key_exists('component_id', $component_instance))` in `ComponentInputsMapping::__construct()`.

The fix re-keys the base `component_tree` by UUID before the merge, calling `ComponentTreeConfigEntityBase::asDeterministicallyAndTranslatableKeyedComponentTreeSequence()`, mirroring what `getTranslatedComponentTree()` already did for a different code path (as noted in that method's own docblock). Test coverage was added in `PageVariantValidationTest::testValidationWithTranslationOverrideAndDeltaKeyedTree`, which reconstructs the delta-keyed draft shape, adds a UUID-targeted `hu` override, and asserts no validation errors. This fix was split out of the broader langcode-drift work in [#3591850](https://www.drupal.org/node/3591850) (MR !1400) because it reproduces under plain, single-language-default conditions.

## Upgrade

No action needed for typical Canvas usage; this is an internal bug fix. For context: `ComponentTreeConfigEntityBase::asDeterministicallyAndTranslatableKeyedComponentTreeSequence()` was changed from `private` to `public` (and marked `@internal`) so the validator could reuse the same re-keying logic. It remains an internal method not intended for use outside Canvas core.
