# #3591972: Code editor has no "Document" prop type for the document object shape

- **Project:** Drupal Canvas
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3591972](https://git.drupalcode.org/project/canvas/-/work_items/3591972) · 1 contributor · 5 comments

## Summary

Canvas's code editor previously recognized only "Image" and "Video" object prop types. A code component prop using the newly added `document` schema shape ($ref to `canvas.module/document`) would silently vanish from the Props panel, and there was no way to add a new document prop from the UI. This fix adds full "Document" prop type support: it appears in the prop type selector, has its own configuration form, supports single and multi-value (allow multiple) modes, and shows a filename/file-type chip instead of a broken image preview when a document is set as a prop's default value.

## Impact

Affects module maintainers.

- **New API:** Code components can declare a prop with `$ref: json-schema-definitions://canvas.module/document`, exposed in the code editor as a "Document" prop type.

## Technical details

The root cause was that `derivedPropTypes.ts` had no entry mapping the `document` `$ref` to a prop type, so `Props.tsx` derived `null` for such props and filtered them out. The fix adds a `document` entry (`displayName: 'Document'`) whose `derive` callback matches `$ref === 'json-schema-definitions://canvas.module/document'`, with an `init` example carrying `src`, `filename`, and `mimetype`. As part of this, the existing `image` and `video` `derive` callbacks were tightened from `$ref?.includes('image')`/`includes('video')` substring checks to exact `$ref` equality checks, since substring matching became ambiguous with three object `$ref`s in play.

`Props.tsx` gained a `case 'document':` branch rendering a new `FormPropTypeDocument` component, and `'document'` was added alongside `'image'`/`'video'` everywhere those two were special-cased: the limited-count array handling, the "has a dedicated example form" check that suppresses the generic required-prop default, the allow-multiple whitelist, and the limited/unlimited `valueMode` switch. `utils.ts`'s `serializeExample`/deserialization logic gained an `isDocument` flag so multi-value document examples get the same empty-`src` filtering and URL rewriting as image and video examples.

On the PHP side, `JsComponent::EXAMPLE_URL_ALLOW_LIST` (replacing two separate constant checks) now also allows the new `EXAMPLE_DOCUMENT` constant (`/ui/assets/documents/sample.pdf`) as a root-relative example URL for validation purposes. `DefaultImagePreview.tsx`, which previously rendered a raw `<img src>` for any media-library-style prop default, now detects document values (`'filename' in value || 'mimetype' in value`) and renders a file-extension chip with a filename label instead of attempting to render a PDF as an image.</technical>
