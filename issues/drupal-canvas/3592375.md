## Summary

Content templates can now be created for content entity types that have no page of their own. Media is available even when stand-alone media URLs are off (the Drupal core default), and content blocks (`BlockContent`) are available too. Other fielded entity types that opted into Field UI, such as Paragraphs' `paragraph`, also become eligible. Sites that create no template for these types see no change. The component instances in a template decide the look of the entity, so presentation added by the entity type's own view builder (for example Paragraphs behavior plugins such as background color or layout) does not apply to entities rendered by a template.

## Impact

Affects module maintainers and site owners.

- **Config change:** The content template list and the "Add new template" dialog now include Media and Content block (and eligible contrib entity types) without any configuration.
- **New API:** Public `ContentTemplateRepository::isSupportedEntityType()` no longer requires a canonical page; `media`, `block_content` and contrib entity types such as `paragraph` become eligible.

## Technical details

`ContentTemplateRepository::isSupportedEntityType()` drops the condition that the `canonical` link template differs from `edit-form`. An entity type is now eligible if it opted into Field UI (`field_ui_base_route`), is stored (not `ContentEntityNullStorage`), and does not implement `ComponentTreeEntityInterface`. `comment` remains excluded by name, now because threading and indentation from `CommentViewBuilder` would be lost. `ContentTemplateHooks::entityTypeAlter()` still runs last to see `field_ui_base_route`.

A block copies the attributes and contextual links of its content block when the block is built. Core builds the content block immediately in its view builder, but `ContentTemplateAwareViewBuilder` builds lazily when a template renders it, so the block lost the content block's contextual links (no "Edit" link). The fix: `ContentTemplateHooks::blockAlter()` (`hook_block_alter`) swaps the plugin class of `BlockContentBlock` and Layout Builder's `InlineBlock` for the `@internal` `ContentTemplateAwareBlockContentBlock` and `ContentTemplateAwareInlineBlock`. Both use `BuildsContentBlockImmediatelyTrait::build()`, which calls the new `ContentTemplateAwareViewBuilder::buildImmediately()` to remove the lazy `#pre_render` callback and build at once. The code is marked for removal once core does this itself (https://www.drupal.org/project/drupal/issues/3638853).

Tests cover eligibility of `media` and `block_content`, an embedded media item with a template, and a content block with a template placed as a block. `docs/config-management.md` is updated with the new eligibility rules and the note about view builder presentation.
