## Summary

Drupal Canvas's AI "Page Builder" chat agent previously could only add new components to a page. This issue extends it so it can also update the content of a component already on the page (for example, "summarize this text" or "change the button color to blue" on a selected component) and move an existing component to a different region, slot, or position relative to another component. A single chat request can combine adding, editing, and moving in one go, and the orchestrating agent's instructions were rewritten so it correctly routes "edit the text" requests to the page builder agent instead of treating them as a code-component change. The admin form for customizing how components are described to the AI also gains an optional "detailed description" field, giving site builders finer control over the guidance the AI receives for each component.

## Impact

Affects site owners.

- **Config change:** `canvas_ai.component_description.settings` config schema changed from a mapping to a sequence and gained `label` and `detailed_description` keys; sites with saved component descriptions should re-save the settings form.

## Technical details

Three new `FunctionCall` plugins were added to the `canvas_ai` module: `get_component_content` returns the current prop values (and, recursively, slot children) of a placed component by reading `CanvasAiTempStore::COMPONENTS_IN_PAGE_WITH_PROP_VALUES_KEY`; `update_component_data` validates the target UUID and the new prop values through `AiResponseValidator::validateComponentPropUpdate()` (which builds a single-item component tree and runs it through Canvas's constraint validator, and rejects array-shaped values for media props, requiring a media ID instead) before returning a structured `{uuid, fieldValues}` payload; `move_component_in_page` validates the UUID/region/reference-UUID/placement combination and asks the new `CanvasAiPageBuilderHelper::calculateNodepathToMoveComponent()` for the resulting `nodePath`. `CanvasBuilder::render()` now clears the tempstore at the start of every request, seeds the components-with-values key from the submitted layout, and merges `UpdateComponentData`/`MoveComponentInPage` tool output into the JSON response as `UPDATE`/`MOVE` operations alongside the existing `ADD` operations, via the new `CanvasAiPageBuilderHelper::includeUpdateOperations()`/`includeMoveOperations()`.

The `canvas_page_builder_agent` system prompt is restructured into three explicit workflows (A: add, B: modify, C: move), and a new `get_metadata_of_components` tool lets the agent fetch full prop/slot definitions on demand instead of receiving them all upfront in the "Available Components Catalog." A new `PageBuilderAgentPreExecuteSubscriber` listens for `AgentRequestEvent` and prepends the selected component's UUID to the user's chat message before the page builder agent sees it. `CanvasAiPageBuilderHelper::populateMediaPropIfNeeded()` resolves an already-placed image's public file URL back to its media entity ID (via `PublicStream` and a `field_media_image` query) so that editing unrelated props on a component doesn't blank out its image. Separately, `CanvasAiPageBuilderHelper::getAllComponentsKeyedBySource()` now calls `ApiConfigControllers::list()` directly instead of issuing an internal HTTP sub-request, and caches the result via `CacheBackendInterface`. This work builds on the original add-only agent from [#3533079](https://www.drupal.org/node/3533079).

## Upgrade

If you customized component descriptions via the "Canvas AI Component Description" settings form, re-save the form once this lands: the stored config for `canvas_ai.component_description.settings` moved from

```yaml
component_context:
  type: mapping
  mapping:
    '*':
      type: component_source_entry
```

to a sequence that also stores a `label` per source:

```yaml
component_context:
  type: sequence
  sequence:
    type: mapping
    mapping:
      enabled: { type: boolean }
      data: { type: text }
```
