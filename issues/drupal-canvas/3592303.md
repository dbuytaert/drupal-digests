## Summary

Post-update 0031, which moves 1.x auto-save drafts into Workspaces staging, no longer aborts `updb` when a draft's entity is already tracked in another workspace. A draft whose entity is tracked by a workspace using core's default provider is staged into that workspace instead of Main, and it replaces that workspace's pending changes for that translation. If the workspace belongs to another provider, or the lock changes mid-write, the 1.x draft is dropped and a warning is logged. The remaining drafts are still migrated.

## Impact

No upgrade or configuration changes required.

## Technical details

`LegacyAutoSaveMigrator::migrate()` now calls `WorkspaceAutoSave::getOwningWorkspaceId()` for the entity. If another workspace owns it and its provider is not `DefaultWorkspaceProvider`, the row is dropped through `drop()` and a warning with the workspace and provider is logged. Otherwise the new `stageContentRow()` persists the row via `executeInWorkspaceUnchecked()` in the owning workspace. A `WorkspaceEntityLockedException` thrown during the write (the lock moved after the check) rolls back the transaction, drops the row and logs a warning. Any other `\Throwable` is still rethrown and aborts the update.

Violation rows follow the draft. `rekeyViolationToWorkspace()` moves the form violation row and the component instance violation rows to the target workspace's prefix. 1.x keyed component instance rows by bare UUID only, so the UUIDs are read from the draft's `ComponentTreeItem` fields via `componentInstanceUuids()`. `drop()` now also deletes those component instance rows. A row dropped because it is malformed or because its entity or language is gone is not covered: it keeps its component instance rows, which are re-keyed under Main.

The post-update's inline re-key loop is replaced by the new `LegacyAutoSaveMigrator::rekeyViolation()`. It skips keys that already carry any workspace's prefix, not only Main's. `hasWorkspacePrefix()` checks that the first segment is an existing workspace ID and the second an entity type ID, since a workspace ID can equal an entity type ID. When a key exists both bare and prefixed, the prefixed row is kept and the bare one deleted. The constructor gains an autowired `logger.channel.canvas` logger.
