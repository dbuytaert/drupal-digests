# #3591748: Hydrate components with diamond dependencies

- **Project:** Drupal Canvas
- **Type:** Major bug report
- **Status:** Fixed
- **Discussion:** [#3591748](https://git.drupalcode.org/project/canvas/-/work_items/3591748) · 1 contributor · 8 comments

## Summary

A code component that imports another code component and also directly imports one of that component's own dependencies no longer fails to hydrate. Previously, with `Pricing` importing `Card` and `Button`, and `Card` also importing `Button`, the browser threw `Failed to resolve module specifier "@/components/demo_button"` and the card did not render. The generated import map now includes a scope for every intermediate component, so such component trees render.

## Impact

No upgrade or configuration changes required.

## Technical details

The bug was in the private `JsComponent::getScopedDependencies()`, which builds the per-component `scopes` entries of the import map. Its `$seen` array behaved as a global visited set shared across sibling branches. Because dependencies are sorted, the shared leaf (`demo_button`) was visited before the intermediate (`demo_card`). By the time the code recursed into `Card`, `Button` was already in `$seen`, so the loop skipped it and `Card`'s own `@/components/demo_button` scope entry was never written. The browser then had no scope to resolve the import inside `Card`'s module.

The fix makes `$seen` the current recursion path (ancestors only). `$seen[] = $component->id()` is added at the start of each call, and the `@/components/{name}` entry for the component's scope is now written before the cycle check. A dependency that is an ancestor on the current path still `continue`s to avoid infinite recursion, but only after its scope entry has been recorded. The existing step that merges a dependency's scope into its parent's scope is unchanged.

`getDependencyLibraries()` has the same `$seen` shape but was not changed in the merged commit. The issue notes global deduplication is desirable for libraries, but its remaining-task checkbox to confirm it cannot drop a needed library in a diamond was left unchecked. The issue also describes a kernel test, `JsComponentTest::testImportMapsWithDiamondDependency()`.
