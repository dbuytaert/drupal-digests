# #3592060: Canvas AI: Update orchestrator for content-only / page-variant chrome

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed

## Summary

Canvas's AI orchestrator, the agent that decides which specialized AI agent (page builder, template builder, etc.) should handle a user's request, previously still assumed that pages have theme-global header/footer/sidebar regions that its builder agents can fill in. After a related change moved that "chrome" into page variants (edited separately in the Canvas editor), the orchestrator's prompt was left describing the old model: it would tell users it could "build complete pages with headers, footers, and multiple sections" and would route a request like "add a header to this page" to the page builder agent, which no longer has any way to place chrome. This update rewrites the orchestrator's instructions so it correctly explains that headers, footers, navigation, and sidebars come from the page variant (called a "page template" in the editor), and instead of invoking a builder agent for such requests, it now points users to the specific places in the Canvas editor where the page template can be edited.

## Impact

Affects site owners.

- **Config change:** New `canvas_ai_post_update_0014_reimport_orchestrator_content_only_chrome()` reimports the `ai_agents.ai_agent.canvas_ai_orchestrator` config entity's `system_prompt` on update, overwriting any direct customizations of that prompt.

## Technical details

The fix is entirely in the `system_prompt` text of `config/install/ai_agents.ai_agent.canvas_ai_orchestrator.yml`, plus a new post-update hook, `canvas_ai_post_update_0014_reimport_orchestrator_content_only_chrome()` in `canvas_ai.post_update.php`, that reimports just that key (preserving the config entity's `uuid` and `_core` hash) so existing sites pick up the corrected prompt.

The prompt changes: the tool blurb for `canvas_template_builder_agent` now says it builds "a complete page body ... in the content region" and explicitly does not build headers, footers, or sidebars. A new "Rule #9: Site Chrome Comes From the Page Variant" instructs the orchestrator to still call the template builder for a full page request that also asks for a header/footer, but with a prompt scoped to the page body only, and to *not* call any builder agent at all when the user asks only to add/modify a header or footer on an existing page. Instead it should explain that chrome comes from the page variant and name the three UI entry points to edit it: the "Page templates" section of the Templates panel, the outermost row of the Layers panel, and the "Edit template" link on the "Page data" tab. Several few-shot examples and anti-pattern bullets were updated to match. `CanvasAiOrchestratorPostUpdateTest` was extended with a data provider covering both post-updates 0003 and 0014 that reimport this prompt, asserting the new prompt text is present and the old "including headers, footers, and multiple sections" wording is gone.

This is a direct follow-up to [#3592030](https://www.drupal.org/node/3592030), which made the same content-only change to the page and template builder agents themselves; this issue closes the gap by updating the orchestrator that routes to them.
