# #3592111: Unify headless frame-ancestors policies across frameworks

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592111](https://git.drupalcode.org/project/canvas/-/work_items/3592111) · 1 contributor · 5 comments

## Summary

Canvas headless frontends embed inside the Canvas editor's iframe during draft preview, which requires the frontend's Content-Security-Policy to allow that specific embedding via `frame-ancestors`. Each framework adapter (Next.js, Nuxt, Astro, TanStack Start) previously computed this policy on its own, and at least one combination, Vercel-hosted Next.js apps, ended up refusing the embed entirely, blocking preview and editing of the headless site from within Canvas. All adapters now share one resolver for this policy, so the behavior is consistent and documented across frameworks, and site owners get an explicit `CANVAS_EDITOR_ORIGINS` setting to override the defaults when needed.

## Impact

Affects site owners.

- **Config change:** New `CANVAS_EDITOR_ORIGINS` environment variable (a whitespace- or comma-separated list of origins) that explicitly sets which origins may embed a headless frontend for draft preview. When unset, the policy defaults to `'self'` plus the `CANVAS_SITE_URL` origin and the current draft session's editor origin; setting `CANVAS_EDITOR_ORIGINS` (even to an empty or fully invalid value) replaces both defaults rather than adding to them.

## Technical details

The policy logic now lives in one place, `resolveFrameAncestors()` and `mergeFrameAncestors()` in `packages/headless/src/server/csp.ts`, exported from `@drupal-canvas/headless/server`, and every adapter's middleware/plugin (`headless-next`'s `applyCanvasHeaders()`, `headless-nuxt`'s `beforeResponse` server plugin, `headless-astro`'s `onRequest` middleware, `headless-tanstack-start`'s `cspMiddleware`) calls the same two functions instead of building the header itself.

`resolveFrameAncestors()` reads `process.env.CANVAS_EDITOR_ORIGINS` on every call. When set, it replaces both defaults with the parsed list (split on whitespace or commas); when unset, it falls back to `CANVAS_SITE_URL` plus the current draft session's `renewUrl` origin. Every candidate goes through `toEditorOrigin()`, which normalizes to scheme, host, and port and rejects anything that is not a plain `http(s)` URL: credentialed URLs, wildcard or CSP-delimiter-bearing hosts, and literal IPv6 addresses are all dropped (DNS hostnames that resolve to IPv6 still work). `'self'` is always included, and origins are deduplicated.

`mergeFrameAncestors()` folds the resolved directive into whatever `Content-Security-Policy` value(s) the app already set, handling repeated header fields, array values, and comma-separated policy lists uniformly, and leaves an application-owned `frame-ancestors` directive untouched rather than overriding it. This is embedding policy only; it does not affect draft authentication or postMessage trust between the editor and the frontend. The Astro and TanStack Start Vite integrations also now load `CANVAS_EDITOR_ORIGINS` from framework `.env` files into `process.env`, matching how they already load `CANVAS_SITE_URL`.

## Upgrade

Optional. To explicitly control which origins may embed the frontend for draft preview, set the new variable in the frontend's environment, for example:

```
CANVAS_EDITOR_ORIGINS=https://cms.example, https://staging.example:8443
```

Leave it unset to keep the default behavior (`'self'` plus `CANVAS_SITE_URL` and the draft session's editor origin). Setting it to an empty string suppresses both defaults and admits only `'self'`.
