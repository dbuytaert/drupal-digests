# #3591785: Strengthen AutoSaveManager to generate stable hashes

- **Project:** Drupal Canvas
- **Type:** Major unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591785](https://git.drupalcode.org/project/canvas/-/work_items/3591785) · 1 contributor · 3 comments

## Summary

Drupal Canvas's AutoSaveManager hashes each entity's normalized data both to detect when a draft differs from the last saved version and to detect edit conflicts between concurrent editors. Because that normalization step did not consistently cast values to their canonical PHP types before hashing, equivalent data could produce different hashes, making conflict detection and auto-save comparisons unreliable. This issue strengthens the normalization so hashing is stable and deterministic. On update, a database update hook automatically rehashes all existing stored auto-save entries, so no manual action is required, and the previous fallback that treated entries without a stored hash as conflict-free has been removed since it is no longer needed.

## Impact

Affects site owners.

- **Database update:** New `canvas_post_update_0026_rehash_auto_save_items()` update hook rewrites `data`, `data_hash` and `original_hash` for every existing keyvalue-stored Canvas auto-save entry using the strengthened normalization.

## Technical details

The root cause was that `AutoSaveManager::toStorableArray()` stored raw `FieldItemListInterface::getValue()` output while `normalizeEntity()` separately cast primitives via `PrimitiveInterface::getCastedValue()`, and a near-duplicate casting routine existed in `ComponentSourceBase`. These divergent, partially-raw code paths meant `data_hash` computation could differ for logically identical data.

Both are replaced by a single new helper, `Drupal\canvas\Utility\TypedDataHelper::castRawPhpTypes()`, which recursively normalizes any `TypedDataInterface`: primitives are cast via `getCastedValue()`, traversable elements are walked to arrays, an absent value stays `NULL` while a present-but-empty complex value becomes `[]`, and `ComponentTreeItem` instances are cloned and run through `optimizeInputs()` first so equivalent component trees always normalize identically. A few properties are special-cased to keep `NULL` instead of being cast to `''` or `0`: `ComponentTreeItem::NULLABLE_STRING_PROPERTIES` (`parent_uuid`, `slot`, `label`), `PathItem::langcode`, `EntityReferenceItem::target_uuid`, and `TextItemBase::format`. `AutoSaveManager::toStorableArray()` now also uses this helper, and for config entities carrying a component tree it optimizes inputs on a clone before calling `toArray()`.

With hashing now trustworthy for every entry, the special-case fallback in `AutoSaveManager` that treated auto-save entries lacking `original_hash` (from before an earlier commit) as having no conflict was removed from `detectConflicts()`, `resolveConflict()`, and `getAllAutoSaveList()`; the `AutoSaveEntry` phpstan type now declares `original_hash` and `data_hash` as always present. `canvas.post_update.php` adds `canvas_post_update_0026_rehash_auto_save_items()`, which uses reflection to invoke the now-private `normalizeEntity()`, `generateHash()`, and `toStorableArray()` methods against every stored auto-save keyvalue entry, rebuilding its `data`, `data_hash`, and stored-entity hash in place.</technical>
