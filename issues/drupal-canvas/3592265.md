## Summary

In page templates used with a headless frontend, the Page content marker no longer vanishes in the editor preview in common cases. When a component sync removes the slot that holds Page content, the marker is now kept and placed right after its former container instead of being deleted with the slot. Headless previews no longer replace a slot that contains only Page content with an empty-slot placeholder. If the active frontend reports no editable content region, for example because it lacks the container component, the preview now shows a warning above the frame instead of silently leaving editors with nowhere to add components.

## Impact

Affects module maintainers.

- **New API:** `ComponentTreeItemList::moveItemAfter()` added; `@drupal-canvas/headless-host` geometry events gain an optional `reset: true` flag.

## Technical details

In `JsonSchemaPropsComponentInstanceUpdater`, removed-slot handling now collects every descendant of the removed slots, walking up ancestors. Any item whose component ID is `Marker::PAGE_CONTENT_COMPONENT_ID` gets the container's `parent_uuid` and `slot`, and is moved after the container with the new `ComponentTreeItemList::moveItemAfter()`. The remaining collected subtrees are then filtered out. `ComponentTreeConfigEntityBase::set()` now drops explicit `NULL` `parent_uuid` and `slot` values from `component_tree`, because config represents them by omitting the keys. This matters when the marker moves to the root. The sync docs note the exception.

In the headless package, `isCanvasComponentTreeSlotEmpty()` now treats a string child as a default or example only when it contains no Canvas component comment markers, checked with `parseCanvasCommentMarker()` from `@drupal-canvas/preview-geometry`. Page content marker markup therefore counts as a real child and is rendered in the slot.

In `@drupal-canvas/headless-host`, the `geometry` event gets an optional `reset?: true`. The host sets it on activation, iframe reload, navigation and malformed snapshots, so a host reset can be told apart from a valid empty report from the frontend. In Canvas UI, `useHeadlessDraftSession` returns a new `geometryReady` value. A reset clears both geometry and height readiness. `HeadlessPreview` shows an amber `Callout` only when the preview is active, both height and geometry have been reported, and no `region` with id `content` exists. It keeps the previous iframe height while a reloaded document reports.

## Upgrade

Consumers of `@drupal-canvas/headless-host` that handle `geometry` events can use the optional flag to tell a host reset from a real empty report:

```ts
| { type: 'geometry'; geometry: CanvasGeometry[]; reset?: true }
```
