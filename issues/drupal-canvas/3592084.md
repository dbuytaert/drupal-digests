# #3592084: Canvas entity edit/delete/translation routes render in the front-end theme instead of the admin theme

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)

## Summary

The delete page (`/page/{id}/delete`) and the translations overview page (`/page/{id}/translations`) for Canvas pages used to render in the site's front-end theme. They showed the public header and navigation, and the content was unstyled. They now render in the configured admin theme. The Canvas editor itself is unchanged.

## Impact

No upgrade or configuration changes required.

## Technical details

`Drupal\canvas\Entity\Routing\CanvasHtmlRouteProvider` extended core's `DefaultHtmlRouteProvider`, which never sets the `_admin_route` route option, so the theme negotiator fell back to the default theme. It now extends `AdminHtmlRouteProvider`, which sets `_admin_route: TRUE` on the add, edit and delete form routes it generates. `content_translation` copies that option from `entity.canvas_page.edit_form` onto `entity.canvas_page.content_translation_overview`, so that route is fixed too. The editor route `canvas.boot.entity` is defined separately in `canvas.routing.yml` and does not use this provider. Currently only `canvas_page` uses `CanvasHtmlRouteProvider`. The issue lists test coverage as a remaining task, and I did not check whether tests landed.
