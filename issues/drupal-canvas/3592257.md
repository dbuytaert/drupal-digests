## Summary

In Headless SDK draft mode, reading a single resource of a type without revisions, such as `user--user`, no longer fails. Drupal answered those reads with `501 Not Implemented`, so single-resource reads could resolve to `undefined` and collection items silently fell back to published data. Non-revisionable resources are now readable in draft mode, and revisionable ones such as articles still return their working copy.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix is in `CanvasJsonApiClient` in the `drupal-canvas` package. `getResource()` still adds the configured resource version (`rel:working-copy`) first. If Drupal replies with a JSON:API 501 error (status 501, JSON:API media type, an error with `status: '501'`), the client repeats the read once without the version. This applies only when the caller did not pick a version and did not request `rawResponse`.

The client remembers the type in a private `unversionedTypes` set only if the retry returns the requested resource (same type and id) with a `links` object that has no `working-copy` link. Drupal adds that link to every revisionable resource. After that, reads of the type skip the version parameter, and the result is cached under the unversioned key within the client's cache scope. If the retry looks different, for example an error, non-JSON, a collection, another id or a resource that has a `working-copy` link, the original 501 response is returned and nothing is cached or remembered. Network and draft-session errors still throw. `getResourceByPath()` goes through `getResource()`, so it gets the same behavior.

Collection reads now fetch a working copy only for items that carry a `working-copy` link (`hasWorkingCopyLink()`). Items of non-revisionable types are kept as they are, which avoids one failing request per item. The commit also adds a changeset marking this as a patch for `drupal-canvas`, plus tests.
