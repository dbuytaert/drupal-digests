## Summary

The Canvas Headless content API can now return content in the json-render format when the client sends a `Canvas-Client-Capabilities: json-render` header. The Headless SDK sends this header automatically and its framework components (React, Astro, Nuxt, Next.js, TanStack Start, Angular) now render json-render through new shared `@drupal-canvas/json-render*` packages. Clients that do not send the header still get the legacy Custom Elements JSON, which the README says Canvas 2.0.0 will remove. Headless app developers must now pass `page.isPreview` to the component tree to get preview mode, and the module needs Custom Elements 3.5.0 or later.

## Impact

Affects module maintainers and site owners.

- **Requirements:** `canvas_headless` now requires `custom_elements` 3.5.0 or later.
- **Config change:** New `canvas_headless_content_format` cache context varies content API responses by requested format.
- **API change:** Content and entity API accept a `Canvas-Client-Capabilities: json-render` request header and then return a json-render document (`root`, `elements`) instead of nested Custom Elements JSON; `CanvasComponentTree` gets a `preview` prop and preview mode is no longer inferred from the tree.
- **New API:** New npm packages `@drupal-canvas/json-render`, `-react`, `-astro`, `-vue`, `-angular`; new `Page.isPreview` field from `fetchPage()`; PHP `Drupal\canvas\CanvasClientCapabilities::has()`.

## Technical details

`CanvasContentController` and `CanvasEntityController` pick the format with `CanvasClientCapabilities::has($request, 'json-render')` (case-insensitive, comma-separated tokens) and delegate to the new `CanvasContentSerializer`. It runs the render array through `CanvasRenderConverter`, which replaces `JsComponentCanvasRenderConverter` and is registered as a `custom_elements.render_converter` at priority 60. It then calls the Custom Elements normalizer, using the new `CanvasJsonRenderNormalizer` (tagged `custom_elements.format_normalizer`) for json-render. `CanvasCustomElement` carries the exact component ID and instance UUID, and keeps authored prop and slot names. Element types keep the component ID, for example `js.example_card`. Preview responses use `canvas-marker`, `canvas-slot-placeholder` and `canvas-preview-content-region` elements. An empty managed tree is `root: ""` with `elements: {}`; unmanaged routes still return `content: null`. For legacy requests the old single-root and `renderless-container` shaping is kept inside the serializer.

Caching: the new `canvas_headless_content_format` cache context (`HeadlessContentFormatCacheContext`) is added to responses so the two formats are cached separately. `CanvasHeadlessServiceProvider` alters `http_middleware.page_cache` to chain a new `DisallowCanvasContentApiRequests` policy. Only Internal Page Cache is affected, so HTTP caching of public responses is unchanged. `openapi.yml` documents the header and the `CanvasJsonRenderDocument` and `LegacyCanvasContent` schemas.

SDK: the `@drupal-canvas/headless` package no longer contains its own renderer. Page types now come from `@drupal-canvas/json-render`, and `convertLegacyCustomElementsFormat()` (`legacy-custom-elements.ts`) converts older backend output to json-render using the app's component registry. `fetchPage()` and the entity fetch return `isPreview` (live draft session and managed route) instead of marking the tree with `canvasDraftMode`. The per-framework `CanvasComponentTree` implementations became thin wrappers over the `json-render-*` packages. Those packages render the Canvas editor's component, slot and region markers and empty drop targets in preview mode.

## Upgrade

Pass the `isPreview` value from `fetchPage()` or `fetchEntity()` to the tree. It is no longer inferred from content.

```tsx
<CanvasComponentTree
  tree={page.content}
  preview={page.isPreview}
  context={page.context}
  components={{ 'hello-card': HelloCard }}
/>
```

In Nuxt use `:preview="page.isPreview"`, and in Angular use `[preview]="page.isPreview"`. Update `custom_elements` to 3.5.0 or later (`"drupal/custom_elements": "^3.5.0"`). Apps without the SDK header keep receiving legacy Custom Elements JSON until Canvas 2.0.0.
