## Summary

On the `1.x-workspaces` branch, the Canvas editor now works against the active workspace. Opening the editor with no active workspace switches to Main (when the user may view it). Drafts are read from the workspace, while page deletes, translation deletes and config translation override deletes act directly on Live. Deleting a page or translation that another workspace has staged changes for is refused with a 409 naming that workspace. Content create and status changes stay inside the workspace, and config entity writes through the Canvas config API still go to Live at once.

## Impact

Affects site owners.

- **Permission change:** Page delete access is now decided against Live (`ApiContentControllers::deleteAccess()`), so the delete link and route work while a workspace is active. Publish in tests needs `edit any workspace`.

## Technical details

Core has no staged deletion and forbids deleting an entity Live has while a workspace is active. `ApiContentControllers::delete()` and `ApiTranslationControllers::delete()` therefore became instance methods that call `WorkspaceAutoSave::assertNotLockedInAnotherWorkspace()` and then wrap the delete in `executeOutsideWorkspace()` (from `OptionalWorkspaceManagerTrait`). The `canvas.api.content.delete` route swaps `_entity_access` for `_custom_access: ApiContentControllers::deleteAccess`, which checks `delete` access outside the workspace. The `::list()` delete link uses the same check. The translation delete loads Live via `loadLiveVersion()`, removes the translation and saves outside the workspace. That save fires `hook_entity_translation_delete()`, which drops the translation from every workspace's staged copy. If the translation exists only in the active workspace's draft, it calls `AutoSaveManager::deleteTranslation()` instead. The two PHPStan ignores on `$workspaceManager` are removed now that it is read.

Route upcasting runs inside the workspace, so the upcast entity may be a staged revision. `ApiLayoutController` (layout GET and the label callback) and `EntityFormController` (AJAX POST rebuild) now call `WorkspaceAutoSave::loadLiveVersion()` when no auto-save data applies. In the layout GET, Live also becomes `$original_entity`, so `isNew` and `hasUnsavedStatusChange` are not computed against the staged revision. In the form rebuild, building from the staged revision would add extra rows to multi-value widgets. `CanvasController::__invoke()` loads the Main workspace (`AutoSaveWorkspace::ID`) and calls `setActiveWorkspace()` if none is active and the user has `view` access. The `canvas_update_11201()` guard still applies because `$workspaceManager` is nullable. `ComponentInstanceForm` now implements `WorkspaceSafeFormInterface`. Client side, `brandKit.ts` `updateAutoSave` now handles the returned `autoSaves` hash. Other UI service changes were not in the portion of the diff I read.

Several `@todo Workspaces MR n:` markers were added or retargeted. They cover the `status` default in `ContentTemplate::createFromClientSide()` (MR 9, templates are still created enabled), the `lockedInWorkspace` response key (MR 8), publish access (MR 7a) and whether Main stays active after leaving the editor (MR 16). The ADR text is updated: content create runs inside the workspace and templates are created enabled.
