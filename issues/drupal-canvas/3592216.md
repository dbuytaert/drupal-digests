## Summary

This is the first MR of the Workspaces series on the `1.x-workspaces` feature branch (planned in [#3592187](https://www.drupal.org/node/3592187)). Canvas now requires core Workspaces. Installing Canvas, or updating a 1.x site, enables `workspaces` and creates an undeletable "Main Canvas workspace" (`canvas_default`). Auto-save still uses the 1.x key-value store at the end of this MR, so editors see no change in how drafts are saved. The MR also adds ADR 0022, the design for staging Canvas drafts in workspaces, where the whole workspace is the unit of publish and per-item publish goes away. That ADR is marked "Proposed" and describes behaviour that later MRs in the series implement.

## Impact

Affects module maintainers and site owners.

- **Requirements:** Core `workspaces` module becomes a required dependency of Canvas (core floor unchanged at `^11.3`).
- **Database update:** `canvas_update_11201()` (partial) enables `workspaces` and creates the Main workspace; `Page` `owner` and metatag fields become revisionable, with the update for existing sites in a later MR.
- **Config change:** A `canvas_default` workspace ("Main Canvas workspace") is created on install/update and cannot be deleted while Canvas is installed.
- **New API:** New `Drupal\canvas\AutoSave\Workspace\AutoSaveWorkspace` class with `ID` and `LABEL` constants.

## Technical details

The Main workspace ID and label live in the new `AutoSaveWorkspace` class (`ID = 'canvas_default'`). `WorkspaceAutoSaveRevisionHooks` blocks deleting it: `workspace_access` forbids the `delete` operation, and `workspace_predelete` throws a `LogicException` for programmatic deletes. Per the issue description, the install and update code is `canvas_install()`, `_canvas_ensure_auto_save_workspace()` and a partial `canvas_update_11201()`. I could not read those files in the diff I received, so I have not checked them.

`WorkspaceAutoSaveHooks::entityTypeBuild()` assigns core's `IgnoredWorkspaceHandler` as the `workspace` handler on config entity types provided by `canvas` or a `canvas_*` module. Without it, core refuses to save those entities while a workspace is active.

`Page` now marks the `owner` field revisionable, and the metatag field on pages is also revisionable. A pending revision only carries revisionable fields, so this stops draft changes from skipping the draft and landing on the live page. The issue says an update for existing sites is planned as `canvas_update_11202()` in a later MR. `ViewModeDisplayController` now type-hints `FormController` instead of `HtmlEntityFormController`, because Workspaces decorates `controller.entity_form`. `ApiConfigControllers`, `ApiContentControllers` and `ApiTranslationControllers` gain a nullable `WorkspaceManagerInterface $workspaceManager` constructor argument, autowired from `workspaces.manager`. Per the comment in the diff, it is NULL while a 1.x site has not yet run `canvas_update_11201()`. It is not read yet: each is marked with a `@todo Workspaces PR 5` and PHPStan ignores.

`ComponentSourceManager` takes a new `TypedConfigManagerInterface` and returns early from component generation when `canvas.component_source_settings.*` has no config schema. This covers the case where Canvas and Workspaces install in one batch and Layout Builder's cache tag invalidator clears the block manager before Canvas's schema is available. The `workspace_switcher` block is added to the excluded list in `BlockComponentDiscovery`. `EntityFieldPropSourceMatcher` skips fields that are explicitly internal, such as Workspaces' `workspace` revision field, using `TypedDataHelper::isExplicitlyInternal()`.

Tests and docs make up the rest. The tests install `workspaces`, add the `workspace` cache context to expected responses, and add a `WorkspacesDependencyUpdateTest` update-path test. The docs are ADR 0022, `docs/diagrams/workspace-autosave.md` and a `docs/personalization.md` update. A `@todo Workspaces PR` convention is documented in the branch's PR-landing skill file.

## Upgrade

Sites on Canvas 1.x updating to this branch should run database updates: per the issue, `canvas_update_11201()` enables `workspaces` and creates the `canvas_default` workspace. Core Workspaces is a core module, so there is no composer change, and the core floor stays `^11.3`. Tests that install Canvas now also need `workspaces` and its schemas, a `canvas_default` workspace, and the `workspace` cache context in expected cache contexts. Controllers that read through `controller.entity_form` should type-hint `Drupal\Core\Controller\FormController` rather than `HtmlEntityFormController`.
