## Summary

Enabling the core `block_content` module on a site with Canvas installed (reproduced on Drupal CMS) no longer breaks the site. Before the fix, the install failed partway with a missing `block_content` table error, and even `drush cr` failed afterwards, so only a database restore or reinstall recovered the site. Canvas now holds off generating block components until the module install has finished.

## Impact

No upgrade or configuration changes required.

## Technical details

Core clears plugin definition caches in the middle of `ModuleInstaller::doInstall()`, before the new module's entity tables exist. Canvas's `BlockManagerDecorator::clearCachedDefinitions()` called `generateComponents()` for the block source right then. That triggered block discovery, and the `block_content` derivative queried a table that wasn't there yet. The same pattern was reported to crash Webform on sites with Trash 3.1.0.

The fix adds a public `$moduleInstallInProgress` flag on `BlockManagerDecorator` (the class loses `readonly`, with its constructor properties made `private readonly`). `clearCachedDefinitions()` still clears the decorated cache but returns early without generating components while the flag is set. `ComponentSourceHooks::modulePreinstall()` (`hook_module_preinstall`) sets the flag and `modulesInstalled()` clears it, after which Canvas generates components again. The flag lives on the service, so a container rebuild resets it. The code comments say this is safe because core rebuilds the container before `hook_module_preinstall()` and any later rebuild happens after the tables exist.

New kernel tests in `BlockManagerDecoratorTest` install `block_content` alone and together with `contact`, and check that new reusable block content still becomes a `Component` right after the install. The decorator carries a `@todo` to refactor once core issue [#3001284](https://www.drupal.org/node/3001284) (cache tags for plugin derivers) lands.

### Collaboration

phenaproxima reproduced the failure on the latest Drupal CMS, then showed Canvas was the trigger by uninstalling it and re-enabling `block_content` without errors. After discussing it with mglaman, who agreed it was not a core bug, phenaproxima concluded that Canvas was populating a cache while core was clearing it. The agreed direction was to generate components lazily rather than during cache clear. The delivered fix is narrower: it skips generation only while a module install is in progress.
