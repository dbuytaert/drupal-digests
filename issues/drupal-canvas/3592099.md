# #3592099: Add headless previews for entities

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592099](https://git.drupalcode.org/project/canvas/-/work_items/3592099) · 1 contributor · 3 comments

## Summary

Sites using Canvas Headless previously showed an empty page when a published node, page, or other Canvas-managed entity was opened directly on the Drupal domain, since Drupal has no theme to render the frontend-owned component tree. This release embeds the configured headless frontend in those pages instead: authenticated users with the preview permission now see the actual frontend rendering inside an iframe, with Drupal's toolbar, admin navigation, and status messages still visible around it. Links that resolve to Drupal-owned destinations navigate normally in the parent window, while frontend-only links stay inside the iframe. The same embedding now also covers node form previews, revision routes, and Content Moderation's "latest version" routes, letting editors preview unsaved drafts and past revisions through the real frontend rather than through Drupal's own rendering. A new `excludeAutoSave` option lets a preview request render only saved content, ignoring in-progress Canvas auto-saves.

## Impact

Affects module maintainers.

- **New API:** New `Drupal\canvas_headless\Routing\CanvasContentRoute::resolve()` identifies the entity and view mode shared by Drupal and frontend rendering for canonical, preview, revision, and latest_version routes; new `EmbeddedPreviewSubscriber` selects a `canvas_headless_preview` page display variant to embed the frontend.

## Technical details

The core addition is `Drupal\canvas_headless\EventSubscriber\EmbeddedPreviewSubscriber`, which hooks `RenderEvents::SELECT_PAGE_DISPLAY_VARIANT` at priority `-110` (after Canvas's own `-100` variant selection) and, for eligible authenticated requests, swaps in the new `EmbeddedHeadlessPreviewPageVariant` display variant. That variant renders an `iframe` pointed at the frontend's preview URL plus Drupal's status messages, and ships a new `headless.preview` library (built from the new `@drupal-canvas/headless-embedded-preview` package) that handles session bootstrap and link navigation delegation via the existing `@drupal-canvas/headless-host` package.

Route identification is centralized in the new `Drupal\canvas_headless\Routing\CanvasContentRoute` value object, replacing the old `CanvasContentRouteEnhancer::PRIMARY_ENTITY_PARAMETER` mechanism. It recognizes `entity.*.canonical`, `.preview`, `.revision`, and `.latest_version` route names, resolves the correct entity and view mode, and flags whether the route is a "preview" (unsaved form values or a specific revision) versus a normal canonical view. `CanvasContentController` and `CanvasEntityController` use this to decide `$use_auto_save` independently from `$is_entity_preview`, since preview/revision routes must render the exact selected content (never a Canvas auto-save) and must disable render and response caching (`max-age = 0`), matching core's `NodePreviewController` behavior. A new `NodePreviewAccessCheck` decorates core's `access_check.node.preview` to grant read-only access to a preview token's subject without also granting the write access core normally requires for node previews.

`CanvasContentEntityRenderer::containsThemePageTemplate()` was inverted into public `isHeadlessCompatiblePageVariant()`, reused by both the controller and the new subscriber to decide whether a page variant can be embedded. On the frontend SDK side, `fetchPage()` in `@drupal-canvas/headless`, `-next`, `-nuxt`, `-astro`, `-angular`, and `-tanstack-start` now reads preview context per request (via a new `preview-context.ts` module and `excludeAutoSave` support) instead of a shared draft session, so multiple open tabs no longer clobber each other's rendering settings, and a new `navigation-bridge.ts` in `@drupal-canvas/headless` delegates eligible embedded link clicks to the host Drupal window in draft mode.
