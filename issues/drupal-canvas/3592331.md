## Summary

In the Canvas editor, editing a component's props no longer reloads the whole preview iframe when only one component instance changed. That instance's markup is replaced in the live preview, or, for an island whose only change is its props, the props attribute is updated so it re-renders without going blank. This removes the flicker and the refetching of all CSS and JavaScript on each edit. Any other difference, such as changed `<head>` assets or `drupalSettings`, still loads the whole document as before.

## Impact

No upgrade or configuration changes required.

## Technical details

A new `inPlaceUpdate.ts` provides `findInPlaceUpdate()`, which compares the previous and new preview HTML by common prefix and suffix. It finds the innermost `canvas-start-…`/`canvas-end-…` comment-marker pair enclosing the whole difference and returns null if the change lies outside any instance or nothing changed. `applyInPlaceUpdate()` locates the marker pair in the active iframe's document, and returns false if the markers are not siblings. Otherwise it detaches Drupal behaviors from the old elements with `Drupal.detachBehaviors(element, null, 'unload')`, unmounts removed `canvas-island` elements, inserts the new markup, and calls `Drupal.attachBehaviors()` on the markers' parent element. When the replaced content is a single `canvas-island` differing only in `props`, the attribute is set on the live element, and only if the decoded props differ.

`IFrameSwapper` tracks the HTML the active iframe shows and tries an in-place update first. It falls back to the hidden-iframe load and swap when none applies. `Viewport` gets an `inPlaceUpdates` counter so `unsetUpdatingComponent` still fires, since an in-place update changes neither loading flag. Because it works on HTML, it covers undo and redo with no API change.

Supporting changes: the `canvasDisableLinks` behavior now returns early when its context has no `body`, since behaviors can now run with an element context. The island custom element unmounts the previous render before re-rendering when `ssr` is set, and unmounts nested islands replaced by a render. The `attributeChangedCallback` workaround that deleted Preact's private VNode property is removed.

## Upgrade

Custom Drupal behaviors that run in the Canvas preview may now receive an element as `context` rather than the document, as `canvasDisableLinks` was changed to handle. Guard any use of `context.body` and use `once()` so unchanged siblings are not initialized twice.

```js
if (!context.body) {
  return;
}
```
