## Summary

Canvas (formerly Experience Builder) can now ask which config entities, such as pattern or page region entities, depend on particular versions of a Component, not just on the Component as a whole. The goal is to support later work on pruning unused Component versions ([#3530097](https://www.drupal.org/node/3530097)). Calls that don't pass versions behave as before. This describes the merge request diff, which is a proposal.

## Impact

Affects module maintainers.

- **New API:** `ComponentAudit::getConfigEntityDependenciesUsingComponent()` accepts an optional `array $version_ids = []` to restrict results to config entities using those Component versions.

## Technical details

The method signature becomes `getConfigEntityDependenciesUsingComponent(ComponentInterface $component, string $config_entity_type_id, array $version_ids = [])`. It mirrors the version-aware `getContentRevisionsUsingComponent()`. When `$version_ids` is non-empty, the dependents found through the config dependency manager are filtered further. Each dependent is loaded. It is kept only if it implements `VersionedConfigEntityInterface`, one of the requested versions exists in `getVersions()`, and `getVersionSpecificDependencies($version_id)` for that version contains the Component's config dependency name. Dependents that are not versioned config entities are dropped when a version filter is given. With an empty array the original behavior is unchanged. The diff shows no test changes, and the author left the issue at "Needs work" so others could add tests.
