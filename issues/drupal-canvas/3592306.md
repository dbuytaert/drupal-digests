## Summary

In Canvas, layout edits made in quick succession are sent to the server one at a time. If an editor switched to another page while an edit was still waiting, the edit was sent to the page they had switched to. For a duplicated page, which shares component instance UUIDs with its source, the edit was silently saved into the duplicate's draft and the original lost it. For other pages the server returned a 404 and the edit was lost. Queued edits now go to the page that was showing when the edit was made.

## Impact

No upgrade or configuration changes required.

## Technical details

In `withSerializedLayoutMutations` in `ui/src/services/baseQuery.ts`, layout POST and PATCH requests are chained so only one runs at a time. Previously the `{entity_type}` and `{entity_id}` placeholders in the URL were only replaced when the request actually ran, using `window.location.href` at that moment. Because the request also carried the new page's autoSaves hash, the server's conflict check passed.

The fix calls `extractEntityParams(window.location.href)` and `replaceEntityParamsInUrl` before the request joins the queue, builds `resolvedArgs` (handling both string and object args), and passes that to `baseQuery` once the previous request resolves. The target URL is therefore frozen at queue time. New tests in `ui/src/services/baseQuery-utils.test.ts` cover a navigation from `/canvas/editor/node/1` to `/node/99` while a PATCH waits, and check that PATCH and `postPreview` run in order.
