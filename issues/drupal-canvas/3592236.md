## Summary

This is the 1.x update path for the Workspaces work, merged to the `1.x-workspaces` branch. A 1.x site with unpublished Canvas drafts now keeps them when updating. A new post-update moves each draft into the Main workspace. It keeps the draft's content, its last editor and its last-edit time. Drafts whose entity or language no longer exists are dropped. Form validation error rows are re-keyed so they still match the migrated drafts. The update tests for the 1.x fixtures were adjusted to expect the drafts in workspace staging, and a new update test covers the migration.

## Impact

Affects site owners.

- **Database update:** New `canvas_post_update_0031_migrate_auto_save_to_workspace()` moves 1.x `canvas.auto_save` key-value drafts into the Main workspace and re-keys form violation rows with a `main:` prefix.

## Technical details

`canvas_post_update_0031_migrate_auto_save_to_workspace()` is a batched post-update that handles 25 rows per pass. Each row goes through the new `LegacyAutoSaveMigrator::migrate()` (registered in `canvas.services.yml`), which resolves the target entity or translation and calls `WorkspaceAutoSave::importLegacyArray()` inside `executeInWorkspaceUnchecked()` for the Main workspace. Content entity rows are staged as workspace revisions inside a database transaction. Config entity rows are moved as they are into `AutoSaveFallbackStore`. If the entity already has staged content in Main (`hasWorkspaceStaging()`), the staged draft wins and the 1.x row is dropped. Malformed rows, rows for deleted entities, and rows for deleted languages are also dropped, along with their violation row.

A 1.x row holds one translation. The importer therefore overlays it onto a copy of the stored entity, or onto the revision already tracked in Main. That way sibling translations and the real default language survive publishing. The new `legacyAttribution` property lets `stampAutoSaveWorkspaceRevisionMetadata()` use the 1.x editor and edit time. If the 1.x editor user no longer exists, the current user is used. Under `drush updb` that is anonymous, and the code carries a `@todo` for it.

Once all rows are migrated, the post-update re-keys the form violation stores (`FORM_VIOLATIONS_STORE` and `COMPONENT_INSTANCE_FORM_VIOLATIONS_STORE`) under the `AutoSaveWorkspace::ID . ':'` prefix. It skips keys that already carry the prefix, so a re-run is safe. This happens in the post-update, not in `canvas_update_11201()`, because `canvas_post_update_0010_migrate_auto_save()` writes violation rows after every `hook_update_N()` has run. `PageVariantMigration` now migrates the `page_region:` rows itself, so its draft lookups find them. `AutoSaveManager::overlaySnapshotOntoStored()` became public, marked `@internal` for the importer.

The diff has no changes for the `ServiceNotFoundException` and Main-workspace lock failures that the issue lists as known bugs. It has no `canvas_post_update_0032_workspace_permissions()` and no `canvas_update_11202()` change either. I did not verify those items.

## Upgrade

Run database updates as usual (`drush updb`). `canvas_update_11201()` enables Workspaces and creates Main, then `canvas_post_update_0031_migrate_auto_save_to_workspace()` migrates the 1.x drafts. Code that reads the `canvas.auto_save` key-value store directly will find it empty afterwards. Staged drafts are read through `AutoSaveManager`.
