# #3591839: Prefix-strip redirect misses default-language prefixes and is overridden by ?destination

- **Project:** Drupal Canvas
- **Type:** Major bug report
- **Version:** 1.x-dev
- **Status:** Fixed
- **Discussion:** [#3591839](https://git.drupalcode.org/project/canvas/-/work_items/3591839) · 1 contributor · 14 comments

## Summary

Canvas's editor could show a blank gray screen on multilingual sites when the site's default language itself has a URL prefix (e.g. `/en/` is configured as the prefix for the default English language). The redirect that strips the language prefix from `/canvas` paths only fired when the current language differed from the default, so a prefixed default-language path reached the React app unstripped and it couldn't route it. Separately, clicking Edit on `/admin/content/pages` for a page under a prefixed language could bounce the user back to the content overview instead of opening the editor, because the `destination` query parameter carried by that link survived the redirect and Drupal's core redirect handling used it to override the target. Both problems are fixed: the prefix is now stripped based on what is actually configured for the current URL-negotiated language (default or not), and the query string is preserved on the redirect while `destination` is cleared from the request so it can no longer hijack the target.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix is in `CanvasRouteOptionsEventSubscriber` (marked `@internal`), whose redirect method was renamed from `redirectCanvasToDefaultLanguage()` to `redirectCanvasToUnprefixedPath()` to match its new behavior. Instead of comparing the current negotiated language against the site's default language, it now reads the prefix actually configured for the URL-negotiated language from `language.negotiation:url.prefixes`; an empty prefix means there's nothing to strip, regardless of whether that language is the default. It also checks `language.negotiation:url.source` against `LanguageNegotiationUrl::CONFIG_PATH_PREFIX` so a leading path segment is only treated as a language prefix under path-prefix negotiation (not domain negotiation, where a matching segment is a real path component), and it bails out early if the `language` module isn't installed, since `LanguageNegotiationUrl` would not be autoloadable in that case.

When a prefix is stripped, the method now builds the `LocalRedirectResponse` target from `$request->getQueryString()` so query parameters survive the redirect, and calls `$request->query->remove('destination')` before building the response so `RedirectResponseSubscriber` in core cannot later override the computed redirect target with a stale `destination` value. New kernel tests in `CanvasLanguageRoutesTest` cover: a default language with its own non-empty prefix, single-language sites with a configured prefix, query-string preservation including `destination`, a non-matching leading path segment being left untouched, and domain-based negotiation not stripping a path segment that happens to match a configured prefix.
