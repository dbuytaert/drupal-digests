## Summary

Canvas config drafts (content templates, patterns, page variants, code components) were invisible to core's Workspaces screens, because core only tracks content entity revisions. A workspace holding only config drafts showed "no changes" on the publish and manage pages, the Publish button was disabled, and the delete form did not name the drafts it would discard. Each config draft now has a small tracked "Canvas draft" marker, so core lists and counts it (for example "1 Canvas draft"). Run database updates after upgrading. Drafts that already exist get a marker only on their next auto-save.

## Impact

Affects module maintainers and site owners.

- **Database update:** `canvas_update_11203()` installs the new `canvas_auto_save_draft_marker` content entity type.
- **Config change:** None beyond the new entity type; the Doctor JSON schema gains an `auto_save_draft_markers` entry.
- **New API:** Internal `AutoSaveDraftMarker` entity, `AutoSaveDraftMarkerManager` service, and new `auto_save_draft_markers` Doctor check (advisory risk).

## Technical details

Config drafts stay as rows in the per-workspace fallback store; a new internal, revisionable content entity type `canvas_auto_save_draft_marker` (`Drupal\canvas\Entity\AutoSaveDraftMarker`, using core's `DefaultWorkspaceHandler`) is tracked by `WorkspaceTracker` in their place. Decorating the tracker was rejected because its consumers pass the returned revision IDs to `loadMultipleRevisions()` or `deleteRevision()`, which config entities cannot satisfy. The marker stores the workspace ID, fallback key, target entity type and ID, and langcode; label, changed time and owner are read from the store's metadata at render time, so later auto-saves write no new revision.

The new `AutoSaveDraftMarkerManager` service creates the marker inside the workspace on the first fallback-store write and deletes it outside any workspace on discard, after publish, and on workspace delete. A unique key on the target is added through `AutoSaveDraftMarkerStorageSchema`. `AutoSaveManager::purgeDeletedEntity()` ignores markers. The new `auto_save_draft_markers` Doctor check reports drafts without a marker and markers without a draft as an advisory risk, not a failure. ADR 0022 is updated accordingly.

The commit also changes publish gating. `AutoSaveManager::hasChangedLiveBase()` makes the pre-publish check refuse a config draft whose Live entity changed since the draft started (reusing the base hash comparison extracted into `getChangedLiveBase()`), and a new `onCanvasConfigOverrideChange()` subscriber on `language.save_override` and `language.delete_override` advances a draft's stored base hash when its entity gains or loses a translation. Per the issue, `WorkspacePublishValidationException` is changed to extend core's `WorkspacePublishException`, so the publish form shows per-item violations; that file was in the omitted part of the diff and I did not read it. Merging child workspaces is explicitly not supported; ADR 0022 records this.

## Upgrade

Run `drush updatedb`. `canvas_update_11203()` installs the `canvas_auto_save_draft_marker` entity type. Existing config drafts are not backfilled (see the `@todo Workspaces MR 6` in the update function) and get a marker on their next auto-save.
