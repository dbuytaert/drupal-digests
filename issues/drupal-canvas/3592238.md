## Summary

In the 1.x-workspaces branch, the Canvas publish review panel now publishes the whole workspace at once. The per-change checkboxes, "Select all" and "Publish N selected" are gone, replaced by a single "Publish now" button and an "N unpublished changes" count. The side-by-side review button becomes "Review all changes", which walks every reviewable change. A conflicted change blocks publishing until it is resolved. Refusals that concern the workspace as a whole, such as core refusing to publish an item in an unpublished moderation state, now show in the error list under "Workspace".

## Impact

Affects module maintainers and site owners.

- **Permission change:** Publishing now goes through core workspaces, so the e2e/test setups grant `view any workspace`, `edit any workspace` and `create workspace` alongside `publish auto-saves`.
- **New API:** `drupalSettings.canvas.workspaces.stagingWorkspaceId` is now exposed to the UI, and a `canvas_e2e_support.update_live` test route (`LiveEntityController::updateLive`) saves the Live copy outside any workspace.

## Technical details

`ui/src/services/pendingChangesApi.ts`: `publishAllPendingChanges` takes no argument. It POSTs to `/canvas/api/v0/auto-saves/publish` with `{ workspace, pendingChanges }`. `workspace` comes from `getStagingWorkspaceId()`, which reads `drupalSettings.canvas.workspaces.stagingWorkspaceId`. The server now sets that value from `workspaceAutoSave->getStagingWorkspaceId()`, so a tab whose workspace was switched elsewhere cannot publish a different workspace. `pendingChanges` maps each auto-save key to its `data_hash` from the cached `getAllPendingChanges` result. Before building the body it waits for in-flight preview and layout auto-save mutations and refetches the list, so a publish right after an edit isn't refused as "edited after the review". On a 409 it restores the previous pending changes and sets the conflicts and errors. On success it clears the whole pending cache.

`PublishReview` loses its selection state, and `onPublishClick` is called without arguments. `UnpublishedChanges` passes all unpublished changes to the hook's cleanup. `onReviewSelectedChanges` is replaced by `onReviewAllChanges`, and conflicted pages and non-page changes are excluded from the walk. The review is still gated on `isReviewUxEnabled()`. A refused publish drops the snapshot, so discarding the refused changes afterwards doesn't flash "Published". `ReviewErrors` labels errors whose `source.pointer` is `workspace` as "Workspace". Errors tied to no entity (code 11 for a discarded key, validation violations, server errors, plain 403 strings) are counted in the header but not listed. Auto-save keys are now workspace-scoped (e.g. `canvas_default:canvas_page:1:en`). `PageStatus` therefore finds the homepage staged config update with `findInChanges` instead of an exact key lookup.

The Playwright specs were rewritten for this. `canvas_e2e_support` gets a `LiveEntityController` route that simulates external edits to Live, and a new `article_moderation` recipe fixture backs a spec checking that a draft moderation state refuses to publish. Two `@todo Workspaces MR 8` and `MR 9` markers remain for the workspace switcher, lock notice and Draft badge.

## Upgrade

Tests or custom code that drove per-item publish must change. Replace the selection clicks (`canvas-publish-review-select-all`, `Select change <title>`, `Publish N selected`) with a click on the `Publish now` button. Test roles that publish need core workspace access, as in the updated setups:

```
'publish auto-saves',
'view any workspace',
'edit any workspace',
'create workspace',
```

Pending-change keys now carry the workspace prefix, for example `canvas_default:canvas_page:${id}:en`.
