## Summary

On the `1.x-workspaces` branch, a page created in the Canvas editor while a workspace is active is now staged as published, so a single workspace publish makes it live. Before, it went live unpublished and the editor had to stage the status and publish a second time. A content template created in a workspace is now created disabled, so the core display keeps rendering for every visitor until the template's first draft is published with the workspace. Before, it was saved to Live enabled with an empty component tree and rendered that view mode empty.

## Impact

No upgrade or configuration changes required.

## Technical details

Config has no workspace storage and core keeps the Live default revision of a workspace-created entity unpublished, then promotes pending revisions verbatim. For pages, `ApiContentControllers::post()` now defaults `status` to the new private `createsPublished()`, which is TRUE when `workspaceManager->hasActiveWorkspace()`. Core's `WorkspaceProviderBase::entityPresave()` and `entityInsert()` then save an unpublished default revision in Live and a published pending revision in the workspace. An explicit `status` in the request body still wins, and outside a workspace the default stays FALSE. `duplicate()` uses the same decision and no longer calls `autoSaveManager->delete()` on the duplicate.

`AutoSaveManager::entityIsConsideredNew()` now always loads the Live version through `WorkspaceAutoSave::loadLiveVersion()` and returns FALSE if that Live entity is published, otherwise falls back to the default-title or duplicate-suffix check. In `getEntityOperations()` the branch that hid both publish and unpublish actions for drafts is removed, so a staged-published new page shows "Unpublish page". In the UI, `PageStatusBadge` shows "Draft" on `isNew` alone, and `ChangeRow.tsx` no longer checks `isNew` when deciding whether a page is unpublished.

For templates, `ContentTemplate::createFromClientSide()` restores the 1.x default `'status' => $data['status'] ?? FALSE`. At publish, `WorkspaceAutoSave::stageFallbackDrafts()` calls `ContentTemplate::autoSavePublish()`, which sets status TRUE, so the template is enabled when its draft goes Live. A template created and never edited has no draft and stays disabled after publish. ADR 0022 is updated (content template created disabled; consequence 9 rewritten). A newly created page is now a pending change that appears in the review panel.
