## Summary

Publishing a workspace no longer deletes it. Before this change, Canvas deleted every published workspace except Main on every publish surface (Workspaces UI, Drush, cron, Canvas API), even workspaces holding no Canvas content. Now a named workspace is kept after publish, matches core's behavior, stays active for sessions that had it active, and shows no pending changes. Deleting it is left to the site admin through core's delete form, which checks delete access and refuses a workspace with children. The editor stays on the published workspace instead of reloading into Main.

## Impact

Affects site owners.

- **Config change:** Published named workspaces now persist and must be deleted manually through core's delete form; previously Canvas deleted them on publish.

## Technical details

`AutoSaveWorkspacePublishSubscriber::onPostPublish()` now only calls `clearWorkspaceStores()` for the published workspace and no longer calls `$workspace->delete()`. This removes three problems the issue lists: the delete bypassed access checks, `Workspace::preDelete()` threw for a workspace with children after core had already committed the publish (the UI reported "Publication failed" while content was Live), and core's publish form hit a 404 on the deleted workspace's route. The subscriber keeps its `-600` priority on `WorkspacePostPublishEvent`, now documented as running after core's `WorkspaceTracker::onPostPublish()` association cleanup (`-500`) so the cleared caches are not rebuilt from tracking rows core is about to remove.

With deletion gone, the fallback in `CanvasWorkspacePublisher::publish()` that called `switchToLive()` when the active workspace had vanished was removed. On the frontend, `usePublishPendingChanges` no longer calls `window.location.reload()` after publishing a named workspace; it always invalidates the `Workspaces` RTK Query tag to refresh the pending count. ADR 0022 and the architecture diagram were updated (post-publish now clears stores and keeps the workspace), the `@todo Workspaces MR 13` comments were removed, and kernel, controller, Vitest and Playwright tests were changed to assert the workspace survives. A new kernel test, `testCoreWorkspacePublishKeepsNamedWorkspace`, covers a workspace with a child workspace, a second publish from the same workspace, and a workspace holding no Canvas drafts.
