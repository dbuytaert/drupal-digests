# #3591894: Error message for empty value is displayed for select props even when they're not required

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)

## Summary

In the Canvas editor, choosing "- None -" on an optional select prop (one backed by an enum) no longer shows a validation error such as "data must be string". Required selects are still validated as before.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix landed in `getCurrentValueFromProps()` in `ui/src/components/form/react-hook-form/utils/index.ts`, not in `shouldSkipPropValidation()` as the issue body proposed. When a select had options but none was marked `selected`, the function returned `undefined`. The existing check in `shouldSkipPropValidation()` (`componentFieldValidation.ts`) only skips validation for an optional `SELECT` or `OPTION` when the value is `'_none'`, which matches core's behavior. So the `undefined` value reached schema validation and failed. `getCurrentValueFromProps()` now returns the selected option's value if there is one. Otherwise, if `props.options` exists, it returns `'_none'`, so the existing skip logic applies. The change adds Vitest unit tests in `ui/tests/vitest/unit/formUtils.test.js`.
