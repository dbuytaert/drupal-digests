# #3592009: Have date props display in the format of the selected locale

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592009](https://git.drupalcode.org/project/canvas/-/work_items/3592009) · 1 contributor · 3 comments

## Summary

Canvas stores `date`, `date-time`, and `time` props as raw ISO strings and previously passed them to templates unchanged, leaving component authors to write their own locale formatting. This adds opt-in helpers, `canvasFormatDate`, `canvasFormatDateTime`, `canvasFormatTime`, and `canvasFormatDateRange`, usable both as Twig filters (in SDC templates) and as JavaScript/TypeScript functions (in code components). They render the value in the site's active Drupal interface language and always treat a value without a UTC offset as UTC, so a stored date never shifts to the previous or next day because of the visitor's local timezone.

## Impact

Affects module maintainers.

- **New API:** New Twig filters `canvasFormatDate`, `canvasFormatDateTime`, `canvasFormatTime`, `canvasFormatDateRange` and matching JS/TS exports (`canvasFormatDate`, `canvasFormatDateTime`, `canvasFormatTime`, `canvasFormatDateRange`, type `CanvasDateFormatOptions`) from `drupal-canvas` for locale-aware formatting of Canvas date props.

## Technical details

On the PHP side, a new `Drupal\canvas\Utility\DateResolver` service backs the Twig filters registered in `CanvasTwigExtension`. It reads the current interface language and formats with `IntlDateFormatter` when the `intl` extension is available, falling back to PHP `date()` patterns in the generated, `@internal` `DateFallbackPatterns` class (produced by `scripts/generate-date-fallback-patterns.php` from ICU short-format data) for environments without `ext-intl`.

On the JS side, `date-utils.ts` in the `drupal-canvas` package implements the same four functions using `Intl.DateTimeFormat` with `timeZone: 'UTC'`, reading the locale from a new `drupalSettings.canvasData.v0.langcode` value. That setting is a new addition to `DrupalSettings` and to the allowed `dataDependencies.drupalSettings` values (`canvas.js_component.*` schema, `ComponentSourceHooks::ASSET_LIBRARY_METHOD_MAPPING`, `CodeComponentDataProvider::getCanvasDataLangcodeV0`); it's populated automatically whenever a code component imports any of the four functions from `drupal-canvas`, similar to how other `v0.*` settings are attached on demand.

## Upgrade

Component authors can opt in without any migration; existing components keep receiving raw ISO strings unless they use the new helpers.

Twig (SDC) templates:
```twig
<p>{{ my_date_prop|canvasFormatDate }}</p>
<p>{{ my_datetime_prop|canvasFormatDateTime }}</p>
```

Code components (JSX/TSX):
```tsx
import { canvasFormatDate, canvasFormatDateTime } from 'drupal-canvas';

const formattedDate = canvasFormatDate(myDateProp);
const formattedDateTime = canvasFormatDateTime(myDatetimeProp, { dateStyle: 'long' });
```
Importing any of the four functions automatically adds `v0.langcode` to the component's `dataDependencies.drupalSettings`.
