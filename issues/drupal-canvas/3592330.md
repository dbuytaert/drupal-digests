## Summary

On the unreleased `1.x-workspaces` branch, a Canvas config entity (content template, pattern, page variant, code component and so on) with a draft in one workspace is now locked to that workspace, the same way content is. A second workspace, Main included, that tries to write a draft of the same entity is refused with a 409 naming the owner, until the draft is published or discarded. This stops the workspace published last from silently overwriting the other's config change in Live. A staged translation of a config entity shares its entity's lock, so a draft of either one locks both.

## Impact

No upgrade or configuration changes required.

## Technical details

`WorkspaceAutoSave::getFallbackDraftOwningWorkspaceId()` finds the owner of a config entity by looking for a row in each workspace's `AutoSaveFallbackStore` collection, skipping the staging workspace. The fallback row is the lock, not the draft marker, since staged config translations and rows migrated from 1.x have no marker.

The lock is a group: the config entity plus its `StagedLanguageConfigOverride` drafts, one key per site language, built as `staged_language_config_override:<langcode>.<config name>`. A staged translation resolves its parent through `ConfigManagerInterface::loadConfigEntityByName()`; a `ComponentTreeConfigEntityBase` uses `getConfigDependencyName()`. Without grouping, a workspace could stage the parent and then be refused on a translation the other workspace holds, leaving a partial draft. `WorkspaceAutoSave` now takes `ConfigManagerInterface` and `LanguageManagerInterface` in its constructor, and `AutoSaveFallbackStore::getDrafts()` is new, returning the drafts for a list of keys in one call. `holdsLockGroupDraft()` uses it per workspace.

Because one workspace can hold a draft of the group at a time, the publish-time hash-advance comment in `AutoSaveManager` was reworded: a draft in another workspace is only possible for a Live save of the translation made outside a publish. ADR 0022 decision 5 was updated to say translations share the lock. The editor shows no lock notice for config; the second editor just sees the 409 (`EntityLockedInAnotherWorkspace`, with the owner in `meta.workspace`). New tests cover the layout PATCH 409 body for a content template and the lock in both directions between a parent and its `fr` translation draft.
