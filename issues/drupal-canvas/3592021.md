# #3592021: Canvas AI: Unify error handling in `canvas_component_agent`'s tools

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592021](https://git.drupalcode.org/project/canvas/-/work_items/3592021) · 1 contributor · 50 comments

## Summary

The Canvas AI tools used by `canvas_component_agent` now report every validation problem at once instead of stopping at the first one, so the model can fix everything in a single retry. The tools also refuse to run for users without the Canvas AI permission. The error text sent back to the model changes from YAML `error:` output to a markdown list.

## Impact

Affects site owners.

- **Permission change:** `GetJsComponent`, `GetPropsType`, `CreateComponent` and `EditComponentJs` now throw unless the current user has `CanvasAiPermissions::USE_CANVAS_AI`.

## Technical details

This applies the pattern from [#3591958](https://www.drupal.org/node/3591958) (already used by `place_components` and `edit_components`) to the JS component tools. `CreateComponent` and `EditComponentJs` now start with the access check, which throws unchanged. Every other check adds to an `$errors` array keyed by item label (`Component`, `Slots`, `Slot <index>`), and the array is reported through `AiResponseValidator::formatErrors()`. That output starts with "Nothing was applied. Fix every error listed below and call the tool again." and has one `##` section per item with bullet errors. The message is logged as a warning and set as the tool output, so a failing call applies nothing.

In `AiGeneratedJsComponentPropsAndSlotsTrait`, `transformSlotsMetadata()` now takes an `array &$errors` by-reference parameter instead of throwing. It collects an error for each bad slot and leaves invalid slots out of the returned slots, so the remaining structure is still validated in the same pass. In `EditComponentJs` the structure validation runs only when the component was found. The `@apply` CSS check and the "component already exists" check in `CreateComponent` now accumulate rather than returning early. Constraint violations from `JavaScriptComponent::createFromClientSide()` are added under `Component` using the `ConstraintViolationException` message.

Unexpected exceptions are still caught and logged. Their output is now plain text, `Failed to create the component: ...` or `Failed to update the component: ...`. It was previously `Yaml::dump(['error' => 'Failed to process Javascript component data: ...'])`. `GetJsComponent` and `GetPropsType` gain the same `USE_CANVAS_AI` permission check. `GetPropsType` gets a `create()` method to inject `AccountProxyInterface`. Kernel tests for the four tools were updated, and a new `GetPropsTypeTest` was added.

## Upgrade

Any code that parses the YAML `error:` output of `CreateComponent` or `EditComponentJs` must handle the new plain-text and markdown messages. The `transformSlotsMetadata()` trait method now takes a second argument, `array &$errors`, instead of throwing.
