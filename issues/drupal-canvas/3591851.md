# #3591851: Allow patterns to be edited

- **Project:** Drupal Canvas
- **Type:** Normal feature request
- **Version:** 1.x-dev
- **Status:** Fixed
- **Discussion:** [#3591851](https://git.drupalcode.org/project/canvas/-/work_items/3591851) · 1 contributor · 4 comments

## Summary

In the Canvas page builder, Patterns (reusable, saved component groupings) could previously only be inserted or deleted. There was no way to fix a mistake or evolve a pattern after it was saved. This adds an "Edit pattern" action that opens the pattern in the full canvas editor, and a "Rename" action for changing its name, both from the pattern's menu in the library panel.

## Impact

No upgrade or configuration changes required.

## Technical details

The backend already supported updating a Pattern config entity (`Pattern::updateFromClientSide()` and the `PATCH /canvas/api/v0/config/pattern/{id}` route), so the work was mostly building the missing round-trip: loading a stored pattern back into the editor, editing its component tree as a draft, and publishing it back to config, plus wiring up the UI to reach that flow.

New routes `canvas.api.layout.get.pattern`, `.patch.pattern`, and `.post.pattern` (all under `/canvas/api/v0/layout-pattern/{entity}`) and a dedicated `canvas.api.form.component_instance.pattern` route give Patterns their own layout/component-instance-form endpoints, since unlike content templates a Pattern renders standalone with no preview entity. `ApiLayoutController` was generalized to accept `ComponentTreeConfigEntityBase` (Pattern's base class) alongside `ContentTemplate`, and `AutoSaveManager::entityIsConsideredNew()` now treats any `ComponentTreeConfigEntityBase` as "new" only while unsaved (`$entity->isNew()`), rather than relying on the default-title heuristic used for content entities. Since a Pattern has no host content entity for field widgets that need entity context (e.g. image or options widgets), `Pattern::createEmptyHostEntity()` creates a throwaway, unsaved `canvas_page` to serve that role, mirroring `ContentTemplate::createEmptyTargetEntity()`.

On the frontend, a new `/pattern/:patternId` route and `PatternLayout` component fetch and initialize the editor via `useGetPatternLayoutQuery`, and new `postPatternLayout`/`updateComponentInPattern` RTK Query mutations save the draft. `PatternItem.tsx` gains "Edit pattern" and "Rename" menu entries, the latter opening a new `RenamePatternDialog` backed by `useUpdatePatternMutation` (`PATCH /canvas/api/v0/config/pattern/{id}`). A pattern's name is edited immediately through this config API call, separate from the draft/publish cycle used for its component tree. `Topbar` and `PageInfo` were updated to recognize the new `EditorFrameContext.PATTERN` context, hiding the language selector (patterns aren't translated) and showing the pattern's name in the header.</technical>
