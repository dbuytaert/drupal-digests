## Summary

When the Canvas update moves 1.x auto-save drafts into the Main workspace, any draft it cannot keep is now recorded in the log with its key and the reason. Before, malformed rows, rows whose entity was gone and rows whose entity already had a draft in Main were deleted silently, so site owners could not tell what was lost.

## Impact

No upgrade or configuration changes required.

## Technical details

`LegacyAutoSaveMigrator::drop()` now takes a message and context and writes a warning on the `canvas` logger channel before deleting the row and its violation rows. All messages start with `Canvas dropped the 1.x auto-save draft @key during the update:` followed by the reason. Reasons: malformed row, entity type no longer exists, entity no longer exists, entity cannot have a translation in the draft's language (language deleted or entity language neutral), entity already has a draft in the Main workspace, entity tracked in a workspace of a foreign provider, and entity became tracked in another workspace while staging. The last two were already logged and now go through `drop()`.

`resolveTarget()` now returns either an entity or a string, the message `drop()` logs, instead of `NULL`. `migrate()` reads the row with `getMultiple()` rather than `get()`, so a missing key is told apart from a stored `NULL`. A key with no row is not logged, since no draft is dropped. It only clears a leftover violation row. Kernel tests in `WorkspaceAutoSaveStagingTest` assert one log record per dropped row, and none for migrated rows.
