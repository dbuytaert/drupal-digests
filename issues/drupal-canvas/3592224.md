## Summary

Headless frontends registered on one Canvas site (for example local, staging and production) can now provide the same component machine name with different definitions. Previously the sync rejected the second frontend with a conflict error. Now the most recent sync wins, and every frontend that synced the component keeps it in its own component list. After a sync that changes components, the open editor reloads its layout and drops cached props forms. The layer label and props form then match the preview, and newly added props appear without a browser reload. A new docs page, "Managing component changes", explains how definition changes reach pages and how to roll back.

## Impact

No upgrade or configuration changes required.

## Technical details

In `ExternalComponentSync`, the guard that threw an `UnexpectedValueException` when another frontend owned the same external component with different metadata is removed, along with its helpers `findConflictingOwningFrontend()`, `getConfiguredFrontends()` and `matchesExternalContract()`. Components are shared by machine name, and the latest sync overwrites the label, status, props and slots. The kernel test shows that a changed definition creates a new `Component` version. Syncing the first frontend again reactivates its earlier version, and the other version stays loadable.

On the editor side, `FrontendSelect` now acts on the sync result. If `created + updated > 0`, it waits for pending preview requests and running `componentAndLayoutApi` queries and mutations. It then invalidates the `Layout` tag, invalidates a new `ComponentInstanceForm` tag (added to `getComponentInstanceForm` via `providesTags`), and dispatches `setInitialized(false)` and `clearFieldValues(FORM_TYPES.COMPONENT_INSTANCE_FORM)`. It also clears the selected component, because the upgrade can remove it. The cached forms are dropped separately because metadata-only changes, such as prop titles, do not create a new component version. `ComponentInstanceForm` also now rebuilds its form query string when the selected node's `type` changes, which covers an instance upgraded to a new component version after a layout reload.
