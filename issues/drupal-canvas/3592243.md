## Summary

On the Canvas workspaces branch, a failed publish could leave Canvas config drafts (for example code components) already saved to Live. Now a workspace that holds Canvas config drafts can be published only through Canvas. Publishing it from the core Workspaces UI, Drush or other code is refused up front with the message "This workspace has unpublished configuration changes made in Drupal Canvas. Publish it from Drupal Canvas." Nothing is written when it is refused. Workspaces without config drafts publish from every surface as before.

## Impact

Affects site owners.

- **Config change:** Publishing a workspace that holds Canvas config drafts from the core Workspaces UI, Drush or `$workspace->publish()` is now refused; publish it from Canvas.

## Technical details

Core's `WorkspacePublisher::publish()` dispatches `WorkspacePrePublishEvent` before it opens its own transaction. `AutoSaveWorkspacePublishSubscriber::onPrePublish()` saves the config fallback drafts to Live through `WorkspaceAutoSave::stageFallbackDrafts()` at that point, so a later failure left them Live. Only the Canvas API path, `CanvasWorkspacePublisher::publish()`, wraps the whole publish in a database transaction.

The change keeps that transaction on the Canvas path only. `CanvasWorkspacePublisher` gets a `$transactionActive` flag, set after `startTransaction()` and cleared in a `finally`, exposed as `isActiveTransaction()`. The subscriber now receives `CanvasWorkspacePublisher` and `EntityTypeManagerInterface`. If no Canvas transaction is active and `hasConfigFallbackDrafts()` finds a non-content entry in `WorkspaceAutoSave::getAllList()`, it calls `$event->stopPublishing()->setPublishingStoppedReason(...)` with `configDraftsOutsideTransactionReason()`, before anything is written. Content drafts do not count, since they are tracked revisions. Core surfaces the reason as the message of its `WorkspacePublishException`. The `@todo Workspaces MR 11` was removed.

ADR 0022 (decisions 2 and 3, consequence 8) is updated. The limit goes away if config drafts become workspace-tracked config (work item 3592208) or if core opens its publish transaction before the pre-publish event. A rollback restores only the database: the config factory and entity caches keep what the publish wrote until reset. `WorkspaceAutoSaveStagingTest` gains `testFailedPublishIsRolledBack()` (config draft failure and revision promotion failure) and now uses the `keyvalue.database` factory for the fallback store so rollbacks are testable.
