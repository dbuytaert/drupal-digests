# #3591848: ∅ is added for empty fields, forcing translation and rendering on the page

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591848](https://git.drupalcode.org/project/canvas/-/work_items/3591848) · 1 contributor · 8 comments

## Summary

When translating Canvas Pages with TMGMT, empty component inputs no longer show a literal ∅ in the review form or force the translator to fill them in. An input that is empty in the source now reads "This field is empty in the source language." An optional input can be left blank in the translation and is saved as empty. A required input still gives TMGMT's "The field is empty." error. If a translator plugin returns an exact ∅, it is discarded and the value from the default translation is kept. This fixes content translation only. Config translation jobs (ContentTemplate, PageRegion) still show, force and store ∅. Falling back to the source value at render time is not part of this change.

## Impact

No upgrade or configuration changes required.

## Technical details

`ComponentInputsTranslatablesExtractor::EMPTY_SENTINEL` (`∅`) is still the extracted `#text` for empty optional inputs, because TMGMT's `Data::flatten()` strips empty strings. It is now an internal marker only. `TmgmtHooks` implements `hook_tmgmt_data_item_text_output_alter` to blank it in both review columns, but only for content job items whose entity has a Canvas field. It also implements `hook_form_tmgmt_job_item_edit_form_alter` and `hook_form_tmgmt_local_task_item_edit_form_alter`. These replace the missing source textarea with a message. They also add validate callbacks that temporarily set the sentinel on empty translations of optional props, so TMGMT's "The field is empty." check passes, and restore the empty value afterwards. Required props, checked via `prop_field_definitions[...]['required']` of the component version the tree item uses, are not masked and keep the error. The "Validate" and "Save as completed" buttons are handled the same way. The local task form (tmgmt_local) gets a parallel set of mask and unmask callbacks.

In `ComponentTreeFieldProcessor`, `writeNestedTranslationsToInputs()` returns NULL for a translation that is exactly the sentinel. An empty string is kept as a valid, explicitly empty translation. If every translatable leaf of a composite input (such as `text_format`) is NULL, the whole composite becomes NULL. `setTranslations()` then refills NULL values at any depth from the default translation via `refillDiscardedFromDefault()` and `defaultTranslationInputs()`. Values that stay NULL are dropped. Only an exact match is discarded, so a translation that merely contains ∅ is stored as written.

`ComponentInputsTranslatablesExtractor` also gets `getUnresolvedSchemaDefinition()`. It reads the config schema before type resolution, because core rewrites definitions in place and removes `type`. Without it, `text_format` inputs could lose their `#format`. A `@todo` points to work item 3592014 for extending the sentinel handling to config job items.
