## Summary

Canvas's JavaScript packages were updated to resolve `npm audit` advisories in direct and transitive dependencies. Patch releases are queued for the CLI, headless, workbench, create and ESLint config packages. Two behavior changes are worth knowing: `@drupal-canvas/create` now refuses to run git if certain git environment variables are set, and the ESLint config reports a missing default export at a different location with newer typescript-eslint.

## Impact

Affects site owners.

- **Security:** Addresses `npm audit` advisories in Canvas's direct and transitive npm dependencies, including `simple-git` 3 to 4.
- **Requirements:** `@drupal-canvas/create` now errors when `GIT_DIR`, `GIT_WORK_TREE` or `GIT_CONFIG_PARAMETERS` are set.

## Technical details

`simple-git` in `@drupal-canvas/create` moves from `^3.36.0` to `^4.0.2`. Per the changeset, git settings inherited from the environment (commit identity, certificates, proxies, LFS options) are still passed through, but variables that point git at another repository (`GIT_DIR`, `GIT_WORK_TREE`) and `GIT_CONFIG_PARAMETERS` overrides now stop the command with an error naming the variable. A new real-git test file for `useGit` (`use-git.js`) covers this without mocks.

The root `package.json` `overrides` raise `glob` to `^14.0.6` and pin patched versions of `minimatch` (under `@typescript-eslint/typescript-estree` and `@ts-morph/common`), `readdir-glob` (under `archiver`), `@joshwooding/vite-plugin-react-docgen-typescript`, `postcss-selector-parser` and `esbuild` (under `tsup`). One package also moves `zod` to `^4.6.7`, `vitest` to `^4.1.12`, and the Angular example dependencies to 21.2.26.

In `@drupal-canvas/eslint-config`, the missing-default-export report now uses `context.sourceCode.getFirstToken(node)?.loc ?? node.loc`, so it lands on the first line of code with typescript-eslint 8.72 and later, as with earlier versions and the default parser.

## Upgrade

If you script `npm create` style tooling with `@drupal-canvas/create` and have `GIT_DIR`, `GIT_WORK_TREE` or `GIT_CONFIG_PARAMETERS` set in the environment, unset them before running it, since the command now fails with an error naming the variable.
