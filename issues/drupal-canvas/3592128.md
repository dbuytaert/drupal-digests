# #3592128: Remove experimental Canvas Headless properties and CLI flag

## Summary

The Canvas Headless submodule has graduated out of experimental status. It is no longer marked `hidden` or `experimental`, so it now shows up and can be enabled like any other module instead of being concealed from the module list. Its description was also updated to reflect that it connects a headless frontend app to Canvas for editing and preview. Separately, the `@drupal-canvas/create` scaffolding CLI no longer requires the `--experimental-headless` flag: all headless frontend templates (Next.js, Astro, Nuxt, TanStack Start, Angular) are now offered directly in the interactive template picker, and non-interactive runs that omit `--template` fall back to the `default` template instead of erroring out.

## Impact

Affects module maintainers and site owners.

- **Config change:** The `canvas_headless` submodule is no longer `hidden`/`experimental`, so it appears in the module list and can be enabled directly.
- **API change:** The `@drupal-canvas/create` CLI's `--experimental-headless` flag and the `experimental`/`experimentalHeadless` options on its `Template` and `CreateOptions` types were removed.

## Technical details

In `modules/canvas_headless/canvas_headless.info.yml`, the `lifecycle: experimental` and `hidden: true` keys were removed and the module description was rewritten. In the `@drupal-canvas/create` package, the `experimental` flag on each `Template` (in `templates.json` and the `Template` type) was dropped, along with the `experimentalHeadless` option on `CreateOptions` and the `--experimental-headless` Commander option. The template selection logic in the CLI's main command was simplified to always build its list from `predefinedTemplates` rather than filtering by an `experimental` flag; the special-case branch that auto-selected a single available template, or exited with an error in non-interactive mode when none was specified, was replaced with a straightforward fallback to the `default` template for non-interactive runs.

## Upgrade

Remove any use of the `--experimental-headless` flag from scripts or documentation that invoke the CLI:

```
# before
npx @drupal-canvas/create@latest --experimental-headless

# after
npx @drupal-canvas/create@latest
```

The Canvas Headless module can now be enabled directly (it is no longer `hidden`), so no special discovery step is needed to find it in the module list.
