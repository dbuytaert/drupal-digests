# #3592062: Support rendering SVGs in SDC and code components with an image prop

- **Project:** Drupal Canvas
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3592062](https://git.drupalcode.org/project/canvas/-/work_items/3592062) · 1 contributor · 3 comments

## Summary

Canvas (Experience Builder) lets editors place an SVG media item into a component's `image` prop, but until now the SVG silently failed to render: the image was requested through a resizing/derivative pipeline that cannot process SVGs, producing broken image requests, and the unknown width/height of an unprocessable image was recorded as `0` rather than "unknown", which makes an `<img>` invisible. A third, related bug made the `Image` wrapper used by code components always assume a resizing loader was available, logging an error for every candidate size on an SVG. With this fix, SVGs assigned to an `image` prop (in SDCs and code components) render correctly, sized from the SVG's own `width`/`height` or `viewBox` when available. SVG support remains opt-in per media type; Canvas' default allowed file extensions are unchanged.

## Impact

Affects module maintainers.

- **API change:** `Evaluator` no longer casts a NULL-resolving primitive prop value to `0`, `''`, or `false`; an optional object prop with no value is now omitted/absent (visible in `inputs_resolved` and in code component props) instead of a false-y placeholder, and empty items in a multiple-cardinality static prop preview are omitted instead of becoming `0`. Required props are unaffected since they still map onto required field properties that throw when empty.

## Technical details

The fix targets three call sites that assumed every image file could be resized. `ImageDerivativeWithParametrizedWidth` and `ComputedUrlWithQueryString` (and `ImageAndStyleAdapter`) now check `ImageStyle::supportsUri()` before building a `canvas_parametrized_width--{width}` derivative URL or appending an `?alternateWidths=` query string, and omit the query parameter entirely when it would evaluate to NULL, so `srcset` candidates are no longer generated for files the image toolkit can't process.

Separately, `Evaluator` stopped casting NULL-resolving primitive field property values with `(int)`/`(string)`/`(bool)`, which previously turned an unreadable image's `width`/`height` into `0`. Object props that evaluate to NULL are now omitted rather than serialized as a false-y value, since `null` doesn't validate against most prop shapes. This uncovered two related bugs that were also fixed: access-denied inference for a required-but-empty field property had assumed Typed Data marks `width`/`height` as required (it doesn't), and a computed field property that resolves to NULL still needs to carry cacheability from the property definition rather than from the (absent) computed value. At save time, SVG intrinsic dimensions are now read from the SVG's own `width`/`height` attributes (when in pixels) or its `viewBox`, so an icon without explicit width/height doesn't get stretched to fill its containing block.

The `Image` wrapper for code components (built on `next-image-standalone`) now marks an image `unoptimized` when there's no `alternateWidths` to build a loader from, which omits `srcset`/`sizes` instead of invoking a loader that assumes optimization always applies.

## Upgrade

Code that reads `inputs_resolved` or code component props for an optional `image`-shaped prop should no longer expect a `0`, `''`, or `false` placeholder when the value is absent or unresolvable; such props are now simply omitted. Required props are unaffected. See the change record at [#3623307](https://www.drupal.org/node/3623307) for details.
