# #3592142: ColorFormPopover resets edits in progress when the color list refetches

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592142](https://git.drupalcode.org/project/canvas/-/work_items/3592142) · 1 contributor · 3 comments

## Summary

In Canvas's brand kit color editor, editing a color's values (e.g. dragging the RGB sliders) could silently revert to the previously saved value if the color list happened to refetch in the background while the popover was still open, such as right after a related save. Users would lose their in-progress edits with no warning. The popover's form now only initializes once per time it is opened, so a refreshed color object arriving mid-edit no longer wipes out unsaved changes.

## Impact

No upgrade or configuration changes required.

## Technical details

`ColorFormPopover` reinitialized its form state in a `useEffect` keyed on `[open, operation, color]`. Because `color` is a fresh object identity after each brand kit refetch (e.g. from RTK Query cache updates), any refetch while the popover was open re-ran `INIT_EDIT`/`INIT_ADD` and overwrote whatever the user had typed.

The fix adds an `initializedRef` (via `useRef`) that is set to `true` the first time the effect runs after `open` becomes true, and reset to `false` when the popover closes. Subsequent re-renders with a new `color` reference while `open` stays `true` now skip the `updateForm` dispatch entirely, so the reducer state (and thus the visible form inputs) is left alone until the popover is closed and reopened. A new test, `ColorFormPopover.test.tsx`, verifies this by re-rendering with a new `color` object after a field is edited and asserting the edited value and derived preview persist.
