# #3592122: Canvas AI: get_component_details and get_component_context omit item type and item limits of multi-value props

## Summary

The Canvas AI `get_component_details` function, and `get_component_context` with `catalog_only` set to false, now describe multi-value props fully. Before, an array prop showed only `type: array`, so an AI agent could not tell what each value should be or how many values were allowed. The output now includes the item type and the `minItems` and `maxItems` limits when the component sets them. Defaults of formatted text arrays are now HTML strings instead of a list of `null` values.

## Impact

No upgrade or configuration changes required.

## Technical details

In `CanvasAiPageBuilderHelper`, a new private `getMultiValuePropMetadata()` runs for props whose schema `type` is `array`. It adds `items`, normalized through `propMetadataNormalizer` with `PropShape::normalizePropSchema()` so `format`, `contentMediaType` and `enum` come through. It also copies `minItems` and `maxItems` when they are set. The method is used on both the SDC/default path and the JS component path.

Default values that are arrays are now mapped item by item, with `MarkupInterface` items cast to strings. This fixes the multi-value formatted text defaults.

For code (JS) components, the prop schema is no longer taken from the client-side `jsonSchema` plus a manual copy of `meta:enum` and `x-translation-context`. It is now built from `getJavaScriptComponent()->toSdcDefinition()['props']['properties']` and passed through `componentPluginManager->resolveJsonSchemaReferences()`, which keeps `meta:enum`. The constructor type hint changed to `Drupal\canvas\Plugin\ComponentPluginManager`. Tests were added to `GetComponentDetailsTest`, along with a new `formatted-text-list` fixture component in the `canvas_ai_test` module.
