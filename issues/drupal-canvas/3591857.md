# #3591857: Removing a media item from one image prop deletes the stored value of every other media-backed prop on the same component instance

- **Project:** Drupal Canvas
- **Type:** Major bug report
- **Version:** 1.x-dev
- **Status:** Fixed
- **Discussion:** [#3591857](https://git.drupalcode.org/project/canvas/-/work_items/3591857) · 1 contributor · 5 comments

## Summary

In the Canvas page builder, components with more than one image or media prop (for example a component with a "first image" and "second image") had a data-loss bug: clicking the remove (X) button on one image would silently wipe out the other, untouched image prop as well. The saved page and preview would lose the second image even though the editor never touched it. This is now fixed: removing one media item only clears that item, and other media props on the same component instance keep their stored values.

## Impact

No upgrade or configuration changes required.

## Technical details

The bug was in `buildRemoveModel()` in `ui/src/components/form/components/drupal/DrupalMediaListContainer.tsx`. It called `syncPropSourcesToResolvedValues()` (from `layoutModelSlice.ts`) across all of a component's props before sending the PATCH to `/canvas/api/v0/layout/...`. That helper copies each prop's `resolved` value back into its `source.value`, but after a prior PATCH round trip the Redux model's `resolved` value for a media prop is a server-evaluated object (`{src, alt, width, height}`) rather than a media entity ID. Feeding that evaluated object back as a `source.value` for the entity-reference-backed `StaticPropSource` made `clientModelToInput()` (`JsonSchemaPropsComponentSourceBase.php`) treat the untouched prop as empty, dropping it from the stored inputs entirely.

The fix narrows `buildRemoveModel()` to only rewrite the removed prop's `source` entry (`source[propName] = { ...source[propName], value: resolved[propName] }`), leaving every other prop's `source` untouched, and removes the call to `syncPropSourcesToResolvedValues()` from this code path since it's no longer needed here. The bug was introduced in [#3577219](https://www.drupal.org/node/3577219); prior remove-path tests only covered single-media-prop components, so the cross-prop corruption wasn't caught. A Playwright regression test was added using the `mixed-images-with-example` component, populating two image props and removing one, and `CanvasMedia.ts`'s `addMediaImage()` test helper was extended with an optional `fieldset` locator so tests can target a specific media widget when a component has multiple media fields.
