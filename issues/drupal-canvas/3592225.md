## Summary

This is the core change of the Canvas Workspaces integration, developed on the `1.x-workspaces` branch. Every Canvas draft is now staged in the active workspace instead of the 1.x key-value auto-save store. Content entity drafts are kept as workspace revisions. Config entities that can't be staged that way are kept in per-workspace fallback storage. Drafts in different workspaces are separate. An entity that another workspace has claimed is locked, and the API reports this as a 409 conflict. This issue is a planning and tracking record. Its body describes the intended scope and has no linked merge request or comments, so the wording below follows the plan, not merged code.

## Impact

Affects module maintainers and site owners.

- **Requirements:** Builds on PR 2 (#3592216), which made Workspaces a hard dependency of Canvas on the `1.x-workspaces` branch.
- **New API:** New `WorkspaceAutoSave` and `AutoSaveFallbackStore` classes under `src/AutoSave/Workspace/`, and a new `WorkspaceEntityLockedException`.

## Technical details

The issue body says the change is split from the controllers (PR 5) by call direction: everything below the controllers lands here. I could not check the merged code. The `1.x-workspaces` branch I cloned didn't contain these classes yet, and the issue has no linked merge request.

Per the plan, the main pieces are:
- `AutoSaveFallbackStore` uses per-workspace collections named `canvas.auto_save.{ws}` and `canvas.auto_save_meta.{ws}`. It has a workspace ID length guard, `deleteWorkspace()` and `workspaceIds()`.
- `WorkspaceAutoSave` is the engine. It covers persisting staged entities, claiming an entity for a workspace, keeping only the latest revision, and retaining a fallback draft when the storage throws. It also covers loading and listing drafts, discard and delete, staging fallback drafts, and clearing workspace stores.
- `AutoSaveManager` delegates to the engine, uses workspace-prefixed keys, and adds `executeInStagingWorkspace()`, `getEntityForLayoutEditing()`, `deleteTranslation()` and a `forcePreserve` option. `onCanvasConfigEntitySave()` also gets an `isPublishTimeStaging()` check.
- Supporting changes: `WorkspaceEntityLockedException`, a new code 8 in `ErrorCodesEnum`, and the lock-to-409 mapping in `ApiExceptionSubscriber`.
- `ClientDataToEntityConverter` validates inside the staging workspace and raises `changed` to the request time.
- The symmetrical translation synchronizer skips staged non-default translations.
- `ContentTemplate` is created enabled.
- Conflict detection is kept from the 1.x branch. The base hash is stored in the workspace meta collection (or as `original_hash` on a fallback row) and compared against `loadUnchangedBase()`.

The plan lists known gaps after this PR: `ApiAutoSaveControllerTest` fails until PR 7a replaces per-item publish, the 1.x `post()` is unsafe inside a workspace, and the PR 5 controllers still read Live content.
