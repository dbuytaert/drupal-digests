# #3592109: CLI pull/push loses entity references and options in component link props

- **Project:** Drupal Canvas
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3592109](https://git.drupalcode.org/project/canvas/-/work_items/3592109) · 1 contributor · 3 comments

## Summary

Pulling and pushing pages or page templates with the Canvas CLI no longer degrades component link props. A link stored as `entity:node/7` with a `target="_blank"` option used to come back as `internal:/node/7` with empty options, even when nobody edited it. Unchanged links now keep their original URI and options. If you edit the URL, the link is rebuilt as before, with empty options.

## Impact

No upgrade or configuration changes required.

## Technical details

Pages and page templates pull through `resolvedComponentTreeToAuthoredElementMap()`, which writes link props as plain resolved URL strings. The old `extractMediaProvenance()` is now `extractPropProvenance()` in `packages/cli/src/utils/authored-elements.ts`. Besides media references, it records `{ uri, options, resolved_url }` in the element's `_provenance` for any link prop (stored input with a string `uri` and `options`, resolved to a string).

On push, `linkTransformer.serialize()` in `packages/cli/src/utils/prop-transforms.ts` gets the provenance. If `provenance.resolved_url` equals the authored string, it returns the original `{ uri, options }`. Otherwise it uses the existing normalization, such as the `internal:` prefix, with empty options. `resolved_url` is local metadata and is never sent to Drupal. Content templates were not affected, because their pull path already keeps the raw link object. The change ships as a patch changeset for `@drupal-canvas/cli`.
