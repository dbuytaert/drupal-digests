## Summary

In the Canvas editor, saving changes could keep failing after the session changed, for example after logging out and back in from another tab. This happened on routes that return an HTML 403 page, such as the headless frontend and component sync routes. The editor now recovers from these failures by fetching a fresh CSRF token and retrying. Users no longer have to reload the editor.

## Impact

No upgrade or configuration changes required.

## Technical details

The editor reuses a cached session CSRF token (introduced in [#3592277](https://www.drupal.org/node/3592277)). When a mutation gets a 403, `rawBaseQuery` in `ui/src/services/baseQuery.ts` drops the cached token with `forgetCsrfToken()` and retries once. The retry condition checked `result.error?.status === 403`. With an HTML body, `fetchBaseQuery` cannot parse JSON and reports `PARSING_ERROR` as the error status, so the retry was skipped. The condition now checks `result.meta?.response?.status === 403`, which holds the HTTP status whatever the body is. A vitest test stubs `fetch` to return an HTML 403 for the stale token and checks that the request is resent with a new token.
