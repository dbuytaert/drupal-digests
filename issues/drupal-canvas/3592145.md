# #3592145: canvas-page-variant.html.twig removes #main-content

- **Project:** Drupal Canvas

## Summary

Pages rendered through a Canvas page variant now include a `#main-content` anchor, so the theme's "Skip to main content" link has something to jump to. Before this, the variant template replaced the whole page and the anchor was missing. This affects every site rendering through page variants, including sites upgraded from global regions.

## Impact

No upgrade or configuration changes required.

## Technical details

`CanvasPageVariant::buildPageVariant()` now prefixes the route's main content, which is injected at the "Page content" marker, with the placeholder `<!--canvas-main-content-anchor-->`. A `#post_render` callback, `CanvasPageVariant::resolveMainContentAnchor()`, runs after the whole variant has rendered. It replaces the placeholder with `<a id="main-content" tabindex="-1"></a>` only if the rendered HTML has no `id="main-content"` already, and otherwise removes it. This avoids duplicate ids when a theme page template component renders the theme's `page.html.twig`, which already ships the anchor. The id match is case-sensitive and bounded, so `Main-Content` and `main-content-foo` do not count as existing anchors. The class now implements `TrustedCallbackInterface` for the callback. `renderComponentTree()` still injects main content exactly as passed, so other callers such as the headless content API are unaffected. The change is covered by new kernel tests and an update to `docs/page-variants.md`.
