## Summary

The One Line Installer no longer dies on Ubuntu 26.04 after installing Docker Engine. That release ships neither `sg` nor `newgrp`, so the new `docker` group membership could not be activated, and the installer waited 60 seconds for a Docker daemon it could not reach before failing. It now restarts itself with `sudo -u "$USER" -g docker` when `sg` is missing, so the install carries on. If neither works, it stops immediately with log-out advice instead of waiting.

## Impact

No upgrade or configuration changes required.

## Technical details

In `linux_ensure_docker`, a new `_docker_group_activator` helper prints `sg` if available, else `sudo`, else nothing. `sg` remains the first choice. `_reexec_under_docker_group` now takes `sg` or `sudo` as an argument. With no activator, the installer calls `die` right away, skipping the 60 s wait. The message no longer mentions `newgrp`.

The `sudo` path builds its command in `_docker_group_sudo_argv`, which fills the `DOCKER_GROUP_SUDO_ARGV` array. It runs `sudo -u "$USER" -g docker env ... bash <installer> <original args>`. The issue notes that sudo-rs (the `sudo` on Ubuntu 26.04) ignores `-E` and drops variables such as `INSTALLER_URL`, `DBUS_SESSION_BUS_ADDRESS`, `XDG_RUNTIME_DIR` and `WAYLAND_DISPLAY`. So every exported variable (`compgen -e`) is passed back through `env VAR=value`. `OLI_DOCKER_GROUP_REEXEC` is excluded from that list and set to `1` explicitly, so the re-exec guard still prevents looping. New bats tests cover sg present, sg missing with sudo, neither available, and the argv construction.
