## Summary

`--config-url` now accepts a drupal.org project page URL such as `https://www.drupal.org/project/ai` and translates it to the matching `https://git.drupalcode.org/project/ai` repo before cloning. The installer prints a `Resolved drupal.org project ...` line showing what it will clone. Git URLs, SSH remotes, other hosts and non-project drupal.org pages are left untouched.

## Impact

No upgrade or configuration changes required.

## Technical details

A new helper, `_normalize_config_url` in `src/lib/config/_normalize_config_url.sh`, is called at the top of `load_config_url()` before the clone. Other loaders such as `--config-path` are unaffected. A `remote-configs.json` pointer that goes through `follow_remote_config` re-enters `load_config_url`, so it gets the same translation.

The helper matches `http(s)://(www.|new.)?drupal.org/project/` case-insensitively on the host. It drops any query string or fragment, then splits the rest of the path on `/`. It skips drupal.org's own `/project/` sections (`issues`, `usage`, `releases`, `search`), the browse listings (`project_module`, `project_theme`, `project_theme_engine`, `project_distribution`, `project_core`) and the `modules`/`themes`/`distributions` aliases. So `/project/issues/ai` and `/project/ai/issues/12345` both resolve to `ai`. The first remaining segment is the machine name. If it is missing or doesn't match `^[a-z0-9_-]+$`, the original URL is returned unchanged rather than inventing a repo URL. That means `/project/AI`, `/project/issues` and `/docs/...` all pass through. A lookalike host such as `drupal.org.evil.com` is not rewritten.

Bats tests were added for the normalizer (`_normalize_config_url`) and for the `load_config_url` clone. The `--config-url` help text, man page and `AGENTS.md` source-layout notes were updated.

## Upgrade

Existing git URLs work unchanged. To use the new form, pass the project page URL directly:

```
--config-url https://www.drupal.org/project/ai
```
