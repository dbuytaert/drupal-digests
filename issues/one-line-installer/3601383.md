# #3601383: Curated npx skills (agent-browser, drupal-module-finder, superpowers, find-skills) missing after install — lost between .claude/skills and the .agents/skills symlink

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3601383](https://git.drupalcode.org/project/one_line_installer/-/work_items/3601383) · 1 contributor · 16 comments

## Summary

one_line_installer scaffolds DDEV-based Drupal projects wired up for AI coding agents (Claude Code, Codex, OpenCode), including a curated set of default "skills" (agent-browser, drupal-module-finder, superpowers, find-skills) installed via the `npx skills add` CLI. A bug meant these curated skills could vanish after install: they were placed into each chosen agent's own directory (e.g. `.claude/skills`), but a later step then replaced `.claude/skills` with a whole-directory symlink pointing at `.agents/skills`, a directory the curated skills were never actually copied into, so they became invisible to the agent. The fix makes the installer always install curated skills into the shared `.agents/skills` directory (the `skills` CLI's `universal` target) regardless of which agent(s) were chosen, so Codex and OpenCode (which read `.agents/skills` natively) and Claude Code (which reaches it through the existing symlink step) all reliably see the curated skills after install.

## Impact

No upgrade or configuration changes required.

## Technical details

Previously `_skill_agent_targets` mapped each chosen agent to its own `npx skills add -a <target>` value: `claude`→`claude-code` (which installs into `.claude/skills`), `codex`→`codex`, `opencode`→`opencode`, with bring-your-own (no agent chosen) installing to all three. Separately, `link_claude_skills` replaces `.claude/skills` with a whole-directory symlink to `.agents/skills` whenever `.claude/skills` is empty, absent, or a stale symlink. Since `-a claude-code` had just made `.claude/skills` a real, populated directory, that directory usually didn't qualify for the symlink replacement in a way that preserved the just-installed skills, and the two mechanisms fell out of sync, orphaning the curated skills between the two directories.

The fix in `src/lib/steps/install_skills.sh` changes `_skill_agent_targets` to always return the single value `universal`, which the `skills` CLI resolves to the shared `.agents/skills` directory, the same directory ai_best_practices' `drupal-ai skills-sync` aggregates into and that Codex/OpenCode already read natively. `link_claude_skills` is unchanged in logic but now runs against a `.claude/skills` that is normally absent, so its whole-dir symlink to `.agents/skills` is the common path; it still falls back to symlinking skills in individually when a user has their own real, non-empty `.claude/skills`. A new `SKILLS_CLI="skills@1.5.23"` pin fixes the `npx` invocation to a known version so the `universal` → `.agents/skills` mapping cannot silently change upstream, and `--copy` is now passed explicitly instead of relying on the CLI's `-y` auto-detected placement mode. The same target logic is reused by `src/lib/extras/extra_agent_ready_drupal_build_kit.sh` and `src/lib/shared/manage/manage_skills.sh` (the "add/remove skills" management menu), which is updated to look for skills under `.agents/skills` (plus a user's own real `.claude/skills`) rather than under each agent's own directory.
