## Summary

In the One Line Installer, `--yolo` now takes the default project directory without asking even when a config source is given (`--config-url`, `--config-path`, `--global-config`, or a positional source). Before, those runs stopped at "Enter a name for the new project" and failed with `/dev/tty: Device not configured` when no terminal was available. The GitHub repository questions are skipped in the same case. The interactive "Use a config" menu still asks for a name.

## Impact

No upgrade or configuration changes required.

## Technical details

`step_create_project_dir` only took the default silently when `YOLO=1` and `USE_CONFIG=0`, and every config loader sets `USE_CONFIG=1`. The "Use a config" menu sets `YOLO=1` itself, so `YOLO` alone can't tell the user's own flag from the menu. The fix adds `YOLO_FLAG`, set in `setup_site_command.sh` right after `YOLO` is read from `args[--yolo]`, and a new helper `yolo_takes_defaults` (`src/lib/core/yolo_takes_defaults.sh`). It returns true when `YOLO_FLAG=1`, or when `YOLO=1` with `USE_CONFIG=0`.

`step_create_project_dir` (the in-place empty directory default, the free default name, and the existing-directory warning path) and `github_setup` now call this helper instead of testing `YOLO`/`USE_CONFIG` directly. An existing default directory still produces a warning and, with no terminal, dies with the `--name` guidance. Bats tests cover the helper, `YOLO_FLAG`, and the create-dir and GitHub steps, and `AGENTS.md` documents the new global.
