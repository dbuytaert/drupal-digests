## Summary

On a fresh Linux desktop where snap Firefox has never been opened, the installer now starts Firefox once in headless mode so it creates its profile. The DDEV local CA is then added to that profile. Before, the CA step found no profile and printed manual import steps. The site then opened in a Firefox that did not trust the CA, and showed "Warning: Potential Security Risk Ahead". macOS is unchanged.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `src/lib/platform/ensure_local_https.sh`. `_trust_snap_browsers` now calls the new `_snap_firefox_first_run` before its loop. That function returns early unless snap Firefox is installed, `certutil` and `firefox` are on the PATH, and no `~/snap/firefox/common/.mozilla/firefox/*/cert9.db` exists yet. Otherwise it runs `timeout 60 firefox --headless --screenshot ~/snap/firefox/common/oli-first-run.png about:blank` and removes the screenshot. A failure or timeout is ignored. If no store exists afterwards, the existing manual import message is printed. Firefox creates its own default profile, rather than the installer using `-CreateProfile` or `certutil -N`.

A new helper, `_snap_installed`, checks for `/snap/bin/<name>`. The browser loop now uses it as well as the `~/snap/<name>` directory check, because that directory only appears after a snap's first run. An installed but never opened snap Chromium therefore gets the manual import instructions instead of being skipped silently. Bats tests cover the headless run, the screenshot cleanup, an existing profile, a failed first run, missing `certutil`, macOS and the Chromium case. `AGENTS.md` was updated to match.
