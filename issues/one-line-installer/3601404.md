# #3601404: Let a config name the command the agent hand-off runs, instead of only opening a shell

## Summary

The installer's last step, `step_agent_handoff`, used to only ever drop the operator into a shell in the freshly built project directory, leaving any follow-up command (like starting a migration script) to be printed in the welcome text and typed by hand. A config can now set a `handoff_command` key so the installer offers to run that command itself at the very end, instead of opening a shell. The operator is still asked first: pressing Enter runs the command, Esc skips it, and, unlike the shell hand-off, letting the prompt time out also skips it rather than running the command unattended. When `handoff_command` is left unset, the installer behaves exactly as before.

## Impact

Affects site owners.

- **Config change:** New `handoff_command` key in `.drupalaibp.json`: when set, `step_agent_handoff` offers to run it in the project directory instead of opening a shell there.

## Technical details

The new key is threaded through the usual config plumbing: added to `DRUPALAIBP_KNOWN_KEYS` in `load_config.sh`, read into `HANDOFF_COMMAND` via `json_get`, and round-tripped back out by both `export_config.sh` and the inline exporter in `drupalaibp`.

In `step_agent_handoff` (`src/lib/steps/agent_handoff.sh`), a new branch fires when `HANDOFF_COMMAND` is non-empty: it prompts with the command and reuses `_agent_handoff_read_choice`, then execs `"${SHELL:-bash}" -c "$HANDOFF_COMMAND" </dev/tty` in place of the process, same as the existing shell hand-off does with a bare `exec "${SHELL:-bash}" </dev/tty`. Any answer other than `open` (i.e. `skip` or `timeout`) falls back to `_agent_handoff_skipped` and prints the command so it can be run by hand.

To make that distinction possible, `_agent_handoff_read_choice` now returns `timeout` instead of `open` when the read loop runs out its window without a keypress. The plain shell hand-off branch below still checks only for `== "skip"`, so a `timeout` return still opens the shell there, exactly as before; only the new command branch treats `timeout` differently from an explicit `open`.</technical>
