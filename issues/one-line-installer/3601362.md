## Summary

The one-line Drupal installer (via its `configure_ddev` step and the "Extra Drupal Installations" mechanism from [#3601361](https://www.drupal.org/node/3601361)) can now set up a virtual display you can actually watch. A new opt-in extra, "Watch the agent's browser (noVNC)", adds a DDEV add-on that runs a virtual X display and a browser-based VNC viewer inside the web container, so `agent-browser` can be run non-headless (`--headed`) and you can watch what the agent's browser is doing live, instead of only seeing whatever screenshot the agent happened to take. Headless remains the default; this is purely opt-in. The optional ffmpeg session-recording idea from the original proposal was not implemented in this change, only the required VNC display piece.

## Impact

No upgrade or configuration changes required.

## Technical details

The extra, `extra_agent_browser_display` in `src/lib/extras/extra_agent_browser_display.sh`, does no installation itself: it appends a pinned add-on URL (`_AGENT_BROWSER_DISPLAY_ADDON`, a release-tag tarball for `aivazashvilitekla/ddev-agent-browser-display`) to the `DDEV_ADDONS` array. That array is fetched by `step_install_ddev_addons` (`ddev add-on get`) and applied by the existing add-on restart step, so this extra costs the build no extra DDEV restart. The add-on itself (external to this repo) runs Xvfb + x11vnc + noVNC as `web_extra_daemons` in the web container, sets `DISPLAY=:99`, and publishes noVNC through ddev-router on port 6080.

The pin matters because the extra hardcodes the add-on's contract, port `6080` and path `/vnc.html`, in the welcome text; a floating `owner/repo` reference could resolve to a future release whose port or path differs, so the extra warns if a config supplies a non-pinned entry for the same add-on (matched by repo name substring) while still deferring to that config's choice.

A new built-in handler, `_agent_browser_display_welcome` in `src/lib/defaults/agent_browser_display_addon.sh`, is registered on the existing `ddev_addon_added` event (fired only after a successful `ddev add-on get`) and appends the "Watch the agent's browser" line, including the `{SITE_URL}:6080/vnc.html` address, to `APPEND_WELCOME_TEXT`, which `print_welcome.sh` renders at the end of the build. This mirrors the pattern already used by `selenium_addon.sh`'s `_selenium_headed_rewrite`. Because `step_install_extras` now has one more extra ahead of it, its documented pipeline slot moved from 10 to 11 (and the add-on fetch/restart slots shifted accordingly), a bookkeeping change with no behavioral effect on existing extras.
