# #3601386: Support multiple configs in one repo: order the picker by a weight key, falling back to alphabetical

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3601386](https://git.drupalcode.org/project/one_line_installer/-/work_items/3601386) · 1 contributor · 2 comments

## Summary

When a repo or directory offers more than one installer config (several `*.json` files under `.drupalaibp/`), the picker prompt now lets each config declare an optional `weight` to control its position in the list, and an optional `label` to control how it's displayed. Configs are sorted by ascending weight (lower first), falling back to alphabetical order by file name for configs that omit weight, or as a tie break between equal weights. This is fully backwards compatible: a config that sets neither key behaves exactly as before, a set of configs that never set a weight sorts alphabetically as it always did, and a directory with only one config still loads immediately with no prompt.

## Impact

Affects site owners.

- **Config change:** New optional `weight` (integer, default 0, lower sorts first) and `label` (display name, default the file name) keys in `.drupalaibp.json` order and label entries in the config picker shown when a source offers more than one config.

## Technical details

The picker logic lives in `select_config()` in `src/lib/config/select_config.sh`. For each `*.json` candidate it now calls a new helper, `_config_picker_meta`, which loads the file (via `json_load`/`json_get` in a subshell, so a malformed sibling config can't abort the whole pick and doesn't clobber the global `JSON_DATA` before the real `drupalaibp_load` runs) and reads `weight` (default `0`, with a non-integer value warning and falling back to `0`) and `label` (default the file's basename). When more than one config is found, a new `_select_config_sort` reorders the parallel `files`/`names`/`labels`/`weights` arrays with `LC_ALL=C sort -t $'\t' -k1,1n -k2,2`, i.e. numeric sort on weight then alphabetical on name, before building the `select_one` menu. Each menu row shows `Label (name)` when the label differs from the file's basename, or just the name when they match, so the value to pass to `--config <name>` stays visible either way. Both keys were added to `DRUPALAIBP_KNOWN_KEYS` in `load_config.sh` (in two places) so they don't trigger unknown-key warnings, though they are picker-only metadata and never reach the build itself. A new `docs/examples/multi-config/` example with four configs (two weighted, two not) demonstrates the ordering, and `tests/bats/lib/config/select_config.bats` covers alphabetical fallback, weight ordering, tie-breaking, label display, non-integer weight handling, and the single-config no-prompt case.</technical>
