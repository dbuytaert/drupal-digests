## Summary

On Linux desktops where Firefox or Chromium is installed as a snap (the Ubuntu default), the installer now adds DDEV's local certificate authority directly to the browser's own certificate store. Previously `mkcert -install` could not reach that store, so `https://<project>.ddev.site` still showed a security warning. After the installer runs, restart the browser if it is open. A snap browser that has never been opened has no certificate store yet, so the installer still prints the manual import steps for it.

## Impact

No upgrade or configuration changes required.

## Technical details

`_warn_snap_browsers` in `src/lib/platform/ensure_local_https.sh` is replaced by `_trust_snap_browsers`, called from `ensure_local_https` on Linux after `mkcert -install`. For each of `~/snap/firefox` and `~/snap/chromium` that exists, it collects NSS database directories: every `~/snap/firefox/common/.mozilla/firefox/*/` containing `cert9.db`, and `~/snap/chromium/current/.pki/nssdb` if it has `cert9.db`. The new helper `_add_ca_to_nss_dbs` runs `certutil -A -d "sql:<dir>" -t "C,," -n "mkcert development CA (DDEV)" -i "$(mkcert -CAROOT)/rootCA.pem"` on each one, and fails if certutil is missing or any add fails.

The issue proposed skipping databases that already hold the CA, but the code does not check first. A comment in the code says re-adding the same CA is harmless. Browsers that were updated print an `ok` message asking for a restart. Browsers with no database, or where certutil fails, print the existing warning with manual import instructions. The function always returns 0, so the step stays best-effort. New bats tests cover multiple Firefox profiles, the Chromium nssdb, no-profile, missing certutil, a failing `certutil -A`, and macOS. `AGENTS.md` and the spelling dictionary (`nssdb`) are updated.
