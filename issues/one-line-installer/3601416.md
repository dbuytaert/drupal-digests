## Summary

On a fresh Linux machine the installer now sets up browser trust for DDEV's local certificate authority, so `https://<project>.ddev.site` no longer shows a certificate warning that has to be accepted by hand. It installs the missing NSS tools and runs `mkcert -install` even when DDEV was already installed. For snap-packaged Firefox or Chromium, which keep their own certificate store, it prints instructions for importing the CA manually.

## Impact

No upgrade or configuration changes required.

## Technical details

Adds `ensure_local_https` in `src/lib/platform/ensure_local_https.sh`, called from `step_ensure_ddev` after `_ensure_ddev_cli` and before `ensure_git`, as `ensure_local_https || true`, so failure never aborts the install. DDEV's `install.sh` only runs `mkcert -install` when it installs DDEV itself, and on Linux mkcert can only write to Chrome/Firefox NSS stores through `certutil`, which nothing installed.

The function warns and returns 1 if `mkcert` is missing. On Linux it calls `_ensure_certutil`, which installs `libnss3-tools` via apt or `nss-tools` via dnf depending on `PKG`, and warns if `PKG` is empty (unmapped distro) or the install fails. It then runs `mkcert -install`. On Linux, `_warn_snap_browsers` checks for `~/snap/firefox` and `~/snap/chromium` and, if found, warns to import `$(mkcert -CAROOT)/rootCA.pem` through the browser's certificate settings. macOS gets no package install. New bats tests cover each branch, and the `step_ensure_ddev` tests cover the call order and the carry-on-on-failure behaviour.
