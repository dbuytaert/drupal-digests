## Summary

The installer now installs git on the host by default, alongside Docker and DDEV. Before this, on a fresh Linux machine `--config-url` (and remote-config picks or `pull`) stopped with "requires git, which was not found on this host". The git install is best-effort, so builds that never clone a repo still run if git can't be installed. A new `--skip-git-install` flag opts out. With that flag, a config fetched from a URL needs git already installed, and the error message names the flag.

## Impact

Affects module maintainers.

- **New API:** New `--skip-git-install` flag on `setup-site`; git is now installed on the host by default.

## Technical details

A new `src/lib/platform/ensure_git.sh` adds two functions. `ensure_git` returns early if git exists or `INSTALL_GIT` is 0. On Linux it installs git from distro packages (`apt-get` or `dnf`, using `PKG` from `linux_detect_distro`). On macOS it only warns with an `xcode-select --install` / `brew install git` hint. It warns and returns 1 on any failure instead of dying. `step_ensure_ddev` calls `ensure_git || true` after `_ensure_ddev_cli`.

A config URL is cloned before the pipeline reaches `step_ensure_ddev`. So `load_config_url` and `_git_clone_ref` now call `require_git`, which installs git on demand and dies if it can't. If `--skip-git-install` was given, `require_git` dies with a message naming that flag. `INSTALL_GIT` (default 1, 0 with the flag) is set in `setup_site_command.sh` next to `YOLO`, not in `apply_cli_flags`, so it is already in effect at clone time. The flag is declared in `src/bashly.yml`, and the generated script, man page and usage docs were regenerated. New bats tests cover the behavior.

## Upgrade

To keep the previous behavior of not installing git, pass the new flag:

```
--skip-git-install
```
A `--config-url` or remote-config source then needs git already installed.
