# #3591485: Support downloading necessary binaries into vendor/bin

## Summary

Drupal CMS projects now include a tool, `internal/dload`, that downloads standalone binaries into `vendor/bin` whenever `composer update` runs. The goal is to let site templates use things like a JavaScript runtime (Deno or Bun) to build frontend assets without requiring Node on the server. The issue proposes that a site template that needs binaries ships a `dload.xml` file and that site owners commit it so the binaries can be restored on deployment. That shipping and scaffolding of `dload.xml` is not part of the merged change.

## Impact

Affects module maintainers.

- **New API:** Drupal CMS project templates now require `internal/dload` and run `dload get --quiet --path=vendor/bin` on `post-update-cmd`, so binaries declared for a project are downloaded into `vendor/bin`.

## Technical details

The merged change edits `project_template/composer.json`. It adds `"internal/dload": "^1.17"` to `require`. It also appends `dload get --quiet --path=vendor/bin` to the existing `post-update-cmd` script, after the line that unlinks `vendor/bin/composer`. The commit title references both `cms` and `cms_cpanel`, but only `project_template/composer.json` appears in the diff. The same commit removes the `scripts-descriptions` block (the `canary:*` descriptions) from `dev.composer.json`. The issue body also discusses a limitation: different site templates could ship conflicting `dload.xml` files. It argues this is acceptable because only one site template can be chosen at install time. The hook is on `post-update-cmd` only, not on install, so I could not verify from the diff what happens on a fresh `composer install`.

## Upgrade

Existing projects created from the Drupal CMS project template would need to add the same lines to their own `composer.json` to get this behavior:

```json
"require": {
    "internal/dload": "^1.17"
},
"scripts": {
    "post-update-cmd": [
        "@php -r \"@unlink('vendor/bin/composer');\"",
        "dload get --quiet --path=vendor/bin"
    ]
}
```
