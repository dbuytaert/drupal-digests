# #3591382: Implement and document changing the web root during 'composer create-project' installation

## Summary

Drupal CMS's DDEV-based local development setup now supports changing the web root (document root) cleanly at install time. Previously, users on shared hosting who wanted a web root other than the default `web` (e.g. `public_html`) had to manually edit `composer.json`, `.gitignore` and `AGENTS.md`, and doing so via `ddev config --docroot=...` would overwrite the project's DDEV configuration and skip Composer's automatic recipe-unpacking step, leaving packages like `drupal/mercury` listed as raw direct dependencies and breaking later `composer remove` commands. Now, running `ddev config --docroot=new_web_root` before `ddev launch` is all that's needed: DDEV will rewrite the relevant files and correctly install and unpack recipes.

## Impact

Affects site owners.

- **Config change:** The DDEV project template now ships a `post-start` hook in `.ddev/config.yaml` that, when no `composer.lock` exists yet, rewrites `web/` references in `composer.json`, `AGENTS.md` and `.gitignore` to match DDEV's configured docroot before running `composer install` and `composer drupal:recipe-unpack`.

## Technical details

The fix lives in the DDEV project template shipped by `composer create-project drupal/cms`. Previously `project_template/assets/.ddev/config.yaml` was a separate file moved into `.ddev/` as a post-install step, with no awareness of a custom docroot; it only ran `composer install` and `composer drupal:recipe-unpack` on post-start. That file is removed and its config is merged directly into a new `project_template/.ddev/config.yaml`, which still defaults `docroot: web` but adds logic to its `post-start` hook: if no `composer.lock` is present yet (i.e. dependencies haven't been installed), it uses `sed` to rewrite `web/` occurrences in `AGENTS.md` and `composer.json` to `$DDEV_DOCROOT/`, and adjusts the leading `/web/` entry in `.gitignore` to match (or strips it entirely when the docroot is `.`). Only after that rewrite does it run `composer install` followed by `composer drupal:recipe-unpack`, so recipe unpacking now happens regardless of which docroot was chosen.

The related `.ddev/commands/web/tag` script (used to build the cPanel-flavored `cpanel_template`, which uses docroot `.`) is simplified to rely on the same `yq`-driven docroot update rather than duplicating the `sed` rewrites by hand. `project_template/README.md` now documents the supported workflow: run `ddev config --docroot=new_web_root` before `ddev launch`.
