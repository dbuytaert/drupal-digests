## Summary

In Drupal CMS, a user whose only role was Content editor got "access denied" after logging in, and the navigation toolbar was missing. The cause was the missing `view any unpublished content` permission. Once the basic moderation workflow was added, the default home page started out unpublished, so editors couldn't view it. The Content editor role now has that permission, and the default home page is created as published. Anonymous visitors can see the home page again as well.

## Impact

Affects site owners.

- **Config change:** The default home page content now ships with `moderation_state: published`.
- **Permission change:** The `content_editor` role now gets `view any unpublished content`.

## Technical details

The fix adds `view any unpublished content` to the permissions list in the content editor role config, next to `view scheduled content`. It also adds `moderation_state: published` to the default home page content, so anonymous users no longer get a 403 or a redirect to the login form. The drupal_cms_content_type_base test now includes `testContentEditorPermissions()`. It creates an unpublished page as a content editor and checks that it returns a 200, then checks again after publishing. The starter recipe test now checks that the front page is accessible and that the editor sees the Dashboard link in the navigation. `PerformanceTest` gained assertions that the home page text is present, and its stylesheet, script and cache-get thresholds were adjusted. `ContentDuplicationTest` now finds the row by its link instead of a `tr:nth-child(2)` selector. The same change was committed to both `1.x` and `1.0.x`.

## Upgrade

Existing sites do not appear to get this automatically, because the diff changes only recipe config and default content and has no update path. Site owners with content editors affected by the 403 can grant `view any unpublished content` to the `content_editor` role manually. They can also publish the home page.
