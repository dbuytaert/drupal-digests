# #3591502: Installer writes Composer's cache into <project root>/.composer when installing a site template

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591502](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591502) · 1 contributor · 4 comments

## Summary

When COMPOSER_HOME isn't set, the Drupal CMS installer falls back to a `.composer` directory in the project root so Composer can run. That fallback also caused Composer's download cache to be written to `.composer/cache/`, leaving hundreds of changed files in version-controlled or repository-deployed code directories after installing a site template. The installer now disables Composer's cache in that situation, so the project stays clean. This affected 2.2.3 through 2.2.5.

## Impact

No upgrade or configuration changes required.

## Technical details

In `ComposerExecutor::execute()` (`drupal_cms_installer/src/ComposerExecutor.php`), when the `COMPOSER_HOME` fallback is applied, the installer now also sets `COMPOSER_CACHE_DIR` to `/dev/null` (`NUL` on Windows) via `Platform::putEnv()`, and clears it in the `finally` cleanup along with `COMPOSER_HOME` and `COMPOSER_HTACCESS_PROTECT`. Composer's `Factory::getCacheDir()` otherwise derives the cache path from `COMPOSER_HOME`, which is why the cache landed in the project. A null cache dir makes Composer disable its cache, so no cache directory is created. This was chosen over the two options in the issue: passing `--no-cache` in `run()`, and a per-project temp directory. Because it is only applied when the fallback is used, sites with a real `COMPOSER_HOME` keep their normal cache. The unit test `ComposerExecutorTest` now asserts `COMPOSER_CACHE_DIR` is set inside `execute()` and unset afterwards, and that a real `ComposerExecutor::run()` doesn't create the `.composer` directory.

## Upgrade

If a site already ran the installer on 2.2.3 to 2.2.5 without COMPOSER_HOME set, an existing `<project root>/.composer/cache/` directory may remain and can be deleted or excluded from version control.
