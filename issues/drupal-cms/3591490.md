# #3591490: Add an initial 'ping' when opting into telemetry

## Summary

When a Drupal CMS site opts into telemetry, it now sends an initial "opt in" event, so the project can count opt-ins over time even if the site never triggers any other tracked action. The telemetry documentation lists this event as carrying no extra data. The site template install event is also now queued before any opt-in decision, but it is only sent once the site opts in.

## Impact

Affects module maintainers.

- **New API:** New `Telemetry::OptIn` enum case (`opt_in`) in `drupal_cms_helper`.

## Technical details

`TelemetryManager::status()` now calls `$this->log(Telemetry::OptIn)` whenever it is set to a truthy value, using the new `Telemetry::OptIn` case (`opt_in`). Opting out (`FALSE`) still deletes the `drupal_cms_telemetry` queue. `log()` is also changed so that `Telemetry::SiteTemplateInstall` is queued even when `status()` is still `NULL`. At install time there has been no explicit opt-in, and without this the project would never learn which site templates are used. Nothing is sent until the site opts in, because `sendAll()` only runs for opted-in sites. The change adds tests: the kernel test asserts the `OptIn` event is queued, and a new `testOptOutClearsTheQueue()` covers the opt-out queue deletion. `InteractiveInstallTest` asserts the single deferred `SiteTemplateInstall` event is queued after install. The docs table in `docs/src/updates/telemetry.md` gains an "You opt into telemetry" row.
