# #3591424: Recipes cannot be installed via UI due to bug with append-default.settings.php.txt

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591424](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591424) · 1 contributor · 5 comments

## Summary

Installing recipes through the UI on a Drupal CMS site could fail with `Scaffold file assets/append-default.settings.php.txt not found in package drupal/cms`. This was reported on a DDEV site. The Drupal CMS project template no longer appends anything to `default.settings.php`, which removes the failure.

## Impact

Affects site owners.

- **Config change:** The Drupal CMS project template no longer appends `config_sync_directory` or `package_manager.settings` overrides to `default.settings.php`, and the empty `config/sync/.gitkeep` is removed.

## Technical details

The template's `composer.json` used the Composer scaffold `append` file mapping for `[web-root]/sites/default/default.settings.php`, pointing at `assets/append-default.settings.php.txt`. When a recipe is installed through Package Manager, the scaffold operation ran against a sandbox copy of the project and could not find that `assets` file. The old appended snippet worked around this by setting `package_manager.settings.include_unknown_files_in_project_root` when an `assets` directory existed (with a `@todo` pointing to core issue 3531174).

The fix removes the problem at its source. The `file-mapping` entry, `project_template/assets/append-default.settings.php.txt` and the root `assets` symlink are all deleted. The appended snippet also set `$settings['config_sync_directory']` to `../config/sync` when it existed, and `project_template/config/sync/.gitkeep` is deleted too. In `drupal_cms_helper`, the `Dockerfile` no longer copies `assets/`. `SiteArchiveCommand` no longer includes `assets/` in the site archive or creates an `assets` directory, and `SiteArchiveCommandTest` no longer asserts that directory exists.

## Upgrade

Existing sites that already have the appended block in `settings.php` keep it, since it was written to that file at install time. This is not a documented step, and I did not verify what happens to such sites after updating `drupal/cms`.
