# #3591508: Trust the cweagans/composer-patches plugin by default

## Summary

Drupal CMS now trusts the `cweagans/composer-patches` plugin by default, in both Composer and Package Manager. A site owner who wants to patch dependencies can run `composer require cweagans/composer-patches` and it works, with no extra step to allow the plugin. The plugin is still not bundled with Drupal CMS.

## Impact

Affects site owners.

- **Config change:** `cweagans/composer-patches` added to `allow-plugins` in the project template `composer.json` and to `additional_trusted_composer_plugins` in the site template base recipe's `package_manager.settings`.

## Technical details

The Composer side is handled by adding `"cweagans/composer-patches": true` to `config.allow-plugins` in `project_template/composer.json`. It was removed from `dev.composer.json`, which is the development setup for the Drupal CMS repository itself.

The Package Manager side was previously a runtime config override. `scripts/PackageManagerSettings.php` implemented `ConfigFactoryOverrideInterface` and injected the plugin into `package_manager.settings:additional_trusted_composer_plugins`. That override and its `config.factory.override` tag in `scripts/services.yml` are removed. The class now only implements `EventSubscriberInterface`. The plugin is instead listed in the shipped config, `recipes/drupal_cms_site_template_base/config/package_manager.settings.yml`, next to `tbachert/spi`. That file carries a `@todo` to delete it when [#3557220](https://www.drupal.org/node/3557220) is released.

## Upgrade

Existing sites that already added the plugin keep working. New projects from the project template already have it in `allow-plugins`. To use it:

```
composer require cweagans/composer-patches
```
