# #3591494: CMS 2.2.4 causes contrib DrupalCmsCompatibilityTest to fail. Replace with a new job

## Summary

Since Drupal CMS 2.2.4, the standard contrib `DrupalCmsCompatibilityTest` fails with an `assert(is_array($all_choices) && array_key_exists($choice, $all_choices))` error, so the `Drupal CMS` job in standard GitLab pipelines breaks. Rather than patching the test, Drupal CMS adds a new GitLab CI include, `site-templates.ci.yml`, that smoke-tests a module, theme or recipe against a chosen site template. The old test is deprecated and now just skips itself.

## Impact

Affects module maintainers.

- **Deprecation:** `DrupalCmsCompatibilityTest` is deprecated, now skips itself, and will be removed in the next major version of Drupal CMS.
- **New API:** New `site-templates.ci.yml` GitLab CI include with a `.cms-site-template-base` job, configured through the `SITE_TEMPLATE` and optional `PAGES` variables.

## Technical details

`site-templates.ci.yml` defines a hidden job, `.cms-site-template-base`, marked `@api`. It does not run the extension's PHPUnit tests. Its `script` requires the extension to have a `composer.json` with `name` and `type`. It moves the extension into a temp directory and creates a `drupal/recommended-project`. It adds the extension as a `path` repository and requires the package at `@dev`, the site template named in the `SITE_TEMPLATE` variable, and `drush/drush`. It then runs `drush site:install` with `../recipes/<template>`. The extension is installed by package type: `pm:enable` for `drupal-module`, `theme:install` for `drupal-theme`, `drush recipe` for `drupal-recipe`. Any other type fails the job. Finally it starts `drush serve` on port 8888 and fetches each page in `PAGES` with curl. `PAGES` defaults to `/` and `/user/login`.

The file's header says the standard GitLab configuration already includes it. It also says a maintainer can add a per-template job that extends `.cms-site-template-base` and sets `SITE_TEMPLATE` (for example `drupal/haven`). I did not confirm from this repo that the include is wired into the standard templates. The root `DrupalCmsCompatibilityTest.php` is now `@deprecated`: `testExtensionIsInstallable()` only calls `markTestSkipped()`. Its docblock says it will be removed in the next major version of Drupal CMS. The same commit also adds a large set of `.ddev` helper commands and `.agents` files for project development, which are unrelated to the fix.

## Upgrade

Extension maintainers who relied on `DrupalCmsCompatibilityTest` should switch to the new include. If the standard GitLab configuration doesn't already include it, add:

```yaml
include:
  - { project: project/drupal_cms, file: site-templates.ci.yml }
```

To test against a specific site template, add a job:

```yaml
haven:
  extends: .cms-site-template-base
  variables:
    SITE_TEMPLATE: drupal/haven
```

The extension needs a `composer.json` that defines `name` and `type`.
