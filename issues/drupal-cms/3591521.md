## Summary

The default Drupal CMS AI assistant no longer ships with preset model parameters (token limit, temperature and similar). These values worked with OpenAI and Anthropic models but would break when Amazee is the provider. The assistant now starts with an empty configuration, so the chosen provider's own defaults apply.

## Impact

Affects site owners.

- **Config change:** Default `llm_configuration` in the `drupal_cms_assistant` AI assistant config is now an empty object instead of hardcoded `max_tokens`, `temperature`, `frequency_penalty`, `presence_penalty` and `top_p` values.

## Technical details

In the `ai_assistant_api.ai_assistant.drupal_cms_assistant` config, `llm_configuration` was changed from `max_tokens: 4096`, `temperature: 1.0`, `frequency_penalty: 0`, `presence_penalty: 0` and `top_p: 1.0` to an empty mapping (`{  }`). `llm_provider: __default__` and `llm_model: ''` are unchanged, so the provider and model still come from the site's default AI provider settings. The motivation was a bug in the AI module's assistant system (ai work item 3586815, MR 2106), which would expose the incompatibility with Amazee once merged. The diff only touches this one default config file. The diff output does not show the file path, so the path comes from the issue text.

## Upgrade

Existing sites keep their stored config. Only new installs get the empty default. Sites that hit the Amazee problem can clear the same keys in the assistant's configuration:

```yaml
llm_configuration: {  }
```
