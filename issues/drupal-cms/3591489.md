# #3591489: Use the Tagify User List widget by default for user reference fields

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591489](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591489) · 1 contributor · 4 comments

## Summary

On new Drupal CMS sites, user reference fields now use the Tagify User List widget by default instead of core's plain autocomplete. This covers new "User" reference fields added through Field UI and the "Authored by" field on newly created content types. User emails are not shown in the suggestions. Existing sites are unchanged, and content types that ship with a saved form display (such as Basic page) keep their current widget.

## Impact

Affects site owners.

- **Requirements:** `drupal/tagify` constraint in the recipe raised from `^2.0` to `^2.0.4`.
- **Config change:** The `drupal_cms_site_template_base` recipe sets `tagify_user_list.settings:set_default_widget` to true.

## Technical details

The `drupal_cms_site_template_base` recipe now applies `simpleConfigUpdate: set_default_widget: true` to `tagify_user_list.settings`, next to the existing `tagify.settings` entry. The setting comes from the Tagify User List submodule in Tagify 2.0.4 (see the Tagify issue [#3590704](https://www.drupal.org/node/3590704)), so the recipe's `composer.json` requires `drupal/tagify` `^2.0.4`. Older versions lack the setting and the recipe would fail to apply. `ContentEditingTest` now asserts that the `uid` component of a new content type's form display uses `tagify_user_list_entity_reference_autocomplete_widget`. Because the setting only affects newly created fields and displays, saved form displays such as `node.page.default` stay on their existing widget. Switching Basic page's "Authored by" is left to a follow-up. Per the issue, existing sites get the setting added as off by Tagify's `tagify_user_list_update_8003()`.
