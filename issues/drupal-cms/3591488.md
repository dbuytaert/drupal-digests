# #3591488: Add telemetry events for Project Browser

## Summary

Drupal CMS's opt-in telemetry now tells the project how much Project Browser is used. Module install events record whether the install came from Project Browser and whether a recipe triggered it. Recipe applied events record whether Project Browser applied the recipe, which separates it from a command line apply. Visits to Project Browser's module list are now reported as an admin page visit, alongside the existing recommended add-ons page. The telemetry documentation table was updated to match.

## Impact

Affects site owners.

- **Requirements:** `drupal_cms_helper` now requires `drupal/core` `^11.4.8` (for `RecipeRunner::isApplying()`).

## Technical details

`TelemetryManager::log()` now adds `project_browser` to `Telemetry::ModuleInstall` and `Telemetry::RecipeApplied` events. It is true when the current route is `project_browser.activate`. `ModuleInstall` events also get `via_recipe`, taken from `RecipeRunner::isApplying()`. Both use `??=`, so a caller can pass its own value. `TelemetryHooks::onModuleInstall()` previously detected a running recipe by scanning `debug_backtrace()` for `RecipeRunner`. It now uses `RecipeRunner::isApplying()`, which is why `drupal_cms_helper/composer.json` requires core `^11.4.8`.\n\n`TelemetrySubscriber` now matches `project_browser.browse` on the raw `source` route parameter. `drupalorg_jsonapi` is logged as page `module list` and `recommended` as `recommended add-ons`. Other sources log nothing.\n\nThe diff also moves the opt-out check for tests, previews and CI (`drupal_valid_test_ua()`, `Environment::isPreview()`, `Environment::isCi()`) from `TelemetryHooks::cron()` into `TelemetryManager::sendAll()`. In `cron()`, the 30 day ping is now logged only when telemetry is enabled, and the interval is the new `TelemetryHooks::PING_INTERVAL` constant. `TelemetryManager::QUEUE_NAME` became public. A new kernel test, `TelemetryHooksTest`, covers the events. `dev.composer.json` pins PHPStan to `~2.2.17`.
