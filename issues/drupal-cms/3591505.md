## Summary

Drupal CMS's telemetry "still alive" ping is now sent every 7 days instead of every 30. Each ping includes a `count` of how many pings the site has sent, so the Drupal CMS team can tell how long a site has existed. This lets them separate short-lived test, prototype and demo sites from long-running ones. The telemetry documentation page is updated to describe the new interval and the counter.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `TelemetryHooks::cron()` in `drupal_cms_helper`. `PING_INTERVAL` goes from `86400 * 30` to `86400 * 7`. The `drupal_cms_telemetry.ping` state value used to hold the last ping timestamp. It now holds a two-item array of `[last ping timestamp, ping count]`. A legacy numeric value is converted to `[$last, 0]` on read, so existing sites carry on without an update hook.

Each ping carries `count`, which is the stored count plus one. The first ping (`count` of 1) still adds `opt_in` and, for `drupal/cms` or `drupal/cms_cpanel` root packages, `project_name`. The state is only written back when a ping is actually logged. The old `if ($this->telemetry->status())` wrapper around the ping logic is removed. Now only `sendAll()` is guarded by the status check, and `TelemetryManager::sendAll()` gains an `assert($this->status())`. `TelemetryManager::log()` still checks `status()` itself, so no ping event is queued while telemetry is disabled. The state is still updated in that case, so the counter advances even when no event is recorded.

`TelemetryHooksTest` now asserts `count` of 1 and then 2. `docs/src/updates/telemetry.md` is updated. In the diff the edited table row ends with an extra `||`.
