# #3591455: Update search recipe to create blocks instead of a views page

## Summary

The Drupal CMS search recipe no longer creates a `/search` page for results. It now provides a views block for the results, which can be placed on a Canvas page. The issue author found the page-based setup unintuitive and noted that it had been a rushed change before the 2.0 launch. With the recipe applied, site builders create their own Canvas page and add the search form and results components to it.

## Impact

Affects site owners.

- **Config change:** In the `drupal_cms_search` recipe, the `search` view's `page` display (path `search`) is replaced by a `block` display with machine name `search`.

## Technical details

In `recipes/drupal_cms_search/config/views.view.search.yml`, the `page` display is replaced by a display with id `search`, titled "Block", using the `block` plugin. The `path: search` setting is removed and `exposed_block: true` is kept. This produces two Canvas components, `block.views_block.search-search` for the results and `block.views_exposed_filter_block.search-search` for the exposed form. They replace the single `block.views_exposed_filter_block.search-page` component.

The same view config also gets a few smaller edits:
- The title `element_class` changes from `heading-responsive-3xl` to `text-2xl`.
- The title fields add `link_rel: canonical`.
- The `delta_*` formatter settings are added.
- `text_input_required` is set to 'Enter keywords to search.'

`ComponentValidationTest` now creates a Canvas `Page` containing both components and runs the search from that page. It no longer places a block with `drupalPlaceBlock()`. The `CoversMethod` attributes for `FormHooks` are removed from the test.
