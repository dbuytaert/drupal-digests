# #3591496: Drupal CMS 2.2.4 : Read-only installs have no site templates and the template step crashes

- **Project:** Drupal CMS

## Summary

In Drupal CMS 2.2.4, new projects ship without any site templates on disk. If the code directory is read-only (for example Pantheon in Git mode), the installer can only list templates already downloaded, so the "Choose a site template" step was empty and clicking Next threw a TypeError. The step now shows the error "There are no site templates available." and no longer offers a form that crashes. Note this only prevents the crash: such an install still cannot proceed without a template, so the first install needs a writable code directory.

## Impact

No upgrade or configuration changes required.

## Technical details

`SiteTemplateForm::buildForm()` in `drupal_cms_installer` merges `SiteTemplate::findAll()` with the curated online list. If the merged `$all_choices` is empty, it now adds a messenger error and returns the form early, before the template options and the actions element are built. That removes the Next button, and so the path where `getChoice()` returned null and caused the TypeError. The `$form['#title']` assignment moved to the top so the title still shows on the early return. In `drupal_cms_installer_theme.theme`, the `add_ons` wrapper prefix and suffix are now set directly rather than with `+=`. The issue body's proposed test for the empty case is not part of the commit.
