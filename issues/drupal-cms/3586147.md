## Summary

The Drupal CMS accessibility tools recipe now depends on Editoria11y 3.x instead of 2.x. The issue says 2.x is functionally end-of-life. According to the issue, 3.x ships with 16 languages (2.x only had German), has more tests, rewritten tips, CSV exports moved to a submodule, and dashboard views that can filter on live node data. The Editoria11y results dashboard view that the recipe ships was rewritten to match the new 3.x data model.

## Impact

Affects site owners.

- **Requirements:** The accessibility tools recipe now requires `drupal/editoria11y` `^3` instead of `^2.2`.
- **Config change:** The `A11y Tools Editoria11y results` view now uses the Editoria11y 3.x tables `ed11y_result` and `ed11y_page`, with `page_result_count` replaced by `content_results`.

## Technical details

The recipe's `composer.json` requirement changes from `drupal/editoria11y: ^2.2` to `^3`. The root `composer.json` also adds an exclusion for `modules/editoria11y_export/tests` under `drupal/editoria11y`, next to the other per-package test exclusions.

The recipe's `A11y Tools Editoria11y results` view config was updated for the 3.x schema. The base table changes from `editoria11y_results` to `ed11y_result`. A new relationship `editoria11y_result_to_page` joins to `ed11y_page`, and the `page_title`, `page_path` and result count fields now come from `ed11y_page` through it. The `page_result_count` field and sort become `content_results`, and a hidden `pid` field is added. The `editoria11y_sync_check` header now uses table `views`.

The view only works with Editoria11y 3.x tables, so it will not work with 2.x.
