## Summary

Drupal CMS's weekly telemetry ping now includes a `launcher` true/false value. It tells the project team which sites run through the Drupal CMS launcher app. It is sent only when telemetry is enabled. Sites can opt out in the site information form or in `settings.php`. The issue has no comments and no linked merge request. The change is visible in the repository, where it landed with the broader telemetry rework in [#3591506](https://www.drupal.org/node/3591506).

## Impact

No upgrade or configuration changes required.

## Technical details

The issue asked for `launcher = TRUE` on ping events. As implemented, it is a boolean on the ping only, set in `TelemetryHooks::cron()` in `drupal_cms_helper`. It is true when the root `composer.json` has an `extra.drupal-launcher` key and `PHP_SAPI === 'cli-server'`. The `cli-server` check matches the built-in PHP web server that the launcher uses. To read the `extra` array, `ProjectResolver::readPackageInfo()` now returns `mixed` instead of `?string`. The kernel test `TelemetryHooksTest` asserts that `launcher` is a bool on both the first and the second ping. I found this code in the repo's history under commit 56ef97e ([#3591506](https://www.drupal.org/node/3591506)). I did not find a separate commit for this issue.
