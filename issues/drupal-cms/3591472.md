# #3591472: Fresh 2.2.0 projects cannot composer require anything: recipe unpacking drops the @alpha flag on drupal/canvas_translate

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591472](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591472) · 1 contributor · 3 comments

## Summary

Any site built from `composer create-project drupal/cms` on version 2.2.0 was left in a broken state where adding or updating any Composer package afterward failed outright, with an error about `drupal/canvas_translate` being fixed to an alpha version that violates the project's minimum stability. This happened because Composer's recipe unpacking step, which runs at the end of `create-project`, merged two version constraints for `drupal/canvas_translate` (one from the root project, one from the bundled multilingual recipe) in a way that silently dropped the `@alpha` stability flag, while the lock file still pinned the actual alpha release. The fix restores that flag so freshly created projects can have modules added to them normally.

## Impact

No upgrade or configuration changes required.

## Technical details

The root cause is in Composer's `drupal/core-recipe-unpack` package: `Unpacker.php`'s call to `SemVer::minimizeConstraints()` merges the project template's `"drupal/canvas_translate": "@alpha"` with the `drupal_cms_multilingual` recipe's `"drupal/canvas_translate": "^1"` into a plain `^1`, losing the stability flag even though `composer.json` still declares `minimum-stability: stable` and `composer.lock` keeps the actual `1.0.0-alpha4` version. Any later partial update (i.e. any `composer require`) then rejects the locked alpha version against the project's stability settings.

Rather than changing core's unpacker, the fix (commit `1b10389`, "Make a stability affordance for canvas_translate") re-adds `"drupal/canvas_translate": "@alpha"` directly to `project_template/composer.json`, ensuring the root constraint always carries the stability flag on its own. A companion fix in the related issue [#3591473](https://www.drupal.org/node/3591473) also changed the `drupal_cms_multilingual` recipe's own constraint from `"^1"` to `"^1@alpha"` in `recipes/drupal_cms_multilingual/composer.json`, so both sides of the merge already carry the alpha flag and `minimizeConstraints()` no longer has a way to drop it.

## Upgrade

Sites already created from Drupal CMS 2.2.0 that hit this need to manually restore the stability flag in their project's root `composer.json` before requiring anything else:

```json
"require": {
    "drupal/canvas_translate": "@alpha"
}
```

Alternatively, avoid triggering the bug on new projects with the documented workaround: `composer create-project --no-install drupal/cms test-site`, then `cd test-site && composer install`. This keeps recipes packed (rather than unpacked) so the `@alpha` flag in `composer.json` is never dropped, and later `composer require` calls work normally.
