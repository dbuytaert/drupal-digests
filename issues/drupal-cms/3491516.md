## Summary

On Drupal CMS sites using the blog or news content type recipes, the tags exposed filter no longer shows when there are no tags, and it only lists tags that have content for that content type. Before, the filter block appeared even with no tags, and since the tags vocabulary is shared it listed tags with no matching results. The blog and news listing pages also get an "Add a blog post" or "Add a news item" button, matching the events view.

## Impact

Affects site owners.

- **Requirements:** The blog and news recipes now require `drupal/add_content_by_bundle` ^1.2.2 and `drupal/selective_better_exposed_filters` ^3.0.
- **Config change:** The blog and news views config enables Selective Better Exposed Filters options for the tags filter and adds an `add_content_by_bundle` header area.

## Technical details

The change is in the blog and news recipes of Drupal CMS. In each recipe's views config, the tags filter's Better Exposed Filters settings gain `options_show_only_used: true`, `options_show_only_used_filtered: false` and `options_hide_when_empty: true`. These settings come from the Selective Better Exposed Filters module, which is added to `recipe.yml` `install` and to `composer.json`. `better_exposed_filters` is no longer in the `install` list of either recipe, and it stays in the blog recipe's `composer.json` requirements. The recipes also install `add_content_by_bundle`. The views get an `add_content_by_bundle` header handler with the label "Add a blog post" (bundle `blog`) or "Add a news item" (bundle `news`), using the `button` class. `autosubmit_textfield_minimum_length: 3` is also set. The parent recipe's `composer.json` requirement on `add_content_by_bundle` was raised from ^1.2 to ^1.2.2. The committer noted that he fixed some Views schema errors while merging, which he suspected came from Better Exposed Filters supporting properties not defined in schema.
