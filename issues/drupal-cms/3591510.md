# #3591510: Switch `drush si` default site template to Forma

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)

## Summary

When Drupal CMS is installed non-interactively with `drush si` and no site template is named, the default is now Forma instead of Starter. The issue frames this as a test of 1-2 weeks. Starter is the most popular template in analytics, and the maintainers want to know whether that is only because it was the default. Scripts and CI jobs that run a bare `drush si` and expect Starter should name the template explicitly.

## Impact

No upgrade or configuration changes required.

## Technical details

I could not read the merged diff, so this describes the prior code and the issue text only. Before this change, `SiteTemplateForm::buildForm()` in `drupal_cms_installer/src/Form/SiteTemplateForm.php` set `$form['add_ons']['#default_value']` to `drupal_cms_starter` when `$install_state['interactive']` was empty, as it is for command line installs. The comment there says Starter was chosen because Blank looks like an error to someone who doesn't know what to expect. `drupal_cms_installer/site-templates.yml` already defines a `forma` entry (package `drupal/forma`), which is the template the issue names as the new default. The interactive installer's default (Blank) is not part of the issue.

## Upgrade

To keep getting Starter from a scripted install, name the template explicitly, as `project_template/README.md` does:

```
ddev drush site:install /var/www/html/recipes/drupal_cms_starter --yes
```
