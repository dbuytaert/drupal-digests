# #3591486: Allow Tagify 2.0.x in drupal_cms_site_template_base

## Summary

Drupal CMS's site template base recipe now requires the Tagify module at `^2.0` instead of `^1.2`. Before this, Composer would not let a Drupal CMS project install Tagify 2.x, and the site templates repo was blocked from moving too. The issue states the tags widget looks and behaves the same, and that config, widget plugin IDs and widget settings are identical between 1.2.x and 2.0.x, so no update path is needed.

## Impact

Affects site owners.

- **Requirements:** `recipes/drupal_cms_site_template_base/composer.json` now requires `drupal/tagify` `^2.0` instead of `^1.2`; Tagify 2.0.x requires core `^11.1 || ^12`.

## Technical details

The change is a one-line constraint bump for `drupal/tagify` in `recipes/drupal_cms_site_template_base/composer.json`, plus regenerated README files via `ddev readme`. This is taken from the issue description, since no diff was available. The issue's comparison of Tagify branches found that `config/` and `tagify.install` are identical, the widget plugin ID `tagify_entity_reference_autocomplete_widget` is unchanged, and the `match_operator: CONTAINS` and `suggestions_dropdown: 1` values still match the new enums. `tagify.settings.set_default_widget`, which `recipe.yml` sets, still exists. The option `^1.2 || ^2.0` was rejected because Drupal CMS 2.x already requires Drupal 11.4.

## Upgrade

Site templates that use a `^1.2` constraint for `drupal/tagify` (the issue names everbright, forma, byte, haven and mercury_demo) need to move to `^2.0` to stay compatible with this recipe.
