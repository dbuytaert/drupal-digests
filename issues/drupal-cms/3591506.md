# #3591506: Updates to telemetry for env info, remove user_login, specify recipes & templates

- **Project:** Drupal CMS

- **Status:** Fixed

## Summary

Drupal CMS telemetry changed in what it reports. Every event now carries an environment label (ddev, local, dev, staging, production, or `?`) in place of the old production flag. The weekly ping also says whether the site appears to run under the Drupal CMS launcher app. The `user_login` event, which sent a hashed user ID, is gone. Recipe and site template names are now sent only if they are on a fixed allowlist. Anything else is reported as `?`. Installs from the command line also record whether the site template was named explicitly. A new `DRUPAL_CMS_TELEMETRY` environment variable (`0` or `1`) is applied when the helper module is installed. The telemetry documentation was updated to match.

## Impact

Affects site owners.

- **Config change:** New `DRUPAL_CMS_TELEMETRY` environment variable (0 or 1) sets the telemetry status when `drupal_cms_helper` is installed. Telemetry is still stored per environment.

## Technical details

`TelemetryManager::log()` now sets an `environment` property, replacing `is_production`. It comes from the `drupal-environment` library, and only when `Environment` is autoloadable. Local environments report `ddev` or `local`. Otherwise the order is `dev`, `staging`, `production`, then `?`.

`TelemetryHooks` drops the `user_login` hook and the `Telemetry::Login` case. The weekly ping adds a `launcher` boolean. It is true when the root `composer.json` `extra` has a `drupal-launcher` key and `PHP_SAPI === 'cli-server'`. `ProjectResolver::readPackageInfo()` now returns `mixed` so it can read `extra`. The code component insert hook now skips events during install and config sync.

`RecipeSubscriber::onApply()` no longer reads the recipe's `Custom` type or the `extra.drupal_cms.no_telemetry` flag. Both are replaced by `isReportable()`, which matches the recipe directory name against the new `Telemetry::SITE_TEMPLATES`, `CONTRIB_RECIPES` and `CORE_RECIPES` constants (a trailing `*` is a prefix match). Names that don't match are sent as `?`. Recipes applied while installing from a site template are no longer logged. For `Site` recipes during install, the event includes `cli`. When run from the CLI, it also includes `cli_specified`, true if the recipe path appears in `argv`. `Telemetry::CUSTOM_EXTENSION` is renamed `CUSTOM_MODULE`, since only modules can now be custom. The `DRUPAL_CMS_TELEMETRY` handling moved from the recipe subscriber into `drupal_cms_helper_install()`. The recipe analysis output code was also reorganised. The project template `composer.json` now runs `post-update-cmd` on `post-install-cmd` too.
