## Summary

Drupal CMS now enables Drupal core's filename sanitization for whitespace by default. Previously, uploading a file with spaces in its name (e.g. "my photo.jpg") left the spaces intact, which can cause SEO, readability, and URL-compatibility issues. Sites built with Drupal CMS's foundational recipe now automatically replace whitespace in uploaded filenames, without any manual configuration.

## Impact

Affects site owners.

- **Config change:** Drupal CMS's base recipe (`drupal_cms_site_template_base`, formerly `drupal_cms_content_type_base`) now sets `file.settings:filename_sanitization.replace_whitespace` to `true`, so newly uploaded file names have spaces replaced with hyphens by default.

## Technical details

Drupal core's file module has long supported filename sanitization via `file.settings:filename_sanitization`, with independent toggles for `transliterate`, `replace_whitespace`, `replace_non_alphanumeric`, `deduplicate_separators`, and `lowercase` (all `false` by default). Drupal CMS's base recipe now applies a `simpleConfigUpdate` action on `file.settings` that flips only `filename_sanitization.replace_whitespace` to `true`; the other sanitization options (transliteration of accented characters, non-alphanumeric replacement, lowercasing) remain off.

The setting currently lives in `recipes/drupal_cms_site_template_base/recipe.yml`, after that recipe absorbed the former `drupal_cms_content_type_base` recipe (where the setting originated) in a later reorganization. Because recipes apply configuration only at recipe-application time, this affects new sites (or existing sites that reapply the recipe); it does not retroactively rename already-uploaded files.
