## Summary

Applying a recipe that installs two or more modules providing components, where each module's recipe uses the `setComponentTree` config action, no longer fails for the second module. Previously this crashed with an `AssertionError`, though applying the same recipes in separate runs worked.

## Impact

No upgrade or configuration changes required.

## Technical details

`SetComponentTree::setComponentVersions()` guarded `generateComponents()` with a `static $generated` flag, so Canvas components were generated only once per request. Components from a module installed later in the same recipe run did not exist when its tree was processed, and the `assert($component instanceof ComponentInterface)` check failed. The issue proposed regenerating only when a component is missing. The merged change instead removes the static flag, so `componentSourceManager->generateComponents()` runs on every call to `setComponentVersions()`. The fix is in the `drupal_cms_helper` module.
