## Summary

The Drupal CMS web installer showed 'Access denied: The installation can only be continued in the browser session that started it' after choosing a site template and clicking Next on Drupal core 11.4.13. This came from the session check core added in SA-CORE-2026-017. The Drupal CMS installer profile now works around it, so fresh installs on patched core complete normally.

## Impact

No upgrade or configuration changes required.

## Technical details

Core stores an `install_session_token` in the session so only one browser can continue the installer. In `drupal_cms_installer_install_profile()`, the token had not yet been saved when modules were installed. The module install rebuilds the container, which discards unsaved session data and gives the request a new session object. The fix reads the token via `Drupal::request()->getSession()->get('install_session_token')` before `ModuleInstallerInterface::install()`. After `install_install_profile()` it sets the token back on the fresh session object, if one was present. The change is in the Drupal CMS installer profile code. The code comments point to `install_bootstrap_full()` and `DrupalKernel::initializeContainer()`.
