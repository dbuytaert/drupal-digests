# #3591507: Add a hard opt-out for telemetry via settings.php

## Summary

Drupal CMS now has a hard telemetry opt-out in `settings.php`. Setting `$settings['drupal_cms_telemetry'] = FALSE;` turns usage data sharing off for every environment that uses that file. The setting overrides the state value, the Site information checkbox, Drush and the install-time `DRUPAL_CMS_TELEMETRY` environment variable, so an admin can no longer turn it back on. The Site information checkbox is shown disabled and unchecked, with a note that telemetry has been disabled in settings.php. Without the setting, behaviour is unchanged.

## Impact

Affects site owners.

- **Config change:** New optional `$settings['drupal_cms_telemetry']` in settings.php; when `FALSE`, telemetry is always off.

## Technical details

The `drupal_cms_helper` module's `TelemetryManager` gets a `KILL_SWITCH` constant (same value as `QUEUE_NAME`, `drupal_cms_telemetry`) and a static `isDisabled()` method, which returns `TRUE` only when `Settings::get()` for that key is strictly `FALSE`. `TelemetryManager::status()` checks it first and returns `FALSE` before reading or writing state, so a call like `status(TRUE)` cannot re-enable telemetry. Other code that asks `status()` whether telemetry is on sees `FALSE`.

In `TelemetryHooks`, the Site information form alter marks the `telemetry` checkbox `#disabled` and replaces the description with "Telemetry has been disabled in settings.php." The usual description and the `saveTelemetrySetting` submit handler are only added when the kill switch is not set. The user guide page `docs/src/updates/telemetry.md` documents the setting. Tests: a kernel test, `testSettingsKillSwitch`, and a functional check in `TelemetryOptOutTest` that the checkbox is disabled.

The diff has no code that explicitly clears an existing queue when the setting is present, so the issue's "clear the queue" item is not verified here. The issue's open question about showing this on the Status report was not addressed in the diff.

## Upgrade

To opt out across all environments, add this to `settings.php`:

```php
$settings['drupal_cms_telemetry'] = FALSE;
```
