## Summary

When a Drupal CMS site has opted in to telemetry, its first ping now also says which official project template it was created from: `drupal/cms` or `drupal/cms_cpanel`. The goal stated in the issue is to learn whether anyone uses the cPanel template. Sites that opt out send nothing. Projects with any other package name send no extra value.

## Impact

No upgrade or configuration changes required.

## Technical details

The change lives in `TelemetryHooks::cron()` in `drupal_cms_helper`. On the first ping, when the stored `drupal_cms_telemetry.ping` state value is 0, the event properties are `opt_in => TRUE`. The code now also reads the root package name with `InstalledVersions::getRootPackage()`. If the name is `drupal/cms` or `drupal/cms_cpanel`, it is added to the event properties as `project_name`. Any other root package name is not sent, so custom projects are not identified. The docs page `docs/src/updates/telemetry.md` lists this under the "Every 30 days" ping row. I could not find a fix diff or commit for this issue, so the description is based on the current repository code and docs, not on a reviewed patch. The issue body asks for a `template` key, but the code I read uses `project_name`. Telemetry classes are marked `@internal`, so there is no public API change.
