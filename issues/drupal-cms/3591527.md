## Summary

On fresh Drupal CMS installs using the Blank or Starter template, two Navigation module components (`navigation.title` and `navigation.message`) stayed enabled and appeared in the Canvas component library, even though they are only meant for the administrative UI. The base site template now disables both. Only new installs are affected; existing sites keep both components enabled.

## Impact

Affects site owners.

- **Config change:** Recipe action `?canvas.component.sdc.navigation.title` replaced by wildcard `canvas.component.sdc.navigation.*` in drupal_cms_site_template_base.

## Technical details

The base recipe had `?canvas.component.sdc.navigation.title`, but the component doesn't exist when the recipe's config action runs, so the `?` made it skip. Canvas creates the SDC components later, during content import (`RecipeSubscriber::ensureComponentsExist()`), enabled by default. `navigation.message` had no line at all. Per the issue, Canvas re-runs the recipe's component actions after apply (`RecipeSubscriber::onApply()`) but only for names starting with `canvas.component.`, so the `?` line was never re-run, and removing the `?` alone failed the install because the entity did not exist.

The fix replaces the line in the recipe's config actions with the wildcard `canvas.component.sdc.navigation.*` with `disable: []`. A wildcard may match nothing on the first pass, and Canvas's re-run then disables both components once they exist. `BasicFunctionalityTest` now loads all `sdc` components with provider `navigation` and asserts each is disabled.

## Upgrade

Existing sites are not changed. To hide the components on an existing site, disable `canvas.component.sdc.navigation.title` and `canvas.component.sdc.navigation.message` in the Canvas component settings.
