# #3591504: Telemetry checkbox prevents Basic site settings from being saved

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591504](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591504) · 1 contributor · 3 comments

## Summary

In Drupal CMS, the telemetry opt-in checkbox added to the Basic site settings form (`/admin/config/system/site-information`) broke saving of that form. Changes to the site name, slogan, email, front page and 403/404 pages were discarded, the page reloaded with the old values, and no confirmation message appeared. Only the telemetry checkbox was stored. The fix makes the form save normally again, together with the telemetry setting. The issue reports it on `drupal_cms_helper` 2.2.5.

## Impact

No upgrade or configuration changes required.

## Technical details

In `drupal_cms_helper/src/Hook/TelemetryHooks.php`, `alterSiteInformationForm()` attached `saveTelemetrySetting` to the Save button's `#submit`. When the triggering button defines its own `#submit`, Form API runs only those handlers and skips the form-level ones, so `SiteInformationForm::submitForm()` never ran and `system.site` was never written. The handler is now added to the form-level `#submit` (`$form['#submit'][] = [$this, 'saveTelemetrySetting'];`), so it runs after the form's own submit handler. The issue notes the bug is hidden when the form is submitted programmatically without the button as the triggering element, which is likely why existing tests missed it. The issue lists a functional test that saves the form through the UI as a remaining task. I did not see one in the repo and could not confirm it was added. No diff was available to me, so the fix is verified only against the current file, which shows the form-level line.

## Upgrade

Update `drupal_cms_helper` to a release containing the fix. Any site information changes made through the form on affected versions were not saved and need to be re-entered.
