# #3591495: Telemetry: switch from opt-in to opt-out

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591495](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591495) · 1 contributor · 4 comments

## Summary

Drupal CMS anonymous usage telemetry is now opt-out instead of opt-in. Sites send data by default, and the non-modal "opt in" dialog that appeared on admin pages is gone. Site owners can turn telemetry off with the "Send anonymous usage data" checkbox on the site information form, which is now checked by default. The telemetry documentation page was updated to say that data goes only from the web server to Amplitude, that no browser, cookies or local storage are involved, and that the hashed user ID is also salted. The issue body says legal advice from LegalWeb found the data collection outside GDPR scope, which is the stated reason for dropping opt-in.

## Impact

Affects site owners.

- **Config change:** Telemetry status now defaults to enabled when the `drupal_cms_telemetry` state key is unset (previously unset meant no data was sent until the user opted in).

## Technical details

`TelemetryManager::status()` now returns `bool` instead of `?bool`, and reads the state with a default of `TRUE`: `$this->state->get('drupal_cms_telemetry', TRUE)`. When a value is passed in, it returns that value instead of `NULL`. Disabling still deletes the queue. `sendAll()` still skips test, preview and CI environments, but the comment about requiring explicit opt-in was removed.

The opt-in UI was deleted: `TelemetryOptInForm`, `js/telemetry.js`, `css/telemetry.css`, the `telemetry` library in `drupal_cms_helper.libraries.yml`, `TelemetryHooks::addOptInDialog()` (`hook_page_bottom`), and the `gin_ignore_sticky_form_actions` hook that supported the dialog. The `AdminContext`, `AccountInterface` and `FormBuilderInterface` constructor arguments of `TelemetryHooks` were removed. The settings checkbox on the site information form stays and now uses `$this->telemetry->status()` as its default. The functional test `TelemetryOptInTest` was removed and `InteractiveInstallTest` was adjusted to look for the `SiteTemplateInstall` event in the queue, since other events may now also be queued. The docs in `docs/src/updates/telemetry.md` were updated as described in the summary.

## Upgrade

Site owners who do not want telemetry should uncheck "Send anonymous usage data" on the site information form (the setting is stored per environment in state). Custom code that calls `TelemetryManager::status()` should no longer expect `NULL`. It always receives a boolean.
