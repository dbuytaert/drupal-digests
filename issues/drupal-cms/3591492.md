# #3591492: drupal_cms_site_template_base 2.2.3 requires Tagify 2, so 11 site templates of the official list cannot be installed

- **Project:** Drupal CMS
- **Type:** Normal unknown (0)
- **Status:** Fixed
- **Discussion:** [#3591492](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591492) · 1 contributor · 3 comments

## Summary

Drupal CMS 2.2.3 could not install eleven site templates from the official list (Archimedes, CareSphere, Convene, Convivial Gov, Goodwell, Healthcare, Hourglass Corporate, Local, Provus EDU, Pulse, Summit). The installer stopped with "An error occurred" as soon as one was chosen. The cause was that the base recipe required Tagify 2 while those templates still require Tagify 1.2. The issue proposes allowing both major versions again, and a 2.2.4 release.

## Impact

Affects site owners.

- **Requirements:** `drupal_cms_site_template_base` `drupal/tagify` constraint proposed as `^1.2.52 || ^2.0.4` instead of `^2.0.4`.

## Technical details

[#3591486](https://www.drupal.org/node/3591486) changed `drupal/tagify` in `recipes/drupal_cms_site_template_base/composer.json` from `^1.2` to `^2.0.4`. That excluded Tagify 1.2, which the eleven templates still require in their latest releases. Composer's message was misleading: it blamed security advisories on Tagify 1.2.x, but the same request still failed with the advisory block turned off. The real conflict was the base recipe's `^2.0.4`. SA-CONTRIB-2026-043 covers Tagify `<1.2.52`, so 1.2.52 and later are not affected.

The proposed constraint is `"drupal/tagify": "^1.2.52 || ^2.0.4"`. The issue says `tagify_user_list` and its settings also exist in Tagify 1.2.55. It also says the templates only use the `tagify_entity_reference_autocomplete_widget` and `tagify_select_widget` widgets, which both major versions provide. The lower bound is meant to be dropped once the templates allow Tagify 2. The issue also suggests a CI check that requires every template in `site-templates.yml` against the current base recipe. I could not confirm the final landed constraint: no diff was linked and the default branch clone still showed `^2.0.4`.

## Upgrade

Until a release with the widened constraint is available, the issue reporter's workaround is to keep the base recipe at 2.2.2. A site that needs Tagify 2 together with one of the affected templates has to wait for that template to allow `^2.0`.
