# #3591466: Installing in another language does not translate shipped configuration: the installer dropped core's config translation step accidentally

- **Project:** Drupal CMS
- **Type:** Critical bug report
- **Status:** Fixed
- **Discussion:** [#3591466](https://git.drupalcode.org/project/drupal_cms/-/work_items/3591466) · 1 contributor · 6 comments

## Summary

Installing Drupal CMS in a language other than English silently stopped translating the configuration that ships with modules and site templates (things like view titles). A recent optimization to speed up installation accidentally dropped the step that actually applies downloaded translations to configuration, even though the language itself was still set up correctly. This fix restores that step, so installing in German or any other supported language now produces a fully translated site again, as it did before the regression.

## Impact

No upgrade or configuration changes required.

## Technical details

The regression was introduced when `drupal_cms_installer_finish_translations()` (added for [#3591422](https://www.drupal.org/node/3591422) to lock configuration language and speed up install) replaced core's `install_finish_translations()` batch. That change kept the langcode-locking batch from `ConfigLanguageLockBatch` but dropped the actual translation-rewrite batch that core's original function ran via `Locale\LocaleConfigBatch`. As a result, `.po` translations were still downloaded and language settings were locked, but the translated strings were never written into shipped configuration, leaving `locales_location` empty for configuration and shipped config, such as the content view's label, untranslated.

The fix adds back a call to `LocaleConfigBatch::buildBatch()` after the config language lock batch in `drupal_cms_installer.profile`, so the sequence is now: download translation files, lock/rewrite config langcodes via `ConfigLanguageLockBatch`, then rewrite config content with translations via `LocaleConfigBatch`, mirroring core's original two-step process but with the langcode-locking behavior config_language_lock provides. Test coverage was added to `TranslatedInstallTest` asserting that the `content` view's label is translated after a German install, guarding against this regression recurring. The workaround is expected to be removed once core issue [#3337864](https://www.drupal.org/node/3337864) is resolved.
