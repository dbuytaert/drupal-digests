# #3591482: Language-neutral content ("und") counts as a template language – Summit is installed in "und" and every page fails

## Summary

Installing Drupal CMS in a language other than English (e.g. German) with the Summit site template previously broke every page with a 500 error. The installer mistakenly treated "language not specified" (`und`) content as if it were a real language, which caused the site's default language configuration to be set to the invalid value `und` instead of the language actually chosen during installation. This made the Event Horizon theme crash immediately because it could not construct a number formatter for a non-existent `und` locale. The fix ignores these internal placeholder langcodes when the installer inspects a template's content, so the language picked during installation is respected.

- **Config change:** Fixes a bug where `system.site:default_langcode` and `config_language_lock.locked_langcode` could be incorrectly set to `und` (language-neutral) instead of the language chosen in the installer.

## Technical details

`SiteTemplate::getLangcodesFromContent()` builds the list of langcodes present in a recipe's shipped content by scanning each content item's `_meta.default_langcode` and its `translations` keys. Summit ships 53 entities with `default_langcode: en` and 3 with no langcode at all, which Drupal represents internally as `LanguageInterface::LANGCODE_NOT_SPECIFIED` (`und`). Because that method previously returned `['en', 'und']`, `detectLanguages()` saw two distinct langcodes and concluded the recipe is genuinely multilingual, triggering `detectDefaultLangcode()`, which simply returns the first `default_langcode` it encounters in content order. That value happened to be `und`, which got written into `system.site:default_langcode` and `config_language_lock.locked_langcode`, overriding the language actually selected in the installer.

The fix filters `LanguageInterface::LANGCODE_NOT_SPECIFIED` (`und`) and `LANGCODE_NOT_APPLICABLE` (`zxx`) out of the langcode list via `array_diff()` before deduplicating with `array_unique()`. With those placeholders removed, Summit's content now resolves to a single real langcode (`en`), so `detectLanguages()` treats it as monolingual and returns an empty array instead of forcing a default language, letting the installer's own language choice stand. `detectDefaultLangcode()` itself is unchanged; it no longer gets invoked in this scenario because the content no longer looks multilingual.</technical>
