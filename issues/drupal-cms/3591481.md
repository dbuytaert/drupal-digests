# #3591481: Web installer fails on Apache with mod_php: Composer needs HOME or COMPOSER_HOME

- **Project:** Drupal CMS

## Summary

The Drupal CMS web installer no longer fails at the first batch step on Apache with mod_php. Previously, after you chose a site template, Composer aborted with "The HOME or COMPOSER_HOME environment variable must be set", because Apache with mod_php sets neither. The installer now supplies a Composer home itself when none is set, so no Apache `envvars` or `PassEnv` workaround is needed. PHP-FPM setups were already working.

## Impact

No upgrade or configuration changes required.

## Technical details

`ComposerExecutor` (in `drupal_cms_installer`) now has a public static `execute(callable $callback)` that wraps a callback. If `COMPOSER_HOME` is empty, it sets it through `Composer\Util\Platform::putEnv()` to `<project root>/.composer`, and sets `COMPOSER_HTACCESS_PROTECT=0` so Composer does not create that directory. In a `finally` block it clears both variables again. The code that did this already lived inline in `SiteTemplate::findAll()` (see [#3591473](https://www.drupal.org/node/3591473)) and was moved here. The issue's proposed resolution suggested a directory under the temporary directory, but the merged code uses the project root.

The old `ComposerExecutor::execute(string ...$arguments)` was renamed to `run()` and now runs the Process inside that wrapper. A new `getProjectRoot()` returns the real path of the root package install path. Callers in `drupal_cms_installer.profile` (`_drupal_cms_installer_require_recipe()`) and `SiteTemplateForm` were updated to `run()` and `getProjectRoot()`. `Platform::putEnv()` sets both the process environment and `$_SERVER`, which is what Symfony Process needs to pass the variable to the child process.
