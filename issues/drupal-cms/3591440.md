# #3591440: Fix installer page backgrounds and add interstitial at the end

- **Project:** Drupal CMS
- **Type:** Normal feature request
- **Status:** Fixed

## Summary

The Drupal CMS installer used to leave the final progress bar sitting at 100% for several seconds (uninstalling the install profile, rebuilding the router, flushing caches) with no feedback, which looked like the install had stalled or that the last visible step (often translation import) was slow. A new "Your site is almost ready" holding screen with a spinner now displays during that final cleanup so the wait reads as intentional. At the same time, the decorative background artwork that previously only appeared on a few installer forms has been extended to the batch/progress screens (including the module installation step, which now uses a previously unused "recipes" pattern), so the whole install experience looks visually consistent instead of switching between patterned forms and bare white progress pages.

## Impact

No upgrade or configuration changes required.

## Technical details

In `drupal_cms_installer.profile`, `drupal_cms_installer_install_tasks_alter()` now inserts a new install task, `drupal_cms_installer_almost_ready`, immediately before `install_finished` (using the module's existing `$insert_before` helper). That task renders a holding page (`cms-installer__finishing` markup with heading, subhead, and CSS spinner) and attaches a `Refresh` meta tag pointing back to `install.php` with the original install parameters, so the page displays for one render cycle and then the browser auto-refreshes into the real `install_finished` step.

The per-step decorative artwork was refactored from several separate `hook_form_alter()` implementations (each attaching its own `#theme => step_svg` element with a `#weight`) into a single lookup in `drupal_cms_installer_theme_preprocess_install_page()`. It reads `$install_state['active_task']` and maps it via a `match` expression to a pattern id (`settings`, `name`, `account`, `recipes`, or none), exposing it as the `pattern` template variable. `install-page.html.twig` prints `{{ pattern }}` inside `<main>` after `page.content`, so the artwork now renders consistently across forms and batch/progress pages alike, instead of only on individual forms. New CSS (`.cms-installer__finishing`, `.cms-installer__finishing-spinner`, and a `cms-installer-finishing` keyframe animation with a `prefers-reduced-motion` fallback) styles the new interstitial, and `.cms-installer__main .progress` is capped at `720px` so the progress bar aligns with the body copy above it now that batch screens carry the same artwork.</technical>
