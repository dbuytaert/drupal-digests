## Summary

As part of ongoing work to remove the Toolbar module from Drupal core (into contrib), the CSS overrides that let Claro or Default Admin restyle the toolbar when they are the admin theme but not the active front-end theme have been moved out of those two themes and into the Toolbar module itself. There is no visible change for site visitors or administrators; the toolbar looks and behaves the same, only the code that swaps in the theme-specific stylesheets has been relocated and consolidated.

## Impact

Affects front-end developers.

- **Theme change:** Claro and Default Admin no longer implement `hook_library_info_alter()` or declare `libraries-override` entries for Toolbar; the override CSS moved from `core/themes/claro/css/...` and `core/themes/default_admin/css/...` to `core/modules/toolbar/css/claro/...` and `core/modules/toolbar/css/default_admin/...`, and `Toolbar\ToolbarThemeHooks::libraryInfoAlter()` now performs the swap for both themes.

## Technical details

Previously, Claro's `ThemeHooks::libraryInfoAlter()` and Default Admin's `ThemeHooks::libraryInfoAlter()` each implemented `hook_library_info_alter()`, reading a `libraries-override` block declared in their own `.info.yml` (`toolbar/toolbar` and `toolbar/toolbar.menu`) via `ThemeHandlerInterface::listInfo()` and rewriting the `toolbar` library's CSS paths accordingly. That logic and the `.info.yml` override declarations were both removed from `claro.info.yml`, `default_admin.info.yml`, and `default_admin`'s `ThemeHooks` (which also dropped its now-unused `ThemeHandlerInterface` dependency).

The replacement lives entirely in `Drupal\toolbar\Hook\ToolbarThemeHooks::libraryInfoAlter()`: it checks the configured admin theme (`system.theme:admin`) against the active theme, and for `claro` or `default_admin` applies a hardcoded `$overrides` map (component/theme/state CSS keyed per theme) instead of reading it from the theme's own info array. The corresponding CSS and pcss source files were physically moved from `core/themes/claro/css/...` and `core/themes/default_admin/css/...` into `core/modules/toolbar/css/claro/...` and `core/modules/toolbar/css/default_admin/...`, and `ToolbarClaroOverridesTest` was updated to assert the new paths.

One side effect surfaced in the issue thread: `core/scripts/css/compile.js` excludes icon `.pcss.css` files under `core/modules/*` from its pixels-to-rem conversion, but not files under `core/themes/*`. Since the icon stylesheets now live under `core/modules/toolbar/`, their compiled output switched from rem back to px (e.g. `text-indent: -624.9375rem` became `-9999px`, and the orientation-toggle button's `2.4375rem` width/height became `39px`); the rendered result is visually unchanged.</technical>
