## Summary

Claro, Drupal's default administration theme, is now formally deprecated in core. This follows the core team's consensus decision ([#3576460](https://www.drupal.org/node/3576460)) to eventually remove Claro from core and replace it. Existing sites using Claro are unaffected functionally for now, but should start planning to move to a replacement admin theme, since Claro is expected to be removed from core in a future release. Anyone who explicitly installs the theme, whether a site builder scripting a theme install or a developer's custom code, will start seeing a deprecation notice.

## Impact

Affects module maintainers.

- **Deprecation:** The Claro admin theme is marked `lifecycle: deprecated` in `claro.info.yml`; explicitly installing it (not merely relying on it as an existing dependency) now triggers an `E_USER_DEPRECATED` notice.

## Technical details

The change adds `lifecycle: deprecated` and `lifecycle_link: https://www.drupal.org/node/3223395#s-claro` to `claro.info.yml`, hooking into core's `ExtensionLifecycle` deprecation machinery. As a result, `ThemeInstaller::install()` now emits an `E_USER_DEPRECATED` notice ("The theme 'claro' is deprecated...") whenever Claro is explicitly requested for installation; themes pulled in only as a dependency of another theme are exempt from the notice.

Within Claro's own test suite, `MenuLinkDefaultFormTest` and `NodeTitleTest` both set `$defaultTheme = 'claro'`, which causes `BrowserTestBase` to install Claro during setup and thus trip the new deprecation notice, so both were annotated with `#[IgnoreDeprecations]`. Other core usages of Claro outside the theme itself were already migrated away by the prerequisite issue [#3621198](https://www.drupal.org/node/3621198) (Change remaining usages of Claro), which had to land in 11.x before this deprecation could be backported.

## Upgrade

If code or tests explicitly install Claro, expect a new deprecation notice:

```
The theme 'claro' is deprecated. See https://www.drupal.org/node/3223395#s-claro
```

Tests that intentionally keep using Claro as `$defaultTheme` should add `#[IgnoreDeprecations]`, as done here:

```php
#[Group('claro')]
#[IgnoreDeprecations]
#[RunTestsInSeparateProcesses]
class MenuLinkDefaultFormTest extends BrowserTestBase {
```

Longer term, sites and contributed modules that depend on Claro should begin planning a migration to a different admin theme ahead of its eventual removal from core.
