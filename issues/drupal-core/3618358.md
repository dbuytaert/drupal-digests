## Summary

This is a cleanup of Drupal core's locale (interface translation) subsystem: the last remaining procedural, underscore-prefixed helper functions used to rebuild and invalidate JavaScript translation files have been deprecated. Their logic has been moved into the existing `LocaleJs` service class. Site owners are not affected functionally; this only matters to developers or contributed modules that call these low-level functions directly.

## Impact

Affects module maintainers.

- **Deprecation:** Six `locale.module` underscore functions (`_locale_refresh_translations()`, `_locale_refresh_configuration()`, `_locale_strip_quotes()`, `_locale_parse_js_file()`, `_locale_invalidate_js()`, `_locale_rebuild_js()`) are deprecated in Drupal 11.5 for removal in Drupal 13.0; most have replacements on the `Drupal\locale\LocaleJs` service.

## Technical details

The six functions' bodies were moved onto `Drupal\locale\LocaleJs` as methods (`refreshTranslations()`, `parseJsFile()`, `invalidate()`, `rebuild()`), or dropped with no replacement (`_locale_refresh_configuration()`, `_locale_strip_quotes()`, both folded inline or made a private `stripQuotes()` helper). The old functions now just emit an `E_USER_DEPRECATED` trigger_error and delegate to `\Drupal::service(LocaleJs::class)`. `parseJsFile()` and `rebuild()` remain public (rather than the `protected` originally proposed in the issue summary) but are marked `@internal`, because tests call them directly; only `stripQuotes()` became `protected`.

To support this, `LocaleJs`'s constructor gained several new dependencies (`StringStorageInterface`, `LocaleLanguages`, `LanguageManagerInterface`, `PluralFormulaInterface`, `FileSystemInterface`, a lazy logger closure, and `EventDispatcherInterface`), and `LocaleFileManager`'s constructor gained an optional `?LocaleJs $localeJs` parameter; omitting it triggers its own deprecation notice and falls back to `\Drupal::service(LocaleJs::class)`. Call sites in `locale.module`, `TranslateEditForm`, and locale's hook implementations were updated to call the service directly instead of the deprecated functions. As a drive-by fix, the `@see` link on the already-deprecated `locale_string_is_safe()` was corrected to point to the right change record.

## Upgrade

Replace direct calls to the deprecated functions with the `LocaleJs` service:

```php
// Before:
_locale_refresh_translations($langcodes, $lids);
_locale_invalidate_js($langcode);
_locale_parse_js_file($filepath);
_locale_rebuild_js($langcode);

// After:
\Drupal::service(\Drupal\locale\LocaleJs::class)->refreshTranslations($langcodes, $lids);
\Drupal::service(\Drupal\locale\LocaleJs::class)->invalidate($langcode);
\Drupal::service(\Drupal\locale\LocaleJs::class)->parseJsFile($filepath);
\Drupal::service(\Drupal\locale\LocaleJs::class)->rebuild($langcode);
```

`_locale_refresh_configuration()` and `_locale_strip_quotes()` have no replacement; inline the equivalent logic if still needed. Custom services extending or instantiating `LocaleFileManager` directly should pass a `LocaleJs` instance as the new constructor argument to avoid the deprecation notice.
