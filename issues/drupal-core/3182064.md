## Summary

Exposed numeric and date range filters (the "between" operator, showing two input fields) previously always labeled their fields "Min" and "Max", which made little sense for a date range like "Authored on". Views now lets you configure these labels per filter, under "Minimum value label" and "Maximum value label" in the exposed filter settings. New filters default to "Minimum"/"Maximum" for numeric fields and "Start date"/"End date" for date fields; existing exposed filters keep showing "Min"/"Max" after upgrade so nothing changes visually unless you opt in.

## Impact

Affects site owners.

- **Config change:** Views numeric filter `expose` config gains `min_label` and `max_label` keys (defaults `Minimum`/`Maximum`, or `Start date`/`End date` for date filters); `views_post_update_filter_min_max_labels()` back-fills existing exposed filters with the legacy `Min`/`Max` labels so upgrading sites keep their current display.

## Technical details

The change lives in `NumericFilter` and the date filter that extends it (`views.filter.numeric`/date schema in `views.schema.yml`). `defineOptions()` and `defaultExposeOptions()` add `min_label`/`max_label` to the `expose` array, and `buildExposeForm()` adds the two textfields (visible only when a two-value operator like "between" is selected, via the same `#states` used for the placeholder fields). `valueForm()` now sets `$form['value']['min']['#title']`/`['max']['#title']` from `$this->options['expose']['min_label']`/`max_label` instead of the hardcoded `t('Min')`/`t('Max')`.

Because this adds new config keys, `ViewsConfigUpdater::needsMinMaxLabelUpdate()`/`processMinMaxLabelUpdate()` and the `views_post_update_filter_min_max_labels()` post-update hook detect filters that already have `min_placeholder` (i.e. derive from `NumericFilter`) but lack `min_label`, and set both to the literal string `Min`/`Max` so upgraded sites render exactly as before. New views created after this change get the friendlier defaults instead.
