## Summary

Drupal core's experimental "Default Admin" theme (successor to the Gin admin theme merge) shipped with several Twig template overrides that were never actually reachable: `menu-region--top.html.twig`, `menu-region--middle.html.twig`, and `menu-region--bottom.html.twig` had no matching theme hook to attach to and were removed. Two other templates, `page--clone.html.twig` and `page--group.html.twig`, were reachable, but only via Drupal's automatic page template suggestions for paths that core itself doesn't provide: they exist to support the contrib Group and Quick Node Clone modules' `/group/*` and `*/clone` pages. Sites that use Default Admin together with either of those contrib modules will now see those pages rendered with the normal page template instead of the node-edit-style layout Default Admin previously applied. A sixth template, `input--submit--paragraph-action.html.twig`, only overrode a render suggestion generated by the contrib Paragraphs module and is also removed. No core-only site (not running Group, Quick Node Clone, or Paragraphs) will notice any change.

## Impact

No upgrade or configuration changes required.

## Technical details

Investigation (in comments) traced each template's theme hook registration. `default_admin` declares no `hook_theme()` of its own, and its `hook_theme_registry_alter()` only repoints the `toolbar` and `menu__toolbar` hooks at `templates/navigation`; the Navigation module's `hook_theme()` registers `top_bar*`, `block__navigation`, `navigation_menu`, `navigation_content_top`, and `navigation__messages`, none of which is a `menu_region` base hook. With no base hook and no Twig `include`/`embed` referencing them anywhere in core, `menu-region--top.html.twig`, `menu-region--middle.html.twig`, and `menu-region--bottom.html.twig` could never render, and the commit (`41e2e84c`) deletes all three along with their containing directory logic.

`page--clone.html.twig` and `page--group.html.twig` are different: Drupal resolves page template suggestions from the URL alias/path pattern regardless of whether a hook is declared, so these were live for any site running the contrib Group or Quick Node Clone modules, which have `/group` and `*/clone` routes respectively. Both files were just one-line `{% extends '@default_admin/page/page--node.html.twig' %}` wrappers. Since core doesn't ship those routes itself, the templates were judged out of scope for core and removed, leaving those contrib integrations without special-cased layout support in Default Admin. `input--submit--paragraph-action.html.twig` was likewise a one-off override of an input suggestion generated only by the contrib Paragraphs module and was folded into the same cleanup. A related follow-up, [#3621155](https://www.drupal.org/node/3621155), was opened to remove contrib-specific CSS selectors (Paragraphs, Smart Date, Inline Entity Form, Views Bulk Operations) left over in the same theme.
