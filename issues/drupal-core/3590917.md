## Summary

Drupal core's PHPUnit test base classes, `UnitTestCase`, `KernelTestBase`, `BrowserTestBase`, and `Drupal\BuildTests\Framework\BuildTestBase`, now all extend a single common ancestor, `Drupal\Tests\DrupalTestCase`, instead of each separately extending `PHPUnit\Framework\TestCase` and using `DrupalTestCaseTrait`. For the vast majority of unit, kernel, functional, functional-javascript, and build tests in contrib and custom code, which extend one of these existing base classes, nothing changes. The change mainly matters if you write PHPUnit tests for a `Drupal\Component` library that extend `PHPUnit\Framework\TestCase` directly (as is required, since Component code must not depend on Core code): if such a test wants Drupal's PHPUnit extensions, it now has to import `DrupalTestCaseTrait` explicitly rather than getting it automatically.

## Impact

Affects module maintainers.

- **API change:** The already-deprecated `getDrupalRoot()` method moved from `DrupalTestCaseTrait` to `DrupalTestCase` and lost its `static` modifier, becoming a regular instance method.
- **New API:** New abstract `Drupal\Tests\DrupalTestCase` class is the common ancestor of `UnitTestCase`, `KernelTestBase`, `BrowserTestBase` and `Drupal\BuildTests\Framework\BuildTestBase`.

## Technical details

Previously, `UnitTestCase`, `KernelTestBase`, `BrowserTestBase`, and `BuildTestBase` each independently extended `PHPUnit\Framework\TestCase` and separately used `DrupalTestCaseTrait` for shared behavior, most notably setting the `$root` property via a `#[Before(100)]`-tagged `setUpRoot()` hook and exposing the deprecated `getDrupalRoot()` accessor. The new `Drupal\Tests\DrupalTestCase` abstract class centralizes that: it extends `PHPUnit\Framework\TestCase`, uses `DrupalTestCaseTrait` once, and declares the `$root` property, `setUpRoot()`, and `getDrupalRoot()` itself. All four base classes now extend `DrupalTestCase` instead of `TestCase` directly, and dropped their own `use DrupalTestCaseTrait;` statements.

`DrupalTestCaseTrait` itself was trimmed down to the remaining cross-cutting helpers (such as registering the dumper CLI handler) and re-documented as something you only need to import directly when writing a `Drupal\Component` test that extends `PHPUnit\Framework\TestCase` and still wants Drupal's PHPUnit extensions. As part of moving `getDrupalRoot()` onto `DrupalTestCase`, it dropped the `static` modifier it had on the trait, since `$this->root` is an instance property.

## Upgrade

If you maintain a `Drupal\Component` PHPUnit test that extends `PHPUnit\Framework\TestCase` directly and relies on Drupal's PHPUnit extensions (previously available for free via `DrupalTestCaseTrait`), import the trait explicitly:

```php
use Drupal\Tests\DrupalTestCaseTrait;
use PHPUnit\Framework\TestCase;

class MyComponentTest extends TestCase {
  use DrupalTestCaseTrait;
}
```

Tests that already extend `UnitTestCase`, `KernelTestBase`, `BrowserTestBase`, or `BuildTestBase` require no changes.
