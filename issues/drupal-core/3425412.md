## Summary

Drupal core's static analysis now runs at PHPStan rule level 3 instead of level 1. Levels 2 and 3 add checks for unknown methods on any expression, PHPDoc validation, return types and types assigned to properties. Existing violations were added to the baseline file, so core's own checks keep passing. New code that violates these rules now fails the PHPStan job. Open merge requests that touch the baseline or add such violations will probably need a rebase and fixes. The change was committed to `main` and backported to 12.0.x.

## Impact

Affects site owners.

- **Requirements:** New dev dependency `jangregor/phpstan-prophecy` (^2.2, locked at 2.3.0) in core's `composer.json` require-dev.

## Technical details

`core/phpstan.neon.dist` changes `level: 1` to `level: 3`. It also drops the explicit `PHPStan\Rules\Classes\AccessPrivateConstantThroughStaticRule`, whose comment said it could go once the level reached 2. The explicit return-typehint rules stay, since their comment says they can go at level 6. `checkFunctionArgumentTypes: true` was already set, so the argument type checks that level 5 mainly adds were already active.

`jangregor/phpstan-prophecy` is added to `require-dev` (`composer.json` and the core `composer.json`) and `composer.lock` is updated. It lets PHPStan resolve Prophecy mocks to the types they mock. The issue says this avoids roughly 2k false positives in the baseline. `jangregor` is added to the cspell dictionary. The regenerated `core/.phpstan-baseline.php` was not in the diff I read. In the thread, the baseline at level 3 was measured at about 11,000 entries and 3.3 MB, against 1.7 MB at level 1.

The thread also compared levels 4 to 9. Level 5 adds little over level 4 because argument type checking is already on, and level 4 would add about 2,500 errors that can be cleaned up in minor releases. The release managers chose level 3. Their reasoning was that tightening typing contracts is a major-only change.

## Upgrade

Contrib and core developers who run core's PHPStan config should rebase open branches and regenerate the baseline if it conflicts. The CI job produces the regenerated baseline as a downloadable artifact. Code touched in a branch may now report level 2 and 3 errors. The new dev dependency is installed with:

```
composer require --dev jangregor/phpstan-prophecy
```

The level was settled late in the thread. Timing was also coordinated. The release managers held the change until the beta window so it would not disrupt other merge requests.
