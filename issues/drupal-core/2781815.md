## Summary

Previously, the User module defined two Views relationships, "Content authored" and "Representative node", that actually depend on the `node_field_data` table. These showed up in the Views UI even when the Node module was uninstalled, and using them produced SQL errors (missing `node_field_data` table) or a broken views admin page. The fix moves these relationship definitions out of the User module and into the Node module, so they only appear when Node is actually installed. Existing views on a site where Node is uninstalled that already use one of these relationships will show it as a "Broken/missing handler" after upgrading, rather than silently erroring.

## Impact

No upgrade or configuration changes required.

## Technical details

The `users_field_data.uid` "Content authored" relationship and the `uid_representative` "Representative node" relationship were previously registered by `user.module`'s Views data provider (`UserViewsData::getViewsData()`), even though both point at `node_field_data`. They are now registered instead by `Drupal\node\Hook\NodeViewsHooks::viewsDataAlter()`, a new `hook_views_data_alter()` implementation (ordered with `Order::First`) added to the Node module, which alters the `users_field_data` table's Views data to add the same relationship definitions. Since this is a `hook_views_data_alter()` rather than the base `hook_views_data()`, it only runs, and only adds the relationships, when `node.module` is enabled.

The corresponding kernel test, previously `Drupal\Tests\user\Kernel\Views\RelationshipRepresentativeNodeTest` using the `user_test_views` test module, was moved to `Drupal\Tests\node\Kernel\Views` and now uses a new `node_test_views` test module, keeping the test coverage with the code it now exercises.</technical>
