## Summary

Core's `system` library definitions no longer use per-file CSS weights. The five utility stylesheets in `system/base` (align, container-inline, clearfix, hidden, js) now sit in the `base` CSS group, which loads before `component`, so they still load early. Weights were also dropped from other system libraries. One fewer stylesheet file is aggregated in the standard performance test. Themes or modules that override or remove these files under the `component` group keep working, but with a deprecation message, until they switch to `base`. This is part of the effort to deprecate per-file weight in the libraries API ([#3467488](https://www.drupal.org/node/3467488)).

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** The `system/base` CSS files `align`, `container-inline`, `clearfix`, `hidden` and `js` (`css/components/*.module.css`) moved from the `component` group to the `base` group. Theme `libraries-override` entries should use `base` instead of `component`.
- **Deprecation:** The old `system/base` `component` locations of those five CSS files are deprecated via `moved_files` (deprecation_version 11.5.0, removed_version 13.0.0).

## Technical details

In `core/modules/system/system.libraries.yml`, `system/base` previously listed its CSS under `component` with `weight: -10` so it loaded early. It now lists them under `base` with no weight. A `moved_files` entry maps each old `component` path to the same file under `base`. It has `deprecation_version: 11.5.0`, `removed_version: 13.0.0` and a link to this issue. Existing overrides keyed on the old location are therefore still resolved, and they trigger deprecation messages.

The remaining `weight: -10` entries were removed from `system/maintenance` (kept in the `theme` group), `system/status.report` (kept in `component`) and `drupal.system.admin_compact` (kept in `theme`). The issue thread says the maintenance CSS stays in `theme` because theme files always load after module files, and the maintenance page styling is hard-coded in `preprocessMaintenancePage()`. A follow-up, [#3623221](https://www.drupal.org/node/3623221), was opened to deprecate the `system.maintenance` library.

Test fixtures were updated to match: a test module's `libraryInfoAlter()` now adds its CSS under `base`, and a `libraries-override` fixture for `system/base` now targets `base` for `css/components/js.module.css`. Performance test expectations were also changed for the stylesheet count. The change was committed to main and 12.0.x, and also backported to 11.x and 11.5.x.

## Upgrade

If a theme overrides or removes these files in `system/base`, change the group key from `component` to `base`:

```yaml
libraries-override:
  system/base:
    css:
      base:
        css/components/js.module.css: false
```

Using the old `component` key still works until 13.0.0, but it triggers a deprecation message.
