## Summary

Opening a modal dialog and closing it again very quickly (within about 20 milliseconds) could throw an uncaught JavaScript error, "cannot call methods on dialog prior to initialization; attempted to call method 'option'", because a scheduled dialog resize callback ran after the dialog had already been destroyed. This could interrupt other JavaScript on the page and was also causing intermittent failures in Drupal core's own JavaScript test suite. The fix ensures a resize that is still pending when a dialog closes is cancelled instead of running against a dialog that no longer exists.

## Impact

Affects module maintainers.

- **New API:** `Drupal.debounce()` now returns a function that has a `cancel()` method, letting callers abort a scheduled invocation that has not run yet.

## Technical details

The root cause was in `misc/dialog/dialog.ajax.js`: `Drupal.dialog.resetSize` is invoked via `Drupal.debounce` on window resize/scroll events, but the `dialog:beforeclose` handler only unbound those event listeners; it could not stop a resize call that had already been scheduled by `debounce`'s internal `setTimeout`. By the time that timeout fired, the dialog's DOM element (and its jQuery UI instance) had already been removed, so calling `.dialog('option', ...)` on it threw.

The fix has two parts. `misc/debounce.js`'s `Drupal.debounce` now returns a function that also carries a `cancel()` method, which clears the pending `timeout` so a scheduled call never runs. `dialog.ajax.js` stores the `autoResize` debounced function on the dialog element via `$element.data('drupalAutoResize', autoResize)` when the dialog opens, and its `dialog:beforeclose` handler now calls `$(e.target).data('drupalAutoResize')?.cancel()` before unbinding the resize/scroll handlers. As a defensive second layer, `resetSize()` also now bails out early if `event.data?.$element?.data('ui-dialog')` is falsy, i.e. the jQuery UI dialog instance is no longer present. Test coverage was added in `DialogTest` that opens a modal, triggers a resize, immediately closes the dialog, and asserts no JS errors are logged.

A change record ([#3619513](https://www.drupal.org/node/3619513), referenced in comments) documents the new `debounce().cancel()` API for other core and contrib code that debounces callbacks tied to DOM elements that may be removed.</technical>
