## Summary

This is a backport of the fix from [#3524971](https://www.drupal.org/node/3524971), which hardens Guzzle's `FileCookieJar` class against a known PHP object-injection "gadget chain" that could let an attacker who controls unserialized data force an arbitrary file write. That protection had only landed on the 11.x development branch; this issue brings the same shim to the 10.6.x, 11.3.x, and 11.4.x release branches, so sites running those core versions get the defense too. It also fixes a deprecation warning in the shim code that had already been committed to 11.x.

## Impact

Affects site owners.

- **Security:** The hardened `\GuzzleHttp\Cookie\FileCookieJar` shim that defends against a PHP object-injection file-write gadget chain (see #3524971) is now also shipped on the 10.6.x, 11.3.x, and 11.4.x branches, not just 11.x.

## Technical details

The fix adds `core/includes/guzzle_file_cookie_jar_shim.php` to the 10.6.x, 11.3.x, and 11.4.x branches, registered via each branch's `composer.json`/`composer.lock` autoload `files` list alongside `includes/bootstrap.inc`. The shim conditionally defines `\GuzzleHttp\Cookie\FileCookieJar` (only if the real Guzzle class hasn't already loaded) as a verbatim backport of the hardened Guzzle 8.0 implementation: it adds a private `$autoSave` flag that `__wakeup()` sets to `false`, so an instance reconstructed from attacker-controlled serialized data no longer triggers a file write in `__destruct()`.

On all four branches (including 11.x, where the shim already existed), `save()` and `load()` were changed to call PHP's native `json_encode()`/`json_decode()` with `JSON_THROW_ON_ERROR` instead of `GuzzleHttp\Utils::jsonEncode()`/`jsonDecode()`. Those `Utils` methods are deprecated as of guzzlehttp/guzzle 7.15 and removed in 8.0; the deprecation only surfaced once Guzzle was upgraded past the version core had previously been pinned to (7.12.1). Each branch also got a corresponding `FileCookieJarShimTest` in `core/tests/Drupal/Tests/Component/Cookie/`, adapted to each branch's PHPUnit annotation style (`@group` vs. the `#[Group]` attribute).</technical>
