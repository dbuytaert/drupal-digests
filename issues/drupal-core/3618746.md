## Summary

This is a follow-up cleanup to [#3611762](https://www.drupal.org/node/3611762) that finishes moving Toolbar-only code out of the User, Contextual, and Announcements modules into the Toolbar module. Nothing changes for site visitors or content editors: the toolbar looks and behaves the same. The practical effect is for developers and themers: a handful of PHP classes, services, and CSS/JS libraries that only existed to support the admin toolbar have moved house and been renamed, without a deprecated alias, so any code pointing at the old names will break.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** The `user/drupal.user.icons` and `contextual/drupal.contextual-toolbar` libraries are removed; their toolbar icon CSS now ships in Toolbar's own icon libraries (`toolbar/toolbar.contextual`, plus per-theme icon stylesheets).
- **API change:** `Drupal\user\ToolbarLinkBuilder` and the `user.toolbar_link_builder` service moved to `Drupal\toolbar\UserToolbarLinkBuilder` / `toolbar.user_link_builder` with no deprecated alias.

## Technical details

The user-facing piece: `Drupal\user\ToolbarLinkBuilder` and its `user.toolbar_link_builder` service become `Drupal\toolbar\UserToolbarLinkBuilder` and `toolbar.user_link_builder`. This class is not marked `@internal`, so this is a real, unshimmed API rename. `ToolbarHooks::userToolbar()` and `announcementsFeedToolbar()` in `core/modules/toolbar/src/Hook/ToolbarHooks.php` now reference the new lazy builder callbacks (`toolbar.user_link_builder:renderDisplayName`, `toolbar.announcements_feed_link_builder:renderAnnouncements`) and use the injected `$this->currentUser` instead of `\Drupal::currentUser()`.

The announcements piece (`Drupal\announcements_feed\LazyBuilders` to `Drupal\toolbar\AnnouncementsFeedToolbarLinkBuilder`, `Drupal\announcements_feed\RenderCallbacks` to `Drupal\toolbar\RenderCallbacks`, and the `announcements_feed.lazy_builders` service to `toolbar.announcements_feed_link_builder`) is internal restructuring: both classes carry `@internal`.

On the asset side, `user/drupal.user.icons`, `contextual/drupal.contextual-toolbar`, and `announcements_feed/drupal.announcements_feed.toolbar` libraries are removed from their original modules. The `.toolbar-icon-user` and `.toolbar-icon-edit` CSS rules move into Toolbar's own icon stylesheets (and its Claro, Olivero and Default Admin theme variants) as the new `toolbar/toolbar.contextual` and `toolbar/toolbar.announcements_feed` libraries; the `person.svg` icon, previously only used via `core/misc/icons`, is copied into `core/modules/toolbar/icons` since it now has no other consumer. The pencil icon stays in `core/misc/icons` because Contextual's own trigger link still uses it directly. `big_pipe_test` no longer piggybacks on the (now-moved) toolbar service as an arbitrary lazy-builder target; `BigPipeTestController` gained its own `displayName()` callback for that purpose. A follow-up, [#3622941](https://www.drupal.org/node/3622941), was opened to actually copy the icon SVG files into the Toolbar module rather than referencing them via relative paths across module boundaries. The sibling issue [#3620812](https://www.drupal.org/node/3620812) does the equivalent move for Workspaces, and [#3618772](https://www.drupal.org/node/3618772) covers the `hook_toolbar_alter()` implementations.

## Upgrade

Update any code referencing the old names:

```php
// Before
use Drupal\user\ToolbarLinkBuilder;
// Service: user.toolbar_link_builder

// After
use Drupal\toolbar\UserToolbarLinkBuilder;
// Service: toolbar.user_link_builder
```

Libraries to update in custom/contrib `*.libraries.yml` or attached library arrays:

```yaml
# Before                                    # After
user/drupal.user.icons                      # (removed, rules now in toolbar's own icon libraries)
contextual/drupal.contextual-toolbar        toolbar/toolbar.contextual
announcements_feed/drupal.announcements_feed.toolbar   toolbar/toolbar.announcements_feed
```
