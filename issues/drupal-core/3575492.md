## Summary

Several core caching methods, `CacheableMetadata::merge()`, `BubbleableMetadata::merge()`, and `Cache::mergeContexts()`, `Cache::mergeTags()`, `Cache::mergeMaxAges()`, are immutable-style helpers: they return a new merged result rather than modifying the object they are called on. Forgetting this and discarding the return value is an easy mistake that silently drops cache contexts, tags, or max-age constraints, which can cause incorrect caching and even expose data that should have been varied per user or context. On PHP 8.5 and later, code that calls these methods without using the returned value will now trigger a runtime warning, helping developers catch this class of bug early.

## Impact

Affects site owners.

- **Requirements:** Running on PHP 8.5 or later, code that calls `CacheableMetadata::merge()`, `BubbleableMetadata::merge()`, `Cache::mergeContexts()`, `Cache::mergeTags()`, or `Cache::mergeMaxAges()` without using the return value will now emit a runtime warning.

## Technical details

The fix adds the PHP `#[\NoDiscard]` attribute to `CacheableMetadata::merge()`, `BubbleableMetadata::merge()` (which calls `parent::merge()` and further merges attachments), and the three static helpers on `Cache`: `mergeContexts()`, `mergeTags()`, and `mergeMaxAges()`. `#[\NoDiscard]` is a native PHP 8.5 attribute; Drupal core's `composer.json` and `Drupal::MINIMUM_PHP` already require PHP `8.5.0` on this branch, so the attribute is immediately effective. No method logic changed: `merge()` still clones `$this` and returns the merged copy rather than mutating the receiver. This is the same pattern already applied to `AccessResult`'s static constructors and `andIf()`/`orIf()` methods and to `EntityBase` methods in sibling issues, extending the discoverability guard to the cacheability metadata API.
