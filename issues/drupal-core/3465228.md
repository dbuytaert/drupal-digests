## Summary

Single Directory Components (SDC) prop and slot names are now validated to ensure they are usable as Twig variables. Because Twig compiles a dash in a variable name as a subtraction operator, a prop or slot named something like `test-required-string` silently broke templates instead of producing a clear error, costing developers debugging time. Component definitions with prop or slot names that don't start with a letter or underscore and continue with letters, digits, or underscores now fail validation immediately with a clear error message, rather than failing confusingly at render time. Variant names are unaffected, since they are used as string values (e.g. CSS modifiers) and never become Twig variable or block names.

## Impact

Affects module maintainers.

- **API change:** Single Directory Component (SDC) prop and slot names must now match `^[a-zA-Z_][a-zA-Z0-9_]*$` (valid Twig/PHP identifiers); previously dashes and other characters were tolerated even though they never worked correctly in Twig templates.

## Technical details

The fix lives in two places. `core/assets/schemas/v1/metadata.schema.json` tightens `slotDefinition`'s `patternProperties` from `^[a-zA-Z0-9_-]+$` to `^[a-zA-Z_][a-zA-Z0-9_]*$`, and wraps `propDefinition` in an `allOf` alongside the existing draft-04 schema `$ref` to add the same `patternProperties`/`additionalProperties: false` constraint for props (this was needed because `propDefinition` delegates its base schema to `http://json-schema.org/draft-04/schema#`, which can't be edited directly). `$comment` annotations document why props/slots differ from variants.

Because prop names are validated against a JSON Schema draft version (draft-04, via `justinrainbow`) that lacks `propertyNames` support, `ComponentValidator::validateDefinition()` in `core/lib/Drupal/Core/Theme/Component/ComponentValidator.php` also gained an explicit PHP-side check: it filters `$prop_names` against `/^[a-zA-Z_][a-zA-Z0-9_]*$/` and throws `InvalidComponentException` up front, before falling through to the JSON Schema validator, when it finds a name that doesn't match. This gives an explicit "Prop names must match the pattern..." error instead of a validator error that's harder to trace back to the actual cause.</technical>
<parameter name="upgrade">Rename any SDC prop or slot names that contain dashes, spaces, or a leading digit to use only letters, digits, and underscores, starting with a letter or underscore:

```yaml
props:
  type: object
  properties:
    my-prop:   # invalid, will now throw InvalidComponentException
      type: string
    my_prop:   # valid
      type: string
```

The same pattern applies to `slots`. `variants` names are unaffected and may still contain dashes.</upgrade>
