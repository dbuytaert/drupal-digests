## Summary

Drupal core no longer includes the large, already-minified `ckeditor5.css` (about 218KB) in CSS aggregation. Previously, if a site had multiple content types or forms with different CKEditor 5 configurations, this file could be duplicated across several different aggregated CSS files, multiplying the bytes transferred unnecessarily. Excluding it from aggregation means it's served once as its own file and can be cached and reused across pages instead of being bundled repeatedly, cutting the total stylesheet bytes sent to visitors editing content.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix sets `preprocess: false` on the `assets/vendor/ckeditor5/ckeditor5.css` entry in the `ckeditor5` library definition (`core.libraries.yml`), mirroring the setting already used for `ckeditor5.umd.js` in the same library. This tells Drupal's asset optimizer to skip this file during CSS aggregation, so it is always delivered as a standalone request rather than concatenated into a page-specific aggregate.

Core's own performance test (`doTestNodeAddPagesAuthor`) had its expected metrics updated accordingly: `StylesheetCount` rose from 23 to 27 (the file is now a separate, unaggregated request) while `StylesheetBytes` dropped from 1,085,546 to 640,654, confirming the reduction in duplicate bytes transferred. This was spun out of [#3615654](https://www.drupal.org/node/3615654) (adding `aggregate_target` support to core and ckeditor5 libraries) specifically so the aggregation exclusion could be evaluated and potentially backported on its own.</technical>
