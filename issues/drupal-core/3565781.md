## Summary

The Search module (and its submodules that index content, users, and help) is now officially marked deprecated in Drupal core, following the policy decision made in [#3476883](https://www.drupal.org/node/3476883) to move Search from core into a contributed project. Sites that currently have the Search module enabled will start seeing a deprecation notice, and should begin planning to migrate to a contributed search solution before Search is removed from a future core release. No functionality was removed yet: this issue only starts the formal deprecation clock and cleans up the codebase in preparation for eventual removal.

## Impact

Affects module maintainers.

- **Deprecation:** The `search`, `node_search`, `user_search`, and `help_search` modules are now marked `lifecycle: deprecated` in their `.info.yml` files, per the decision in #3476883 to move Search from core to a contributed project.

## Technical details

The change adds `lifecycle: deprecated` and `lifecycle_link: https://www.drupal.org/node/3223395#s-search` to the `.info.yml` files of `search.module`, `node_search`, `user_search`, and `help_search`, which is the standard Drupal core mechanism (per the module/theme removal process) for flagging an extension for future removal. Because installing or using a deprecated module now triggers an `E_USER_DEPRECATED` notice via the module installer, every test in these four modules (and tests elsewhere that install them, such as `SearchPageTest`, the JSON:API/REST `SearchPage*` resource tests, and Olivero's `testConfigSchema`/`testPreprocessBlock`) gained the `#[IgnoreDeprecations]` PHPUnit attribute so the notices don't fail the test suite.

As part of the cleanup pass required before deprecation ("thorough search of core for any remaining references"), four leftover config fixture files (`core.entity_view_mode.node.search_index.yml` and `core.entity_view_mode.node.search_result.yml`, in both the `multilingual` and `testing_config_install` fixture sets) were deleted; investigation showed these view modes had no actual dependency on the Search module. Claro and Olivero's own search-related theme code was intentionally left in place because those two themes are themselves slated for deprecation, with separate follow-up issues ([#3620801](https://www.drupal.org/node/3620801) for `default_admin`, [#3620804](https://www.drupal.org/node/3620804) for Umami) handling their theme-specific references instead.

## Upgrade

Modules or sites that depend on the `search`, `node_search`, `user_search`, or `help_search` modules should plan to migrate to a contributed replacement before these are removed from core. Contributed or custom code that installs one of these modules in tests should add the `#[IgnoreDeprecations]` PHPUnit attribute to avoid failures from the new deprecation notice, for example:

```php
use PHPUnit\Framework\Attributes\IgnoreDeprecations;

#[Group('search')]
#[IgnoreDeprecations]
class MyCustomSearchTest extends BrowserTestBase {
```
