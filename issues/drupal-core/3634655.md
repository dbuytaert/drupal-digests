## Summary

Drupal's `main` and 12.0.x branches now depend on Symfony 8.2.0-BETA1 instead of 8.1.x. Drupal 12.0 is meant to require Symfony 8.2, which was not yet stable, so the beta is used for now and is expected to be replaced by the stable release before Drupal 12.0.0. Sites and projects tracking these branches will receive the Symfony beta packages.

## Impact

Affects module maintainers and site owners.

- **Requirements:** Symfony components raised from 8.1.x to ~8.2.0-BETA1 (contracts packages to ~3.8.1), so the beta is pulled in until the stable 8.2 release.
- **API change:** `Drupal\Core\DependencyInjection\ContainerBuilder::reset()` now declares `reset(/* bool $shutdown = false */)` to match the upcoming Symfony parent signature.

## Technical details

`composer.json` and the `core/lib/Drupal/Component/*` composer.json files move to `~v8.2.0-BETA1` for Symfony components and `v3.8.1` for the contracts packages. `ComposerProjectTemplatesTest::MINIMUM_STABILITY` is lowered from `stable` to `beta` to allow the beta temporarily.

Code adjustments for Symfony 8.2 changes:
- `Drupal\Core\DependencyInjection\ContainerBuilder::reset()` now has the signature `reset(/* bool $shutdown = false */)` and reads the argument with `func_get_arg()`, passing it to `parent::reset($shutdown)`. Symfony's `Container::reset()` will require `bool $shutdown` in the next major; a matching entry was added to the deprecation ignore list.
- `FinishResponseSubscriber::isCacheControlCustomized()` now treats 308 as well as 301 redirects without an explicit `Cache-Control` header as not customized, because Symfony 8.2 removes that header for both.
- The Drupal `Route` attribute passes `NULL` for the new `firewall` argument of the Symfony parent constructor. The firewall parameter is not supported by Drupal's attribute.
- `core.services.yml` adds a class-name alias `Symfony\Component\HttpKernel\Controller\ArgumentResolver\QueryParameterValueResolver` to `argument_resolver.query_parameter` and marks that service `public: false`.
- Three phpstan baseline entries for `ConstraintViolationBuilderInterface::setParameter()` in CKEditor 5 validators are removed, and `TestSiteApplicationTest` now normalizes line breaks in the console output it asserts on.

## Upgrade

If you override `ContainerBuilder::reset()`, keep it compatible with Symfony 8.2:

```php
public function reset(/* bool $shutdown = false */): void {
  $shutdown = \func_num_args() && func_get_arg(0);
  // ...
  parent::reset($shutdown);
}
```
