## Summary

Drupal core's entity reference field API now uses PHP 8.4 property hooks to expose the `entity` and `target_id` properties on entity reference field items and item lists, instead of relying on PHP's `__get()`/`__set()` magic methods. This removes a fragile workaround that was needed to avoid a PHP bug where suspending a Fiber inside `__get()` could incorrectly trigger PHP's recursion guard, and it also fixes `isset()` checks on these properties inside a running Fiber, since PHP routes `isset()` through a property hook's `get` accessor but not through `__isset()`.

## Impact

Affects module maintainers.

- **API change:** `entity` and `target_id` on `EntityReferenceItem` and `EntityReferenceFieldItemList` are now declared as typed properties with PHP 8.4 property hooks instead of being handled by `__get()`/`__set()` magic methods; `unset()` on either property now throws `Error: Cannot unset hooked property` instead of silently clearing the value.

## Technical details

Previously, `EntityReferenceItemBase::__get()` special-cased the `entity` property: when called while a Fiber was already running, it wrapped the call to `parent::__get()` in a new Fiber and manually pumped `resume()`/`usleep()` until it terminated, to dodge a PHP fiber/recursion-guard bug (php/php-src[#14983](https://www.drupal.org/node/14983)). That override is now removed entirely; `EntityReferenceItemBase` is back to an empty class body.

Instead, `EntityReferenceItem` declares `entity` and `target_id` as typed properties (`?EntityInterface $entity` and `string|int|null $target_id`) using property hooks: the `get` hook delegates to the existing `__get()` logic and the `set` hook calls `$this->set()`. `EntityReferenceFieldItemList` gets the same two hooked properties, with `get` proxying to `$this->first()?->__get(...)` and `set` appending a field item if needed before calling `$item->set()`. Because property hooks don't share the fiber/recursion-guarding bug that plain `__get()` had, the workaround class from [#3565937](https://www.drupal.org/node/3565937) is no longer necessary, and new tests (`testEntityReferenceListIssetFiberSuspension`, `testEntityReferenceItemIssetFiberSuspension`) verify `isset()` works correctly from inside a Fiber, addressing the `__isset()` half of the problem tracked in [#3590537](https://www.drupal.org/node/3590537).

Both files carry `phpcs:ignoreFile` because PHP_CodeSniffer and PHPStan (via `mglaman/phpstan-drupal`) do not yet fully support property hook syntax, which caused internal errors during static analysis; this was raised upstream (github.com/mglaman/phpstan-drupal/pull/935) but not yet resolved at commit time.</technical>
