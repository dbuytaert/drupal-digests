## Summary

CSS aggregates now use the exact list of libraries they contain to build their URL, the way JavaScript aggregates already do. Before, a CSS aggregate's URL depended on everything else on the page, so the same content was downloaded again under different query strings on different pages. Now an aggregate that contains the same libraries gets the same URL on every page, which improves browser and CDN cache hits. The number of stylesheet files per page often goes up, but total bytes transferred usually goes down or stays flat. The issue reports some cases about a third smaller, and some Umami pages with fewer files. No configuration is needed.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `CssCollectionGrouper::group()` in `core/lib/Drupal/Core/Asset/CssCollectionGrouper.php`. Previously the `libraries` parameter was only used for CSS when `aggregate_target['css']` was set. Now every preprocessed item that has a `library` key is recorded in the group's `libraries` list, so `aggregate_target` is no longer a precondition. It still controls splitting: `TRUE` groups by the item's library and a string groups by that name. Group keys still include the item's `category`, so an aggregate holds only one CSS category (base, theme, component). Libraries that are split across aggregates, for example when one of their files is excluded from aggregation, still fall back to include/exclude. Items without a `library` key, such as files added in `hook_css_alter()`, are skipped when recording libraries, and the alter hook is assumed to add them in the same place each time. Include/exclude support is not removed. The thread says that needs per-file weights removed first, and follow-up [#3636352](https://www.drupal.org/node/3636352) covers documenting that `hook_css_alter()` and `hook_js_alter()` should only modify or remove files. The Navigation and CKEditor `aggregate_target` changes were split out of this issue ([#3615642](https://www.drupal.org/node/3615642) and [#3622766](https://www.drupal.org/node/3622766)). Most of the diff is updated performance test expectations (`StylesheetCount` and `StylesheetBytes`) and `CssCollectionGrouperUnitTest` fixtures, which now carry `category` and `library` keys.

## Upgrade

Custom or contrib code that adds CSS files in `hook_css_alter()` without a `library` key still works. Those files are not included in the `libraries` list. Attaching them to a real library is more robust.
