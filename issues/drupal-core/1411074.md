## Summary

Kernel test classes can now opt in to sharing one database across all their test methods with the `#[ShareEnvironment]` attribute. The schema, config and other initial state are built once per class instead of once per method, which speeds up classes with many methods (the issue reports roughly 20 to 40 percent of total time). Classes without the attribute behave exactly as before. In core, the config entity validation tests were converted as the first users. Converting the rest of core's Kernel tests, and later making sharing the default in the next major, are follow-ups. The change was also backported to 11.x and 11.5.x so contrib can adopt it.

## Impact

Affects module maintainers.

- **API change:** `ConfigEntityValidationTestBase` now builds its entity in `setUpEnvironment()` and reloads it in `setUp()` for shared classes. Core subclasses were converted from `setUp()` to `setUpEnvironment()`.
- **New API:** New `Drupal\TestTools\Attribute\ShareEnvironment` attribute, plus `KernelTestBase::setUpEnvironment()`, `resetEnvironment()` and `sharesEnvironment()`.

## Technical details

The attribute is not inherited: `ShareEnvironment::isEnabledFor()` reflects on the concrete class only, and `#[ShareEnvironment(FALSE)]` marks a class as needing its own environment. For an opted-in class, a `#[BeforeClass]` hook (`allocateSharedDatabase()`) reserves one database prefix with a locked `TestDatabase` and passes it to the forked per-method processes through the `DRUPAL_TEST_SHARED_DB_PREFIX` environment variable. An `#[AfterClass]` hook drops all the tables and releases the lock. `PHPUnit`'s `#[RunTestsInSeparateProcesses]` is still in effect, so each method still has its own process, container and virtual file system. Only database state is shared.\n\nIn `bootKernel()` the first method calls the new `setUpEnvironment()` hook (empty by default), then records the table list and a `ready` row in a `test_shared_database_state` table. Later methods skip the hook. If the hook fails, or a method breaks the shared state, the state is marked `invalid` and the remaining methods fail with the recorded reason. For shared classes the `keyvalue` service is a `KeyValueDatabaseFactory` instead of the in-memory factory, so entity definitions and `state` persist with the tables. `core.extension` is rewritten per method with the module list rebuilt but the installed themes kept.\n\nThe old `tearDown()` table-dropping logic moved to `resetEnvironment()`, which does nothing for shared classes. Instead `tearDownEnvironment()` fails the method if it dropped a shared table or left a new table behind. `INFRASTRUCTURE_TABLES` (currently `cache_container`) is exempt, and a class can redeclare it. Test methods must not assume a clean database, and tables they create must be removed in `resetEnvironment()`. `ConfigEntityValidationTestBase` was adapted: shared subclasses build `$this->entity` in `setUpEnvironment()`, and the base `setUp()` records and reloads the entity from the key value store. Unconverted subclasses that assign `$this->entity` in `setUp()` still work. A change record is at node 3623403, and follow-ups are [#3623409](https://www.drupal.org/node/3623409) (add the attribute to all Kernel tests) and [#3623410](https://www.drupal.org/node/3623410) (make sharing the default). [#3613347](https://www.drupal.org/node/3613347) (re-use the container) builds on this.

## Upgrade

To opt a Kernel test class in, add the attribute and move fixture creation from `setUp()` to `setUpEnvironment()`, as the converted core tests do:

```php
use Drupal\TestTools\Attribute\ShareEnvironment;

#[RunTestsInSeparateProcesses]
#[ShareEnvironment]
class ActionValidationTest extends ConfigEntityValidationTestBase {

  protected function setUpEnvironment(): void {
    parent::setUpEnvironment();
    // Build the shared fixture here.
  }

}
```

Remove tables or other state a test method adds by overriding `resetEnvironment()` and calling the parent.
