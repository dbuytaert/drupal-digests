## Summary

Core now requires `masterminds/html5` 2.12.0 or newer. That version fixes two vulnerabilities in the HTML5 parser library that the issue says could affect Drupal sites. The fix was committed to main, 12.0.x, 11.x, 11.5.x, 11.4.x and 11.3.x. Previously core-recommended pinned an older version (the issue says 2.10), so sites could not pick up the fix with a normal update. Sites should update core and its dependencies.

## Impact

Affects site owners.

- **Security:** Updates `masterminds/html5` to 2.12.0, which the issue says fixes two vulnerabilities (GitHub advisories GHSA-6c7p-58mg-f5jv and GHSA-pj59-fvjc-74pp) that could affect Drupal sites.
- **Requirements:** Core's `masterminds/html5` constraint raised from `^2.7` to `^2.12.0`; the library now requires `ext-mbstring`.

## Technical details

The issue reported that `drupal/core-recommended` forced 2.10, which blocked 2.12.0. The `main` commit bumps the `masterminds/html5` constraint in `core/composer.json` and in `composer/Metapackage/CoreRecommended/composer.json` (to `~2.12.0`). It also bumps the constraint in `drupal/core-utility`'s `composer.json`, and updates `composer.lock` (library version, source references, and the core package reference hash). The core constraint was raised from `^2.7` to `^2.12.0` so the vulnerable versions cannot be installed. The locked 2.12.0 package adds `ext-mbstring` to its requirements. Each supported branch got its own MR because the lockfile hash changes.

## Upgrade

Run `composer update drupal/core "drupal/core-*" --with-all-dependencies` (or your usual core update) to get `masterminds/html5` 2.12.0. Make sure `ext-mbstring` is enabled, because the new library version requires it.
