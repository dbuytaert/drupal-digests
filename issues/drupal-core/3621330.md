## Summary

The Status report page (/admin/reports/status) now shows a "Bandwidth optimization" entry. It reads "Enabled" when both CSS and JavaScript aggregation are on. If either is off, it shows "Disabled" with a warning. This makes it easier to notice that aggregation was turned off by mistake on a live site. The entry links to the Bandwidth optimization section of the Performance settings page.

## Impact

No upgrade or configuration changes required.

## Technical details

A new `preprocess_enabled` runtime requirement is added in `checkRequirements()`. It reads `css.preprocess` and `js.preprocess` from `system.performance` config, so config overrides in settings.php are reflected. Severity is `RequirementSeverity::Info` by default and becomes `RequirementSeverity::Warning` if either value is falsy. Warning rather than error was chosen because nothing breaks when aggregation is off, it is only sub-optimal. The description includes a "Change bandwidth optimization" link to `system.performance_settings` with the fragment `edit-bandwidth-optimization`.
