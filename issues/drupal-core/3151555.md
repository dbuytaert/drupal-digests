## Summary

The procedural function `user_picture_enabled()`, which checked whether the `user_picture` field exists on the user entity, is now deprecated. It had only one known usage in contrib and two internal usages in core, so it is being phased out rather than kept as a permanent API. Sites and modules calling this function directly will see a deprecation notice starting in Drupal 11.5.0, and the function will be removed entirely in Drupal 13.0.0.

## Impact

Affects module maintainers.

- **Deprecation:** `user_picture_enabled()` is deprecated in Drupal 11.5.0 and removed in 13.0.0, with no replacement function.

## Technical details

The function's only real logic was `isset(\Drupal::service('entity_field.manager')->getFieldDefinitions('user', 'user')['user_picture'])`, a thin wrapper that added little value over calling the entity field manager directly. Both of core's own call sites, `\Drupal\system\Form\ThemeSettingsForm::buildForm()` and the `#[Hook('user_view_alter')]` implementation in the user module, were updated to inline that field-definition lookup instead of calling the deprecated function, so core itself no longer triggers the deprecation. `user_picture_enabled()` itself keeps its original behavior but now emits an `E_USER_DEPRECATED` error via `@trigger_error()`, per Drupal's deprecation policy, pointing to the change record at drupal.org/node/3619932.

## Upgrade

Replace calls to `user_picture_enabled()` with a direct field-definition check:

```php
$field_definitions = \Drupal::service('entity_field.manager')->getFieldDefinitions('user', 'user');
if (isset($field_definitions['user_picture'])) {
  // ...
}
```

The function will be removed in Drupal 13.0.0.
