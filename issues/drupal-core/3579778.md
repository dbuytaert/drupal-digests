## Summary

Several modules that used to live only in Drupal core (Ban, Contact, Field Layout, History, Search, Settings Tray, Shortcut, Stable9, Telephone, Toolbar) have been split out, or are being prepared to split out, into standalone contrib projects with their own `drupal/<module>` Composer package. Because core's `composer.json` did not declare these as "replaced" packages, Composer could get confused when a site or another dependency (as reported for the Forum, Pathauto and Metatag modules depending on History) required the new standalone release: it would try to resolve both the core-bundled code and the contrib package under the same name, producing conflicts. This change adds the appropriate entries to core's `composer.json` `replace` section so Composer knows the bundled core version already satisfies that package name, avoiding the conflict for site owners who add these contrib releases as dependencies.

## Impact

Affects site owners.

- **Config change:** Core's `composer.json` `replace` section now lists formerly core-only modules that have separate contrib releases (varies by branch), telling Composer that installing `drupal/core-recommended`/core already satisfies that package name.

## Technical details

Core's `composer.json` `replace` array previously contained only Symfony polyfill entries; a general module `replace` mechanism had been removed from core in [#3292380](https://www.drupal.org/node/3292380). This issue restores targeted entries, but with different lists per branch because of version-specific risk: on `10.6.x`, the `replace` list gained `drupal/ban`, `drupal/contact`, `drupal/field_layout`, `drupal/history`, `drupal/search`, `drupal/settings_tray`, `drupal/shortcut`, `drupal/stable9`, `drupal/telephone` and `drupal/toolbar`, all modules already deprecated in Drupal 10 with stable contrib releases. On `11.x` (main/12.0-dev) and `11.4.x`, only `drupal/search`, `drupal/settings_tray`, `drupal/shortcut` and `drupal/toolbar` were added: modules that don't yet have a contrib release. Ban, Contact, Field Layout, History, Stable9 and Telephone were deliberately left out of the 11.x/11.4.x replace list because sites on those branches may already be requiring the contrib releases directly (see [#3482198](https://www.drupal.org/node/3482198) for Ban's deprecation), and adding a core-side replace there would force Composer to fall back to the bundled core version instead of the contrib package a site had intentionally installed. `composer.lock`'s `content-hash` was regenerated in each commit to match.

berdir reported that the missing replace entry for History was breaking downstream testing of the Forum module (and in turn Pathauto and Metatag), pushing this from a theoretical concern to an active breakage affecting the 11.2 branch as well. catch worked out the phased branch strategy: since a site on 11.3+ could already be using the contrib releases of Contact, Ban, Field Layout or History directly, adding those to the 11.x/11.4.x replace list would wrongly force Composer back to the bundled core version, so only modules without existing contrib releases (Search, Settings Tray, Shortcut, Toolbar) were added there, while 10.6.x got the full list. cmlara additionally argued for reconsidering the earlier removal of core's replace mechanism ([#3292380](https://www.drupal.org/node/3292380)) and filed [#3582324](https://www.drupal.org/node/3582324) to think about the underlying Composer facade for future major versions. smustgrave did the legwork of opening the separate merge requests for the 11.x, 11.4.x and 10.6.x branches, and godotislate committed the changes, dropping some unrelated "allowed plugins" entries from the 10.6.x branch after review and waiting for catch's confirmation before committing that branch.
