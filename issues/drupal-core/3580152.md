## Summary

Themes have historically been able to put certain hook implementations, most commonly `hook_form_system_theme_settings_alter()`, in a special `theme-settings.php` file that Drupal auto-loads. Now that hooks can be implemented as attribute-based classes and can live in their own files, this special-cased file is deprecated and will stop being supported in Drupal 12. Core's own Olivero theme has been converted as an example: its theme settings form alter now lives in an OOP hook class instead of `olivero/theme-settings.php`. Any theme (core, contrib, or custom) that still ships a `theme-settings.php` file will now trigger a deprecation notice, and should convert its code before Drupal 12.0.0.

## Impact

Affects module maintainers.

- **Deprecation:** Using a `theme-settings.php` file in a theme is deprecated in Drupal 11.5.0 and will be removed in Drupal 12.0.0; convert hook implementations to attribute-based OOP hook classes (or move them to the theme's `.theme` file if legacy support below 11.3 is needed).

## Technical details

The deprecation is enforced in `ThemeHookCollectorPass::collectThemeHookImplementations()`: when a discovered file is identified as a theme's `theme-settings.php` (`$isThemeSettings`), an `E_USER_DEPRECATED` notice is triggered pointing to the change record at drupal.org/node/3587273, in addition to the file still being loaded and its procedural hooks still working through Drupal 12.

Olivero's `olivero/theme-settings.php` was removed and its `olivero_form_system_theme_settings_alter()` logic moved verbatim into a new `Drupal\olivero\Hook\OliveroThemeSettingsHooks` class, implementing `hook_form_FORM_ID_alter()` via the `#[Hook('form_system_theme_settings_alter')]` attribute and using `StringTranslationTrait::t()` instead of the procedural `t()`.

The `test_theme_settings` test theme's `theme-settings.php` was deliberately left in place to preserve legacy procedural-hook test coverage; the affected functional tests (`FileFieldWidgetTest`/related theme settings form tests) were updated with `#[IgnoreDeprecations]` and `expectUserDeprecationMessage()` calls, with a comment noting that file should be converted once support for the deprecated behavior is fully removed. The related issue [#3581218](https://www.drupal.org/node/3581218) similarly deprecates the `.theme` file extension itself.

## Upgrade

Convert any hook implementations in a theme's `theme-settings.php` to an attribute-based hook class, following the Olivero example:

```php
namespace Drupal\mytheme\Hook;

use Drupal\Core\Form\FormStateInterface;
use Drupal\Core\Hook\Attribute\Hook;

class MythemeThemeSettingsHooks {

  #[Hook('form_system_theme_settings_alter')]
  public function formSystemThemeSettingsAlter(array &$form, FormStateInterface $form_state): void {
    // Moved logic from theme-settings.php here.
  }

}
```

Then delete `theme-settings.php`. If the theme must simultaneously support versions of Drupal older than 11.3 alongside Drupal 12, move the hook implementation to the theme's `.theme` file instead, but note that `.theme` files are themselves deprecated (see [#3581218](https://www.drupal.org/node/3581218)) and will need converting again later.
