## Summary

The "Users" search plugin, previously bundled inside the User module, has been moved into a new core submodule called Search user, following the same pattern already used to split search functionality out of the Node and Help modules. Existing sites are upgraded automatically: a database update enables the new `search_user` module whenever `user` is already installed, and the `user_search` search page configuration now depends on `search_user` instead of `user`. No end user visible change is expected; the Users search page and its results work the same as before.

## Impact

Affects module maintainers.

- **Deprecation:** `Drupal\user\Plugin\Search\UserSearch` is deprecated in favor of `Drupal\search_user\Plugin\Search\SearchUser` in the new `search_user` module; the old plugin now returns no results and denies access.

## Technical details

The old `Drupal\user\Plugin\Search\UserSearch` plugin in `user.module` is now `@deprecated` (removed in Drupal 12.0.0, see the linked change record) and its `execute()` and `access()` methods are stubbed out to return no results and deny access respectively; the real implementation moved verbatim to `Drupal\search_user\Plugin\Search\SearchUser` in the new `search_user` module.

Unlike the earlier node and help extractions, `search_user` sorts alphabetically before `user`, so normal module-precedence rules would let the old, now-inert `UserSearch` plugin win when both modules are enabled. To avoid that, `search_user` implements `hook_search_plugin_alter()` (`SearchUserHooks::searchPluginAlter()`) to force the `user_search` plugin definition's class to the new `SearchUser` regardless of load order. A new `search_update_11403()` installs `search_user` automatically for any site that has `user` enabled but not yet `search_user`, and `search.schema.yml`'s `search.plugin.user_search` config schema moved from `user.module` to the new module. `search.module`'s help text was also hardened with a `try`/`catch` around `Url::fromRoute('search.view')`, since that route only exists once a default search page is configured, which was surfacing as a fatal error in the generic module test.

## Upgrade

Update references to the deprecated plugin class:

```php
// Before
use Drupal\user\Plugin\Search\UserSearch;

// After
use Drupal\search_user\Plugin\Search\SearchUser;
```

Contrib modules and custom code that enable Search functionality for users should depend on `search_user` (not just `user`), and any `.info.yml` or test `$modules` list that expects the `user_search` search page to work must include `search_user`.
