## Summary

This issue upgrades the Selenium/Chrome version used by Drupal core's automated JavaScript test suite from 127 to 133, and adjusts several tests to match newer Chrome behavior. As a side effect of testing against the newer Chrome, it uncovered and fixed a real bug in the Olivero theme: the `secondLevelNavMenus` variable in the second-level navigation script was left `undefined` whenever a site's primary menu had no top-level items with children, causing JavaScript errors instead of behaving as an empty menu. This also fixes the Escape-key-does-not-close-mobile-menu problem described in [#3584314](https://www.drupal.org/node/3584314) for sites combining the search block with an empty or childless main menu. Sites running Olivero are unaffected unless their primary menu has no items with children, in which case menu-closing interactions (Escape key, tap-outside) now work instead of erroring silently in the console.

## Technical details

The core change bumps `.with-selenium-chrome` in `.gitlab-ci.yml` from `selenium/standalone-chrome:127.0` to `133.0`. Several functional JS tests needed adjustment for behavior differences in the newer Chrome/Chromedriver: `BrowserWithJavascriptTest::testJavascript` now reads `window.outerHeight` instead of `window.innerHeight`, because headless Chrome 128+ reports a viewport about 139px smaller than the size requested via `resizeWindow()`. `LayoutBuilderDisableInteractionsTest::testFormsLinksDisabled` resizes to `1339` instead of `1200` for the same reason. Several CKEditor 5 tests (`CKEditor5AllowedTagsTest`, `CKEditor5Test`, `AdminUiTest`, `TableTest`) swap `responseContains()` assertions for `waitForText()`/`waitForElementVisible()` because content updates now render asynchronously relative to form submission in the newer browser. The Nightwatch `drupalCreateRole` command now resizes the browser to `1024x768` before toggling permission checkboxes.

Separately, `core/themes/olivero/js/second-level-navigation.js` initializes `secondLevelNavMenus` to `[]` instead of leaving it declared but unassigned. Previously it was only assigned inside `init()`, which only runs when a `[data-drupal-selector="primary-nav-menu--level-1"]` element with children exists; without one, `closeAllSubNav()` and `areAnySubNavsOpen()` called `.forEach()` on `undefined` and threw. Chrome 133 started firing resize events in situations where older Chrome versions did not, which is what surfaced this latent bug during the CI upgrade; the root cause traces back to [#3568566](https://www.drupal.org/node/3568566).
