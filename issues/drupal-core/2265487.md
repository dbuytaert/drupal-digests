## Summary

Lists built from configuration entities, such as content type lists, vocabularies, view modes, blocks, and date formats, are now sorted correctly when their labels contain accented or non-ASCII characters (like é, ñ). Previously these items were pushed to the end of alphabetically sorted lists regardless of their actual letter, because the sort relied on a plain byte comparison. As a side effect, embedded numbers now sort numerically too (for example "Format 10x10" before "Format 100x100"), and block labels, which were previously sorted case-sensitively, are now sorted case-insensitively like other config entities.

## Impact

Affects module maintainers.

- **New API:** New `Drupal\Core\Utility\NaturalSort::strnatcasecmp()` static method, a locale-aware, collation-based drop-in replacement for PHP's `strnatcasecmp()`, used internally by config entity sort methods.

## Technical details

The various `::sort()` implementations across config entity classes (`ConfigEntityBase`, `DateFormat`, `EntityDisplayModeBase`, `Language`, `Block`, `Action`) called PHP's byte-wise `strnatcasecmp()` (or, in `Block`'s case, `strcmp()`) to order labels, which is locale-unaware and sorts accented characters after all plain ASCII letters. The fix adds a new final class `Drupal\Core\Utility\NaturalSort` with a static `strnatcasecmp(string $string1, string $string2, ?string $langcode = NULL)` method that, when the `intl` extension is loaded, builds (and caches per langcode in a static array) a `\Collator` for the given or current language and enables `Collator::NUMERIC_COLLATION` so embedded numbers compare numerically. It falls back to plain `strnatcasecmp()` when `intl` isn't available or no langcode can be resolved. All the affected `::sort()` methods were updated to call this helper instead of the raw PHP functions.

Getting there took several redesigns. An earlier iteration deprecated `ConfigEntityBase::sort()` in favor of new `sortEntities()`/`compare()` methods and added a `symfony/polyfill-intl-icu` dependency as a fallback when `intl` is missing; that version was committed to 11.x, then reverted within hours because `Symfony\Polyfill\Intl\Icu\Collator::compare()` wasn't actually implemented, which crashed `drush cr` and any other code path on sites without the `intl` extension (duplicate issue [#3516545](https://www.drupal.org/node/3516545)). The version that eventually landed drops the polyfill dependency entirely and keeps the original `sort()` method signatures unchanged, so there is no deprecation and no new required dependency: `composer.json` only gained a `suggest` entry for `ext-intl`.

A follow-up issue, [#3624817](https://www.drupal.org/node/3624817), tracks adding a `NaturalSort::natcasesort()` helper and converting other locale-sensitive `strnatcasecmp()`/`strcmp()` call sites across core (e.g. `SortArray`, plugin collection sort helpers) to use this new utility.</technical>
<parameter name="upgrade">Code that needs locale-aware label sorting can use the new helper instead of PHP's native function:

use Drupal\Core\Utility\NaturalSort;
