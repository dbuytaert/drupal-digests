## Summary

The database update page (`update.php`) now uses Drupal core's Default Admin theme instead of always forcing Claro. This is part of ongoing work to deprecate Claro as core's default admin theme, and mirrors a similar earlier change made for the installer, so that core's non-standard front controllers (installer and updater) consistently use the same fallback admin theme rather than hardcoding a theme that is being phased out.

## Impact

Affects front-end developers.

- **Theme change:** The `update.php` (database update) page now renders with the `default_admin` theme (a Drupal core admin theme) instead of the hardcoded `Claro` theme.

## Technical details

The fix changes `\Drupal\system\Theme\DbUpdateNegotiator::determineActiveTheme()` so it returns `default_admin` instead of the literal string `claro`. This negotiator is responsible for forcing a stable theme during update.php runs, regardless of the site's configured admin theme, so that database updates don't depend on a theme that might itself be broken or mid-update. The rationale, per the issue discussion, is consistency with the installer's front controller, which was already switched to use the Default Admin theme for the same stability reasons.
