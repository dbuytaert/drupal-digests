## Summary

Drupal core's development branch (targeting Drupal 12) updates its bundled Symfony components from the 8.0.x series to 8.1.1, along with a matching PHPUnit bump. There is no behavioral change for end users. The practical impact is for developers who write PHPUnit tests: Symfony 8.1 changed how `Request` and `Response` expose their public properties (`query`, `request`, `server`, `headers`), and the old pattern of mocking these classes and assigning those properties directly, which Drupal core's own test suite used extensively, no longer works reliably. Tests need to construct real `Request`/`Response` objects instead. Symfony's validator component also deprecates the old `ConstraintValidator::initialize()`/`::validate()` methods in favor of `validateInContext()`.

## Impact

Affects module maintainers and site owners.

- **Requirements:** Drupal core (main, targeting Drupal 12) now requires `symfony/*` packages `^8.1` instead of `^8.0`, and bumps `phpunit/phpunit` to `^12.5.15`.
- **Deprecation:** Symfony 8.1 deprecates directly setting public properties like `$response->headers` or `$request->query` on `Request`/`Response`/`CacheableResponse` (now property hooks), and deprecates `ConstraintValidator::initialize()`/`::validate()` in favor of `validateInContext()`.

## Technical details

The diff bumps version constraints in `composer.json`/`core/composer.json` (and the corresponding `composer.lock`) for `symfony/console`, `dependency-injection`, `event-dispatcher`, `filesystem`, `finder`, `http-foundation`, `http-kernel`, `mailer`, `mime`, `process`, `routing`, `runtime`, `serializer`, `validator`, and `yaml` from `^8.0` to `^8.1`, plus dev dependencies (`phpunit/phpunit` to satisfy sebastianbergmann/phpunit[#6545](https://www.drupal.org/node/6545), `symfony/browser-kit`, `css-selector`, `dom-crawler`, `error-handler`, `lock`, `var-dumper`).

Two small production fixes were needed for compatibility: `ConsoleCompilerPass::process()` now calls `addTag('console.command')` instead of `setTags(['console.command' => []])`, since `symfony/console` 8.1 conflicts with `symfony/dependency-injection` below 8.1 and expects the new tagging API (this also absorbs the fix from [#3607060](https://www.drupal.org/node/3607060), "ConsoleCompilerPass incompatible with symfony/console ≥ 8.1"). `PhpMail::mail()` now passes an explicit `''` default to `$this->request->server->get('SERVER_SOFTWARE', '')`, since calling `ServerBag::get()` without a default is newly deprecated.

The bulk of the remaining diff is test suite fallout: `BrowserTestBase`, `FinishResponseSubscriberTest`, `NegotiationMiddlewareTest`, `LoggerChannelTest`, `PhpMailTest`, and `RoutePathGenerationTraitTest` were rewritten to stop stubbing `Request`/`Response` and setting properties like `->query`, `->server`, `->headers` directly on the mock, using real `new Request()`/`new Response()` (or `new CacheableResponse()`) instances instead, since Symfony 8.1 turns those properties into property hooks that reject external writes. `BrowserTestBase::getTestMethodCaller()` was also adjusted to recognize PHPUnit's new `invokeTestMethod()` caller frame alongside `runTest()`. New entries were added to `core/.deprecation-ignore.txt` and `core/.phpstan-baseline.php` to suppress the newly surfaced Symfony 8.1 deprecations (tagged-service indexing in dependency injection, the HttpFoundation property-hook writes, and `ConstraintValidator::initialize()`/`validate()`) until they can be addressed properly.
