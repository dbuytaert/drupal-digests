## Summary

Package Manager (used by Automatic Updates, Project Browser, and other update tooling) used to copy the entire codebase into a fresh, randomly-named sandbox directory for every composer operation, then delete it afterwards. On hosts with limits on file operations (some shared/managed hosting providers), this churn of tens of thousands of file creates and deletes per operation could trip usage caps and lock accounts. Now Package Manager keeps a single sandbox directory around permanently and reuses it for every operation, so `rsync` only needs to copy files that actually changed instead of recreating the whole codebase each time. Stale sandboxes are cleaned up automatically during cron after a configurable number of days (14 by default), and the directory is still deleted immediately if a site turns off `include_unknown_files_in_project_root`, since leftover excluded files would otherwise never get removed.

## Impact

Affects module maintainers and site owners.

- **Config change:** New optional `$settings['package_manager_max_sandbox_age']` (default 14 days) controls how long the now-persistent Package Manager sandbox directory is kept before cron deletes it.
- **API change:** `SandboxManagerBase::destroy()` no longer deletes the sandbox directory (it stays on disk for reuse) and no longer queues cleanup via the `package_manager_cleanup` queue; `getSandboxDirectory()` now returns a fixed path (`sandbox_directory`, not a random per-stage name) and no longer throws `\LogicException` when called before the stage is created or claimed.

## Technical details

The sandbox directory's name changed from a per-stage random token to a fixed `sandbox_directory` constant (`SandboxManagerBase::COMPOSER_SANDBOX_DIRECTORY`) under the site's staging root, so the same physical directory is reused across create/destroy cycles. `SandboxManagerBase::destroy()` was simplified to just release the lock and mark the stage available; it no longer deletes the directory or enqueues it to the `package_manager_cleanup` queue (the `Cleaner` queue worker itself is untouched, pending a possible follow-up to remove it). `sandboxDirectoryExists()` now means "the stage is actively claimed and its directory exists on disk," which is a different question from "does the directory physically exist," since a long-lived sandbox persists after `destroy()`.

Because Composer Stager's stock `StagingDirDoesNotExistInterface` precondition expects an empty target, a new `Drupal\package_manager\StagingDirDoesNotExist` decorator was added that always reports the precondition as fulfilled, letting the sandbox be reused even though it already exists. Two new pieces of infrastructure manage the directory's lifecycle: `EventSubscriber\LongLivedSandboxSubscriber` records the timestamp of the last `PostCreateEvent` in state (`package_manager.last_create_event`), and deletes the sandbox immediately when `package_manager.settings:include_unknown_files_in_project_root` transitions from `TRUE`/unset to `FALSE`. `Hook\CronHook` (a `#[Hook('cron')]` implementation) compares that timestamp against `Settings::get('package_manager_max_sandbox_age', 14)` (in days) and deletes the sandbox if it's stale and not currently locked. `getSandboxDirectory()` and `getStagingRoot()` were also relaxed to work without an active lock (needed since cron and the config subscriber must locate the directory outside of a claimed stage), but `getStagingRoot()` only caches its result in the shared tempstore when a lock is actually held, to avoid polluting shared state from incidental lookups.

## Upgrade

Code that calls `SandboxManagerBase::getSandboxDirectory()` before creating or claiming a stage will no longer get a `\LogicException`; it now returns the deterministic sandbox path directly. Code that relied on `destroy()` deleting the sandbox directory (or on the `package_manager_cleanup` queue running shortly after) must not assume the directory is gone until cron has run and the configured `package_manager_max_sandbox_age` has elapsed. Sites that need faster or slower cleanup can set, for example:

```php
// settings.php
$settings['package_manager_max_sandbox_age'] = 7; // days
```
