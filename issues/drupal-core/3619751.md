## Summary

Generating the permissions list for the Filter module used to build a link (to the text format's edit page) inside each permission's title. Constructing that link forced Drupal's lazy-built router to rebuild, adding about 500ms to every standard Drupal installation and to any test that installs the Filter module. This change removes the link from the permission title text, which now just reads "Use the [format label] text format" without a hyperlink. The fix has no functional effect beyond faster installs and slightly plainer wording on the permissions page.

## Impact

No upgrade or configuration changes required.

## Technical details

The slowdown traced back to `Drupal\filter\FilterPermissions::permissions()`, which built each permission's `title` with `$this->t('Use the <a href=":url">@label</a> text format', [':url' => $format->toUrl()->toString(), ...])`. Calling `$format->toUrl()->toString()` triggers URL generation, which in turn caused the install-time lazy router to rebuild on every call, the actual source of the ~500ms overhead per installation. The fix simply drops the `:url` argument and the anchor markup, leaving `$this->t('Use the @label text format', ['@label' => $format->label()])`.

A related cleanup landed in `FilterDefaultConfigTest`: a comment and an `installEntitySchema('user')` call that existed only to support the now-removed URL generation were deleted from `setUp()`, since the test still installs user configuration via `installConfig(['user', 'filter_test'])` for its role-related assertions.
