## Summary

Drupal core now requires and locks Twig 3.31.1 (and `twig/html-extra` 3.31.1), picking up fixes for newly published Twig CVEs. The update was also committed to the 12.0.x, 11.x, 11.5.x, 11.4.x, 11.3.x and 10.6.x branches. Sites should update to a core release containing it, or otherwise run `composer update twig/twig` so `composer audit` stops reporting the advisories.

## Impact

Affects module maintainers and site owners.

- **Security:** Updates Twig to v3.31.1 to address newly released Twig CVEs (the issue flags them via `composer audit`).
- **API change:** Core's Twig loader `addPath()` gains a third parameter `bool $check = TRUE` on main, matching Twig's `FilesystemLoader`; subclasses overriding it need a compatible signature.

## Technical details

The commit bumps the `twig/twig` constraint from `^3.28.0` to `^3.31.1` in core's `composer.json`, and updates `composer.lock` (`twig/twig` from v3.30.0 to v3.31.1, `twig/html-extra` from v3.29.0 to v3.31.1). The issue states lockfiles and `core-recommended` need the update before further security releases on all supported branches.

Twig 3.31 adds a `bool $check` argument to `FilesystemLoader::addPath()`. Core's Twig loader overrides that method, so on `main` its signature becomes `addPath(string $path, string $namespace = self::MAIN_NAMESPACE, bool $check = TRUE): void`, and the docblock is replaced with `{@inheritdoc}`. In the thread, the concern was that making this a required signature change could disrupt contrib or custom subclasses on production branches; for 11.4.x the MR was reworked to use Twig's commented-out parameter form (`/* , bool $check = true */`) with deprecation ignores, while 11.5.x keeps the new parameter. I only read the `main` diff, so the exact backport forms on other branches are not verified here.

## Upgrade

If you extend the core Twig loader and override `addPath()`, update the signature on main/12.0.x:

```php
public function addPath(string $path, string $namespace = self::MAIN_NAMESPACE, bool $check = TRUE): void {
```

Sites using their own lockfile should run `composer update twig/twig twig/html-extra`.
