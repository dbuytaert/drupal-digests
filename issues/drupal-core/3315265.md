## Summary

On PostgreSQL 18+ (the minimum for Drupal 12), Drupal's Merge query (the "insert or update" helper used by core's key_value store, the locale module's string location tracking, and the taxonomy index that is rebuilt whenever a published node is saved) now executes as a single native SQL `MERGE` statement instead of a `SELECT` followed by a separate `INSERT` or `UPDATE`. This halves the number of database round trips for these operations and also closes a small race-condition window that existed in the old check-then-write approach. There is no API change and nothing for site owners or module authors to configure; PostgreSQL sites simply get faster, safer merge queries automatically. Benchmarks in the issue showed 14 to 18% less time per merge query on a low-latency connection, with larger savings expected when there is more network latency between the web and database servers.

No upgrade or configuration changes required.

## Technical details

The PostgreSQL driver gets a new `\Drupal\pgsql\Driver\Database\pgsql\Merge` class, returned by the driver's `Connection::merge()`, which extends the generic `\Drupal\Core\Database\Query\Merge`. Its `__toString()` builds a `MERGE INTO {table} USING (SELECT 1) AS drupal_merge_source ON (...)` statement with `WHEN MATCHED THEN UPDATE` and `WHEN NOT MATCHED THEN INSERT` clauses, ending in `RETURNING merge_action()`. `executeNativeMerge()` binds all placeholders (including blob fields, expressions, and select-expression arguments) and maps the returned `merge_action()` value ('INSERT'/'UPDATE') back to `Merge::STATUS_INSERT` or `Merge::STATUS_UPDATE`, returning `NULL` when the row matched but no update fields were supplied.

`isNativeMerge()` gates when the native path is used: the condition must target the merge table itself and there must be insert fields or default fields. Otherwise `execute()` falls back to the parent's generic `SELECT` + `INSERT`/`UPDATE` emulation, specifically when the condition targets another table (no `ON` clause possible), when there are no insert fields (no `WHEN NOT MATCHED THEN INSERT` possible), or when values are inserted into serial fields, since the generic insert path also synchronizes the table's sequence afterwards.

Because native `MERGE` under PostgreSQL's default `READ COMMITTED` isolation is still subject to a race where a concurrent transaction inserts the same row between the match phase and the write, `execute()` catches `IntegrityConstraintViolationException` and retries the statement once, so the now-existing row is matched and updated instead. A new `\Drupal\Tests\pgsql\Kernel\pgsql\MergeTest` covers the native SQL string, single-statement execution, the no-update-match case, expressions, blob fields, and each fallback-to-emulation scenario.</technical>
