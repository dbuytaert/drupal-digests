## Summary

Recipes that configure a CKEditor 5 toolbar can now add several buttons in a single step. Previously the `addItemToToolbar` config action only accepted one toolbar item at a time, so a recipe that needed to add several buttons had to repeat the action once per button. The new `addItemsToToolbar` action accepts a list of items, each either a button name or an options array (for example to set `position` or `allow_duplicate`), and applies them all in one pass.

## Impact

Affects module maintainers.

- **New API:** New `hook_config_action_alter()` lets modules alter or alias config action plugin definitions, and a new `editor:addItemsToToolbar` config action adds multiple CKEditor 5 toolbar items in a single recipe action.

## Technical details

`Drupal\ckeditor5\Plugin\ConfigAction\AddItemToToolbar::apply()` now normalizes its `$value` argument: a plain string or an associative array is treated as a single item and wrapped in a list, while an indexed array is treated as multiple items. Each item is delegated to a new private `applySingle()` method, which contains the original per-item logic (position, replace, allow_duplicate, plugin default configuration), and the editor entity is saved only once at the end if anything actually changed. Invalid input, an empty list, a non-string/array item, or an item missing `item_name`, now throws a `ConfigActionException` with a descriptive message instead of failing a silent `assert()`.

Because the `#[ConfigAction]` attribute isn't repeatable, the plural `addItemsToToolbar` isn't a second plugin class: it's registered as an alias of `editor:addItemToToolbar` inside `Ckeditor5Hooks::configActionAlter()`, which implements the new `hook_config_action_alter()` documented in `core.api.php`. That hook receives the config action plugin definitions array by reference and lets any module copy or alter entries, here it copies the `editor:addItemToToolbar` definition to a new `editor:addItemsToToolbar` key and gives it its own `admin_label`. Maintainers noted in review that using an alter hook for aliasing is a stopgap that decouples the plural action from its singular definition, and that dedicated alias support on the `ConfigAction` attribute would be a cleaner long term solution, left as a followup.

## Upgrade

To add multiple CKEditor 5 toolbar buttons in a recipe, replace repeated `addItemToToolbar` calls with a single `addItemsToToolbar` call taking a list:

```yaml
config:
  actions:
    editor.editor.content_format:
      addItemsToToolbar:
        - specialCharacters
        - codeBlock
        -
          item_name: italic
          position: 0
          allow_duplicate: true
```

Modules can also implement `hook_config_action_alter(array &$definitions)` to alias or otherwise alter any config action plugin definition, not just this one.
