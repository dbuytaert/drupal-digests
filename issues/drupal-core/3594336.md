## Summary

Drupal core's console (`dr`) gets an `ex:list` command that lists the modules and themes on a site. The output is a table of package, name (with machine name), install status and version. It can instead be printed as JSON or YAML. Filter options narrow the list by extension type, core or non-core, package and install status. It is the counterpart of Drush's `pm:list`, and it is part of the CLI in Core initiative ([#3582246](https://www.drupal.org/node/3582246)).

## Impact

Affects module maintainers.

- **New API:** New `Drupal\Core\Command\OutputFormat` enum (`Yaml`, `Json`) for console command output formats.

## Technical details

The command is `Drupal\Core\Extension\Command\ExtensionListCommand`, marked `@internal` and declared with the `#[AsCommand]` attribute. Its options use Symfony's `#[Option]` attributes: `--core/--no-core`, `--type` (the existing `ExtensionType` enum), `--package` (comma delimited, case insensitive), `--installed/--no-installed` and `--format`. It merges the lists from `ModuleExtensionList` and `ThemeExtensionList`. It always skips extensions whose path contains `tests`. The `--core` filter relies on `$extension->origin`, which themes lack, so there is a `@todo` pointing to [#3605703](https://www.drupal.org/node/3605703). Without `--format` the output is a Symfony `Table`. With it, the rows are encoded by `json_encode()` or `Yaml::encode()`, using the new `Drupal\Core\Command\OutputFormat` backed enum. The command is registered under `ex:list` and currently also carries the aliases `pm:list` and `pml`. A reviewer (see collaboration) suggested replacing these with `exl`. Table formatting and line length were left to [#3611694](https://www.drupal.org/node/3611694). Making `OutputFormat` extensible is tracked in [#3629792](https://www.drupal.org/node/3629792). A kernel test, `ExtensionListCommandTest`, covers the JSON output, the filters and the table output.
