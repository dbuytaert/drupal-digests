## Summary

As part of converting the locale module to object-oriented code, six procedural helper functions in `locale.module` are now deprecated: `locale_translation_use_remote_source()`, `locale_string_is_safe()`, `locale_translatable_language_list()`, `locale_js_translate()`, `locale_translation_language_table()`, and `locale_is_translatable()`. Calling any of them now triggers a deprecation notice, and they will be removed in Drupal 13.0.0. Most gained a direct service or static-method replacement; two (`locale_translation_use_remote_source()` and `locale_translation_language_table()`) have no replacement because their logic was inlined into the code that used to call them. This only affects code that calls these functions directly (custom or contributed modules); regular site administrators are not affected.

## Impact

Affects module maintainers.

- **Deprecation:** Procedural functions `locale_string_is_safe()`, `locale_translatable_language_list()`, `locale_is_translatable()`, `locale_js_translate()`, `locale_translation_language_table()`, and `locale_translation_use_remote_source()` are deprecated in Drupal 11.5.0 and removed in 13.0.0.
- **New API:** New `Drupal\locale\LocaleLanguages` service (`getTranslatableLanguages()`, `isTranslatable()`) and new `Drupal\locale\LocaleXss` class (`stringIsSafe()`) replace the deprecated locale functions.

## Technical details

The deprecated function bodies now just call the new location and stay as thin wrappers that raise `E_USER_DEPRECATED`. `locale_string_is_safe()` moved verbatim to `LocaleXss::stringIsSafe()`. `locale_translatable_language_list()` and `locale_is_translatable()` moved to the new `LocaleLanguages` service (`getTranslatableLanguages()` and `isTranslatable()`). `locale_js_translate()` moved to the new `LocaleJs::jsTranslate()` service, but that class is marked `@internal`, so the deprecation message points to a service that isn't part of the committed public API. `locale_translation_language_table()`'s logic was moved into a new `TranslationStatusForm::translationLanguageTable()` method and wired up as the form's `#after_build` callback instead of the old procedural callback. `locale_translation_use_remote_source()` had no natural home, so every caller was changed to inline the underlying config check (`$config->get('locale.settings')->get('translation.use_source') == LOCALE_TRANSLATION_USE_SOURCE_REMOTE_AND_LOCAL`) directly.

Introducing `LocaleLanguages` (and, in one case, `LocaleJs`) as an injected dependency required adding a new constructor parameter to numerous locale classes that previously called the procedural functions: several services (`LocaleFetch`, `LocaleProjectChecker`, `LocaleSource`, `LocaleConfigManager`, `LocaleFileManager`), forms (`ExportForm`, `ImportForm`, `TranslateFormBase`, `TranslationStatusForm`), hook classes (`LocaleHooks`, `LocaleFormHooks`, `LocaleThemeAlterHooks`, a new `LocaleThemeAlterHooks` split out of the old `LocaleFormHooks`), `LocaleRequirements`, and the `LocaleConfigSubscriber` event subscriber. Several of these classes were also modernized to constructor property promotion in the same pass. `LocaleThemeAlterHooks` is a newly split-out class holding the `hook_js_alter()` and `hook_library_info_alter()` implementations that used to live in `LocaleFormHooks`, and it now injects `LocaleJs` via an `#[AutowireServiceClosure]` to avoid a hard circular/unnecessary dependency.

## Upgrade

Replace direct calls to the deprecated functions:

```php
// Before
locale_string_is_safe($string);
locale_translatable_language_list();
locale_is_translatable($langcode);
locale_js_translate($files, $language);

// After
\Drupal\locale\LocaleXss::stringIsSafe($string);
\Drupal::service(\Drupal\locale\LocaleLanguages::class)->getTranslatableLanguages();
\Drupal::service(\Drupal\locale\LocaleLanguages::class)->isTranslatable($langcode);
\Drupal::service(\Drupal\locale\LocaleJs::class)->jsTranslate($files, $language);
```

For `locale_translation_use_remote_source()` and `locale_translation_language_table()`, there is no replacement API; inline the equivalent logic:

```php
// Before
locale_translation_use_remote_source();

// After
\Drupal::config('locale.settings')->get('translation.use_source') == LOCALE_TRANSLATION_USE_SOURCE_REMOTE_AND_LOCAL;
```

If a custom or contributed module extends any of the affected locale classes (for example `TranslateFormBase`, `ExportForm`, `ImportForm`, `TranslationStatusForm`, `LocaleFetch`, `LocaleSource`, `LocaleConfigManager`, `LocaleProjectChecker`, `LocaleFileManager`, or `LocaleConfigSubscriber`) and overrides its constructor, add the new `LocaleLanguages $localeLanguages` constructor argument (no backward-compatibility shim was added for these on `main`).
