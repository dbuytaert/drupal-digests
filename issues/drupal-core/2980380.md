## Summary

The error summary that Inline Form Errors shows at the top of a form, such as \"3 errors have been found:\" followed by links to the fields, now renders through a real Twig template. Before, the module built it as a raw render array, so themes had nothing to override. Themes and sites can now customize its markup, for example to match a base theme's alert styling, and can target a single form. The default output is almost the same as before. The only visible change is a `<span>` around the count text.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** The "N errors have been found:" summary now renders through a template, and the count text is wrapped in a new `<span>`.
- **New API:** New `inline_form_errors_summary` theme hook with `inline_form_errors_summary.html.twig` and an `inline_form_errors_summary__FORM_ID` suggestion.

## Technical details

`FormErrorHandler::displayErrorMessages()` used to build the summary from a `#markup` plural string plus an `item_list` render array. It now builds one render array with `#theme => 'inline_form_errors_summary'`, `#error_links` and `#form_id` (taken from `$form['#form_id']`), then passes it to `renderInIsolation()` and `addError()`. Each link is wrapped as `['value' => <link renderable>]` so the list is fed to `item-list.html.twig` as items.

`InlineFormErrorsThemeHooks` gains a `hook_theme()` implementation declaring the `error_links` and `form_id` variables. It also gains a `hook_theme_suggestions_inline_form_errors_summary()` implementation that adds `inline_form_errors_summary__FORM_ID` when a form ID is present. The new `inline_form_errors_summary.html.twig` uses `{% trans %}` with plural handling for the count, wraps the count text in a `<span>`, and includes `item-list.html.twig` with `context: {list_style: 'comma-list'}`.

`FormErrorHandlerTest` was refactored because the render array shape changed, and a test was added that checks the `#theme`, `#form_id` and `#error_links` values. `PathAliasTest` assertions were split into two `statusMessageContains()` calls because the span changes the whitespace around the text. Field-level inline error markup and the fieldset case from the original report were not touched. Only the summary got a template.

## Upgrade

To customize the summary, copy `core/modules/inline_form_errors/templates/inline_form_errors_summary.html.twig` into your theme. To target one form, name the copy after its form ID, for example `inline_form_errors_summary--node-article-form.html.twig`. Hyphens replace underscores in template filenames. Code that parsed the old summary text directly (for example `1 error has been found: URL alias`) should allow for the new `<span>` around the count text.

### Collaboration

The issue was opened in 2018 around a Bootstrap theming need and sat idle for years. smustgrave picked it up from [#2880011](https://www.drupal.org/node/2880011) and opened the MR. dcam reviewed it and suggested approaches. nicxvan pointed to `item-list` as the right template for a list. The final version moved the markup into a template that includes `item-list.html.twig`. alexpott committed it to `main` and also backported it to 12.0.x as a non-disruptive minor bug fix, since the markup change is only a new span and a change record covers the new template.
