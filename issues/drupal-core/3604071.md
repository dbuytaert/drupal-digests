## Summary

The default admin theme (`default_admin`) now defaults its light/dark mode setting to "Auto" instead of "Light". Previously, every new site forced the admin interface into light mode until an administrator manually changed it. Now the admin interface follows the visitor's operating system or browser color scheme preference out of the box, which is more accessible for people who need dark mode for visual comfort. The "Auto" option was also moved to the top of the settings list, ahead of "Light" and "Dark", to reflect that it's the recommended choice.

## Impact

Affects site owners.

- **Config change:** The `default_admin` theme's `enable_dark_mode` setting now defaults to `auto` (follow system/browser preference) instead of `0` (light mode).

## Technical details

The change is a one-line default flip in `core/themes/default_admin/config/install/default_admin.settings.yml`, where `enable_dark_mode: '0'` becomes `enable_dark_mode: 'auto'`. The corresponding `#options` array in `Settings::getSettingsForm()` (`default_admin/src/Settings.php`) was reordered to list `auto` before the numeric `0`/`1` (Light/Dark) options. This only affects the shipped default configuration and new installs; existing sites that already have `default_admin.settings` configured keep their current `enable_dark_mode` value unless reset. Functional tests in `AdminTest.php` were updated to assert `"dark_mode":"auto"` in the rendered settings JSON instead of `"dark_mode":"0"`.

This was landed ahead of the broader dark-mode rework tracked in [#3606655](https://www.drupal.org/node/3606655), which the maintainer noted would make these specific settings redundant; [#3604071](https://www.drupal.org/node/3604071) was still committed separately as an accessibility improvement in case the larger issue does not land before the next release.
