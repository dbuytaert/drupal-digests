## Summary

Drupal core's bundled htmx JavaScript library is updated from 4.0.0 to 4.0.1. The issue says one fix in this release affects `hx-partial`, a new htmx 4 feature. The release also fixes other htmx behavior around request handling, triggers, out-of-band swaps and history. Sites and modules that build on core's HTMX support get the fixes automatically, with no code changes. The change was committed to `main` and 12.0.x.

## Impact

No upgrade or configuration changes required.

## Technical details

The `htmx` library definition in `core/core.libraries.yml` now points to version `4.0.1`, with the license URL updated to match. `core/assets/vendor/htmx/htmx.min.js` was regenerated, and `package.json` and `yarn.lock` pin `htmx.org` at 4.0.1. The unminified source diff shows these behavior changes:

- `hx-action`, the verb attributes (`hx-get`, `hx-post` and so on), `hx-trigger` and `hx-validate` no longer pick up implicit inheritance from ancestors. `#attributeValue` gained an `allowInheritance` argument for this.
- `hx-trigger` now accepts `every 1s [cond]`. The `changed` modifier is tracked per event target. A new trigger cancels any pending delayed or throttled trigger on the same element. `intersect` now observes the `from:` elements.
- Boosted elements now go through `#initializeTriggers`.
- Indicators and disabled elements are tracked on `ctx.indicators` and `ctx.disabledElements`. A request that is replaced no longer releases the queue slot of the request that replaced it. `AbortError` no longer fires `htmx:error`, except for timeouts. A swap is skipped if the target was removed while the request was in flight.
- Out-of-band targets are resolved relative to the source element, and `swapStyle:selector` parsing was changed. The `ignoreTitle` swap modifier is now honored in more places. A scroll or show target of `window` or `document` is handled.
- History is now stamped with `replaceState` on the first htmx swap rather than at initialization, and it is updated only after a swap is confirmed.
- `htmx.ajax()` rejects with "Target not found" when an explicit `target` can't be resolved.
- A named submit button that owns `hx-post` is treated as the submitter.
- HTML is parsed with `Document.parseHTMLUnsafe(trusted, {})` as a workaround for Chrome 150 to 156 dropping comments.
