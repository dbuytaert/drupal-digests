## Summary

Procedural `.module` files are now deprecated, and so are `.profile` files. Drupal emits one deprecation notice per file, naming the file. This tells module and profile maintainers to move any remaining code into classes: hooks into hook classes, other functions into services or other classes. The deprecation applies to the files, not to modules as an extension type. The notice is only emitted on `main` and 12.0.x. It was not backported to 11.5.x, although the deprecation text says 11.5.0 and the change record (https://www.drupal.org/node/3619765) is published. Core's own `.module` files are converted. The ones that still hold deprecated legacy functions are marked with the attribute to stay quiet.

## Impact

Affects module maintainers.

- **Deprecation:** Code in `.module` and `.profile` files is deprecated in drupal:11.5.0 and must be converted before drupal:13.0.0. The deprecation notice is emitted only on `main` and 12.0.x, not on 11.x.
- **New API:** `#[ExtensionFileIsConverted]` is now also honoured in `.module` and `.profile` files. Put it on the first function in the file to suppress the deprecation notice.

## Technical details

`HookCollectorPass` already scanned `.module` and `.profile` files for procedural hook implementations. It now records every such file it finds in a new `deprecatedFiles` property. In `writeToContainer()` it emits `Code in {name}.{ext} is deprecated in drupal:11.5.0 and must be converted before drupal:13.0.0. Use classes instead. See https://www.drupal.org/node/3619765`.

A file is removed from that list, so no notice is emitted, in two cases. First, if a function in it carries `#[ExtensionFileIsConverted]`. Second, if every function in it carries `#[LegacyHook]` or `#[LegacyRequirementsHook]` (so a file holding only legacy hook wrappers produces no notice). The result is cached under a new `@skip_extension_file_deprecation` key.

The procedural scan used to be skipped entirely when `$skip_procedural` was set or `#[ProceduralHookScanStop]` was hit. Deprecation detection needs to see every function in the file, so the scan now always runs. When either skip condition applies, it only stops adding hooks to the hook map and keeps looking for non-legacy functions. The cached structure changed from a flat list to `['hooks' => [...], '@skip_extension_file_deprecation' => TRUE]`. The file-cache keys were bumped (`hook_implementations:1`, `procedural_hook_implementations:1:...`) so old entries are not reused.

The attribute can only target a function. A `.module` file that contains no functions therefore needs a dummy function to carry it, as discussed in the thread. The `.theme` collector got the same treatment and its message text was aligned with the module wording (`Code in ... is deprecated ... must be converted before drupal:13.0.0`). Core `.module` files that still hold deprecated legacy functions (for example `text_summary()`, `filter_formats()`, `views_add_contextual_links()`) got `#[ExtensionFileIsConverted]`. Legacy test modules and profiles that intentionally keep procedural code now expect the deprecation in their tests. The related theme change is [#3581218](https://www.drupal.org/node/3581218).

## Upgrade

To silence the notice while a `.module` file must remain (for example to support older core), add the attribute to the first function in the file, as core did:

```php
use Drupal\Core\Hook\Attribute\ExtensionFileIsConverted;

#[ExtensionFileIsConverted]
function text_summary($text, $format = NULL, $size = NULL) {
```

Per the attribute docs, use it only for legacy support. If your minimum supported core is 11.3.0 or later, convert the file's contents to classes and remove the `.module` file. See https://www.drupal.org/node/3619765.

### Collaboration

The issue first landed on `main` and 12.0.x. alexpott then tried an 11.x backport and hit conflicts, including `hook_hook_info()` implementations in system and views and a missing earlier theme change. After discussion with nicxvan, berdir, catch and xjm, the group agreed not to backport it. berdir noted that the deprecation noise would hit contrib sooner on 11.x. The issue was left marked as an 11.5.0 release highlight because the change record is already published and the attribute already exists in 11.5.x. Earlier, alexpott found that the first scan-stop or skip-procedural function suppressed the deprecation. His added tests exposed this, and nicxvan changed the scan to continue past those functions.
