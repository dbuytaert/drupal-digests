## Summary

The scaffolded `.htaccess` no longer sets the `assert.active` PHP directive, which is deprecated in PHP 8.3 and can log a deprecation under Apache with `mod_php`. It now sets `zend.assertions` to `0` (assertions compiled in but skipped). Comments recommend `1` on development machines and `0` or `-1` in production. The fix was committed to `main` and backported to 12.0.x, 11.x, 11.5.x, 11.4.x, 11.3.x and 10.6.x. Release managers said it needs a release note because it changes a scaffolded, site-owner-managed file.

## Impact

Affects site owners.

- **Config change:** Scaffolded `.htaccess` now sets `php_value zend.assertions 0` instead of `php_value assert.active 0`.

## Technical details

The `.htaccess` template (`php_value assert.active 0` inside `<IfModule mod_php.c>`) is replaced with `php_value zend.assertions 0`, plus a comment pointing to the PHP manual. The header comment is reworded to say the block is for PHP settings that cannot be changed at runtime. The docblock in `default.settings.php` is also updated. It now says to set `zend.assertions=1` in `php.ini` on development machines and `0` or `-1` in production, with a `@see` link to the PHP manual. It no longer claims the setting cannot be changed from `.htaccess`.

Background from the thread: [#3375693](https://www.drupal.org/node/3375693) removed the `assert_options()` calls and the assertion-enabling code in `example.settings.local.php`. It left `assert.active 0` in `.htaccess`. Under Apache with `mod_php`, that value still takes effect. A `settings.local.php` that only sets `zend.assertions` therefore could not turn assertions back on. Using `zend.assertions` in `.htaccess` restores the documented way to enable them.

The thread notes that `zend.assertions` can only be fully enabled or disabled in `php.ini`. If `php.ini` sets it to `-1`, the `.htaccess` line can trigger a PHP warning in the Apache log. Participants suggested that such sites remove the line or ignore the warning. A related question, whether tests should force assertions on, was split off to a gitlab_templates issue (3500234).

## Upgrade

Existing sites keep their current `.htaccess`, because it is a scaffolded file. To pick up the change, update the block manually or re-scaffold:

```
<IfModule mod_php.c>
  php_value zend.assertions 0
</IfModule>
```

If your PHP config sets `zend.assertions` to `-1`, you can remove that line.
