## Summary

Sites running Drupal 10.6.x or 11.3.x with `drupal/core-recommended` were previously locked to exact patch versions of Guzzle, Twig, and Symfony's polyfill packages. Because these libraries often ship security fixes only in new minor releases, Composer's security-advisory blocking could prevent `composer update` from resolving at all until Drupal core itself cut a new patch release with updated pins, sometimes requiring off-schedule releases every couple of weeks. This change widens those constraints on the 10.6.x and 11.3.x branches (matching a change already made for 11.4.x in [#3600889](https://www.drupal.org/node/3600889) and follow-up [#3612247](https://www.drupal.org/node/3612247)), so sites can now pull in upstream security fixes for these transitive dependencies directly via `composer update` without waiting on a core release.

## Impact

Affects site owners.

- **Config change:** In `drupal/core-recommended`'s generated composer.json for 10.6.x and 11.3.x, exact-version constraints on `guzzlehttp/guzzle`, `guzzlehttp/promises`, `guzzlehttp/psr7`, `twig/twig`, and the `symfony/polyfill-*` packages are no longer pinned, matching what already shipped for 11.4.x.

## Technical details

The fix is in `Drupal\Composer\Composer::getPackage()` (used to generate `core-recommended`'s composer.json from `composer.lock`), which builds a `$remove_list` of packages to exclude from the generated `require` section instead of copying their locked exact version. `guzzlehttp/guzzle`, `guzzlehttp/promises`, `guzzlehttp/psr7`, `twig/twig`, and the relevant `symfony/polyfill-*` packages (the set differs slightly between branches: 10.6.x includes `symfony/polyfill-php83`, 11.3.x includes `symfony/polyfill-php84` and `symfony/polyfill-php85`) were added to this list for both the 10.6.x commit `d30e4429` and the 11.3.x commit `ecffa56f`. The corresponding fixture composer.json files under core-recommended and the relevant test in `BuilderTest::builderTestData()` were updated to drop the now-removed pinned entries (e.g. `symfony/polyfill-ctype`).

Related issue [#3600889](https://www.drupal.org/node/3600889) made the equivalent change for the 11.4.x/main branches, and [#3612247](https://www.drupal.org/node/3612247) was an interim patch-release update of the Guzzle pins before this broader constraint-widening landed. [#3603733](https://www.drupal.org/node/3603733) was an earlier security update to the same pinned Guzzle versions.</technical>
<parameter name="collaboration">After the change was committed, several users reported in comments that their CI pipelines with `minimum-stability: dev` unexpectedly updated `drupal/core` itself to a `-dev` release. Catch diagnosed this: previously Composer's security-advisory blocking had silently prevented any update because the pinned Guzzle version was blocked, masking the `minimum-stability: dev` setting; once the pin was widened, updates could proceed and picked up the dev core release too. Catch recommended affected sites set `minimum-stability: stable` and require individual dev-only dependencies with `@dev` instead.
