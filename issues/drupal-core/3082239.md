## Summary

Partial (prefix) column lengths are now documented as valid only for indexes, not for primary or unique keys. Code that passes a column with a length, such as `['name', 10]`, in a primary key or unique key now triggers a deprecation notice. In Drupal 13 it will throw a `SchemaException`. Core has no such keys, so this mainly affects contrib and custom modules. Those should specify full columns, or move the partial-length columns to an index.

## Impact

Affects module maintainers.

- **Deprecation:** Specifying a column length (e.g. `[['name', 10]]`) in a primary key or unique key is deprecated in drupal:12.1.0 and will throw a `SchemaException` in drupal:13.0.0. `Schema::ensureNotNullPrimaryKey()` is deprecated in favour of `validatePrimaryKeySchema()`.
- **New API:** New protected `Schema::validatePrimaryKeySchema()` and `Schema::validateUniqueKeySchema()` methods for driver implementations.

## Technical details

The check runs in the shared `Schema` base class and is called from the MySQL, PostgreSQL and SQLite drivers. It covers `createTable()`, `addPrimaryKey()`, `addUniqueKey()`, `addField()` and `changeField()`. `validatePrimaryKeySchema()` emits the deprecation when any primary key column is an array. It also keeps the existing check that primary key fields are `not null`, which replaces `ensureNotNullPrimaryKey()`. `validateUniqueKeySchema()` emits the deprecation for unique keys. In the 12.x deprecation period the request is still processed. The PostgreSQL driver already ignored prefix lengths for primary and unique keys, and the deprecation message describes the length as disregarded.

The `addField()` primary key detection in the MySQL and PostgreSQL drivers now uses `fieldNames()`, so array-form key columns are handled. The `PrimaryKey` and `UniqueKey` value object docblocks no longer mention length arrays, and the Database API docs now say that partial length is for indexes only. The existing `SchemaUniquePrefixedKeysIndexTestBase` driver tests now expect the deprecation. A `@todo` notes that they should test full-length columns once 13.0.0 lands ([#3615136](https://www.drupal.org/node/3615136)). The change record is https://www.drupal.org/node/3375071.

## Upgrade

Replace partial-length columns in primary and unique keys with full columns, or move them to an index:

```php
// Deprecated in 12.1.0, throws SchemaException in 13.0.0.
'primary key' => [['test_field_1', 10]],
'unique keys' => ['test_unique_key' => [['test_field_1', 10]]],

// Use full columns for the key...
'primary key' => ['test_field_1'],
// ...or put the partial length on an index.
'indexes' => ['test_index' => [['test_field_1', 10]]],
```

Custom driver code that calls `ensureNotNullPrimaryKey()` should call `validatePrimaryKeySchema()` instead.
