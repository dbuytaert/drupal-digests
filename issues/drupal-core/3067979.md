## Summary

Starting with Drupal 12 (main), the `tests` directory under Drupal core is excluded from the packages that most sites actually download: the Composer "dist" zip and the release tarballs built by drupal.org. This shrinks the on-disk footprint of a typical Drupal installation (tests accounted for a large share of core's total file count) and removes test code, which the issue's participants noted has occasionally been a source of security concerns, from production deployments. Nothing changes for anyone working from a git checkout of core, including core contributors and the testbot. Sites and projects that need to run tests which rely on core's test base classes or core-only test modules (for example when testing custom or contributed code against core, or applying patches that touch test files) need to install `drupal/core` from source instead of from the default dist package.

## Impact

Affects site owners.

- **Requirements:** Projects that run automated tests extending core test base classes (e.g. `KernelTestBase`, `WebDriverTestBase`) or depending on core test-only modules must install `drupal/core` from source (e.g. `composer install --prefer-source` for that package) since dist packages/tarballs no longer ship `core/tests`.

## Technical details

The mechanism is a new `core/.gitattributes` file with a `tests export-ignore` (and `.gitattributes export-ignore`) directive. Drupal.org's packaging pipeline builds releases with `git-archive`, which honors `export-ignore`, so the entire `core/tests` directory is dropped from both the packaged tarball and the Composer dist zip without any change to the packaging scripts themselves.

This landed in three steps. The first commit (`5341dd83`) tried a fine-grained approach, excluding most test paths but carving out exceptions such as `modules/*/tests/src/` and `profiles/tests/testing/` so that base test classes contrib relies on (like `WebDriverTestBase`) would survive in dist packages. That broke contrib CI within hours because those base classes still depend on test-only helper modules (`js_testing_ajax_request_test`, `js_testing_log_test`, `css_disable_transitions_test`, `entity_test`, `performance_test`, etc.) that lived in the excluded paths, so it was reverted (`34b130bd`). After discussion of the maintenance burden of an ever-growing exceptions list versus the simplicity of `--prefer-source`, the maintainers landed a much simpler final version (`b8367add`): `core/.gitattributes` excludes the entire `tests` directory, with no carve-outs, on the understanding that anyone needing core's test infrastructure installs `drupal/core` from source.

Because Package Manager's own build tests assemble a Composer project from the checked-out core codebase, its `TemplateProjectTestBase::createTestProject()` now explicitly mirrors the `package_manager` module's own test modules into the built test project, since those modules are no longer present when core is installed as a dist package.

Follow-up work was split out rather than handled here: a gitlab_templates change to default CI to `--prefer-source` for `drupal/core`, plus separate issues [#3625050](https://www.drupal.org/node/3625050) (documenting composer-patches usage without patching tests) and [#3625358](https://www.drupal.org/node/3625358) (deciding what to do with `run-tests.sh` and similar dev scripts in dist builds, which currently fail without the excluded test code).</technical>
<parameter name="upgrade">If your project or CI pipeline runs tests that depend on Drupal core's test base classes, traits, or test-only modules (for example `Drupal\Tests\...\KernelTestBase`, `WebDriverTestBase`, or fixture/test modules under `core/tests` or `core/modules/*/tests`), install `drupal/core` from source rather than from dist, for instance:
```
composer install --prefer-source
```
or, to target only core:
```
composer config --global preferred-install.drupal/core source
```
Patches that modify files under any `tests` directory will also fail to apply against a dist install of core; see [#3625050](https://www.drupal.org/node/3625050) for guidance on stripping test-only changes from patches.
