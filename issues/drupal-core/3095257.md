## Summary

Required entity reference fields using the "Select list" widget (for example a required taxonomy term reference) could silently corrupt data. If the referenced entity was deleted, or became inaccessible to the current user, the widget's usual "- Select a value -" placeholder disappeared and the select box defaulted to the first available option instead. Editors who saved the form without noticing would overwrite the field with an unintended value. Now, when a required single-value select has no valid selection, the widget adds a "- Select a value -" option and forces the editor to explicitly pick a real value before the form can be saved, rather than defaulting to an arbitrary option.

## Impact

No upgrade or configuration changes required.

## Technical details

The bug was in `OptionsSelectWidget::getEmptyLabel()`, which decided whether to show a placeholder option based solely on `$this->has_value` (whether the field item list originally had a value), not on whether that value was still present among the currently available options. When a referenced entity was deleted or became inaccessible, `has_value` remained `TRUE` even though the resulting default value was empty, so no placeholder was added and the browser's `<select>` fell back to auto-selecting its first `<option>`.

The fix moves the decision into `OptionsSelectWidget::formElement()`: it computes `$options` and `$selected` directly, determines whether the field will render as a `multiple` select (accounting for the case where a multi-value field collapses to a single select because only one option remains), and if the field is `required`, not `multiple`, and `$selected` is empty, prepends a synthetic `_none` option labeled "- Select a value -" so the browser has an explicit non-answer to fall back to instead of the first real option. `getEmptyLabel()` itself is simplified to only return `'- None -'` for non-required fields (used elsewhere for the optional case) and no longer inspects `has_value` at all.

The fix intentionally preserves existing auto-select behavior for multi-value (multiple-select) widgets and for the case where a required field has exactly one available option and no prior value (for example when creating a new entity), since changing that was judged out of scope; a UX warning for the "value became unavailable" case was deferred to follow-up [#3623828](https://www.drupal.org/node/3623828), and a broader entity-reference-on-delete data integrity concern was noted for a separate follow-up issue.</technical>
