## Summary

Install profiles can now declare that they should never be installed as a module in their own right. Adding `opt_out_install: true` to a profile's `.info.yml` tells the installer to skip the step where the profile itself is enabled after its modules and configuration are in place. This is aimed at minimal profiles used for testing or automated environments that have no hooks of their own to run, so there is no reason to keep them installed as a module. Drupal core's own `testing` and `testing_nightwatch` profiles are now marked this way.

## Impact

Affects module maintainers.

- **New API:** New `opt_out_install` key in an install profile's `.info.yml` lets the profile skip being installed as a module at the end of the installer.

## Technical details

The installer reads each profile's parsed info array into `$install_state['profile_info']` (via `install_profile_info()`). `install_install_profile()` in `install.core.inc` now checks `$install_state['profile_info']['opt_out_install']` before calling `\Drupal::service('module_installer')->install()` on the profile itself, skipping that call when the key is truthy. `drupal_install_system()` in `install.inc` was likewise updated so that the `core.extension` config's `profile` key is cleared (not just when there is no profile at all) whenever the profile has opted out, keeping the stored configuration consistent with the fact that the profile was never installed as a module.

Because the core `testing` profile is used by hundreds of tests and now opts out, several tests that relied on the `testing` profile's optional configuration (a body field on `node`, and a locale config override) had to be reworked: the body field was extracted into a new `body_field` test module, and a new `testing_locale` profile was added that still gets installed and carries the locale-specific config for the handful of tests that depend on it. A new `testing_skip_install` profile, whose `hook_install()` throws an exception, was added purely as test coverage ([#3614401](https://www.drupal.org/node/3614401)'s `ProfileSkipInstallTest`) to prove the opt-out path never runs the profile's install hook. This work builds on [#3614153](https://www.drupal.org/node/3614153), which moved the System module install step earlier in the installer.

## Upgrade

Add `opt_out_install: true` to an install profile's `.info.yml` if the profile has no `hook_install()` or other behavior that depends on being installed as a module:

```yaml
name: My minimal profile
type: profile
opt_out_install: true
```

Profiles that rely on optional configuration tied to the profile's own module weight, or that implement install hooks, should not set this key.
