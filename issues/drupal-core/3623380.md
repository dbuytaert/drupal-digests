## Summary

Installation profiles can now provide their custom install tasks and task alterations through a class instead of `hook_install_tasks()` and `hook_install_tasks_alter()` in the `.profile` file. This removes one of the remaining reasons profiles need a procedural `.profile` file. The old procedural hooks still work but now trigger deprecation errors.

## Impact

Affects module maintainers.

- **Deprecation:** Procedural `hook_install_tasks()` and `hook_install_tasks_alter()` are deprecated in drupal:11.5.0 and removed from drupal:13.0.0.
- **New API:** New `\Drupal\Core\Extension\Install\TasksInterface` with `getTasks(array &$install_state): array` and `alter(array &$tasks, array $install_state): void`.

## Technical details

A profile adds a class in `src/Install/Tasks/` (namespace `Drupal\PROFILE_NAME\Install\Tasks`) that implements `\Drupal\Core\Extension\Install\TasksInterface`. `getTasks(array &$install_state)` replaces `hook_install_tasks()` and `alter(array &$tasks, array $install_state)` replaces `hook_install_tasks_alter()`. The class is created through `\Drupal::classResolver()`, so it can implement `ContainerInjectionInterface`. Only core services can safely be injected, because this runs before the install is complete.

In `install.core.inc`, `install_tasks()` calls the new `install_get_tasks()` and `install_alter_tasks()` helpers (both `@internal`). The procedural `PROFILE_install_tasks()` and `PROFILE_install_tasks_alter()` are only called when no OOP implementation supplied tasks (for `getTasks`) or exists (for `alter`). When the procedural fallback runs, it triggers an `E_USER_DEPRECATED` error pointing to https://www.drupal.org/node/3623397. The profile file is still loaded before `alter()`, so the class can rely on functions defined there.

The directory scan that `install_check_class_requirements()` used to find `Install/Requirements` classes was extracted into `install_get_fixed_class_name()`, which now serves both lookups. It `require_once`s each PHP file in the directory and keeps the class name of the last file it finds, so keep one class per `Install/Tasks` directory. The hook docs in `core.api.php` were updated with the `@deprecated` notes. Follow-up [#3630429](https://www.drupal.org/node/3630429) is about changing the doc wording on state versus key value expirable.

## Upgrade

Move the procedural hooks into a class, for example `src/Install/Tasks/MyProfileTasks.php`:
```php
namespace Drupal\myprofile\Install\Tasks;

use Drupal\Core\Extension\Install\TasksInterface;

class MyProfileTasks implements TasksInterface {

  public function getTasks(array &$install_state): array {
    // Return what myprofile_install_tasks() returned.
    return [];
  }

  public function alter(array &$tasks, array $install_state): void {
    // Body of myprofile_install_tasks_alter().
  }

}
```
Then remove `myprofile_install_tasks()` and `myprofile_install_tasks_alter()` from the `.profile` file. If the class exists, the procedural versions are ignored.
