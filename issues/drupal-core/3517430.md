## Summary

Drupal core's test tooling now supports a `#[Skip]` attribute for marking PHPUnit test methods as skipped, as an alternative to calling `$this->markTestSkipped()` inside the test body. This makes it obvious from the method's declaration alone that it is skipped, and it takes effect before the test's `setUp()` runs, so any expensive or Drupal-bootstrapping setup logic is avoided for skipped tests. This is relevant to anyone writing PHPUnit tests against Drupal's test base classes, including contrib module maintainers.

## Impact

Affects module maintainers.

- **New API:** New `Drupal\TestTools\Attribute\Skip` PHP attribute to mark a PHPUnit test method as skipped, with an optional message.

## Technical details

The new `Skip` attribute class lives in `core/tests/Drupal/TestTools/Attribute/Skip.php`, targets methods only (`#[\Attribute(\Attribute::TARGET_METHOD)]`), and takes an optional `$message` constructor argument that is passed through to `markTestSkipped()`.

Support for the attribute is wired into `Drupal\Tests\DrupalTestCase` via a new `skipTestWithAttribute()` method registered with `#[Before(200)]`, a high priority chosen so it runs before any `setUp()` logic. It reflects on the current test method for a `Skip` attribute instance and, if found, calls `static::markTestSkipped($attribute->newInstance()->message)`. Since `DrupalTestCase` is the common ancestor for Drupal's PHPUnit base classes, the attribute works across unit, kernel, and functional tests. Two existing skips in core were converted as examples: `EditorValidationTest::testLabelValidation` (no message) and `SettingsTest::testRealDeprecatedSettings` (with a message), both replacing an inline `markTestSkipped()` call with `#[Skip(...)]` on the method.

A follow-up commit (`f7eadfbe`) also removed the skip from `testRealDeprecatedSettings` on the `11.x` branch after #24 and #25 established it should no longer be skipped there, since the underlying setting deprecation issues ([#3591513](https://www.drupal.org/node/3591513), [#3613344](https://www.drupal.org/node/3613344)) had landed.

## Upgrade

Test authors can replace an in-body skip with the attribute:

```php
// Before:
public function testSomething(): void {
  $this->markTestSkipped('Reason here.');
  // ...
}

// After:
use Drupal\TestTools\Attribute\Skip;

#[Skip('Reason here.')]
public function testSomething(): void {
  // ...
}
```

The message argument is optional; `#[Skip]` alone is valid.

### Collaboration

dcam prototyped the feature after being inspired by a related issue ([#3615036](https://www.drupal.org/node/3615036)) about marking tests skipped in `setUp()`, converting two existing skips to prove it worked, and wrote the initial change record. mondrake suggested renaming the attribute from an earlier working name to the simpler `#[Skip]` to match the naming style of upcoming PHPUnit `#[Retry]`/`#[Repeat]` attributes, which dcam adopted. catch weighed in that core doesn't need to wait on upstream PHPUnit support given the small number of skipped tests expected, a view dcam agreed with, noting a homegrown solution could later be deprecated if PHPUnit added equivalent support. godotislate committed the change after making small review tweaks (using `static::markTestSkipped()` instead of `$this->`, and reading the message via `$attribute->newInstance()->message`), then during backport review caught that `testRealDeprecatedSettings` should no longer be skipped on `11.x` at all, which mstrelan confirmed based on prior involvement in the related deprecation issue, leading to that skip being removed on the `11.x` branch.
