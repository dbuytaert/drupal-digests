## Summary

As part of moving Search out of Drupal core into a contrib module, the Umami demo theme has had all of its search-specific theming removed. Umami no longer ships custom templates, CSS, or a keyword placeholder for the search block and search results page, and its breadcrumb logic no longer special-cases search page titles. If you run the Umami profile and separately install the contrib Search module, the search form and results will render with Drupal's default markup and styling instead of Umami's custom design.

## Impact

Affects front-end developers.

- **Theme change:** The Umami demo theme no longer overrides search markup or styling: `block--search-form-block.html.twig`, `search-result.html.twig`, and `item-list--search-results.html.twig` are deleted, the `classy.search-results` library and `css/components/blocks/search/*.css` are removed from `umami.libraries.yml`, and the custom search placeholder text and search-icon SVG are gone.

## Technical details

The change strips every trace of the Search module from the `umami` theme. `umami.theme` no longer implements `hook_form_search_block_form_alter()` (which set a "Search by keyword, ingredient, dish" placeholder), and `preprocessBreadcrumb()` drops its special case for `SearchPageInterface` entities, now always resolving the current page title via the `title_resolver` service. The Twig overrides `block--search-form-block.html.twig`, `search-result.html.twig`, and `item-list--search-results.html.twig` are deleted along with their CSS (`search.css`, `search-results.css`, and the classy `search-results.css`), the `classy.search-results` library entry, and the search icon SVG. The global CSS library no longer attaches the search block/results stylesheets, and several performance test fixtures were updated to reflect the reduced stylesheet byte counts. The fix landed on `main` (commit `dde124da`) and was backported to `11.x` (commit `e943d853`).
