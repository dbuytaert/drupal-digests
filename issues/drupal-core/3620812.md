## Summary

Sites that use the core Toolbar module together with Workspaces continue to see the workspace switcher tab in the toolbar exactly as before. This is an internal reorganization: the code that renders that tab now lives in the Toolbar module instead of the Workspaces UI module, but no toolbar behavior changes for site owners.

## Impact

No upgrade or configuration changes required.

## Technical details

Previously, `workspaces_ui` owned a `workspaces_ui.lazy_builders` service (`WorkspacesUiLazyBuilders`) and a `drupal.workspaces_ui.toolbar` library that `toolbar`'s `ToolbarHooks::workspacesUiToolbar()` depended on via `#lazy_builder` and an attached library, creating a dependency in the "wrong" direction (a UI module reaching into toolbar internals). This commit relocates that class into `Drupal\toolbar` as `WorkspacesUiToolbarLinkBuilder`, registered as `toolbar.workspaces_ui_link_builder` in `toolbar.services.yml`, and moves its CSS into a new `toolbar.workspaces_ui` library in `toolbar.libraries.yml` (the old `drupal.workspaces_ui.toolbar` library and its CSS are removed from `workspaces_ui`).

The initial patch simply deleted the toolbar integration from `workspaces_ui`, but reviewers `longwave` and `larowlan` objected that sites already using Toolbar (rather than the newer Navigation module) would silently lose the workspaces tab on upgrade, since Toolbar was still the default for many 11.0-11.3 sites until Navigation stabilized in 11.4. The approach was changed to a move instead of a removal.

The new `toolbar.workspaces_ui_link_builder` service is always registered, but its `WorkspaceManagerInterface` constructor argument is optional (`@?workspaces.manager`), so the service is inert when Workspaces isn't installed. Similarly, `NavigationServiceProvider` now checks `container.modules` for `workspaces_ui` instead of checking for the now-removed `workspaces_ui.lazy_builders` service when conditionally registering `navigation.workspaces_lazy_builders`. The `WorkspacesLazyBuilder` used by Navigation is a separate, unrelated class from the one moved here.

### Collaboration

The initial patch removed workspaces support from Toolbar entirely, on the reasoning (stated by `catch`) that "people can move to navigation if they want all bells and whistles." `gábor hojtsy` initially agreed this was fine given prior scoping in [#3618746](https://www.drupal.org/node/3618746). But `longwave` raised a concrete upgrade concern: sites still on Toolbar (common for anyone who adopted Drupal before Navigation left experimental status in 11.4) would lose the feature going from 11.4 to 11.5 with no equivalent in Toolbar. `larowlan` agreed, expecting the code to be moved into `toolbar` rather than dropped. `gábor hojtsy` then reworked the patch into a move (a net +30 lines across 11 files) instead of a removal. `longwave` further suggested always registering the lazy builder service rather than conditionally, to avoid extra complexity since an unused service is harmless; `gábor hojtsy` adopted a nullable-argument pattern for this, noting it differed from the existing conditional-registration pattern used by `NavigationServiceProvider`. `amateescu` confirmed the revised, move-based approach was "much more update friendly."
