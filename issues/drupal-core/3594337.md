## Summary

Drupal core's `dr` command line tool gains a `config:export` command. It writes the site's active configuration into the configured sync directory, matching what the Configuration UI export produces. It shows a table of what will be created, updated, deleted or renamed, and asks for confirmation unless `--yes` (`-y`) is passed. If the sync directory already matches, it reports that and does nothing. This is part of the CLI in Core initiative ([#3582246](https://www.drupal.org/node/3582246)) and is useful for deployment workflows and keeping config in source control.

## Impact

Affects module maintainers.

- **New API:** New `config:export` console command (`Drupal\Core\Config\Command\ConfigExportCommand`, marked `@internal`) run via `dr config:export`, with a `--yes`/`-y` option.

## Technical details

`ConfigExportCommand` is registered with `#[AsCommand(name: 'config:export')]` and autowires the `config.storage.export` service, the same export storage the UI uses. Because of that, config overrides (such as `$config` settings overrides) are not exported, and export transformers (for example from `config_transformer_test` in the tests) are applied. It also takes the `SyncFactory` service. The sync storage is resolved inside `__invoke()` rather than the constructor. `SyncFactory::get()` throws `ConfigDirectoryNotDefinedException` when no sync directory is configured, and a throwing constructor would break `dr list` for every command. The command catches that exception, prints the message and returns `FAILURE`.\n\nA `StorageComparer` between export and sync storage builds the changelist. With no changes it prints a success message and exits. Otherwise `renderTable()` prints Collection, Config and Operation columns, with renames shown as `old -> new`. After confirmation the command calls `replaceStorageContents()` from `StorageCopyTrait`, which replaces the sync contents with the export. Declining the confirmation throws `UserAbortException`. A kernel test, `ConfigExportCommandTest`, covers the missing directory case, `--yes`, the no-changes case, cancelling, and transformers being applied. A PHPStan baseline entry was added for the missing return type on `replaceStorageContents()`.
