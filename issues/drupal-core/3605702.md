## Summary

Drupal core's new "Default Admin" theme (the experimental successor being built from Gin, intended to eventually replace Claro) was forked with many leftover `gin` and `claro` names baked into its CSS classes, data attributes, JavaScript behaviors, settings, and local storage keys. This issue is the tracking/implementation issue for a full cleanup: renaming those implementation details to a consistent Default Admin naming scheme, while keeping an explicitly reviewed and documented allowlist for names that legitimately still need to reference Gin or Claro (historical attribution, upstream project links, or a persisted configuration value). No visual or behavioral regressions are intended; this is a naming and internal-consistency cleanup, not a redesign.

## Impact

No upgrade or configuration changes required.

## Technical details

The commit touches 173 files across the `default_admin` theme (CSS/PCSS sources and their compiled output, JS, PHP hook classes, Twig templates, and tests). CSS selectors and custom properties lost their `gin-`/`claro` prefixes, for example `.gin-details` to `.details`, `.gin-breadcrumb__*` to `.breadcrumb__*`, `[data-gin-accent]` to `[data-accent]`, `[data-gin-layout-density]` to `[data-layout-density]`, `.gin--dark-mode` to `.dark-mode`, and `@keyframes gin-throbber`/`claro-throbber` merged into a single `throbber` keyframe. On the JS side, `Drupal.behaviors.ginSettings` became `Drupal.behaviors.adminSettings`, `Drupal.ginSettings`/`Drupal.ginAccent` became `Drupal.adminAccent`/`Drupal.adminSettings`, and `drupalSettings.gin` became `drupalSettings.defaultAdmin` in `ThemeHooks::pagePreRender()`; the old `drupalSettings.gin` key is deliberately still populated as a compatibility alias "while the theme is experimental" per an entry in the new allowlist. PHP-side form classes (`FormHooks`) renamed attribute/class names such as `gin-sticky-form-actions` to `sticky-form-actions` and `gin-sidebar` to `admin-sidebar`.

Persisted browser state is migrated rather than silently dropped: `migration/js/init.js` now runs a `migrateLegacyStorage()` routine that copies old keys like `GinSidebarOpen`, `Drupal.gin.toolbarExpanded`, `Drupal.gin.sidebarExpanded.mobile/desktop`, and `Drupal.gin.sidebarWidth` into their new `Drupal.navigation.sidebarExpanded` / `Drupal.defaultAdmin.sidebarExpanded.*` / `Drupal.defaultAdmin.sidebarWidth` equivalents (without overwriting an already-set new value) before removing the legacy keys; purely internal flags like `GinDarkMode` are just deleted. A stored theme setting value of `preset_focus_color: 'claro'` is intentionally kept as a machine name (its label changed from "Claro Green" to "Legacy green") so existing site configuration keeps working.

To prevent regressions, the change adds `ImplementationNameTest` (a unit test scanning theme source for a list of superseded `gin`/`claro`/intermediate `default-admin`-prefixed identifiers) and `LegacyStorageTest` (a JS functional test asserting the local-storage migration behavior), plus `tests/fixtures/implementation-name-allowlist.json`, which documents every remaining Gin/Claro reference and the reason it is intentionally kept.

## Upgrade

Default Admin is `lifecycle: experimental`, but sites or contributed code that already integrate with it should update references:
```
/* CSS */
.gin-details              -> .details
.gin-breadcrumb__item     -> .breadcrumb__item
[data-gin-accent]         -> [data-accent]
.gin--dark-mode           -> .dark-mode
```
```js
// JS
Drupal.behaviors.ginSettings -> Drupal.behaviors.adminSettings
Drupal.ginAccent             -> Drupal.adminAccent
drupalSettings.gin           -> drupalSettings.defaultAdmin // old `gin` key still populated for now, but treat as deprecated
```
Local storage keys under `Drupal.gin.*` are migrated automatically on first page load after upgrading; no manual action is needed for persisted browser state.
