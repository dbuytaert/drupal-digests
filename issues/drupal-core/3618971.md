## Summary

The installer, update.php, and any early maintenance-mode pages (shown when the database or bootstrap is unavailable) now use the Admin theme (default_admin) instead of Claro. This is a step toward deprecating Claro. Distribution profiles that need a different installer theme can still request one via the `distribution.install.theme` key in their info file, and sites can still override the theme by setting `$settings['maintenance_theme']` in `settings.php`.

## Impact

Affects module maintainers and site owners.

- **Config change:** The `maintenance_theme` example in `default.settings.php` now shows `default_admin` instead of `claro`; sites that explicitly set `$settings['maintenance_theme'] = 'claro';` keep working, but the out of the box default for install, update.php and early maintenance pages is now `default_admin`.
- **New API:** New `\Drupal\Core\Installer\InstallerKernel::INSTALL_THEME` constant identifies the theme used for install, update, and early maintenance pages, replacing hardcoded `'claro'` strings throughout core.

## Technical details

The hardcoded `'claro'` fallback used in `install_state_defaults()`, `_drupal_maintenance_theme()`, and `InstallerKernel::getExtensions()` was replaced with a new `InstallerKernel::INSTALL_THEME` constant (`'default_admin'`). `InstallerKernel::getExtensions()` was refactored into a new private `getInstallThemes()` helper that resolves the install theme (and its base themes, unless the theme is the default install theme, which declares `base theme: false` so no filesystem scan is needed) whether or not a profile has been selected yet.

A new `InstallerKernel::updateThemes()` override keeps the install theme's hook implementations registered throughout the whole install process: normally, installing a profile or recipe replaces the theme registry with just the themes the profile installed, which drops the install theme's hooks (`Drupal\Core\Hook\ThemeHookCollectorPass`) even though the install theme keeps rendering the remaining pages, including the final "configure site" step. This previously caused subtle breakage such as fonts not being preloaded and custom installer-theme hook implementations disappearing mid-install; both are now covered by new assertions in `InstallerTest` and `test_installer_theme`.

Other fixes needed to make `default_admin` usable during install: `HtmlResponseAttachmentsProcessor::processAttachments()` now uses `$this->fileUrlGenerator->generateString()` for preloaded fonts so the URL is root-relative instead of relative to `install.php`; `default_admin`'s `PreprocessHooks::preprocessHtml()` now short-circuits toolbar/navigation class handling via `InstallerKernel::installationAttempted()` because permission checks need a database that does not exist yet during install; and `default_admin\Settings::getAdminTheme()` now returns `?string` (falling back to the active theme) since `system.theme` configuration is unavailable during install.
