## Summary

Three long-standing procedural functions for handling file uploads from forms, `file_save_upload()`, `file_managed_file_save_upload()`, and `_file_save_upload_from_form()`, are now deprecated in favor of two new services. The functions still work exactly as before (they now just delegate internally), so no behavior changes for site visitors, but any custom code calling them directly will start seeing deprecation notices and must be updated ahead of the Drupal 13.0.0 removal.

## Impact

Affects module maintainers.

- **Deprecation:** Procedural functions `file_save_upload()`, `file_managed_file_save_upload()`, and `_file_save_upload_from_form()` are deprecated in drupal:11.5.0 and removed in drupal:13.0.0, replaced by the `Drupal\file\Upload\FormFileUploader` and `Drupal\file\Upload\ManagedFileElementHelper` services.

## Technical details

The old code mixed API-level file handling with Form API concerns (setting form errors, adding/removing Messenger messages, rendering error lists) in the same functions, which made the logic hard to reuse or test in isolation. This part of the broader [#3221796](https://www.drupal.org/node/3221796) modernization effort splits that responsibility into two services.

`Drupal\file\Upload\FormFileUploader::saveFormUploadedFiles()` replaces `file_save_upload()`. It is the API-level entry point: it pulls uploaded files via `UploadedFilesExtractor`, delegates the actual move/validate/rename work to `FileUploadHandlerInterface::handleFileUpload()`, and caches results per form field in the `cache.memory` bin (keyed `file:uploads:<field_name>`) instead of the old function-static `$upload_cache`, so repeated calls within a request return the same result without reprocessing. It still calls `\Drupal::messenger()->addError()` directly on failure rather than being fully decoupled from user-facing messaging; a follow-up to remove that was tried and then reverted (see [#3619417](https://www.drupal.org/node/3619417)) to keep this change scoped.

`Drupal\file\Upload\ManagedFileElementHelper` replaces `file_managed_file_save_upload()` and `_file_save_upload_from_form()`. It owns the Messenger and Renderer dependencies, handling the form-level concerns: collecting per-field validation errors into a single `FormStateInterface::setError()` call, preserving pre-existing error messages, and calling into `FormFileUploader` for the actual upload. `Drupal\file\Element\ManagedFile::valueCallback()` and other core callers (`ThemeSettingsForm`, `SystemBrandingOffCanvasForm`, navigation's logo settings, and file access checks) were updated to call these services directly. Both services are registered in `file.services.yml`.</technical>

In 2025 kim.pepper concluded the issue had stalled "because it was trying to do too much" and proposed splitting it into several smaller, independently reviewable sub-issues ([#3619416](https://www.drupal.org/node/3619416) through [#3619420](https://www.drupal.org/node/3619420)).
