## Summary

PHP's `#[SensitiveParameter]` attribute tells the engine to redact an argument's value from stack traces and uncaught exception output. Drupal added this attribute to most sensitive parameters in a previous cleanup ([#3296293](https://www.drupal.org/node/3296293)), but missed the `$connection_options` argument of `Connection::open()`, which carries the database password and other connection details. If `open()` throws an exception or triggers an error, tools that display full stack traces with arguments (such as the Symfony error handler, or PHP configured with `zend.exception_ignore_args` disabled) could expose the plaintext database password. This fix adds `#[\SensitiveParameter]` to that argument so it is redacted like other sensitive values.

## Impact

Affects site owners.

- **Security:** Database connection credentials could appear in stack traces or error output (e.g. via the Symfony error handler or `zend.exception_ignore_args`) if `Connection::open()` throws; the `$connection_options` argument is now marked `#[\SensitiveParameter]` so PHP redacts it.

## Technical details

The `#[\SensitiveParameter]` attribute was added to the `$connection_options` parameter of `Connection::open()` in the abstract base class (`core/lib/Drupal/Core/Database/Connection.php`) and in every core database driver's concrete override: mysql, mysqli, pgsql, and sqlite. Since `open()` is a static method invoked before a `Connection` object exists, the array containing credentials such as `password` was previously fully visible in exception backtraces; the attribute causes PHP to substitute an `Object(SensitiveParameterValue)` placeholder instead when rendering traces.
