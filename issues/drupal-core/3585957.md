## Summary

When the new navigation sidebar's render cache was cold, Drupal used BigPipe to stream it in after the rest of the page had already loaded. This caused the whole page content to visibly jump sideways as the sidebar popped in, an effect known as content layout shift (jank). This fix stops the navigation sidebar from being deferred via BigPipe, so it renders inline with the rest of the page instead. This can make the initial page response marginally slower on a cache miss, but avoids the jarring layout shift, and testing also showed it slightly reduces the number of separate asset/cache operations needed for the page.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix adds `#placeholder_strategy_denylist` to the `navigation` render element built in `NavigationRenderer::buildNavigation()` (`core/modules/navigation/src/NavigationRenderer.php`), denylisting `BigPipeStrategy::class`. This is the same mechanism already used elsewhere in core, such as `BlockViewBuilder` and `Core\Render\Element\StatusMessages`, to opt a `#lazy_builder` placeholder out of BigPipe handling via `ChainedPlaceholderStrategy`. The element still has `#create_placeholder` set, so it keeps its own cache item and placeholder behavior, it simply is no longer eligible to be swapped in asynchronously by BigPipe; it now renders synchronously with the rest of the page.

A `@todo` comment ties this to [#3505610](https://www.drupal.org/node/3505610), a stalled attempt to instead add a proper placeholder preview (skeleton) for the navigation sidebar; once that lands, this denylisting is intended to be removed. During review, a tester found that on `HEAD` the BigPipe-rendered navigation could fail entirely with a `big_pipe.commands.js` JS error on first cache clear, a symptom suspected to be related to a race condition discussed in [#3566843](https://www.drupal.org/node/3566843); this change avoids that failure mode as well since the sidebar no longer goes through BigPipe's swap mechanism. Performance test baselines (`StylesheetCount`, `QueryCount`, `CacheGetCount`, `CacheSetCount`) were updated to reflect the slightly different asset/cache call counts caused by loading navigation CSS/JS with the main request instead of as a separate BigPipe response.
