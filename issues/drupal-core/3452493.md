## Summary

Drupal core has removed 46 legacy image files (GIFs and PNGs) that were left behind after earlier issues replaced them with SVG versions: the ajax throbber and loading indicators in `core/misc`, and the file-type icon sets (PDF, text, audio, spreadsheet, etc.) shipped with the Claro theme, the Umami demo theme, and Starterkit theme. The SVG replacements have been in use since Drupal 11, so this is cleanup of now-dead files rather than a behavior change for standard sites. It only matters if a custom theme, override, or piece of custom CSS still points directly at one of the removed file paths.

## Impact

Affects front-end developers.

- **Theme change:** Removed 46 legacy raster image files (the ajax throbber/loading indicators in `core/misc`, and file-type icon sets in Claro, Umami, and Starterkit) that had already been superseded by SVG equivalents; any code still referencing the old `.gif`/`.png` paths must switch to the `.svg` files of the same name.

## Technical details

The removed files are `core/misc/loading-small.gif`, `core/misc/loading.gif`, `core/misc/throbber-active.gif`, and `core/misc/throbber-inactive.png`, plus 14 file-type icons each (`application-pdf`, `text-html`, `x-office-document`, etc.) under `core/profiles/demo_umami/themes/umami/images/classy/icons/`, `core/themes/claro/images/classy/icons/`, and `core/themes/starterkit_theme/images/icons/`. In every case an SVG file of the same base name already exists in the same directory (e.g. `core/misc/throbber-active.svg`, `core/themes/claro/images/classy/icons/application-pdf.svg`), added by prior issues [#2575253](https://www.drupal.org/node/2575253), [#1974928](https://www.drupal.org/node/1974928), and [#3521857](https://www.drupal.org/node/3521857). No template, library, or CSS file needed updating in this commit because those consumers had already been switched over to the SVG assets in those earlier issues; this change is purely deleting the now-orphaned raster files.

## Upgrade

Any custom theme, template override, or CSS that hardcodes a path to one of the removed files (for example `core/themes/claro/images/classy/icons/application-pdf.png` or `core/misc/throbber-active.gif`) will 404 after upgrading. Update those references to the SVG file of the same name in the same directory, e.g.:
```
core/misc/throbber-active.gif      -> core/misc/throbber-active.svg
core/themes/claro/images/classy/icons/application-pdf.png -> core/themes/claro/images/classy/icons/application-pdf.svg
```
