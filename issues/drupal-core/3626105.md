## Summary

On persistent PHP workers such as FrankenPHP in worker mode, the theme registry service can outlive a request. After the first request's cleanup, later requests could log "Theme hook %hook not found." and render nothing for the affected hooks. The registry now discards its runtime collectors during cleanup, so the next request gets fresh ones and theme hooks are found again. Sites on classic PHP-FPM or Apache are not affected.

## Impact

No upgrade or configuration changes required.

## Technical details

`Registry::destruct()` called `destruct()` on each collector in `$this->runtimeRegistry` but kept them. `CacheCollector::destruct()` persists pending changes and resets storage. `Registry::getRuntime()` then returned the same retained, emptied `ThemeRegistry`, whose `has()` and `get()` read that storage directly. So previously registered hooks came back as missing, and `ThemeManager::render()` logged the "not found" message and returned `FALSE`.

The fix copies `$this->runtimeRegistry` to a local variable, sets the property to `[]`, then destructs the copies. The next `getRuntime()` call builds a new `ThemeRegistry`, whose constructor loads the runtime cache or initializes on a miss. Repeated `destruct()` calls also skip collectors that were already processed. A new kernel test, `testRuntimeRegistryAfterDestruct()` in `RegistryTest`, checks that a hook is still found after `destruct()` and that a different collector instance is returned. The committer noted that for persistent workers it may be better not to clean up these collectors at all, so a loaded registry stays available across requests. That is left for later work.
