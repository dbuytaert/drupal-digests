## Summary

Drupal core's bundled HTMX library has been upgraded from version 2 to the newly released version 4, which the HTMX project describes as a complete rewrite ("the fetch()ening"). Core's HTMX integration (the PHP `Htmx` attribute-builder class, the request-header helpers, `FormBuilder`'s HTMX handling, and the client-side JavaScript that wires HTMX into Drupal's AJAX/behavior system) has been refactored to work with the new library. There are no visible UI changes for standard core usage, but sites with custom code, themes, or contrib modules that use HTMX attributes, HTMX request/response headers, or HTMX JavaScript extensions should review the published change record, since htmx 4 changes attribute names, header names and formats, event payloads, the extension registration API, and introduces a default 60 second request timeout and different history/back-navigation behavior.

## Impact

Affects module maintainers and site owners.

- **Requirements:** The bundled `htmx.js`/`htmx.min.js` vendor library is upgraded from 2.0.4 to 4.0.0, a rewrite with backward-incompatible changes to attributes, headers, events, and the extension API.
- **API change:** The `Drupal\Core\Htmx\Htmx` factory class was substantially reworked for htmx 4: several methods were renamed or removed (e.g. `disable()`→`ignore()`, `disabledElt()`→`disable()`, `request()`→`config()`; `ext()`, `disinherit()`, `history()`, `inherit()`, `params()`, and `prompt()` were removed because those attributes no longer exist in htmx 4), most builder methods gained an `int $modifiers` parameter for the new `:inherited`/`:append` attribute modifiers, and new methods `action()`, `method()`, `query()`, and `status()` were added for new htmx 4 attributes. `HtmxRequestInfoTrait` methods were renamed to match new/changed HTMX headers: `getHtmxTrigger()` and `getHtmxPrompt()` are gone, `getHtmxTriggerName()` now parses the triggering element's name out of the new `HX-Source` header, and a new `getHtmxRequestType()` reads the `HX-Request-Type` header.
- **Deprecation:** `FormBuilderInterface::HTMX_REQUEST` constant is deprecated in favor of `HtmxRequestInfoTrait::isHtmxRequest()`.

## Technical details

The core-side changes track htmx 4's rewrite closely. `HtmxRequestInfoTrait` was updated because htmx 4 replaces the old `HX-Trigger`/`HX-Trigger-Name` headers with `HX-Source` (a CSS-selector-like identifier for the triggering element, URI-encoded) and adds `HX-Request-Type` (`"full"` or `"partial"`); `getHtmxTriggerName()` now regex-extracts a `name="..."` fragment out of `HX-Source` instead of reading a dedicated header. `FormBuilder::prepareForm()` had a latent bug here: it still read the removed `hx-trigger` header directly (rather than through the trait), which meant `$hx_trigger` was always `NULL` and the out-of-band `form_build_id` swap fired unconditionally; this was caught during review and fixed to use `getHtmxSource()`/`getHtmxTarget()` via the newly-added `HtmxRequestInfoTrait` usage in `FormBuilder`.

The `Htmx` class (`core/lib/Drupal/Core/Htmx/Htmx.php`) gained `self::INHERITED`/`self::APPEND` bit-flag modifiers, threaded through nearly every builder method via a new `keyWithModifiers()` helper, to support htmx 4's explicit `:inherited`/`:append` attribute-inheritance syntax. Several methods for attributes htmx 4 removed (`ext`, `disinherit`, `history`, `inherit`, `params`, `prompt`) were removed outright, others were renamed to match new attribute names (`disable()`→`ignore()`, `disabledElt()`→`disable()`, `request()`→`config()`), and new methods (`action()`, `method()`, `query()`, `status()`) were added for htmx 4's new `hx-action`, `hx-method`, `hx-query` (supporting the HTTP `QUERY` method), and `hx-status` attributes. Deprecation shims for the removed/renamed methods were left to a follow-up issue rather than being part of this change.

On the client, `core/misc/htmx/htmx-assets.js` was rewritten to hook into htmx 4's new event/task model: `Drupal.attachBehaviors`/`detachBehaviors` are now triggered from `htmx:before:swap`/`htmx:after:swap` handlers that resolve the correct DOM context from the swap task's target rather than the old `htmx:beforeSwap`/`htmx:afterSettle` events. `core/core.libraries.yml` now aggregates the htmx asset and points at v4.0.0. `FormBuilderInterface::HTMX_REQUEST` is marked `@deprecated` in favor of `HtmxRequestInfoTrait::isHtmxRequest()`.

## Upgrade

Review the published HTMX 4 change record for the full list of breaking changes. In particular, if custom or contrib code:

- Calls removed `Htmx` methods, replace them, e.g.:
```php
// Before
(new Htmx())->request(['timeout' => 5000]);
// After
(new Htmx())->config(['timeout' => 5000]);
```
- Reads the old HTMX request headers directly, switch to the trait or the new header names (`HX-Trigger`/`HX-Trigger-Name` are gone, use `HX-Source`/`HX-Request-Type`).
- Listens for Drupal's custom `htmx:drupal:load`/`htmx:drupal:unload` events, note the event payload shape may differ since it now derives its target from the htmx 4 swap task queue.
- Registers an HTMX extension, htmx 4 replaces `htmx.defineExtension()` with `htmx.registerExtension(name, extension)` and a flat hook-object shape.

Also account for the new default 60 second request timeout and the change to no-DOM-cache history/back-navigation behavior in htmx 4.

### Collaboration

This nine-month effort was driven largely by fathershawn, who repeatedly rebased the branch through multiple htmx 4 beta releases (beta2 through beta6 and finally the 4.0.0 stable release) as the upstream API kept shifting, and who coordinated directly with htmx maintainers (including latent, credited with an assist on the swap/extension code) to resolve an upstream htmx bug where `outerHTML` swaps against a full-document response corrupted target attributes; the htmx team fixed it upstream after the discussion here. cosmicdreams did a close technical review that caught a real regression: `FormBuilder` still read the removed `hx-trigger` header, making its out-of-band `form_build_id` swap fire unconditionally, and separately flagged that Drupal's own `htmx:drupal:load`/`htmx:drupal:unload` custom events changed payload shape (`detail.elt` to `target`) without any upstream documentation to flag it, which fathershawn folded into the change record. longwave, catch, and others pushed to land the upgrade on `main` early despite htmx 4 still being in beta, reasoning it was safer to ride htmx 4's betas toward Drupal 12 than to release Drupal 12 locked to htmx 2 for years; catch's comment framed this directly given "HTMX has never had, and never will have, a version 3."
