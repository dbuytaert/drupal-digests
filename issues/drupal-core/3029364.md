## Summary

The "None" contextual filter validator in Views lost a numeric check years ago. A cleanup removed the check because it referenced an undefined variable. The check is back. For a numeric argument handler where `break_phrase` is not set in the options, a numeric value now passes validation. A non-numeric value still fails. Before the fix, every value failed in that case. The fix was backported to 12.0.x, 11.x and 11.5.x as a low-risk bug fix.

## Impact

No upgrade or configuration changes required.

## Technical details

`Drupal\views\Plugin\views\argument_validator\None::validateArgument()` originally came from the procedural `validate_argument_basic($arg)`. When it was moved into a method taking `$argument` in [#1788266](https://www.drupal.org/node/1788266), the `is_numeric($arg)` check kept the old variable name. [#3316276](https://www.drupal.org/node/3316276), a PHPStan "undefined variable" cleanup, then removed the check as unused. Without it, the condition `!empty($this->argument->definition['numeric']) && !isset($this->argument->options['break_phrase'])` returned `FALSE` for any value.

The merged change restores the check using the real parameter: `&& !is_numeric($argument)`. It also adds the unit test `Drupal\Tests\views\Unit\Plugin\argument_validator\NoneTest`. The test covers numeric and non-numeric values, the `break_phrase` bypass, and the null and empty cases with and without `must_not_be`.
