## Summary

You can now add a style for the horizontal rule to a text format's CKEditor 5 Styles setting, for example `hr.class-name|Label`. Before, saving that entry gave the error "The `<hr>` tag is not yet supported by the Style plugin." Editors can then pick the style from the Styles dropdown when an `<hr>` is selected, and the class is kept when the content is saved. The fix was backported to 11.5.x.

## Impact

No upgrade or configuration changes required.

## Technical details

The Styles configuration validator, `StyleSensibleElementConstraintValidator`, keeps a list of elements the Style plugin does not support. `<hr>` was on that list, so a style for it failed validation. The fix removes `<hr>` from that list. A new test case, "VALID: Style plugin configured to add class to <hr>", in the validator's data provider uses the `horizontalLine` and `style` toolbar items with `<hr class="fancy">` and expects no violations. The diff touches only the validator and its test.

The issue also asked for allowlisting `id` and `class` on `<hr>` through Source editing's "Manually editable HTML tags". The diff does not change that. The thread points to [#3410100](https://www.drupal.org/node/3410100) as a related issue about "Manually editable HTML tags".
