## Summary

Form elements can now define their `#value_callback` using the same "service notation" already supported by `#process`, `#after_build`, `#submit`, `#validate`, and `#entity_builders`. Previously `#value_callback` only accepted plain PHP callables (functions, static methods, or `[$object, 'method']` arrays); it could not point to a method on a class resolved through the service container, so it could not use constructor-injected dependencies. This unblocks converting existing static value callback methods, such as those used by file upload widgets, into injectable services.

## Impact

Affects module maintainers.

- **New API:** `#value_callback` on form elements can now be defined in `CallableResolver` service notation (e.g. `MyService:method`), not just plain `is_callable()` values.

## Technical details

`FormBuilder::handleInputElement()` previously read `#value_callback` directly and fell back to `\Drupal\Core\Render\Element\FormElementBase::valueCallback` only when the given value was not `is_callable()`. It now always resolves the callback through `CallableResolver::getCallableFromDefinition()`, after passing it through `FormStateInterface::prepareCallback()` (the same pipeline used for `#process` and `#after_build`), so definitions like `MyClass:method` or a service id with a method are resolved via the class resolver/container instead of requiring a directly callable value. Plain static and array callables continue to resolve the same way, since `CallableResolver` falls back to normal PHP callable resolution when the definition is already callable. An unresolvable definition now throws `\InvalidArgumentException` instead of silently falling back to the default value callback, as covered by the new `testValueCallbackInvalidDefinitionThrows()` kernel test. This change removes a blocker for [#3616654](https://www.drupal.org/node/3616654), which converts `ManagedFile::valueCallback()` into an injectable service, part of the file upload modernization tracked in the meta issue [#3221796](https://www.drupal.org/node/3221796).

## Upgrade

Existing `#value_callback` definitions (plain functions, static method strings, or `[$object, 'method']` arrays) keep working unchanged. To use dependency injection, define the callback in service notation, for example:

```php
$element['#value_callback'] = MyValueCallbackService::class . ':value';
```

which is then resolved through `CallableResolver` the same way `#process` and `#submit` callbacks already are.
