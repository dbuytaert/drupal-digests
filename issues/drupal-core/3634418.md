## Summary

If a CSS file in a `*.libraries.yml` file is listed without options (for example, a key with nothing after the colon instead of `{}`), the assertion error now says so. It reads: "CSS file options must be an array. Use {} when no options are needed." Before, the message said "CSS must be nested under a category," which pointed at the wrong problem. Assertions only run in development setups where `assert()` is enabled. The change was also backported to 11.5.x.

## Impact

Affects module maintainers.

- **New API:** `LibraryDiscoveryParser::validateCssLibrary()` now returns 3 when a CSS file entry has a NULL options value.

## Technical details

`LibraryDiscoveryParser::validateCssLibrary()` now returns a new code `3` when a file's options value is `NULL`. YAML parses a key with no value as `NULL`, which previously failed the `is_array()` check and returned `1` (improper nesting). `buildByExtension()` has a new assertion that rejects code `3` and shows the new message. It runs before the existing `< 2` and `=== 0` assertions, so the nesting message no longer masks it. The docblock return values list the new code. A kernel/unit test case `Missing CSS options` with a `css_missing_options` fixture covers it.
