## Summary

Navigation and the Default Admin theme each used to load their own copy of the Inter font, so admin pages with both downloaded it twice (about 557 KB of fonts). Core now ships one shared Inter font, split by character set, and both use it. On a typical English admin page only the Latin subset (about 104 KB) is downloaded and preloaded. The issue's own Slow 4G measurements, which were generated with Claude, show fonts finishing loading about 2.6 seconds sooner. Default Admin moves from Inter v3 to v4, which Navigation already used, so admin headings come out a few percent narrower. Body text is almost unchanged.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** Navigation and Default Admin no longer ship their own Inter `@font-face` CSS or font files; they depend on `core/font`. Admin typography now uses Inter v4, so headings render slightly narrower.
- **New API:** New `core/font` library (Inter v4 variable, unicode-range subsets, preloaded latin file) and `--drupal-font-inter` CSS custom property.

## Technical details

A new `font` library in `core/core.libraries.yml` loads `core/misc/fonts/inter.css` and preloads `misc/fonts/inter-latin.woff2` through the library `fonts` key. `inter.css` declares eight `@font-face` blocks for the `Inter` family (latin, latin-ext, cyrillic, cyrillic-ext, greek, greek-ext, vietnamese, symbols), each with a `unicode-range`. Browsers fetch only the subsets needed by the characters on the page. The CSS also defines metric-adjusted fallback faces, `Inter Fallback Helvetica Neue` and `Inter Fallback Arial`, using `size-adjust`, `ascent-override`, `descent-override` and `line-gap-override` to reduce layout shift while Inter loads. `:root` gets `--drupal-font-inter`, which lists `inter` followed by those fallbacks and `sans-serif`. The `--drupal-` prefix was added after review to avoid clashing with other themes' variables. An unused `--font-inter-size-adjust` variable was removed.

Consumers now use the shared pieces. `navigation/internal.navigation` and `default_admin/global-styling` list `core/font` as a dependency, and their own `fonts.css`/`font.css` files, `fonts:` preload entries and (for Default Admin) the v3.19 font file reference are removed. `--admin-toolbar-font-family` in the Navigation variables and `--admin-font-family` in Default Admin are both set to `var(--drupal-font-inter)`. The installer test assertion that the preloaded font URL avoids `install.php` was removed. Performance test expectations (`StylesheetBytes`) were updated. The change was also backported to 12.0.x, 11.x and 11.5.x.

## Upgrade

Themes or modules that bundle their own Inter copy (for example Gin or Mercury, as discussed in the issue) can drop it and depend on the core library:

```yaml
dependencies:
  - core/font
```

Then reference the shared stack in CSS:

```css
--admin-font-family: var(--drupal-font-inter);
```

Custom CSS that depended on Navigation's or Default Admin's `fonts.css`/`font.css` files, or on their `inter-var.woff2`/`inter.woff2` file paths, should switch to `core/font`.
