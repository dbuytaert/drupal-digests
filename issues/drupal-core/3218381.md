## Summary

The `managed_file` form element accepted `#file_value_callbacks` and called whatever was listed there, bypassing the trusted callback protections added in [#2966327](https://www.drupal.org/node/2966327) to limit remote code execution through render arrays. Those callbacks are now checked the same way as other render callbacks. In Drupal 12.1 an untrusted callback still runs but triggers a deprecation. In Drupal 13.0 it will throw an exception. Custom and contrib code that uses `#file_value_callbacks` needs updating.

## Impact

Affects module maintainers and site owners.

- **Security:** Closes a bypass of the trusted callback protections: arbitrary callables in `#file_value_callbacks` were executed unchecked.
- **Deprecation:** Using `#file_value_callbacks` callbacks on `managed_file` that are not `#[TrustedCallback]`-tagged methods, `TrustedCallbackInterface` methods or anonymous functions is deprecated in drupal:12.1.0 and will throw in drupal:13.0.0.

## Technical details

`ManagedFile::valueCallback()` used to run `$callback($element, $input, $form_state)` for each entry in `#file_value_callbacks`. It now passes each one to `StaticTrustedCallbackHelper::callback()` with a custom message. That message says untrusted callbacks are deprecated in drupal:12.1.0 and will throw in drupal:13.0.0, and it links to https://www.drupal.org/node/3620771. `StaticTrustedCallbackHelper` no longer supports a silenced deprecation ([#3081025](https://www.drupal.org/node/3081025)). The code therefore catches `UntrustedCallbackException`, calls `@trigger_error($e->getMessage(), E_USER_DEPRECATED)`, and then still invokes the callback, which keeps the deprecation period working. The `%%s` in the `sprintf()` format is intentional: it leaves a `%s` placeholder for the helper to fill in with the callback. Trusted callbacks are methods tagged `#[TrustedCallback]`, methods of a `TrustedCallbackInterface` class, and anonymous functions. Kernel test coverage was added in the file module's managed file element test. A comment on the issue notes that contrib has copied this pattern into other elements, and follow-up issues are probably needed for them.

## Upgrade

Tag any `#file_value_callbacks` callback method with the attribute used in the core test:

```php
use Drupal\Core\Security\Attribute\TrustedCallback;

#[TrustedCallback]
public function managedFileValueCallbackTrusted(array &$element, $input, FormStateInterface $form_state): void {
  // ...
}
```

Alternatively, implement `TrustedCallbackInterface` on the class or use an anonymous function. Plain function names such as `'die'` are no longer trusted. They trigger a deprecation in 12.1 and will throw in 13.0.
