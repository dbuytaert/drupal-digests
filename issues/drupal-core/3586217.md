## Summary

The Search module has been removed from Drupal core. This includes the `/search` routes and controller, the "Search form" block, the search page entity type and its admin UI, the node/user/help search plugins, the search index tables, and the Views integration (search argument, filter, sort, and row plugins) that shipped with the module. Site owners who use core's built-in keyword search need to install the contrib Search module before upgrading to keep this functionality; running `update.php` with `search` still enabled will show a warning that the module was removed from core. This follows Drupal's policy of moving lightly maintained core modules to contrib, the same path taken by HAL, RDF, and others (see the deprecated/removed modules list at drupal.org/node/3223395#s-search).

## Impact

Affects module maintainers and site owners.

- **Requirements:** Sites with the `search` module still enabled will see an update.php requirements warning telling them the module was removed from core.
- **Deprecation:** The core Search module (including its `search_node`, `search_user`, `search_help`, and `search_embedded_form`/other test submodules) is removed entirely; a contrib Search module should be installed as a replacement.

## Technical details

The commit deletes `core/modules/search` in its entirety, roughly 17,000 lines: the `SearchPage` config entity, `SearchPageRepository`, `SearchIndex`/`SearchQuery`/`ViewsSearchQuery`, the `SearchPluginBase`/`SearchPluginManager` plugin system (`#[Search]` attribute), `SearchController`, the admin forms, the `search_form_block` block plugin, the `search.page.*` and `search.settings` config schemas, and the bundled `search_node`, `search_user`, `search_help`, and `search_embedded_form` submodules along with all their tests.

Outside the module directory the change is intentionally narrow: `search` is added to `SystemRequirements::DRUPAL_CORE_REMOVED_MODULE_LIST` in `core/modules/system/src/Install/Requirements/SystemRequirements.php` so `SystemRequirementsHooks` can surface an update-time warning on sites that still have it enabled, `SchemaCheckTrait` drops its now-unneeded `search.page.*`/`search.settings` ignored-property-path entries, and the `core_fake`/`CoreFakeWithAllCustomClasses` test database drivers drop their `SearchQuery`/`ViewsSearchQuery` subclasses. `core/.phpstan-baseline.php` and `.deprecation-ignore.txt` are pruned of search-specific entries. The removal was postponed until after [#3595089](https://www.drupal.org/node/3595089) (Olivero theme removal) since Olivero contained search-specific markup and test coverage that would otherwise have failed.

## Upgrade

Before upgrading a site that uses core search:

1. Install the contrib [Search](https://www.drupal.org/project/search) module (or another search solution) to replace the functionality.
2. Any custom code implementing `\Drupal\search\Plugin\SearchInterface` / extending `SearchPluginBase`, or referencing `\Drupal\search\SearchPageRepositoryInterface`, `SearchIndex`, `SearchQuery`, or the `search.page.*`/`search.settings` config, needs to be ported to the contrib module's equivalents.
3. Views using the core `views.argument.search`, `views.filter.search`, `views.field.search_score`, `views.sort.search_score`, or `views.row.search_view` plugins will need to be rebuilt against contrib alternatives.
