## Summary

Drupal's locale module previously exposed its internal state (customized vs. non-customized translations, translation source types, overwrite behavior, translation update mode) through a set of global PHP constants defined in locale.module, a pattern core is moving away from as part of modernizing the module. This issue deprecates fourteen of those constants in favor of PHP backed enums and class constants, with no functional change to how translation import, update checking, or the translation settings form behave. Site owners see no change; custom code or contrib modules that reference the old constants directly will start seeing deprecation notices and need to update before Drupal 13.0.0, when the constants are removed.

## Impact

No upgrade or configuration changes required.

## Technical details

The constants are replaced according to a fixed mapping: `LOCALE_NOT_CUSTOMIZED`/`LOCALE_CUSTOMIZED` become `LocaleDefaultOptions::NOT_CUSTOMIZED`/`LocaleDefaultOptions::CUSTOMIZED`; `LOCALE_TRANSLATION_USE_SOURCE_LOCAL`/`LOCALE_TRANSLATION_USE_SOURCE_REMOTE_AND_LOCAL` become `\Drupal\locale\Model\TranslationUpdateMode::Local`/`::RemoteAndLocal` (both backed by string values, use `->value` where a string is expected); `LOCALE_TRANSLATION_OVERWRITE_ALL`/`_NON_CUSTOMIZED`/`_NONE` become `\Drupal\locale\Model\Overwrite::All`/`::NonCustomized`/`::None`; and `LOCALE_TRANSLATION_REMOTE`/`_LOCAL`/`_CURRENT` become `\Drupal\locale\Model\SourceType::Remote`/`::Local`/`::Current`. The `TranslationUpdateMode` and `Overwrite` enums use the new `OptionsEnumTrait` to supply their `#options` arrays directly to the translation settings form (`LocaleSettingsForm`), replacing hand-written arrays keyed by the old constants. `LOCALE_JS_STRING`, `LOCALE_JS_OBJECT` and `LOCALE_JS_OBJECT_CONTEXT` have no replacement: their regex patterns are now local variables inlined inside `LocaleJs::parseJsFile()`. `LOCALE_TRANSLATION_STATUS_TTL` also has no replacement; its value (600 seconds) is now a literal in `TranslationStatusForm::submitForm()` pending a follow-up ([#3619926](https://www.drupal.org/node/3619926)) to reconsider the TTL.

`LocaleTranslationSource` gained three helper methods used throughout the locale codebase to replace direct access to its `$type`/`$files` properties: `getType()` (returns a `SourceType` enum or `NULL`), `getFile(SourceType $type)`, and `isUpdateAvailable()` (true when the type is `Local` or `Remote`). Callers such as `LocaleFetch`, `LocaleSource`, `LocaleProjectChecker` and `TranslationStatusForm` were updated to use these helpers instead of comparing against the old constants or indexing `$source->files[LOCALE_TRANSLATION_LOCAL]` directly. A related bug in `PoDatabaseWriter::writeItems()`'s unhandled transaction exceptions was found during review and split off into [#3619927](https://www.drupal.org/node/3619927) rather than fixed here.</technical>
