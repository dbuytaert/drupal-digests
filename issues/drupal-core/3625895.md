## Summary

Database query objects (`Select`, `Insert` and so on) can no longer be serialized or unserialized on the main branch (12.x). Attempting it now throws a `LogicException`. On 11.5.x the same methods were deprecated rather than removed, so custom or contrib code that serializes a query, or an object holding one, gets a deprecation notice there and should stop. Core itself does not do this anywhere.

## Impact

Affects module maintainers.

- **API change:** `Query::__sleep()` and `Query::__wakeup()` removed in 12.x; `Query` serialization and unserialization now throw `\LogicException` (deprecated in 11.5.0 on the 11.x branches).
- **Deprecation:** `Query::__sleep()` and `Query::__wakeup()` are deprecated in drupal:11.5.0 and removed from drupal:12.0.0.

## Technical details

`Query::__sleep()` and `Query::__wakeup()` are replaced in `Drupal\Core\Database\Query\Query` by `__serialize()` and `__unserialize()`, which both throw `\LogicException`. The old `__wakeup()` reattached an unserialized query to whatever connection `Database::getConnection($this->connectionTarget, $this->connectionKey)` returned at the time, with no guarantee that connection was the right one. This was inconsistent with `Connection`, which already refuses serialization ([#2463321](https://www.drupal.org/node/2463321)), and with PDO. The change also finishes off [#2463321](https://www.drupal.org/node/2463321). The now-unused `Database` import is removed. `SerializeQueryTest` is rewritten to assert that `serialize()` and `unserialize()` throw. Per the thread, the full test suite showed nothing in core round-trips a query apart from that one test. The commit landed on `main` and 12.0.x as a hard removal. On 11.x and 11.5.x it landed as a deprecation, with the deprecation version being 11.5.0 and removal in 12.0.0, pointing to change record https://www.drupal.org/node/3625908. I only read the `main` diff, so the 11.5.x deprecation details come from the reviewer comment on MR !17239. [#3548971](https://www.drupal.org/node/3548971) (replacing `__sleep()`/`__wakeup()` with `__serialize()`/`__unserialize()`) is the related issue, and this change means `Query` no longer needs converting there.

## Upgrade

Stop serializing query objects, and objects that hold references to them. Store the query arguments or the results instead. The exception message says: "Adjust your code so that is not necessary, for example by storing the query arguments or results instead."
