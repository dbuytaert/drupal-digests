## Summary

Drupal no longer scaffolds a `.csslintrc`, `.eslintignore`, or `.eslintrc.json` file into the root of every site built from `drupal/core-composer-scaffold`. CSSLint was replaced by stylelint back in 2017 ([#2865971](https://www.drupal.org/node/2865971)) and is considered dead, and the scaffolded ESLint config stopped working once core moved to ESLint v9 with a new config format ([#3440225](https://www.drupal.org/node/3440225)). Since using these tools requires manually installing ESLint/CSSLint plus the matching plugins anyway, and most real sites already keep their own lint configuration at the theme or repository root, core stops shipping these unused defaults into every install. This is a disruptive change targeted at Drupal 12.

## Impact

Affects site owners.

- **Config change:** Composer scaffold no longer copies `.csslintrc`, `.eslintignore`, or `.eslintrc.json` into the web root of new or updated Drupal sites.

## Technical details

The fix removes the `[web-root]/.csslintrc`, `[web-root]/.eslintignore`, and `[web-root]/.eslintrc.json` entries from the `drupal-scaffold` `file-mapping` in `core/composer.json` (and the corresponding fixture `composer.json` files used by `drupal-composer-scaffold` tests), and deletes the source files themselves from `assets/scaffold/files/` (`csslintrc`, `eslintignore`, `eslintrc.json`). Test fixtures and expectations across the scaffold plugin's test suite (e.g. `ManageGitIgnoreTest`, drush-style scaffold listing output) were updated to no longer expect these files to be copied or linked.

Core's own internal `.eslintrc.json` and `.stylelintrc.json` inside `core/` are untouched. Only the copies that composer-scaffold writes out to the site's web root are removed, so core's own lint tooling and CI keep working; it is only external sites and themes that lose the auto-provisioned copy.

## Upgrade

Sites that want to keep linting against core's rules must now do so manually, since the scaffolded copy is gone. Before this change, the scaffolded `.eslintrc.json` simply contained:

```json
{
  "extends": "./core/.eslintrc.json"
}
```

Sites relying on this can recreate that file themselves (adjusting the relative path to `core/.eslintrc.json` if their web root differs), or point their own lint configuration directly at core's `core/.eslintrc.json` / `core/.stylelintrc.json`. There is no scaffolded `.csslintrc` replacement, since CSSLint itself is obsolete; use stylelint instead.

### Collaboration

The main open question was whether this would break contrib CI. `alexpott` flagged that [#3559584](https://www.drupal.org/node/3559584), the companion issue in the `gitlab_templates` project to move these linting scaffold files to the assets folder, was still unresolved when the MR was ready. `fjgarlin` had already opened that issue ahead of time to handle the contrib-CI side. `neclimdul` pushed on the practical question of how custom themes/sites are meant to keep following core's lint rules once the scaffolded copies disappear, given years of the scaffolded ESLint config being broken while waiting on [#3440225](https://www.drupal.org/node/3440225); `longwave` clarified that core's own `.eslintrc.json`/`.stylelintrc.json` inside `core/` are unaffected and can still be referenced directly, though making that reuse convenient is left to a separate issue.
