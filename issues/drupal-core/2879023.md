## Summary

Batch operations that run through the browser progress bar no longer break when a CDN or reverse proxy sorts query string parameters (Cloudflare "Query String Sort" and Fastly were reported). Before, the batch requests ended in a 406 "Not acceptable format: json" error and larger batches did not finish. The fix was backported to 11.4.x and later. Sites that worked around this with a page rule disabling query string sorting for `/batch*` can drop that rule after updating.

## Impact

No upgrade or configuration changes required.

## Technical details

The initial batch URI already contains `op=do_nojs`. `core/misc/batch.js` appended a second `op` to it (`&op=do` for polling, `&op=finished` at the end). A proxy that sorts parameters alphabetically moved `op=do_nojs` last. PHP then used that value, so `_batch_page()` took the `do_nojs` branch for a `_format=json` request and returned an HTML render array, which triggered the 406.

The shipped fix is client side. `batch.js` now builds a `URL` from `batch.uri` and calls `url.searchParams.set('op', ...)` for both the `do` polling URL and the `finished` redirect, so each request carries exactly one `op`. An earlier approach (MR !15103, merged server side) treated `do_nojs` on non-HTML requests as `do` in `_batch_page()`. It was dropped because the duplicate parameter comes from Drupal's own JavaScript, so fixing it at the source was preferred. Both approaches got manual confirmation on Cloudflare.

The no-JS meta refresh path is unchanged. A FunctionalJavascript test (`testBatchUrls`) uses a new `batch9` in the `batch_test` module. It checks that each polling request URL ends in `/batch?_format=json&id=1&op=do` and that the finished URL ends in `/batch?id=1&op=finished`.
