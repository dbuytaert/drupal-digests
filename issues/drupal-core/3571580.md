## Summary

Core now has a generic delete form for bundle entities (content types, block types, media types, comment types and so on). If any content of that bundle exists, the form says so, hides the Delete button and keeps a Cancel button, which non-JS users need on the standalone page. Node, block content, media and comment types now use it. Their separate copies of this logic are gone, so the wording of the "you can't delete this" messages changes slightly. For example, nodes are now described as "content items" instead of "pieces of content". Contrib bundle entity types can use the same form instead of writing their own.

## Impact

Affects module maintainers and front-end developers.

- **Theme change:** The delete forms for node, block content, media and comment types now render the blocking message and a Cancel button, built from the entity type labels. Markup and message wording differ from before.
- **New API:** New `Drupal\Core\Entity\Form\BundleEntityDeleteForm`, a generic delete form for bundle entity types, with overridable `getContentEntityCount()` and `getAdditionalReasonsToPreventDeletion()`.

## Technical details

`Drupal\Core\Entity\Form\BundleEntityDeleteForm` extends `EntityDeleteForm`. In `buildForm()` it reads `getBundleOf()` from the bundle entity type and throws a `\LogicException` if the type is not a bundle of anything. It then counts content entities of that bundle via `getContentEntityCount()`, using an entity query with `accessCheck(FALSE)` on the content entity type's bundle key. It also collects strings from `getAdditionalReasonsToPreventDeletion()`, which returns an empty array by default. If either blocks deletion, the form shows each reason as a paragraph, changes the title to "Unable to delete @bundle-label %type", and returns only the actions element with `submit` removed. Otherwise it defers to the parent form. The messages use the singular and plural labels of both entity types, so a bundle entity type should define `label_singular` and `label_plural` for itself and for its content entity type to get good wording.

`CommentTypeDeleteForm` now extends this class. It overrides `getAdditionalReasonsToPreventDeletion()` to report comment fields that still use the comment type. The `@internal` classes `NodeTypeDeleteConfirm`, `BlockContentTypeDeleteForm` and `MediaTypeDeleteConfirmForm` were deleted. The `delete` form handler on `NodeType`, `BlockContentType` and `MediaType` now points to `BundleEntityDeleteForm`. Tests in `entity_test` gain labels and `edit-form` and `delete-form` links for `entity_test_bundle`, plus a kernel test `BundleDeleteFormTest`. A follow-up commit fixed that test's namespace from `Drupal\FunctionalTests\Entity` to `Drupal\KernelTests\Core\Entity`.

The issue discussed a "delete all content" option, as Paragraphs offers. It was left out of scope. Core's `DeleteMultipleForm` does not yet support bundles, so this would need a follow-up.

## Upgrade

Contrib bundle entity types that hand-roll a "can't delete while content exists" form can switch to the generic one in their entity type attribute:

```php
use Drupal\Core\Entity\Form\BundleEntityDeleteForm;

handlers: [
  'form' => [
    'delete' => BundleEntityDeleteForm::class,
  ],
],
```

To add extra blocking conditions, extend it and override the method, as `CommentTypeDeleteForm` does:

```php
protected function getAdditionalReasonsToPreventDeletion(): array {
  $reasons = parent::getAdditionalReasonsToPreventDeletion();
  $reasons[] = $this->t('...');
  return $reasons;
}
```
