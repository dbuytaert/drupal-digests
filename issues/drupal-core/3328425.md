## Summary

CKEditor 5 balloons, such as the link dialog opened from the toolbar, are now visible when the editor is inside a modal dialog. Before, the balloon could render behind the dialog, so links could not be added in a CKEditor 5 field inside a modal, for example a media caption or a Layout Builder or Paragraphs modal. The fix is in CSS only.

## Impact

Affects front-end developers.

- **Theme change:** `ckeditor5.dialog.fix.css` now applies to every `.ck-body-wrapper` and raises `--ck-z-panel` above jQuery UI dialogs, so themes or modules carrying their own z-index overrides for CKEditor 5 balloons can drop them.

## Technical details

The balloon z-index (1000) was below the jQuery UI dialog (1260). The earlier fix from [#3274937](https://www.drupal.org/node/3274937) used the selector `.ui-dialog ~ .ck-body-wrapper`, which only matches when `.ck-body-wrapper` comes after the dialog in the DOM. CKEditor 5 appends one shared body wrapper when the first editor is created. If an editor already exists on the page before the dialog opens, the wrapper comes first and the rule does not match.

In `core/modules/ckeditor5/css/ckeditor5.dialog.fix.css` the selector is now plain `.ck-body-wrapper`. It sets `--ck-z-panel: calc(var(--ck-z-default) + 1261)`. Thread comments say 1262 is needed so a balloon works in a modal opened from within another modal. It also redeclares `--ck-layer-panel`, `--ck-layer-panel-above` and `--ck-layer-panel-below` on the wrapper. The CSS comment says CKEditor 5 49.0.0 and later resolves these on `:root`, so they would not pick up the override otherwise.

The change landed in two attempts. The first commit was reverted because its own new test failed on main. The second commit added the layer variables. The patch adds a `ckeditor5_test.dialog_with_editor` route and a `CKEditor5DialogTestForm` to the `ckeditor5_test` module. It also adds `testBalloonVisibleInDialogOpenedAfterEditor()` to `CKEditor5DialogTest`. That test checks that the balloon is the topmost element at its centre point, using the `default_admin` theme because Stark does not raise dialog z-index.
