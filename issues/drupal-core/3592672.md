## Summary

Drupal core's User module used to ship two views, "Who's new" (a block listing the newest user accounts) and "Who's online" (a block and page showing recently active users and a total count). These were carried over from the days when Views was a contributed module and have been removed from core. The issue notes that "Who's online" raises privacy concerns even on community sites, and "Who's new" can expose spam accounts on sites without pre-moderated registration. The views also showed up in the Views UI for every site regardless of whether they were used, and had to be loaded from the database and written to the config cache on every cold cache request, adding a small but non-zero overhead. This is similar in spirit to [#3589894](https://www.drupal.org/node/3589894), which removed the Node module's Archive, Glossary, and Recent content views for the same reasons.

## Impact

Affects site owners.

- **Config change:** The `views.view.who_s_new` and `views.view.who_s_online` config entities (and their blocks) are removed from Drupal core; sites that have these views enabled or exported in configuration will need to update their config after upgrading.

## Technical details

The change deletes the `who_s_new` and `who_s_online` view config entities from `core/modules/user/config/install`, along with their Spanish translation overrides in `core/modules/config_translation`/language test fixtures. It also removes the dedicated `WhoIsOnlineBlockTest` kernel test, since the block it tested no longer exists.

Several other core tests referenced these views incidentally rather than testing them directly, and were updated to use other views instead: `ViewUI` filter-criteria and tab-CSS tests now use `test_content_recent` and `user_admin_people` instead of `who_s_online`, the views-listing filter test's expected enabled-view count dropped from 4 to 2, and `InstallerExistingConfigMultilingualTest`'s translation-sync assertions were switched from `who_s_new`/`who_s_online` to `watchdog`/`archive` to keep exercising the same translation-sync logic against views that still exist.

## Upgrade

Sites relying on the "Who's new" or "Who's online" blocks or views should recreate equivalent views in Views UI or a custom module before upgrading, since the `views.view.who_s_new` and `views.view.who_s_online` config will no longer be provided by the User module:
```
langcode: en
status: true
dependencies:
  module:
    - user
id: who_s_new
label: 'Who''s new'
...
```
Any custom code or config export referencing these view IDs (e.g. `views_block:who_s_new-block_1` or `views_block:who_s_online-who_s_online_block`) will need to be updated to point at a replacement view.
