## Summary

As part of preparing Drupal core for the next major release, this task removes the backward-compatibility (BC) layer for a large batch of constructor arguments that had been marked deprecated since Drupal 11.4 or 11.5 and were scheduled for removal in 12.0.0. Each affected argument was previously optional (defaulting to `NULL`), with the constructor silently fetching the real service from the container and emitting a deprecation notice if the caller omitted it. That fallback code is now gone: the argument is required. This has no effect on ordinary site building or configuration; it matters only to developers whose custom or contributed modules extend one of the affected core classes (block, ckeditor5, config, content_translation, editor, field, filter, locale, menu, node, options, responsive_image, update, user, and views components) or instantiate it directly without passing the now-required argument.

## Impact

Affects module maintainers.

- **API change:** Removed the deprecated, nullable constructor arguments (and their `@trigger_error()`/`\Drupal::service()` BC fallback) on roughly 30 core classes, including `UpdateRegistry`, `UserController`, `UserAuthenticationController`, `BlockListBuilder`, `BlockDeleteForm`, `ContentTranslationManager`, `FieldConfigEditForm`, and several plugin managers; these arguments are now required.

## Technical details

Across roughly 30 classes, a constructor parameter of the shape `?Type $arg = NULL` with a body containing `if (!isset($arg)) { @trigger_error(...); $arg = \Drupal::service(...); }` (or `$this->prop = $arg ?? \Drupal::service(...)`) was replaced by a required, non-nullable, promoted property `protected Type $arg`, with the runtime fallback and manual property assignment deleted. Examples include `UserController`'s `$oneTimeAuthentication`, `$loginFinalizer`, `$logoutFinalizer`, and `$accountCancellation`; `UserAuthenticationController`'s `$loginFinalizer`, `$logoutFinalizer`, and `$notificationHandler`; `ContentTranslationManager`'s `$currentUser` and `$languageManager`; and the `$yamlCacheCollector`/`$yaml_cache_collector` argument shared by `LocalActionManager`, `LocalTaskManager`, `MenuLinkManager`, and `YamlRouteDiscovery`.

A couple of non-mechanical cleanups rode along: `UpdateRegistry::__construct()` also drops a legacy shim that let a string be passed positionally as `$memoryCache` to mean the old `$updateType` parameter, and `UpdateRegistryTest::testDeprecatedConstructorSignature()` was deleted since the deprecated signature it exercised no longer exists.

After the commit, a maintainer search for the pattern `without the.*drupal:12.0.0` turned up several deprecations added too recently to be caught by this MR, in `jsonapi/Controller/EntityResource.php`, `update/UpdateManager.php`, `user/AccountSettingsForm.php`, `user/EventSubscriber/MaintenanceModeSubscriber.php`, `user/Form/UserMultipleCancelConfirm.php`, and `views/Plugin/Block/ViewsBlockBase.php`; those were left for a follow-up cleanup issue rather than being folded into this one.</technical>
<parameter name="upgrade">Any code that subclasses one of the affected core classes and calls `parent::__construct()` without the now-required argument, or that instantiates the class directly, must be updated to pass it explicitly. For example, code doing:

```php
new \Drupal\Core\Update\UpdateRegistry($root, $site_path, $module_list, $key_value, $theme_handler, 'post_update');
```

must now pass the memory cache service explicitly:

```php
new \Drupal\Core\Update\UpdateRegistry($root, $site_path, $module_list, $key_value, $theme_handler, \Drupal::service('cache.memory'), 'post_update');
```

The same pattern applies to the other affected classes: `UserController`, `UserAuthenticationController`, `UserCancelForm`, `UserLoginForm`, `UserLogoutConfirm`, `UserPasswordForm`, `UserRegistrationResource`, `RegisterForm`, `BlockListBuilder`, `BlockDeleteForm`, `ContentTranslationManager`, `ContentTranslationOverviewAccess`, `FieldConfigDeleteForm`, `FieldConfigEditForm`, `FilterFormatListBuilder`, `FilterHtmlImageSecure`, `ResponsiveImageFormatter`, `NodeAccessGrantsCacheContext`, `NodeGrantDatabaseStorage`, and the views `NumberListField`/`StringListField`/`ListField`/`Text`/`InputRequired` plugins: supply the previously-optional dependency in every constructor call.
