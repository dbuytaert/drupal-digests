## Summary

This policy issue was closed as fixed. The agreed direction is that new PHP code in Drupal core should start with `declare(strict_types=1);`. With it, a value of the wrong scalar type throws a `TypeError` instead of being silently coerced. No existing code changes, and no code was committed. The attached merge request is an information-only experiment. Core contributors writing new files should add the declaration. Contrib authors are not affected.

## Impact

No upgrade or configuration changes required.

## Technical details

The issue body proposes using `declare(strict_types=1);` in all new core files, noting it is already used across the CKEditor5 module. It also notes that it is most useful together with [#3154762](https://www.drupal.org/node/3154762) (type hints in new code). The closing comment says the discussion is split into two follow-ups: [#3630579](https://www.drupal.org/node/3630579) in the Coding Standards queue to document the rule, and [#3529705](https://www.drupal.org/node/3529705) to enforce it in core. Enforcement there is a proof of concept CI job that checks new code via a git diff. Both were still open when this issue closed.

The MR (!10003) is not part of the resolution. It adds the declaration to every file under `core/lib/Drupal/Component`, as an experiment to see what breaks. The maintainer comments say that CI was failing and that the MR is information only. Discussion on placement and spacing (same line as `<?php` versus a separate line, spaces around `=`) is not settled in this issue's thread. The diff uses `declare(strict_types=1);` on its own line after a blank line. Participants also noted that Symfony rejected the idea, and that PHPStan does not replace the runtime checks.
