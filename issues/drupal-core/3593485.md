## Summary

Drupal now reuses parsed menu link, local task, and local action YAML definitions across cache clears instead of re-parsing the underlying `.links.menu.yml`, `.links.task.yml`, and `.links.action.yml` files from every module on each cache rebuild. This follows up on the file-parsing cache collector introduced in [#3486503](https://www.drupal.org/node/3486503) and shaves measurable time off cold-cache page requests (profiling on an Umami install showed roughly a net 12ms saving per cold-cache request from this change alone, out of a total ~90ms available from YAML parsing overall), with bigger gains expected on sites with more modules.

## Impact

Affects module maintainers.

- **Deprecation:** Constructing `MenuLinkManager`, `LocalActionManager`, or `LocalTaskManager` without the new `$yaml_cache_collector` argument is deprecated in Drupal 11.5.0 and will be required in Drupal 12.0.0.

## Technical details

`MenuLinkManager`, `LocalActionManager`, and `LocalTaskManager` each get a new `YamlCacheCollectorDiscovery` (in `Drupal\Core\Plugin\Discovery`) in place of the plain `YamlDiscovery` they previously used in `getDiscovery()`. This new discovery class wraps the component-level `Drupal\Core\Discovery\YamlCacheCollectorDiscovery` with a `Drupal\Core\Utility\YamlCacheCollector` instance, so parsed YAML definitions persist in the `cache.file_parsing` bin rather than being reparsed from disk on every cache rebuild.

Three new services back this: `menu_link.yaml_cache_collector`, `local_action.yaml_cache_collector`, and `local_task.yaml_cache_collector`, each a `Drupal\Core\Utility\YamlCacheCollector` keyed to `menu.link.yaml`, `menu.local_action.yaml`, or `menu.local_task.yaml` respectively, using `@cache.file_parsing`, `@lock`, and `@datetime.time`. The three manager constructors were converted to promoted properties and gained a new optional `?CacheCollectorInterface $yaml_cache_collector = NULL` parameter; when omitted, each manager triggers an `E_USER_DEPRECATED` notice and falls back to pulling the corresponding collector service directly from the container via `\Drupal::service()`.

Existing kernel performance tests (`PageCacheTest`/related `TestFrontPageColdCache`, `testNodePageColdCache`, `doTestNodePageAdministrator`) had their expected `CacheGetCount` and per-bin `file_parsing` counts bumped by one to account for the new collector's cache lookup.</technical>
<parameter name="upgrade">Code that instantiates `MenuLinkManager`, `LocalActionManager`, or `LocalTaskManager` directly (for example in a custom service definition that decorates or replaces one of these) should pass the new argument to avoid the deprecation notice:
