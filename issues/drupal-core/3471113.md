## Summary

Core's FunctionalJavascript tests now run against a current Chrome in CI (pinned to 155.0 in the commit on `main`, previously 133.0) instead of an old one. Since Chrome 134, a WebDriver click could return before the page navigation had started, so tests randomly read the old page. Core's Selenium driver now turns off the Chrome feature behind this. Local, CI and contrib test runs that use Drupal's driver get the fix, with no test changes needed. This does not change site runtime behavior.

## Impact

No upgrade or configuration changes required.

## Technical details

The cause is Chrome's `DeferRendererTasksAfterInput` feature, on by default since Chrome 134. It delays some page tasks until the next frame after an input event. `DrupalSelenium2Driver::setDesiredCapabilities()` is now overridden to append `--disable-features=DeferRendererTasksAfterInput` to `goog:chromeOptions` `args` before calling the parent. Putting the flag in the driver, not in `.gitlab-ci.yml`, means it applies to every runner, including contrib and local ones.

`.gitlab-ci.yml` gets a new `SELENIUM_CHROME_TAG` variable, set to `"155.0"`. The `.with-selenium-chrome` service now uses `selenium/standalone-chrome:$SELENIUM_CHROME_TAG`, and the job that runs with `COMPOSER_UPDATE: "1"` overrides the tag to `latest`. The issue text proposed 152.0, but the diff pins 155.0.

`CKEditor5AllowedTagsTest::testFullHtml()` is now skipped with `markTestSkipped()`. Newer ChromeDriver treats zero-height elements as not displayed, which exposed empty filter tips under text format selectors. That is tracked in [#3621903](https://www.drupal.org/node/3621903).

The issue notes that Chromium has not formally shipped this feature, so a later Chrome may remove the flag. The alternative was waiting for two animation frames after each click and form submit. It costs about 30 ms per click, so it was not chosen. It is being explored separately in [#3631249](https://www.drupal.org/node/3631249) for the remaining random failures. Related earlier discussion: [#2909782](https://www.drupal.org/node/2909782) and [#2936122](https://www.drupal.org/node/2936122).
