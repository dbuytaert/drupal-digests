## Summary

Drupal's installer used to install the database driver module (for databases other than core's built-in drivers, such as PostgreSQL) as a separate, dedicated step before any other module was installed. This issue removes that special case: the database driver module is now installed together with the rest of the site's modules, using the same batch installation process, while still guaranteeing it goes in first and triggers the container rebuild it needs. This is an internal installer change with no effect on how sites are built or configured.

## Impact

No upgrade or configuration changes required.

## Technical details

The dedicated call to `module_installer->install([$provider], TRUE)` inside `drupal_install_system()` in `install.inc` is removed. Instead, a new helper `_install_get_database_module_name()` in `install.core.inc` inspects the active database connection (via `Database::getConnection()->getProvider()` and its `autoload` option looking for `src/Driver/Database/`) to determine whether the database is provided by a driver module rather than core. If so, `install_profile_modules()` prepends that module to the list of modules to install with `array_unshift()`, and `install_recipe_required_modules()` marks it as required so it sorts to the front of the batch alongside modules flagged `required` in their `.info.yml`.

This relies on the `container_rebuild_required` info key mechanism (introduced for the related change in [#3614153](https://www.drupal.org/node/3614153), which did the same for the System module). `pgsql.info.yml` now sets `container_rebuild_required: true`, so `install_profile_modules()`'s batch grouping logic in `install.core.inc` puts the driver module in its own batch group and rebuilds the container before and after installing it, the same way any other module can request a rebuild, rather than through installer-specific code.

A follow-up, [#3618797](https://www.drupal.org/node/3618797), was filed to replace the remaining `_install_get_database_module_name()` helper with `Database::getConnection()->getProvider()` directly.
