## Summary

When a Drupal installation profile is configured to be uninstalled right after installation (as Drupal CMS's installer profile does), the installer was rebuilding the routing table twice in a row: once implicitly because uninstalling the profile module always rebuilds the router, and once explicitly at the end of `install_finished()`. Each rebuild took around 450ms in testing, so this doubled work was adding noticeable time to the last step of installation. The fix skips the redundant explicit rebuild in that case, so installs that uninstall their profile finish faster with no change in the end result.

## Impact

No upgrade or configuration changes required.

## Technical details

In `install_finished()`, the explicit `\Drupal::service('router.builder')->rebuild()` call is now only made in the branch where the profile is kept (`$install_state['profile_info']['keep_profile']` is true). When the profile is instead uninstalled via `\Drupal::service('module_installer')->uninstall([$profile])`, that call's own module uninstall process already triggers a router rebuild, so the subsequent explicit rebuild was pure duplicate work. The comment explaining why the rebuild is needed at all (the installer never fires `KernelEvents::TERMINATE`, which normally triggers this rebuild via an HTTP kernel) was moved alongside the remaining call site.
