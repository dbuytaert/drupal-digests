## Summary

Drupal's default .htaccess already blocked direct web access to package.json and yarn.lock (from [#3308369](https://www.drupal.org/node/3308369)) but did not block package-lock.json, the lock file produced by npm. Contributed themes or modules that use npm instead of Yarn, such as Gin, can ship a package-lock.json alongside their code, and until now that file was publicly downloadable if placed in the docroot. This change extends the existing protection to also cover package-lock.json, as a hardening measure. It does not affect Drupal core itself, which uses Yarn and does not produce this file, but it protects sites running contributed themes or modules that do.

## Impact

Affects site owners.

- **Security:** package-lock.json files (produced by npm, used by some contrib themes/modules such as Gin) are now blocked from direct HTTP access, matching the existing protection for package.json and yarn.lock.

## Technical details

The fix widens the existing `FilesMatch` regex in `.htaccess` from matching `package\.json` to `package(-lock)?\.json`, so `package-lock.json` gets a `403` alongside `package.json`, `yarn.lock`, `composer.json` and `composer.lock`. The equivalent PHP built-in web server protection in `Drupal\Core\Test\PhpUnitTestSuiteBaseTest` / the core `getProtectedFiles()` helper (used for the file-serving fallback when no `.htaccess` support exists) was updated the same way, adding an explicit `$file_paths["$path/package-lock.json"] = 403;` entry next to the existing `package.json` and `yarn.lock` entries. Test coverage was added with a fixture `package-lock.json` file to verify the new rule returns `403`. The scaffold files that generate `.htaccess` for site installs were updated to match, since `.htaccess` is normally scaffolded rather than hand-maintained.

## Upgrade

Sites with a customized `.htaccess` (including scaffold-managed sites that override the scaffolded file) should apply the same change manually: replace `package\.json` with `package(-lock)?\.json` in the `FilesMatch` rule, for example:
```
^(\.(?!well-known).*|Entries.*|Repository|Root|Tag|Template|composer\.(json|lock)|web\.config|yarn\.lock|package(-lock)?\.json)$
```
