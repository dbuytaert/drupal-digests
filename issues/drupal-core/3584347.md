## Summary

Admin pages such as the permissions page offer a "compact mode" that hides field descriptions to reduce clutter. This used to be implemented server-side: clicking the toggle loaded the `/admin/compact/{mode}` route, which set a `Drupal_visitor_admin_compact_mode` cookie (with a `system.site:admin_compact_mode` config fallback), and every request re-rendered the page accordingly. That mechanism has been deprecated and replaced with a purely client-side implementation: toggling compact mode now happens instantly via JavaScript and `localStorage`, with no page reload and no cookie or config lookup on the server.

## Impact

Affects module maintainers, front-end developers and site owners.

- **Config change:** `system.site:admin_compact_mode` config key is deprecated in 11.5.0, removed from 12.0.0, and cleared by the new `system_post_update_clear_admin_compact_mode_config()` update function.
- **Theme change:** Admin block templates (`system-admin-block-content.html.twig` and the `claro`/`gin` equivalents) no longer receive a `compact` boolean variable; description elements are now always rendered and marked with a `data-admin-compact-collapsible` attribute that CSS hides based on a `data-admin-compact-mode` attribute on `<html>`.
- **API change:** `system_admin_compact_mode()` and `SystemController::compactPage()` (route `system.admin_compact_page`) are deprecated in Drupal 11.5.0 and removed in Drupal 12.0.0, with no server-side replacement.
- **Deprecation:** Admin compact mode moved entirely to the client: the `system.site:admin_compact_mode` config key and the cookie/config based toggle are deprecated in favor of a `localStorage` flag set purely in JavaScript.

## Technical details

The old flow relied on `system_admin_compact_mode()` reading a cookie (falling back to `system.site:admin_compact_mode` config) and controllers/preprocess functions like `SystemAdminThemePreprocess::preprocessAdminBlockContent()` and `UserPermissionsForm::buildForm()` conditionally omitting description markup server-side. Both `system_admin_compact_mode()` and `SystemController::compactPage()` now call `@trigger_error()` and are marked `@deprecated` in 11.5.0 for removal in 12.0.0, with no replacement (see the linked change record 3588109). The `admin_compact_mode` key is stripped from `system.site.yml` defaults and cleared from existing sites via `system_post_update_clear_admin_compact_mode_config()`.

The replacement lives entirely in a new `system/drupal.system.admin_compact` library (`system.admin_compact.js` + `.css`). It sets a `data-admin-compact-mode` attribute on the document root from a `Drupal.admin.compact_mode` `localStorage` value before behaviors attach (to avoid flicker), and toggles it on click of any `[data-admin-compact-toggle]` element. Description elements that used to be conditionally rendered are now always rendered but wrapped with `data-admin-compact-collapsible`, hidden purely via the CSS rule `:root[data-admin-compact-mode] [data-admin-compact-collapsible] { display: none; }`. `Drupal\Core\Render\Element\SystemCompactLink::preRenderCompactLink()` no longer builds a URL to the toggle route; it renders a static `#` link carrying `data-admin-compact-toggle` that the new behavior intercepts. An accessibility follow-up to turn this link into a proper switch/button is tracked in [#3593539](https://www.drupal.org/node/3593539).

## Upgrade

If a theme overrides `system-admin-block-content.html.twig` (or the `claro`/`gin` versions) and checks the old `compact` variable, remove that check. Descriptions are now always passed through; mark the collapsible element instead, matching core:

```twig
<dd class="list-group__description" data-admin-compact-collapsible>{{ item.description }}</dd>
```

Replace any calls to `system_admin_compact_mode()` or links to `/admin/compact/{mode}`: there is no server-side replacement. Compact mode is now a purely client-side `localStorage` flag (`Drupal.admin.compact_mode`), toggled by attaching `data-admin-compact-toggle` to a clickable element and depending on the `system/drupal.system.admin_compact` library.

### Collaboration

The design shifted during review. znerol originally proposed moving compact mode entirely into `localStorage`, but andypost cautioned that server-side controllers still rely on knowing the compact state, questioning whether a client-only replacement was feasible. nicxvan then built an MR implementing the `localStorage` approach anyway, noting "all of the core interactions with this do it server side", and mstrelan separately suggested making it a per-user account preference instead (similar to Gin theme's appearance setting). nicxvan reported discussing the tradeoffs in Slack with catch and andypost before settling on the final approach, crediting them and Godotislate for help working out the details.
