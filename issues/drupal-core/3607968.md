## Summary

Following up on the introduction of PHP attributes for route discovery ([#3311365](https://www.drupal.org/node/3311365)), Drupal core now provides its own `#[Route]` attribute that extends Symfony's, adding a top level `title` property. Previously, setting a page title on an attribute-based route required nesting it inside `defaults: ['_title' => ...]`; now it can be written as `title: new TranslatableMarkup('...')` directly on the attribute. The new attribute also supports closures for dynamic titles, letting modules avoid writing a separate `_title_callback` controller method just to compute a title. This is a developer-facing convenience change with no end-user visible effect, aside from the many core routes (`system.module`'s admin pages, block content add form, etc.) that were converted to use it.

## Impact

Affects module maintainers.

- **Deprecation:** `BlockContentController::getAddFormTitle()` is deprecated in favor of a title closure on the route attribute.
- **New API:** New `title` property on Drupal's `#[Route]` attribute (`Drupal\Core\Routing\Attribute\Route`, extending Symfony's), accepting a string, `TranslatableMarkup`, or closure for the page title.

## Technical details

The new `Drupal\Core\Routing\Attribute\Route` class extends `Symfony\Component\Routing\Attribute\Route` and, in its constructor, moves a passed `title` argument into `$this->defaults['_title']`. Passing both `title` and a `_title` default simultaneously trips an assertion. Because closures cannot be serialized into the router table, `AttributeRouteDiscovery::getAttributes()` detects a closure title and replaces it in the stored defaults with a `_title_closure` reference tuple of `[class, method, index]` (the `index` disambiguates multiple `#[Route]` attributes on the same method). `TitleResolver::getTitle()` was updated to recognize `_title_closure` and resolve the actual closure at render time via the new static method `Route::getTitleClosure()`, which re-reflects the method's attributes to retrieve the closure (since it can't be persisted) and resolves controller arguments the same way `_title_callback` does, except without container access.

All core routes previously using `defaults: ['_title' => ...]` on attribute-based routes were converted to the top level `title` property, including the `system.module` admin controllers and `SiteInformationForm`. `BlockContentController::addForm()`'s route was converted to use a closure title (`title: static function (BlockContentTypeInterface $block_content_type) {...}`), and its old `getAddFormTitle()` method was deprecated for removal in Drupal 13.0.0, with the accompanying `block_content.add_form` YAML route definition removed since discovery now happens purely through the attribute.

## Upgrade

Modules converting `*.routing.yml` route definitions to `#[Route]` attributes (per [#3311365](https://www.drupal.org/node/3311365)) can now write, instead of:

```php
#[Route(
  path: '/admin/config/system/site-information',
  name: 'system.site_information_settings',
  requirements: ['_permission' => 'administer site configuration'],
  defaults: ['_title' => new TranslatableMarkup('Basic site settings')],
)]
```

the shorter:

```php
#[Route(
  path: '/admin/config/system/site-information',
  name: 'system.site_information_settings',
  title: new TranslatableMarkup('Basic site settings'),
  requirements: ['_permission' => 'administer site configuration'],
)]
```

For dynamic titles that don't need injected services, a closure can replace a separate `_title_callback` method:

```php
#[Route(
  path: '/block/add/{block_content_type}',
  name: 'block_content.add_form',
  title: static function (BlockContentTypeInterface $block_content_type) {
    return new TranslatableMarkup('Add %type content block', ['%type' => $block_content_type->label()]);
  },
  requirements: ['_entity_create_access' => 'block_content:{block_content_type}'],
)]
```

Code calling `Drupal\block_content\Controller\BlockContentController::getAddFormTitle()` should stop using it before Drupal 13.0.0.

### Collaboration

The design went through several iterations before landing. longwave initially proposed extending the Symfony `Route` attribute, but also floated an alternative of a separate `#[PageTitle]` attribute (mirroring how Symfony handles access control via a separate `#[IsGranted]` attribute). godotislate and mstrelan weighed in on the tradeoffs, and godotislate pointed out the deciding issue: `SystemController::systemAdminMenuBlockPage()` has several different `#[Route]` attributes stacked on one method, each needing its own title, which rules out a single class or method level `#[PageTitle]` attribute since there would be no way to tell which title belongs to which route. This led longwave to add closure support directly to the `#[Route]` attribute and solve the "which attribute" ambiguity by recording an `[class, method, index]` reference during route discovery. godotislate reviewed the resulting MR, confirmed the route discovery skip-file logic still worked with the new attribute, and catch merged it, noting it was "soft-blocking a lot of route conversions from YAML."
