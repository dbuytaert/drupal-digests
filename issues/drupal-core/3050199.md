## Summary

Drupal previously blocked changes to a node's menu settings (parent, weight, or removing the menu link) while editing a pending, non-default revision by attaching a validation constraint directly to the node entity type. Because that constraint ran on every save of a node, not just form submissions, it could reject unrelated saves made through code that doesn't go through the node edit form, such as JSON API or REST requests, or programmatic saves during content moderation workflows (as reported in [#3048698](https://www.drupal.org/node/3048698)). This entity-level check has been removed. The same protection now runs only as part of the node add/edit form's validation, so saving a node's menu settings through other means, such as web services or custom code, is no longer restricted by this rule.

## Impact

Affects module maintainers.

- **Deprecation:** `MenuSettingsConstraint` and `MenuSettingsConstraintValidator` are deprecated in drupal:11.5.0 for removal in drupal:13.0.0; the check they performed moved to `MenuUiHooks::formNodeFormValidate()`.

## Technical details

The check lived in `MenuSettingsConstraint`/`MenuSettingsConstraintValidator`, added to the `node` entity type unconditionally in `MenuUiHooks::entityTypeBuild()`. Since `$entity->menu` is only populated by `menu_ui_node_builder()` during a node form submission, the constraint's logic was effectively meaningless outside that context, which is what [#3048698](https://www.drupal.org/node/3048698) and [#3010750](https://www.drupal.org/node/3010750) ran into.

The fix drops the `$entity_types['node']->addConstraint('MenuSettings', [])` call from `entityTypeBuild()` and moves the equivalent logic into a new `MenuUiHooks::formNodeFormValidate()` method, registered via `$form['#validate'][]` inside `formNodeFormAlter()`. It reads the submitted `menu` form value plus `MenuUiUtility::getMenuLinkDefaults()` and calls `$form_state->setErrorByName()` for the same three cases the old constraint reported: removing a menu link, changing its parent menu, or changing its weight, all while editing a pending revision.

`MenuSettingsConstraint` and `MenuSettingsConstraintValidator` remain in the codebase but are marked `@deprecated` for removal in Drupal 13.0.0 (see https://www.drupal.org/node/3606616); the validator's `validate()` method now only triggers an `E_USER_DEPRECATED` notice and performs no validation.</technical>
<parameter name="upgrade">Code that explicitly instantiates or extends `MenuSettingsConstraint` or `MenuSettingsConstraintValidator` should stop doing so before Drupal 13.0.0, when they will be removed:

```php
/**
 * @deprecated in drupal:11.5.0 and is removed from drupal:13.0.0. Menu
 *   settings validation is now handled as a form validation callback in
 *   \Drupal\menu_ui\Hook\MenuUiHooks::formNodeFormValidate().
 */
```

If your code relies on menu settings for pending revisions being protected outside the node edit form (for example, saves through JSON API, REST, or custom code), add your own validation, since the node entity type no longer carries the `MenuSettings` constraint.
