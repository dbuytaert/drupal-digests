## Summary

Fixes a security vulnerability in the file upload widget used by file and image fields. Previously, a logged in user could tamper with the file ID submitted by the upload form (for example by editing the hidden `fids` input in browser dev tools) and cause another user's private file, one they had no permission to view or download, to be attached to their own content. An attacker did not need to know the file's contents, only its numeric ID, which is easy to guess since file IDs are sequential. Sites using private file storage for file or image fields should update to receive this fix.

## Impact

Affects site owners.

- **Security:** Insecure Direct Object Reference (IDOR) in the `ManagedFile` upload widget allowed a user to attach a private file they do not have download access to (identified only by guessing its `fid`) to their own content.

## Technical details

The fix is in `ManagedFile::valueCallback()` in `core/modules/file/src/Element/ManagedFile.php`. When processing newly uploaded files for multi-value widgets, the code now loads all candidate files with `File::loadMultiple($fids)` and filters out any whose `$file->access('download')` check fails for the current user, removing those denied fids from the array before they are stored on the field. The same access check was added to the code path that reconstructs `$fids` from `$default_fids` (used when redisplaying a form after validation errors or AJAX rebuilds), replacing a bare `File::load($fid)` existence check with an `access('download')` check via `File::loadMultiple()`.

A new test, `ManagedFileFidValidationTest`, exercises this directly: it creates a private, temporary file owned by one user, then logs in as a second user and confirms that submitting a form with the first user's fid injected via the URL (simulating a tampered request) does not result in that fid being accepted, whether or not the second user also performs a legitimate upload in the same request. An existing image test (`testDefaultImages`) needed a `setOwner()` call added so its private test images remain accessible to the test's own user under the new check.
