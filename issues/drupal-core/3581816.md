## Summary

The Navigation module's "Shortcuts" block used to reach directly into the Shortcut module's render logic, and Shortcut had no awareness of the block it powered in Navigation's layout. This left a gap: if a site uninstalled the Shortcut module while keeping Navigation, the Shortcuts block placement stayed behind in Navigation's block layout configuration, pointing at a module that no longer provided it. This issue moves ownership of the Shortcuts navigation block, its lazy builder, and its layout defaults into the Shortcut module itself, so installing or uninstalling either module now correctly adds or removes the block from Navigation's layout. Existing sites get an update hook that removes any orphaned Shortcuts block left over from before this change.

## Impact

Affects site owners.

- **Config change:** New `navigation_post_update_remove_shortcut_block()` update hook strips any leftover `navigation_shortcuts` block component from `navigation.block_layout` config on sites where Navigation is installed but Shortcut is not.

## Technical details

The block plugin backing `navigation_shortcuts` now lives as `Drupal\shortcut\Plugin\Block\ShortcutNavigationBlock` (marked `@internal`). `Drupal\navigation\Plugin\Block\NavigationShortcutsBlock` becomes a thin subclass kept only for backward compatibility, carries `@deprecated in drupal:11.5.0 and is removed from drupal:12.0.0`, and no longer carries the `#[Block]` attribute itself, so plugin discovery resolves to the Shortcut class. The lazy builder moved from `Drupal\navigation\ShortcutLazyBuilder` to `Drupal\shortcut\ShortcutNavigationLazyBuilder`, and the container registration of the `navigation.shortcut_lazy_builder` service moved from `NavigationServiceProvider` to a new `Drupal\shortcut\ShortcutServiceProvider`, keyed off the `navigation.renderer` service existing rather than a shortcut-specific one.

Shortcut now implements `hook_navigation_defaults()` and `hook_block_alter()` (previously implemented in `NavigationHooks`) to supply the default block placement and the `allow_in_navigation`/`_block_ui_hidden` flags for `navigation_shortcuts`. Because Navigation stores this plugin placement in simple config (`navigation.block_layout`), which per [#3587499](https://www.drupal.org/node/3587499) can't formally express a dependency on Shortcut, `shortcut_install()` and `shortcut_uninstall()` now directly add or remove the block component from that config, with a duplicate check for the case where both modules install in the same request. A new `navigation_post_update_remove_shortcut_block()` post-update cleans up any leftover placement on existing sites. The commit initially shipped with a wrong namespace on the new `NavigationUpdateTest` fixture test, was reverted, and recommitted with the namespace corrected to `Drupal\Tests\navigation\Functional\Update`.

## Upgrade

Code that instantiates or type-hints `Drupal\navigation\Plugin\Block\NavigationShortcutsBlock` directly should switch to the new class before Drupal 12.0.0:

```php
// Before (deprecated in 11.5.0, removed in 12.0.0):
use Drupal\navigation\Plugin\Block\NavigationShortcutsBlock;

// After:
use Drupal\shortcut\Plugin\Block\ShortcutNavigationBlock;
```

Code referencing the internal `Drupal\navigation\ShortcutLazyBuilder` class directly (not the `navigation.shortcut_lazy_builder` service, which keeps its name) must update to `Drupal\shortcut\ShortcutNavigationLazyBuilder`; no deprecation shim was left for this internal class.

### Collaboration

berdir diagnosed the underlying design problem (comment [#16568255](https://www.drupal.org/node/16568255)): Navigation stores plugin configuration with cross-module dependencies in simple config, which can't formally declare those dependencies, so removing Shortcut broke `ConfigImportAllTest`. He recommended a quick test exclusion rather than a full refactor, and quietone filed the follow-up [#3587499](https://www.drupal.org/node/3587499) to track the proper fix. godotislate reviewed the install/uninstall ordering in detail (comments [#16602087](https://www.drupal.org/node/16602087), [#16609667](https://www.drupal.org/node/16609667)) and found that `hook_navigation_defaults` already fires on `hook_modules_installed`, which meant an initially-proposed change to `shortcut_install()` wasn't actually needed. smustgrave reported using Claude to help add the duplicate-block check that finally made the test suite pass. After the fix first landed, quietone caught that it had to be reverted because of a namespace error in the new update-path test, matching a pattern seen in a similar Olivero test-migration issue, and it was recommitted with the namespace corrected.
