## Summary

The Status Report page (`admin/reports/status`) now lists the actual database connection details, host, database name, and table prefix, for every configured database connection, not just the default one. Previously the status page gave no indication of which database(s) a site was actually connected to, which made it easy to mix up databases when cloning or migrating sites for testing. The new "Database connection" (or "Database connections", pluralized when there is more than one) entry surfaces this information directly, including any additional connections such as a `replica` target.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix lives in `SystemManager::checkRequirements()` in `system.module`. It calls `Database::getAllConnectionInfo()` to retrieve every configured connection (keyed by connection name, e.g. `default`, and then by target, e.g. `default`, `replica`), and builds a `$requirements['database_connection']` entry with one line per connection/target showing `Host: %host` (omitted for drivers like SQLite that have no host key), `Database: %database`, and either `Prefix: %prefix` or `No prefix`. The requirement's title uses `PluralTranslatableMarkup` so it reads "Database connection" or "Database connections" depending on how many are configured.

The accompanying test in `SystemTest::testStatusPage()` (in `core/modules/system/tests/src/Functional/System/SystemTest.php`) asserts the presence of the host/database/prefix text, branching on `databaseType() === 'sqlite'` since SQLite connections have no `host` key.
