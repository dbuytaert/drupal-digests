## Summary

New sites installed with the Standard profile no longer show a node listing at `/node` as the front page. Instead the front page is now the login page, and a one-time welcome message (with links to the User Guide, community, events, Slack, and support) is shown after installation and disappears like any other status message. The node listing view that used to power the front page still exists (it's needed for the "Promoted" content checkbox and the RSS feed) but is now called "Promoted Content" and ships disabled, so it no longer silently leaks unpublished-looking content on sites that never intended to use a blog-style listing. Olivero's special-cased "Get Started" guide, previously shown on `/node` until you promoted content, is removed; if you enable the Promoted Content view and it has no results, Olivero now shows the view's own (much shorter) configured empty text instead.

## Impact

Affects module maintainers and site owners.

- **Config change:** Node module's `views.view.frontpage` is renamed to `views.view.promoted_content` and now ships disabled by default; the Standard profile's default front page (`system.site` `page.front`) changes from `/node` to `/user/login`.
- **API change:** The generic `Congratulations, you installed @drupal!` messenger message in `install_finished()` (`core/includes/install.core.inc`) was removed; install profiles/distributions that want a post-install welcome message must add their own (see `standard_install_finished()` in `core/profiles/standard/standard.profile`).

## Technical details

The core change is that `core/modules/node/config/optional/views.view.frontpage.yml` is renamed to `views.view.promoted_content.yml` with `status: false`, its empty-view text trimmed to `'No promoted content has been created yet.'`, and its title area cleared (it was `'Welcome!'`). Because the view is disabled by default, its routes (`view.promoted_content.page_1`, `.feed_1`) don't exist until something enables it, so a large share of the diff is test plumbing: a new `PromotedContentViewTestTrait` (`core/modules/node/tests/src/Traits/PromotedContentViewTestTrait.php`) with `enablePromotedContentView()` is applied across dozens of test classes that relied on `/node` or the RSS feed, and those tests now explicitly enable the view and rebuild the router.

Olivero's `views-view--frontpage.html.twig` is renamed to `views-view--promoted-content.html.twig` and its `{% elseif empty %}` branch no longer includes the deleted `includes/get-started.html.twig`; it just renders the view's own `{{ empty }}` region. The former "Congratulations" messenger call in `install_finished()` is gone entirely; the Standard profile now implements `hook_install_tasks_alter()` in the new `core/profiles/standard/standard.profile` to append a `standard_install_finished` task that adds the richer welcome message via `\Drupal::messenger()->addStatus()`. The Standard profile's `system.site.yml` and the `core/recipes/standard/recipe.yml` both change `page.front` from `/node` to `/user/login` and drop `views.view.frontpage` from the recipe's enabled-views list. A separate `NodePerformanceTest` was split out of `StandardPerformanceTest` to keep covering cache-invalidation behavior of the (now non-default) promoted content view, since `StandardPerformanceTest` itself no longer exercises `/node` by default.

### Collaboration

The design went through several rounds of rethinking captured in the thread. gábor hojtsy initially special-cased the welcome text back into Olivero's templates, but lauriii pushed back that a persistent per-request template didn't fit and asked whether it should instead be a one-time post-install message. gábor hojtsy prototyped both options, comparing screenshots of the ephemeral installer message versus the persistent view-driven one, and pameeela weighed in from the Drupal CMS perspective that the disappearing-on-content-creation behavior was confusing and that a one-time message was clearer. That feedback settled the final approach: moving the welcome text into a one-off `standard_install_finished()` message and removing the generic installer message entirely. Separately, berdir did repeated close reviews of the performance test assertions across several rebases to make sure the query/cache-count changes in `StandardPerformanceTest` and the new `NodePerformanceTest` were fully understood and justified, flagging a roughly 3x increase in config-invalidation rebuild cost that was discussed and accepted as a worthwhile tradeoff for the lighter default front page.
