## Summary

Drupal has deprecated the long-standing procedural functions `user_login_finalize()` and `user_logout()` in favour of two new services. Logging a user in or out still works exactly the same way for site visitors; this change is about how module code performs those actions. Any custom or contributor code that calls these functions directly will keep working but will trigger a deprecation notice, and should switch to the new services before Drupal 13.

## Impact

Affects module maintainers.

- **Deprecation:** `user_login_finalize()` and `user_logout()` are deprecated in drupal:11.5.0 and will be removed in drupal:13.0.0; use the new `LoginFinalizer`/`LogoutFinalizer` services instead.
- **New API:** New final services `Drupal\user\LoginFinalizer` (`finalizeLogin()`) and `Drupal\user\LogoutFinalizer` (`finalizeLogout()`) registered in `user.services.yml`.

## Technical details

The procedural logic previously living in `user_login_finalize()` and `user_logout()` (session regeneration, updating the last-login timestamp, invoking `hook_user_login()`/`hook_user_logout()`, destroying the session, and logging) has been moved verbatim into two new `final readonly` classes, `Drupal\user\LoginFinalizer::finalizeLogin()` and `Drupal\user\LogoutFinalizer::finalizeLogout()`. Both are plain services (no interfaces: an interface was originally proposed but dropped after `berdir` questioned the need for a swappable API with no known use case) declared in `user.services.yml`. The old functions now just emit an `E_USER_DEPRECATED` notice and delegate to the new services.

All core call sites were switched to constructor-injected dependencies instead of calling the global functions: `UserAuthenticationController`, `UserController`, `UserLoginForm`, `UserLogoutConfirm`, `RegisterForm`, and `install.core.inc`. Each affected constructor gained new optional `LoginFinalizer`/`LogoutFinalizer` parameters defaulting to `NULL`, with a deprecation notice thrown when omitted so that existing subclasses keep working until the parameter becomes required. `MaintenanceModeSubscriber`, which runs on every request, injects the logout service lazily via `#[AutowireServiceClosure(LogoutFinalizer::class)]` rather than eagerly resolving it in the constructor.</technical>
<parameter name="upgrade">Replace direct calls to the deprecated functions:
```php
// Before
user_login_finalize($account);
user_logout();

// After
\Drupal::service(\Drupal\user\LoginFinalizer::class)->finalizeLogin($account);
\Drupal::service(\Drupal\user\LogoutFinalizer::class)->finalizeLogout();
```

Prefer constructor injection of `Drupal\user\LoginFinalizer` and/or `Drupal\user\LogoutFinalizer` where possible.

If you subclass `UserAuthenticationController`, `UserController`, `UserLoginForm`, `UserLogoutConfirm`, or `RegisterForm` and call their constructors directly, pass the new `$loginFinalizer`/`$logoutFinalizer` arguments to avoid deprecation notices; they will become required in a future release.

### Collaboration

This task sat open for over a decade before landing. Late in its life, `catch` and `longwave` pushed back on the design, questioning whether bundling login/logout into one service with seven dependencies made sense, and whether an event-based approach would be more flexible than a `final` service. `berdir` explained the real motivation (moving one of the last `.module`-level procedural calls out of controllers so `.module` files only need loading when a hook actually fires) and argued against duplicating the existing login/logout hooks with events. `znerol` sketched out a longer-term vision for a unified login/logout API with pluggable authentication mechanisms, but the group (`heddn`, `kim.pepper`) agreed to keep this issue narrowly scoped and defer that redesign. Based on the feedback, `kim.pepper` split the single service into separate `LoginFinalizer` and `LogoutFinalizer` classes and removed the interfaces after `berdir` pointed out core has moved away from adding interfaces without a concrete use case. TFA maintainer `cmlara` flagged that contrib modules call `user_login_finalize()` directly for non-form logins, which shaped the decision to keep the deprecated procedural wrappers rather than removing them outright.</collaboration>
