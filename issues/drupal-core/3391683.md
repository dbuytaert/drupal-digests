## Summary

Drupal core has deprecated several procedural functions from the update.inc include file: `update_check_requirements()`, `update_system_schema_requirements()`, `update_do_one()`, and the internal `_update_fix_missing_schema()`. Their logic has moved to a new `Drupal\Core\Update\DatabaseUpdate` service class. This is part of a longer-running effort to stop relying on manually included legacy `.inc` files and let the class autoloader handle this code instead. There is no behavioral change for site owners; this only affects developers and contrib/custom code that calls these functions directly.

## Impact

Affects module maintainers.

- **Deprecation:** `update_check_requirements()`, `update_system_schema_requirements()`, `update_do_one()`, and `_update_fix_missing_schema()` in update.inc are deprecated in favor of methods on the new `Drupal\Core\Update\DatabaseUpdate` service.
- **New API:** New `Drupal\Core\Update\DatabaseUpdate` autowired service providing `getRequirements()`, `systemSchemaRequirements()`, and `doOne()`.

## Technical details

The new `Drupal\Core\Update\DatabaseUpdate` class (registered as an autowired service) exposes `getRequirements()`, `systemSchemaRequirements()`, `doOne()`, and an `@internal` `fixMissingSchema()` method, reproducing the logic that used to live in the standalone functions but using constructor-injected dependencies (`UpdateHookRegistry`, `ModuleHandlerInterface`, `MessengerInterface`, `LoggerChannelFactoryInterface`) instead of `\Drupal::service()` lookups. The old update.inc functions are now thin deprecated wrappers that trigger `E_USER_DEPRECATED` and delegate to `\Drupal::service(DatabaseUpdate::class)`.

`DbUpdateController` was updated to take `DatabaseUpdate` and `UpdateHookRegistry` as (nullable, for backward-compatible construction) constructor arguments, using them internally instead of calling `update_check_requirements()` or `\Drupal::service('update.update_hook_registry')` directly. The batch operation that used to invoke the procedural `update_do_one` callback now calls the class method callable `DatabaseUpdate::class . ':doOne'`. This issue was scoped to the first three functions of update.inc; it is a followup to the "[#2999721](https://www.drupal.org/node/2999721): [META] Deprecate the legacy include files before Drupal 9" effort, and further update.inc functions are handled in separate follow-up issues.

## Upgrade

Replace direct calls to the deprecated update.inc functions with the new service:

```php
// Before:
$requirements = update_check_requirements();
$schema_requirements = update_system_schema_requirements();
update_do_one($module, $number, $dependency_map, $context);

// After:
$requirements = \Drupal::service(\Drupal\Core\Update\DatabaseUpdate::class)->getRequirements();
$schema_requirements = \Drupal::service(\Drupal\Core\Update\DatabaseUpdate::class)->systemSchemaRequirements();
\Drupal::service(\Drupal\Core\Update\DatabaseUpdate::class)->doOne($module, (int) $number, $dependency_map, $context);
```

`_update_fix_missing_schema()` has no direct public replacement; its logic is now `DatabaseUpdate::fixMissingSchema()`, which is marked `@internal`.

Any code constructing `DbUpdateController` directly should pass the new `$databaseUpdate` and `$updateHookRegistry` constructor arguments; omitting them still works but triggers a deprecation notice and will be required in Drupal 13.
