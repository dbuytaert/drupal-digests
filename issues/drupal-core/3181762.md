## Summary

Validation errors from the Link field widget now name the field they belong to. When an entity form has several Link fields and more than one is invalid, each message identifies its own field instead of showing generic text the user has to hunt down. The wording of the messages changed, so custom tests, translations, or scripts that match the old text need updating.

## Impact

Affects front-end developers.

- **Theme change:** None

## Technical details

In `LinkWidget::formElement()` the URI element now carries a `#field_label` property copied from the widget element's `#title`. `validateUriElement()` uses it as the `%field_name` placeholder in the invalid internal path messages for the external, internal and generic link types. For example, the generic message is now "The %field_name field must contain a content title, an internal path starting with /, ? or #, or a full external URL including the protocol, such as %link_example." The `LINK_INTERNAL` message also gained `$args`, which it previously lacked.

`validateTitleNoLink()` now reads "The %field_name field: @uri is required when @title is specified.", with `%field_name` taken from `$element['#title']`. The old "Enter a content title to select it..." and "External links must be a full URL..." strings are gone. Tests in the link module's `LinkFieldTest` and a menu_link_content form test were updated to the new strings. The field name pattern follows `OptionsWidgetBase`.

## Upgrade

Update any custom tests or code that assert on the old text, for example:

```
// Before
'Enter a content title to select it, or enter an internal path starting with /, ? or #.'
// After (internal link type)
'The %field_name field must contain a content title or an internal path starting with /, ? or #.'
```
The same applies to `'The @uri field is required when the @title field is specified.'`, which is now `'The %field_name field: @uri is required when @title is specified.'`. Translations of the old strings will need re-translating.
