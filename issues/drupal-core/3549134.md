## Summary

Drupal's long-deprecated "Text (formatted, long, with summary)" field type is being carved out of the core `text` module into its own dedicated, deprecated `text_with_summary` module, as the final step of removing it from core ahead of Drupal 12. Existing sites that already use this field type (most commonly the `body` field on nodes) are automatically migrated: an update hook installs the new `text_with_summary` module when any field of that type is detected, and follow-up update hooks repoint the `module` dependency on the affected field storage, field, form display, and view display configuration from `text` to `text_with_summary`. No manual action is required for a normal update; the field, its data, and its "Summary or trimmed" display option keep working exactly as before.

## Impact

Affects module maintainers.

- **Deprecation:** `text_with_summary` field type/formatter/widget classes in the `text` module (`TextWithSummaryItem`, `TextSummaryOrTrimmedFormatter`, `TextareaWithSummaryWidget`) are deprecated in Drupal 11.5.0 and removed in Drupal 12.0.0; use the equivalent classes in the new `text_with_summary` module instead. The `drupal.text` asset library in `text.module` is deprecated the same way.

## Technical details

The field type plugin (`TextWithSummaryItem`), its widget (`TextareaWithSummaryWidget`), the `text_summary_or_trimmed` formatter, the associated JS behavior (`js/text.js`, the summary show/hide toggle), and the corresponding `field.field_settings.text_with_summary`/`field.value.text_with_summary`/`field.widget.settings.text_textarea_with_summary`/`field.formatter.settings.text_summary_or_trimmed` schema all move into the new `core/modules/text_with_summary` module (`lifecycle: deprecated`, depends on `drupal:text`). The old classes remain in `text` as thin, `@deprecated` shims pointing to their `text_with_summary` counterparts (see [#3568381](https://www.drupal.org/node/3568381)), and `TextTrimmedFormatter` gained a protected `addTrimPreRender()` helper so both the `text` module's own `text_trimmed` formatter and the new module's `text_summary_or_trimmed` formatter can share the trimming logic without one depending on the other's field type.

Because `text_with_summary` depends on `text` rather than the reverse, `text_with_summary` uses `hook_field_formatter_info_alter()` to re-register the `text_with_summary` field type against `text`'s `text_default`/`text_trimmed` formatters, and `hook_library_info_alter()` to make the `text` module's `drupal.text` library (now empty and marked `deprecated` in `text.libraries.yml`) depend on `text_with_summary/drupal.text`, which carries the actual JS.

The migration path lives in `text.install`'s `text_update_12001()`, which installs `text_with_summary` only if a `field_storage_config` of type `text_with_summary` exists, followed by post-update hooks (`text_post_update_update_field_storage_dependencies`, `..._field_dependencies`, `..._form_display_dependencies`, `..._view_display_dependencies`, `..._view_dependencies`) that use `ConfigEntityUpdater` to flip the recorded `module` dependency from `text` to `text_with_summary` on each affected config entity. A new `TextWithSummaryUpdatePathTest` and its fixture (`add-text-with-summary-field.php`) exercise this path directly since the base update-path fixture no longer ships a `text_with_summary` field.

## Upgrade

Update references to the deprecated classes before Drupal 12.0.0:

```php
// Before
use Drupal\text\Plugin\Field\FieldType\TextWithSummaryItem;
use Drupal\text\Plugin\Field\FieldWidget\TextareaWithSummaryWidget;
use Drupal\text\Plugin\Field\FieldFormatter\TextSummaryOrTrimmedFormatter;

// After
use Drupal\text_with_summary\Plugin\Field\FieldType\TextWithSummaryItem;
use Drupal\text_with_summary\Plugin\Field\FieldWidget\TextareaWithSummaryWidget;
use Drupal\text_with_summary\Plugin\Field\FieldFormatter\TextSummaryOrTrimmedFormatter;
```

If custom code attaches the `text/drupal.text` library directly for the summary-toggle JS, attach `text_with_summary/drupal.text` instead. Modules that declare a dependency on `text_with_summary` fields should add `drupal:text_with_summary` to their own `.info.yml` dependencies rather than relying on `text`.
