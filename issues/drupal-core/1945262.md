## Summary

Drupal's asset library system now lets a library declare that it must load `before` or `after` another library, in addition to the existing `dependencies` key. This gives module and theme authors a reliable way to control asset ordering for cases where a real dependency relationship doesn't exist (for example, a library that only reacts to another library if it happens to be present), without resorting to fragile per-file `weight` values or custom `hook_js_alter()`/`hook_css_alter()` code. As part of this change, many long-standing `weight` overrides and ordering workarounds in core library definitions (jQuery UI assets, `contextual`, `views`, `settings_tray`, CKEditor 5 translations, `locale`, `form_test`, and others) were replaced with explicit `dependencies`, `before`, or `after` declarations, or removed outright where dependencies already implied the correct order.

## Impact

Affects module maintainers.

- **New API:** Asset library definitions in `*.libraries.yml` now support `before` and `after` keys, listing other libraries that must load after or before the declaring library, respectively.

## Technical details

The core mechanism for resolving library load order was rewritten around a directed graph instead of ad hoc weight math. `LibraryDependencyResolver::doGetDependencies()` now builds a graph of libraries and their `dependencies` as edges, `doProcessBeforeAfter()` adds extra edges for any `before`/`after` keys found in each library's definition (only when the referenced library is already part of the graph), and `getLibrariesWithDependencies()` runs the result through `Drupal\Component\Graph\Graph::searchAndSort()` and then sorts by the resulting weight to produce the final load order. `getMinimalRepresentativeSubset()` was similarly reworked to use the graph's edges rather than repeatedly calling `getLibrariesWithDependencies()`.

`AssetResolver::getCssAssets()` and `getJsAssets()` no longer nudge weights by `count($css) / 30000` to preserve insertion order; instead they skip re-adding an asset file that has already been added, so the first occurrence (which reflects the correct dependency/before/after order) wins. `ckeditor5_js_alter()` no longer manipulates a synthetic `weight` to group translation files for aggregation, it just filters out translation files that don't match the current language via `array_filter()`. Similarly, `locale_js_alter()` no longer sets a `weight` to force the translation file to load first, and `settings_tray` drops its `cssAlter()` hook and `group: 200` override in favor of an `after: [core/drupal.dialog]` declaration.

Several core libraries were updated to use `before`/`after`: `drupal.contextual-links` now declares `before: [contextual/drupal.context-toolbar]`, `drupal.vertical-tabs` gets `before: [core/drupal.collapse]` (moved from `form_test`'s own weight hack), and test fixture libraries (`common_test`, `js_testing_ajax_request_test`) were added to exercise the new keys directly.

### Collaboration

This task sat open for over a decade, blocked mainly on how to remove per-file `weight` overrides without breaking ordering guarantees that weights had been silently providing. `wim leers` repeatedly identified edge cases where dependency declarations alone couldn't express the needed ordering (`contextual.toolbar.js` needing to run after `contextual.js` without formally depending on it, and the analogous `tour.js`/overlay case), which is what motivated the `before`/`after` design discussed with `sdboyer` and `nod_` back in comment #4. Early attempts to remove weights outright (`nod_`'s and `penyaskito`'s patches) were committed and then reverted by `webchick` after `wim leers` reported breakage on `/admin/config/development/testing`, and `wim leers`'s review in comment #38 caught several library comments that would have become lies (`contextual.js`, `views-contextual.js`) had the weights simply been dropped without replacement ordering guarantees. The eventual approach, proposed by `wim leers` in comment #76 (keep weights for BC while adding `before`/`after`, then deprecate weights separately), matched what `catch` suggested and was later implemented by `taran2l` in the merge request, building on `nod_`'s earlier groundwork of adding `before` keys without yet acting on them.
