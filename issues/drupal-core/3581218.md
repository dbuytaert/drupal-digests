## Summary

Drupal has deprecated the practice of putting procedural hook implementations in a theme's `.theme` file (the old-style magic-autoloaded file, e.g. `olivero.theme`). Themes are not being deprecated, only that specific file mechanism. Starting in Drupal 11.5.0, if hook discovery finds any function in a `.theme` file, it triggers a PHP deprecation warning pointing at the change record; this will become a hard removal in Drupal 13.0.0. Theme maintainers should move their remaining procedural hook implementations into OOP hook classes under `src/Hook`, as most core themes already have.

## Impact

Affects module maintainers.

- **Deprecation:** Procedural `.theme` files are deprecated starting in Drupal 11.5.0 (previously targeted 12.0.0) and will be removed in Drupal 13.0.0; hook implementations should move to OOP hook classes in `src/Hook`.
- **New API:** New `Drupal\Core\Hook\Attribute\ExtensionFileIsConverted` attribute lets a function in a `.theme` file suppress the deprecation, for legacy multi-version compatibility.

## Technical details

The deprecation is emitted from `ThemeHookCollectorPass`: while `collectThemeHookImplementations()` walks a theme's files during hook discovery, any file with a `.theme` extension is recorded in the `$deprecatedThemeFiles` property; after the container is written, `writeToContainer()` fires `@trigger_error(..., E_USER_DEPRECATED)` for each one, with a message naming the file and citing https://www.drupal.org/node/3581222. The message wording was tuned after review from alexpott.

To avoid forcing an all-or-nothing conversion, a new `#[ExtensionFileIsConverted]` attribute (`Drupal\Core\Hook\Attribute\ExtensionFileIsConverted`) can be placed on any function inside a `.theme` file to suppress the deprecation for that file; per its docblock it's meant only for legacy/multi-version support and must not be used once a project's minimum core version is >= 11.3.0. A second commit adjusted the emitted version string from `drupal:12.0.0` to `drupal:11.5.0` after the team decided to backport the deprecation to the 11.x branch rather than waiting for 12.0.0.

Documentation was also updated to drop stale references to `.theme` as a valid home for hooks: `hook_theme_suggestions_HOOK()` and `hook_theme_suggestions_HOOK_alter()` docs now point to `src/Hook` with the `#[Hook(...)]` attribute, and `ThemeHandlerInterface::themeExists()` / `ThemeManagerInterface::invoke()` no longer describe theme names as "without the .theme extension".

## Upgrade

Convert remaining procedural hooks in a theme's `*.theme` file into an OOP hook class under `src/Hook`, tagged with the `#[Hook('...')]` attribute, matching the pattern already used elsewhere in core.

If a `.theme` file must be kept temporarily to support older core versions, silence the new deprecation on a per-function basis:

```php
use Drupal\Core\Hook\Attribute\ExtensionFileIsConverted;

#[ExtensionFileIsConverted]
function mytheme_procedural_alter(array &$args): void {
  // ...
}
```

Note this attribute is only for legacy/back-compat support; once a theme's minimum supported core version is 11.3.0 or later, it must be removed along with the `.theme` file.

### Collaboration

The design went through several iterations before landing. nicxvan initially proposed checking for `.theme` files via an `ignore_theme_file_deprecation` info.yml key evaluated during `Extension::load()`, but berdir pushed back strongly (in Slack, summarized in comment [#16524050](https://www.drupal.org/node/16524050) and again in [#16546436](https://www.drupal.org/node/16546436)) that triggering deprecations on every request or test run would be too costly, and suggested an attribute-based marker instead, closer to the existing `ProceduralHookScanStop`. nicxvan tried a couple more variations (tracking via `ExtensionDiscovery`, a runtime_requirements hook) before settling on collecting and emitting the deprecation inside `ThemeHookCollectorPass` with the new `ExtensionFileIsConverted` attribute, which he called "far more elegant" despite needing an extra file cache. Late in review, alexpott caught remaining stale documentation referencing the `.theme` extension pattern (`ThemeHandlerInterface::themeExists()`, `Theme::__construct()`, `ThemeManagerInterface::invoke()`), which nicxvan fixed promptly. The team (berdir, catch, larowlan as framework/release manager) also debated and agreed to backport the deprecation into 11.5.0 rather than waiting for 12.0.0.</collaboration>
