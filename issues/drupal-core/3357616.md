## Summary

Links to the password reset page now appear only when the visitor can actually access it. On sites that disable `user.pass` (common with external authentication), a failed login now shows "Unrecognized username or password." without the "Forgot your password?" link that previously led to a 403. The same applies to the flood-control blocked messages and the current password hint on the user edit form. Because the strings change, this landed in main only (12.1.0) despite being filed as a bug.

## Impact

No upgrade or configuration changes required.

## Technical details

`UserLoginForm::validateFinal()` now builds `Url::fromRoute('user.pass')` once and calls `$pass_url->access()` before adding the link. Three messages have a no-link variant: the generic failed login error, the user-based flood message (singular and plural via `formatPlural()`), and the IP-based flood message. The flood variants end with "Try again later." when access is denied. `AccountForm::form()` applies the same check to the `current_pass` description, which drops the "Reset your password" link when access is denied. `UserLoginForm::validateFinal()` runs on form submission, which is not cached, so no cache variation was added (per alexpott's reply to the cache question). Tests add a `user_disable_password_reset` test module whose `RouteSubscriber` sets `_access: FALSE` on `user.pass`, and `UserLoginTest::testFailedLoginMessageWithNoPasswordResetAccess()`. Contributors decided against a new configuration option. Controlling the link by route access follows an existing core pattern.
