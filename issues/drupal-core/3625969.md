## Summary

Twig 3.30 changed how its `escape`/`e` filter compiles, and Drupal's mechanism for swapping in its own `MarkupInterface`-aware escaping broke as a result: every templated page threw a `TypeError` and produced a white screen of death. This fix restores compatibility so sites can run Drupal with Twig 3.30 (or Twig 3.28/3.29) without the crash. Anyone who had pinned `twig/twig` to an older version as a workaround can lift that pin once they update to a core release containing this fix.

## Impact

No upgrade or configuration changes required.

## Technical details

Twig 3.30 introduced a dedicated `EscapeFilter` node that compiles directly to `$this->escaper->escape(...)`. Drupal's `TwigNodeVisitor::leaveNode()` previously handled `escape`/`e` filters by swapping the compiled node's callable to Drupal's own `drupal_escape` filter, but leaving Twig's own `EscapeFilter` node in place to build the call. Twig 3.30 still emitted the direct `escaper->escape()` call, but built its arguments for `drupal_escape` (which needs the environment as its first parameter), so `$this->env` was inserted as an extra leading argument, every other argument shifted over, and `null` (the charset) ended up in the `$autoescape` boolean slot.

Rather than swapping the callable on Twig's own escape node at parse time, `TwigExtension::getFilters()` now registers Drupal's `escapeFilter` method directly under the names `escape` and `e` (in addition to `drupal_escape`), reusing a shared `$escape_options` array. Because Twig loads Drupal's extension after its own `EscaperExtension`, and later-registered filters of the same name win, Twig's built-in escape node/filter is overridden outright and never compiled, so the argument-shifting bug can't occur regardless of Twig version. A new `TwigExtension::escapeFilterIsSafe()` static method replaces the previous reliance on Twig's internal `twig_escape_filter_is_safe` helper as the `is_safe_callback`. `TwigNodeVisitor::leaveNode()` was simplified accordingly: it no longer swaps the node's callable, it just checks whether the filter name is `escape`, `e`, or `drupal_escape` to set `$this->skipRenderVarFunction`. A new `testEscapeFilterOverride()` test in `TwigExtensionTest` asserts that both explicit (`|escape`, `|e`) and automatic escaping compile to Drupal's own `escapeFilter` method.</technical>
