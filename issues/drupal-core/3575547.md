## Summary

`StatementPrefetchIterator` is deprecated. Only the SQLite driver extended it, and `StatementBase` is now the base class for statements, so the middle class no longer serves a purpose. The SQLite `Statement` now extends `StatementBase` directly. Contrib or custom database drivers that extend `StatementPrefetchIterator` get a deprecation notice and should move to `StatementBase`. Per the committer, this may be the first 12.1-only deprecation to land.

## Impact

Affects module maintainers.

- **Deprecation:** `\Drupal\Core\Database\StatementPrefetchIterator` is deprecated in drupal:12.1.0 and removed in drupal:13.0.0; extend `\Drupal\Core\Database\Statement\StatementBase` instead.

## Technical details

`StatementPrefetchIterator` now triggers `E_USER_DEPRECATED` when the file is loaded and in its constructor. It is marked deprecated in drupal:12.1.0 and will be removed in drupal:13.0.0. The change record is https://www.drupal.org/node/3575664.

The SQLite `Statement` class now extends `StatementBase`, uses `PdoTrait`, and has its own constructor. It takes over the prefetch logic in a new protected `executeAndPrefetch()`. That method dispatches the statement execution start, failure and end events, then runs the statement. It reads all rows into a `PrefetchedResult` and releases the client statement so no SELECT lock stays open. `execute()` still retries once on SQLite error 17 (schema change), and it now applies the `fetch` option itself with `setFetchMode()` after execution.

`getClientStatement(): \PDOStatement` previously existed as a duplicate in `StatementPrefetchIterator` and `StatementWrapperIterator`. It is now implemented once in `PdoTrait`, which replaces the abstract declaration there. The thrown exception type documented in its docblock changes from `\RuntimeException` to `\LogicException`, matching what the code actually throws. The unit test that instantiated `StatementPrefetchIterator` now uses an anonymous `StatementBase` subclass.

## Upgrade

Drivers extending the deprecated class should extend `StatementBase` and implement the prefetch logic themselves. The SQLite driver now does this:

```php
use Drupal\Core\Database\Statement\PdoTrait;
use Drupal\Core\Database\Statement\StatementBase;

class Statement extends StatementBase {
  use PdoTrait;
}
```
