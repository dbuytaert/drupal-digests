## Summary

Requests for aggregated CSS/JS files that pointed at a stale, invalid, or crafted `delta` value could crash with an uncaught "Only file JavaScript/CSS assets can be optimized" exception, producing a 500 response and filling logs with errors. This typically happened right after a deployment (which deletes all existing aggregate files) when old cached pages, reverse proxies, or crawlers replayed aggregate URLs whose `delta` no longer matched a file based group, for example because it now pointed at an externally hosted asset or one marked `preprocess: false`. Drupal now recognizes this situation and responds with a normal 400 Bad Request instead of throwing an exception, matching how other invalid aggregate requests are already handled.

## Impact

No upgrade or configuration changes required.

## Technical details

The `delta` query parameter is just a position in the list of asset groups that `\Drupal\system\Controller\AssetControllerBase::deliver()` rebuilds on every request, not a stable identifier. That list also includes groups with `type: external` or `preprocess: false`, which are never aggregated and are linked directly in the HTML. When an aggregate file is missing from disk (as happens after `drupal_flush_all_caches()`) and an incoming `delta` resolves to one of those non-aggregated groups, `deliver()` fell through to `JsCollectionOptimizerLazy::optimizeGroup()` / the CSS equivalent, which threw because `JsOptimizer::optimize()` and `CssOptimizer::optimize()` only handle file based, preprocessed groups.

The fix adds a check in `deliver()` right after resolving `$group`: if `$group['type'] !== 'file' || $group['preprocess'] === FALSE`, it throws a `BadRequestHttpException('The requested asset group is not aggregated.')` before the code reaches the hash comparison and redirect logic (a hash mismatch there would otherwise redirect back to the same non-aggregated group and hit the optimizer again). A new `KernelTests\Core\Asset\AssetControllerTest` covers this along with the controller's other existing input validation paths, and the functional `AssetOptimizationTest` was extended to also exercise `assertInvalidAggregates()` for out-of-range and hash-mismatched deltas after aggregates are deleted from disk. This overlaps with the regression tracked in [#3535330](https://www.drupal.org/node/3535330) (introduced by [#3414173](https://www.drupal.org/node/3414173)'s external minified CSS support) and with the narrower mitigation in [#3416508](https://www.drupal.org/node/3416508) that skips generating aggregates for stale requests; this fix instead makes `deliver()` itself reject the request outright.
