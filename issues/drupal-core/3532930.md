## Summary

The `Drupal\Core\Database\Database` class, along with `Connection::setKey()`/`setTarget()` and `Log::__construct()`, has been made type strict and fully documented for PHPStan's strictest level. Connection keys and targets (the identifiers used to select which database to talk to, e.g. `'default'`) have always been documented as strings, but the code silently accepted integers too. That silent acceptance is now deprecated: passing an integer key or target still works today but triggers a deprecation notice and will throw a `TypeError` once removed in Drupal 13. Sites and contributed modules that pass integers as database keys or targets (for example in multi-database setups) should switch to strings.

## Impact

Affects module maintainers.

- **API change:** `Drupal\Core\Database\Database`'s static methods now declare native `string|int` parameter types and return types (e.g. `getConnection(string|int $target = 'default', string|int|null $key = NULL): Connection`) instead of being untyped, and the class itself now uses `declare(strict_types=1)`.
- **Deprecation:** Passing a non-string value as the database connection `$key` or `$target` to `Drupal\Core\Database\Database` methods (`getConnection()`, `addConnectionInfo()`, `startLog()`, `getLog()`, `setActiveConnection()`, `getConnectionInfo()`, `renameConnection()`, `removeConnection()`, `openConnection()`, `closeConnection()`, `ignoreTarget()`, `getConnectionInfoAsUrl()`), to `Connection::setKey()`/`setTarget()`, or to `Log::__construct()` is deprecated in drupal:11.5.0 and is removed from drupal:13.0.0.

## Technical details

The class gained `declare(strict_types=1);` and PHPStan-level-10-compliant documentation, including new `@phpstan-type` array shapes (`UnprocessedConnectionInfoArray`, `ConnectionInfoArray` in `Database.php`, `DatabaseLogEntry` in `Log.php`) that describe the connection-info and query-log array structures instead of relying on `array` alone. All previously-untyped static methods (`startLog()`, `getLog()`, `getConnection()`, `setActiveConnection()`, `parseConnectionInfo()`, `addConnectionInfo()`, `getConnectionInfo()`, `getAllConnectionInfo()`, `setMultipleConnectionInfo()`, `renameConnection()`, `removeConnection()`, `openConnection()`, `closeConnection()`, `ignoreTarget()`, `getConnectionInfoAsUrl()`) now declare native parameter and return types, mostly `string|int` for keys/targets to preserve backward compatibility, with a `@trigger_error()` deprecation added wherever an `int` is passed instead of the documented `string`. Internally, values are cast with `(string)` before being handed to `Connection::setTarget()`/`setKey()` or `Log`'s constructor, since those now also deprecate non-string input under the stricter typing PHPStan otherwise enforces across the call chain.

`parseConnectionInfo()` was reworked to build a fresh `$connection_info` array (asserting `namespace`/`autoload` end up set) rather than mutating the incoming `$info` in place, which also let outdated Drupal 8 backward-compatibility test cases for the old `Drupal\Driver\Database\*` namespace layout (removed back in [#3294695](https://www.drupal.org/node/3294695)) be dropped from `SettingsTest`. A follow-up, [#3533038](https://www.drupal.org/node/3533038), proposes replacing the long connection-info array shape with a `ConnectionParameters` value object, but was postponed in favor of this narrower type-strictness pass. Contrib database drivers were checked for impact; the MS SQL Server driver's queue got a dedicated follow-up ([#3577786](https://www.drupal.org/node/3577786)) and the Oracle and DruDbal drivers were found unaffected or no longer maintained.</technical>
<parameter name="upgrade">Replace integer database connection keys or targets with strings wherever `Drupal\Core\Database\Database` methods are called, for example:

```php
// Before (still works, but now deprecated):
Database::addConnectionInfo(100, 300, $connection_info);
Database::getConnection(200, 100);

// After:
Database::addConnectionInfo('100', '300', $connection_info);
Database::getConnection('200', '100');
```

The same applies to `Drupal\Core\Database\Connection::setKey()`/`setTarget()` and to the `$key` argument of `Drupal\Core\Database\Log::__construct()`. Non-string values will raise a `TypeError` once support is removed in Drupal 13.0.0.

### Collaboration

The change nearly broke real-world usage: alexpott tested the MR and found he could currently call `Database::getConnection(1)` with an integer key, something that "works just fine" today, but bootstrapping failed with a `TypeError` once the MR's strict types were applied. That prompted mondrake and alexpott to work out, in comments #19 to #22, a softer approach: keep `string|int` as the accepted type but add `@trigger_error()` deprecation notices for integer input rather than breaking it outright, deferring the hard break to Drupal 13. mondrake also raised, in #4, that `@final` on an `abstract class` looks contradictory; the discussion concluded the class is effectively meant to be static-only and uninstantiable, but changing that further was deferred to a separate issue to avoid delaying this one.
