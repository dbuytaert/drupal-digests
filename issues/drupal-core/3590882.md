## Summary

For new sites installed with the Standard profile, Drupal no longer installs or enables the Olivero theme. Claro becomes both the admin theme and the default front end theme. The site's front page is now a new `/admin/welcome` page that explains the difference between Drupal Core and Drupal CMS and lists first steps (build a content model, pick a theme, extend Drupal), plus how to change the front page or remove the welcome page by uninstalling the Standard profile. Because that page requires an administration permission, anonymous visitors to the homepage now see a login block instead. None of this affects existing sites: the theme switch and welcome page only apply to fresh Standard profile installs, upgrading a site changes nothing. Installs done via the `standard` recipe (the CLI/recipe based path) also skip the welcome page and no longer pull in a separate recipe that installed Olivero as the front end theme, since Claro is now set directly.

## Impact

Affects site owners.

- **Config change:** Fresh Standard profile installs now set `claro` as both the admin and default (front end) theme instead of `olivero`, and set `/admin/welcome` as the site's front page instead of `/user/login`.

## Technical details

In `core/profiles/standard`, `standard.info.yml` no longer lists `olivero` under `themes`, and the profile's shipped `system.theme` config sets `default: claro` (was `olivero`). `system.site.yml`'s `page.front` is now `/admin/welcome` instead of `/user/login`. The new `standard.welcome` route (in `standard.routing.yml`) is gated by `WelcomeController::access()`, which checks a `standard.show_welcome` state flag; `standard_install()` in `standard.install` sets that flag only on a fresh install, so already-updated sites never see the page. The old `standard_install_finished()` status message and its `hook_install_tasks_alter()` were removed from `standard.profile`. The page is rendered through a new `standard_welcome_page` theme hook (`Drupal\standard\Hook\StandardHooks`) and `standard-welcome-page.html.twig`, styled by a new `welcome-page.css` library, and linked from a `Welcome` admin menu item using a Phosphor `signpost` icon.

Because the welcome page needs `access administration pages`, anonymous visitors to the front page now get a 403; a new `block.block.claro_login` block places a login form in the content region on every page except `/user` and `/user/*`, so anonymous users still get a usable homepage instead of a bare error page. Claro gained a `user-login-block.css` component, and a Classy `block--user-login-block.html.twig` override renders that block without its default list wrapper. The `standard` recipe (`core/recipes/standard/recipe.yml`) drops the now-deleted `core_recommended_front_end_theme` recipe and sets `system.theme.default: claro` directly instead of setting `page.front` and relying on Olivero being installed by that recipe; recipe based installs therefore never see the welcome page and anonymous users still land on `/user/login`. A number of tests (`StandardTestTrait`, `StandardPerformanceTest`, `MediaStandardProfileTest`, installer and build tests) were updated to reflect the new default markup and page-load query counts now that Claro, not Olivero, renders Standard's front end.

### Collaboration

The first version of this change replaced Olivero's welcome content with a one-time status message shown on `/user`, but a Drupal usability team review rejected that outright: benjifisher reported "strong consensus that a one-time message...is a bad idea" because it disappears on reload, navigation, or a coffee break, and mixes unrelated content like User Guide and event links into a transient message (see [#3612901](https://www.drupal.org/node/3612901)). Following that review, gábor hojtsy rebuilt the feature as a dedicated `/admin/welcome` page. mherchel and abenbow then raised concerns about the page's verbosity and intended audience, and the group agreed to treat it as an introductory pass to be refined later in the follow-up [#3614228](https://www.drupal.org/node/3614228) rather than block this issue on design polish. lauriii flagged that the welcome menu's drop icon did not follow Drupal's brand guidelines, prompting gábor hojtsy to swap it for a Phosphor "signpost" icon, and mherchel contributed CSS fixes so the page's two-column layout works correctly in both Claro and the new default_admin theme, including dark mode.
