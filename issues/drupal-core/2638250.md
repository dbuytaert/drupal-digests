## Summary

The "Member for" text on user profile pages used to be hard-coded HTML markup (a `&lt;h4&gt;` element) baked into `user.module`, which meant it could not be restyled, wasn't overridable via normal field templates, had accessibility issues, and had a cache-invalidation bug because its time interval wasn't captured as cache metadata. Drupal now exposes the user entity's existing `created` field as a normal, configurable field on the "Manage display" page (hidden by default), and deprecates the old `member_for` extra field, scheduled for removal in Drupal 13. Sites that currently show "Member for" will keep showing it after upgrading to 11.5 or 12 (nothing changes visually), but a deprecation notice will appear whenever it renders, prompting site owners to switch their display configuration to the `created` field, which behaves like any other field and can be labeled, formatted, and themed normally. New installations have both fields hidden by default.

## Impact

Affects module maintainers and site owners.

- **Config change:** The user entity's `created` field is now configurable on the user "Manage display" page (hidden by default); a post-update hook adds it as hidden to existing user displays.
- **Deprecation:** The `member_for` user profile extra field is deprecated as of Drupal 11.5 and will be removed in Drupal 13; use the `created` field instead.

## Technical details

In `User::baseFieldDefinitions()`, the `created` base field gained `->setDisplayOptions('view', ['region' => 'hidden'])->setDisplayConfigurable('view', TRUE)`, so it now appears on the user "Manage display" screen like any other field instead of being invisible to Field UI. `UserHooks::entityExtraFieldInfo()` relabels `member_for` to "Member for (deprecated)" and sets `'visible' => FALSE` in its `hook_entity_extra_field_info()` definition. `UserHooks::userView()` still builds the same hard-coded `<h4 class="label">` render array for backward compatibility, but now wraps it in a `#post_render` callback, `triggerMemberForDeprecation()`, which raises an `E_USER_DEPRECATED` notice referencing the change record at https://www.drupal.org/node/3611943.

A new post-update function, `user_post_update_add_created_to_display()`, uses `ConfigEntityUpdater` to add `created` to the hidden section of every user entity view display that doesn't already define it, so upgrading sites gain the new field definition without any visible change. Default install profile displays (`core.entity_view_display.user.user.*`) now list both `created` and `member_for` under `hidden` and no longer include `member_for` under `content`. `Drupal\user\UserListBuilder`, used by the admin `/admin/people` listing, renamed its "Member for" table column key from `member_for` to `created` to match.</technical>
<parameter name="upgrade">Sites and contrib/custom code that reference the `member_for` extra field (for example in `EntityViewDisplay` configuration, or custom code checking `$display->getComponent('member_for')`) should switch to the `created` field instead, since `member_for` is deprecated in Drupal 11.5 and will be removed in Drupal 13:

```php
// Old: relied on the always-visible, hard-coded 'member_for' extra field.

// New: enable the 'created' base field on the user display, e.g. via
// Manage Display UI, or programmatically:
EntityViewDisplay::collectRenderDisplay($user, 'default')
  ->setComponent('created', [
    'type' => 'timestamp_ago', // or 'timestamp', etc.
  ])
  ->save();
```

Code that keys off the `/admin/people` listing's "Member for" column by machine name should use `created` instead of `member_for` (see `Drupal\user\UserListBuilder::buildHeader()`/`buildRow()`).

### Collaboration

This issue was open for nearly a decade with several competing proposals. Berdir (#comment ~14508451) pushed back on an earlier "convert to a computed field" approach as unnecessarily complex, arguing the display's only real job was showing `created` with a different label, and suggested instead making `created` configurable with an overridable label; larowlan agreed this was the better path. Years later godotislate picked up the implementation, initially tried rendering `created` with the `TimestampFormatter`'s JS-driven time-diff display, but ran into cache-invalidation test failures (`DateFormatter::formatDiff()` cacheability has max-age 0) and needed help from berdir and catch on Slack to fix the performance tests. After that proved complex, godotislate switched to the simpler "hide `created` by default" approach berdir and larowlan had originally proposed, which Gábor Hojtsy confirmed as acceptable on Slack before it was committed.
