## Summary

As part of Claro's deprecation, Drupal core now ships new sites with the (experimental) Default Admin theme instead of Claro. The Standard installation profile and the Umami demo profile now install `default_admin` as their administration theme, and Standard also uses it as its default front-end theme. The `core_recommended_admin_theme` recipe and the `standard` recipe were updated the same way, so applying either to a site now sets up Default Admin rather than Claro. This only affects new installs or sites that explicitly apply these profiles/recipes; existing sites keep whatever admin theme they already have configured.

## Impact

Affects site owners.

- **Config change:** Standard and Umami install profiles, and the `core_recommended_admin_theme`/`standard` recipes, now set `default_admin` as the admin theme (and, for Standard, also as the default theme) instead of `claro`.

## Technical details

The change swaps `claro` for `default_admin` throughout the profile and recipe config: `system.theme.yml` for `standard`, `demo_umami`, and `nightwatch_a11y_testing`, the `themes:` list in their `.info.yml` files, and the block config shipped for the admin theme (`claro_login` became `default_admin_login`, `claro_help`/`claro_breadcrumbs`/etc. became `default_admin_*`). The `core_recommended_admin_theme` recipe now installs `default_admin` and imports its blocks instead of Claro's, and `standard` recipe's `system.theme` action sets `default: default_admin`.

Because Default Admin doesn't render field wrapper classes the way Claro does (no `.field--name-*` markup), several functional tests that asserted on those classes (media library embed tests, standard profile tests, `ImplementationNameTest`) were rewritten to scope assertions to `#block-default-admin-content` and element selectors instead. A few Default Admin theme templates and styles were also adjusted to support being used this way: `block--user-login-block.html.twig` and a new `user-login-block.css` were added to render the login form without list markup, `admin-toolbar-top-bar.html.twig` gained `role="region"`/`aria-label` attributes, and the primary/secondary local-tasks templates now put the visually-hidden heading inside the `<nav>` element rather than before it.
