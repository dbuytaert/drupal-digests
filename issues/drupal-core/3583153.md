## Summary

Previously, calling `ModuleHandler::invoke()` to run a specific hook for a specific module would throw a `LogicException` as soon as that module had more than one implementation of the hook, regardless of what those implementations returned. This forced developers to fall back on the more awkward `invokeAllWith()` just to support a module with multiple hook implementations. Now, `invoke()` runs all of that module's implementations and merges their results when possible, so code that only needs array results (the common case) works without extra workarounds. The exception is now only raised when the implementations return something that cannot be merged, such as strings or plain objects.

## Impact

Affects module maintainers.

- **API change:** `ModuleHandler::invoke()` no longer always throws when a module implements the same hook more than once: if every implementation returns `NULL`, an array, or an `\ArrayObject`, the results are merged with `NestedArray::mergeDeep()` and returned; it still throws `\LogicException` only when a non-mergeable value (e.g. a string or object) is returned.

## Technical details

In `ModuleHandler::invoke()`, the branch handling multiple listeners for a module/hook pair (`Drupal\Core\Extension\ModuleHandler::invoke()`) no longer throws immediately on `count($listeners) > 1`. Instead it iterates the listeners, skips any that return `NULL`, and merges array or `\ArrayObject` results together with `NestedArray::mergeDeep()`. If a listener returns any other type, the original `\LogicException` ("Module $module should not implement $hook more than once.") is thrown instead, preserving the old failure mode for non-mergeable results. The interface doc comment on `ModuleHandlerInterface::invoke()` was updated to document this merging behavior.

A new hidden test module, `hook_single_invoke`, was added with hook implementations that return arrays, `\ArrayObject`s, strings, and `stdClass` objects, used by new tests (`testInvokeWithMergeable()`, `testInvokeWithNotMergeableString()`, `testInvokeWithNotMergeableClass()`) covering both the merge path and the exception path.</technical>
