# #3586448: Disable agent subscriptions for Languages and gate Specific Entities on availability

- **Project:** Drupal AI
- **Type:** Major task
- **Status:** Fixed
- **Discussion:** [#3586448](https://git.drupalcode.org/project/ai_context/-/work_items/3586448) · 1 contributor · 15 comments

## Summary

In AI Context, agents can no longer subscribe to Languages. A language tag on an item no longer ranks it higher for an agent. Items are still dropped when the request language doesn't match, and they are still included in Relevant and Broad when it does. In Minimal mode, items tagged only with a language are no longer injected unless they use Always include. Existing language subscriptions stay in agent config but are ignored. Sites without Dynamic Entity Reference now list Specific Entities as Unavailable on the scope overview, where it used to be missing. Rebuild caches after updating. No update hook or config change is needed.

## Impact

Affects module maintainers and site owners.

- **Config change:** No config change; existing agent `scope_subscriptions.language` values are preserved but ignored.
- **New API:** `getParticipatingSubscriptions()` added to the `@internal` `AiContextScopeResolverInterface`; `ai_context_ai_context_scope_info_alter()` is no longer implemented.

## Technical details

Languages now overrides `supportsSubscriptions()` to `FALSE` and keeps `supportsSituationalMatch()` as `TRUE`, so its capability row is `language => [FALSE, FALSE, TRUE]`. The request language from `AiContextLanguageService::detect()` is always known, so `matchesRequestContext()` is never NULL. A subscription could only re-rank items and never broaden reach, the same reasoning as Roles. Form hiding, the "do not allow subscriptions" note, the scoring skip and save-time preservation of stored values follow from the capability.

Changing the capability alone leaked language-only items into Minimal. `prefilterItemIdsByScope()` is also used for Global index lookup, so non-subscription scopes can't be stripped inside it. The internal resolver (`@internal` `AiContextScopeResolverInterface`) gains `getParticipatingSubscriptions()`. It drops empty lists and scopes that are disabled, unavailable or `supportsSubscriptions(): FALSE`. The selector and budget calculator call it before prefilter and subscribed-ID resolution. This also fixes the same leak for stored Roles subscriptions.

Specific Entities was handled differently from Languages: `ai_context_ai_context_scope_info_alter()` removed its `entity_item` definition when `dynamic_entity_reference` was missing. That made its capability unreadable, so `calculateScopeScore()` carried a hardcoded skip list (`global`, `entity_item`, `target_entity`). Now `AiContextScopeEntityItem::isAvailable()` reports whether DER is installed, the alter hook implementation is removed, and the skip list is gone. Scoring and `getParticipatingSubscriptions()` decide purely by capability. A stored `entity_item` subscription on a non-DER site previously scored at the minimum weight and diluted other dimensions (90/91 instead of 90/90). Because the settings tab is now reachable while the scope is unavailable, `validateSettingsForm()` no longer queries the missing `entity_items` field, which otherwise threw a `QueryException`. The local task deriver is the one `getScopePlugins()` consumer that doesn't gate on availability, so the tab shows up.

## Upgrade

Rebuild caches (`drush cr`) after deploying so plugin definitions and the agent form pick up the new capability and availability. Stored `scope_subscriptions.language` values on agents are kept but have no effect.
