# #3586470: Fix CCC beta4-to-beta5 upgrade and config-import path

- **Project:** Drupal AI
- **Type:** Major bug report
- **Status:** Fixed
- **Discussion:** [#3586470](https://git.drupalcode.org/project/ai_context/-/work_items/3586470) · 1 contributor · 34 comments

## Summary

Fixes three problems for sites upgrading AI Context from beta4 to beta5. Migrated agents now keep beta4's implicit Minimal selection mode instead of silently becoming Relevant. `match_all` becomes Broad, and explicit Minimal, Relevant and Broad values are preserved. A complete beta4 config export can be imported after `updatedb`. Its agents are turned into consumers, and the usage View is repaired. Settings without a selection mode fall back to the beta5 default. The one-shot post-update 0006 now removes only scope values whose entities no longer exist. Values for disabled or unavailable scopes stay. The beta5 release notes say to run `drush updatedb` before importing configuration, and to re-export afterwards.

## Impact

Affects site owners.

- **Config change:** A beta4 `ai_context.settings` object without `selection_mode` is accepted on import, and a beta4 sync directory is converted to consumers during import.

## Technical details

Update 10028 and the import transform share a new `@internal` helper, `AiContextLegacyAgentConverter`. `convertAgentRow()` normalizes the selection mode: missing or unrecognized becomes `minimal`, `match_all` becomes `broad`, valid modes are preserved. `convertAgentsToConsumerRows()` collapses identical duplicate rows and throws on conflicting duplicates. It also throws when the `agents` list is missing, because that is treated as corrupt rather than empty. Converted rows are written in the `ai_context.consumers` schema key order. Without that, `StorageComparer` would report a phantom update on every later import.

`AiContextConfigImportValidateSubscriber` now also subscribes to `ConfigEvents::STORAGE_TRANSFORM_IMPORT` via `onImportStorageTransform()`. When the source has `ai_context.agents` but no `ai_context.consumers`, it converts the rows and drops the leftover agents object. Per the issue it also does these things:

- It supplies the agent consumer-type settings and copies the active Roles settings when the source omits them.
- It remaps leftover usage-View handlers, beta1/beta2 paths and scope-map plugin IDs in place.
- It runs the same residual repairs when `ai_context.agents.yml` is missing but structural leftovers remain, so a mixed sync does not delete beta5 settings or restore a leftover View.
- It fails validation if leftover agents appear alongside consumers, and tells the site to re-export.
- It is registered after Config Split's default merge and before Config Ignore.

`ai_context_post_update_0006_scrub_stale_scope_values()` now calls `ai_context.scope_cleanup`'s `scrubStaleScopeValuesForUpgrade()`. This is a conservative upgrade-specific policy: it skips disabled or unavailable scope plugins, and removes Entity Types values only when the entity type or bundle no longer exists. It does not remove Site Section values based on pre-import settings, and it preserves Language values when Language is unavailable. The live settings-save cleanup from [#3586416](https://www.drupal.org/node/3586416) is unchanged. The docblock of post-update 0004 now describes Relevant as the new-install default and Minimal as beta4's implicit behavior.

## Upgrade

Run `drush updatedb` before importing configuration. A beta4 sync directory can still be imported after the upgrade, but re-export afterwards. Scope values for a language removed from active configuration, or for an entity type whose module is disabled in the database, are removed even if the incoming configuration re-adds them. Re-add those by hand after the import.
