# #3586638: Scope settings table: Edit links do not say which scope they are for (WCAG 2.4.4)

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586638](https://git.drupalcode.org/project/ai_context/-/work_items/3586638) · 1 contributor · 9 comments

## Summary

On the AI Context Scope settings page, all the Edit links were just called "Edit", so screen reader users could not tell which scope each one opened. Each link now has an accessible name that includes the scope, such as "Edit Global", while the visible text stays "Edit". The scope name in the first column is now a row header, so assistive technology announces it as the heading for its row. This addresses WCAG 2.2 SC 2.4.4 (Link Purpose) and SC 1.3.1 (Info and Relationships).

## Impact

Affects front-end developers.

- **Theme change:** Scope overview table now renders the first cell of each row as `<th scope="row">` and Edit links carry an `aria-label`.

## Technical details

The change is in `src/Form/AiContextScopeOverviewForm.php`. The label cell gets `'#wrapper_attributes' => ['header' => TRUE, 'scope' => 'row']`, so the `table` element renders a `th` instead of a `td`. Each operations link gets `'attributes' => ['aria-label' => $this->t('Edit @scope', ['@scope' => $plugin->getLabel()])]`. The label starts with "Edit", so voice control users can still say "Edit" (SC 2.5.3 Label in Name). The issue also lists a functional test checking that each Edit link has its own name and that the first cell is a `th` with `scope="row"`. I read the form code in the repo but did not read the test.
