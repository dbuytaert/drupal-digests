## Summary

Never include on a consumer now holds when the Get Relevant tool receives an item ID written with leading zeros, such as `"0123"` for item 123. Before, that spelling slipped past the exclusion and the item was delivered. The Load tool is also stricter: it accepts only integers and digit-only strings from 1 to 2147483647, so values such as `1e0`, `1.0` or `+1` no longer load an item, and the call reports `No valid numeric context item IDs provided.` when none are usable. Leading zeros and surrounding spaces are still accepted.

## Impact

Affects site owners.

- **Security:** Never include on a consumer could be bypassed by passing an item ID with leading zeros (such as `"0123"`) in `always_include` of the Get Relevant tool; fixed.

## Technical details

The Never include subtraction in `AiContextSelector::loadCandidateItems()` used `array_diff()` on strings, so `"0123"` did not match `"123"`, while the entity query compared the ID as a number and loaded item 123. The fix gives each numeric ID one spelling. `AiContextNumeric` (`@internal`) gets `entityId()`, which accepts integers and digit strings, trims whitespace and leading zeros, and rejects `0`, floats, booleans and `1e0`/`1.0`/`+1`. It has no upper limit, so Never include can still name an item with an ID above 2147483647 (possible on SQLite). `boundedEntityId()` applies the same rule and also rejects values above 2147483647 by comparing digit strings, without an integer cast.

`AiContextItemIdentifierResolverTrait::resolveContextItemIdentifiersToIds()` now uses `entityId()`, so both the always include and never include lists, from tool input or stored consumer config, normalize to the same string and duplicates collapse. An all-digit value that normalizes to nothing (`0`) is dropped and not treated as a UUID. `AiContextLoadItemsFunctionCallBase::validateIds()` uses `boundedEntityId()` instead of `is_numeric()`, since Load passes IDs straight to a query. As a defensive check, `loadCandidateItems()` also runs `array_diff_key()` to remove Never include items from the always-included group by loaded entity ID.

Unchanged behaviors: an explicit `consumer_id` in tool input still selects that consumer's config, `always_include` items skip hard-filter scopes, and the Load tool does not apply Never include. Docs gain an "Item ID format" section in `docs/developers/function_calls.md`.
