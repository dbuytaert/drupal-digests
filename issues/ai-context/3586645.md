## Summary

When a consumer's token budget is too small, the renderer shortens some context items and leaves others out. Before this fix, usage records and the generic-path invocation result still counted every selected item as delivered. The usage pages could then show an item as used by a consumer whose prompt never contained it. Now only items that reached the prompt are recorded and reported. A shortened item still counts as delivered, because part of it reached the model. An item the budget left out does not count.

## Impact

Affects module maintainers.

- **API change:** Generic-path invocation result `item_ids` and `item_count` now contain only delivered items, so they can be smaller than the selection on sites with a tight token budget.
- **New API:** `AiContextSelectionResult::getOmittedItemIds()` and `getDeliveredItemIds()`, plus `AiContextSelectionTextRenderedEvent::getOmittedItemIds()`, and an `omitted_item_ids` key in the renderer result.

## Technical details

`AiContextRenderer::render()` now returns an `omitted_item_ids` list next to `truncated_item_ids`. It holds the IDs that produced no block at all: the budget had no room, or the entity could not be loaded or was unpublished. `getTruncatedItemIds()` is unchanged and still covers both shortened and dropped items, so an ID can appear in both lists. `AiContextSelector` passes the list into `AiContextSelectionTextRenderedEvent` (read-only, new trailing constructor argument `omittedItemIds`) and into `AiContextSelectionResult`.

`AiContextSelectionResult::getDeliveredItemIds()` returns `getSelectedItemIds()` minus the omitted IDs. `AiContextBuildSystemPromptSubscriber` (agent path) and `AiContextPreGenerateResponseSubscriber` (generic path) use it for `recordUsage()`. The generic path also uses it for the invocation result. `getSelectedItemIds()` is unchanged. The renderer decides what counts as delivered, so a `TEXT_RENDERED` subscriber that edits item text does not change the records.

The generic path still decides whether to push based on the selection, not on delivered items. If the budget leaves out every selected item but a `TEXT_RENDERED` subscriber added text, that text is pushed with status `pushed`, empty `item_ids` and `item_count` 0. In that case no usage is recorded. The docs (`api-stability.md`, `consumer_api.md`, `usage_tracking.md`) are updated, with a new "Beta upgrade: usage and item_ids count delivered items" section. A new kernel test covers both push paths, using a length-based test tokenizer so budgets can actually be exceeded.

## Upgrade

Code that compared `item_count` or `item_ids` in the invocation result against its own selection count may now see fewer items. Use `getSelectedItemIds()` for what selection chose and `getDeliveredItemIds()` for what reached the prompt:

```php
$result->getSelectedItemIds();   // unchanged
$result->getOmittedItemIds();    // left out completely
$result->getDeliveredItemIds();  // selected minus omitted
```
