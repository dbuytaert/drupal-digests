# #3586571: Scheduled publish on save can leave context item Draft in the listing

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586571](https://git.drupalcode.org/project/ai_context/-/work_items/3586571) · 1 contributor · 18 comments

## Summary

On a moderated site with Scheduler enabled, saving an AI Context Item whose **Publish on** date was already due used to publish the item but leave its moderation state at Draft. The listing showed Draft while selection and counts treated the item as published. The moderation state now follows the scheduled publish state, so the listing shows Published. Future dates handled by cron already worked and are unchanged.

## Impact

No upgrade or configuration changes required.

## Technical details

Scheduler publishes immediately in `hook_entity_presave()` when the date is due and dispatches `SchedulerAiContextItemEvents::PUBLISH_IMMEDIATELY`. `scheduler_content_moderation_integration` only listens to the node and media versions of that event, so `moderation_state` was never updated. The listing reads `moderation_state`, while selection and counts use the `status` flag.

The fix adds an `@internal` event subscriber, `AiContextSchedulerImmediatePublishSubscriber`, registered as `ai_context.scheduler_immediate_publish_subscriber`. It takes `content_moderation.moderation_information` as an optional dependency, so it does nothing when Content Moderation or Scheduler is absent. On the event it checks that the entity is moderated, has the `publish_state` field, and that the field is not empty. It then copies `publish_state` into `moderation_state`. Like the node and media handling, it leaves `publish_state` in place. Cron publish and unpublish go through the generic Scheduler hooks and were not changed. A kernel test (`AiContextSchedulerImmediatePublishTest`) covers a due `publish_on` without SQL backdating.
