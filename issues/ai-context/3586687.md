## Summary

AI Context selection results now vary by a new `ai_context.request_path` cache context. Site Sections filters on a path that can be supplied in a request attribute, a posted `path` parameter, a JSON body or a same-site Referer, not only the URL. Before this fix, two requests to one endpoint with different supplied paths could select different items but carry identical cache contexts. Custom code that cached a selection, or a render array built from one, could then serve items from the wrong site section. The module itself doesn't store selection results by cacheability, so the gap only affects custom consumers that cache them.

## Impact

Affects module maintainers.

- **New API:** New `ai_context.request_path` cache context (`cache_context.ai_context.request_path`) holding the path that Site Sections filters on, now declared by the selector, the budget calculator and the detected language context.

## Technical details

New `AiContextRequestPathCacheContext` (marked `@internal`), registered as `cache_context.ai_context.request_path` in `ai_context.services.yml`. Its `getContext()` returns `AiContextRequestInfoResolver::getPath()` or `none`, and its own cacheable metadata is empty.

The context is added to the contexts declared by `AiContextSelector`, to `AiContextSubscriptionBudgetCalculator` (its totals fingerprint reads the resolver's path), and to `AiContextDetectedLanguageCacheContext::getCacheableMetadata()` (language detection reads the same path for a language prefix). `url.path` and `route` are kept, because the resolver falls back to the URL and dropping `url.path` would change existing cache keys.

Docs: `api-stability.md` gets a "Caching a selection result" section. It says to compute cache keys in the same AI call, before `AiContextRequestInfoResolver::resetRequestInfo()` clears the supplied path or entity. It also warns that the supplied path is normalized but not validated against routes, so its cardinality is unbounded. Kernel tests cover the context's values (URI fallback, posted path, JSON path, same-site and cross-site Referer) and show that two body paths give different selections and different resolved cache keys.

## Upgrade

Run `drush cr` so Drupal registers the new cache context. If custom code caches a selection result or a render array built from one, key it on all of the result's cache metadata (`AiContextSelectionResult::getCacheableMetadata()`), and don't drop `url.path` or `route`.
