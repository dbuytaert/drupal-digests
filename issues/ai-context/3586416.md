# #3586416: Clean stale scope values when options are deleted

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586416](https://git.drupalcode.org/project/ai_context/-/work_items/3586416) · 1 contributor · 15 comments

## Summary

Context items and agent subscriptions no longer keep scope values for options that have been removed. Deleting a content type, taxonomy term, vocabulary, context tag, language or role now removes that value from items, subscriptions and the scope index. Removing an entity type from Entity Types settings, or a site section from settings, does the same. Uninstalling a module that provided those options also triggers a scrub. Deleting a bundle keeps the type-level `type:_all` value, but removing the whole type from settings removes it. Use Case values are never scrubbed. After upgrading, run `drush updatedb`: a one-time post-update cleans up leftovers that already exist. Because updates normally run before config import, on a lower environment with a copied production database this scrub can remove values for options the import is about to add.

## Impact

Affects module maintainers and site owners.

- **Database update:** Post-update `ai_context_post_update_0006_scrub_stale_scope_values()` strips already-stale scope values from items, agent subscriptions and the scope index.
- **New API:** New optional `AiContextScopeStoredValueInterface` for scope plugins whose options can disappear; new `AiContextScopeCleanupService` methods `scrubScope()`, `scrubStaleScopeValues()`, `scrubScopesAfterEntityDelete()`, `scrubScopesAfterBundleDelete()`, `scrubScopeAfterSettingsChange()`.

## Technical details

The existing `ai_context.scope_cleanup` service (`AiContextScopeCleanupService`) still only strips values. The decision about what is stale moved into scope plugins through the new optional `AiContextScopeStoredValueInterface`: `getStaleStoredValues()`, `shouldScrubAfterEntityDelete()`, `getStaleStoredValuesForEntityDelete()`, `shouldScrubAfterBundleDelete()` and `shouldScrubAfterSettingsChange()`. The service now takes `plugin.manager.ai_context_scope`, collects stored values from the scope index (new `AiContextScopeIndexService::getIndexedScopeValues()`) and from raw `ai_context.agents` subscriptions, then asks the plugin which are stale. `AiContextScopeInterface` is unchanged.

Triggers are generic and do not special-case plugin IDs: `ai_context_entity_delete()`, the new `ai_context_entity_bundle_delete()`, and the new `ai_context_modules_uninstalled()`. The last skips config sync and skips uninstalling `ai_context` itself. `AiContextScopeConfigSubscriber` now reacts to any `ai_context.scope_settings.{plugin_id}` save and skips it while `config.installer` `isSyncing()`, because a mid-import scrub would compare stored values to a half-imported environment. Bundle-delete hooks still run during sync.

Plugin policy: Language, Roles, Tag and Entity Types treat a value as stale if it is missing from `getAlteredValues()`, via the new `AiContextScopeBase::getStoredValuesMissingFromAlteredValues()`. Site Section also keeps `custom:` patterns. Taxonomy Terms keeps a value if the term exists and is not in the `ai_context_tags` vocabulary, or an alter hook added it. Term, language and role deletes return the deleted ID for a cheap strip. A vocabulary delete returns `NULL` for a full scan. Entity Types scrubs after a bundle delete only when that entity type is enabled in settings, and after any settings save. Use Case, Global and Entity Item do not implement the interface.

## Upgrade

Run the new post-update after deploying:

```bash
drush updatedb -y
drush cr
```

`ai_context_post_update_0006_scrub_stale_scope_values()` runs against the environment as it exists at that moment, before `drush config:import` in standard pipelines. On a lower environment with a copied production database it can remove values for options that the pending import would add.

Custom scope plugins that can lose options can implement `AiContextScopeStoredValueInterface` (in the `Drupal\ai_context\Plugin\AiContextScope` namespace) alongside `AiContextScopeInterface`. Plugins that do not implement it are left alone.
