## Summary

When a subcontext item that uses its parent's scope ("Same as parent") is detached, because the parent is deleted or because "Enable subcontext hierarchy" is turned off and the item is saved, every published translation is now unpublished. Before, only one translation was unpublished. The other translations stayed published with no parent and no scope, so the List tool and Broad selections could give them to users outside the former parent's Roles scope. Pending "Publish on" dates are also cleared so Scheduler cannot republish a translation later.

## Impact

Affects site owners.

- **Config change:** A workflow without an unpublished default-revision state (such as Archived) cannot unpublish a detached item; it stays published and an error is logged.

## Technical details

Both detach paths now call a new `AiContextItem::unpublishDetachedTranslations()`, which unpublishes every published translation with `setUnpublishedWithModerationState()` and clears `publish_on` (and `publish_state`) on translations that have a date. It first checks `canUnpublishWithModerationState()`. If the workflow has no unpublished default-revision state, the item is left published and an error is logged, because content moderation would publish it again. The paths are `AiContextItem::preSave()` and `AiContextChildrenService::clearParentReferences()`. The `logDetachedUnpublished()` warning is kept.

Content moderation stores the moderation state of the saved translation only, so on moderated items the other translations must be saved in their own revisions. That cannot happen in `preSave()` or `postSave()`. `preSave()` records the state in `detachAfterSave`, and the new `ai_context_entity_insert()` and `ai_context_entity_update()` hooks call `AiContextItem::saveDetachedTranslationsAfterSave()`, which calls `saveDetachedTranslations()` for each other translation. `ai_context_module_implements_alter()` now also orders these two hooks after content_moderation's, in the same transaction. On Drupal 12, where `hook_module_implements_alter()` is removed, this order must come from the `order` argument of `#[Hook]`.

If content moderation keeps the save as a pending draft, `saveDetachedTranslationsAfterSave()` loads the default revision. Only when that revision also inherits the parent's scope, has no scope of its own and has no stored entity items are its published translations archived in new revisions based on the draft, so the latest revision keeps the editor's text. A default revision with its own scope stays published. The saved object is no longer the latest revision after this, so code that saves it again should reload it first. `docs/features/subcontext.md` is updated to match.
