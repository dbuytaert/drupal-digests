## Summary

The Duplicate action on AI Context items now always creates a draft copy, for every user and whether or not "Publish by default" is on. Before, a user who could not use the Publish transition could still get a published copy, which skipped editorial review. The copy is also now owned by the user who duplicated it, gets new created and changed dates, and keeps neither the original's publishing schedule nor its revision log message. A user without the "Create new draft" transition now gets a form error instead of a copy. At the global item limit, duplicating a global item now saves a draft and shows no error, because the limit is checked when the copy is published. Sites running earlier versions should look for published items with the same label or created date as another item and review them.

## Impact

Affects site owners.

- **Security:** Editorial workflow bypass: a user without the publish transition could get a published copy through Duplicate when Publish by default was on. Needs restricted permissions (Create and Edit AI Context Item).
- **Permission change:** Duplicate now requires the `use ai_context_editorial transition create_new_draft` permission. Users without it get a form error, even if they may publish.

## Technical details

The cause was in `AiContextItemDuplicateForm::buildDuplicate()`. It set the published status and the `published` moderation state from `default_status`, and `validateForm()` only ran the module persistence rules, never entity validation. So Content Moderation's `ModerationState` constraint never checked the transition. Now `buildDuplicate()` always produces a draft, using the new `setDuplicateState()` to call `setUnpublished()` and set `moderation_state` to `draft` on every translation. `createDuplicate()` copies all translations, but the route only passes the one in the current content language. `validateForm()` also calls `->validate()` on the `moderation_state` field and turns each violation into a form error. A new item is checked as a transition from the workflow's initial state, so the user needs the Create new draft transition.

`buildDuplicate()` also resets fields that described the original. The `RESET_FIELDS` constant (`uid`, `created`, `changed`, `publish_on`, `publish_state`, `unpublish_on`, `unpublish_state`) gets `applyDefaultValue()` on each translation, since `created` and `changed` are translatable. The revision creation time and log message are reset through the entity type's revision metadata keys. The revision user is set to `NULL` so that `AiContextItem::preSave()` falls back to the owner. `getDefaultStatus()` and the config factory constructor argument are removed, and `getDescription()` always returns "A new draft copy will be created." The description of "Publish by default" in `AiContextItemSettingsForm` now says Duplicate always creates a draft. The docs are updated, including the removal of references to a "Duplicate tab". Kernel tests (`AiContextItemDuplicateFormTest`, new `AiContextItemDuplicateScheduleTest`) and functional tests in `AiContextItemListTest` were updated or added.

## Upgrade

Grant `use ai_context_editorial transition create_new_draft` (AI Context editorial workflow: Use Create new draft transition) to any role that should keep using Duplicate. Copies made before this fix keep the original's label and created date, so check for published items sharing a label or created date with another item. This check also finds legitimate copies made by users who could publish.
