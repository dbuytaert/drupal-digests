## Summary

For AI agents, automatic context selection now uses the user's request as the task, not the agent's system prompt. Conditional subcontext decisions now depend on the actual question. Before, they were made from the agent instructions, so the same result could be reused for every question. The provider set under "AI Provider/Model" in the CCC general settings now receives the first 500 characters of the user request instead of the agent instructions. That provider can differ from the agent provider, and the request may contain personal data. Sites that don't want this can turn off conditional subcontext AI decisions or use the same provider as their agents.

## Impact

Affects module maintainers and site owners.

- **Security:** The conditional subcontext decision provider now receives the first 500 characters of the user request on agents, which may contain personal data.
- **API change:** On agents, `AiContextSelection::getTask()` returns the user request (or an empty string) instead of the agent system prompt; selection event subscribers must accept an empty task.

## Technical details

`AiContextBuildSystemPromptSubscriber::onBuildSystemPrompt()` used to pass the system prompt to `AiContextSelectionFactoryInterface::fromConsumer()`. That prompt holds the agent instructions, default information tool output and the loop text, so `getTask()` returned it and the decision cache key changed on every loop. It now passes a stored user request, or `''` when there is none, as on the generic chat path.

`onAgentStarted()` reads the request through the new `readUserRequest()`. It reads on loop 0, or when nothing is stored for the agent yet (a restored run starts above loop 0). The result is kept per agent ID in `$userRequests`, because `BuildSystemPromptEvent` has no runner ID. The first source with text wins: the latest user message of the agent chat input; the description of the agent task (`TaskInterface::getDescription()`); the latest user message of the event chat history. On a restored run (loop above 0) the history fallback is cut at the first tool call or tool result by `getMessagesBeforeTools()`, because the agent adds its own user messages after tool calls. Text is only trimmed, not stripped or shortened. A failure while reading is logged and leaves the task empty, and context is still injected.

Known limits from the issue: an agent that calls itself as a sub-agent shares one stored request. Code that dispatches `BuildSystemPromptEvent` without `AgentStartedExecutionEvent` gets the last stored request for that agent ID, or an empty task. Docs (`events.md`, `index.md`, `subcontext.md`, `rag.md`, `api-stability.md`) were updated. `rag.md` now shows an example that returns early on an empty task.

## Upgrade

Subscribers of `ai_context.selection.items_selected` and `ai_context.selection.text_rendered` that use the task as a query must handle an empty string, as in the updated `rag.md` example:

```php
$query = $event->getSelection()->getTask();
if ($query === '') {
  return;
}
```
