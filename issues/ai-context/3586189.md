## Summary

When there are more published global context items than the `max_global_items` limit, the AI Context selector now keeps the most recently changed items. Previously the items that made it under the cap depended on load order, so older or earlier-loaded items could win arbitrarily. Items with the same changed time are ordered by higher item ID first, so the result is the same on every run. Sites at or under the cap are unaffected. Sites over the cap may see a different set of global items than before.

## Impact

No upgrade or configuration changes required.

## Technical details

In `AiContextSelector`, the old check `count($globalItems) < $maxGlobalItems` kept the first global items seen. It is replaced by a private `insertTopGlobalCandidate()`. It adds each global item to a bounded list, sorts it with `uasort()` using `compareByChangedDesc()` (`getChangedTime()` descending, then `(int) id()` descending), and slices the list to `$maxGlobalItems`. A cap of 0 or less keeps nothing. The list is trimmed as items are seen, so the ranking holds across the chunks the selector iterates. Selected global items still come before always-include, auto-included and scored items, and `getSelectedItemIds()` preserves the ranked order. The docs now describe the cap ordering. `AiContextSelectorAlgorithmTest` replaces the old cap test with tests for the changed-time ranking and the ID tie-breaker.
