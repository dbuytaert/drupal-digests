## Summary

AI Context now exposes its main selection API, `select()`, through an interface. Custom code and contrib modules can depend on that interface instead of the concrete selector class. The change was made before RC1, since the public API is harder to change after a stable release.

## Impact

Affects module maintainers.

- **API change:** Internal constructors and the `GetRelevantAiContextItems::$selector` property now type hint `AiContextSelectorInterface` instead of `AiContextSelector`.
- **New API:** New `Drupal\ai_context\Service\AiContextSelectorInterface` with `select(AiContextRequest $request): AiContextResult`, aliased in `ai_context.services.yml`.

## Technical details

`AiContextSelector` now implements the new `AiContextSelectorInterface`, which declares only `select(AiContextRequest $request): AiContextResult`. `ai_context.services.yml` adds the alias `Drupal\ai_context\Service\AiContextSelectorInterface: '@ai_context.selector'`, so the service can be autowired or fetched from the container by interface name. The existing `ai_context.selector` service ID is unchanged.

Consumers inside the module were switched to the interface type: the constructors of `AiContextSystemPromptSubscriber` and `AiContextRequestFactory`, and the `$selector` property of the `GetRelevantAiContextItems` function call plugin. Docblocks and the docs were updated to match. `AiContextSelectorContractTest` gains `testSelectorServiceInterfaceAlias()`, which checks that the interface alias resolves to the same instance as `ai_context.selector`.

## Upgrade

Custom code that type hints the concrete class can switch to the interface:

```php
use Drupal\ai_context\Service\AiContextSelectorInterface;

$selector = \Drupal::service(AiContextSelectorInterface::class);
```

Code that replaces or decorates `ai_context.selector` and is passed to the module's constructors must now implement `AiContextSelectorInterface`.
