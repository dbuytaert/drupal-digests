## Summary

The AI Context admin listings now open with useful defaults. The context items listing (`/admin/config/ai/context/items`) shows only **Published** items, and the consumers listing (`/admin/config/ai/context/settings/consumers`) shows only consumers with Automatic push **On**. Each listing has a **Reset** button that appears once a filter differs from its default. It restores the defaults and clears the search. If the default view is empty, the table says so and tells you to switch the filter to All. Without JavaScript the filter toolbar is hidden and every row stays visible.

## Impact

No upgrade or configuration changes required.

## Technical details

Filtering stays client-side. The toolbars render with `hidden`, and the JS unhides them once it has applied the defaults. This is why a no-JS page shows every row.

Items listing: `AiContextItemListBuilder` now always renders the Status select with `published` preselected, even if no listed row is published. Published is matched through a new `data-context-published` row attribute (`1` or `0`), not the workflow state name, so custom workflow states that publish an item are covered. The remaining Status options are only the unpublished states seen on rendered rows. As a result, Published can still show unpublished relatives, such as a draft child of a published parent, because of the hierarchy-aware parent/child visibility.

Consumers listing: `AiContextConsumersForm` sets the push filter `#value` to `on`. Both selects get a `data-default-value` attribute, which the Reset handler restores. For the Type select that default is the type from an incoming `?type=` link, or All. Reset also moves focus to Search.

Empty results now insert a `.ai-context-items-no-results` or `.ai-context-consumers-no-results` row into the table. The live-region message changed from "...match the current filter." to "...match the current filters." Initial load does not announce a nonempty count, except on the consumers page when it arrives with a `?type=` prefilter. The JS now only selects rows with `data-entity-id` or `data-consumer-push`, so the empty-message row is never filtered. CSS and help text were updated, and the existing tests were adapted to the new defaults.
