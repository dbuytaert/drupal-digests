# #3586388: Align scope scoring, language service, and contextual selection behavior

- **Project:** Drupal AI
- **Type:** Major task
- **Status:** Fixed
- **Discussion:** [#3586388](https://git.drupalcode.org/project/ai_context/-/work_items/3586388) · 1 contributor · 28 comments

## Summary

Scope ordering, subscription scoring and language handling in AI Context now follow one rule. A scope plugin's `weight` sets both its position in the UI and its influence on scoring, and higher values come first. Entity Bundle and Site Section scoped items are now excluded when no entity or request is available, instead of staying eligible. Content language is now detected the same way for selection, the language scope, and the list and load-by-id function calls. This includes AJAX calls that carry the language only in the Referer header.

## Impact

Affects module maintainers.

- **API change:** Scope plugin `weight` now means higher = displayed first and scored more strongly (previously lower = first). The `AiContextScope` attribute default weight changed from 0 to 1, and `AiContextScopeBase::getWeight()` falls back to 1.
- **New API:** New `ai_context.detected_language` cache context, used by selection cache metadata.

## Technical details

Built-in weights are now Global 100, Use Case 70, Entity Type (shown as Entity Bundle) 60, Site Section 50, Tag 40, Language 30 and Specific Entities (`entity_item`) 10. Scores use the weight directly through a `max(1, weight)` clamp in `AiContextScopeResolver`, replacing `abs(weight) + 1`. Scoring skips scopes where `supportsSubscriptions()` is FALSE. For plugin IDs with no plugin instance it also skips `global`, `entity_item` and `target_entity`. `AiContextScopeManager` sorts by weight descending with plugin ID as the tiebreaker. It no longer lists `ai_context` provider plugins before other modules, so custom plugins can fall between built-ins.

The new `Drupal\ai_context\Service\AiContextLanguageService` (`ai_context.language_service`, marked `@internal`) provides `detect()`, `translateItem()` and `translateItems()`. It replaces `AiContextLanguageDetectorTrait`, which is deleted, and the private `translateItems()` copies in `AiContextSelector` and `LoadAiContextItemById`. `AiContextSelector`, `AiContextScopeLanguage`, `ListAiContextItems` and `LoadAiContextItemById` all use it. The `AiContextSelector` constructor now takes the language service in place of `LanguageManagerInterface`. `AiContextItemRevisionOverviewForm` drops its unused `languageManager` argument. A new `AiContextDetectedLanguageCacheContext` returns `detect()` as its value and itself depends on `languages:language_content` and `url.path`. `AiContextSelector` now uses it in place of `languages:language_content`.

`AiContextScopeEntityType` gains `matchesCurrentContext()`: no item values gives NULL (neutral), no current value gives FALSE, otherwise a match test. `AiContextScopeSiteSection` returns FALSE instead of NULL when there is no current request. `ListAiContextItems` seeds the current entity from `entity_type` and `entity_id` through `AiContextCurrentEntityResolver::setCurrentEntity()` before `filterByCurrentContext()`, and clears it in a `finally` block.

## Upgrade

Custom scope plugins that declared a `weight` for the old "lower is first" ordering need new values. For example, the built-in plugins changed like this:

```php
// AiContextScopeGlobal
weight: 100,   // was -100
// AiContextScopeUseCase
weight: 70,    // was -10
// AiContextScopeLanguage
weight: 30,    // was 0
```

Pick a value between the built-in weights (for example 65, between Use Case and Entity Bundle) to place a custom scope. Code that calls `ListAiContextItems` for bundle-scoped content must pass `entity_type` and `entity_id`, because bundle-scoped items are now rejected when no entity can be resolved.
