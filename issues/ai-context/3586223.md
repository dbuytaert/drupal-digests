## Summary

Uninstalling the AI Context module (CCC) could fail with fatal errors: a missing `ai_context_usage` table broke uninstall validation, and after uninstall the site could show a white screen from stale Scheduler plugin definitions. Uninstall now works in both cases. Sites should run database updates to pick up a new update that creates or repairs the usage table.

## Impact

Affects site owners.

- **Database update:** New `ai_context_update_10005()` installs or repairs the `ai_context_usage` entity table; it throws `UpdateException` if a partial table contains rows.

## Technical details

Three causes were fixed.

1. Core's `ContentUninstallValidator` runs a SELECT on every content entity table, which threw when `ai_context_usage` was absent. `AiContextUninstallValidator` now takes `@database` and `@entity.definition_update_manager`, is tagged with `priority: 100` so it runs before core's validator, and calls `installEntityType()` for any `ai_context` content entity whose base table is missing (`ensureEntitySchemasExist()`). Installing the full schema avoids leaving stub tables if another validator then blocks uninstall.

2. `hook_uninstall()` used the `Workflow` entity API (`removeEntityTypeAndBundle()` plus `save()`) to remove `ai_context_item` from `basic_editorial`. By then the entity type is already unregistered, so content_moderation's save validation threw `PluginNotFoundException`. It now edits the `workflows.workflow.basic_editorial` config directly and unsets `type_settings.entity_types.ai_context_item`.

3. The Scheduler plugin discovery cache kept `ai_context_item_scheduler`, whose class no longer exists, which caused the `PluginException` WSOD (e.g. on `/admin/reports/dblog`). Uninstall now calls `clearCachedDefinitions()` on `plugin.manager.scheduler`, or deletes the `scheduler_info` entry from the `discovery` cache if the service is unavailable.

`ai_context_update_10005()` installs the `ai_context_usage` entity type when the table is missing. If the table exists but lacks the expected columns, it drops it when empty and throws `UpdateException` when it has rows. A new kernel test, `AiContextInstallUninstallTest`, covers these cases.

## Upgrade

Run database updates so `ai_context_update_10005()` can create or repair the `ai_context_usage` table:

```
drush updatedb
```

If the update fails because `ai_context_usage` exists with missing columns and contains rows, empty the table and rerun it.
