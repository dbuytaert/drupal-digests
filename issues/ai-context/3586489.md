# #3586489: Remove stale consumer config when a host entity is deleted

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586489](https://git.drupalcode.org/project/ai_context/-/work_items/3586489) · 1 contributor · 14 comments

## Summary

Deleting an AI Automator now removes its `automator:{id}` row from `ai_context.consumers`. Before this, only deleting an `ai_agent` did that, and a deleted automator showed up as a stale entry in the consumers listing until an admin removed it by hand. Consumer types from other modules can now get the same cleanup by declaring which entity type hosts them. A consumer type that fails to load is now skipped and logged instead of breaking entity deletes, the consumers listing, or routing.

## Impact

Affects module maintainers.

- **API change:** `AiContextConsumerTypeInterface` gains a required method; plugins that implement the interface directly instead of extending `AiContextConsumerTypeBase` must add it.
- **New API:** `AiContextConsumerTypeInterface::getConsumerIdForDeletedEntity()` and a `host_entity_type` key on the `AiContextConsumerType` attribute.

## Technical details

`ai_context_entity_delete()` no longer special-cases `ai_agent`. It calls a new `AiContextConsumerTypeManager::getConsumerIdsForDeletedEntity()`, which is marked `@internal`. That method asks every discovered consumer type plugin, including disabled or unavailable ones, because a leftover row can exist after a kill switch. Each returned ID goes to the existing `AiContextScopeCleanupService::removeDeletedConsumerConfig()`, so there is no second write path.

Each type answers through the new `getConsumerIdForDeletedEntity(EntityInterface $entity): ?AiContextConsumerId` method. `AiContextConsumerTypeBase` implements the 1:1 case from the new `host_entity_type` attribute argument. If the entity type matches and the ID is non-empty, it returns `{plugin_id}:{entity_id}`. Otherwise it returns NULL. The `agent` and `automator` plugins set `host_entity_type` to `ai_agent` and `ai_automator`. Types with a different ID scheme override the method. Types with no host omit the key.

`AiContextConsumerTypeManager::getConsumerTypePlugins()` now catches `\Exception` (not `\Error`) from `createInstance()`. It logs the failure and omits that type. The same applies to the mapping call. This is why a broken type is also dropped from the listing and from routing. The manager takes a new optional `$logger` argument, wired to `@logger.channel.ai_context` in `ai_context.services.yml`. No config dependencies were added on `ai_context.consumers`, and rows that are already stale are not cleaned up retroactively.

## Upgrade

Plugins that extend `AiContextConsumerTypeBase` need no change. A type whose instances are 1:1 with a host entity can opt in through the attribute:

```php
#[AiContextConsumerType(
  id: 'automator',
  // label and description omitted
  host_entity_type: 'ai_automator',
)]
```

Types with a different ID scheme should override `getConsumerIdForDeletedEntity()`. Do not gate it on `isEnabled()` or `isAvailable()`. Return NULL when the type does not own the entity.
