## Summary

Modules that are not AI agents can now get CCC context with a single call to the `ai_context.request_factory` service. You pass scopes, an optional token limit, an optional target entity and an optional consumer ID. You get back the rendered context text, or an empty string if nothing matches. A second method returns the full result object, which includes cache metadata and the selected item IDs. The change also renames "token budget" to "max tokens" in labels, docs and the result API.

## Impact

Affects module maintainers.

- **API change:** `AiContextResult::getTokenBudget()` renamed to `getMaxTokens()`, and the constructor parameter `tokenBudget` to `maxTokens`.
- **New API:** `AiContextRequestFactory::getRenderedContext()` and `getResult()` return CCC context for given scopes in one call.

## Technical details

The methods are on `AiContextRequestFactory`, not in a new `ai_context.retriever` service as the issue proposed. The maintainer chose this to avoid adding a 22nd service. The factory now takes `@ai_context.selector` as a third constructor argument. This is a service definition change only for code that instantiates the factory directly.

`getResult(array $scopes = [], ?int $maxTokens = NULL, ?EntityInterface $targetEntity = NULL, ?string $consumerId = NULL): AiContextResult` builds an `AiContextRequestParamsData` with an empty task and `selectionMode: 'match_all'`. It takes the entity type and ID from `$targetEntity`, calls `fromParameters()`, and passes the request to `AiContextSelector::select()`. `getRenderedContext()` returns `getResult()->getRenderedText()`. Because of `match_all`, published items that pass the context filters are candidates even when they lack matching scope subscriptions. The new kernel test covers this: a scoped item is selected when `scopes` is empty.

Also in this commit: `AiContextSelector::emptyResult()` now uses the request's `maxTokens` when one is supplied, so the empty result reports the caller's limit. `AiContextResult::getTokenBudget()` is renamed to `getMaxTokens()`, with the constructor parameter renamed to match. The settings form label for `max_tokens` becomes "Max tokens for injection". Docs under `docs/developers` now describe the current services and the agent and non-agent flows.

## Upgrade

Replace calls to the renamed result getter:

```php
// Before.
$result->getTokenBudget();
// After.
$result->getMaxTokens();
```

Non-agent code can now use:

```php
$text = \Drupal::service('ai_context.request_factory')->getRenderedContext(
  scopes: ['use_case' => ['empathy_evaluation']],
  maxTokens: 2000,
  targetEntity: $node,
  consumerId: 'my_module',
);
```
