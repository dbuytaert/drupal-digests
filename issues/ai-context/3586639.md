# #3586639: Status badge contrast (WCAG 1.4.3): Unavailable fails on row hover

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3586639](https://git.drupalcode.org/project/ai_context/-/work_items/3586639) · 1 contributor · 10 comments

## Summary

The status badges in the AI Context listing and on the item page no longer change contrast when the row behind them is hovered or striped. An accessibility audit found the Unavailable badge dropped to 4.23:1 on row hover, below the WCAG 2.2 AA minimum of 4.5:1. With the fix it measures about 4.53:1 in every row state, in light and dark mode, by the issue's own calculation. The Disabled badge still fails AA on its own (about 4.18:1 before any hover). That comes from Gin's danger colours and was left for an upstream Gin issue.

## Impact

Affects front-end developers.

- **Theme change:** Status badge CSS in `css/ai_context.css` and `css/ai_context_item.css` now sets `background-color` and `background-image` instead of the `background` shorthand; themes overriding the badge `background` may need to adjust.

## Technical details

The badge colours come from Gin variables such as `--gin-status-warning-bg`, which are semi-transparent. Gin's row hover tint therefore showed through and lowered contrast. Changing CCC's literal fallback values would have had no effect on a Gin site, since Gin defines the variables. The fix keeps Gin's palette and gives each badge an opaque base instead. The base class sets `background-color: var(--gin-bg-layer, #fff)`. Each status modifier then paints its colour with `background-image: linear-gradient(var(--gin-status-*-bg, …), var(--gin-status-*-bg, …))`. A gradient is used because `background-image` can layer a flat colour over the opaque base colour. `--gin-bg-layer` follows the theme, so it covers dark mode too. The change applies to `.ai-context-status*` in `css/ai_context.css` and to `.ai-context-item-entity__status*` in `css/ai_context_item.css`. Text colours are unchanged.
