## Summary

When an AI Automator in base mode runs over a multi-value field, each request now gets exactly one context block. Before, request k carried k blocks, so token use grew with each value and could exceed the per-instance `max_tokens` budget. One known limit remains: if a later request on the same field does not push context (for example Relevant mode selects nothing), OpenAI-based providers can still send the earlier block. That needs a fix in AI Automators (project/ai[#3586900](https://www.drupal.org/node/3586900)) and is documented in the module's Known issues.

## Impact

No upgrade or configuration changes required.

## Technical details

The cause is in AI core's `ProviderProxy`. It copies the system role of a provider instance into the new `ChatInput` before `PreGenerateResponseEvent`, and copies the system prompt back to the role afterwards. Automators reuse one provider instance for all values, so the next fresh `ChatInput` (with no stored result) already contains the previous block, and `AiContextPreGenerateResponseSubscriber` appended another.

On a routed request the subscriber now first removes earlier blocks, then adds one block if the request pushes. It keeps the text of each block it appended in a private history (`BLOCK_HISTORY_SIZE` = 50, a re-appended block moves to the end). `removeAppendedBlocks()` strips exact copies from the system prompt with `strtr()`, so a block that contains an older block is removed whole. Text from the caller or other subscribers is left alone, even if it looks like a context block. Removal also runs when the request does not push (`push_disabled`, `declined`, `no_items`). Requests the subscriber does not route, such as agent requests, are untouched. `buildContextBlock()` now uses a `CONTEXT_DELIMITER` constant.

Limit: if more than 50 different blocks take turns in one PHP process, an older block is no longer recognised and not removed. The removal step carries a `@todo` to drop it once AI Automators reset the system role per request (project/ai[#3586900](https://www.drupal.org/node/3586900)). Docs were updated in `events.md`, `consumer_api.md`, `debugging.md`, `consumer_configuration.md` and `known-issues.md`. The subscriber is `final` and `@internal`, so there is no public API change.
