# #3586545: Store Tag and Taxonomy scope values as entity UUIDs

- **Project:** Drupal AI
- **Type:** Critical task
- **Status:** Fixed

## Summary

In AI Context, the Context Tags and Taxonomy Terms scopes now store the term's UUID instead of its serial term ID. Before this, default content and recipes could not carry these scope values across installs. Terms got new IDs on import, so items and consumer subscriptions pointed at the wrong term or at nothing. Recipes can now ship `scope_id: tag` with a UUID `value`, and the term YAML no longer needs a pinned `tid`. A post-update converts existing stored IDs. Unknown or deleted IDs are left as they are and stay unmatched.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_context_post_update_0013_convert_tag_taxonomy_scope_values_to_uuids` rewrites tids to UUIDs in the item scope field tables, the scope index and consumer `scope_subscriptions` config.
- **Config change:** `scope_subscriptions` for `tag` and `taxonomy` in `ai_context.consumers` and `ai_context.agents` now hold term UUIDs.
- **API change:** `AiContextItem::getContextTagIds()` is removed. Tag and Taxonomy scope value IDs, in `scope_subscriptions` and item scope values, are now term UUIDs instead of numeric tids.

## Technical details

Runtime matching was already string equality on `scope.value`, so the change is in what gets stored and how it is resolved. The new `AiContextTaxonomyTermUuidTrait` is used by `AiContextScopeTag` and `AiContextScopeTaxonomy`. It loads terms by stored value and converts autocomplete term IDs to UUIDs on save. `getValues()` keys options by UUID. Form defaults, label lookup, cacheable-metadata dependencies, stale-value detection and delete cleanup (`getStaleTermValuesForEntityDelete()`) all resolve by UUID. `AiContextScopeTaxonomy` also adds the `taxonomy_term_list` cache tag, because a stored UUID can start resolving after its term is imported. Detected request-entity values and `getMatchingIndexedValues()` now use term UUIDs.

Tag stale-value detection still keeps a leftover numeric tid until the post-update converts it, provided its tag is still offered.

`ai_context_post_update_0013_convert_tag_taxonomy_scope_values_to_uuids()` collects numeric values from `ai_context_item__scope`, `ai_context_item_revision__scope`, the scope index table, and `scope_subscriptions` in `ai_context.consumers` and `ai_context.agents`. It maps each tid to a UUID per scope: terms in the `tags` vocabulary map to `tag`, and all other terms map to `taxonomy`. A tid that points at the other scope's vocabulary is left for stale cleanup. The update rewrites the field tables, the index (dropping rows that would collide on the primary key) and the consumer config. It can be re-run if it stops partway.

`AiContextItem::getContextTagIds()` is removed. Callers can use `getScopeValues('tag')`, which the removed method wrapped. The scope diff builder, docs and `AiContextSelection` examples were updated to UUIDs. New test fixtures for a tagged item and a portable tag term cover the default-content round trip.

## Upgrade

Run database updates so `ai_context_post_update_0013_convert_tag_taxonomy_scope_values_to_uuids` converts stored tids.

Custom code, recipes and exported config that pass serial term IDs for the `tag` or `taxonomy` scopes need to pass the term UUID instead:

```yaml
scope:
  - scope_id: tag
    value: 7a1e8432-3616-438e-a411-76c93afba733
```

Term YAML in recipes should no longer set `tid`. Replace calls to the removed `AiContextItem::getContextTagIds()` with `getScopeValues('tag')`, which now returns UUIDs.
