## Summary

The AI Context Get Relevant tool no longer fails with a database exception on MariaDB and MySQL when `always_include` or `never_include` holds a value such as a label with non-ASCII characters (for example `café`). Such values are now silently ignored. The same guard applies to stored consumer include lists, saving the consumer settings form, and post-update 0008, so a single bad stored value can no longer break saving any consumer or fail the database update. Include-list values must be a numeric item ID or a lower-case UUID to match anything.

## Impact

No upgrade or configuration changes required.

## Technical details

`AiContextItemIdentifierResolverTrait::resolveContextItemIdentifiersToIds()` sent every non-numeric identifier to an entity query on `uuid`. That column is ASCII, and MariaDB and MySQL raise "Illegal mix of collations" (1267) when it is compared with a non-ASCII value, while SQLite just returns no row. The trait now skips any identifier for which `Drupal\Component\Uuid\Uuid::isValid()` is false before it is added to the lookup list.

The identical split-and-query code in `AiContextConsumerForm::calculateConsumerContentDependencies()` and `_ai_context_post_update_0008_calculate_consumer_content_dependencies()` got the same `Uuid::isValid()` guard ([#3586749](https://www.drupal.org/node/3586749) was closed by this change). The form runs it over every stored consumer row on each save, so one bad value in another consumer's list would previously have blocked saves.

`Uuid::isValid()` accepts only the lower-case 8-4-4-4-12 form. Values with a leading no-break space or zero-width space, and upper-case UUIDs, are therefore dropped before the query. Upper-case UUIDs already failed to resolve earlier, because results are keyed by the stored lower-case UUID. Dropped values stay in stored config, and post-update 0008 leaves unrecognized values unchanged. New kernel tests `AiContextIncludeListIdentifierTest` and `AiContextConsumerIncludeListNonUuidTest` assert via `Database::startLog()` that the value never reaches a query, so they hold on SQLite too.
