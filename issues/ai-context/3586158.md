## Summary

Context items scoped to a site section using a `custom:` path (for example `custom:/products/*`) are now selected when the current request path matches. Before, custom path patterns never matched during context selection, so those items were effectively never applied. Predefined site sections and items with no site-section value behave as before.

## Impact

No upgrade or configuration changes required.

## Technical details

`AiContextScopeSiteSection` now overrides `matchesCurrentContext()`. The base scope logic only compared the detected section ID to stored values, which ignored `custom:` entries. The override reads the item's site-section values and returns `NULL` (no restriction) if there are none or if `RequestStack::getCurrentRequest()` returns nothing. Otherwise it passes `$request->getPathInfo()` and the item values to the existing `matchesCurrentPath()`, which handles both configured section IDs and `custom:` patterns. Kernel tests in `AiContextScopeResolverTest` cover predefined sections, wildcard and exact custom paths, a non-matching path, and the no-request case.
