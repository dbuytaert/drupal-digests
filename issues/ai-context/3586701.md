## Summary

Users whose role had core's "View any unpublished content" permission, such as the Content editor role on Drupal CMS, could read draft and archived AI Context items even with no AI Context permission. This included the item page, the Latest version tab, revision pages, and the CCC listing for roles that also had "View AI Context Items in CCC". After the fix, unpublished items are visible only to users with "Administer AI Context", "View any unpublished AI Context Item", or the owner holding "View AI Context Items in CCC". Roles that need to see drafts must be given "View any unpublished AI Context Item". Published items are unchanged. Run `drush cr` after updating.

## Impact

Affects module maintainers and site owners.

- **Security:** Access bypass: core's "View any unpublished content" (via Content Moderation) let users read draft and archived context items without any AI Context permission. Affects 1.0.0-beta1 to 1.0.0-rc1 and 1.0.x.
- **API change:** `view` access on an unpublished context item is now forbidden, not neutral, when no context item rule allows it, so `hook_entity_access()` and `hook_ai_context_item_access()` implementations can no longer grant it.

## Technical details

`AiContextItemAccessControlHandler::checkAccess()` returned a neutral result for `view` of an unpublished item when no rule matched. Content Moderation's `hook_entity_access()` allows `view` of any unpublished entity for "view any unpublished content", and a neutral result let that grant win. The handler now returns `AccessResult::forbidden()` in that case, because a forbidden result cannot be overridden by other access hooks. Cache metadata is kept: a non-owner with `view ai context items` gets a forbidden result with per-permissions and per-user contexts. A user without that permission gets a forbidden result per permissions only, since ownership does not matter, plus the item as a cacheable dependency. Published items still return neutral.

Because the check is on entity `view` access, it also covers the routes that depend on it: the Latest version tab still needs core's "View the latest version" and "View any unpublished content" but now also needs view access to the item. The revision history and revision pages need the revision permission plus view access to each revision. Kernel tests in `AiContextItemModerationAccessTest` and `AiContextItemAccessControlHandlerCacheTest` cover these routes and the cache contexts. Docs were updated in `access-boundaries.md`, `configuration.md` and `api-stability.md`.

## Upgrade

Roles that must see draft or archived context items (including editors who save a new draft and are redirected to the Latest version tab) need the "View any unpublished AI Context Item" permission. Without it the Latest version tab now shows "Access denied", though the save still works. Custom `hook_entity_access()` or `hook_ai_context_item_access()` code can no longer allow `view` of unpublished items. Run `drush cr` after updating.
