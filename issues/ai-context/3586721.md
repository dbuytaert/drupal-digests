## Summary

On the translation form of an AI Context item, the settings shared by all languages are now hidden: the Context Scope controls, Priority, Specific Entities, Same as parent, Parent context and Subcontext type. Before, a translator without edit permission could change them, for example by clearing a Roles restriction or marking the item global, and the change applied to every language. This was possible when items were outside the editorial workflow. The fix also lets translations of subcontext child items be saved again. They previously failed with "Subcontext type is required when a parent context is selected."

## Impact

Affects site owners.

- **Security:** Users with translation permission but no edit permission could remove Roles scopes or mark an item global from the translation form when items were outside the editorial workflow.

## Technical details

Core `ContentTranslationHandler::entityFormSharedElements()` hides untranslatable widgets on translation forms but skips `details` elements, and `AiContextItemForm` puts the scope controls, Priority, Specific Entities and Same as parent inside the `context_scope` details element. `AiContextItemForm::form()` now sets `#access` to FALSE on `context_scope`, `subcontext_settings`, `parent` and `subcontext_type` when `sharedSettingsAreReadOnly()` is TRUE. That is the case when core's `content_translation` `translation_form` form state flag is set, or when the entity is a non-default translation and `isDefaultTranslationAffectedOnly()` is TRUE. New items and non-translatable entities are excluded.

In the entity build step, `restoreSharedSettings()` writes the stored values of `scope`, `priority`, `entity_items`, `inherit_parent_scope`, `parent` and `subcontext_type` back onto the entity for those forms. A crafted POST therefore cannot change them. This also fixes the child translation save, because the hidden Subcontext type was previously submitted as empty.

On the translation form only, a warning "Fields that apply to all languages are hidden to avoid conflicting changes." is added. It links to the original language edit form only if the user has `update` access to the original. On the other path core already shows its own message. Editors can still change shared settings while adding a translation to items outside the editorial workflow, as in core. `docs/features/multilingual.md` gains a "What a translation can change" section, and functional tests were added to `AiContextItemTranslationUITest`.
