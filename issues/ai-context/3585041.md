## Summary

The sub-tabs under the AI Context Scope settings page are now generated from the discovered scope plugins instead of being hardcoded. If a scope plugin is removed, for example by uninstalling a module providing it or altering its definition away, its tab disappears too instead of leaving a broken link. Contributed scope plugins get a tab automatically, labelled with the plugin label.

## Impact

Affects module maintainers and site owners.

- **Config change:** 
- **New API:** New `AiContextScopeLocalTask` deriver generates a `ai_context.settings.scope.{plugin_id}` local task per scope plugin definition.

## Technical details

The six hardcoded `ai_context.settings.scope.*` entries in `ai_context.links.task.yml` are replaced by one entry, `ai_context.settings.scope.local_tasks`, with `deriver: \Drupal\ai_context\Plugin\Derivative\AiContextScopeLocalTask`. The deriver loops over `AiContextScopeManager::getDefinitions()` and, per plugin, sets `route_name` to `ai_context.settings.scope.{plugin_id}`, `title` to the plugin `label`, `parent_id` to `ai_context.settings.scope_tab`, and `weight` to the plugin's declared `weight` (default 0). Tab order therefore follows plugin weights, not the old fixed 0 to 50 values.

`AiContextScopeManager` takes a new optional `cache_tags_invalidator` constructor argument (the service definition passes `@cache_tags.invalidator`) and overrides `clearCachedDefinitions()` to invalidate the `local_task` cache tag, so derived tabs follow definition changes without a full cache rebuild. The `@todo` in `ai_context_local_tasks_alter()` that unset the `target_entity` tab when `dynamic_entity_reference` was missing is removed. Per the added docs, routes are named `ai_context.settings.scope.{plugin_id}` with underscores kept, while the URL path uses dashes. The deriver does not create routes, so this relies on routes that already exist for each plugin.

The diff also adds a unit test for the deriver, a `ai_context_test_scope` test module providing a `test_scope` plugin, and replaces a bare `t()` with `$this->t()` in `AiContextEntityTargetResolver`.

## Upgrade

If your module defines its own local task entry for a scope settings tab, remove it, since the tab is now derived. Link to scope settings pages by route name, with underscores, for example:

```php
public function getManageRoute(): ?array {
  return ['route_name' => 'ai_context.settings.scope.target_entity'];
}
```
