## Summary

Scope cleanup no longer leaves an item published with an emptied scope. Before, deleting a role (or language, term, bundle, referenced entity, or uninstalling a module) could remove the last value limiting a context item, so an item limited to the "Reviewer" role was suddenly delivered to every user, with no log or message. Now cleanup unpublishes such an item (state Archived on the `ai_context_editorial` workflow), saves a new revision explaining which value was removed, logs a warning per item, and shows the acting user one warning with a count and a link to the item list. After deleting roles, languages, terms or bundles, or uninstalling modules, check the context item list for newly unpublished or archived items. Items that stay published: Global items, items that keep at least one value, and items that only lose Context Tags (ranking only). Sites that already ran post-update 0006 on 1.0.0-beta5 or 1.0.0-rc1 do not run it again, so items it emptied earlier stay published and need manual review.

## Impact

Affects module maintainers and site owners.

- **Config change:** `ai_context.scope_cleanup` service gains new constructor arguments (logger, messenger, current user, time, database, notice service); only relevant to code that instantiates it directly.
- **New API:** `AiContextItem::canUnpublishWithModerationState()` (`@internal`) and a persisted `ai_context.scope_cleanup_notice` service (`@internal`) hold cleanup counts for one warning per request.

## Technical details

The change is in `AiContextScopeCleanupService`. When `removeScopeValuesFromItems()` empties a scope, or `removeEntityItemReference()` removes the last Specific Entities reference, `widensWhenEmptied()` decides whether the item would reach more requests. The rule: any stored-value scope except Context Tags (`RANKING_ONLY_SCOPES`) counts as a hard filter, custom stored-value scopes included, and there is no public policy API in 1.0. Global items are never unpublished. A subcontext item with no stored inherit flag is unpublished when it would resolve to a Global parent, even if the emptied value was a tag.

Unpublishing uses `setUnpublishedWithModerationState()` on every published translation, saved in one database transaction. `publish_on` (and `publish_state` when present) is cleared on every translation so Scheduler cannot republish it. The save is a new revision with a log message, the current user as author, and the request time. Saves that do not unpublish use `setSyncing(TRUE)` so content moderation does not add a revision that copies the old log message. If a moderated workflow has no unpublished default-revision state (`AiContextItem::canUnpublishWithModerationState()`), the item is not saved: the stale value stays (it matches no request), an error is logged once per scope, and the warning gets an extra sentence. Already unpublished items get the stale value removed with no revision, log or message, unless they have a `publish_on` date, in which case it is cancelled in a new revision.

Counts live in the new `ai_context.scope_cleanup_notice` service, tagged `persist` so one warning with totals survives the container rebuild during a module uninstall. The messenger warning is skipped for the anonymous user (cron, Drush) and deferred until the surrounding transaction commits on entity delete. Post-update 0006 uses the same rule. Docs for scopes, services and custom scopes were updated, and kernel tests were added including `AiContextScopeCleanupForeignValuesTest` (one case per trigger) and a new `ai_context_test_item_save_fail` test module.

## Upgrade

Site owners: after `drush updatedb` (post-update 0006), after deleting roles, languages, terms, vocabularies or bundles, or after module uninstalls, review the context item list for newly unpublished or archived items and re-check their scope before republishing. On sites that already ran 0006 on 1.0.0-beta5 or 1.0.0-rc1, review published items that have no Roles, Languages, Site Sections, Entity Types, Taxonomy Terms or Specific Entities value. Custom workflows need an unpublished state with Published cleared and Default revision selected, or cleanup will not save the item and logs an error. Custom stored-value scope authors: cleanup now treats your scope as a hard filter.
