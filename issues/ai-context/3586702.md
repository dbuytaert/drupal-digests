## Summary

With usage tracking on, a user who could send requests to a push consumer (for example a chatbot) could make a usage record grow without limit by sending a different, very long `path` in each request. That slowed AI requests for everyone using the consumer and could make them fail. Each usage record now keeps only the last 20 request paths, each at most 255 characters, and a client-supplied path hint longer than 2,048 characters is ignored. Errors from usage tracking during agent runs are now logged and no longer fail the run. Usage tracking is off by default. A record saved before the update is cut the next time a path is added to it. A record already too large to load is not cut and must be cleared.

## Impact

Affects site owners.

- **Security:** Unbounded growth of usage record `routes` from client-supplied paths could slow or break AI requests of a push consumer for all users (denial of service, no data exposure); usage tracking is off by default.

## Technical details

The new `AiContextUsage::setRoutes()` drops empty and non-string values, truncates each path to `MAX_ROUTE_LENGTH` (255) characters with `Unicode::truncate()` and an ellipsis, moves repeated paths to the end, and stores only the last `MAX_ROUTES` (20). `addRoute()` now delegates to it, so a repeated path moves to the end instead of keeping its first position. In `AiContextUsageTracker::attachEntity()`, the old record's routes are merged first (`setRoutes(array_merge(old, current))`), so the limit drops the oldest paths and keeps the run's. A new record for another entity gets its first path through `addRoute()`, so the limits apply there too.

`AiContextRequestInfoResolver::normalizeSuppliedPath()` returns NULL when the path, after the query string and fragment are removed, is longer than `MAX_PATH_LENGTH` (2048) characters (`mb_strlen()`). `setPath()` then returns FALSE and `getPath()` falls through to the next source, ending at the request path, which has no limit of its own.

`AiContextAgentToolSubscriber::onToolFinished()` wraps `recordToolUsed()`, `extractEntityInfo()` and `attachEntity()` in a `try` block. `AiContextAgentFinishedSubscriber::onAgentFinished()` does the same for `flushToolsUsed()`. Both catch `Throwable` and log an error naming the runner ID. `AiContextAgentFinishedSubscriber` gets a `LoggerInterface` as its second constructor argument, wired to `@logger.channel.ai_context` in `ai_context.services.yml`. A PHP memory-limit error is fatal and is not a `Throwable`, so the path limits are the main fix and the try/catch is a second safeguard. No update hook is added. All changed classes are `@internal`.

## Upgrade

If a consumer already fails because of oversized usage records, turn off usage tracking at `/admin/config/ai/context/settings/usage`, then clear the records at `/admin/config/ai/context/settings/usage/clear`. If the clear page also fails, empty the table and rebuild the caches:

```
drush sql:query "TRUNCATE TABLE ai_context_usage"
drush cr
```
