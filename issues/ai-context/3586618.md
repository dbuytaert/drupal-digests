## Summary

Drupal tokens in context item text are no longer replaced when context reaches the AI. Before this change, AI Agents ran token replacement over the whole system prompt, so an item containing `[user:mail]` sent the email of whoever ran the agent to the AI provider, and `[user:uuid]` stopped the agent run with an error. The same happened in the List, Load and Get Relevant tool output when a site used them as default information tools. CCC now writes tokens with a space on both sides of the colon, for example `[user : mail]`, on the agent path, the generic chat path, the three tools and the public selection API. Sites that used tokens in item text on purpose must write the real values into the text. Items that document token patterns (for example `[node:title]` for URL aliases) now show them with spaces, so authors may want to tell the agent to remove the spaces when writing a token into a field. The **Context prefix** setting is not changed, so `[site:name]` there is still replaced on the agent path.

## Impact

Affects site owners.

- **Security:** Personal data leak: `[user:mail]` in context item text was replaced by AI Agents with the running user's email and sent to the AI provider. Item text is now neutralized on every path.
- **Config change:** Context prefix is still token-replaced on the agent path; Content and Context prefix field help texts now say how tokens are treated.

## Technical details

A new `@internal` service `ai_context.token_neutralizer` (`AiContextTokenNeutralizer`) uses `Token::scan()` and rewrites each match to `[type : name]`, so a later scan no longer matches. It handles every type from `Token::getInfo()`. It also handles undeclared types that look like token types (for example ECA's `[current_user:mail]`) when the first part of the name has no whitespace, `/` or `@`. Root-level data paths such as `[current_user.mail.value]` are broken when the part before the first dot is a declared type or `current_user`. Root-level matches without a colon, such as `[2]` or `[optional]`, are left alone. It rescans up to three times, because ECA's `scan()` can hide root-level tokens behind a literal `[_eca_root_token:x]`. Side effects: `items[i:j]`, some IPv6 forms like `[fd12:3456::1]`, and dotted Markdown links like `[node.js](...)` also get the spaces.

It is applied in three places. `AiContextRenderer` neutralizes the assembled text, so the token budget is checked on the neutralized text and tokens spanning fields are caught. `AiContextSelector` neutralizes the final text after `TEXT_RENDERED` subscribers run, and the `label`, `purpose` and `content_snippet` in the selected-item data. `ListAiContextItems` neutralizes its own output, because it does not use the renderer. The renderer and selector constructors take the neutralizer as a new last argument, and the service definitions are updated.

Documented limits: each output is neutralized separately, so deliberately split tokens across joined outputs can still be replaced. Sites that decorate `ai_context.selection_factory` must return the inner factory text. Sites that replace it must break tokens in their own output. To read item text as written, load the `ai_context_item` entity.

## Upgrade

The output of `getRenderedContext()`, `getResult()`, `getResultFromSelection()`, `AiContextSelectionResult::getSelectedItems()` and `TEXT_RENDERED` text now has tokens neutralized, for example `[user:mail]` becomes `[user : mail]`. To read item text with its tokens as written, load the context item entity and read its fields. If you replace `ai_context.selection_factory`, put a space on both sides of the colon of Drupal tokens in the text you return, because `ai_context.token_neutralizer` is internal. If you decorate it, return the inner factory text and do not add item text from other sources.
