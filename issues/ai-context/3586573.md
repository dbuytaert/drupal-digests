## Summary

Context Control Center can now optionally appear as its own item in the main admin menu instead of only under Configuration > AI. It is off by default. On the General settings page, above "Show overview page", a new "Add to main menu" checkbox turns it on, and a "Menu item title" field (default "Context") appears when it is checked. The item uses a stack icon and links to the existing CCC redirect, so it opens the overview page when that is enabled and the context items list otherwise. With Navigation (Drupal CMS) it shows in the sidebar after Media; with Toolbar only it shows at the top level after Content. Existing sites get the new settings from a post-update, and the item stays off until an admin enables it.

## Impact

Affects site owners.

- **Database update:** Post-update `ai_context_post_update_0016_add_main_menu_settings` adds the two keys to existing sites; the item stays off.
- **Config change:** New `ai_context.settings` keys `main_menu_enabled` (default `false`) and `main_menu_title` (default `Context`), both optional in schema; title has NotBlank, max 255 and no `<` or `>` constraints.

## Technical details

The link is provided by a menu link deriver, `AiContextMainMenuLinkDeriver`, declared as plugin `ai_context.main_menu_item` in `ai_context.links.menu.yml` (class `MenuLinkDefault`). It returns nothing unless `main_menu_enabled` is on. With the `navigation` module installed the link goes in the `content` menu (weight 10); otherwise it goes in `admin` under `system.admin` (weight -9). When both are installed it appears in Navigation only. The title is stripped of tags and falls back to a translatable "Context" when it is empty or equals the default; a custom title is not translated. The existing `ai_context.main_menu_link` under Configuration is kept, and its plugin ID is retained so overrides and styling still apply.

`AiContextSettingsConfigSubscriber` now takes `router.builder` and calls `setRebuildNeeded()` when the toggle changes, or when the title changes while the toggle is on. Core rebuilds menu links on a router rebuild, so no `drush cr` is needed. The settings form calls `rebuildIfNeeded()` in submit so the redirect shows the change. `ai_context_toolbar_alter()` adds the `config:system.menu.admin` cache tag to the Toolbar tray, so a user whose tray was empty does not keep a cached empty tray after the item is enabled.

Validation: the schema marks both keys `requiredKey: false`, so older exports still import. The title carries NotBlank, Length (255) and a Regex that rejects `<` and `>`, because Navigation inserts the title into an HTML tooltip. The form only requires the title while the toggle is on. While it is off, a blank title keeps the saved one, tags are stripped, and a still-invalid title becomes "Context". The form reads defaults from the editable config, not the overridden config, so `settings.php` overrides are not written back on save. CSS adds the icon for the new link's toolbar classes and an `.ai-context-settings-nested` indent.

The diff also changes `AiContextScopeBase::buildValueForm()` to run option labels through `Html::escape`, so a role label containing markup no longer breaks the value form. This is unrelated to the menu setting.

## Upgrade
