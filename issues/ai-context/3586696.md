## Summary

The AI Context load tool has a new ID, `ai_context:load_ai_context_items`, because the old name `load_ai_context_item_by_id` did not match what the tool does (it loads one or more items) or the other two tool IDs. The new tool has the same inputs, access checks and output as before. The old ID stays as a deprecated alias until 2.0.0, so existing agents keep working. The agent tool list shows it as "Load AI Context Item By ID (deprecated)". New agents should use the new tool. Existing agent configuration is not migrated automatically. Agent prompts that name the old tool must be edited by hand.

## Impact

Affects module maintainers and site owners.

- **Config change:** Agent configuration that names the old plugin ID (tools, default information tools, overrides) keeps working but should be changed by hand to the new ID. No update hook migrates it.
- **Deprecation:** Function call plugin ID `ai_context:load_ai_context_item_by_id` is deprecated in 1.0.0 and removed in 2.0.0. Each call triggers `E_USER_DEPRECATED`.
- **New API:** New function call plugin ID `ai_context:load_ai_context_items` (function name `ai_context_load_ai_context_items`, tool name "Load AI Context Items").

## Technical details

The load logic moved out of `LoadAiContextItemById` into a new `@internal` abstract base class, `AiContextLoadItemsFunctionCallBase`. The new `LoadAiContextItems` plugin extends it with no overrides. `LoadAiContextItemById` also extends it, keeps its old `id` and `function_name`, and changes its `name` and `description` to say it is deprecated and name the new ID. Its `execute()` calls `@trigger_error(..., E_USER_DEPRECATED)` and then `parent::execute()`. The notice fires only when the tool runs. Listing the tools, building the agent form or creating the plugin does not trigger it. Both `#[FunctionCall]` attributes carry the same `context_definitions`, and the class docblock says to keep them in sync.

The docs (`docs/developers/api-stability.md`, `function_calls.md`, `index.md`, `services.md`) now use the new ID. `api-stability.md` lists the alias under "Deprecated APIs" and has an "Upgrade from 1.0.0-rc1: Load tool plugin ID" section. That section says to change `default_information_tools` entries and agent overrides to the new ID. It also says usage records still show the old ID for agents that have not been moved. A new kernel test, `AiContextLoadFunctionCallAliasTest`, checks that the definitions match, the output is identical for both IDs including the permission denial, and the deprecation fires only on execute. `AiContextEchoAiSystemPromptTest` gains a case that runs the old ID as a default information tool.

## Upgrade

Replace the old plugin ID in agent config, using the same parameters:

```
tool: ai_context:load_ai_context_item_by_id
```
becomes
```
tool: ai_context:load_ai_context_items
```

This applies to the agent's tool selection and tool settings, its **Default information tools**, and any AI Agents agent overrides. Agent prompts that mention `ai_context:load_ai_context_item_by_id` or `ai_context_load_ai_context_item_by_id` must be edited by hand to use `ai_context:load_ai_context_items` or `ai_context_load_ai_context_items`. To find agents that still use the old ID, check the **Tools used** list on usage records.
