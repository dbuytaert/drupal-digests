## Summary

Several help texts in AI Context described behavior the code does not have, and this fixes them. The Language scope text said an item is kept when the current language cannot be determined. That never happens, because a language is always detected. With no language prefix in the path, as in Drush, cron or queue calls, Drupal's negotiated content language is used, usually the site default. An item set only to other languages is therefore left out of those calls. The cap field "Max conditional parent decisions per request" is now labelled "per context resolution call", because one page request or agent run can make several resolution calls. Consumer form help now also names the Roles filter as a way items are left out. Behavior does not change, but the edited strings are translatable, so existing translations of them will need updating.

## Impact

No upgrade or configuration changes required.

## Technical details

This is a text and docs change only. `AiContextLanguageService::detect()` always returns a code, so `AiContextScopeLanguage` never produces a neutral (NULL) result for an item that has Language values. The corrected strings are in the `AiContextScopeLanguage` plugin description and `getItemFormDescription()`, in the Default row and Scope Subscriptions help in `AiContextConsumerForm`, and in the `conditional_max_parents` title and description in `AiContextItemSettingsForm`. The setting key, schema and `AiContextSubcontextResolver` limit logic are untouched.

Docs updated: `docs/features/scopes.md` (the Language example now says S also passes on a Spanish request, and explains the fallback), `docs/features/subcontext.md`, `docs/developers/configuration.md`, `docs/developers/debugging.md` (`decision_cap_exhausted`), plus `multilingual.md` and `context_selection.md`. These drop the claims that "detection happens once per request" and that Language "changes how it scores". The commit adds a kernel test, `testRequestWithoutPrefixUsesNegotiatedLanguage()`, and a second one for a non-default negotiated language. Functional tests are updated to assert the new strings.
