## Summary

AI Context now keeps a separate, indexed table of each context item's scope values. When a request carries scope subscriptions, the selector uses it to narrow which items are loaded before scoring. Previously every published item was loaded into PHP and filtered there. Run database updates after upgrading so existing items are indexed.

## Impact

Affects module maintainers and site owners.

- **Database update:** New `ai_context_item_scope_index` table, created and backfilled in batches by `ai_context_update_10004()`.
- **New API:** New `ai_context.scope_index` service (`AiContextScopeIndexService`) and `AiContextScopeResolver::prefilterItemIdsByScope()`.

## Technical details

The scope map is a serialized field, so it can't be filtered in SQL. The new `ai_context_item_scope_index` table (defined in `hook_schema()`) stores one row per `(item_id, scope_id, value)`, with a primary key on all three columns and secondary indexes on `(scope_id, value)` and `item_id`. `target_entity` is excluded because it already lives in a separate dynamic entity reference field. Only the current entity state is indexed, not historical revisions.

`AiContextScopeIndexService` (`ai_context.scope_index`) writes the rows. `indexItem()` deletes and re-inserts inside a transaction. It is called from `hook_ai_context_item_insert` and `hook_ai_context_item_update`, and the delete hook calls `deindexItem()`. `getItemIdsByScope()` returns a superset of the final matches: items with a row matching any subscribed scope value, plus candidates that have no rows for at least one subscribed scope, because a missing scope means a broad match. The broad-match step only runs when candidate IDs are passed. `AiContextScopeResolver::prefilterItemIdsByScope()` wraps it and returns `NULL` for empty subscriptions, meaning no prefilter. The resolver constructor now takes the index service as a second argument.

`AiContextSelector` uses this in the same commit. When subscriptions are present, it loads access-checked published IDs, prefilters them, and adds global item IDs (queried via `['global' => ['global']]`) and applies `neverInclude`. It then loads the entities in chunks by ID through `loadPublishedItemsByIds()`. PHP scoring still runs on the loaded entities for exact ranking. Without subscriptions, the old chunked scan is used. The selector still queries the published IDs, so this narrows entity loading, not ID enumeration.

## Upgrade

Run database updates. `ai_context_update_10004()` creates `ai_context_item_scope_index` if missing and backfills existing items in batches of 100. Code that constructs `AiContextScopeResolver` directly must pass the `ai_context.scope_index` service as the second argument.
