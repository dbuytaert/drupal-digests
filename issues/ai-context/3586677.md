## Summary

The token figures shown for AI Context items now match what each item costs when injected. Before, the Tokens badge, its tooltip and the consumer budget summary counted only an item's guidance text. Items are actually injected as a block with an ID, label and purpose header and indented guidance. Items that looked like they fit within **Max tokens for injection** could still be cut off at render time. The "Items cut off due to token limit: 4" warning also now says what the number means: how many of the selected items did not fit, which token budget, which consumer, and the item IDs. After updating, run `drush updatedb` and `drush cr`. Expect higher badges, percentages and budget totals. Sites near their budget may now see **Context budget exceeded**. Selection and rendering behave as before.

## Impact

Affects module maintainers and site owners.

- **Database update:** Update `10032` recounts the stored `token_count` of every `ai_context_item` revision and translation so it covers the rendered block.
- **Config change:** No config schema change; the consumer budget summary note and the cut-off warning text are reworded.
- **New API:** `AiContextRendererInterface` gains `estimateItemTokens()` and `estimateBlockTokens()`; `AiContextTokenCountBackfillScheduler` gains `writeTokenCounts()`.

## Technical details

`AiContextItem::preSave()` now stores `AiContextRendererInterface::estimateItemTokens()` in `token_count` instead of estimating the guidance text alone. That method calls the new `estimateBlockTokens($id, $label, $purpose, $content)`, which builds the block with the same `buildBlockPrefix()` and `buildBlock()` helpers the renderer uses, so the stored figure and `render()` stay in step. The per-item figure excludes the blank separator between blocks. The context prefix and delimiters are added after the budget is enforced.

A new item has no ID in `preSave()`, so `postSave()` recounts it and writes the result through the new `AiContextTokenCountBackfillScheduler::writeTokenCounts()`. That writes straight to the column and avoids a second entity save. The recount check in the entity now also fires when the label or purpose changes. It also fires when a draft is published or an older revision is reverted to, because those carry whatever count they were saved with.

Update `10032` recounts through `AiContextTokenCountBackfillScheduler::backfillChunk()`, which now reads every revision and translation (from the revision data table when available) rather than only the current revision. It passes `id`, `label`, `purpose` and `content` to `estimateBlockTokens()`. If `AiContextTokenizerUnavailableException` is thrown, it calls `deferRecount()` so cron recounts later, as update `10023` does. The scheduler now takes `@ai_context.renderer` as a constructor argument.

The selector warning in `AiContextSelector` now uses `@count`, `@selected` and `@max`, plus `@consumer` when `getConsumerId()` is set. `AiContextTokenEstimator::formatListingTooltip()` gained a `$children` argument so a parent row says its figure already covers its subcontext items, which are listed separately. The budget summary note text in `AiContextConsumerBudgetSummaryLazyBuilder` was reworded.

## Upgrade

Run the database update, then clear caches:

```bash
drush updatedb -y
drush cr
```

Update `10032` recounts every revision and translation in chunks. Code that decorates `ai_context.renderer` must implement the two new methods on `AiContextRendererInterface` (an `@internal` interface):

```php
public function estimateItemTokens(AiContextItem $item): int;
public function estimateBlockTokens(string $id, string $label, string $purpose, string $content): int;
```
