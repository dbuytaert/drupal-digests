## Summary

On multilingual sites, AI Context no longer sends an unpublished translation (Draft or Archived) of a context item to AI prompts or tool output. The published default-language text is used instead, and the item is left out when that is not published either. This applies to every user, including administrators. Non-admin users also now get a published translation of a draft source item, and context push no longer fails for them when a selected item has an unpublished translation in the request language. Sites with moderated translations, where translations often start as Draft, were most exposed.

## Impact

No upgrade or configuration changes required.

## Technical details

Status is stored per translation, but `AiContextLanguageService::translateItem()` returned a requested translation whenever it existed. The List, Load and selector paths checked `access('view')` on the default translation before the language switch. As a result, an Archived translation could be shown to a user who only had the published-context permission. A draft source with a published translation was dropped. The selector threw an `AccessException`. The parent text sent in the conditional subcontext prompt used the translated parent, so it was exposed too.

`translateItem()` now works from `getUntranslated()`. It returns the requested translation only if `isPublished()`, and otherwise returns the default translation. `translateItems()` now filters. It keeps an item only if the chosen translation is published and `access('view')` passes on that translation. `isPublished()` is checked first on purpose, because the boolean `access()` call drops cacheability. That is safe only for published translations, since the per-user owner access result applies to unpublished ones.

The per-item `access('view')` loops on the default translation were removed from `AiContextSelector` (`loadPublishedItemsByIds()` and the chunk loader), `ListAiContextItems` and `LoadAiContextItemById`, because all delivery paths already call `translateItems()`. List and Load now return `No context items are available.` and `None of the requested context items are available.` when nothing survives. Subcontext children passed through `translateItems()` are also dropped when their delivered translation is unpublished or not viewable. The issue says a follow-up, [#3586617](https://www.drupal.org/node/3586617), replaces this boolean check for children with one that keeps access cacheability. Docs under `docs/` were updated, and new kernel tests cover the reader, admin, conditional-prompt and EchoAI agent cases.
