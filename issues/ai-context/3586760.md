## Summary

Context items can now have an optional Token name, for example `brand_voice`. The item text is then available as `[ai_context:item:brand_voice]`, so a site builder can place one exact item in an AI agent system prompt instead of relying on selection. The token works anywhere Drupal tokens are replaced (AI Agents system prompts, Pathauto, Metatag, Webform mail, ECA), but AI core does not yet replace tokens in other prompts. The token gives the published translation the current user can view, plus required subcontext children. If nothing is viewable, it gives an empty string. Scope rules, including the Roles filter, do not apply. The item form warns when a change would make existing uses of the token empty.

## Impact

Affects module maintainers and site owners.

- **Database update:** `ai_context_update_10033()` installs the new `token_name` field storage definition on `ai_context_item`.
- **Permission change:** Only users with `administer ai context` can edit the `token_name` field; field access enforces this outside the form too.
- **New API:** New Drupal token `[ai_context:item:TOKEN_NAME]` via `hook_token_info()` and `hook_tokens()`, and new `token_name` base field on `ai_context_item` with `AiContextItem::getTokenName()`.

## Technical details

`token_name` is a `string` base field on `AiContextItem`: not revisionable, not translatable, max length `AiContextItemToken::TOKEN_NAME_MAX_LENGTH`, with a `UniqueField` constraint, a regex requiring a lowercase letter first then lowercase letters, numbers and underscores, and a new `AiContextItemTokenNameRevision` constraint. That constraint blocks a token name change in a non-default-revision save, since only the default revision would store it. `AiContextItemAccessControlHandler::checkFieldAccess()` limits editing to `administer ai context`. The form shows the field in a "Token" sidebar section.

Token replacement lives in the new `ai_context.item_token_resolver` service (`AiContextItemTokenResolver`), called from `AiContextTokensHooks` through `hook_token_info()` and `hook_tokens()`. Procedural `#[LegacyHook]` bridges in `ai_context.module` and an explicit service registration keep it working on D10. Output goes through the existing token neutralizer, which now also adds a space after an open bracket at the end of a value, so adjacent outputs cannot be joined into a live token. The docs describe cache tags for the item and `ai_context_item_list`, plus `user.permissions` and content language contexts. They also describe debug log messages for empty tokens.

There are also new warnings for the token name change, unpublish, scheduled unpublish, delete and revert. They list config that uses the token, found by `AiContextItemTokenUsageFinder`. New `AiContextItemDeleteForm` and `AiContextItemTranslationDeleteForm` handlers carry the delete warnings. The docs note that the token is not limited to AI prompts, and that the same item can appear twice in an agent prompt if pushed context also selects it. The fix is **Never include** for that agent.

## Upgrade

Run database updates so `ai_context_update_10033()` adds the field:

```bash
drush updatedb -y
drush cr
```

Existing items get no token name. To use it, set Token name on an item and add `[ai_context:item:brand_voice]` (your own name) to the agent system prompt.
