## Summary

The "Last Used" column on the Context usage page (`/admin/config/ai/context/usage`) now moves every time a context item is used. Before, a repeat use through the same consumer and route, such as CKEditor on a new node, stopped updating it after the second use, so it behaved like "first used". Usage cleanup on cron reads this value, so records still in use are no longer treated as old.

## Impact

No upgrade or configuration changes required.

## Technical details

"Last used" is the usage record's `changed` time. Core's `ChangedItem` only advances it when another field value differs, and a repeat use writes identical values. `AiContextUsageTracker` now takes `datetime.time` as a third constructor argument (wired in `ai_context.services.yml`). It calls `setChangedTime($this->time->getRequestTime())` before every `save()` in `recordUsage()` (both the existing-record and new-record paths) and in `attachEntity()` (the paths that update the runner's record, update an existing entity record, and create a new record). The stamp is the request start time, so a long-running job records when it started.

The usage docs now say that Last Used is written on every use and that both cron cleanup rules (maximum age, then maximum record count) read Last Used rather than Created. Tests add a hand-moved clock, `AiContextTestClock`, swapped into the container's `datetime.time`. The kernel tests fail at the third use without the fix.
