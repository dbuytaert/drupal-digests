## Summary

On the AI Context consumers listing, Automator rows are easier to read and use. The description is now a sentence such as "Automator for the Body field on the Article Content type" instead of a dotted machine name. The listing name is prefixed with the bundle and a colon (for example "Blog: Content Default"). Old-style stored labels like "Utility page Content Default" are shown as "Utility page: Content Default". The name links to the field's configuration edit form when Field UI is available and the user can administer that entity type's fields. Otherwise it links to the Automator edit form. Consumer name links now open in a new tab.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `AiContextConsumerTypeAutomator`. `getLabelRoute()` loads the Automator and its `field_config` (`{entity_type}.{bundle}.{field_name}`). It returns `entity.field_config.{entity_type}_field_edit_form` only when all of these hold: the `field_ui` module is installed, the entity type declares `field_ui_base_route`, and the current user has `administer {entity_type} fields`. The route parameter name comes from the entity type's `getBundleEntityType()`, with `bundle` as fallback. In every other case it returns `entity.ai_automator.edit_form`. This includes a missing field config or a missing Automator.

`buildInstanceDescription()` resolves the field label from `field_config`, falling back to the field machine name. It resolves the bundle label from bundle info. For the entity type wording it uses the bundle entity type's label (for example "Content type" or "Taxonomy vocabulary"), falling back to the entity type's own label. It returns NULL when the entity type, bundle or field name is empty. `buildInstanceLabel()` matches an existing bundle-label prefix on a word boundary and rewrites it to `Bundle: rest`. A label that merely starts with the same letters, like "Blogging tips" on Blog, still gets the prefix. Loaded Automators and field configs are cached per plugin instance. Each field config is added as a cache dependency of the instance collection, and the listing form adds the `user.permissions` cache context because the link target depends on permissions.

`AiContextConsumersForm` now builds the name link with `AiContextNewTabLinkTrait::buildNewTabLink()`. The description markup is always a `span.ai-description`, and the CSS colour rule moved from `.description-truncate` to `.ai-description`. Docs and the `getLabelRoute()` interface docblock were updated to say implementations may return an accessible fallback route. Kernel and browser tests were added.
