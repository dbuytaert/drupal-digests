# #3586466: Consumer include/exclude config stores context item entity IDs instead of UUIDs

- **Project:** Drupal AI
- **Type:** Major bug report
- **Version:** ersion::v1.0.x-dev
- **Status:** Fixed
- **Discussion:** [#3586466](https://git.drupalcode.org/project/ai_context/-/work_items/3586466) · 1 contributor · 18 comments

## Summary

AI Context consumer "Always include" and "Never include" overrides are now stored as context item UUIDs instead of local numeric entity IDs. Before, exporting config and importing it into another environment could attach the wrong context item, or none, because the numeric IDs differed between databases. The exported `ai_context.consumers.yml` now also lists the referenced items under `dependencies.content` (for example `ai_context_item:ai_context_item:<uuid>`), so config import can use Drupal's missing-content dependency workflow. A post-update converts existing sites, so run database updates and re-export config.

## Impact

Affects site owners.

- **Database update:** Post-update `0008` converts numeric IDs in `ai_context.consumers` to UUIDs and backfills `dependencies.content`.
- **Config change:** `ai_context.consumers` `always_include`/`never_include` now hold context item UUIDs, with a new optional `dependencies.content` key.

## Technical details

Config now stores UUIDs, while runtime selection still works with local entity IDs. `AiContextSelectionFactory` resolves stored identifiers (UUIDs or leftover numeric IDs) to local IDs when building an `AiContextSelection`, and `AiContextSubscriptionBudgetCalculator` does the same. The shared logic is in the `@internal` `AiContextItemIdentifierResolverTrait`. Input order is kept and the first occurrence wins. `AiContextSelector::select()` called directly still accepts UUIDs or numeric IDs. `AiContextConsumerStoredConfig` and `AiContextConsumerResolvedConfig` return the stored values as-is, so callers may see UUIDs or leftover numeric IDs.

`AiContextConsumerForm` saves UUIDs, still recognizes leftover numeric IDs when showing inclusion state (never wins over always, including mixed UUID and numeric entries), and rewrites them to UUIDs on save. On save it computes `dependencies.content` from `getConfigDependencyName()` of the referenced items and merges it into the existing `dependencies` map, so other keys such as `module` survive. An empty list removes only `content`. The previous carry-over of entries for deleted items was removed, so unknown identifiers are no longer dropped on save. The `ai_context.consumers` schema gains an optional `dependencies` key of type `config_dependencies`, and the `always_include` and `never_include` labels now say UUIDs. The `GetRelevantAiContextItems` function call parameter is relabeled "Always include UUIDs" and accepts UUIDs or leftover numeric IDs.

Post-update `ai_context_post_update_0008_convert_consumer_context_item_ids_to_uuids()` converts numeric IDs to UUIDs where the item still exists, deduplicates the lists, and backfills `dependencies.content`. Numeric IDs for items that no longer exist stay in the list. Per the issue, leftover `ai_context.agents` config is not converted and still holds IDs.

## Upgrade

Run database updates (`drush updb`) so post-update `0008` converts stored numeric IDs to UUIDs and adds `dependencies.content`, then re-export config. Custom code that builds `always_include` or `never_include` lists can pass either UUIDs or numeric IDs; numeric IDs remain accepted until the next consumer form save or post-update.
