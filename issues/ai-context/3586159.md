## Summary

Conditional subcontext items now need an AI provider/model configured in AI Context settings. Before, with no provider configured, every conditional child was included in the context, which could inflate token usage unexpectedly. Now those children are skipped. In the item form, the "conditional" option is hidden when no provider/model is set, and a link to the AI Context general settings explains why. Existing conditional items are not converted. They stay conditional but are ignored until a provider/model is configured. The settings page also shows how many published conditional items depend on the provider.

## Impact

Affects site owners.

- **Config change:** Conditional subcontext is only usable when `provider_config` has both `provider_id` and `model_id`; with none configured, conditional children are skipped.

## Technical details

`AiContextSubcontextResolver` now returns an empty candidate list when `provider_config` lacks `provider_id` or `model_id`, where it used to return all candidates. Per the updated docblocks, provider selection failure or an undecodable AI response also skips conditional children. Children listed in the always-include IDs are still included, as the new kernel test `testNoProviderSkipsConditionalChildren` shows.

`AiContextItemForm` gets a private `hasProvider()` check. Without a provider it removes the `conditional` option from the `subcontext_type` widget through `limitConditionalSubcontextOption()`. It keeps the option when the entity is already conditional, so editing doesn't silently turn it into a required item.

`AiContextSettingsForm` now takes `EntityTypeManagerInterface` as an extra constructor argument, wired up in `create()`. It counts published conditional children and puts that in the provider field description. `validateForm()` adds a defensive error, keyed `conditional_subcontext_provider`, if a provider/model is currently saved, the submitted one is empty, and published conditional items exist. The `ai_provider_configuration` element does not currently offer a "no provider" option, so this guards against future element changes or programmatic submissions. Docs and a small CSS spacing rule for the settings form were also updated.
