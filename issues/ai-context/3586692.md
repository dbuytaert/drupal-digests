## Summary

The empty AI Context Items listing at `/admin/config/ai/context/items` now shows "There are no AI Context Items yet. Add one." with a working link to the add form. Before, it showed core's text without the link. The link appears only for users who can create context items, and it works on sites installed in a subdirectory.

## Impact

No upgrade or configuration changes required.

## Technical details

`AiContextItemListBuilder::render()` set `$build['#empty']`, but core's `EntityListBuilder::render()` only renders empty text from `$build['table']['#empty']`. The text was never shown and core's default appeared instead. It now sets `$build['table']['#empty']`.

The link is built with `Url::fromRoute('entity.ai_context_item.add_form')` instead of the raw `getLinkTemplate('add-form')`, so it includes the base path. It is output only when `$url->access($this->currentUser, TRUE)` is allowed. Otherwise the plain text is shown. The access result and the generated URL are added to the table's cacheability.

`AiContextUsageListBuilder::render()` had the same mistake and now sets `$build['table']['#empty']`. The issue notes that no route uses this list builder today. A new kernel test, `AiContextItemListBuilderEmptyTest`, covers the creator, viewer and usage listing cases.
