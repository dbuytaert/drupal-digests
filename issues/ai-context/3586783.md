## Summary

Uninstalling AI Context (CCC) used to delete every role whose only CCC-related permission was `translate ai_context_item`, together with all its other permissions and its assignment to users. It could also log "Non-existent permission(s)" errors and leave stale workflow and Scheduler permissions on roles. Uninstall now strips these permissions from all roles first, so no role is deleted, the roles keep their unrelated permissions, and no error is logged.

## Impact

No upgrade or configuration changes required.

## Technical details

Cause: `ModuleInstaller::uninstall()` removes the `ai_context_item` bundle before the config cleanup runs, so content_translation no longer defines `translate ai_context_item`. `Role::onDependencyRemoval()` cannot remove an undefined permission, so core deleted roles that depended on `ai_context` only through it. The old `hook_uninstall()` also deleted `workflows.workflow.ai_context_editorial` as raw config, so roles depending on the workflow were not updated.

The fix adds `_ai_context_uninstall_revoke_permissions()` in `ai_context.install`, called first in `ai_context_uninstall()`. It loads all roles with `loadMultipleOverrideFree()` and removes `translate ai_context_item`, `schedule publishing of ai_context_item`, `view scheduled ai_context_item` and every `use ai_context_editorial transition *` permission. It reads the stored `permissions` value rather than `Role::getPermissions()`, because the latter is empty for admin roles, so admin roles are cleaned too. The workflow is then deleted with `Workflow::load(...)?->delete()` instead of deleting raw config, so core updates config that depends on it. A new "hook_uninstall()" section in the module docs describes this. Kernel tests cover roles with only or with additional permissions, admin roles, a removed transition, a logger check for warnings, and a workflow without the enforced dependency.
