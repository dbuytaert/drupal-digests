## Summary

Opening the AI agent form and selecting a Tool module tool that has a map input with no declared properties no longer crashes with a PHP `TypeError`. The crash appeared after the Tool serializer began emitting empty schema objects as `\ArrayObject` ([#3582972](https://www.drupal.org/node/3582972)). The fix is in the `tool_ai_connector` submodule.

## Impact

No upgrade or configuration changes required.

## Technical details

`SchemaToolsPropertyConverter::convert()` passed the serialized schema straight to the AI module's `ToolsPropertyInput`. Its constructor routes properties through `setProperties(array ...)`, which is strictly typed, so any `\ArrayObject` in the schema triggered the `TypeError`. The converter's own `is_array()` check on `properties` was also FALSE for an `\ArrayObject`, so recursion skipped those values.

`convert()` now starts by calling a new protected helper, `arrayObjectsToArrays()`. It walks the schema recursively and replaces every `\ArrayObject` with its `getArrayCopy()`, at any nesting depth. The `{}` versus `[]` distinction only matters at JSON-encoding time, and `ToolsPropertyInput` does its own rendering, so plain arrays lose nothing. `testConvertsArrayObjectSchemaValues` in `SchemaToolsPropertyConverterTest` covers a top-level empty `properties` and a nested empty map.
