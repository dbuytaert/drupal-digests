## Summary

Tools can now take and return config entities, such as user roles, through invokers that ask for entity handles, for example an MCP server or the AI connector. Before, the input schema had no type, so a model didn't know what to send. Sending a machine name failed validation. Config entity outputs came out as empty objects. Now these entities cross the boundary as their machine name (for example `editor`) and the schema says `string`. An unknown machine name fails the input with a clear error. Content entities still use handles, and invokers without `EntitiesAsHandles` see no change.

## Impact

Affects module maintainers.

- **New API:** `EntityHandleTransformer` gains public `isConfigEntityDefinition()`, `resolveConfigInput()` and `transformConfigOutput()`. New `MachineNameNotFoundException` implements `HandleExceptionInterface`.

## Technical details

When the invoker has `InvokerCapability::EntitiesAsHandles`, `EntityHandleTransformer::isConfigEntityDefinition()` detects an `entity:TYPE` definition whose entity class implements `ConfigEntityInterface`. `transformInputDefinition()` and `transformOutputDefinition()` turn it into a `string` definition, with "(pass the machine name of the TYPE)" appended to the description for inputs. The bare `entity` data type is not covered, because the entity type is needed to load by ID.

On input, `EntityHandleTransformSubscriber` checks for a config entity definition before the content entity case. It calls `resolveConfigInput()`, which loads the entity through the type's storage. Non-string values pass through untouched. On output, `transformConfigOutput()` replaces a config entity with its ID and a hint. The batch path handles lists, either `isMultiple()` outputs or `ListOutputDefinition` items. It replaces each config entity with its ID and adds one hint per list, such as "Output `roles` contains 2 user_role machine name(s)".

An unknown machine name throws the new `Drupal\tool\Handle\MachineNameNotFoundException`. It is `final`, extends `\RuntimeException` and implements `HandleExceptionInterface`. It is separate from `HandleNotFoundException`, so a wrong value does not get the advice about handle expiry and ownership. The input violation names the input property. The commit adds a `config_entity_tool` test tool in `tool_test` and updates the handle docs.

## Upgrade

Code that catches `HandleExceptionInterface` already covers the new `MachineNameNotFoundException`. Code that catches `HandleNotFoundException` specifically will not see unknown machine names, and needs to catch the new class or the interface.
