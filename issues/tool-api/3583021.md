# #3583021: Remove the ai_tools_property_alter hook implementation superseded by the schema property converter

- **Project:** Drupal AI
- **Type:** Normal unknown (0)
- **Status:** Fixed

## Summary

The `tool_ai_connector` module's `hook_ai_tools_property_alter()` implementation has been removed, along with its service registration. This hook used to expand one level of map properties onto a tool's advertised schema, but it only ever fired on a code path that the tool module's bridge no longer uses: the bridge builds its schema properties directly from the tool's JSON Schema output, which already covers nested maps, list inputs, and constraint-derived keywords that the old hook never handled. For sites and modules using the supported bridge (`ToolPluginBase::normalize()`), nothing changes; schemas are generated the same way they already were.

## Impact

Affects module maintainers.

- **API change:** Removed `Drupal\tool_ai_connector\Hook\AiToolsPropertyHooks` (the `hook_ai_tools_property_alter()` implementation) and its service registration; no replacement is needed on the supported bridge path.

## Technical details

The hook (`AiToolsPropertyHooks::aiToolsPropertyAlter()`), its `#[Hook('ai_tools_property_alter')]` attribute, the legacy procedural bridge function in `tool_ai_connector.module`, and the service registration in `tool_ai_connector.services.yml` were all deleted. The hook only fired when a `MapDataDefinition`-backed property was normalized via the `ai` module's default `FunctionCallBase::normalize()`, which routes through `Utility\ContextDefinitionNormalizer`. The tool bridge's own `ToolPluginBase::normalize()` overrides that method and instead builds properties from the tool's emitted JSON Schema via `SchemaToolsPropertyConverter`, so for every tool-bridged function call, the hook's `instanceof MapContextDefinition` branch was dead code. Removing it also clears a straggler reference to `MapContextDefinition`, a class slated for deprecation and removal in the context-system detach plan tracked in [#3583016](https://www.drupal.org/node/3583016).

Coverage for the removal landed as a new kernel test, `MapListAdvertisementTest`, which asserts the bridge advertises complete schemas without the hook: a map input with nested maps produces `object` schemas with properties at every depth, a multiple-value input advertises an `array` with an `items` schema, and a free-form map (no declared properties) advertises a plain `object` rather than an empty or untyped schema.</technical>
<parameter name="upgrade">A third-party function-call plugin that routed tool definition objects through `ai.context_definition_normalizer` directly (rather than through the tool bridge's `normalize()`) loses the one-level map expansion the removed hook provided.
