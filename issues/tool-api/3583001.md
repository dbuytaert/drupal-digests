## Summary

Tool inputs now accept more of the value spellings LLM clients commonly send. Datetimes with fractional seconds, such as the `2026-11-14T09:32:00.500Z` that JavaScript's `toISOString()` emits, are converted to the declared storage format. Previously they passed through unconverted and were then rejected. Space-separated datetimes that carry an offset also convert. Booleans sent for integer inputs become 1 or 0. Bare numbers sent for string inputs become strings. Integral floats `0.0` and `1.0` become booleans. A new test suite pins the exact JSON Schema each input shape emits, and checks that values generated from a tool's advertised schema are accepted by the tool. Two bugs the suite found, involving `Count` constraints on multiple inputs and optional entity properties in maps, were left for separate issues.

## Technical details

`InputTypeCoercionSubscriber` gains these coercions. `DATETIME_INPUT_FORMATS` now includes `Y-m-d\TH:i:s.uP`, `Y-m-d H:i:sP` and `Y-m-d H:i:sO`. Every accepted datetime format still carries a timezone, and sub-second precision is truncated because the storage format cannot hold it. Datetimes without an offset are still left untouched. For `integer` targets, booleans map to 1 or 0. For `string` targets, ints and floats become their string spelling (floats via `formatDecimalString()`, which avoids exponent notation). Booleans are left for validation on string targets. For `boolean` targets, `0.0` and `1.0` now convert alongside `0` and `1`.

On the legacy (pre-11.1) schema path, `ContextDefinitionNormalizer` now emits an empty, unconstrained schema for the `any` data type. Before, it fell back to advertising `type: string`, which falsely excluded other JSON values. Core's own normalizers on 11.1+ already emit an untyped schema.

The module now registers `IdenticalTo` and `PositiveOrZero` as constraint plugins, so inputs declaring them work on Drupal 10, where core does not provide them. `PositiveOrZeroConstraint` unpacks an options array for cores without named-argument support. The `GreaterThan` docblock was updated to match.

Tests live under `tests/src/Kernel/Matrix/`: `InputSchemaMatrixTest`, `InputCoercionMatrixTest`, `AdvertisedSchemaAcceptanceTest` and `TransformSubscriberInteractionTest`. They use a new `SchemaMatrixTool` fixture in `tool_test` with 26 inputs. `TransformSubscriberInteractionTest` pins the subscriber priority order: invoker 100, then coercion 50, then recursive dispatch -100. It also pins that `stopPropagation()` in the invoker slot silently disables coercion, and that child dispatches carry the item-level definition. `AdvertisedSchemaAcceptanceTest` skips `labels` on `comprehensive_types_tool` and the omitted optional entity property case, behind `@todo` markers. It also skips `complex_entity_event_tool`. The old `InputTypeCoercionTest` is kept for now and is planned for deletion after previous-major CI validates the matrix suite.

## Upgrade

Code that builds on the Tool module can reuse `SchemaSampleGeneratorTrait` from its own kernel tests to generate values from a tool's advertised schema. The issue says the trait is meant to be reusable by tool_belt and the MCP bridge.
