# #3583036: Add --format=json to tool:list and tool:search

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed
- **Discussion:** [#3583036](https://git.drupalcode.org/project/tool/-/work_items/3583036) · 1 contributor · 7 comments

## Summary

The Tool module's `drush tool:list` and `drush tool:search` commands now support `--format=json`, in addition to the existing `table` and `markdown` formats. Previously these commands only produced a table (which truncates descriptions at 60 characters) or interleaved markdown, neither of which round-trips cleanly through `jq` or a JSON decoder. This matters for automated agents that discover tools via `tool:list`/`tool:search` and then inspect one with `tool:info --format=json`: they can now stay in JSON the whole way through instead of scraping rendered text.

## Impact

Affects module maintainers.

- **New API:** `tool:list` and `tool:search` Drush commands accept `--format=json`, emitting a JSON array of tool summaries (or `[]` when empty).

## Technical details

The change introduces `ToolOutputTrait::buildToolSummary()`, a single private method that builds the per-tool fields (`id`, `label`, `description`, `operation`, `destructive`, `provider`, `requirements`) shared by `tool:info`, `tool:list`, and `tool:search`. `ToolInfoCommand::outputInfoAsJson()` now calls this shared builder and appends its `inputs`/`outputs`/schema fields on top, while a new `ToolOutputTrait::outputToolsAsJson()` maps the builder over the filtered definitions for `tool:list` and `tool:search` and writes the array with `Json::encode()`. This keeps the three commands' JSON field names from drifting apart since only one place declares them.

Both commands special-case `--format=json` before their existing "no tools found" checks, so an empty result set still prints the JSON document `[]` and exits 0, rather than the prose message used by the table and markdown formats. Neither command prints its usual trailing summary line (`Total tools: N` or `Found N tool(s) matching: ...`) in JSON mode, keeping the output a single parseable document; consumers get the count from the array length. The `requirements` field mirrors the `RequirementStatus::forTool()` work from [#3583025](https://www.drupal.org/node/3583025), and `--operation`/`--unmet` filtering apply to the JSON output exactly as they do to the table.
