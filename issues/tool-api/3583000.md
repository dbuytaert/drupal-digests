## Summary

Tools that take a `datetime_iso8601` input could not set a Drupal `datetime` field. Coercion re-emitted every value with a UTC offset, which Drupal's offset-less storage format rejects. Inputs that declare a `DateTime` or `DateOnly` constraint are now converted to the storage format the field uses. An offset datetime such as `2026-11-14T09:32:00-07:00` is stored as `2026-11-14T16:32:00`. Inputs with no such constraint are unchanged. The merged behavior is stricter than the issue proposed: a bare date given to a datetime target is not coerced and fails validation.

## Impact

No upgrade or configuration changes required.

## Technical details

The change is in `InputTypeCoercionSubscriber`, in the `datetime_iso8601` branch. It checks the definition's constraints for `DateOnly` and `DateTime`.

With neither marker, behavior is as before. A bare `Y-m-d` value passes through, and any other parseable string is re-emitted with `format('c')`.

With a marker, the input is parsed by the new `parseDeclaredDateTime()`. It uses `DateTimeImmutable::createFromFormat()` against an allowlist and rejects any parse that produced errors or warnings. For `DateTime`, the allowlist is `RFC3339` and `ISO8601`, both of which carry an offset. The result is converted to UTC and emitted as `Y-m-d\TH:i:s`. For `DateOnly`, only `Y-m-d` is accepted, and the date is emitted without any timezone conversion.

Anything that does not match the allowlist is left untouched, so the target's constraints report it. That covers an offset-less `2026-11-14T09:32:00`, a bare date for a `DateTime` target, a time component on a `DateOnly` target, `tomorrow`, and whitespace. This differs from the issue's proposal, which read offset-less input as UTC and gave a bare date midnight. The merged code avoids guessing a timezone and avoids PHP reading `''` or whitespace as "now". The three storage constants (`STORAGE_TIMEZONE`, `DATETIME_STORAGE_FORMAT`, `DATE_STORAGE_FORMAT`) are private and duplicated locally, so `tool` does not depend on the optional `datetime` module.

`CoercionTestTool` gains `starts_on` (`DateOnly`) and `occurs_at` (`DateTime`) inputs and outputs, and `InputTypeCoercionTest` gains cases covering both markers.

## Upgrade

Callers that targeted a `DateTime` input with an offset-less value or a bare date should send RFC 3339 with an offset, for example `2026-11-14T09:32:00-07:00`. Callers targeting a `DateOnly` input should send a plain `Y-m-d` value. Values in any other shape are no longer rewritten and fail validation.
