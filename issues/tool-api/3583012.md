# #3583012: Ship a use-drupal-tools agent skill so agents discover, inspect, and run Tool operations

- **Project:** Drupal AI
- **Type:** Normal feature request
- **Status:** Fixed

## Summary

Tool now ships a ready-made Agent Skill file that teaches AI coding agents how to find, inspect, and run its operations. Previously, every module that consumes Tool and ships its own Agent Skill (like `canvas_tools`) had to restate the same mechanics: how to search for an operation, read its input contract, and call it via `drush tool:run`. Those hand-written explanations drift whenever an input is renamed. With this skill in place, agents load a single, maintained procedure straight from the module, and downstream modules can shrink their own skills to their domain-specific steps while pointing back at this one for the underlying Tool mechanics.

## Impact

Affects module maintainers.

- **New API:** Module now ships `.agents/skills/use-drupal-tools/SKILL.md`, a procedural Agent Skill (per the Agent Skills specification) documenting the `tool:search`, `tool:list`, `tool:info`, and `tool:run` Drush commands for AI coding agents.

## Technical details

The change adds `.agents/skills/use-drupal-tools/SKILL.md`, following the Agent Skills specification (a `SKILL.md` with frontmatter `name`/`description` that an agent loads on demand). It documents the four-step workflow: search or list operations with `tool:search`/`tool:list --format=json` and filter by `operation` kind (`read`/`explain`/`transform` are non-mutating, `write`/`trigger` are); inspect an operation's `input_schema`/`inputs`/`output_schema` with `tool:info --format=json` rather than copying inputs from an example; run it with `tool:run --input=... --json` and branch on the `{success, message, outputs}`/`{success, error, error_type}` shape; and always pass `--uid` so `checkAccess()` runs as the real caller instead of anonymous or uid 1. It also documents that the same plugin id is exposed as an MCP tool name via `mcp_server_tool_bridge` (`mcp_tool_config` entities) and as a function name in `tool_ai_connector`, and lists several open bugs agents need to work around (e.g. silent dropping of malformed `--input`, exit code 0 on not-found lookups, and access denials that don't surface a reason).

Alongside the skill file, `docs/usage/agent-skills.md` and a `README.md` section explain how the skill reaches a project: `drupal/ai_best_practices` syncs `.agents/skills/` from installed modules into the project root on `composer install`, or it can be copied/symlinked manually. The commit also formalizes an existing `create-tool-plugins` skill (scaffolding a `#[Tool]` plugin) alongside the new one and adds both to the `mkdocs.yml` navigation.
