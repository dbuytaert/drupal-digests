## Summary

Validating a map input that leaves out an optional entity property no longer crashes. Before, a value like `['metadata' => ['label' => 'sample']]` caused a fatal `Call to a member function isNew() on null`. This happened in `validateInputs()`, `execute()` and invoker failure paths, even though the value was valid for the advertised schema. Such values now validate cleanly with zero violations. A required property that is missing from a map now produces a violation.

## Impact

No upgrade or configuration changes required.

## Technical details

The cause was core's recursive typed-data validation. It instantiated every declared map property, including absent ones, and the empty `EntityAdapter` reached core's `EntityUntranslatableFieldsConstraintValidator`, which dereferences a NULL entity. The issue also proposes a core follow-up to make that validator return early. The tool-side guard does not wait for it.

In `TypedInputsTrait::validateInputValue()`, a `MapContextDefinition` with declared property definitions and an array value is no longer passed to `Context::validate()`. Instead each declared property is checked in turn. An absent property is skipped, treated as "not touched". If the absent property is required, a `ConstraintViolation` reading "The @label property is required." is added. Present properties recurse through `validateInputValue()` and their violations are added with the `property` prefix. Previously only list-shaped properties recursed.

Maps with no declared properties, and other definition types, still use the `Context` path, including the prototype-cache reset workaround and the "must be an entity" check. That check now also matches data types starting with `entity:`. Map properties are now only type-checked per property rather than run through core's full entity constraint traversal.

The `@todo` sample override for `comprehensive_types_tool.metadata` was removed from `AdvertisedSchemaAcceptanceTest`. A new `MapOptionalEntityValidationTest` covers the omitted-optional case and checks that a missing required top-level entity input still produces a violation.
