## Summary

The Tool module drops two backward-compatibility shims before 1.0.0-rc1. The old `ContextDefinitionNormalizer` class and its `tool.normalizer.context_definition` service ID are gone, and so is the old `hook_data_type_adapter_info_alter()` hook for altering typed data adapters. Custom or contrib code still using the old names will break and must switch to the new ones.

## Impact

Affects module maintainers.

- **API change:** Removed `Drupal\tool\Normalizer\ContextDefinitionNormalizer`, the `tool.normalizer.context_definition` service alias, and support for `hook_data_type_adapter_info_alter()`.
- **Deprecation:** Completes the removal of shims deprecated in tool 1.0.0-beta4 (adapter alter hook) and 1.0.0-beta12 (normalizer name), as scheduled for rc1.

## Technical details

The deleted `ContextDefinitionNormalizer` was an empty subclass of `InputOutputDefinitionNormalizer` that only triggered a deprecation. Its deprecated alias in `tool.services.yml` and `ContextDefinitionNormalizerDeprecationTest` are removed with it.

In `TypedDataAdapterManager`, the `alterDefinitions()` override is deleted. It fired the legacy `data_type_adapter_info` alter hook before delegating to the parent. The constructor's `alterInfo('tool_typed_data_adapter_info')` already runs `hook_tool_typed_data_adapter_info_alter()`, so the new hook is unaffected. Per the issue, `Drupal\ai\Utility\ContextDefinitionNormalizer` from the ai module is a different class and is not touched.

## Upgrade

Replace references to the old normalizer and rename the alter hook implementation:

```php
// Before
\Drupal\tool\Normalizer\ContextDefinitionNormalizer
// service: tool.normalizer.context_definition

// After
\Drupal\tool\Normalizer\InputOutputDefinitionNormalizer
// service: tool.normalizer.input_output_definition
```

Rename `hook_data_type_adapter_info_alter()` implementations to `hook_tool_typed_data_adapter_info_alter()`.
