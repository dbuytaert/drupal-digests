## Summary

Before the rc1 freeze, the Tool module removes interfaces that only described `final` classes or had a single implementation. Code that type-hints, implements or checks `instanceof` against any removed interface must switch to the concrete class. Tool result getters now return the concrete result classes. The interfaces were removed outright, without a deprecation period. The deprecated `ExecutableResultInterface` shell is also gone, so tools no longer pass `instanceof ExecutableResultInterface` checks.

## Impact

Affects module maintainers.

- **API change:** Removed `ToolResultInterface`, `FormattedToolResultInterface`, `TypedInputsDefinitionInterface`, `TypedOutputsDefinitionInterface`, `TextInterface`, `ToolContextDefinitionInterface` and the deprecated `ExecutableResultInterface`. `getResult()` and `getFormattedResult()` now return `ExecutableResult` and `FormattedExecutableResult`.

## Technical details

`ExecutableResult` and `FormattedExecutableResult` now implement core's `CacheableDependencyInterface` directly. The methods that used to come from `ToolResultInterface` and `FormattedToolResultInterface` keep their docblocks on the classes. `ToolDefinition` no longer implements `TypedInputsDefinitionInterface` or `TypedOutputsDefinitionInterface`, and its methods carry their own docs. The `assert()` calls in `TypedInputsTrait` and `TypedOutputsTrait` now check `ToolDefinition`. `TextData` no longer implements the empty `TextInterface` marker.

`ToolInterface` no longer extends `ExecutableResultInterface`, so the matching phpstan suppression was removed from `phpstan.neon`. `ToolInterface::getResult()` and `ToolInvocation::getResult()` return `ExecutableResult`. `ToolInterface::getFormattedResult()` and `ToolInvocation::getFormattedResult()` return `FormattedExecutableResult`. Existing `ToolBase` subclasses still work because a subclass may return a narrower type.

In `tool_ai_connector`, `ToolContextDefinitionInterface` is removed. Its `getToolDefinition()` and `toToolDefinition()` methods now live only on `ToolContextDefinitionTrait`, which is used by the `final` classes `ToolContextDefinition` and `ToolEntityContextDefinition`. `ToolContextDefinition::fromToolDefinition()` returns `ToolContextDefinition|ToolEntityContextDefinition`. The override check in `ToolPluginBase::applyContextDefinitionOverridesToInputSchema()` tests both classes.

## Upgrade

Replace the removed types with the concrete classes:

```php
// Before.
function f(ToolResultInterface $result) {}
// After.
function f(ExecutableResult $result) {}

// Callers that accept either result type use a union.
function g(ExecutableResult|FormattedExecutableResult $result) {}
```

Use `FormattedExecutableResult` instead of `FormattedToolResultInterface`. Use `ToolDefinition` instead of `TypedInputsDefinitionInterface` or `TypedOutputsDefinitionInterface`. Use `ToolContextDefinition|ToolEntityContextDefinition` instead of `ToolContextDefinitionInterface`. Drop any `TextInterface` references. Code that type-hinted `ToolResultInterface` because of the old `ExecutableResultInterface` deprecation notice should switch to `ExecutableResult`.
