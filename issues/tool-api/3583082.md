# #3583082: Provide shared plain-text formatters for violation lists and access denials

## Summary

Tool API now ships two shared helpers for the plain-text messages an invoker shows a caller: one for input validation failures and one for access denials. Drush, the AI connector and the MCP bridge each had their own copy, and the copies had drifted. The AI connector, for one, still leaked the typed-data root prefix into failure text. Invoker authors can call the helpers and get the same message shape everywhere.

## Impact

Affects module maintainers.

- **New API:** New final class `Drupal\tool\ToolMessages` with static `violationList()` and `denialReason()` helpers.

## Technical details

The commit I read adds `src/ToolMessages.php`, a `final` class with two static methods. `ToolMessages::violationList(ConstraintViolationListInterface $violations): string` renders each violation's `getMessage()` through `PlainTextOutput::renderFromHtml()` and joins the results with `"\n"`. It never uses the list's `__toString()`, so the `Object(...):` or bare leading colon root prefix does not appear. `ToolMessages::denialReason(AccessResultInterface $access): string` returns the reason from an `AccessResultReasonInterface` as plain text, or `Access denied.` when no reason is attached. The class is static so invokers can use it without injection. In this repo, `ToolRunner` already calls both helpers when building the invalid input and denial messages. Kernel tests were added in `ToolMessagesTest` and `TypedInputsValidationTest`. The issue also lists conversions of drush `ToolRunCommand`, `tool_ai_connector` and `mcp_server_tool_bridge`. I did not see those in this commit, and the bridge conversion was planned to land on the bridge side.

## Upgrade

Invokers that build their own failure text can switch to the helpers, for example `ToolMessages::violationList($violations)` in place of `(string) $violations`, and `ToolMessages::denialReason($access)` in place of a custom denial formatter.
