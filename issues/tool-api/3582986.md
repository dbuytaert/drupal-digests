## Summary

The Tool module's base plugin class now always has a logger channel, and the logger can no longer be left out. Tool plugins that declare their own `$logger` property must give it the exact type the base class uses, or PHP throws a fatal error. Code that builds tools directly without the container must now pass a logger.

## Impact

Affects module maintainers.

- **API change:** `ToolBase::__construct()` now requires a non-nullable `LoggerChannelInterface $logger` (previously `?LoggerChannelInterface $logger = NULL`); subclasses redeclaring `$logger` must use exactly that type.

## Technical details

[#3582971](https://www.drupal.org/node/3582971) added a promoted `$logger` constructor property to `ToolBase`, typed `?LoggerChannelInterface`. `ToolBase::__construct()` is `final`, so subclasses inject their own services by declaring a property and overriding `create()`. `$logger` is the usual name for that property. A subclass declaring it with a different type, such as `LoggerInterface`, causes a compile-time property type mismatch fatal.

The fix keeps the `$logger` name and makes it `protected LoggerChannelInterface $logger`, required and non-nullable. The issue says `create()` always supplies the `logger.channel.tool` channel, so the nullability had no justification. The `NULL` guard around `Error::logException($this->logger, $e)` in `execute()` is removed. The constructor docblock now states the contract: subclasses redeclaring the property must use the exact type `LoggerChannelInterface`. Per the issue, a subclass `create()` may still assign its own channel over the parent's.

The issue also describes companion changes in tool_belt: `LogMessage` drops its own property and `create()` override, and `WorkspaceCreateAndSwitch` needs no change. Those are not in this commit's diff.

## Upgrade

If a tool plugin redeclares `$logger`, the type must be exactly `LoggerChannelInterface`:

```php
protected LoggerChannelInterface $logger;
```

Code that instantiates a tool without `create()` must now pass a logger as the sixth constructor argument. Tools that only wanted the `tool` channel can drop their own property and `create()` override, because the parent injects it.
