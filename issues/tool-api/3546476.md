## Summary

The Tool module's AI connector now describes map-type tool inputs (`MapContextDefinition`) to AI providers as objects with nested properties, instead of leaving them unhandled. This is only a partial fix. `ListContextDefinition` is not yet handled, and the author noted it will probably need similar treatment.

## Impact

Affects module maintainers.

- **API change:** `MapContextDefinition::getValueDefinition()` renamed to `getValueDefinitions()`.
- **New API:** `tool_ai_connector` now implements `hook_ai_tools_property_alter` to expose `MapContextDefinition` inputs to AI chat tools.

## Technical details

A new `Drupal\tool_ai_connector\Hook\AiToolsPropertyAlter` class uses the `#[Hook('ai_tools_property_alter')]` attribute. When the context definition is a `MapContextDefinition`, it normalizes the nested value definitions with the `ai.context_definition_normalizer` service. It then calls `setType('object')` and `setProperties()` on the `ToolsPropertyInputInterface` property. To support this, the accessor on `MapContextDefinition` was renamed from `getValueDefinition()` to `getValueDefinitions()`. The commit's `getValueDefinitions()` still returns the `value_definitions` array.

## Upgrade

Any custom code calling the old accessor must switch to the new name:

```php
// Before
$definition->getValueDefinition();
// After
$definition->getValueDefinitions();
```
