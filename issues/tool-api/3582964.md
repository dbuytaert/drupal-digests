## Summary

The Tool module reworked its execution contract before the RC1 freeze. Tool plugins are no longer treated as core "executables", which avoids a future fatal error when core changes the signature of its `execute()` method. Result objects now have interfaces, so code can type against those interfaces instead of final classes. Code that type-hints the old `ExecutableResultInterface`, or checks tools with `instanceof` against core's `ExecutableInterface`, should be updated.

## Impact

Affects module maintainers.

- **API change:** `ToolInterface` no longer extends core's `Drupal\Core\Executable\ExecutableInterface`, declares `execute(): static` and the result accessors itself, and `getResult()`/`getFormattedResult()` now return `ToolResultInterface`/`FormattedToolResultInterface`.
- **Deprecation:** `Drupal\tool\ExecutableResultInterface` is now an empty shell, deprecated in tool:1.0.0-beta4 and removed in tool:1.0.0-rc1.
- **New API:** New `Drupal\tool\ToolResultInterface` and `Drupal\tool\FormattedToolResultInterface` value interfaces, implemented by `ExecutableResult` and `FormattedExecutableResult`.

## Technical details

Core's `ExecutableInterface::execute()` is declared with a commented-out `?object $object = NULL` parameter that becomes real in the next major. `ToolBase::execute(): static` takes no parameter, so every tool plugin would have fataled when core made the change. The parameter's meaning (execute against a subject object) also doesn't fit tools, which take typed inputs. `ToolInterface` now declares `execute(): static`, `getResult()`, `getResultStatus()` and `getResultMessage()` itself. It no longer inherits from core's `ExecutableInterface`.

`ToolResultInterface` has `isSuccess()`, `getMessage()` and `getContextValues()`. `FormattedToolResultInterface` extends it with `getHints()` and `getOriginalResult()`. The final readonly classes `ExecutableResult` and `FormattedExecutableResult` implement them, and `ToolInterface::getResult()` and `getFormattedResult()` are now typed against the interfaces. This is option (a) from the issue, so results can be decorated or mocked.

`ExecutableResultInterface` is kept as an empty deprecated shell and `ToolInterface` still extends it, so `instanceof ExecutableResultInterface` keeps working for one beta cycle. A `phpstan.neon` ignore for `interface.extendsDeprecatedInterface` covers this. A new kernel test, `testExecutionContractShape`, asserts that tools are no longer `ExecutableInterface` instances and that results implement the new interfaces.

## Upgrade

Replace type hints and checks as follows:

```php
// Before
use Drupal\tool\ExecutableResultInterface;
// After
use Drupal\tool\Tool\ToolInterface;       // for tools
use Drupal\tool\ToolResultInterface;      // for result values
use Drupal\tool\FormattedToolResultInterface; // for formatted results
```

Any code relying on tools being `\Drupal\Core\Executable\ExecutableInterface` instances must stop doing so. Call `$tool->execute()` directly, as invokers already do.
