## Summary

Tool inputs defined as multiple now have every item validated, not just the first. Previously an invalid value in position 2 or later (for example `[1, 'not a number']` on an integer input) passed validation and the tool executed with it. This matters most where values come from an AI connector. An empty array on a required multiple input is still accepted, and that behavior is now pinned by a test.

## Impact

Affects site owners.

- **Security:** Validation bypass: only the first item of a multiple-value tool input was validated, so invalid later items reached `doExecute()`.

## Technical details

In `TypedInputsTrait::validateInputValue()`, the multiple-value branch had a `return` inside the `foreach`, so only the first item's violations were returned. The fix clones the definition once, calls `setMultiple(FALSE)` on the clone, and merges each item's result into `$violations` with `addAll()`. The method returns the accumulated list after the loop. Each violation keeps its own invalid value.

The issue also asked what to do with an empty array on a required multiple input. The commit keeps the existing behavior: no violations. A test comment says `required` checks that a value is present, and a minimum item count needs an explicit `Count` constraint. A new kernel test, `TypedInputsValidationTest`, covers a multi-item failure (two violations from three items), an all-valid pass, and the empty-array case. It follows [#3553721](https://www.drupal.org/node/3553721), which was closed but did not fully fix this.
