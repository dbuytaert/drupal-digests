# #3583047: tool:run --json prints an entity output as its full field array, including the password hash

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583047](https://git.drupalcode.org/project/tool/-/work_items/3583047) · 1 contributor · 9 comments

## Summary

The `tool:run` Drush command could print an entity output's entire field array, in both JSON and plain text mode. For a user entity this included `pass`, the hashed password, which could end up visible in a terminal, a log, or an AI agent's transcript. The command now prints entities only as a small reference (entity type, ID, UUID, and label) instead of dumping their fields, so no field data, secret or otherwise, leaks through `tool:run` output.

## Impact

Affects site owners.

- **Security:** Fixed exposure of entity field values, including a user's password hash, in `drush tool:run` output (both `--json` and text modes).

## Technical details

The fix adds a `referenceEntities()` helper to `ToolOutputTrait`, used from both `ToolRunCommand::serializeOutputs()` (the `--json` path) and `ToolOutputTrait::formatOutputValue()` (the plain-text path). Any value that is an `EntityInterface` is replaced with an array of `entity_type`, `id`, `uuid`, and `label` (taken from the entity's own `label()`, so no direct field access happens); arrays are walked recursively so a `multiple` entity output has each item replaced too. This closes a gap left by [#3583035](https://www.drupal.org/node/3583035), which switched `ToolRunCommand` to `getFormattedResult()->getContextValues()` but only replaces entities with handles for invokers that declare `InvokerCapability::EntitiesAsHandles`; `DrushInvoker` declares none, so the formatted result still held the raw entity object, and the previous `toArray()`/`get_class()` fallbacks either dumped every field or leaked nothing useful.

The change is deliberately scoped to the reference shape described in the issue rather than waiting for real CLI entity handles (tracked separately in [#3582977](https://www.drupal.org/node/3582977)), which will eventually replace this reference representation. Test coverage is a new `account_output_tool` test plugin returning a user both as a single output and as a `multiple` output, with a kernel test asserting the password hash and the `pass` key never appear in either output mode.
