# #3583035: tool:run sends the PHP output values, not the formatted result

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583035](https://git.drupalcode.org/project/tool/-/work_items/3583035) · 1 contributor · 10 comments

## Summary

The `tool:run` Drush command (used to invoke and inspect Tool module plugins from the command line) was sending raw PHP values instead of the values formatted according to each output's advertised schema. This meant, for example, that a timestamp output showed up as a raw Unix integer (`1785606907`) instead of the documented `date-time` string, and an empty map printed its internal `\ArrayObject` class name instead of `{}`. The MCP bridge already did this correctly; `tool:run` was the last in-tree caller reading unformatted values. The command now sends the same formatted output that other invokers, like the MCP bridge, produce.

## Impact

Affects module maintainers.

- **API change:** `ToolRunCommand` now emits the formatted output values (matching each output's advertised schema) instead of the tool's raw PHP values; an empty map now serializes as `{}` instead of an `\ArrayObject` class name.

## Technical details

`ToolRunCommand::runTool()` previously called `$tool->getOutputValues()` (guarded by a success check, since output contexts are unset on failure and `getOutputValues()` throws otherwise) to build the outputs array. It now calls `$tool->getFormattedResult()->getContextValues()` unconditionally: a failed tool simply carries no output values, so the success guard is removed. `getFormattedResult()` applies the transform pipeline added in the related timestamp/decimal/datetime coercion work ([#3583030](https://www.drupal.org/node/3583030)), turning entities into handles and spelling timestamps, decimals, and dates the way the schema's `date-time` etc. types describe.

`ToolOutputTrait::formatValue()` and `ToolRunCommand::serializeOutputs()` were both updated to special-case `\ArrayObject` (used to represent an empty map) so it serializes as `{}` in both the JSON and human-readable text output paths, rather than falling through to `is_object()` handling that printed the class name.

Docblocks were added to `TypedOutputsInterface::getOutputValue()` and `getOutputValues()` clarifying that these return the tool's raw PHP values (for the tool itself and its tests), and that anything leaving the process should read `getFormattedResult()` instead. The issue also raised whether to rename these to something like `getRawOutputValues()`/`getFormattedOutputValues()` to make the distinction harder to get wrong, but that rename was deferred as a pre-1.0 API decision; only the docblock clarification landed here.

## Upgrade

If code or scripts invoke `drush tool:run --json` and parse specific output fields, expect formatted values rather than raw PHP values, for example:

```
# Before: raw Unix timestamp
"date": 1785606907

# After: formatted per the output's date-time schema
"date": "2026-08-01T17:55:07+00:00"
```

Empty map outputs now serialize as `{}` instead of an `ArrayObject` class name string.
