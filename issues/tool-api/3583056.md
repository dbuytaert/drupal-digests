## Summary

Constraints declared on list and map outputs, such as `Count` with `min` or `max`, are now enforced when a tool's outputs are validated. Before, they were advertised but never checked. This also covers outputs declared with the deprecated `multiple: TRUE`, which the shim converts to a list. Tool authors may see new output violations where a list or map has the wrong number of items or properties. A required list or map with no `Count` still accepts an empty value.

## Impact

Affects module maintainers.

- **New API:** `ValueViolationsTrait::validateDeclaredConstraints()` now accepts input or output definitions, so `TypedOutputsTrait` can use it too.

## Technical details

`validateOutputValue()` in `TypedOutputsTrait` now calls `validateDeclaredConstraints()` after it has walked the items of a list or the properties of a map. Only the author-declared constraints run, not the typed-data defaults, so an empty required collection stays valid unless `Count` says otherwise. Each declared constraint is validated against its own freshly created data as a non-root call. This stops core's validator from descending into members and reporting each member fault twice. The prototype reset guard ([#3616328](https://www.drupal.org/node/3616328)) applies. A misdeclared constraint, for example `Count` with no options, throws, as it does on the input side ([#3583048](https://www.drupal.org/node/3583048)). For maps, an exception from a constraint is dropped only if the property walk already reported a violation, so the walk's violation rejects the value.

The helper moved from `TypedInputsTrait` to `ValueViolationsTrait`. Its `$definition` parameter is now typed `InputDefinitionInterface|OutputDefinitionInterface`, so inputs and outputs share it. New kernel tests in `TypedOutputsTest` cover lists, maps, a map without properties, a converted `multiple` output, empty values, and an invalid declaration. The map test is skipped on core below 11, which recurses into map properties and entity fields on a non-root validation with explicit constraints ([#3583093](https://www.drupal.org/node/3583093)).
