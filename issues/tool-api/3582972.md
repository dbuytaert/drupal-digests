## Summary

Tool input schemas, as seen by LLM and MCP clients, now carry more of the constraints that tools already declare. Regex patterns, numeric comparisons, list item counts, email and UUID formats, bundle lists and country codes now appear in the schema. Optional inputs that must not be null no longer advertise `null`. Decimals are described as patterned strings instead of the non-standard `format: number`. Every input also gets a `title` (the label is still merged into `description`). The input root now sets `additionalProperties: false`. Empty `properties` encodes as `{}` rather than `[]`. Clients that relied on the old decimal format, or that pass undeclared input names, may notice the difference.

## Impact

Affects module maintainers.

- **API change:** Emitted input schemas change: decimals become `type: string` with a `pattern` instead of `format: number`, every definition gets a `title`, and the input root gets `additionalProperties: false`.
- **New API:** New constraint plugins `GreaterThan`, `GreaterThanOrEqual`, `LessThan`, `LessThanOrEqual` usable in input definitions, plus public constants `ContextDefinitionNormalizer::DECIMAL_PATTERN` and `DERIVED_ENUM_LIMIT`.

## Technical details

Constraint mapping now lives in `ContextDefinitionNormalizer::applyConstraintSchema()` (scalars) and `applyListConstraintSchema()` (lists). Newly mapped constraints:
- `Regex` becomes `pattern`. `convertPcreToEcma()` strips the delimiters and the `i`, `m` and `s` modifiers. Patterns with other modifiers such as `x` or `u`, and `match: false` patterns, are omitted. The body is not checked for PCRE-only syntax.
- `GreaterThan`, `GreaterThanOrEqual`, `LessThan` and `LessThanOrEqual` become `exclusiveMinimum`, `minimum`, `exclusiveMaximum` and `maximum`.
- `Count` becomes `minItems` and `maxItems`; `exactly` sets both.
- `Email` and `Uuid` become `format`.
- `NotBlank` on strings becomes `minLength: 1`.
- `PositiveOrZero` becomes `minimum: 0`.
- `IdenticalTo` becomes `const`.
- `CountryCode` becomes the pattern `^[A-Z]{2}$`.
- `EntityBundleExists` becomes an `enum` of bundle IDs.

Enums derived from site state (`PluginExists`, `EntityBundleExists`) are omitted when they exceed `DERIVED_ENUM_LIMIT` (50). `Choice` and `AllowedValues` lists are never capped. `NotNull`, and `NotBlank` without `allowNull`, suppress the null branch on optional inputs via `removeNullBranch()`, which handles both the `type: [X, null]` and `oneOf` shapes.

`LegacyTypedDataNormalizer` gains `Timestamp` (integer) and `DateTimeInterface` (`string` with `format: date-time`) arms, placed before the integer and string arms because of inheritance. Core's `datetime_iso8601` schema is overridden to `date-time`. On the legacy path, timestamps get the description note "A Unix timestamp in seconds."

`ToolDefinitionSerializer::normalizeInputSchema()` adds `additionalProperties: false` only at the root. Maps stay open because refiners may add properties and free-form maps are legitimate. `MapDefinitionNormalizer` and the map branch in `ContextDefinitionNormalizer` use `new \ArrayObject()` for empty `properties`. The `title`/`description` split is deliberately deferred to a follow-up.

Four constraint plugin classes are added under `Plugin/Validation/Constraint/`, because core registers only `PositiveOrZero` and `IdenticalTo` from Symfony's comparison family. `ComprehensiveTypesTool` is extended and a new `RicherSchemaEmissionTest` is added. It snapshots the schemas on both the legacy and core normalizer paths.

## Upgrade

Tool authors can now declare the comparison constraints in input definitions, for example:

```php
constraints: [
  'GreaterThan' => ['value' => 0],
  'LessThanOrEqual' => ['value' => 100],
],
```

Consumers that matched on decimal inputs having `format: number` should instead check for `type: string` with `pattern` equal to `ContextDefinitionNormalizer::DECIMAL_PATTERN`. Consumers that pass input names not declared by the tool will now conflict with the root `additionalProperties: false`.
