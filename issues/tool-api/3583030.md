# #3583030: outputSchema describes a timestamp member as date-time, structuredContent sends integer

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583030](https://git.drupalcode.org/project/tool/-/work_items/3583030) · 1 contributor · 15 comments

## Summary

The Tool module builds an MCP `outputSchema` for each tool's declared output types, but the actual `structuredContent` payload it sent for a tool's result didn't always match that schema. A `timestamp` output, for example, was advertised as an RFC 3339 date-time string but sent as a raw Unix integer. Since the MCP spec requires servers to send structured results that conform to the schema, and expects clients to validate against it, this mismatch could make an otherwise-correct tool result get rejected by a compliant client. The fix converts affected values to the format the schema promises before they go out over the wire.

## Impact

Affects module maintainers.

- **API change:** `getFormattedResult()` now converts `timestamp`, `decimal`, and DateTime-constrained `datetime_iso8601` output values, plus empty `map` outputs, to match the wire format their advertised `outputSchema` describes (e.g. a Unix timestamp becomes an RFC 3339 string, an empty map becomes `{}` instead of `[]`); `getResult()`/`getOutputValue()` keep returning the original PHP values.

## Technical details

The conversion lives in a new `OutputTypeCoercionSubscriber`, an event subscriber on `ToolOutputTransformEvent` that runs after invoker-specific subscribers but before the recursive subscriber that walks list/map items, so nested members get the same treatment. It handles four mismatches: a `timestamp` value is reformatted from a Unix integer to `DateTimeInterface::RFC3339` when the active core is 11.1+ (core's schema-aware `TimestampNormalizer` describes it as a date-time string there; older cores use the module's `LegacyTypedDataNormalizer`, which describes it as an integer, so it's left alone); a `decimal` int or float is formatted as a fixed-point string via a new shared `DecimalStringTrait` (extracted from `InputTypeCoercionSubscriber`, which already needed the same logic for input coercion); a `datetime_iso8601` value carrying the `DateTime` constraint is reformatted from the offset-less storage spelling (`Y-m-d\TH:i:s`) to RFC 3339, but only when it matches that exact storage format, anything with an offset or otherwise non-conforming is left untouched; and an empty PHP array for a non-multiple `map` output is replaced with `new \ArrayObject()` so it JSON-encodes as `{}` instead of `[]`.

The new `AdvertisedOutputSchemaConformanceTest` exercises every discovered tool with schema-conforming sample inputs and validates each formatted output against its normalized schema, plus pins the exact converted spellings so a value that happens to validate but changes meaning (a shifted timezone, a rounded decimal) is still caught.
