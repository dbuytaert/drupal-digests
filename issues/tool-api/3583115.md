## Summary

In the Tool module, `drush tool:info --format=json` now prints a tool's `output_schema` as a JSON Schema object, the same shape as `input_schema`, the serializer and the MCP bridge. Before, it printed a bare map of output name to schema, so code written against one form broke on the other. Scripts that parse `tool:info` output need to read the output names under `output_schema.properties`.

## Impact

Affects module maintainers.

- **API change:** `drush tool:info --format=json` now prints `output_schema` as `{type: object, properties: {...}}` instead of a map of output name to schema.

## Technical details

`ToolInfoCommand::buildSchemas()` now calls `ToolDefinitionSerializer::normalizeOutputSchema()` instead of `normalizeOutputDefinitions()`, so the printed `output_schema` matches what the serializer returns. The `?: new \ArrayObject()` fallback is gone, since the wrapped schema is never an empty list. For a tool with no outputs the result is `{"type":"object","properties":{}}`. The separate `outputs` key is unchanged: one entry per output with `type` and `required`. The Drush command docs were updated to describe `output_schema` as an object schema shaped like `input_schema`, and `ToolInfoCommandTest` was updated to match.

## Upgrade

Consumers of `drush tool:info --format=json` should read output schemas from the `properties` key:

```php
// Before: $data['output_schema']['received']['title']
// After:
$data['output_schema']['properties']['received']['title'];
```
