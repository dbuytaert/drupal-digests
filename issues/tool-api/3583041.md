# #3583041: Issue #3583041: Keep a multiple definition's description on the array

## Summary

The Tool module builds JSON Schema descriptions of each tool's inputs, which are consumed by AI agents and MCP clients to know what a tool accepts. For inputs that accept multiple values (`multiple: TRUE`), the schema generator previously threw away the field's own description and title, replacing them with a generic `Array of <label>` string, while duplicating the real label and description onto the nested `items` schema instead. This meant the actual, useful description written by the tool's author was hidden one level down instead of appearing where a caller would look for it. The fix keeps the field's real title and description on the array schema itself, where they belong, and leaves `items` to describe only the type of each element.

## Impact

Affects module maintainers.

- **API change:** For context definitions with `multiple: TRUE`, `ContextDefinitionNormalizer` no longer duplicates the label/description onto `items` or rewrites the array's own description as `Array of <label>`; the definition's real description and title now stay directly on the array schema, and `items` carries only its type (and constraints like `format`).

## Technical details

The bug was in `ContextDefinitionNormalizer::normalize()` in the `tool` module: when handling a `multiple` context definition, the code cloned the item definition, normalized it to build `items`, then copied that clone's description onto `items['description']` and synthesized `$schema['description'] = 'Array of ' . $object->getLabel()`, overwriting whatever description the array schema already had.

The fix clears the label and description on the cloned single-item definition before normalizing it (`$item_definition->setLabel(''); $item_definition->setDescription('');`), so `items` no longer picks up a redundant title/description, and removes the block that rewrote `$schema['description']` to the generic `Array of ...` string. The array's own title and description, already set earlier in the method from the definition, are left untouched. Kernel tests in `InputSchemaMatrixTest` and `RicherSchemaEmissionTest` were updated to assert the corrected shape, e.g. a `multi_string` field now emits `{"items": {"type": "string"}, "description": "Multi string: A multiple string input.", "title": "Multi string"}` instead of nesting the description inside `items` and replacing the top-level description with `"Array of Multi string"`.</technical>
<parameter name="upgrade">Code or tests that assert on the exact JSON Schema produced for `multiple` tool inputs must be updated. For example, a `multi_string` field's schema changes from:

```json
{
  "type": ["array", "null"],
  "items": {
    "type": "string",
    "description": "Multi string: A multiple string input.",
    "title": "Multi string"
  },
  "description": "Array of Multi string",
  "title": "Multi string"
}
```

to:

```json
{
  "type": ["array", "null"],
  "items": { "type": "string" },
  "description": "Multi string: A multiple string input.",
  "title": "Multi string"
}
```
