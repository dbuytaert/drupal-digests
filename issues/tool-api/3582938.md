## Summary

AI agents that use a Tool plugin through `tool_ai_connector` now keep the providing module as a dependency. Before, the agent config entity's `dependencies` was empty. For example, an agent using `entity_save` from `tool_belt_content` did not list `tool_belt_content`, so exported config could be missing that dependency. Existing agents probably need re-saving before their config picks up the new dependency. I did not verify that.

## Impact

No upgrade or configuration changes required.

## Technical details

`ToolPluginDeriver::getDerivativeDefinitions()` now reads `$tool_definition->getProvider()` and adds it to `$definition['module_dependencies']` on each derived AI function call definition. The list is de-duplicated with `array_unique()` and reindexed with `array_values()`. The fix is only in the deriver. I did not read the AI module code that consumes `module_dependencies`, so how it turns the key into config dependencies is not verified here. The issue reports `tool_ai_connector` as expected alongside the provider module. Nothing in this diff adds `tool_ai_connector` itself.
