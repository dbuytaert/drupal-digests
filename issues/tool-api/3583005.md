# #3583005: Advertise truthful formats for unmarked datetimes and timestamps

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583005](https://git.drupalcode.org/project/tool/-/work_items/3583005) · 1 contributor · 10 comments

## Summary

Tool input schemas now describe what Drupal actually accepts. Timestamp inputs advertise integer seconds as well as RFC 3339 strings, so strict clients such as the MCP bridge, which validates arguments against the schema, no longer reject a bare integer. Datetime inputs with no date-only or date-time marker advertise both a full date-time and a bare date, instead of core's date-only `date`. Output schemas are not changed. If you have clients or tests that depend on the old advertised schema, expect the output of schema normalization to differ.

## Impact

Affects module maintainers.

- **API change:** Advertised input JSON schema changes: core-path `timestamp` inputs become `type: ["string","integer"]` (plus `null` if optional); unmarked `datetime_iso8601` inputs advertise `anyOf` of `date-time` and `date` formats.

## Technical details

The change is in `InputOutputDefinitionNormalizer` (`src/Normalizer/InputOutputDefinitionNormalizer.php`). The issue text proposed advertising plain `format: "date-time"` for unmarked datetimes. The committed code differs: for an unmarked `datetime_iso8601` input, it removes `format` and emits `anyOf: [{format: date-time}, {format: date}]`, with the description note "An RFC 3339 date-time, or a date alone as YYYY-MM-DD." The comments in the code give the reason: the input coercion subscriber re-emits a full datetime in canonical form but leaves a bare `Y-m-d` date untouched, and naming only `date-time` would make a strict invoker reject the bare date. Marked definitions are unchanged: `DateOnly` gives `date`, `DateTime` gives `date-time`.

For `timestamp` on the core (11.1+) path, an input schema of `type: string` is widened to `["string", "integer"]`. The note becomes "An RFC 3339 date-time or a Unix timestamp in seconds." This is skipped for `OutputDefinitionInterface` objects, because the output transform sends the string core describes. The legacy path already used integer and keeps its Unix-seconds note. The optional-input handling now also appends `null` to an array-valued `type`, so a union gains the null branch the same way a single string type does. Unmarked datetime outputs are deliberately left alone, since the output transform only rewrites to RFC 3339 under the `DateTime` marker. The commit also updates the schema matrix and acceptance tests.
