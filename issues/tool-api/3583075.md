# #3583075: Rename ContextDefinitionNormalizer now that it normalizes input and output definitions

- **Project:** Drupal AI
- **Type:** Normal task
- **Status:** Fixed
- **Discussion:** [#3583075](https://git.drupalcode.org/project/tool/-/work_items/3583075) · 1 contributor · 5 comments

## Summary

The Tool module's JSON Schema builder for input and output definitions is renamed from `ContextDefinitionNormalizer` to `InputOutputDefinitionNormalizer`. The old name described core's context system, which the definition families no longer build on. The old class name and service ID keep working for one release but trigger deprecation notices. Behavior is unchanged. Custom code that extends the class, uses its constants, or injects it by service ID should switch to the new names before rc1.

## Impact

Affects module maintainers.

- **API change:** The JSON Schema normalizer for input and output definitions is now `Drupal\tool\Normalizer\InputOutputDefinitionNormalizer`, with the same `DECIMAL_PATTERN` and `DERIVED_ENUM_LIMIT` constants.
- **Deprecation:** `Drupal\tool\Normalizer\ContextDefinitionNormalizer` and the `tool.normalizer.context_definition` service are deprecated in tool:1.0.0-beta12 and removed from tool:1.0.0-rc1. Use `InputOutputDefinitionNormalizer` and `tool.normalizer.input_output_definition`.

## Technical details

The full implementation moved into `src/Normalizer/InputOutputDefinitionNormalizer.php`. Its docblock now names the input and output definition families as the subject. Core `ContextDefinitionInterface` support is described as the ai module's override path. `ContextDefinitionNormalizer` stays as a thin shell that extends the new class. Its constructor calls `@trigger_error()` with `E_USER_DEPRECATED`, and its docblock carries `@deprecated in tool:1.0.0-beta12 and is removed from tool:1.0.0-rc1`.

In `tool.services.yml` the service is now `tool.normalizer.input_output_definition`, still tagged `normalizer` with priority 100. `tool.normalizer.context_definition` stays as a private alias with a `deprecated` message. Normalizers are private services, so the old ID resolves only where another service definition injects it by ID. A new kernel test, `ContextDefinitionNormalizerDeprecationTest`, covers the class and alias deprecations. Internal references were updated: `LegacyTypedDataNormalizer` uses `InputOutputDefinitionNormalizer::DECIMAL_PATTERN`, and comments in `EntityHandleTransformer` and `EffectiveDataDefinition` plus `NormalizerFormatRestrictionTest` were changed to match. The issue body says tool_belt, canvas_tools and mcp_server_tool_bridge do not refer to the old class or service ID.

## Upgrade

Replace the class and service references:

```php
// Before
use Drupal\tool\Normalizer\ContextDefinitionNormalizer;
// After
use Drupal\tool\Normalizer\InputOutputDefinitionNormalizer;
```

```yaml
# Before
arguments: ['@tool.normalizer.context_definition']
# After
arguments: ['@tool.normalizer.input_output_definition']
```
