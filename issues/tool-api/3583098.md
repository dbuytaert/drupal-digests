## Summary

When a tool run fails on bad input, the error text now tells an agent (or any caller) what to change. An unknown input lists the inputs the tool accepts, a missing required input reads "This input is required.", and a value of the wrong type reads like "This input must be a string." or "This input must be an integer." without extra constraint messages for that input. The `ToolRunner` class can also now be autowired. Code or tests that match the old messages, such as "This value should not be null.", need updating.

## Impact

Affects module maintainers.

- **API change:** Input validation message text changed (`This input is required.`, `This input must be a string.`, unknown input lists accepted inputs); `NOT_AN_ENTITY_ERROR` now also marks a required single entity input left out.
- **New API:** `ToolRunner` is now a service alias for `tool.runner`, so it can be autowired.

## Technical details

In `TypedInputsTrait`, the unknown-input `InputException` message now ends with "It takes a, b, c." (or "It takes no inputs."), built from `getInputDefinitions()`, so locked inputs are not offered. In `validateInputValues()`, a `NULL` value on a required input yields a single "This input is required." violation in place of the `NotNull` detail. For a single (non-multiple) entity input, that violation carries `TypedInputsInterface::NOT_AN_ENTITY_ERROR`, so `drush tool:run` still appends its "cannot pass entities" advice. Lists of entities get no code.

In `validateInputValue()`, primitive typed data now goes through a new `validatePrimitiveType()` first. It runs only core's `PrimitiveType` constraint, and skips even that for arrays, because other validators (e.g. `Regex` via `preg_match()`, and the URI check via `parse_url()`) throw on an array. If the type is wrong, it returns one violation worded as the input schema words the type: string, integer, number, true or false, decimal formatted as a string, URI with a scheme, RFC 3339 date-time, `YYYY-MM-DD`, ISO 8601 duration, or timestamp. The `DateOnly` and `DateTime` constraint markers narrow the datetime wording. Other constraints on that input are then not run.

A service alias for `ToolRunner` pointing at `@tool.runner` is added to the module's services file. The diff also adds a test tool, `quoted_constraint_tool`, and a test asserting that a constraint message with quotes stays plain text for text callers after `PlainTextOutput::renderFromHtml()`. The result message is still escaped once for HTML callers.

## Upgrade

Callers or tests that matched the old text need updating, for example:

```text
Invalid input:
recipient: This input is required.
```

This replaces `recipient: This value should not be null.` An unknown input now reads `nope: This input is not defined for the tool. It takes entity, mode.` For advice on entity inputs, match on `TypedInputsInterface::NOT_AN_ENTITY_ERROR` rather than on message text. You can now type-hint the `ToolRunner` class in an autowired service.
