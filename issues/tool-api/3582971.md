## Summary

Unexpected exceptions thrown while a tool runs no longer leak their raw message into the failure result. The result now says `Tool execution failed: <ExceptionClass>. The full error has been logged.`, and the full exception goes to a new `tool` log channel. This matters because results can be read by end users or by LLMs whose output reaches end users. Input validation messages are also now translatable.

## Impact

Affects module maintainers.

- **API change:** `ToolBase::__construct()` takes a new optional `?LoggerChannelInterface $logger` argument. Failure results for unexpected exceptions now contain only the exception class, not its message.
- **New API:** New `logger.channel.tool` logger channel service.

## Technical details

`ToolBase::execute()` now catches `\InvalidArgumentException | InputException` as expected failures and keeps their curated message in the existing `Tool execution failed due to invalid input: @message` result. Any other `\Throwable` is passed to `Error::logException()` and the result shows only `get_class($e)`. `ToolBase::__construct()` gets a new optional trailing `?LoggerChannelInterface $logger = NULL` argument, and `create()` passes `logger.channel.tool`, a new service defined in the module's services file with parent `logger.channel_base`. If the tool is constructed without a logger, nothing is logged.

In `TypedInputsTrait`, the former `sprintf()` strings (invalid context, locked input, input value invalid, `Input @name: @message` violation prefix, `must be an entity`, `input is invalid`) now use `TranslatableMarkup` with placeholders. The `InputException` messages are cast to string at construction. The `input value is invalid` and `input is invalid` messages still embed the underlying `$e->getMessage()` through the `@message` placeholder. `ToolBaseTest` now asserts that the thrown text does not appear in the result.

## Upgrade

Code or tests that read the raw exception text from `$tool->getResult()->getMessage()` for unexpected exceptions must now check the `tool` log channel instead. The result message looks like this:

```
Tool execution failed: RuntimeException. The full error has been logged.
```

Tool subclasses that override the constructor should accept the new optional `?LoggerChannelInterface $logger = NULL` argument and pass it to the parent.
