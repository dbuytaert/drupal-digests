## Summary

Adds a "Set Configuration" tool that lets a tool caller, such as an MCP client or AI agent, change one value in an existing configuration object. The caller gives a config name (e.g. `system.site`), a key (e.g. `slogan`) and a value. The tool returns the old and new values. In the issue, it was tested by asking Claude Desktop over MCP to change the site name and slogan. Near the end of the thread a maintainer proposed moving the issue to the Tool Belt module, since tools are being moved out of Tool API. The MR has not been committed to this project.

## Impact

Affects module maintainers.

- **New API:** New `config_set` Tool plugin (`Drupal\tool_system\Plugin\tool\Tool\ConfigSet`) in the `tool_system` module.

## Technical details

The MR adds a single final class, `ConfigSet`, as a `#[Tool]` plugin with id `config_set`. Its inputs are `config_name` (string), `key` (string) and `value` (any). It has one output, `updated_config` (any).

`doExecute()` loads the object with `ConfigFactoryInterface::getEditable()`. If `isNew()` is true, it returns `ExecutableResult::failure()` instead of creating a new config object. Otherwise it reads the old value with `get($key)`, then calls `set()` and `save()`. It returns a success message plus `updated_config` containing `config_name`, `key`, `old_value` and `new_value`. Any `\Exception` is caught and returned as a failure result. Non-scalar values are JSON-encoded in the message only.

`checkAccess()` returns `AccessResult::allowedIfHasPermission($account, 'administer site configuration')`. The tool does not validate the key or value against the config schema in the code shown. The `set()`/`save()` call is the only write step.
