## Summary

When an AI agent sends invalid input to a tool, for example a text format that doesn't exist on the site, the tool never runs. Code that reads the tool's result directly, such as the ai_agents image collection loop, then hit a `BadMethodCallException`. That aborted the whole agent run, and the LLM never got the error message it needed to retry. Now the AI connector records a failure result on the tool, so reading the result is safe and the LLM gets its corrective feedback.

## Impact

Affects module maintainers.

- **API change:** Classes implementing `ToolInterface` directly (not via `ToolBase`) must implement the two new methods. `hasResult()` now also returns TRUE after `setFailureResult()`.
- **New API:** `ToolInterface::setFailureResult(TranslatableMarkup $message)` and `ToolInterface::hasExecuted()` added; `ToolBase` implements both.

## Technical details

`ToolInterface` gains `setFailureResult(TranslatableMarkup $message)`, which stores `ExecutableResult::failure($message)` on a tool that never ran. It throws `\LogicException` if a result already exists, so a real execution result can't be overwritten. It also gains `hasExecuted()`, backed by a new `ToolBase::$executed` flag set at the start of `execute()`. This separates "a result exists" (`hasResult()`) from "`execute()` ran", so retry logic and telemetry can still tell a seeded failure from a real one. The `hasResult()` docblock is updated to say so.

At the end of `ToolPluginBase::execute()` in the `tool_ai_connector` module, if `$this->errorMessage` is set and the wrapped plugin has no result (input failure or access denial), the connector calls `setFailureResult()` with the error message. The existing `errorMessage` and `getStructuredOutput()` behavior is unchanged. `getResult()` still throws for genuine caller errors. A kernel test, `SeededFailureResultTest`, covers both the seeded failure and the refusal to overwrite. The issue notes the underlying bug is also in ai_agents, which should guard `getResult()` with `hasResult()`.

## Upgrade

Only classes that implement `ToolInterface` without extending `ToolBase` need changes. They must add:

```php
public function hasExecuted(): bool;
public function setFailureResult(TranslatableMarkup $message): static;
```

Code that treats `hasResult()` as "the tool executed" should switch to `hasExecuted()`.
