# #3583063: Reject the generic entity data type in the entity definition family

- **Project:** Drupal AI
- **Type:** Minor task
- **Status:** Fixed
- **Discussion:** [#3583063](https://git.drupalcode.org/project/tool/-/work_items/3583063) · 1 contributor · 3 comments

## Summary

Declaring a tool input or output with `new EntityInputDefinition('entity')` or `new EntityOutputDefinition('entity')` now throws an `InvalidArgumentException` immediately. Previously it silently produced the nonexistent `entity:entity` type, and the error only appeared later, for example when the tool's input schema was generated. The message tells authors to use a plain `InputDefinition` or `OutputDefinition` with data type `entity` for a generic "any entity" declaration.

## Impact

No upgrade or configuration changes required.

## Technical details

`EntityDefinitionBase::normalizeEntityDataType()` prefixes any value lacking `entity:`. It now throws when the value is exactly `entity`. `EntityInputDefinition` and `EntityOutputDefinition` both construct through this helper, so the one guard covers both. Only the exact string `entity` is rejected; `node` and `entity:node` behave as before. The issue argues the guard cannot break a working declaration, because `entity:entity` already failed downstream with `PluginNotFoundException`. A unit test, `EntityDefinitionGenericTypeTest`, was added. The behavior mirrors core's `EntityContextDefinition`, which has the same shorthand and the same trap. The issue notes that tool_belt hit this with a generic entity list item.

## Upgrade

If you declare a generic entity with the entity definition classes, switch to the base definitions:

```php
// Before: now throws InvalidArgumentException.
new EntityInputDefinition('entity');
// After: use a plain InputDefinition (or OutputDefinition) of type 'entity'.
```
