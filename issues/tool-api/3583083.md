# #3583083: Entity input violation tells an in-process invoker that it cannot pass entities

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583083](https://git.drupalcode.org/project/tool/-/work_items/3583083) · 1 contributor · 6 comments

## Summary

When a non-entity value (such as a node ID) was set on an entity input, Tool told every invoker without the entity handle capability that it "cannot pass entities". That was false for in-process invokers like ECA, which hand real entity objects to tools. The validation message now states only the reason, "This input must be an entity.", for every invoker. `drush tool:run` still gives its own advice to use a tool that takes an entity type and ID.

## Impact

Affects module maintainers.

- **New API:** New `TypedInputsInterface::NOT_AN_ENTITY_ERROR` violation code, set on the violation for a non-entity value on an entity input.

## Technical details

The first fix attempt, from [#3583046](https://www.drupal.org/node/3583046), keyed the hint on `InvokerCapability::EntitiesAsHandles`. That capability only says whether an invoker uses handle strings. It does not say whether the invoker can carry a PHP object. The fix drops the invoker check from `TypedInputsTrait`. Validation cannot know what an invoker can supply, because any module may turn what an invoker sent into an entity through an input transform. The violation is now always `This input must be an entity.` and carries the new code `TypedInputsInterface::NOT_AN_ENTITY_ERROR`.

An invoker that knows its own boundary can match on that code and add its own advice instead of matching on the message. `ToolRunCommand` does this. When a failed run, not an access denial, has a violation with that code, it appends `drush tool:run cannot pass entities; use a tool that takes an entity type and ID instead.` The check covers list items and map properties too. Tests cover the message and code with no invoker, a capability-less invoker and a handles invoker, and check that the code survives the path rebuild for list items. They also check that Drush adds the advice only for entity violations.
