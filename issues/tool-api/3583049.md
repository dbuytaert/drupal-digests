# #3583049: Deprecate `multiple` on input and output definitions in favor of list definitions

- **Project:** Drupal AI

## Summary

Declaring a tool input or output as `multiple: TRUE` is now deprecated in favor of declaring a list definition. Existing `multiple` declarations still load: they are converted to a list automatically and trigger a deprecation notice. The advertised JSON Schema stays the same. The conversion also fixes a bug where a `Count` constraint on a `multiple` input rejected every value, because `Count` now applies to the list and not to each item. The `multiple` option is planned for removal in 1.0.0-rc1.

## Impact

Affects module maintainers.

- **API change:** The `$multiple` constructor parameter is dropped from `ListInputDefinition` and `ListOutputDefinition`, so positional arguments after `$required` shift by one.
- **Deprecation:** `multiple: TRUE` on input definitions, output definitions (including core `ContextDefinition` passed as outputs), map properties and refiner results is deprecated in tool:1.0.0-beta10 and removed in 1.0.0-rc1; declare list definitions instead.

## Technical details

The two ways of declaring a list disagreed about where constraints go. A `multiple` input copied every constraint, `Count` included, onto each item, so `Count` failed every value. The new `ListInputDefinition::fromMultiple()` splits the constraints: those that describe the list, such as `Count`, go on the list, and the remaining constraints stay on a required item copy with no label or description. This is the same split the normalizer already applies to the JSON Schema, so the output is unchanged. The one exception is the default value, which moves to the list and is no longer advertised on each item. Both `ListInputDefinition` and `ListOutputDefinition` have a `fromMultiple()`. It is marked `@internal` and is deleted together with `multiple`.\n\nThe conversion happens at several entry points, each with an `E_USER_DEPRECATED` pointing at work item 3583049. `ToolDefinition::addInputDefinition()` converts inputs. `MapDefinitionBase` converts map properties, to either an input or an output list. `OutputDefinition::fromContextDefinition()` turns a core `ContextDefinition` with `multiple` into a `ListOutputDefinition`. `TypedInputsTrait` converts a refiner result that returns `multiple: TRUE`, before the narrowing check runs. Lists produced by conversion are flagged (`isConvertedFromMultiple()` in `ListDefinitionBase`) so the refiner constraint split and the entity handle transformer treat them correctly. Bundled test tools such as `ComprehensiveTypesTool` and `SchemaMatrixTool` were moved to explicit list definitions, and `docs/developers/input-output-definitions.md` was updated.\n\nStep 2 of the issue, removing `isMultiple()`/`setMultiple()` and the `$multiple` constructor parameters, is not part of this change.

## Upgrade

Replace `multiple: TRUE` with a list definition, as in the issue's example. Put list-level constraints such as `Count` on the list and per-item constraints on the item:

```php
$list = new ListInputDefinition(
  label: 'Tags',
  description: 'Tags.',
  constraints: ['Count' => ['min' => 2]],
  item_definition: new InputDefinition(
    data_type: 'string',
    label: 'Tag',
    description: 'A tag.',
    constraints: ['Length' => ['min' => 3]],
  ),
);
```

Anything that constructs `ListInputDefinition` or `ListOutputDefinition` with positional arguments must drop the old `$multiple` argument. The new signature is `($label, $description, $required, $default_value, $constraints, $item_definition, ...)`. Using named arguments avoids the problem.
