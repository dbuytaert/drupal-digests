## Summary

Agents whose tools have optional (nullable) inputs no longer fail when run against an Anthropic model. Before, the generated tool schemas put an object under `type`, which Anthropic rejects as invalid JSON Schema draft 2020-12. The Tool module now emits a plain type such as `string` or `array` for those inputs. Nothing is lost, because optionality is still expressed by the property not being in `required`.

## Impact

No upgrade or configuration changes required.

## Technical details

The fix is in `SchemaToolsPropertyConverter::prepareAiPropertySchema()`. The issue traced two invalid shapes to the AI module's `ToolsPropertyInput::setType()` and to the converter's earlier relocation of core's `oneOf` nullable normalization into `type`.

A list-style `type` array such as `['array', 'null']` now drops `'null'` and keeps the first remaining type. It falls back to `'string'` if nothing is left. A `oneOf` or `anyOf` whose members are each a bare `{type: string}` schema is flattened the same way. It becomes the first non-null type and the composition key is removed. Compositions with extra keywords, such as differing `format` values, still go through the existing passthrough into `type`.

The issue notes that `ToolsPropertyInput::setType()` rewriting valid type arrays is an AI module bug that deserves its own upstream issue. This change only makes the connector's output valid. Tests were updated in `SchemaToolsPropertyConverterTest`, with a new `testFlattensNullableTypeArrays`.
