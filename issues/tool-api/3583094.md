# #3583094: A required input explicitly set to NULL throws ContextException from execute() and access()

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583094](https://git.drupalcode.org/project/tool/-/work_items/3583094) · 1 contributor · 2 comments

## Summary

A required input with no default that was explicitly set to NULL used to crash when code called a tool's `execute()` or `access()` directly. `execute()` reported an unhelpful runtime failure, and `access()` threw a `ContextException`. Both now behave the way `validateInputs()` already did. `execute()` returns an input failure naming the input. `access()` returns Forbidden with the reason `Tool input validation failed.` Callers that go through `ToolRunner` or the MCP bridge were not affected, because those call `validateInputs()` first.

## Impact

No upgrade or configuration changes required.

## Technical details

The cause was that `validateInputs()` had its own explicit-NULL rule, but `getExecutableValues()` resolved values through `getExecutableValue()`. For a required input with no default, that call threw `ContextException` from the default-value path. The issue itself was closed with no separate merge request. The fix landed as a side effect of the commit for [#3583085](https://www.drupal.org/node/3583085). That commit moves the rule into a shared `resolveInputValues()` in `TypedInputsTrait`. In that method, an input or configuration value explicitly set to NULL, on an unlocked, required definition with no default, resolves to NULL so it can be reported as a violation. `getExecutableValues()` calls it and then validates, throwing the violations as `InputException::fromViolations()`. `validateInputs()` reads the same values through `getExecutableValues(TRUE)`, so a subclass override of that accessor applies to validation and execution alike. `execute()` and `access()` already handled `InputException` as an input problem. `ToolBaseTest::testExplicitNullRequiredInputIsAnInputFailure()` covers both paths using `numeric_input_tool`.
