## Summary

Tools that declare optional outputs but don't fill them in no longer cause a crash when you read the results. Previously, `getOutputValues()` threw a `ContextException` after the tool had run successfully. Skipped optional outputs now come back as NULL, matching how `getOutputs()` already behaved. Required outputs that were never set, and names the tool doesn't declare, still throw.

## Impact

No upgrade or configuration changes required.

## Technical details

`TypedOutputsTrait::getOutputValue()` used to throw `ContextException` whenever `$this->outputs[$name]` was not set. `getOutput()` instead builds an empty `Context` from the output definition. `getOutputValue()` now delegates to `getOutput($name)->getContextValue()`, and `getOutputValues()`, which loops over it, inherits the fix.

Required and undeclared outputs keep their errors, now from core. Core's `Context` throws when a required output has no value. An undeclared name throws from the definition lookup, with a message like "does not define a 'nonexistent' output". The docblocks in `TypedOutputsInterface` were updated to describe this. The `ContextException` import was removed from the trait.

Tests were added to `ToolBaseTest`: a skipped optional output reads as NULL, a required unset output still throws, and an undeclared name still throws. The `extra_output_tool` test plugin gained an `optional_note` output that it never sets.
