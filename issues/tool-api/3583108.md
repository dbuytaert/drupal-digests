# #3583108: Check view label access before including an entity label in handle hints and Drush output

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583108](https://git.drupalcode.org/project/tool/-/work_items/3583108) · 1 contributor · 4 comments

## Summary

Tool no longer shows an entity's label to an account that is not allowed to see it. Before, the `label:` line of a handle hint and the label in `drush tool:run` output could reveal, for example, the title of another author's unpublished node to a user with only "access content". Now the label is shown only when core's `view label` check passes, and is otherwise omitted (`NULL`).

## Impact

Affects module maintainers and site owners.

- **Security:** Information disclosure: labels (such as the title of an unpublished node) of entities the account cannot view were shown in handle hints and Drush `tool:run` output.
- **API change:** `EntityHandleTransformer::getAccessibleLabel()` gains an optional `?AccountInterface $account` parameter (current user by default) and now requires `view label` access on the entity.

## Technical details

`EntityHandleTransformer::getAccessibleLabel()` now first requires `$entity->access('view label', $account)`. Where the entity type has a label field, it also still requires field `view` access on it. Entity types without a label field, such as user, get only the entity check. The new optional `$account` defaults to the current user. Handle hints are built while the tool runner has switched to the run-as account, so they omit it.

Drush prints after the runner has switched back from the `--uid` account, so a plain check there would use the wrong user. The `formatOutputValue()` and `referenceEntities()` methods moved from `ToolOutputTrait` into `ToolRunCommand` and now take the run-as account. `ToolRunCommand` gets `EntityHandleTransformer` (`tool.entity_handle_transformer`) injected through its constructor. Content entities go through `getAccessibleLabel($value, $account)`. Config entities, which have no field access, use a bare `view label` check, which the code comment says matches the JSON:API split. Kernel tests cover both paths, with a new `tool_test_entity_field_access()` hook in the `tool_test` module to deny title field access.

## Upgrade

Custom code that calls `getAccessibleLabel()` outside a tool run, where the current user is not the account of interest, should pass the account explicitly:

```php
$label = $transformer->getAccessibleLabel($entity, $account);
```

Code that subclasses or constructs `ToolRunCommand` directly must supply the new `EntityHandleTransformer` constructor argument. The class is `final` and autowired, so this mainly affects manual instantiation.
