## Summary

The Tool module now ships Drush commands for working with tools from the command line. You can list tools, search them by keyword, read a tool's details and input format, and run a tool. Output is a table by default, and `--format=markdown` gives output aimed at coding agents. The commands are meant for developers testing tools without a browser, and for coding agents that work better with a CLI than with MCP. Running a tool as the default user 1 bypasses tool access restrictions unless `--uid` selects another user. The commit also fixes a bug where a tool with an optional map input and no default failed.

## Impact

Affects module maintainers.

- **New API:** New Drush commands `tool:list` (`tools`, `tlist`), `tool:search` (`tsearch`), `tool:info` (`tinfo`) and `tool:run` (`trun`).

## Technical details

The commands are in `src/Drush/Commands/` as `ToolListCommand`, `ToolSearchCommand`, `ToolInfoCommand` and `ToolRunCommand`. They share formatting helpers in `ToolOutputTrait` and use the `plugin.manager.tool` service.

`tool:list` and `tool:search` accept `--format=table|markdown` and `--operation=explain|read|transform|trigger|write`. `tool:search` also takes `--match=or|and`, and OR is the default. It matches against plugin ID, label and description only, not input definitions. `tool:info <tool_id>` supports `table`, `markdown` and `json` formats. It shows label, description, operation, destructive flag, provider, input and output definitions, and a generated `drush tool:run` usage example.

`tool:run <tool_id>` takes `--input`, which can be repeated and accepts either a JSON object or `key=value` pairs. Values in `key=value` form are JSON-decoded when possible. `--json` produces a JSON envelope. `--uid` defaults to 1, and the command switches to that account with `AccountSwitcherInterface` and switches back in a `finally` block. A missing tool, a missing user, an input error, access denied and an execution exception each write an error that respects `--json`. They also return a failure exit code, as does a tool result that reports failure. `tool:list`, `tool:search` and `tool:info` return `void`, so their failures still exit with 0.

`MapContextDefinition::getDefaultValue()` now returns `NULL` when the map is not required and has no explicit default. Before, it built a partial array from property defaults, which failed validation. Test tools `greeting_tool` and `optional_map_tool` and kernel tests for each command were added.
