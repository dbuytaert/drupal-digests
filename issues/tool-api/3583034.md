# #3583034: tool:run --json prints raw output values instead of the published ones

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Version:** 1.0.x-dev
- **Status:** Fixed
- **Discussion:** [#3583034](https://git.drupalcode.org/project/tool/-/work_items/3583034) · 1 contributor · 5 comments

## Summary

Running `drush tool:run --json` printed a different, unpublished view of a tool's output than the one MCP clients and `tool:info`'s schema describe. For example a date-time output came out as a raw Unix timestamp integer instead of the RFC 3339 string the schema promises, and an entity output came out as its PHP class name (like `Drupal\node\Entity\Node`) instead of the handle string MCP actually receives. This made the `--json` output untrustworthy for anyone scripting against it or comparing it to the advertised schema. The fix makes `tool:run --json` print the same, published values every other consumer sees.

## Impact

No upgrade or configuration changes required.

## Technical details

`ToolRunCommand::runCommand()` read `$tool->getOutputValues()`, the raw PHP-side view of a tool's outputs, and passed it through a hand-rolled `serializeOutputs()` helper that mapped objects via `toArray()`, `__toString()`, or `get_class()` as a fallback. That path never ran the output transform events that `getFormattedResult()->getContextValues()` runs, so entities never became handles and, once related timestamp/decimal/datetime formatting work landed, dated and decimal values wouldn't match their declared JSON Schema either. The fix reads `$tool->getFormattedResult()->getContextValues()` instead and drops `serializeOutputs()` entirely, since those values are already the ones destined for `Json::encode()`. The text-mode output path keeps using `formatOutputValue()` on the same, now-formatted values.
