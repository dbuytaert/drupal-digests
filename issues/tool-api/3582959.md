## Summary

Configuration values for tool inputs (the middle step of the input > config > default chain) never worked. Setting a value through configuration and running the tool caused a fatal error, and reading a tool's configuration could throw for inputs that had no value set. This is fixed: configuration-sourced values now resolve and execute correctly, and `getConfiguration()` returns a plain array of values, using input defaults for unset keys. Configuration passed when creating a tool instance is now applied.

## Impact

Affects module maintainers.

- **API change:** `getConfigurationValue($name, $return_typed_data)` now returns the plain value by default and the `Context` wrapper when TRUE, and returns NULL instead of throwing `InputException` for unset keys. `getConfiguration()` now returns plain values.
- **New API:** `getConfigurationValue()`, `setConfigurationValue()` and `hasConfigurationValue()` are now declared on `TypedInputsInterface`.

## Technical details

In `TypedInputsTrait`, `getConfigurationValue()` had its ternary inverted. It now returns `->getContextValue()` by default and the stored `Context` when `$return_typed_data` is TRUE. It returns NULL for unset keys instead of throwing `InputException`. `getExecutableValue()` previously called `->getValue()` on a `Context`, which has no such method. It now passes the plain value to `prepareExecutableValue()`.

`setConfiguration()` now resets the configuration storage and stores only keys that were explicitly passed. It no longer seeds definition defaults, because that made `hasConfigurationValue()` unable to tell "configured" from "defaulted" and left the default branch of the resolution chain unreachable. Defaults are applied on read: `getConfiguration()` uses `$definition->getDefaultValue()` for keys without an explicit value. A consequence is that `setConfiguration()` now replaces earlier explicit values rather than merging.

`ToolBase::__construct()` now calls `$this->setConfiguration($configuration)`, so configuration given to `createInstance()` reaches the input chain. The three accessors were added to `TypedInputsInterface` with docblocks. New kernel test `ConfigurationInputTest` covers precedence, the `getConfiguration()` round-trip, and execution with a config-sourced value.

## Upgrade

Code that relied on the old inverted behavior should be updated. `getConfigurationValue($name)` now returns the plain value, and `getConfigurationValue($name, TRUE)` returns the `Context`. Callers that caught `InputException` for unset keys should check for NULL or call `hasConfigurationValue($name)` instead. Code that expected `setConfiguration()` to fill in definition defaults should read them through `getConfiguration()` or `getExecutableValue()`.
