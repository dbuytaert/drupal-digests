## Summary

The `entity_field_values` tool now returns more data for entity reference fields that carry extra properties, such as a media entity's image field. Before, you only got the `target_id` and basic entity info. Now `alt`, `title`, `width` and `height` come back too. This helps agents and other consumers that need image metadata from the tool's output. The merge request is a proposal and no commit had landed when this was written.

## Impact

No upgrade or configuration changes required.

## Technical details

The problem was in `getFieldItemValue()` in `src/Plugin/tool/Tool/EntityFieldValues.php`. It returned early on any field with a `target_id` property, so it only returned `target_id` and an `entity` array (`id`, `label`, `type`). In the MR, that branch builds a `$result` array with the same two keys. It then loops over all field item properties and adds each one that is not computed and is not `target_id`, keyed by property name, using `$property->getValue()`. The result is returned afterwards.

The issue's proposed code skipped `NULL` and empty-string values. After review, the MR includes every non-computed property, empty values too, because no reason to filter them was found. The module maintainer questioned whether a field-type-agnostic approach would be better. He suggested the `isset($properties['target_id'])` block might be removable, but said that may not be possible. That question was not settled in the thread, and the diff keeps the `target_id` branch.
