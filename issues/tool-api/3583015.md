## Summary

Tool outputs now have their own definition classes, mirroring the ones inputs already had. `OutputDefinition`, `EntityOutputDefinition`, `ListOutputDefinition` and `MapOutputDefinition` replace core's `ContextDefinition` family in a tool's `output_definitions`. `description` is now a required constructor argument, so output schemas shown to LLMs carry a description. Tools that still declare outputs with core context classes keep loading for now, but they trigger a deprecation notice. That support is scheduled for removal in [#3583019](https://www.drupal.org/node/3583019). The docs, the Drush `tool.twig` generator template and the `tool_test` module were converted to the new classes.

## Impact

Affects module maintainers.

- **API change:** Output definition parameters and return types on `TypedOutputsDefinitionInterface`, `TypedOutputsInterface`, `ToolOutputDefinitionNormalizeEvent`, `ToolOutputTransformEvent` and `ToolDefinitionSerializer::normalizeOutputDefinition()` changed from `ContextDefinitionInterface` to `OutputDefinitionInterface`.
- **Deprecation:** Declaring `output_definitions` with core `ContextDefinition`, `EntityContextDefinition`, `MapContextDefinition` or `ListContextDefinition` is deprecated in tool:1.0.0-beta9 and removed from tool:1.0.0-rc1 (#3583019).
- **New API:** New `OutputDefinitionInterface`, `OutputDefinition`, `EntityOutputDefinition`, `ListOutputDefinition` and `MapOutputDefinition` in `Drupal\tool\TypedData`.

## Technical details

`OutputDefinitionInterface` extends core's `ContextDefinitionInterface` and has no methods. Its purpose is to own the type boundary, so output-only metadata can be added later without narrowing a parameter type in 1.x. The concrete classes mirror the input ones, minus `locked`. `OutputDefinition` and `EntityOutputDefinition` take `$data_type, $label, $description` first. `MapOutputDefinition` and `ListOutputDefinition` fix the data type and take `$label, $description` first. Each overrides `create()`, because the inherited factory cannot satisfy the required label and description. The map and list classes throw `\InvalidArgumentException` if a property definition or item definition is not an `OutputDefinitionInterface`. The check runs in the constructor, `setPropertyDefinitions()` and `setItemDefinition()`.

`ToolDefinition::__construct()` does not reject bare core definitions, which the issue text proposed. It converts them with the `@internal` `OutputDefinition::fromContextDefinition()` and emits `E_USER_DEPRECATED`. The conversion is recursive for map and list children. When the description is empty, it synthesizes `The <label> output.` `ContextDefinitionNormalizer::requireOutputDefinition()` throws if a non-output definition reaches normalization in the output direction.

Internal `instanceof` checks now target the output classes. These are in `TypedOutputsTrait::validateOutputs()` (the core prototype cache workaround), `RecursiveToolValueTransformSubscriber` and `EntityHandleTransformSubscriber`. `EntityHandleTransformer::transformOutputDefinition()` now returns an `OutputDefinition` string handle.

## Upgrade

Convert output declarations, and update any event subscribers or `TypedOutputs*` implementations to the new type hints:

```php
use Drupal\tool\TypedData\OutputDefinition;

output_definitions: [
  'message' => new OutputDefinition(
    data_type: 'string',
    label: new TranslatableMarkup('Message'),
    description: new TranslatableMarkup('The generated greeting message.'),
  ),
],
```

Use `MapOutputDefinition` (properties must be output definitions), `ListOutputDefinition` and `EntityOutputDefinition` in place of `MapContextDefinition`, `ListContextDefinition` and `EntityContextDefinition`. `description` is now required.
