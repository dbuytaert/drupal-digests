## Summary

The Tool module now accepts more input shapes that LLMs commonly send. It converts them to the expected type instead of failing validation and forcing the model to retry. New cases: JSON-encoded strings for map or list inputs, enum values that differ only in case or whitespace, date strings for datetime and timestamp inputs, whole-number floats such as `5.0` for integers, `0`/`1` for booleans, and an empty string for optional non-string inputs. The module only converts when the intended value is clear. Anything doubtful still fails validation as before, so this only makes accepted input looser.

## Impact

No upgrade or configuration changes required.

## Technical details

All changes are in `InputTypeCoercionSubscriber::onInputTransform()` (priority 50). The invoker (100), coercion (50) and recursive (-100) ordering is unchanged. Decoded or wrapped structures still get per-item coercion from the recursive subscriber's child dispatch.

Behavior as shipped:
- **Empty string:** `''` becomes `NULL` for non-required inputs whose type is boolean, integer, float, decimal, timestamp, datetime_iso8601 or map, or that are lists. Required inputs and string inputs keep `''`.
- **JSON strings:** for map or list targets, a string whose trimmed value starts with `{` or `[` is passed through `json_decode`. The result is accepted only if its shape fits: `array_is_list()` for lists, non-list or empty for maps. This runs before list wrapping. A mismatch, such as a JSON object sent to a list, falls through and is wrapped as a single item.
- **Enums:** `Choice` or `AllowedValues` choices are read from the definition's constraints. A string is snapped to the choice only when exactly one case-insensitive, trimmed match exists. Typos such as `articles` are left alone.
- **Booleans:** integers `0` and `1` become booleans. Other integers stay for validation.
- **Datetimes:** for `datetime_iso8601`, non-numeric strings are parsed with `DateTimeImmutable` and re-emitted with `format('c')`. Purely numeric strings are skipped as ambiguous, for example `"2026"`.
- **Timestamps:** `timestamp` inputs accept numeric strings, integral floats, and parseable date strings, which become Unix timestamps. Unparseable strings stay for validation.
- **Integers:** an integral float becomes an int for integer inputs, with a range check in `isIntegral()`. Fractional floats stay for validation.

Kernel tests in `InputTypeCoercionTest` cover each case, including negative assertions that invalid values still fail. The test tool `CoercionTestTool` gained `category`, `published_at`, `happened_at` and `threshold` inputs.
