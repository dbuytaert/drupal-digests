# #3583045: tool:info --format=json prints [] instead of {} for a tool with no inputs or outputs

- **Project:** Drupal AI
- **Type:** Normal bug report
- **Status:** Fixed
- **Discussion:** [#3583045](https://git.drupalcode.org/project/tool/-/work_items/3583045) · 1 contributor · 8 comments

## Summary

The `tool:info --format=json` Drush command in the Tool module now always prints `inputs`, `outputs`, and `output_schema` as JSON objects (`{}`), even when a tool declares none. Previously an empty PHP array serialized to a JSON list (`[]`) in that case, which broke consumers that expect a map keyed by name, including typed decoders that reject a list where an object is required.

## Impact

No upgrade or configuration changes required.

## Technical details

`ToolInfoCommand::outputInfoAsJson()` built `$data['inputs']` and `$data['outputs']` directly as PHP arrays populated in a loop over the tool's definitions. When a tool had no input or output definitions, the array stayed empty, and PHP's `Json::encode()` (like native `json_encode()`) renders an empty array as `[]` rather than `{}` since there is no key information to distinguish a list from a map. The fix builds `$inputs` and `$outputs` as local arrays as before, then assigns `$data['inputs'] = $inputs ?: new \ArrayObject()` (and likewise for `outputs` and `output_schema`), so `Json::encode()` serializes the empty case as an object. The test `ToolInfoCommandTest::testToolInfoSimpleTool()` was extended to assert `"inputs":{}`, `"outputs":{}`, and `"output_schema":{}` for a tool with no requirements.</technical>
