## Summary

Setting a value that can't be stored on a tool input, such as a malformed JSON string on a map input, no longer throws a bare PHP `InvalidArgumentException`. It now fails with a tool `InputException` whose message names the input, for example "The settings input value is invalid: ...". An LLM invoker can then report which input was wrong and send back the input schema so the model can correct itself, instead of showing a generic execution error.

## Impact

Affects module maintainers.

- **API change:** `setInputValue()` now throws `InputException` (with the original `\InvalidArgumentException` as previous) instead of a bare `\InvalidArgumentException` when typed data can't store the value.

## Technical details

Typed data rejects structurally invalid values, such as a string given to a `Map`, inside `Map::setValue()`. That happens at storage time, before validation can run and produce a named violation. In `TypedInputsTrait::setInputValue()`, the `setInput($name, Context::createFromContext(...))` call is now wrapped in a try/catch for `\InvalidArgumentException`. The catch rethrows `InputException` with the message `The %s input value is invalid: %s`, and the original exception is kept as the previous exception.

The kernel test `ToolPluginBaseStructuredOutputTest::testMapValueThatCannotBeStoredFailsWithInputNamed` checks that a string set on the `settings` map input of `coercion_test_tool` gives `success` false. It also checks that the message contains "The settings input value is invalid" and that `input_schema` is echoed. `InputTypeCoercionTest::testMalformedJsonForMapIsNotDecoded` now expects `InputException` instead of `\InvalidArgumentException`. The diff changes only the trait and tests. I did not check how the invokers (`tool_ai_connector`, MCP) handle `InputException`.

## Upgrade

Code that called `setInputValue()` and caught `\InvalidArgumentException` for un-storable values should catch `\Drupal\tool\Exception\InputException` instead:

```php
try {
  $tool->setInputValue('settings', '{"verbose": tru');
}
catch (InputException $e) {
  // "The settings input value is invalid: ..."
}
```
