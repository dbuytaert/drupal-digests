## Summary

`drush tool:run` can now chain tools that work on content entities. An entity output prints as a `handle:<uuid>` string with a hint naming the entity, and a content entity input accepts that string, as the AI connector and MCP bridge already do. Every call in a chain must run with the same `--uid`, because handles are stored per account. The original proposal to hide such tools from CLI listings was not what shipped: they stay listed, and `tool:list`, `tool:search` and `tool:info` flag them with `requires_handle`.

## Impact

Affects module maintainers.

- **New API:** `tool:run` accepts and prints `handle:<uuid>` strings for content entities, `--json` output gains a `hints` list, and `tool:list`, `tool:search` and `tool:info` JSON gain `requires_handle`. `EntityHandleTransformer` gains `hasContentEntityInputs()`, `hasRequiredContentEntityInputs()` and `hasContentEntityOutputs()`.

## Technical details

`DrushInvoker::create()` now returns `new Invoker(self::ID, InvokerCapability::EntitiesAsHandles)`, so the existing handle transformer applies to drush runs. `tool:run` prints the formatted result: content entities as handles, plus a `hints` list under `--json` or a "Hints:" block in text output, shown only when there are hints.

`EntityHandleTransformer` gains `hasContentEntityInputs()`, `hasRequiredContentEntityInputs()` and `hasContentEntityOutputs()`. They recurse into list items and map properties through a private `containsContentEntityDefinition()`. `requires_handle` is true only when a required content entity input exists. A tool that only returns an entity, or whose entity input is optional, can be the first call of a chain. `isConfigEntityDefinition()` and `isContentEntityDefinition()` now strip a bundle suffix such as `node:article` before the entity type lookup, because `getDefinition()` throws a `LogicException` for such IDs.

`tool:run` logs a warning when run as uid 0 and the tool requires or returns a content entity. Anonymous tempstore owners do not persist across drush processes, so no handle reaches another call. The old "drush tool:run cannot pass entities" advice is replaced by `entityInputAdvice()`. It says "Pass the handle an earlier call returned." for content entity inputs and "Pass the machine name of the <type>." for config entity inputs, which take a machine name ([#3583059](https://www.drupal.org/node/3583059)). `tool:info` shows a "Requires handle" line and builds its example command with `--uid=UID` and `HANDLE` placeholders. It omits optional entity inputs and uses `MACHINE_NAME` for config entity inputs. The skill and drush docs were updated with a "Chain entity tools" section.

## Upgrade

Tool authors need no changes. Scripts or agents that parse `tool:list --format=json` or `tool:search` output get a new boolean `requires_handle` on each tool. Handle chain example from the docs:

```bash
drush tool:run tool_belt:entity_stub --uid=7 --input=entity_type_id=node --input=bundle=article --json
drush tool:run tool_belt:field_set_value --uid=7 --json \
  --input='{"entity":"handle:…","field_name":"title","value":[{"value":"Hello"}]}'
drush tool:run tool_belt:entity_save --uid=7 --json --input=entity=handle:…
```
