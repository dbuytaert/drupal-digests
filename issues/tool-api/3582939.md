## Summary

With the Tool module enabled, entities normalized through Drupal's global serializer (for example in a custom REST resource) came back with every field value as `null`. Cardinality was preserved, so a title looked like `[null]`. The Tool module's definition normalizers now only apply to the `json_schema` format, so REST and other formats use core's normalizers again and field values are returned correctly.

## Impact

No upgrade or configuration changes required.

## Technical details

`MapDefinitionNormalizer` and `ContextDefinitionNormalizer` are registered as global normalizers at priority 100 and inherit `supportsNormalization()` from `ComplexDataNormalizer`, which matches any `ComplexDataInterface`. Core field items extend `Map`, so these normalizers claimed field item normalization for every format. Their `getSupportedTypes()` returned `[Map::class => ($format === 'json_schema')]`. In Symfony Serializer, `false` there means "fall back to `supportsNormalization()`", not "deny". The normalizers therefore still matched, and `doNormalize()` returned `NULL` for non-`json_schema` formats.

The fix returns `[]` from `getSupportedTypes()` when `$format !== 'json_schema'`, so the serializer skips these normalizers entirely. For `json_schema` it returns `TRUE` for `Map::class` and `ContextDefinitionInterface::class` respectively. This is the same pattern used earlier for `LegacyTypedDataNormalizer` in [#3568588](https://www.drupal.org/node/3568588). The commit adds a unit test for the supported types of both normalizers and a kernel test that `EntityTest` field values survive `json` normalization with `tool` enabled.
