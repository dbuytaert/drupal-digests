## Summary

The usage line printed by `drush tool:info` now uses the first example declared on an input definition instead of a made-up value. Before this, a tool declaring `examples: ['Oma']` still showed `"word":"example_word"` in the usage line, even though the JSON Schema printed just above listed `Oma`. Inputs with no declared examples keep the generated placeholder values.

## Impact

No upgrade or configuration changes required.

## Technical details

In `ToolInfoCommand`, `getExampleValue()` now takes the `InputDefinitionInterface` instead of a data type string. It returns `reset($definition->getExamples())` when examples exist. Otherwise, for a `ListInputDefinition` it returns a one-item list built recursively from `getItemDefinition()`, so nested lists produce `[[1]]`. For anything else it uses the existing `match` on data type. A declared example of `0` is honored, because the check is `!== []` rather than a truthiness test. The change applies to both the table and markdown output formats. New tests in `ToolInfoCommandTest` cover declared examples on `example_values_tool` (`field_tags`, `0`, `["alpha"]`) and list fallbacks on `recursive_scalar_transform_tool`.
