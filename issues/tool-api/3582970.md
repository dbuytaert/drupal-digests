## Summary

The Drush commands in the Tool module no longer run tools as the superuser by default. `drush tool:run` runs as anonymous unless you pass `--uid`, so access checks apply to a real account. Use `--uid=1` only when you want superuser execution. Malformed `--input` values now fail with an error and a non-zero exit code, and so do invalid `--uid` values. Scripts that relied on the old default or on silently ignored input need updating. The docs now list exit codes for `tool:run`, `tool:info`, `tool:list` and `tool:search`.

## Impact

Affects site owners.

- **Config change:** No config change. CLI behavior of `drush tool:run` changes: runs as anonymous unless `--uid` is given, and stricter `--uid` and `--input` validation.

## Technical details

The final commit tightens `ToolRunCommand` and its docs. The command's `--uid` option description already said it defaults to anonymous. In this commit `parseUid()` treats `NULL` (option omitted) and `FALSE` (explicit `--uid=0`) as anonymous. Other values go through `filter_var(..., FILTER_VALIDATE_INT, min_range 0)`, replacing the hand-written digit and overflow check. Signs and surrounding whitespace are accepted (`+1`, ` 1 `). Leading zeros such as `01` are rejected with an `Invalid --uid value` error, and the tool does not run. Missing and blocked accounts are documented as failing before execution.

`parseInputValues()` previously treated a successful `json_decode` that returned `NULL` like a decode failure. A JSON `null` input (`--input=null`) now gets the same error as other scalars: `Invalid input 'null': JSON input must be an object containing named input values.` Only a real `JsonException` falls through to `key=value` parsing. The invalid-name message from `addInputValue()` now reads `names must be non-empty and must not be integer keys`.

The docs (`usage/drush.md` and the access-control page) document the exit codes: `tool:run` returns 1 for an unknown tool, invalid input or user, denied access, an execution error or a failed result. `tool:info` returns 1 for an unknown tool. `tool:list` and `tool:search` return 1 for an invalid operation filter, and `tool:search` also returns 1 when no keywords are given. An empty list or no search matches returns 0. Kernel tests in `ToolRunCommandTest` use data providers for valid UID forms and for scalar and null JSON.

## Upgrade

Scripts that relied on the old superuser behavior must now pass the user explicitly, and should use a real account that has the tool's required permissions:

```bash
drush tool:run send_email --uid=2 --input='{"recipient":"test@example.com","subject":"Test","message":"Hello"}'
```

Use `--uid=1` only for deliberate superuser execution. Write user IDs as plain decimals (`7`, not `007`). JSON `--input` must be an object, not a scalar, `null` or a list.
