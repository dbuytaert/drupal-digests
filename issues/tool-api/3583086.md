# #3583086: Let `destructive` be undeclared, so write tools aren't reported as non-destructive

- **Project:** Drupal AI
- **Type:** Normal unknown (0)

## Summary

The Tool module can now tell a tool that never declared `destructive` apart from one that said it is not destructive. An undeclared Write or Trigger tool is now treated as destructive, and an undeclared Read tool is not. Before, every write tool that left the flag out looked non-destructive, so the MCP bridge told clients it only added data. That is the opposite of MCP's own default. Authors of write tools that only add data should now set `destructive: FALSE` explicitly.

## Impact

Affects module maintainers.

- **API change:** `destructive` on `#[Tool]`, `#[ToolMethod]` and `ToolDefinition::setDestructive()` is now `?bool` defaulting to `NULL` (undeclared); `ToolDefinition::isDestructive()` answers from the operation when undeclared.

## Technical details

`destructive` on the `#[Tool]` and `#[ToolMethod]` attributes and the `ToolDefinition::$destructive` property changed from `bool` defaulting to `FALSE` to `?bool` defaulting to `NULL`. `ToolDefinition::setDestructive()` accepts `?bool`. `ToolDefinition::isDestructive()` now returns `$this->destructive ?? $this->getOperation()->isModifying()`. `ToolOperation::isModifying()` is TRUE for `Write` and `Trigger` and FALSE for `Explain`, `Read` and `Transform`. An explicit `TRUE` or `FALSE` always wins over the operation. `#[ToolMethod]` defaults its operation to `Write`, so a method that omits `destructive` is now destructive.

The Drush `ToolGenerator` prompt now defaults its answer to what an undeclared tool would get for the chosen operation. `tool.twig` always writes `destructive: TRUE` or `FALSE` instead of omitting it when false, so answering no on a Write tool is an explicit declaration. The issue body says the MCP bridge (`mcp_server_tool_bridge`) sends this as `destructiveHint`. The commit does not touch that bridge, which gets the new value through `isDestructive()`. The issue was meant to land before the RC1 freeze ([#3582976](https://www.drupal.org/node/3582976)).

## Upgrade

Write or Trigger tools that only add data and relied on the old default must now say so:

```php
#[ToolMethod(id: 'tool_test.notebook.export', operation: ToolOperation::Write, permission: 'access content', destructive: FALSE)]
```

Code that passes `destructive: FALSE` or `TRUE` is unchanged. Code that reads `isDestructive()` still gets a `bool`.
