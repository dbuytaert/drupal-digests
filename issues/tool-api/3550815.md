## Summary

The Tool module now has a shared "handle" system for passing complex values, mainly content entities, between tool calls. A tool can return an entity, and the invoker (for example an LLM) receives an opaque `handle:<uuid>` string. When it passes that string to the next tool, the original entity is restored. This supports chains like load, edit, save without serializing the entity over the wire. This commit adds only the shared infrastructure. Wiring into specific connector modules such as `tool_ai_connector` and the MCP bridge is left to separate issues.

## Impact

Affects module maintainers.

- **New API:** New `tool.handle_store` (`ToolHandleStoreInterface`) and `tool.entity_handle_transformer` services, plus `HandleTransformResult` and handle exception classes in `Drupal\tool\Handle`.

## Technical details

The code is in the new `Drupal\tool\Handle` namespace. `ToolHandleStore` (service `tool.handle_store`, also aliased as `ToolHandleStoreInterface`) is value-agnostic. It keeps values in a `PrivateTempStore` collection named `tool_handles`, under the UUID part of the handle. It offers `store()`, `resolve()`, `has()`, `delete()`, `hasHandlePrefix()` and `isHandle()`. `isHandle()` requires the `handle:` prefix plus a valid UUID. `store()` rejects `NULL`. It also accepts an existing handle to overwrite that handle's value. A request-local `\WeakMap` links objects to handles, so storing or resolving the same object again reuses its handle. `delete()` clears that link. Failures throw `InvalidHandleException` for a malformed handle and `HandleNotFoundException` for a missing or expired one.

`EntityHandleTransformer` (service `tool.entity_handle_transformer`) holds the entity-specific logic and never touches events. `resolveInput()` returns non-handle values unchanged. For handle strings it returns the stored content entity, and throws `InvalidHandleException` or `UnexpectedHandleValueException` otherwise. `transformOutput()` stores a `ContentEntityInterface` value and returns a `HandleTransformResult` with `value` (the handle) and `hint`. The hint names the entity type, bundle, id or "new, unsaved", and language. Config entities and non-entities return `NULL`. `transformInputDefinition()` and `transformOutputDefinition()` replace content-entity definitions (`entity` or `entity:<type>` where the class is a content entity) with `string` definitions. Their descriptions say to pass a handle or that a handle is returned, so the schema shown to an invoker matches what it actually receives.

A connector subscriber calls the transformer from the existing `ToolInputTransformEvent`, `ToolOutputTransformEvent` and the two definition normalize events. It does this only for its own invoker ID. The commit includes `tool_test`'s `TestEntityHandleTransformSubscriber` as a reference, plus a `ComplexEntityEventTool` and kernel tests. The tests cover handles for entities nested in maps and lists. The commit does not include the `tool_ai_connector` or `mcp_server_tool_bridge` subscribers described in the issue body. It also uses the `WeakMap` for handle reuse, not the `_tool_handle` property tagging described there. The tests assert that no `_tool_handle` property is added to the entity.

## Upgrade

Connector authors can wire the transformer in with a thin event subscriber. This follows the pattern in `tool_test`:

```php
public function onInputTransform(ToolInputTransformEvent $event): void {
  if ($event->getInvoker() !== self::INVOKER_ID) {
    return;
  }
  $event->setValue($this->entityHandleTransformer->resolveInput($event->getValue()));
}

public function onOutputTransform(ToolOutputTransformEvent $event): void {
  if ($event->getInvoker() !== self::INVOKER_ID) {
    return;
  }
  $result = $this->entityHandleTransformer->transformOutput($event->getOutputName(), $event->getValue());
  if ($result !== NULL) {
    $event->setValue($result->value);
    $event->addMessage($result->hint);
  }
}
```

The subscriber service takes `@tool.entity_handle_transformer` as an argument. Tools that need non-entity handles can use `tool.handle_store` directly.
