## Summary

The Tool module's AI connector (`tool_ai_connector`) used to drop arguments it didn't recognize. A model that misspelled an input name only heard that the input it meant was missing, so it retried with the same wrong key. The connector now reports the unrecognized name, for example `numbr: This input is not defined for the tool.`, and the tool doesn't run. This matches how the MCP bridge and `drush tool:run` already behaved. A value passed for a locked input is also rejected now, with "This input is locked and cannot be changed." Existing setups may start failing if they pass keys the tool doesn't declare.

## Impact

Affects module maintainers.

- **API change:** `tool_ai_connector` is stricter: an argument the tool doesn't declare, or a value for a locked input, now fails the call instead of being ignored.
- **New API:** `ToolPluginBase::populateValues()` is overridden to set every argument.

## Technical details

Arguments were being dropped in two places before `ToolRunner::run()` saw them. One was the ai module's `FunctionCallBase::populateValues()`, which skips arguments with no context definition. The other was `ToolPluginBase::execute()`, which forwarded only declared input names. The fix overrides `populateValues()` in `Drupal\tool_ai_connector\Plugin\AiFunctionCall\ToolPluginBase`. The override calls `setContextValue()` for every argument, undoing the `__colon__` escaping the way the parent does. `execute()` now passes every stored value to the runner, with `unescapePropertyKeys` applied through `array_map`. The runner's existing validation then produces the "not defined" and "locked" violations, which come back in the structured output with `success` false and the input schema. The context mirroring step after execution now uses `array_intersect_key($values, $definitions)`, so undeclared and locked names, which have no definition, are skipped there. Kernel tests in `ToolPluginBaseStructuredOutputTest` cover a misspelled name, an extra name set through `setContextValue()`, and a locked input.

## Upgrade

The issue notes that ai_agents' `default_information_tools` sets every parameter key from the agent's YAML with `setContextValue()` and doesn't check the names. An undeclared key in that YAML now fails the call, so remove or correct keys the tool doesn't declare. Callers that pass a value for a locked input must also stop doing so.
