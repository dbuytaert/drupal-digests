## Summary

Tool results can now carry cache tags, cache contexts and a max-age, so consumers such as MCP resources, render caching or AI response caching can cache read-only tool output safely. Results stay uncacheable (max-age 0) unless the tool declares what it read, so existing tools behave as before. Failed results are always uncacheable.

## Impact

Affects module maintainers.

- **API change:** Any custom implementation of `ToolResultInterface` must now implement `getCacheContexts()`, `getCacheTags()` and `getCacheMaxAge()`.
- **New API:** `ToolResultInterface` now extends `CacheableDependencyInterface`; `ExecutableResult::withCacheableDependency()` added.

## Technical details

Cacheability sits on the result, not the tool, because the same tool returns different data for different inputs. This is the follow-up to [#3582965](https://www.drupal.org/node/3582965), which removed `CacheableDependencyInterface` from `ToolInterface`.

`ExecutableResult` gets an optional `CacheableMetadata` and `withCacheableDependency(object $dependency)`. It merges `CacheableMetadata::createFromObject($dependency)` into the existing metadata and returns a new instance, since the class is `final readonly`. With nothing declared, `getCacheMaxAge()` returns 0. The first declared dependency makes the result cacheable, and the merge then takes the lowest max-age. An object that isn't cacheable keeps the result at 0. A tool that depends on nothing it loaded can pass an empty `CacheableMetadata` to make the result permanent. `getCacheMaxAge()` also returns 0 for failures, though tags and contexts still pass through.

`FormattedExecutableResult` delegates tags and contexts to the original result. Its max-age is 0 when formatting replaced a `ContentEntityInterface` with a handle, checked recursively through arrays. Handles are stored in the current user's tempstore, so a cached copy would hand out a handle that was never stored. The raw result stays cacheable. Access cacheability is not copied into the result, so consumers merge the access result's cacheability themselves. Docs in `creating-a-tool.md` and the method-tools page are updated. A `cacheable_node_tool` test plugin and kernel and unit tests are added.

## Upgrade

In a tool's `doExecute()`, declare what the result depends on:

```php
return ExecutableResult::success(
  new TranslatableMarkup('Loaded the node.'),
  ['title' => $node->label()],
)->withCacheableDependency($node);
```

Custom classes implementing `ToolResultInterface` need to add `getCacheContexts()`, `getCacheTags()` and `getCacheMaxAge()`.
