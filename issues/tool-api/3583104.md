## Summary

When a tool had already run but one of its output transform subscribers then threw, the exception escaped `ToolRunner::run()` and the caller never got the invocation. Invokers such as Drush `tool:run` and the AI connector recorded the call as if the tool had never run. Now the call comes back as a normal Runtime failure that still reports the tool as executed. The message names only the exception type, and the full error goes to the log.

## Impact

No upgrade or configuration changes required.

## Technical details

The catch landed in `ToolBase::getFormattedResult()`, the alternative the issue mentioned, rather than in `ToolRunner::run()`. The whole output-transform loop is wrapped in `catch (\Throwable $e)`. The catch logs with `Error::logException()`. If the raw result is successful, it replaces `$this->result` with `ExecutableResult::failure(ToolMessages::unexpectedFailure($e), $context_values, FailureCategory::Runtime)`. It then returns a `FormattedExecutableResult` built from that result. It assigns `$this->result` directly because `setFailureResult()` refuses to replace an existing result. Direct callers of `getFormattedResult()` get the same behavior as the runner.

If the tool had already returned its own failure, that failure is kept, since its reason is more useful than the exception type. Handle exceptions thrown by a transform are also treated as Runtime failures, not Input failures, because the tool has run. The formatted result for the failed call has empty context values, while the raw `getResult()` still carries the tool's original context values.

In `ToolRunner::run()` the `HandleExceptionInterface` catch now covers only a handle exception from a tool's own access check, before `execute()`. That is still an Input failure. The final `\Throwable` catch still rethrows when `hasExecuted()` is TRUE, so it never overwrites an existing result. The `ToolInterface` docblock now notes that a transform failure replaces a successful raw result with a failure. Kernel tests in `ToolRunnerTest` cover `\RuntimeException`, `\TypeError` and `HandleNotFoundException`, and the case where the tool's own failure is preserved.

## Upgrade

No changes are needed for invokers. eca_tool can drop the README sentence about the executed-then-lost edge case, as noted in the issue.
