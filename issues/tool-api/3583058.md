# #3583058: Set Restrict Access on Administer Tool

- **Project:** Drupal AI

## Summary

The `administer tool` permission, which grants access to the Tool Explorer UI and the ability to execute any tool registered on the site, is now marked as a restricted permission. A security review found that this permission was not flagged despite the module's own documentation already warning that it should only be granted to trusted roles, since executing a tool can read or write data or trigger processes. Site owners will now see this permission called out with Drupal's standard "restrict access" warning on the permissions page, making it clearer that it should be treated as administrative and not handed out broadly.

## Impact

Affects site owners.

- **Permission change:** The `administer tool` permission is now marked `restrict access: true`, so Drupal flags it as a security risk on the permissions administration page.

## Technical details

The fix is a one-line addition of `restrict access: true` to the `administer tool` entry in `tool.permissions.yml`. This is Drupal's standard mechanism (`hook_permission()`/`*.permissions.yml` `restrict access` key) for surfacing a warning icon and description on `admin/people/permissions` when a role is granted a permission that can affect site security. It does not change any access-checking logic: routes in `tool_explorer.routing.yml` still gate on `_permission: 'administer tool'` exactly as before. The issue author noted the permission is currently only consumed by the `tool_explorer` submodule.
