## Summary

Map inputs in the Tool module's configuration forms now show their nested properties' declared default values. Before, the property fields of a map input rendered empty. Each field now shows the stored value if there is one, otherwise the property's declared default. This applies at every level of a nested map. Entity properties inside a map also show the right entity when the value is an entity ID.

## Impact

No upgrade or configuration changes required.

## Technical details

`MapAdapter::formElement()` now reads the map's current value and calls `setValue()` on each property's typed data before building its element. It uses the stored value when the key exists, including a stored `FALSE`. Otherwise it uses the property's declared default. A property stored as `NULL` stays empty, so a cleared value does not bring the default back. A nested map stored as `NULL` is built like an empty map, so its own properties show their defaults. A value the property cannot hold throws `\InvalidArgumentException`, which is caught and the value dropped.

Core `MapDataDefinition` properties have no default of their own, so `EffectiveDataDefinition::copyPropertyDefinitions()` now copies the default of each `InputDefinitionInterface` property into a new `EffectiveDataDefinition::DEFAULT_VALUE_SETTING` (`tool_default_value`) setting on the rebuilt definition. Output definitions do not get it. `EffectiveDataDefinition` is `@internal`.

`EntityAdapter` gets a private `getEntity()` helper. A map property's stored value or default is often an entity ID rather than an entity object, so the helper loads the content entity by ID. It returns `NULL` for config entity types, IDs that do not load, other value shapes, and definitions with no fixed entity type. The helper result feeds both the target type and `#default_value` of the autocomplete. New kernel tests cover `MapAdapter` defaults and `EntityAdapter` ID handling.
