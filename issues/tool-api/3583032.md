# #3583032: Split title from description in the JSON Schema instead of prefixing the label onto every description

- **Project:** Drupal AI
- **Type:** Normal task
- **Version:** 1.0.x-dev
- **Status:** Fixed
- **Discussion:** [#3583032](https://git.drupalcode.org/project/tool/-/work_items/3583032) · 1 contributor · 15 comments

## Summary

Tool API's generated JSON Schema no longer prepends the label to every `description`. A member with the label \"Title\" and the docblock text \"Gets the title.\" used to be advertised with `\"description\": \"Title: Gets the title.\"`. It now gets `\"description\": \"Gets the title.\"`, and the label stays in `title`. This changes the prompt text of every tool's inputs and outputs. Any client, test or documentation that matches the old `Label: description` strings needs updating. The issue asks for a mention in the 1.0.0 release notes.

## Impact

Affects module maintainers.

- **API change:** `ContextDefinitionNormalizer::getDescription()` now returns the definition's description only, with no `Label: ` prefix (and NULL when empty).

## Technical details

The change is in `ContextDefinitionNormalizer::getDescription()` in `src/Normalizer/ContextDefinitionNormalizer.php`. It now returns `(string) $definition->getDescription() ?: NULL`. A definition with no description therefore emits no `description` key, and the label travels only as `title`. The comment that deferred this split to a follow-up issue was replaced with one saying the label goes out as the title only.

The `multiple` branch already blanked the item definition's label and description before normalizing `items`. I did not see a change to it in the commit I read. With `getDescription()` fixed, the author's text lands on the array and `items` carries a description only when something adds one, such as the entity handle hints \"(pass a handle from a previous tool call)\" and \"(returns a handle for use in subsequent tool calls)\". Most of the diff is test expectation updates: `InputSchemaMatrixTest`, `MultipleListSchemaTest`, `RicherSchemaEmissionTest`, `ListDescriptionSchemaTest`, `MethodToolTest`, `ToolComplexEventTransformTest` and `ToolDefinitionNormalizeTest`. I did not check the documentation examples that the issue's task list mentions.

## Upgrade

Update any code or tests that assert on the old prefixed text. For example:

```php
// Before.
$this->assertSame('Tags: Words that describe the album.', $schema['description']);
// After.
$this->assertSame('Words that describe the album.', $schema['description']);
```

Read the label from `title` if a consumer needs it.
