## Summary

Optional (nullable) tool inputs are now described in the generated JSON Schema with a single spelling: `type: ["string", "null"]`, with `format` and similar keywords beside it. Before, optional strings, booleans and integers came out as `oneOf: [{type: T}, {type: null}]` on Drupal 11.1+, while optional date-time inputs used a type list, so clients that generate types from the schema saw two shapes for the same idea. The published schema for those inputs changes, so any client or test that matches the `oneOf` form needs updating.

## Impact

Affects module maintainers.

- **API change:** Generated input JSON Schema for nullable scalars changes from `oneOf: [{type: T}, {type: null}]` to `type: [T, "null"]` on Drupal 11.1+.

## Technical details

`InputOutputDefinitionNormalizer` gets a new protected method `flattenNullableOneOf()`, called on the schema returned by core's `json_schema` normalizer. It rewrites a `oneOf` into a `type` list only when every branch is a bare `type` string, one branch is `null`, and at most one branch carries extra keywords (such as `format`), which are moved beside the type. A `oneOf` with no null branch, with branches that say more than a type, or with two branches that carry their own keywords is left untouched. The type list replaces `oneOf` at its original key position, and existing sibling keys are not overwritten. The legacy path (pre-11.1 cores via `LegacyTypedDataNormalizer`) already emitted type lists, so both core paths now produce the same shape. `InputSchemaMatrixTest` and `RicherSchemaEmissionTest` drop their per-core `oneOf` expectations for nullable scalars.

## Upgrade

Clients, schema snapshots or tests that expect the old nullable form must switch to the type list:

```json
{"oneOf": [{"type": "string"}, {"type": "null"}]}
```
becomes
```json
{"type": ["string", "null"]}
```
