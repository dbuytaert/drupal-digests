## Summary

When a caller sends a map input but leaves out an optional property that declares a `default_value`, the tool now receives that default. Previously the input schema advertised the default (for example `"size": "medium"`), but the tool saw an empty map. The same now holds for nested maps, maps inside lists, and maps keyed by name. Falsy defaults such as `FALSE`, `0` and `''` are now advertised in the schema too.

## Impact

No upgrade or configuration changes required.

## Technical details

`TypedInputsTrait::getExecutableValue()` is restructured so every value source (locked, input, configuration, default) passes through a new private `withPropertyDefaults()` before `prepareExecutableValue()` and validation. The method walks `MapDataDefinition` properties, `ListDataDefinition` items, and the item values of a `MapInputDefinition` that has an item definition. It fills a property only if it is absent, optional, and has a non-NULL default, and it recurses into the filled default.

Required properties are not filled, so a missing required property is still reported by validation. An absent optional map still stays `NULL`, and a property sent as `null` stays `null`. The issue says that case waits on [#3583106](https://www.drupal.org/node/3583106).

In `InputOutputDefinitionNormalizer`, the schema `default` check changes from truthiness to `!== NULL`, so `FALSE`, `0` and `''` defaults are advertised. To stop a `multiple` definition's empty-list default from now appearing on each item, the cloned item definition gets `setDefaultValue(NULL)`. This also removes the earlier documented difference where a default value was no longer advertised on each item. `SchemaSampleGeneratorTrait` now builds a sample for a keyed map from its `additionalProperties` item schema. The diff adds the `map_property_default_tool` test tool, and a kernel test, `MapPropertyDefaultTest`, covers it.
