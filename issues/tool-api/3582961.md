## Summary

Checking access on a Tool plugin whose required input is missing or invalid no longer throws an exception. It now reports access denied, as `FALSE` or a forbidden access result. Code that checks access before collecting or validating input gets a normal access answer instead of an uncaught error.

## Impact

Affects module maintainers.

- **API change:** `ToolBase::access()` now returns forbidden (`FALSE` or a forbidden `AccessResult` with max-age 0) on invalid or missing input instead of throwing `\InvalidArgumentException`; its `$return_as_object` parameter is now typed `bool`.

## Technical details

`ToolBase::access()` called `getExecutableValues()`, which throws `\InvalidArgumentException` on validation failure. `execute()` already caught this, but `access()` did not. It now catches the exception and fails closed. With `$return_as_object` it returns `AccessResult::forbidden('Tool input validation failed.')` with `setCacheMaxAge(0)`, and otherwise `FALSE`. The reason string is generic and does not include the violation text. Valid input still goes to `checkAccess()` unchanged. The method signature now types `$return_as_object` as `bool`.

Because input validation failures now look like access denials, `ToolPluginBase::execute()` (the function call wrapper) validates explicitly before calling `access()`. It calls `validateInputValues()` on the executable values, and if there are violations it sets `Tool plugin execution failed: ...` with the violation detail. Without this, a model calling the tool would see "access denied" and might give up instead of correcting its arguments. A real access denial still produces `Tool plugin access denied.` together with the input schema.

The commit adds kernel tests for missing input, invalid input and valid input in `ToolBaseTest`. It also adds an `access_denied_tool` test plugin to the `tool_test` module for the genuine denial case.

## Upgrade

Callers that wrapped `access()` in a try/catch for `\InvalidArgumentException` can remove it. To tell invalid input apart from a real denial, validate first, as the function call wrapper now does:

```php
$violations = $tool->validateInputValues($tool->getExecutableValues(TRUE));
if ($violations->count() > 0) {
  // Report the violations.
}
elseif ($tool->access()) {
  $tool->execute();
}
```

Subclasses overriding `access()` should declare `bool $return_as_object = FALSE` to match the new signature.
