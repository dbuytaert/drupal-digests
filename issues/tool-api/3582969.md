## Summary

The Tool Explorer submodule now lives at `/admin/config/development/tool-explorer`, matching its place under Configuration > Development in the menu. The old `/admin/config/tool/explorer` path is gone, and the change landed before the RC1 URL freeze. The Extend page now shows a Configure link to the explorer. On the tool view page, YAML schema output containing `<` characters is now displayed correctly instead of being mangled, and the schema status messages use Drupal's standard status message markup.

## Impact

Affects site owners.

- **Config change:** Tool Explorer routes `tool_explorer.list`, `tool_explorer.view` and `tool_explorer.execute` moved from `/admin/config/tool/explorer` to `/admin/config/development/tool-explorer`.

## Technical details

In `ToolExplorerController`, the hand-built `#markup` strings (`<pre>` YAML and `messages--status`/`messages--warning` divs) were replaced by two private static helpers. `buildMessage()` returns a `#theme => status_messages` element. `buildYaml()` returns an `html_tag` `pre` whose `#value` is `Html::escape(Yaml::encode(...))`. Escaping up front is needed because `html_tag` passes a plain `#value` through `Xss::filterAdmin()`, which strips anything resembling a tag. The `tool_list` cache tag was removed from the list table's `#cache`, since nothing invalidated it. The `user.permissions` context is kept. The three routes in `tool_explorer.routing.yml` changed path, and `tool_explorer.info.yml` gained `configure: tool_explorer.list`. Tests: the existing `ToolExecuteFormTest` paths were updated. A new `ToolExplorerPagesTest` covers anonymous 403, the list, the view page, YAML escaping, a 404 for unknown plugins, and the Extend page configure link. A new `tool_test` fixture, `angle_bracket_label_tool`, has `<none>` in an input label to exercise the escaping. README and docs references to the old path were updated.
